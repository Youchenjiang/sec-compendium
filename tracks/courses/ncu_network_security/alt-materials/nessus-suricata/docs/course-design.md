# 課程文件：CVE-2021-41773 防守側（情境演練二）

這份是這堂課的源頭文件：先定位這堂在整門課的位置，再寫單堂教案。之後的簡報大綱、學員手冊都從這裡衍生，不另外各寫一套。

## A. 課程定位

**這堂是什麼**
情境演練軌的第二場，站在防守方。同一台 CDX 靶機，紅隊那場（情境演練一）把 Apache CVE-2021-41773 打穿；這場反過來，用 Nessus 把這個漏洞掃出來，用 Suricata 在它被攻擊時偵測到。不交 flag，交一份報告。

**兩條軌怎麼分**
- 關卡解題（picoCTF）：練單一技能的基本功，一題一磚。
- 情境演練（這軌）：在一個真實環境裡把工具串起來跑一遍。
這堂屬後者，而且偏藍隊操作。

**對應講義**
- L7 風險管理 / 弱點識別 → Nessus 掃出漏洞。
- L13 入侵偵測 → Suricata 偵測攻擊。
- （L10 是網路防火牆架構，跟這個 web 漏洞無關，不列。）

**學員先備**
- 看過紅隊那場，知道這個 CVE 怎麼被打穿、什麼是路徑穿越。
- 會用終端機、會下基本指令。

**這堂之後**
- 可接 L8 安全流程（評估 → 偵測 → 應變），把今天的掃描與偵測放進一個完整流程裡談。

## B. 單堂教案

### 學習目標（上完這堂，學員能做到）
1. 用 Nessus 對一台主機做弱點掃描，看懂**整份**掃描結果（重點放在高風險項；靶機上的 CVE-2021-41773 若有報出則深入）。
2. 在靶機上把 Suricata 跑起來、確認規則載到，偵測一次攻擊並讀懂 alert（含：alert 跳 ≠ 攻擊得手）。

### 對象與時間
- 對象：修過前面課、看過紅隊那場的學員。
- 時間：約 50 分鐘（配速見下，依實際堂數調整）。

### 流程與配速

| 段 | 分鐘 | 老師做 | 學員做 |
| :-- | :-: | :-- | :-- |
| 開場・定位 | 5 | 講這堂站防守、對照紅隊那場、今天交報告不交 flag | 聽 |
| 環境 | 5 | 帶過兩台 VM、靶機已有漏洞、Suricata 裝哪 | 連上自己的 VM |
| 裝 Suricata | 10 | 先修簽章金鑰（見技術底）、apt 裝、`suricata-update`、grep 確認、起 daemon、tail log | 跟著在靶機上做 |
| Nessus 掃描 | 10 | 示範建 Basic Network Scan、看整份結果、挑重點（CVE-2021-41773 為主） | 自己掃、看整份清單、截圖 |
| 發攻擊看偵測 | 15 | 帶發三個邊界測試、回靶機看 alert；順帶點一句：回 400／403／500 都沒讀到東西，alert 照跳 | 自己發、對照 fast.log、截圖 |
| 收尾・報告 | 5 | 紅藍閉環一句話、交代報告要寫哪幾塊 | 問答 |

### 課堂要 demo 的東西
- Suricata 起動 + `grep 41773` 確認規則（沒載到 alert 就不會跳，這步要讓學員看到）。
- Nessus 掃出的漏洞清單（整份），以 CVE-2021-41773（plugin 153885）為重點。
- 三個邊界測試送出後，fast.log 跳出 alert。

### 提問設計（對準理解，不是背答案）
- Nessus 說「這台有洞」、Suricata 說「有人在打」，這兩句話差在哪？
- Suricata 跳了 alert，代表攻擊者成功了嗎？為什麼？
- 這台用 GET 穿越讀 `/etc/passwd` 只會回 500，為什麼還是算嚴重漏洞？

### 評量 / 交付
交一份報告（不交 flag）：
1. 背景：CVE-2021-41773 是什麼、為什麼危險。
2. 環境：兩台 VM、版本、拓撲圖。
3. Nessus：掃描設定 ＋ 掃描結果（整份漏洞清單截圖，重點標出 CVE-2021-41773）。
4. 攻擊：發的請求 ＋ 透過 RCE 讀到 `/etc/passwd` 的截圖（GET 穿越在這台只會 500）。
5. Suricata：規則 ＋ alert 截圖。
6. 收尾：掃出洞 → 確認可打 → 偵測到攻擊，對應 L7／L13。

成績看能不能講清機制（掃到洞、打得穿、偵測得到，三者怎麼串起來），不是看截圖齊不齊。

## C. 技術底（給老師備課）

> 驗證程度：攻擊行為（穿越三回應、RCE）已對真機 `10.99.69.10` 實測。Suricata 已在 CDX Kali（`10.99.69.11`）實機裝好並 `suricata-update`，CVE-2021-41773 規則確認載入（見下）。**Nessus** 仍只查證 plugin 存在、尚未在本環境實跑掃描確認會報——備課時值得自己先裝一次確認。

**環境**
- 工具機（attacker/scanner）：`10.99.69.11`，裝 Nessus、也從這台發攻擊。
- 靶機（target）：`10.99.69.10`，CDX 範本，Apache 2.4.49（本來就有漏洞，不用裝也不用改設定），再多裝 Suricata 監聽自己的網卡。
- 網段為範例，只在老師提供的靶機與課堂網段操作。

**安裝前置坑（實機踩到）**
- 全新 CDX Kali 映像 `apt update` 會撞 `NO_PUBKEY ED65462EC8D5E4C5`（Kali 2025 換過套件庫簽章金鑰，舊映像沒有新 key），apt 直接裝會失敗。
- 先修金鑰：`sudo wget https://archive.kali.org/archive-keyring.gpg -O /usr/share/keyrings/kali-archive-keyring.gpg`，再 `sudo apt update`。這步學員幾乎一定會卡，課堂／手冊務必先帶。
- 修完 `apt install suricata` 實測可裝（走台灣鏡像約 70MB）。

**Nessus**
- plugin **153885**（Apache HTTP Server 2.4.49 Path Traversal，CGI abuses 家族）。會**主動發一個穿越請求去測**，不是只看版本橫幅，所以靶機真有洞才報。
- 相關 153952 對應 CVE-2021-42013（2.4.50 修補不完全的後續洞，靠版本判定），本堂不用。

**Suricata（ET Open 規則）** — 已在 CDX Kali 實機驗（suricata 8.0.7；`suricata-update` 抓約 6.9 萬條規則、通過 `suricata -T` 自測）
- `2034124` / `2034125`：ET EXPLOIT，Apache 2.4.49 Path Traversal Attempt（規則名標 M1／M2），抓攻擊請求。
- `2034126`：ET POLICY，標記這台可能有漏洞。
- 實機還載到 `2034128`、`2041773`（同一 CVE 的其他變體規則），不特別講，但 grep 時會一起跳出來。
- 起動前 `grep -R 41773 /var/lib/suricata/rules/` 確認載到。裝在靶機本機、HOME_NET 用預設即可涵蓋收到的流量。
- 服務預設 **disabled**（裝完不會自動跑），手動 `suricata -i <網卡> -D` 起。

**攻擊三測試（邊界）** — 已在真機（10.99.69.10）實測
| 請求 | 回應 | 說明 |
| :-- | :-- | :-- |
| `/cgi-bin/../../../../etc/passwd`（明文 `..`） | 400 | Apache 擋掉明文穿越 |
| `/icons/.%2e/.%2e/.%2e/.%2e/etc/passwd` | 403 | 別名存在但未授權，穿越也讀不到 |
| `/cgi-bin/.%2e/.%2e/.%2e/.%2e/etc/passwd` | 500 | 穿越到 `/etc/passwd`，但 cgi-bin 是 ScriptAlias、有載 mod_cgi，它把目標當程式去執行 → 失敗 500（在這台，500 即代表穿越到位） |
- 這台**沒有**可直接 GET 讀檔的路徑（icons／manual 等別名皆 403）。要讀 `/etc/passwd` 得走 **RCE**：`POST /cgi-bin/.%2e/.../bin/sh` 帶一行指令，mod_cgi 會執行它（實測以 `daemon` 身分跑）。
- 攻擊側套件：`../../../sessions/20261002_attack-cve-2021-41773/scripts/01_test_traversal.sh <靶機IP>` 送三個邊界請求；`02_exploit_rce.sh <靶機IP> 'cat /etc/passwd'` 才是實際讀檔那步。手打時 `curl --path-as-is` 不能省。

**偵測 ≠ 攻擊成功**
- Suricata 抓的是「有人送了這個請求」，就算回 400／403／500、檔案沒讀到，alert 照跳。
- 想佐證：對一台已修補（2.4.51+）的機器發同樣請求，Suricata 一樣會 alert。
