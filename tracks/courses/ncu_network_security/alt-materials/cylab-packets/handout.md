# 從封包裡讀出別人的對話

Lesson 2 把竊聽（Eavesdropping）定義為「聽取一段自己並不參與的對話」，並歸類為被動攻擊（passive attack）：攻擊者只是錄下經過的資料，不改動任何東西，收發雙方因此不會察覺。在網路上，這段「對話」就是一個個封包（packet，網路傳輸的最小單位）。只要能在路徑上把封包錄下來，內容有沒有被保護，就決定了竊聽者能看到多少。

這份講義用 CyLab 上的 **Packets Primer** 示範，走的是：**錄下封包 → 找出對話 → 讀出內容 → 判斷有沒有被保護**。這裡的「錄下封包」已經由題目替你做好，存成一個 pcap 檔（封包錄製檔）；我們從打開它開始。

走完這份講義，你應該能做到：

- 用 Wireshark 打開 pcap，看懂畫面上每一區在說什麼。
- 用顯示過濾條件，從一堆封包裡篩出真正帶有資料的那幾個。
- 用 Follow Stream 把散在多個封包裡的一段對話接回來。
- 看著讀出的內容，判斷它是明文、編碼，還是加密。

---

## 步驟一：取得工具與檔案

到 [wireshark.org](https://www.wireshark.org/download.html) 下載安裝 Wireshark。題目頁的提示也直接點名它：只要能安裝，Wireshark 大概是對初學者最友善的封包分析軟體。

在 CyLab 的 Challenge Library 找到 Packets Primer，題目只有一句話：下載封包錄製檔，用封包分析軟體找出 flag。下載下來的檔名是 `network-dump.flag.pcap`，用 Wireshark 的 File → Open 打開它。

## 步驟二：看懂 Wireshark 的畫面

打開後，畫面分成上中下三區，看的是同一批封包的不同深度：

| 區域 | 顯示什麼 | 什麼時候看 |
|---|---|---|
| 封包清單（Packet List） | 一列一個封包：No.、Time、Source、Destination、Protocol、Length、Info | 掌握全局，挑出要細看的封包 |
| 封包細節（Packet Details） | 選中那個封包，一層層拆開各層協定的欄位 | 想知道某個欄位的值 |
| 原始位元組（Packet Bytes） | 同一個封包的原始資料，左邊十六進位、右邊 ASCII 文字 | 想直接看封包裡裝了什麼 |

這份檔案很小，封包清單一眼就看得完。看 Protocol 欄，有 TCP 和 ARP 兩種。前三個 TCP 封包的 Info 欄依序帶著 `[SYN]`、`[SYN, ACK]`、`[ACK]`，這是 TCP 的三向交握（three-way handshake），也就是雙方在正式傳資料前先確認彼此連得上。ARP 是區域網路裡用來查「這個 IP 對應哪張網卡」的協定，跟這段對話的內容無關。

## 步驟三：篩出帶有資料的封包

TCP 封包的 Info 欄都有一個 `Len=`，表示這個封包承載了多少位元組的資料（payload，封包真正運送的內容）。交握封包都是 `Len=0`，只負責建立連線；整份檔案裡只有一個封包的 `Len` 不是 0，它的 Info 帶著 `[PSH, ACK]`，意思是「這裡有資料，請交給應用程式」。

封包一多，用眼睛找就不實際了，這時要用畫面上方的顯示過濾條件（display filter，只顯示符合條件的封包）。輸入：

```text
tcp.len > 0
```

按 Enter 後，清單只剩那個帶資料的封包。點選它，看最下面的原始位元組區，右邊的 ASCII 欄會出現一串中間夾著空白的字：

```text
p i c o C T F { . . . }
```

這個空白會影響搜尋。如果用 `tcp.payload contains "picoCTF"` 去找，什麼都找不到，因為封包裡的位元組實際上是 `p`、空白、`i`、空白……，過濾條件只比對完全相同的位元組；改成 `tcp.payload contains "p i c o C T F"` 才找得到。

## 步驟四：把整段對話接起來

真實的對話很少只有一個封包。一段 TCP 連線（由兩端的 IP 與埠號決定）在 Wireshark 裡叫做一條 stream，從 0 開始編號。對任一封包按右鍵 → Follow → TCP Stream，Wireshark 會把同一條 stream 裡所有封包的資料依序接起來，在新視窗裡用兩種顏色區分兩個方向，同時把上方的過濾條件換成：

```text
tcp.stream eq 0
```

這份檔案只有一條連線，所以接起來的結果和步驟三看到的一樣；但在有上千個封包的檔案裡，這是把「一段對話」從雜訊中單獨拿出來的主要方法。

UDP 沒有連線的概念，但 Wireshark 一樣會把「同一組來源與目的位址、埠號」之間的封包歸成一條 stream，用 Follow → UDP Stream 接起來，過濾條件是 `udp.stream eq <編號>`。Follow 視窗右下角可以直接切換 stream 編號，一條一條往下看。

## 步驟五：判斷內容有沒有被保護

把步驟三那串字的空白去掉，就是 flag。回頭看我們做了什麼：沒有用到任何密碼或金鑰，只是把錄下來的資料原樣讀出來。也就是說，這段流量**完全沒有被保護**，任何能在路徑上錄到它的人都看得到。

從封包讀出來的內容，大致會是下面三種之一：

| 看到的樣子 | 是什麼 | 還原需要秘密嗎 | 例子 |
|---|---|---|---|
| 直接可讀的文字 | 明文（plaintext） | 不需要 | 這一題；FTP、Telnet、HTTP 的帳號密碼 |
| 像亂碼但字元集固定，結尾常有 `=` | 編碼（例如 base64） | 不需要，認出格式就能解 | A2 的 Bases；HTTP Basic 認證 |
| 完全無法辨識的位元組 | 加密 | 需要金鑰 | HTTPS（TLS）連線，Follow 出來只有亂碼 |

只有第三種能讓竊聽者讀不到內容；即使如此，誰在什麼時間和誰連線，從封包標頭仍然看得到。編碼看起來不像文字，但它和明文一樣，竊聽者用 CyberChef 的 From Base64 這類工具就能還原，這是 A2 已經練過的事。

## 遇到大檔案時用得上的操作

Packets Primer 小到一眼看完；封包一多，下面這幾個操作可以幫你縮小範圍：

| 想知道什麼 | 操作 |
|---|---|
| 這份檔案主要是哪些協定 | Statistics → Protocol Hierarchy |
| 誰和誰之間有對話、各傳了多少 | Statistics → Conversations |
| 依某個欄位重新排序（例如時間、長度） | 點封包清單的欄位標題 |
| 只看某種長度的封包 | `tcp.len == <數字>`、`udp.length == <數字>` |
| 把一條對話接起來 | Follow → TCP／UDP Stream，再切換 stream 編號 |

其中排序值得多說一句：清單預設依「錄到的順序」（No. 欄）排列，但每個封包的 Time 欄記的是它的時間戳記，兩者不一定一致。當資料被拆成好幾段、而段落的錄製順序被打亂時，依 Time 排序才能把它們排回原本的先後。
