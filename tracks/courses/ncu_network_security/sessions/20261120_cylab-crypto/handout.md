# 沒有金鑰，密文是怎麼被還原的

前兩堂的對象是檔案和登入頁，這一堂的對象是一段看不懂的字。A2 做過編碼（Base64、十六進位），那些不需要任何秘密就能還原。這一堂的東西都宣稱「沒有金鑰就看不到」，而四題都會在沒有金鑰的情況下拿到明文。

Lesson 12 有一頁「Attack Encryption System」，說加密系統會從三個地方被攻破：

| 講義寫的 | 白話 | 這堂哪一題 |
|---|---|---|
| Weaknesses in the algorithm | 演算法本身留下可利用的規律 | caesar |
| Brute force against the key | 金鑰的可能性少到可以全部試完 | caesar、Mind your Ps and Qs |
| Weaknesses in the surrounding system | 演算法沒問題，用的人把它用壞了 | hashcrack、EVEN RSA CAN BE BROKEN??? |

每一題都問同樣三件事：**這是哪一種東西 → 秘密在哪、有幾種可能 → 弱點是三條路的哪一條**。

## 這堂用哪幾題

| 題目 | 角色 | 題目給什麼 |
|---|---|---|
| caesar | 實作一 | 一個檔案，裡面是一段被位移過的字 |
| hashcrack | 實作二 | 一行 `nc` 連線指令，連上去會給你雜湊值，要你答出原文 |
| EVEN RSA CAN BE BROKEN??? | 課堂示範 | 一行 `nc` 連線指令，連上去給你 `N`、`e` 和密文 |
| Mind your Ps and Qs | 實作三 | 一個檔案，裡面是 `c`、`n`、`e` 三個數字 |

實作一、二不需要先看示範，可以直接做。實作三用的算式和示範完全相同，差別只在 `p`、`q` 怎麼來，看完示範再做。全部在 CyLab 的 terminal 上完成，只用到 `nc`、`cat` 和 `python3`。

## 先分清楚這是哪一種東西

拿到一段看不懂的字，先判斷它屬於哪一類，因為四類的還原方式完全不同：

| 類別 | 還原需要什麼 | 例子 | 這堂怎麼對付 |
|---|---|---|---|
| 編碼（encoding） | 什麼都不用，規則是公開的 | Base64、十六進位 | A2 做過，這堂不再處理 |
| 對稱式加密（講義的 private key encryption） | 加密和解密用同一把金鑰 | 位移密碼、DES、AES | 金鑰可能性太少就全部試 |
| 雜湊（hash） | 無法還原，它是單向函數 | MD5、SHA-1、SHA-256 | 猜原文，算一次雜湊來比對 |
| 公開金鑰加密（public key encryption） | 私鑰；公鑰是公開的 | RSA | 從公鑰設法算出私鑰 |

## 實作一：金鑰只有 25 種（caesar）

講義的替代式密碼（substitution cipher）範例是每個字母往後移三格，K = 3：

```text
U N I V E R S I T Y
X Q L Y H U V L W B
```

K 就是金鑰。英文字母只有 26 個，移 26 格等於沒移，所以金鑰只有 1 到 25 這 25 種可能。不知道 K 也沒關係，25 種全部試一遍，看哪一行讀得懂。在 terminal 輸入 `python3` 進入互動模式，貼上：

```python
ct = "XQLYHUVLWB"
for k in range(1, 26):
    print(k, "".join(chr((ord(c) - 65 - k) % 26 + 65) for c in ct))
```

前五行輸出：

```text
1 WPKXGTUKVA
2 VOJWFSTJUZ
3 UNIVERSITY
4 TMHUDQRHSX
5 SLGTCPQGRW
```

每一行開頭的數字是這一行假設的 K，後面是照這個 K 往回移的結果。只有 K = 3 那一行是讀得懂的字，其餘都是亂碼，所以金鑰是 3。程式裡的 `ord(c) - 65` 把大寫字母換成 0 到 25 的編號（`A` 的字元碼是 65），減掉 `k` 再對 26 取餘數就是往回移，最後加回 65 變回字母。密文是小寫時，兩個 65 都改成 97（`a` 的字元碼）。

題目的檔案用 `cat` 看內容。大括號裡面那一段才是被位移的字，把它換進 `ct` 再跑一次。

這一題同時踩到兩條路。金鑰只有 25 種，是暴力破解；講義另外指出位移之後字母出現的頻率不變，那是演算法本身的弱點，金鑰再多也擋不住頻率分析。

## 實作二：雜湊不能解開，只能猜中（hashcrack）

雜湊函數把任意長度的輸入算成固定長度的輸出，而且是單向的：從輸出算不回輸入。講義在「Password Encryption」那一頁說 Unix 的密碼函數「is actually a one-way function」，系統存的是雜湊值，登入時把你輸入的密碼再算一次來比對。

所以對付雜湊的方法只有一種：猜一個原文，算它的雜湊，看是否相同。先從長度判斷是哪一種演算法，才知道要用哪個函數算：

| 十六進位字元數 | 演算法 |
|---|---|
| 32 | MD5 |
| 40 | SHA-1 |
| 64 | SHA-256 |

驗證一個猜測只要一行。例如猜原文是 `hello`、演算法是 MD5：

```bash
python3 -c "import hashlib; print(hashlib.md5(b'hello').hexdigest())"
```

```text
5d41402abc4b2a76b9719d911017c592
```

印出來的 32 個字元和手上的雜湊值一樣，就猜中了。換演算法時把 `md5` 改成 `sha1` 或 `sha256`。

一個一個猜太慢，實際做法是查表：有人把常見密碼的雜湊值事先全部算好，做成可以反查的資料庫，例如 CrackStation（一個公開的雜湊反查網站）。貼上雜湊值，它回答原文，前提是那個原文在它的表裡。

題目連上去之後會依序給幾個雜湊值，每答對一個才給下一個。這些雜湊查得到，原因有兩個：密碼太常見；沒有加鹽（salt，講義說的那個由系統挑選、和密碼一起算進雜湊的隨機數）。加了鹽之後，同一個密碼在每個帳號算出來的雜湊都不同，事先算好的表就用不上。演算法本身沒有被破解，壞的是使用方式，屬於第三條路。

## 示範：N 是偶數的 RSA（EVEN RSA CAN BE BROKEN???）

### RSA 的四個算式

講義的 RSA 範例用很小的數字：

```text
p = 7, q = 17
n = p × q = 119
φ(n) = (p − 1)(q − 1) = 96
e = 5，d = 77（因為 5 × 77 mod 96 = 1）
公鑰 (e, n) = (5, 119)，私鑰 (d, n) = (77, 119)
加密：C = M^e mod n = 19^5 mod 119 = 66
解密：M = C^d mod n = 66^77 mod 119 = 19
```

用 Python 照著算一次，結果和講義相同：

```python
p, q, e = 7, 17, 5
n = p * q
phi = (p - 1) * (q - 1)
d = pow(e, -1, phi)
print(n, phi, d)
print(pow(19, e, n), pow(66, d, n))
```

```text
119 96 77
66 19
```

`pow(e, -1, phi)` 算的是「乘上 `e` 之後除以 `phi` 餘 1 的那個數」，也就是 `d`。`pow(19, e, n)` 是 19 的 `e` 次方再對 `n` 取餘數。

公開的只有 `e` 和 `n`。要算 `d` 必須知道 φ(n)，要算 φ(n) 必須知道 `p` 和 `q`。所以 RSA 的安全性建立在一件事上：從 `n` 分解出 `p` 和 `q` 很困難。講義那一頁的 RSA-129，n 有 129 位數，1977 年公布，到 1994 年才被分解。

### 這一題的 n 哪裡不對

題目頁給一行 `nc` 指令，連上去會印出三個數字：`N`、`e`、`cyphertext`（密文）。`N` 是一個幾百位的數字，正常情況下分解不了。

先看 `N` 的最後一位數字。兩個質數相乘，只要兩個都是奇數，乘積一定是奇數。如果 `N` 是偶數，其中一個質數只可能是 2，因為 2 是唯一的偶數質數。這樣另一個質數不需要分解，除以 2 就得到了。

進 `python3`，把題目給的三個數字貼進去：

```python
N = <題目給的 N>
e = <題目給的 e>
c = <題目給的 cyphertext>

print(N % 2)
```

印出 `0` 表示 `N` 能被 2 整除。接下來和講義範例的步驟完全相同：

```python
p = 2
q = N // 2
phi = (p - 1) * (q - 1)
d = pow(e, -1, phi)
m = pow(c, d, N)
print(m.to_bytes((m.bit_length() + 7) // 8, "big"))
```

`//` 是整數除法，數字很大時不能用 `/`，那會變成有誤差的小數。`m` 算出來是一個很大的整數，最後一行把它轉回位元組，印出來就是原本的文字。

RSA 的演算法在這一題沒有任何問題，壞的是產生金鑰的那段程式：它挑到了 2。這屬於第三條路，演算法以外的環節出錯。

## 實作三：n 太小的 RSA（Mind your Ps and Qs）

題目給一個檔案，裡面有 `c`、`n`、`e`。這次 `n` 是奇數，上一題的方法用不上；但它比正常的 RSA 金鑰短很多。

短到一定程度的數字，早就有人分解過並把結果公開。FactorDB（一個公開的因數分解資料庫）可以直接查：貼上 `n`，它回答 `p` 和 `q`。

拿到 `p`、`q` 之後，把示範那六行的前兩行換成查到的值，其餘照舊。

這一題屬於第二條路：金鑰太短，分解 `n` 這件事不再困難。

## 回頭看三條路

| 題目 | 演算法 | 被攻破的地方 | 怎麼避免 |
|---|---|---|---|
| caesar | 位移密碼 | 金鑰只有 25 種；字母頻率不變 | 不要用古典密碼保護任何東西 |
| hashcrack | MD5、SHA-1、SHA-256 | 密碼太常見，而且沒有加鹽 | 加鹽，並使用專為密碼設計的慢速雜湊 |
| EVEN RSA CAN BE BROKEN??? | RSA | 金鑰產生程式挑到 2 | 用經過檢驗的函式庫產生金鑰，不自己寫 |
| Mind your Ps and Qs | RSA | n 太短，已經被分解 | 金鑰長度至少 2048 位元 |

四題裡只有 caesar 是演算法本身不行。其餘三題的演算法到今天都還在使用（MD5 和 SHA-1 已不建議用於新系統），出問題的是金鑰長度、金鑰怎麼產生、拿來保護什麼樣的密碼。
