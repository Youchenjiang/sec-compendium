# Wireshark 基礎與封包分析 教師教學講義（20 分鐘）

> **課程代號**：`WORKSHOP_202610_NET_Wireshark-Fundamentals`  
> **時間規劃**：20 分鐘（3 分鐘工具定位 + 3 分鐘角色用途 + 10 分鐘實務情境 + 4 分鐘 AI 協同與 QA）  
> **教學方針**：以初學者能聽懂的語言為主。不背過濾標籤、不背協定封包格式，重點在於讓學員知道「能拿來做什麼、怎麼用它抓出網路問題」，並鼓勵善用 AI 工具查詢過濾語法。

---

## 一、 教學原則與準備

1. **不用教科書術語開場**：
   - 不要一上台就畫 OSI 七層模型或 TCP 標頭 20 bytes 結構。學員需要知道的是「平常遇到什麼問題時，打開這個工具有用」。
2. **用具體現象建立理解**：
   - 網頁打不開是伺服器問題還是網路問題？前端說發了請求、後端說沒收到，到底是誰的問題？這些都是實際工作上天天發生的事。
3. **把過濾語法交給 AI**：
   - 明確告訴學員：不用花時間背 `tcp.analysis.flags` 或 `ip.src == ...` 這種語法。只要把想查的條件（IP、Port、方法）告訴 AI，讓 AI 寫出過濾式，複製貼上即可。工程師的價值在於判斷問題原因與採取行動。

### 【第一階段：00:00 – 03:00】幹嘛？Wireshark 到底在做什麼？（投影片 1~2）

#### 投影片 1：封面開場（0:00 - 0:45）
- **講師台詞建議**：
  > 「大家好。今天這 20 分鐘，我們要介紹一門非常實用、幾乎所有網管、軟體工程師與資安人員都會用到的工具——**Wireshark**。  
  > 今天我們不考任何網路協定規格，也不需要大家死背指令。重點是讓大家知道：這套工具到底在幹嘛、不同工作職位的人怎麼拿它來解決問題，以及在遇到問題時，如何用 AI 幫你寫出過濾語法。」

#### 投影片 2：工具定位：看見網路到底發生了什麼事（0:45 - 3:00）
- **痛點切入**：
  > 「大家平常寫程式或上網一定遇過這種狀況：網頁一直轉圈圈打不開、或者是開發時前端工程師發誓 API 有送出，但後端工程師翻遍 Log 說沒收到。這時候大家只能各說各話，因為網路通訊在電線和空氣中是看不到的。」
- **說明原理**：
  > 「Wireshark 做的事情很單純：它藉由底層驅動，直接在你電腦的網路卡上進行『側錄』。只要有任何資料進出你的網卡，它就完整錄下來，並依照通訊協定的規格把裡面的欄位整理給你看。  
  > 到底封包有沒有發出去？有沒有收到對方的確認？回傳的狀態碼是 200 還是 500？抓包檔一打開，清清楚楚，完全不需要憑空猜測。」

### 【第二階段：03:00 – 06:00】誰在用？四大角色與介面配置（投影片 3~4）

#### 投影片 3：不同崗位的人，平常用 Wireshark 做什麼？（3:00 - 4:30）
逐一說明不同專業人員的實際用途：
1. **網路管理人員 (NetOps)**：
   - 公司網路突然很慢、頻寬被吃滿？抓包看是哪一台主機在狂送封包，或者是不是交換機設定錯誤導致廣播風暴。
2. **軟體開發工程師 (DevOps)**：
   - 前後端除錯必備。確認送出的 HTTP 標頭、JSON 參數對不對，或是串接第三方金流 API 為什麼逾時沒回應。
3. **資安防守人員 (Blue Team)**：
   - 某台電腦疑似中毒，看它到底在跟外面的哪一台 IP 連線？有沒有把檔案往外傳？網域名稱查詢正不正常？
4. **滲透測試人員 (Red Team)**：
   - 測試內網環境是否有系統還在用未加密的通訊協定傳送帳號密碼，或是分析物聯網 (IoT) 設備的自訂通訊格式。

#### 投影片 4：介面結構：三塊核心顯示區域（4:30 - 6:00）
- **消除介面恐懼**：
  > 「剛打開 Wireshark 的人常常被嚇到，因為滿螢幕都是密密麻麻滾動的英文。其實只要看懂三個區塊：」
  1. **上方【封包清單】**：像即時行車紀錄器，每一列代表一個封包，顯示時間、誰寄給誰、走什麼協定。
  2. **中間【協定細節】**：這是最常看的地方。點選某個封包後，中間可以層層展開：看 IP 位址、看 TCP 連接埠、看 HTTP 內容。
  3. **下方【原始位元組】**：底層真實的十六進位與文字。平常除錯 90% 的時間根本不需要看下方，看上方和中間就夠了。

### 【第三階段：06:00 – 16:00】實際應用情境（投影片 5~9）

#### 投影片 5：【情境 1】連線卡住或極慢？排查 TCP 重傳（6:00 - 8:30）
- **情境說明**：
  > 「使用者反映結帳按鈕按下去卡住 5 到 10 秒才跳出結果。維運人員看伺服器 CPU 使用率只有 15%，伺服器明明很閒，問題卡在哪？」
- **Wireshark 觀察**：
  - 在過濾列輸入：`tcp.analysis.flags`
  - 畫面上跳出大量黑底紅字的 `[TCP Retransmission]` 或 `[TCP Dup ACK]`。
- **原因說明**：
  > 「TCP 是一種要求可靠的通訊協定。當發送端把封包丟出去後，如果中途封包掉了，等不到接收端的回應 (ACK)，它就會等個幾秒再重新發送一次。  
  > 這就證明不是後端程式跑得慢，而是中間的實體線路、WiFi 訊號或防火牆正在掉包！維運人員把這個抓包紀錄存下來交給電信商或機房，問題就清楚了。」

#### 投影片 6：【情境 2】為什麼不能用未加密協定？HTTP 明文帳密側錄（8:30 - 11:00）
- **情境說明**：
  > 「大家都知道登入網站要用 HTTPS，不能用 HTTP。但到底為什麼？我們直接看抓包結果。」
- **Wireshark 觀察**：
  - 輸入過濾條件：`http.request.method == "POST"`
  - 點開中間的表單內容，直接看到：
    - `username: admin`
    - `password: SuperSecret2026!`
- **結論**：
  > 「HTTP 傳輸的內容完全是純文字。同一個區網只要有人開啟 Wireshark 側錄，所有帳號密碼都看得一清二楚。這就是為什麼現代網站與 API 必須全面強制使用 HTTPS (TLS 加密)。」

#### 投影片 7：實用功能：Follow TCP Stream 重組完整對話（11:00 - 12:30）
- **操作技巧**：
  > 「一個網頁請求或 JSON 回應，常常被網路切成十幾個 1500 bytes 的小封包。如果一個個點開看，會非常痛苦。  
  > 只要在任何一個封包上按滑鼠右鍵 ➔ `Follow` ➔ `TCP Stream`，Wireshark 就會自動按照封包序號把資料拼好。  
  > 視窗裡**紅色**代表客戶端發送的 Request，**藍色**代表伺服器端回傳的 Response。整段對話就像通訊軟體聊天紀錄一樣呈現，前後端排錯 3 秒搞定。」

#### 投影片 8：加密對比：HTTP vs. HTTPS 側錄對比（12:30 - 14:00）
- **常見疑問**：
  > 「那網站用了 HTTPS 之後，Wireshark 是不是就完全沒用了？」
- **重點對比**：
  - 傳輸內容確實被加密成隨機亂碼，Wireshark **無法直接偷看加密內容**。
  - 但 Wireshark 依然看得到：
    1. 你連向哪一台伺服器 IP 與 Port。
    2. 你連線的網域名稱（在 TLS 交握的 SNI 欄位可以看到）。
    3. 連線的時間、頻率與傳送了多少資料量。
  - 對資安與網管來說，光是知道「誰在什麼時候連去哪裡、傳了多少資料」，就足以判定大部分的異常連線。

#### 投影片 9：【情境 3】電腦沒在用卻有流量？排查異常外連（14:00 - 16:00）
- **情境說明**：
  > 「下班時間辦公室電腦沒人使用，螢幕待機鎖定，但網路卡的燈卻每隔幾秒閃一下。」
- **Wireshark 觀察**：
  - 過濾 `dns` 或是查看對外的連線。
  - 發現系統每隔 10 秒固定查詢一個奇怪的域名，隨後往該外部 IP 發送微小封包。
- **處理方式**：
  > 「很多惡意軟體在背景執行時，會定期向外部控制主機 (C2) 發送心跳連線。即便它在 Windows 工作管理員隱藏自己，只要它想對外通訊，封包就一定要從實體網卡發送出去。資安人員抓到對外連線的 IP 後，就能立刻在防火牆阻斷，並隔離電腦處理。」

### 【第四階段：16:00 – 20:00】AI 協同、課後思考與 QA（投影片 10~12）

#### 投影片 10：不用死背過濾語法：用 AI 快速生成 Wireshark Filter（16:00 - 17:30）
- **教學核心**：
  > 「請大家記住：千萬不要去死背 Wireshark 的過濾標籤。現在有了 ChatGPT、Claude、Gemini 等 AI 工具，你只要用白話文描述你的需求，AI 就會直接產生過濾條件。」
- **示範案例**：
  - 描述：「我想看發往 192.168.1.1 的 HTTP POST」 ➔ AI 生成：`ip.dst == 192.168.1.1 && http.request.method == "POST"`
  - 描述：「抓出所有網路掉包與重傳的封包」 ➔ AI 生成：`tcp.analysis.flags`
  - 描述：「只看 DNS 查詢，排除內網流量」 ➔ AI 生成：`dns && !(ip.addr == 192.168.0.0/16)`
- **結論**：人類負責把問題想清楚，語法交給 AI 翻譯，複製貼上即可。

#### 投影片 11：課後思考與常見問題對照（17:30 - 19:00）
與學員進行互動回顧：
1. **問題一**：前後端工程師吵架，一個說有發 API，一個說沒收到，開 Wireshark 怎麼看？
   - *重點*：右鍵 `Follow TCP Stream`，直接看雙向傳輸文字，確認是否有送出與回傳。
2. **問題二**：在 HTTPS 連線下，Wireshark 雖然看不到傳輸內容，但還看得到什麼？
   - *重點*：連線目標 IP、訪問的網域名稱 (SNI)、連線時間、頻率與傳輸大小。
3. **問題三**：看到一堆黑底紅字的 TCP Retransmission，代表誰的問題？
   - *重點*：代表實體網路、WiFi 訊號或設備嚴重掉包，不是後端程式碼問題。

#### 投影片 12：總結與練習資源（19:00 - 20:00）
- **三大重點總結**：
  1. 網路問題以真實封包為準，不用憑空猜測。
  2. 語法交給 AI 生成，把精力放在定義排錯需求。
  3. 善用 Follow TCP Stream，快速重組完整通訊。
- **自學資源**：
  - Wireshark 官方範例庫（Sample Captures）：免費下載幾百種真實協定 pcap 檔案練習。
- **開放現場提問交流**。
