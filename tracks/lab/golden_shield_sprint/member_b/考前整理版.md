## 🔧 Reverse：組語 & 暫存器
- `test eax,eax` + `je` = **判斷 eax 是否為 0**。
- `lea` = 算位址(不解參照)；`mov [..]` = 讀記憶體內容。
- `cmp a,b` = 做 `a-b` 只設旗標。`call` = push 返回位址+跳；`ret` = pop 回去。
- 回傳值 = **eax/rax**；棧頂 = esp/rsp；指令指標 = eip/rip(Pwn 終極目標)。
- 棧**由高往低**長；蓋掉返回位址 → 劫持流程。

## 📞 呼叫慣例（必考差異）
- **x64 Linux(System V)**：`RDI RSI RDX RCX R8 R9`。
- **x64 Windows**：`RCX RDX R8 R9`（+32B shadow）。
- **cdecl**=呼叫方清棧(支援可變參數)；**stdcall**=被呼叫方清棧`ret n`(Win32 API)。

## 🧩 PE & 脫殼
- `VA = ImageBase + RVA`；**IAT**=匯入函數位址表；**OEP**=脫殼後找的原始入口。
- **UPX** → `upx -d` 脫；**ESP 定律** → stub 跑完 ESP 復原，對 ESP 下硬體斷點找 OEP。
- **DIE(Detect It Easy)** → 辨識殼/編譯器/檔案類型（≠sqlmap）。
- 檔頭：**MZ(`4D5A`)=Windows PE、`7F454C46`=Linux ELF**、PK=ZIP、%PDF、89PNG、FFD8 JPG。
- IDA 箭頭：**綠=條件成立、紅=不成立、藍=無條件**。

## 🕵️ 反除錯
- `IsDebuggerPresent` = 查 PEB BeingDebugged；**NtGlobalFlag**；`rdtsc` 時間差。
- **INT 3 = `0xCC`**：軟體斷點會插 `0xCC`，掃它即偵測被下斷點。

## 💉 注入順序（背死）
`OpenProcess → VirtualAllocEx → WriteProcessMemory → CreateRemoteThread`（開→配→寫→跑）。
- Process Hollowing(掉空) → **Hollow Hunter** 偵測。DLL 搜尋順序劫持 = 只給檔名未給完整路徑。

## 🛡️ Pwn 保護機制（防什麼 / 怎麼繞）
| 機制 | 防 | 繞 |
|:--|:--|:--|
| **NX/DEP** | 棧跑 shellcode | **ROP** |
| **ASLR/PIE** | 位址固定 | **洩漏位址** |
| **Canary** | 棧溢位 | 洩漏/精準蓋/爆破；被改→`__stack_chk_fail` |
| **Full RELRO** | GOT 覆寫 | GOT 唯讀擋死 |
> ⚠️ NX↔ROP、ASLR↔洩漏位址,別配反。checksec 看這四項。

## 💥 溢位 / ROP / 格式化字串
- **ret2text**=跳程式自身碼；**ret2libc**=跳 libc(`system("/bin/sh")`)。皆繞 NX。
- gadget = 以 `ret` 結尾的碼片段；**one_gadget** = libc 中單跳即 execve。
- **格式化字串**：`%p/%x`=洩漏、`%s`=讀、`%n`=**寫**(任意寫)。
- Heap：UAF(釋放後用)、Double Free、tcache 毒化。整數溢位 ≠ NULL deref。

## 🐧 Linux 提權
- **SUID** `find / -perm -4000`(減號=含有)→ GTFOBins。
- **Capabilities** `getcap -r /`；`cap_setuid` 可提權。
- **Dirty COW**(CVE-2016-5195)= copy-on-write 競態 → 寫唯讀檔提權。

## 🌐 網路通識（B 分攤）
- **IPsec**：**AH 不加密(只認證)、ESP 加密**；**Transport**(主機對主機,只 payload)/**Tunnel**(整包封裝,站對站 VPN)。
- **VPN**：site-to-site(閘道對閘道)/ client-to-site(遠端使用者連進來)。
- **SNMP**：v1/v2c 明文 community、**v3 才加密認證**；**UDP 161(agent)/162(trap)**。
- **ARP 欺騙**防禦=**DAI**；**VLAN hopping**=switch spoofing + double tagging。
- **TCP 握手** SYN→SYN-ACK→ACK；**SYN Flood** 塞滿 **SYN_RECV** → 防 **SYN cookies**；**TIME_WAIT** 等 2MSL。
- **DNS 放大** = 偽造來源 IP + 小查詢換大回應；**DNSSEC** 記錄 = RRSIG/DNSKEY/DS/NSEC。

## 🧰 工具誘答（全員必會）
- **gflags = Windows 除錯旗標,非掃描**(2024 誘答)。
- **DIE ≠ sqlmap**；**ffuf** 是 web fuzzing 非除錯。
- **1768.py** 抽 Cobalt Strike 設定；**Hollow Hunter** 偵測掉空；**Regshot** 比對登錄檔(皆 2024)。
- x64dbg 除 64 位元 / x32dbg 除 32 位元,要對應。
- Pwn 工具組：checksec / pwntools / gdb+pwndbg / ROPgadget / one_gadget。

## 📖 脈絡故事版 —「一隻惡意程式的逆向到打靶之旅」
> 把所有考點用一條因果線串起來，順著讀一遍，概念就接起來了。**粗體=考點**。

你是紅隊，手上拿到一個來路不明的執行檔，任務是搞懂它、找出它攻擊伺服器的方式。

**第一步：這是什麼？** 你先用 **Detect It Easy（DIE）** 掃一眼——它不是 sqlmap、是「辨識檔案類型/編譯器/殼」的工具。DIE 告訴你：檔頭是 **`4D 5A`（MZ）→ 這是 Windows PE 執行檔**（如果是 `7F 45 4C 46` 就是 Linux ELF），而且**加了 UPX 殼**。加殼就像把程式包進壓縮袋，直接反組譯只會看到解壓用的 stub。

**第二步：脫殼。** UPX 很乖，`upx -d` 多半能直接脫。萬一是改過的殼，你就用 **ESP 定律**：殼的 stub 跑完、把原程式解壓到記憶體後，**ESP（棧頂指標）會回到初始值**——對那個 ESP 下一個硬體斷點，程式停下來時就接近 **OEP（原始進入點）**，你 dump 下來就得到乾淨的程式。

**第三步：讀它的邏輯。** 丟進 **IDA / Ghidra**（Ghidra 是 NSA 免費版、還能反編譯）。你開始讀組語：`mov` 搬資料、`lea` 算位址（不解參照）、`cmp` 和 `test` 設旗標、`je/jne` 條件跳。IDA 的圖形視圖用箭頭顏色幫你——**綠=條件成立、紅=不成立、藍=無條件**，照著顏色就能走通控制流。看到 `call` 你知道它 push 返回位址再跳，`ret` 再彈回來。要看懂函數在傳什麼參數，得先認出**呼叫慣例**：這是 64 位元 Windows 程式，所以前四個參數在 **`RCX RDX R8 R9`**（如果是 Linux 就是 `RDI RSI RDX RCX R8 R9`）；回傳值永遠看 **rax**。

**第四步：它在反偵查。** 單步除錯時程式一直自殺——它在**反除錯**：呼叫 **`IsDebuggerPresent`**（讀 PEB 的 BeingDebugged 旗標）、檢查 **NtGlobalFlag**、甚至自己掃程式碼裡有沒有 **`0xCC`（INT 3）**——因為你下的軟體斷點就是把目標位元組偷換成 `0xCC`。你一一繞過。

**第五步：它想幹嘛？** 你看 **PE 的 IAT（匯入位址表）**，發現它匯入了一串 API，順序是 **`OpenProcess → VirtualAllocEx → WriteProcessMemory → CreateRemoteThread`**——這就是教科書級的**遠端執行緒注入**（開目標程序→在裡面配記憶體→寫入惡意碼→建執行緒跑它）。它還可能做 **Process Hollowing（掉空）**，而藍隊會用 **Hollow Hunter** 抓到它。

**第六步：換你打伺服器。** 這隻程式的目標是一台 Linux 服務。你拿到那個服務的二進位，先 **`checksec`** 看它開了哪些盾：**NX、ASLR、Canary、RELRO**。你找到一個 **緩衝區溢位**——理論上蓋掉棧上的返回位址就能控制 **rip**。但盾一個個擋你：

- **NX** 讓棧不能執行，你沒法在棧上放 shellcode → 改用 **ROP**，把一堆以 `ret` 結尾的 **gadget** 串起來，重用程式**自身**的碼（**ret2text**）或跳進 **libc** 呼叫 `system("/bin/sh")`（**ret2libc**）。
- **ASLR** 讓位址每次都變 → 你得先**洩漏一個位址**才能算出基底；手上剛好有個**格式化字串**漏洞，用 **`%p`/`%x` 洩漏**棧上的值（而 `%s` 是讀指標指向的記憶體、`%n` 是往記憶體**寫**）。
- **Canary** 擋在緩衝區和返回位址之間，溢位會先撞到它 → 你先把它洩漏出來、原值填回去，否則函數返回前會呼叫 **`__stack_chk_fail`** 直接中止。
- 最後想覆寫 GOT 改函數指標？若是 **Full RELRO**，GOT 唯讀，這條路封死。

你串好 **ROP 鏈（用 ROPgadget 找料、one_gadget 找現成的 execve）**，透過 **pwntools** 打出去，拿到一個 shell。

**第七步：提權。** 進去是低權限，你找 **SUID** 檔（`find / -perm -4000`，減號代表「含有」該位元）對照 GTFOBins；或看 **Capabilities**（`getcap -r /`，有 `cap_setuid` 就能提）；真不行還有老招 **Dirty COW**（copy-on-write 競態，寫進唯讀檔）。你變成 root。

**第八步：它怎麼在網路上活動。** 最後你分析它的連線。它走 **IPsec** 加密通道——記得 **AH 只認證不加密、ESP 才加密**；用 **Tunnel 模式**（整包封裝，站對站）而非 Transport（只保護 payload）。它透過 **VPN**（site-to-site 連兩個網路）回連。偵查階段它打過 **SNMP**（v1/v2c 明文 community、**v3 才加密**，埠 **UDP 161/162**）。它對目標發動過 **SYN Flood**，把伺服器塞滿卡在 **SYN_RECV** 的半開連線（防禦是 **SYN cookies**）；也用過 **DNS 放大**（偽造來源 IP、小查詢換大回應）。而這一切 TCP 連線，都始於那個 **SYN → SYN-ACK → ACK** 的三次握手。

**故事收束**：辨識(DIE/MZ) → 脫殼(UPX/ESP 定律/OEP) → 讀碼(組語/呼叫慣例/IDA 顏色) → 繞反除錯(IsDebuggerPresent/0xCC) → 看它意圖(IAT/注入順序) → 打靶(溢位→NX/ROP、ASLR/洩漏、Canary、RELRO) → 提權(SUID/caps/DirtyCOW) → 網路(IPsec/VPN/SNMP/TCP/DNS)。一條線，全考點。

### 🧠 最後五句免疫
1. x64 傳參：Linux `RDI RSI RDX RCX R8 R9`、Windows `RCX RDX R8 R9`。
2. NX↔ROP、ASLR↔洩漏位址（別配反）。
3. 格式化字串 `%n` 是寫、`%s` 是讀。
4. AH 不加密、ESP 才加密；SNMP v3 才加密、埠 161/162。
5. gflags 非掃描、DIE 非 sqlmap、MZ=PE/7F=ELF。
