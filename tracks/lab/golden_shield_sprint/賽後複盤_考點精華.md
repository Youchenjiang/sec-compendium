## 🔐 密碼學與安全協定（隊員 C ＋ 通識）

### SSL/TLS vs S-HTTP（不可否認性・經典陷阱）
| 特性 | SSL/TLS | S-HTTP |
|:--|:--:|:--:|
| 運作層級 | 傳輸層之上（通道式） | 應用層（訊息式） |
| 機密性 / 完整性 / 身分鑑別 | ✓ | ✓ |
| **不可否認性** | **✗** | **✓** |
| 保護單位 | 整條連線 | 單一訊息 |
| 適用範圍 | 任何上層協定 | 只限 HTTP |

- **為何 SSL 無不可否認性**：握手後用「雙方共享的對稱金鑰 + MAC」保完整性，任一方都能產生同樣 MAC → 無法證明某訊息是誰送的。數位簽章只用在握手階段身分驗證。
- **為何 S-HTTP 有**：以訊息為單位，可用「發送者私鑰」對每則 HTTP 訊息做數位簽章（PKCS#7/CMS）→ 只有發送者有私鑰 → 不可否認。
- 📌 補充：**SET**（雙重簽章）也具不可否認性，常與 SSL 一起比較。
- ⚠️ 這是**教科書標準答案**（考試取向）；現代 TLS 用戶端憑證另當別論。

### HTTPS vs S-HTTP（兩者不同，別混）
| | HTTPS | S-HTTP |
|:--|:--|:--|
| 做法 | HTTP over SSL/TLS（通道） | 修改 HTTP，訊息層級保護 |
| URL | `https://` | `shttp://` |
| Port | 443 | 80 |
| 不可否認性 | ✗（沿用 SSL） | ✓ |
| 現況 | 業界標準 | 幾乎淘汰（RFC 2660） |
> 記法：**HTTPS 屬 SSL 這一派，性質同 SSL**；S-HTTP 是另一套訊息式協定。

### 非對稱金鑰用途（私鑰簽章・公鑰加密）
| 目的 | 用誰的哪把鑰匙 | 對方處理 |
|:--|:--|:--|
| **數位簽章** | 發送者**私鑰**簽 | 發送者**公鑰**驗 |
| **加密** | 接收者**公鑰**加密 | 接收者**私鑰**解 |
- 簽章 → 身分鑑別 + 完整性 + 不可否認；加密 → 機密性。
- 細節：簽章對「訊息雜湊」簽；加密實務用**數位信封**（公鑰加密一把對稱會議金鑰，再用對稱金鑰加密內容）。
- 兩個都要：先自己私鑰簽，再對方公鑰加密。
- ⚠️ 陷阱：「用接收者私鑰簽章」「用發送者公鑰加密」都是**錯的**。

### 臨時金鑰 / 前向保密
- **DH 金鑰交換**：不安全通道協商出臨時共享會議金鑰；每次連線都新產生 = **DHE / ECDHE（Ephemeral）** → **前向保密（Forward Secrecy）**（長期私鑰外洩也解不開過去連線）。
- 其他會「產生臨時物」的：數位信封（一次性對稱金鑰）、TLS 握手（session key）、OTP（一次性密碼）、Kerberos（有時效的 ticket + session key）。

## 🔎 數位鑑識（隊員 C）

### 可作為完整法律證據的拷貝方式
- **答案：位元流複製（Bit-stream copy / 鑑識映像檔 forensic image）**。
- 一般「檔案複製（邏輯複製）」不行，會漏：已刪除未覆寫檔案、未配置空間、slack space、隱藏分割區/MBR，且可能改動時間戳。
- 要點：整顆媒體逐 bit 複製 + **Write Blocker 防寫** + 複製前後**雜湊比對（MD5/SHA）** + **證據保管鏈**。
- 工具：`dd`、FTK Imager、EnCase（.E01）。
> 陷阱：「backup」「檔案複製」都不能當完整證據，**只有位元流複製可以**。

### Process Explorer（Sysinternals）顏色
| 顏色 | 意義 |
|:--|:--|
| **紫色** | **可能加殼（packed）— 資安最需注意** |
| 粉紅 | Windows 服務（如 svchost） |
| 淺藍 | 與啟動 PE 同帳號執行的程序 |
| 綠 / 紅 | 新啟動 / 正在結束（短暫） |
| 深藍 | 目前被選取 |
| 深灰 | 被暫停（suspended） |
| 黃 | .NET 程序 |
| 青 | Windows Store App |
- 功能：樹狀父子關係（看可疑程序誰啟動）、載入的 DLL/Handle、驗數位簽章、整合 VirusTotal。
- 同門工具：Process Monitor（即時監控檔案/登錄檔/網路）、Autoruns（開機自啟/持久化）、TCPView（連線）。
> 記法：看 DLL/程序關係→Process Explorer；即時記錄檔案登錄檔行為→Process Monitor；**紫色=加殼**。

## 🌐 網路通識（全員分攤）

### 代理伺服器（監控 ＋ 加速）
- 情境「主管要監控上網、員工嫌慢」→ **Proxy Server**：所有流量經 Proxy 可記錄/過濾（監控）＋ **快取**常用網頁（加速、省頻寬）。
- 誤選：負載平衡器（分散服務端流量，不監控）、VPN（加密反增負擔）、防火牆（存取控制，無加速）。

### 監聽整個網段的流量
- **網卡開啟「混雜模式（Promiscuous Mode）」** → 收所有經過的封包（Wireshark/tcpdump 用）。
- 交換器環境光開混雜模式不夠 → 還要在交換器設 **Port Mirroring（Cisco 叫 SPAN）** 把其他埠流量複製過來。（早期 Hub 會洪泛到所有埠，開混雜即可。）

### SNMP（集中監控設備）
| Port | 用途 | 誰在聽 |
|:--|:--|:--|
| **161** | 管理端查詢/設定（Get/Set） | 被管設備（Agent） |
| **162** | 設備主動通報（Trap/Inform） | 網管電腦（Manager） |
- **主要跑 UDP**（考試以 UDP 為準）。v1/v2c 明文 community、**v3 才加認證加密**。
- 補充：集中收系統日誌 → **Syslog，UDP 514**。

### IGMP Snooping
- 交換器（L2）「偷聽」IGMP Join/Leave，只把**群播（multicast）**封包送到有加入群組的埠，避免像廣播般洪泛到所有埠 → 省頻寬。應用：IPTV、視訊會議、串流。

### TCP SYN 掃描判讀（送 SYN 探測主機/port）
| 送 | 回應 | 意義 |
|:--|:--|:--|
| SYN | **SYN-ACK** | **port 開、主機存在**（服務在聽）✅ |
| SYN | **RST（RST-ACK）** | 主機存在，但 port 關閉 |
| SYN | 沒回應 / ICMP unreachable | 被防火牆過濾（filtered）或主機不在 |
- 問「主機在 + port 開」→ 收到 **SYN-ACK**（三次握手第二步 SYN→**SYN-ACK**→ACK）。
- **半開掃描（half-open / stealth，nmap `-sS`）**：收到 SYN-ACK 後**改送 RST 不完成握手**，較隱蔽。
- 收到 RST 也證明主機存活（只是 port 關）；完全無回應才分不清關機或被擋。
> 秒記：**回 SYN-ACK=開、回 RST=關、沒回=被擋/不在**。

### ICMP 類攻擊與防禦
| 攻擊 | 手法 | 別名 |
|:--|:--|:--|
| **Ping Flood** | 直接灌大量 ICMP Echo Request | ICMP Flood、洪泛 |
| **Smurf** | 偽造來源 IP，對**廣播位址**發 ping，整網段回應淹受害者（放大） | 藍精靈、ICMP 放大/反射 |
| **Ping of Death** | 送 >65535 bytes 畸形 ICMP，重組當機（靠異常非數量） | 死亡之 Ping |
| **Fraggle** | 同 Smurf 但用 **UDP**（echo 7 / chargen 19） | — |
- **防禦**：一般 ICMP Flood → **ICMP 速率限制（Rate Limiting）**；**Smurf → 關閉 IP 導向廣播**（Cisco `no ip directed-broadcast`）+ 入口過濾 + 主機忽略廣播 ping。
- ⚠️ **廣播風暴（Broadcast Storm）不是攻擊**，是 L2 迴圈造成廣播無限循環 → 解法 **STP**。

## 🛡️ 威脅情資術語（通識・易混）
| 術語 | 是什麼 | 關鍵字 |
|:--|:--|:--|
| **IoC**（Indicator of Compromise，入侵指標） | 判斷是否被入侵的**特徵資訊** | 惡意程式 **Hash**、**C2/中繼站 IP/網域**、惡意檔名/機碼 |
| **IoT**（Internet of Things） | 物聯網**裝置** | 攝影機/路由器/智慧家電、預設密碼、Mirai、當跳板 |
| **Bot** | 被 C&C 遠端控制的**受害電腦** | 被感染、聽命、多台組成 Botnet |
> 簡記：問**特徵資訊**→IoC；問**設備類型**→IoT；問**被控制的機器**→Bot。（IoC 與 IoT 字很像，看清楚！）

## 🧩 逆向工程 — IDA scattered argument（隊員 B）
- IDA/Hex-Rays `__usercall` 的「分散式參數位置」：一個大參數（常是 struct）被拆到多個暫存器。
- 格式：`argoff:register^regoff.size`（argoff=參數內位移、register=暫存器、regoff=暫存器內位移、size=位元組數），多段逗號隔開。
- 例：`0:r12.4, 4:r13` → 參數第 0~3 byte 放 r12 低 4 bytes（r12d）、第 4 byte 起放 r13。
- 暫存器對寫法 `@<r13:r12>`：高:低，每個滿版 8 bytes（= `<0:r12, 8:r13>`）。
- 前 8 bytes 放 r12、後 4 bytes 放 r13d → 寫 `<0:r12.8, 8:r13.4>`。
> 常見於 Go 或最佳化後的內部函式等非標準呼叫慣例。

## 🖥️ 識圖題：這是什麼設備的管理介面？（通識）
- **題型**：給一張管理介面截圖，問「這是什麼裝置/工具的介面」，四選一。
- **回憶到的介面特徵**：偏網管大範圍使用、**有 WAF 選項**、**出口可選 www（服務/應用）**、**來源範圍可選「所有 IP」**。
- **判定答案：UTM（整合式威脅管理設備）/ 次世代防火牆（NGFW）**。
  - WAF 被當成內建可選模組 → 只有**整合式資安閘道（UTM/NGFW）**會把 WAF 與防火牆放同一介面。
  - 依「服務/應用（www）」套策略 = NGFW 的應用辨識特徵；來源選「所有 IP」= any 條件。
- **選項對應**：有 UTM 選 UTM；只有「防火牆/NGFW」則選防火牆；**排除** 代理伺服器（無整合 WAF）、負載平衡器（重點是後端池/健康檢查）、IDS/IPS（只偵測）。
> 記法：**介面同時有「WAF ＋ 防火牆 ＋ 應用/服務分類 ＋ 全 IP 範圍」→ UTM / NGFW**。
> ⚠️ 此為依回憶特徵重建的最佳判定；若日後取得原截圖與四選項，再核對確認。

## 🔴 判讀題：URL 編碼的 payload 是什麼攻擊？（Web・隊員 A）
- **題型**：給一串 URL 編碼 payload（含 `1 or` 與一堆 `%2x`），問這是什麼攻擊，選項含 SQL injection、XSS 等。
- **答案：SQL 注入（SQL Injection）**。
- **關鍵**：那些 `%2x` 是 URL 編碼的 SQLi 字元——**`%27`=`'`（單引號，招牌）**、`%20`=空格、`%2D%2D`=`--`、`%3D`=`=`、`%23`=`#`。
  ```
  1%27%20or%20%271%27%3D%271  →  1' or '1'='1
  1%27%20or%201%3D1%20--      →  1' or 1=1 --
  ```
- **為何不是 XSS**：`1 or`＋`%27` 是打資料庫（布林恆真）；XSS 會是 `%3Cscript%3E`、`alert`、`%3C`/`%3E`（打瀏覽器）。
- **秒殺辨識**：先解碼看字元 → `%27`(')／`or`／`%3D`(=)／`%2D%2D`(--) = **SQLi**；`%3C%3E`(<>)／`script`／`alert` = **XSS**。
> ⚠️ 看到 URL 編碼先解碼再判型，別被 `%` 嚇到；`%27`（單引號）是 SQLi 最強指紋。

### 🧠 一句話速記串
SSL 無不可否認(對稱MAC)／S-HTTP 有(訊息簽章)；HTTPS=HTTP over SSL(443)、S-HTTP(shttp://80)。私鑰簽、對方公鑰加密；DHE/ECDHE=臨時金鑰+前向保密。法律證據=位元流複製(+防寫+雜湊+保管鏈)。Proxy=監控+快取。混雜模式+Port Mirroring 監聽網段。SNMP UDP 161/162、Syslog 514。Smurf=導向廣播放大(關 directed-broadcast)、廣播風暴靠 STP。IoC=特徵/IoT=設備/Bot=肉雞。PE 紫色=加殼。
