> 
> 這是典型的 **GPO 惡意劫持與批次持久化（GPO Abuse / Mass Persistence）**！

## 🧩 第一動：底層機制解剖——GPO 是如何在全網生效的？

群組原則（Group Policy Object）不是單一檔案，它是**一個分散式架構**，由儲存在 AD 資料庫中的元數據，與儲存在共享資料夾中的實體檔案共同組成。

### 1.1 GPO 的雙重結構：GPC 與 GPT

當你在群組原則管理主控台（GPMC）建立一個原則時，底層會同步產生兩個核心組件：

```
[Group Policy Object (GPO)]
  ├── 1. GPC (群組原則容器 - Group Policy Container)
  │      • 存放位置：Active Directory 資料庫 (ntds.dit) 內部 CN=Policies,CN=System...。
  │      • 內容：GPO 的屬性、版本號、狀態（啟用/停用）與客戶端擴展清單。
  │      • 存取方式：透過 LDAP (TCP 389) 讀取。
  │
  └── 2. GPT (群組原則範本 - Group Policy Template)
         • 存放位置：DC 的共享目錄 \\corp.local\SYSVOL\corp.local\Policies\{GUID}\
         • 內容：包含真實的設定檔、腳本（.bat/.ps1）、登錄檔資訊 (registry.pol)。
         • 存取方式：客戶端透過 SMB (TCP 445) 同步下載。

【版本同步的核心機制】：
• GPC 與 GPT 各自維護一個「版本號碼（Version Number）」。
• 客戶端每次開機或執行 gpupdate 時，比對這兩個版本號是否大於本地目前的版本號。
• 若版本號有增加，客戶端立即拉取最新的 registry.pol 並應用生效！
```

### 1.2 GPT 實體目錄結構解構

進入 `\\corp.local\SYSVOL\Policies\{31B2F340-016D-11D2-945F-00C04FB984F9}\`，你可以看到具體的配置核心：

```
{GUID}/
  ├── gpt.ini                     : ★ 記錄目前 GPT 的版本號與名稱。
  ├── Machine/ (電腦設定)
  │     ├── Registry.pol          : 二進位登錄檔！存放所有電腦層級的登錄檔變更。
  │     ├── Scripts/ (Startup)    : 開機前執行的批次檔或 PowerShell 腳本（黑客最愛藏後門的地方！）。
  │     └── Preferences/          : 群組原則喜好設定（可能藏有被棄用的 cpassword 明文密碼！）。
  └── User/ (使用者設定)
        ├── Registry.pol          : 使用者層級的登錄檔變更。
        └── Scripts/ (Logon)      : 使用者登入時執行的腳本。
```

### 1.3 客戶端擴展（CSE, Client-Side Extensions）處理流程

當客戶端下載原則後，會將不同設定派發給對應的 CSE DLL 動態庫進行解析（註冊於 `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon\GPExtensions`）：
- **Registry CSE** (`{35378877-0051-11d0-8229-00C04FB984F9}`)：解析 `registry.pol` 並寫入本機登錄檔。
- **Scripts CSE** (`{42B5FA82-575C-11d0-B28E-00C04FB984F9}`)：在指定生命週期以 SYSTEM 權限派生腳本。
- **Security CSE** (`{8277a931-d78e-11d0-8889-00c04fb984f9}` - `scecli.dll`)：套用密碼原則與受限制群組。

## 🧭 第二動：解碼意圖——GPO 惡意利用與異常速查表

黑客若取得網域權限，必然會利用 GPO 實現全網控制。你該如何依據特徵識別？

### 2.1 GPO 異常特徵與攻擊手法速查表

| GPO 變更與日誌特徵現象（看到什麼） | 底層成因與攻擊手法（是什麼攻擊） | 威脅影響與處置優先級（怎麼應對） |
| :--- | :--- | :--- |
| **GPO 中新增了開機腳本（Startup Script），指向非標準共用路徑** | **全網批次木馬植入（GPO Script Persistence）**：<br>攻擊者在 Computer Configuration 的 Scripts 中加入惡意腳本，全網工作站開機時以 `NT AUTHORITY\SYSTEM` 最高特權自動執行。 | • **影響**：全網所有電腦同時失陷，成為殭屍網絡。<br>• **優先級**：🚨 緊急（立即從 GPO 中移除該腳本連結）。 |
| **GPO 變更了 `Restricted Groups`，將非官方帳號加入 Administrators** | **全網本機管理員後門（Local Admin Injection）**：<br>攻擊者利用受限制群組功能，強制將特定帳號同步為全網每台工作站的本地管理員。 | • **影響**：黑客獲得全網任意機器的本地特權。<br>• **優先級**：🚨 緊急（還原該 GPO，並立即重置/刪除該帳號）。 |
| **全網 Defender / 防火牆設定突然變更為「停用（Disabled）」** | **防禦癱瘓與盲化（Defense Impairment）**：<br>攻擊者下發 GPO，竄改 `HKLM\SOFTWARE\Policies\Microsoft\Windows Defender`，全面關閉端點安全防護。 | • **影響**：全網端點失去防護，隨時遭遇勒索病毒。<br>• **優先級**：🚨 緊急（啟動應急 GPO 強制還原安全設定）。 |
| **SYSVOL 目錄下的 XML 檔案中出現 `cpassword` 屬性** | **GPO 密碼洩漏（MS14-025 歷史弱點）**：<br>舊版 GPO 喜好設定在 XML 檔案中儲存了 AES 加密密碼，因微軟公開了固定金鑰，黑客可在 1 秒內解密出明文管理員密碼。 | • **影響**：任何網域使用者皆可讀取該密碼並提權。<br>• **優先級**：🔴 高（搜尋全 SYSVOL 並徹底刪除帶 cpassword 的 XML）。 |
| **普通使用者帳號對特定 GPO 具備「寫入（Write）」或「建立所有子物件」權限** | **GPO 存取控制列表過度授權（GPO ACL Abuse）**：<br>權限委派不當，攻擊者拿下該普通帳號即可任意編輯 GPO，進而提權成為 Domain Admin。 | • **影響**：潛在的特權提升路徑（Privilege Escalation）。<br>• **優先級**：🔴 高（撤銷非管理員對 GPO 的寫入 ACL）。 |

## 💻 第三動：現場追兇——GPO 排查與變更日誌審計

### 3.1 端點現場診斷指令（CMD / PowerShell）

```cmd
:: 強制立即從 DC 下載並應用所有原則（不論版本號是否有變更）
gpupdate /force
```

### 3.2 網域控制站 GPO 權限與變更審計（PowerShell 自動化工具）

#### 自動化腳本：`gpo_security_baseline_audit.ps1`
```powershell
<#
.SYNOPSIS
    GPO 資安基線與異常編輯審計腳本 (gpo_security_baseline_audit.ps1)
#>
Import-Module GroupPolicy -ErrorAction SilentlyContinue

Write-Host "=== [1] 掃描全網具備危險寫入權限的非管理員帳號 ===" -ForegroundColor Cyan
Get-GPO -All | ForEach-Object {
    $gpo = $_
    $acl = Get-GPPermissions -Guid $gpo.Id -All -ErrorAction SilentlyContinue
    $acl | Where-Object { 
        $_.Trustee.Name -notmatch "(Domain Admins|Enterprise Admins|SYSTEM|Enterprise Domain Controllers)" -and 
        $_.Permission -match "(GpoEdit|GpoEditDeleteModifySecurity)"
    } | ForEach-Object {
        [PSCustomObject]@{
            GPOName    = $gpo.DisplayName
            Trustee    = $_.Trustee.Name
            Permission = $_.Permission
        }
    }
} | Format-Table -AutoSize

Write-Host "`n=== [2] 搜尋 SYSVOL 中殘留的 cpassword 明文憑證洩漏 ===" -ForegroundColor Cyan
$SysvolPath = "\\$env:USERDNSDOMAIN\SYSVOL\$env:USERDNSDOMAIN\Policies"
if (Test-Path $SysvolPath) {
    $LeakedFiles = Get-ChildItem -Path $SysvolPath -Recurse -Filter "*.xml" -ErrorAction SilentlyContinue | 
                   Select-String -Pattern "cpassword="
    if ($LeakedFiles) {
        Write-Host "🚨 警告：在 SYSVOL XML 中發現 cpassword 加密字串！立即刪除！" -ForegroundColor Red
        $LeakedFiles | Select-Object Path, LineNumber | Format-Table
    } else {
        Write-Host "✅ 未在 SYSVOL 中發現 cpassword 屬性。" -ForegroundColor Green
    }
}

Write-Host "`n=== [3] 查詢最近 24 小時 GPO 修改者 (Event ID 5136) ===" -ForegroundColor Cyan
Get-WinEvent -FilterHashtable @{LogName='Security'; Id=5136; StartTime=(Get-Date).AddHours(-24)} -ErrorAction SilentlyContinue | 
Where-Object {
    $xml = [xml]$_.ToXml()
    $xml.Event.EventData.Data | Where-Object { $_.Name -eq 'ObjectClass' -and $_.'#text' -eq 'groupPolicyContainer' }
} | ForEach-Object {
    $xml = [xml]$_.ToXml()
    $data = $xml.Event.EventData.Data
    [PSCustomObject]@{
        TimeCreated = $_.TimeCreated
        Modifier    = ($data | Where-Object { $_.Name -eq 'SubjectUserName' }).'#text'
        GPO_DN      = ($data | Where-Object { $_.Name -eq 'ObjectDN' }).'#text'
        Attribute   = ($data | Where-Object { $_.Name -eq 'AttributeLDAPDisplayName' }).'#text'
    }
} | Format-Table -AutoSize
```

## ⚖️ 第四動：研判分水嶺——正常 IT 部署 vs 惡意 GPO 劫持？

在大型企業中，IT 維運團隊每週都會微調 GPO。你該如何區分是正常的資安加固更新，還是黑客在植入後門？

### 4.1 SOC 8 大黃金研判問題對照表

| 核心提問（研判維度） | 本技術點實戰檢核標準 |
| :--- | :--- |
| **Q1. 觸發原因**（為何會發出此警報？） | 全網大量主機安全軟體被關閉，或 DC 的 Event ID 5136 記錄到 GPO 變更。 |
| **Q2. 操作帳號**（修改 GPO 的人是誰？） | 是已授權的 GPO 治理小組成員，還是普通維運、外包帳號，甚至是服務帳戶？ |
| **Q3. 變更時間**（變更發生的時間點？） | 是在預定的維護窗口（Maintenance Window），還是在深夜、週末非上班時間？ |
| **Q4. 原則範圍**（影響的範圍有多大？） | 修改的是特定測試 OU 的小型原則，還是直接動了掛載在根目錄、影響全網的 **Default Domain Policy**？ |
| **Q5. 腳本特徵**（新增的腳本內容為何？） | 檢視 GPT 中的批次檔：是合法的印表機掛載腳本，還是包含 `powershell -enc`、下載外部 EXE 的惡意程式？ |
| **Q6. 密碼洩漏**（是否有 XML 密碼被寫入？） | 檢查 SYSVOL 中是否有新產生的 `Groups.xml` 或 `Services.xml` 帶有加密字串？ |
| **Q7. 關聯告警**（端點是否有異常行為響應？） | 原則下發後的 15 分鐘內，全網 EDR 是否出現大規模未授權二進位檔啟動的次生告警？ |
| **Q8. 處置動作**（下一步是什麼？） | 1. 於 GPMC 立即將惡意 GPO 狀態改為「已停用（Disabled）」；2. 強制全網下發還原原則；3. 封鎖修改者帳號並重置 SYSVOL 權限。 |

## 🛡️ 第五動：資安基線部署 SOP (Baseline & Hardening)

防禦 GPO 遭篡改並利用 GPO 建立堅固基線，請遵循以下三道防護防線：

### 1. 第一步：收斂 GPO 委派權限與 Hardened UNC Paths
- 預設情況下，避免將一般網域使用者加入 `Group Policy Creator Owners` 群組。
- **Hardened UNC Paths（強化 UNC 路徑）**：設定 GPO 防止針對 SYSVOL/NETLOGON 的中間人篡改攻擊：
  ```text
  電腦設定 ➔ 系統管理範本 ➔ 網路 ➔ 網路提供者 ➔ 強化 UNC 路徑
  新增項目：
  名稱: \\*\SYSVOL
  值  : RequireMutualAuthentication=1, RequireIntegrity=1
  ```

### 2. 第二步：全網推行 CIS / Microsoft 資安核心基線配置
透過 GPO 下發以下三大核心安全開關：
```
1. 終結 LLMNR 毒化攻擊：
   電腦設定 ➔ 系統管理範本 ➔ 網路 ➔ DNS 用戶端
   • 關閉多點傳播名稱解析 (Turn off multicast name resolution) ➔ 【已啟用】

2. 啟用命令列進程稽核（捕捉惡意腳本參數）：
   電腦設定 ➔ 系統管理範本 ➔ 系統 ➔ 稽核處理程序建立
   • 在處理程序建立事件中納入命令列 (Include command line in process creation) ➔ 【已啟用】

3. 禁止在記憶體中儲存 WDigest 明文密碼：
   電腦設定 ➔ 喜好設定 ➔ Windows 設定 ➔ 登錄
   • 機碼：HKLM\SYSTEM\CurrentControlSet\Control\SecurityProviders\WDigest
   • 數值名稱：UseLogonCredential ➔ 設定為【0】
```

### 3. 第三步：全面部署 LAPS（本機系統管理員密碼解決方案）
徹底解決黑客「拿下一台機器本地管理員，就能橫向攻陷全網工作站」的連鎖反應：
- LAPS 自動為全網每一台電腦生成「**完全隨機且互不相同**」的本機 Administrator 密碼。
- 密碼自動加密儲存在 AD 物件屬性中，定期輪替，杜絕 Pass-the-Hash 橫向擴散。

## 🎯 第六動：靶場實戰檢驗 (Hands-on Lab Walkthrough)

請帶著剛才學到的 GPT 結構與 GPO 權限審計技巧，進入真實 AD 靶場：

### 推薦靶場：[TryHackMe - Post-Exploitation Basics (GPO Persistence)](https://tryhackme.com/room/postexploit)
- **靶場背景**：一個已取得普通網域使用者權限的滲透測試環境。
- **作戰任務**：
  1. 連入工作站，執行 `gpresult /r`，列出當前主機套用的所有 GPO 名稱。
  2. 使用 PowerShell 腳本遍歷本網域的所有 GPO，找出一個由於權限配置錯誤（Misconfigured ACL）、允許目前使用者寫入的 GPO。
  3. 檢視該 GPO 的 SYSVOL 路徑，觀察 `Machine\Scripts\Startup` 資料夾結構。
  4. 模擬防守方視角：登入 DC，開啟 Event Viewer，定位 Event ID 5136，找出是誰在何時修改了該原則。

## 📋 第七動：過關驗收檢查點 (Mastery Checklist)

不看筆記，試著回答以下 5 個實戰問題。若都能清楚回答，代表你已徹底掌握 GPO 運作與防禦底層：

- [ ] **Q1**：在 GPO 架構中，**GPC（群組原則容器）** 與 **GPT（群組原則範本）** 的最大差異是什麼？客戶端在開機時，如何判定這兩個組件的版本是否一致？
  > **解答要點**：GPC 儲存在 Active Directory 資料庫中，包含 GPO 的屬性與版本號元數據，透過 LDAP 讀取；GPT 儲存在 DC 的 SYSVOL 檔案共享目錄中，包含具體的 `registry.pol`、腳本等實體檔案，透過 SMB 讀取。兩者各有一個 32-bit 版本號碼（高 16 位元為使用者設定版本，低 16 位元為電腦設定版本）。客戶端在執行原則評估時，會比對 GPC 與 GPT 的版本號，若兩者號碼不一致，客戶端會拋出複寫未就緒警告並暫停套用，直到版本同步。
- [ ] **Q2**：為什麼在歷史滲透案例中，黑客只要在 SYSVOL 搜尋 `cpassword`，就能在一秒內拿到管理員密碼？微軟在 MS14-025 安全公告中採取了什麼根本性的修復？
  > **解答要點**：在舊版群組原則喜好設定（GPP）中，管理員可透過 XML 派發帳號密碼，微軟使用 256-bit AES 對密碼進行加密並存為 `cpassword` 屬性。然而，微軟在 MSDN 官方文檔中公開發布了該固定的靜態 AES 解密金鑰，導致任何能存取 SYSVOL 的普通網域使用者都能直接解密出明文密碼。微軟在 MS14-025 中徹底修復了此問題：在 GPMC 中移除了儲存密碼的功能，強制不再允許建立帶有密碼的 GPP XML 設定。
- [ ] **Q3**：如果一個 GPO 被連結在子 OU 上，但父網域的「Default Domain Policy」被管理員勾選了 **Enforced（強制）**，請問當兩者的登錄檔設定發生衝突時，哪一個原則會最終勝出？
  > **解答要點**：父網域的 Default Domain Policy 會最終勝出。雖然依據常規 LSDOU 規則，子 OU 原則具備較高的覆蓋優先權，但一旦上層原則被標記為 **Enforced（強制生效）**，該原則將無視下層的所有覆蓋設定，並直接穿透子 OU 勾選的「封鎖繼承（Block Inheritance）」，保證全網全域強制生效。
- [ ] **Q4**：黑客若在某個 GPO 的「電腦開機腳本（Startup Script）」中注入了反彈 Shell 腳本，當受害電腦開機執行該腳本時，該進程會以什麼權限身分運行（提示：不是 Domain User）？
  > **解答要點**：會以本機最高特權身分 **`NT AUTHORITY\SYSTEM`** 運行。因為電腦開機腳本是在使用者登入前、由作業系統底層核心服務直接呼叫執行的，因此具備對本機作業系統的完全控制權限，這也是黑客極度熱衷利用 GPO Startup Script 作為全網批次權限提升與持久化載體的核心原因。
- [ ] **Q5**：為什麼現代企業強烈推薦部署 **LAPS（Local Administrator Password Solution）**？它在架構層面解決了 GPO 過去在管理本機管理員密碼時的哪項重大缺陷？
  > **解答要點**：過去企業透過 GPO 或範本部署本機管理員密碼時，所有工作站的本機 Administrator 密碼全部一模一樣。一旦其中一台普通電腦失陷被 Dump 密碼或 Hash，攻擊者便能直接透過 Pass-the-Hash 橫向登入全網所有電腦。LAPS 在架構上徹底解決了此問題：由客戶端擴展程式自動為「每一台電腦」生成隨機且唯一的複雜密碼，定期輪替並將密碼加密回寫至 AD 物件的專屬安全屬性中，僅限指定安全群組讀取，杜絕單點失陷引發全網橫向失守。\n
