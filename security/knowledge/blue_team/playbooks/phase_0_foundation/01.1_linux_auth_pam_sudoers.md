## 🚨 案發現場破題 (Incident Scenario & Mental Workflow)

### 1.1 案情境況：低權限 Web 帳號的「一鍵成王」
週三深夜 23:40，某大型電子商務核心生產叢集的主機入侵偵測系統（HIDS / OSSEC）突然觸發了致命特權躍升警報：
> *Alert: Unauthorized Privilege Escalation to ROOT - Source Process: `/usr/bin/find` executed by user `www-data` (UID: 33) ➔ Spawned Interactive Root Shell `/bin/bash` (UID: 0).*

值班 Linux 維運主管第一時間斬釘截鐵地向 SOC 保證：
「這絕對是誤報！我們的 Linux 基礎映像通過嚴格 CIS Benchmark 加固：
1. `root` 帳號禁止密碼登入，僅允許特定堡壘機的 ED25519 金鑰。
2. 任何開發人員與維運人員都不知曉 `root` 本機密碼。
3. `/etc/passwd` 裡 `root` 的密碼占位符均為標準的 `x`，Shell 為標準 `/bin/bash`，且無任何新增的未知帳號！」

然而，當鑑識人員連入該伺服器審查時，殘酷的真相浮出水面：
1. **Sudo 授權失控**：開發團隊為了方便容器內部的排程日誌清理，在 `/etc/sudoers.d/web_cleaner` 中留下了一行被遺忘的授權：
   `www-data ALL=(ALL) NOPASSWD: /usr/bin/find /var/log/nginx/*`。
2. **GTFOBins 秒級逃逸**：攻擊者透過 Web 漏洞上傳 WebShell 後，僅僅輸入了一行指令：
   `sudo /usr/bin/find /var/log/nginx/ -exec /bin/bash -p \; -quit`
   瞬間跨越權限隔離，直接取得無密碼的互動式 Root Shell！
3. **PAM 後門防禦瓦解**：更致命的是，鑑識人員嘗試審查 `/etc/pam.d/common-auth` 時，發現攻擊者在成功提權後，在該檔案首行植入了：
   `auth sufficient pam_permit.so`
   這意味著整個 Linux 作業系統的身分認證大門已完全向外洞開——任何使用者輸入任何隨意密碼均能直接通過身分驗證！

這是一起結合了 **Sudoers 萬用字元參數逃逸 (Sudo Escape)** 與 **底層 PAM 認證劫持 (PAM Backdoor)** 的複合式實戰攻擊！

```
[ 外部黑客 (Web 攻擊) ] ── (利用 RCE 上傳 WebShell) ──► [ 低權限進程: www-data (UID: 33) ]
                                                                   │
                                                                   ▼
       [ 濫用危險 Sudoers 配置: www-data ALL=(ALL) NOPASSWD: /usr/bin/find ]
                                                                   │
                                    ┌──────────────────────────────┘
                                    │ (調用 find -exec /bin/bash -p 執行 GTFOBins 逃逸)
                                    ▼
                  【 取得最高系統特權: root (UID: 0) 】
                                    │
                                    ▼ (鞏固特權與持久化後門)
       [ 篡改 /etc/pam.d/common-auth ➔ 插入 auth sufficient pam_permit.so ]
                                    │
                                    ▼
       【 全作業系統登入認證瓦解：全體帳戶任意密碼通行無阻！】
```

### 2.1 Linux 核心帳號與密碼資料庫全解構
Linux 核心內部不以字串使用者名稱區分權限，**核心只認 UID（User ID）。UID 0 擁有系統至高無上的核心特權**！

```
[/etc/passwd 7 大欄位標準結構 (以冒號 ':' 分隔)]
root : x : 0 : 0 : SuperUser : /root : /bin/bash
 │    │   │   │       │          │        └─ 7. Default Shell (登入後 Shell, /usr/sbin/nologin 則禁止登入)
 │    │   │   │       │          └────────── 6. Home Directory (家目錄路徑)
 │    │   │   │       └───────────────────── 5. GECOS (備註資訊，如全名、電話)
 │    │   │   └───────────────────────────── 4. GID (主要群組 ID，對應 /etc/group)
 │    │   └───────────────────────────────── 3. UID (★ 使用者 ID！若被黑客篡改為 0 即具備 Root 權限！)
 │    └───────────────────────────────────── 2. Password Placeholder ('x' 代表密碼雜湊存放於 /etc/shadow)
 └────────────────────────────────────────── 1. Username (帳號名稱)

[/etc/shadow 9 大欄位標準結構 (僅 root 與 shadow 群組可讀)]
admin : $6$saltsalt$hashedpassword... : 19750 : 0 : 90 : 7 : 30 : 19900 : 
  │     └──────────────┬────────────┘     │     │   │   │    │     │    └─ 9. Reserved (保留未用)
  │                    │                  │     │   │   │    │     └────── 8. Expiration Date (帳號失效日)
  │                    │                  │     │   │   │    └──────────── 7. Inactivity Days (過期寬限期)
  │                    │                  │     │   │   └───────────────── 6. Warning Days (過期前告警天數)
  │                    │                  │     │   └───────────────────── 5. Maximum Days (密碼有效最長天數)
  │                    │                  │     └───────────────────────── 4. Minimum Days (密碼修改最短維持天數)
  │                    │                  └─────────────────────────────── 3. Last Changed (最後一次變更密碼天數)
  │                    │
  │                    └─ ★ 密碼雜湊欄位狀態判斷（藍隊清查關鍵！）：
  │                       • $6$... : SHA-512 雜湊密碼（$1$=MD5, $5$=SHA-256, $y$=Yescrypt）
  │                       • ! 或 * : 帳號已被【鎖定/停用】(Password Locked)，無法密碼登入
  │                       • !!     : 帳號已建立但尚未設定密碼
  │                       • (空)   : 【致命極度危險】無密碼帳號 (Null Password)，直接 Enter 即可登入！
  └────────────────── 1. Username (對應 /etc/passwd 帳號名)
```

### 2.2 特殊權限位元 (SUID / SGID / Sticky Bit)
檔案系統除了標準的 `rwx` 外，還包含三個高階特權位元（八進位表示）：
- **SUID (4000, `rwsr-xr-x`)**：任何非特權使用者執行該二進位檔案時，執行緒暫時繼承該檔案**擁有者 (Owner)** 的完整權限！若 Owner 為 `root`，使用者執行時即獲取 `euid=0`。
- **SGID (2000, `rwxr-sr-x`)**：執行時暫時繼承該檔案**所屬群組 (Group)** 的權限；掛於目錄時，目錄下新建的檔案自動繼承該目錄的 GID。
- **Sticky Bit (1000, `rwxrwxrwt`)**：主要用於共用寫入目錄（如 `/tmp`），僅允許檔案擁有者與 `root` 刪除或更名該檔案。

### 2.3 PAM（可插入式認證模組）堆疊運作架構
Linux 應用程式（如 `sshd`, `sudo`, `su`, `login`）透過統一的 PAM 介面進行驗證，設定檔位於 `/etc/pam.d/`：

```
[ 應用程式驗證請求 (如 sudo 或 sshd) ]
                  │
                  ▼
   [ /etc/pam.d/ 模組設定檔堆疊解析 ]
    ├── auth      : 身分認證 (驗證憑證/密碼/MFA)
    ├── account   : 帳號檢查 (檢查是否過期、登入時段限制)
    ├── password  : 密碼管理 (修改密碼之複雜度要求)
    └── session   : 會話建立 (掛載環境變數、資源配額 limits)
                  │
                  ▼
   [ ★ PAM Control Flags (控制標記裁量規則) ]
    • required   : 必須成功！若失敗，該鏈必然失敗，但會繼續走完後續模組（隱匿失敗點防枚舉）。
    • requisite  : 必須成功！若失敗，【立即中斷退出】並回傳認證失敗！
    • sufficient : 【充分條件】！若此模組成功且先前無 required 失敗，【立即判定通過認證】！
    • optional   : 參考模組，其成敗通常不影響最終判定。
```

## 💻 第三動：現場追兇——作戰指令與腳本庫

### 3.1 Linux 帳號安全與特權漏洞全自動審計工具 (`audit_linux_auth.py`)
現場調查人員使用本腳本，能在 3 秒內完成全機 UID 0 檢驗、空密碼掃描、Sudoers 語法審計與 PAM 模組比對：

```python
#!/usr/bin/env python3
"""
audit_linux_auth.py - Linux Account, PAM & Sudoers Security Auditor
用途：自動化檢驗 Linux 系統帳號合規性、Sudoers 提權地雷與 PAM 模組完整性。
"""
import os
import sys
import re
import glob

DANGEROUS_GTFOBINS = [
    "find", "vim", "vi", "less", "more", "awk", "nano", 
    "python", "python3", "perl", "ruby", "bash", "sh", 
    "cp", "mv", "tar", "zip", "env", "gdb", "nmap", "su", "sudo"
]

def check_uid_zero():
    print("[*] 1. 正在檢查 /etc/passwd 中的超級使用者 (UID 0)...")
    uid_zero_users = []
    with open("/etc/passwd", "r", encoding="utf-8", errors="ignore") as f:
        for line in f:
            parts = line.strip().split(":")
            if len(parts) >= 3 and parts[2] == "0":
                uid_zero_users.append(parts[0])
    
    if len(uid_zero_users) == 1 and uid_zero_users[0] == "root":
        print("  [+] 通過：全系統僅存在唯一合法 root (UID 0) 帳號。")
    else:
        print(f"  [!] 🚨 【嚴重警報】發現異常 UID 0 超級使用者帳號: {uid_zero_users}")

def check_shadow_empty_passwords():
    print("\n[*] 2. 正在檢查 /etc/shadow 中的空密碼或無效帳號...")
    empty_users = []
    try:
        with open("/etc/shadow", "r", encoding="utf-8", errors="ignore") as f:
            for line in f:
                parts = line.strip().split(":")
                if len(parts) >= 2:
                    user, pwd = parts[0], parts[1]
                    if pwd == "":
                        empty_users.append(user)
    except (FileNotFoundError, PermissionError):
        print("  [-] 無法讀取 /etc/shadow：檔案不存在或無讀取權限 (需要 root 權限)。")
        return
    
    if empty_users:
        print(f"  [!] 🚨 【嚴重漏洞】發現免密碼直接登入帳號: {empty_users}")
    else:
        print("  [+] 通過：未發現無密碼裸奔帳號。")

def check_sudoers_configuration():
    print("\n[*] 3. 正在審查 Sudoers 設定檔 (/etc/sudoers 及 /etc/sudoers.d/*)...")
    sudo_files = ["/etc/sudoers"] + glob.glob("/etc/sudoers.d/*")
    
    found_issues = []
    for s_file in sudo_files:
        if not os.path.isfile(s_file):
            continue
        with open(s_file, "r", encoding="utf-8", errors="ignore") as f:
            for line_no, line in enumerate(f, 1):
                clean_line = line.strip()
                if clean_line.startswith("#") or not clean_line:
                    continue
                
                # 檢測通用 NOPASSWD: ALL
                if re.search(r"NOPASSWD\s*:\s*ALL", clean_line, re.IGNORECASE):
                    found_issues.append(f"{s_file}:{line_no} -> 包含通用無密碼全特權: '{clean_line}'")
                
                # 檢測 GTFOBins 危險程式
                for bin_name in DANGEROUS_GTFOBINS:
                    pattern = rf"NOPASSWD.*(?:/|\b){bin_name}\b"
                    if re.search(pattern, clean_line, re.IGNORECASE):
                        found_issues.append(f"{s_file}:{line_no} -> 包含 GTFOBins 可逃逸特權程式 [{bin_name}]: '{clean_line}'")

    if found_issues:
        print("  [!] 🚨 【發現高危 Sudoers 配置地雷】:")
        for issue in found_issues:
            print(f"      ├─ {issue}")
    else:
        print("  [+] 通過：未檢測出顯而易見的 GTFOBins 免密碼提權條目。")

def check_pam_backdoor():
    print("\n[*] 4. 正在檢查 PAM 設定檔是否存在萬能放行後門 (pam_permit)...")
    pam_files = glob.glob("/etc/pam.d/*")
    pam_issues = []
    for p_file in pam_files:
        with open(p_file, "r", encoding="utf-8", errors="ignore") as f:
            for line_no, line in enumerate(f, 1):
                s = line.strip()
                if s.startswith("#") or not s:
                    continue
                if "auth" in s and "sufficient" in s and "pam_permit.so" in s:
                    pam_issues.append(f"{p_file}:{line_no} -> 包含無條件認證通過後門: '{s}'")
    
    if pam_issues:
        print("  [!] 🚨 【致命 PAM 後門】發現無條件放行配置:")
        for issue in pam_issues:
            print(f"      ├─ {issue}")
    else:
        print("  [+] 通過：未在 PAM auth 鏈頂端發現可疑的 pam_permit 放行規則。")

if __name__ == "__main__":
    print("=" * 75)
    print("🛡️  Linux 帳號安全、PAM 模組與 Sudoers 權限自動化稽核")
    print("=" * 75)
    check_uid_zero()
    check_shadow_empty_passwords()
    check_sudoers_configuration()
    check_pam_backdoor()
    print("=" * 75)
```

## 🧭 第四動：研判分流——SOC 8 問與決策樹

### 4.1 SOC 研判對決 8 問
| 編號 | 檢驗提問 (Verification Questions) | 是 (Yes) 判定導向 | 否 (No) 判定導向 |
|:---:|:---|:---|:---|
| **Q1** | 發起 `sudo` 提權的來源帳號是否為非互動式系統服務帳戶（如 `www-data`, `apache`, `mysql`）？ | 🚨 **極高危**：100% 為 WebShell 入侵提權！立即隔離！ | 來源為實體管理員或研發人員帳號，進入下一步審查。 |
| **Q2** | 執行的 Sudo 命令是否屬於 GTFOBins 逃逸清單（如 `find`, `vim`, `awk`, `less`）？ | 🚨 **確定提權**：惡意逃逸取得 Root Shell 之典型手法。 | 執行命令為標準業務維運指令（如 `systemctl restart`）。 |
| **Q3** | Sudo 授權設定檔是否有對應的企業 IT 變更工單或正式發布流程記錄？ | 傾向合法管理變更，但仍需審查規則寫法是否過於寬鬆。 | ⚠️ **可疑入侵**：非預期變更，高機率為黑客持久化後門。 |
| **Q4** | `/etc/passwd` 中是否存在除 `root` 以外的任何 UID 0 帳號？ | 🚨 **致命後門**：黑客已建立超級使用者後門，全機淪陷！ | 通過：全系統僅存在唯一標準 root (UID 0)。 |
| **Q5** | `/etc/shadow` 中是否存在未設定密碼的空密碼帳號？ | 🚨 **高危漏洞**：允許任何本地使用者免密碼直接提權。 | 通過：所有帳號皆有雜湊保護或處於停用鎖定狀態。 |
| **Q6** | `/etc/pam.d/` 設定檔中是否被插入了 `auth sufficient pam_permit.so`？ | 🚨 **重大事件**：PAM 身分認證架構遭到破壞，萬能後門成形！ | 通過：PAM 認證鏈完整且符合發行版官方基準。 |
| **Q7** | 該提權進程是否有向境外非預期 IP 建立對外連線（反彈 Shell）？ | 🚨 **重大資安事件**：黑客已建立 C2 交互連線，啟動應變 SOP！ | 無網路外聯，僅在本地端執行特定腳本。 |
| **Q8** | Sudo 執行時命令列是否包含路徑遍歷特徵（如 `../../etc/shadow`）？ | 🚨 **越權攻擊**：攻擊者正試圖突破 Sudoers 參數限制讀取機密。 | 命令列參數在預期目錄之合法範圍內。 |

## 🛡️ 第五動：加固防禦與收斂 SOP (Mitigation & Hardening)

### 5.1 應急處置三部曲 (Immediate Containment)
1. **立即移除危險 Sudoers 授權**：
   ```bash
   # 嚴格使用 visudo 編輯，切勿直接以普通編輯器修改
   sudo visudo -f /etc/sudoers.d/web_cleaner
   # 將危險的 NOPASSWD 條目直接註解或刪除
   ```
2. **緊急鎖定受害帳號並踢出連線**：
   ```bash
   # 立即在 /etc/shadow 密碼前加上 ! 鎖定帳號
   sudo passwd -l <username>
   # 強制終止該使用者在全系統的所有進程與會話
   sudo pkill -KILL -u <username>
   ```
3. **還原 PAM 模組完整性**：
   若套件檢查發現 `pam_unix.so` 遭竄改，立即由官方套件庫重新安裝覆蓋：
   ```bash
   sudo apt-get --reinstall install libpam-modules libpam-runtime
   ```

### 5.2 長期系統架構加固 (Long-term Hardening)
1. **配置 `pam_faillock` 防密碼暴力破解**：
   在 `/etc/pam.d/common-auth`（RHEL 為 `/etc/pam.d/system-auth`）加入防爆破機制：
   ```text
   auth required pam_faillock.so preauth silent audit deny=5 unlock_time=900
   auth [default=die] pam_faillock.so authfail audit deny=5 unlock_time=900
   account required pam_faillock.so
   ```
2. **實施 Sudoers 參數嚴格白名單化**：
   絕不在 Sudoers 中使用萬用字元 `*`；若必須授權重啟服務，寫死為完整絕對路徑與固定參數：
   ```text
   # 良好配置：禁止任何參數注入
   operator ALL=(ALL) /bin/systemctl restart nginx.service
   ```

## 📋 過關驗收檢查點 (Mastery Checklist)

- [ ] **Q1：在 Linux 作業系統中，如果一個帳號名稱叫 `devuser`，但在 `/etc/passwd` 中其第三欄 (UID) 被修改為 `0`，該帳號擁有的權限是什麼？核心如何認定？**  
  *考核核心*：在 Linux 核心中，身分與權限判定完全依賴於數值型態的 UID，與文字型態的 Username 毫無關聯。只要使用者的 UID 被指定為 `0`，該使用者即具備與 `root` 完全相同且毫無限制的最高核心特權。在系統稽核時，若僅檢查帳號名稱是否為 root，會完全遺漏此類別名超級使用者後門 (Superuser Backdoor)。

- [ ] **Q2：在 PAM 模組控制標記 (Control Flags) 中，`required` 與 `requisite` 有何關鍵差異？攻擊者最常濫用哪一個控制標記製作後門？**  
  *考核核心*：
  - `required`：模組若驗證失敗，整體鏈必然失敗，但會「繼續執行後續模組」，以防止攻擊者透過計時差異猜測特定模組的成敗。
  - `requisite`：模組若驗證失敗，會「立即中斷並返回錯誤」，不再執行後續模組。
  攻擊者最常濫用 `sufficient`（充分條件）：只要攻擊者在認證鏈頂端插入一條 `auth sufficient pam_permit.so`，只要該行判定通過，PAM 會直接跳過後續所有真實的密碼檢驗模組，達成無條件登入。

- [ ] **Q3：在 Sudoers 語法中，為什麼管理員授權 `operator ALL=(root) /usr/bin/vim /etc/nginx/nginx.conf` 等同於直接賦予該使用者完整的 Root 權限？**  
  *考核核心*：`vim` 本身具備外殼呼叫 (Shell Escape) 的內建功能。雖然管理員限制了其只能編輯特定檔案，但使用者在進入 vim 編輯介面後，只需在指令模式輸入 `:!/bin/sh` 或 `:set shell=/bin/sh` 隨後執行 `:shell`，vim 即會以其當前運行的權限（即 root）衍生出一個全新的互動式 Shell，徹底繞過管理員設定的檔案編輯限制。這屬於典型的 GTFOBins 特權逃逸。

- [ ] **Q4：在 Sudoers 規則中，若配置了帶有萬用字元的命令（例如 `/bin/cat /var/log/*`），攻擊者如何利用路徑遍歷 (Directory Traversal) 達成機密外洩？**  
  *考核核心*：Sudoers 的萬用字元 `*` 匹配機制在預設下不防範路徑遍歷序列。攻擊者可以執行 `sudo cat /var/log/../../etc/shadow`，作業系統在路徑解析時會將 `../../` 向上導航至根目錄，成功讀取系統密碼雜湊檔。防禦規範要求嚴禁在 Sudoers 中使用 `*`，或必須搭配專用的命令封裝腳本進行嚴格正規化過濾。

- [ ] **Q5：當 SOC 分析師在 `/var/log/auth.log` 觀察到 `sudo: www-data : TTY=unknown ; PWD=/var/www/html ; USER=root ; COMMAND=/bin/bash` 時，其攻擊鏈背景通常是什麼？第一時間的標準應變處置為何？**  
  *考核核心*：
  - **背景**：`TTY=unknown` 且執行目錄為 Web 根目錄 (`/var/www/html`)，強烈表明該操作並非真人透過 SSH 登入發起，而是外部黑客透過 Web 漏洞（如檔案上傳、RCE）植入的 WebShell 發起。攻擊者發現 `www-data` 擁有某些 sudo 免密碼權限後，直接嘗試獲取 `/bin/bash`。
  - **處置**：1. 立即終止該 `bash` 進程及相關 Web 執行緒；2. 在 Sudoers 中拔除該服務帳號之免密權限；3. 隔離該 Web 伺服器並回溯 Web 存取日誌，清查並清除植入的 WebShell 與修補入口漏洞。
