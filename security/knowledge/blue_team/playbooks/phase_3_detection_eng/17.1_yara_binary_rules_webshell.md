# 17.1 YARA 檔案二進位特徵碼規則撰寫 (WebShell 與惡意 PE 實戰鑑識)

## 🚨 案發現場破題 (Incident Scenario & Mental Workflow)

週五下班前 17:50，SOC 監控大盤突然收到多台核心 Linux Web 伺服器的檔案完整性監控（FIM / OSSEC）爆量告警：網站靜態目錄 `/var/www/html/uploads/` 與 `/var/www/html/assets/` 下，短時間內被寫入了數十個檔名看似正常的腳本，如 `image_view.php`、`profile_cache.php`、`system_check.phtml`。

端點防毒（ClamAV / Defender）對其中大部分檔案毫無反應，因為攻擊者採用了多層次的字串拼接、動態字串逆轉（`strrev`）、Base64 與 Gzip 壓縮混淆，甚至利用 PHP 7/8 的動態變數函數（`$f = 'sys'.'tem'; $f($_POST['c']);`）規避傳統防毒的簡單靜態特徵碼。維運團隊面臨抉擇：是盲目全盤刪除導致業務圖片遺失，還是逐一人工審閱這數萬個上傳檔案？

「傳統防毒已瞎，特徵匹配當立。」此時藍軍工程師的唯一手術刀，就是**撰寫具備抗混淆、正則比對與二進位 PE 結構感知的 YARA 規則**。

藍軍分析師的現場獵捕思維脈絡：
1. **樣本特徵提煉（Static Feature Extraction）**：快速抽樣惡意檔案，提取不可或缺的語意骨架（如執行命令關鍵原語 `system`、`exec`、`passthru`、`eval`、`assert`）。
2. **對抗混淆變形（Anti-Obfuscation Modifiers）**：使用 `nocase`（忽略大小寫）、`wide`（UTF-16 LE 雙字節編碼）、`ascii`（標準 ASCII）修飾符，封殺大小寫與編碼繞過。
3. **十六進位位元組匹配（Hex Byte Pattern & Wildcards）**：針對 PE 檔頭二進位代碼或 Shellcode，利用萬用字元 `??`、跳躍範圍 `[4-8]` 與替代邏輯 `( AA | BB )` 鎖定核心機器碼指令。
4. **複合條件約束（Condition Logic & PE Module）**：結合檔案大小限制（`filesize < 500KB`）、PE 導出表/區段屬性（`pe.number_of_sections`、`pe.imphash()`）或命中計數（`#eval > 3`），將誤報率（False Positive）徹底壓縮至零。
5. **全盤地毯式獵殺（Enterprise Scanning & Automation）**：將編寫完成的 YARA 規則下發至 EDR、Linux 終端或日誌流水線，即時標記並隔離受害主機上的隱藏 WebShell。

## 🧩 第一動：底層機制/協定解剖 (Mechanics & Physical Structs)

### 1. YARA 規則語法核心解剖

YARA 規則本質上是一個基於布林邏輯的模式匹配描述語言，一份合規的 YARA 檔案由四大區塊構成：

```yara
rule WebShell_PHP_Dynamic_Execution_Pattern {
    meta:
        description = "偵測利用動態函數調用與 Base64 混淆執行的通用 PHP WebShell"
        author = "SOC Blue Team Tier 2"
        date = "2026-09-12"
        severity = "Critical"
        attack_technique = "T1505.003 - Web Shell"

    strings:
        // 1. 關鍵文本特徵 (Text Strings with Modifiers)
        $php_tag = "<?php" nocase ascii wide
        $eval = "eval" nocase fullword
        $assert = "assert" nocase fullword
        
        // 2. 正則表達式特徵 (Regular Expressions) - 捕捉動態可變函數調用
        $re_dynamic = /\$(_{1,2}[A-Z]+|GLOBALS)\[['"][^'"]+['"]\]\s*\(\s*\$/ nocase
        
        // 3. 十六進位字節特徵 (Hex Strings) - 捕捉特洛伊頭部特徵或 Shellcode
        // 4D 5A 為 DOS Header (MZ), 50 4B 03 04 為 ZIP 封裝頭
        $hex_raw = { 65 76 61 6C 28 [0-8] 62 61 73 65 36 34 5F 64 65 63 6F 64 65 }

    condition:
        // 布林邏輯判定 (Condition Logic)
        filesize < 2MB and
        $php_tag at 0 and
        (
            $re_dynamic or
            $hex_raw or
            (2 of ($eval, $assert) and #php_tag == 1)
        )
}
```

### 2. 字串修飾符（String Modifiers）的底層匹配機制

- `nocase`（忽略大小寫）：
  預設情況下 YARA 比對 ASCII 字元是嚴格區分大小寫的。宣告 `nocase` 後，YARA 內部在建構 Aho-Corasick 自動機時，會將 `'a'` 與 `'A'` 映射至同一個匹配狀態節點。
- `wide` 與 `ascii`：
  - `ascii`（預設）：按單字節匹配（如 `eval` ➔ `65 76 61 6C`）。
  - `wide`：針對 Windows 核心常用的 Unicode UTF-16 LE 編碼，在每個 ASCII 字元後自動插入一個 `0x00`（如 `eval` ➔ `65 00 76 00 61 00 6C 00`）。
  - 若宣告 `ascii wide`，YARA 會同時搜尋這兩種編碼，精準打擊在 Windows 記憶體中展開的 UTF-16 WebShell 變數。
- `fullword`（完整單詞邊界）：
  避免部分字串貪婪匹配。例如搜尋 `eval` 時，若未加 `fullword`，則正常程式碼中的 `evaluate_user_score()` 也會被錯誤命中；加上 `fullword` 後，字串前後必須是非字母/數字/底線的字元（如空白、括號、分號）。
- `xor`（XOR 運算遍歷）：
  現代高階 WebShell（如冰蠍、哥斯拉）常對通訊載荷使用單字節 XOR 加密。宣告 `$s = "cmd.exe" xor(0x01-0xff)`，YARA 會自動計算 1 到 255 所有可能異或鍵值後的 255 組特徵碼進行並行搜尋！

### 3. PE 模組（PE Module）二進位剖析

當面對編譯好的惡意二進位檔案（如 Windows DLL 注入後門、Linux ELF 挖礦木馬）時，單純搜尋文字特徵極易失效，必須調用 YARA 官方擴充套件 `import "pe"`：

```yara
import "pe"

rule Suspicious_Injected_PE_Backdoor {
    meta:
        description = "識別偽裝成合法微軟程式但區段可寫可執行的惡意 PE 檔案"
    condition:
        // 驗證是否為合法 PE 檔案 (MZ 標頭與 PE 簽名)
        uint16(0) == 0x5A4D and pe.signatures == "PE" and
        
        // 檢查區段數量與異常高熵值 (判斷是否加殼/加密: 熵值 > 7.0 代表壓縮或加密)
        pe.number_of_sections >= 3 and
        pe.sections[0].entropy > 7.2 and
        
        // 檢查是否有既具備可寫入 (WRITE) 又具備可執行 (EXECUTE) 的高危險記憶體區段 (W^X 違背)
        for any section in pe.sections : (
            section.characteristics & pe.SECTION_MEM_WRITE and
            section.characteristics & pe.SECTION_MEM_EXECUTE
        )
}
```

### 1. YARA 實戰掃描核心指令 Cheatsheet


### 2. 生產級高精度 PHP 變形 WebShell 檢測規則範本

建立檔案 `/etc/yara/rules/webshell_php_deep.yar`：

```yara
rule WebShell_PHP_Obfuscated_Backdoor {
    meta:
        description = "偵測變形、多層混淆、動態調用與冰蠍/哥斯拉 PHP WebShell"
        author = "BlueTeam_IR_Lead"
        date = "2026-09-12"
        reference = "MITRE ATT&CK T1505.003"
        threat_level = "Critical"

    strings:
        // 特徵群組 1：PHP 宣告與高危執行函數
        $php = "<?php" nocase
        $php_short = "<?"
        $f_eval = "eval" nocase fullword
        $f_assert = "assert" nocase fullword
        $f_system = "system" nocase fullword
        $f_passthru = "passthru" nocase fullword
        $f_shell_exec = "shell_exec" nocase fullword
        $f_base64_decode = "base64_decode" nocase fullword
        $f_gzinflate = "gzinflate" nocase fullword

        // 特徵群組 2：外部未過濾輸入源
        $input_post = "$_POST" nocase
        $input_get = "$_GET" nocase
        $input_request = "$_REQUEST" nocase
        $input_cookie = "$_COOKIE" nocase
        $input_server = "$_SERVER['HTTP_" nocase

        // 特徵群組 3：變形特徵與反彈 Shell 管道
        $p_cmd = "/bin/sh" ascii wide
        $p_bash = "/bin/bash" ascii wide
        $p_tcp = "fsockopen" nocase
        $p_proc = "proc_open" nocase

        // 特徵群組 4：動態函數正則 (例如: $a($_POST['x']))
        $re_dyn_func = /\$[a-zA-Z_-ÿ][a-zA-Z0-9_-ÿ]*\s*\(\s*\$_(POST|GET|REQUEST|COOKIE)/ nocase

    condition:
        // 條件 1：限制掃描檔案大小小於 1MB（WebShell 極少大於 1MB，大幅降低 I/O 負載）
        filesize < 1MB and
        ($php at 0 or $php_short at 0 or $php in (0..100)) and
        (
            // 情境 A：動態可變函數調用外部參數
            $re_dyn_func or
            
            // 情境 B：解壓縮/解密後直接丟入 eval/assert
            (($f_base64_decode or $f_gzinflate) and ($f_eval or $f_assert) and 1 of ($input_*)) or
            
            // 情境 C：直接執行系統命令並連接 Shell
            (1 of ($f_system, $f_passthru, $f_shell_exec, $p_proc) and 1 of ($p_cmd, $p_bash) and 1 of ($input_*)) or
            
            // 情境 D：無檔案落地的一句話木馬特徵
            (#f_eval >= 1 and #input_post >= 1 and filesize < 300)
        )
}
```

### 3. 自動化應變排查與隔離腳本 (Bash + YARA)

```bash
#!/usr/bin/env bash
# 藍隊應變自動化：全盤掃描 Web 目錄，發現 WebShell 自動備份後隔離至隔離區

RULE_FILE="/etc/yara/rules/webshell_php_deep.yar"
TARGET_DIR="/var/www/html"
QUARANTINE_DIR="/root/quarantine_$(date +%Y%m%d_%H%M%S)"
LOG_FILE="/var/log/yara_hunt.log"

mkdir -p "$QUARANTINE_DIR"
echo "[*] Starting YARA threat hunt on $TARGET_DIR at $(date)" | tee -a "$LOG_FILE"

# 遍歷掃描並解析命中結果
yara -r -m "$RULE_FILE" "$TARGET_DIR" 2>/dev/null | while read -r line; do
    if [ -n "$line" ]; then
        RULE_NAME=$(echo "$line" | awk '{print $1}')
        SUSPICIOUS_FILE=$(echo "$line" | awk '{print $2}')
        
        echo "[!] DETECTED: Rule [$RULE_NAME] matched file: $SUSPICIOUS_FILE" | tee -a "$LOG_FILE"
        
        # 建立隔離備份 (保全原始時間戳與屬性)
        REL_PATH=$(realpath "$SUSPICIOUS_FILE")
        DEST_FILE="$QUARANTINE_DIR/$(basename "$SUSPICIOUS_FILE")_$(date +%s)"
        cp -a "$SUSPICIOUS_FILE" "$DEST_FILE"
        
        # 移除執行權限並安全置換為唯讀空檔案，中斷攻擊連線
        chmod 000 "$SUSPICIOUS_FILE"
        mv "$SUSPICIOUS_FILE" "${SUSPICIOUS_FILE}.infected"
        echo "[+] Quarantined to: $DEST_FILE" | tee -a "$LOG_FILE"
    fi
done

echo "[*] Threat hunt complete. Quarantine archive: $QUARANTINE_DIR" | tee -a "$LOG_FILE"
```

## ⚖️ 第四動：研判分水嶺——真實威脅 vs 業務誤報

### SOC 研判核心問題表

| 核心提問（研判維度） | 本技術點實戰檢核標準 |
| :--- | :--- |
| **Q1：命中檔案是否位於 Web 伺服器的靜態資源或上傳目錄？** | 若檔案位於 `/uploads/`、`/images/`、`/static/`、`/attachment/` 等目錄下，但副檔名竟然是 `.php`, `.jsp`, `.phtml`, `.asp`，**99.9% 必為真實 WebShell 入侵**！靜態目錄依法不應存在動態腳本執行權限。 |
| **Q2：檔案中是否存在與不可信外部輸入（Input Vectors）的直接連動？** | 檢視命中的 `eval` 或 `system` 參數。如果是 `eval($config['cached_code'])`（內部靜態配置變數），多為模板引擎（如 Smarty/Blade）正常行為；若直接接收 `$_POST`、`$_GET` 或 HTTP 標頭（如 `$_SERVER['HTTP_ACCEPT_LANGUAGE']`），必為真實後門。 |
| **Q3：檔案修改時間（mtime / ctime）是否落在近期告警突發窗口？** | 執行 `stat <file>`。比對該檔案的建立與修改時間，是否精確落在 WAF 告警發起、Web 伺服器 HTTP POST 暴增的相同時間點？ |
| **Q4：檔案的命名與所在目錄結構是否具備隨機性或錯字欺騙？** | 檢查檔名是否帶有點開頭隱藏檔（`.init.php`）、錯別字（`funct1on.php`、`conf1g.php`）或全隨機英數字（`a8f1b2c.php`）。正常專案原始碼命名嚴謹且統一。 |
| **Q5：該檔案是否能透過企業版本控制系統（Git / SVN）溯源？** | 在該專案目錄執行 `git status` 或 `git log -p <file>`。若該檔案被標記為 `Untracked files`（未納管檔案），且在代碼庫中從未由內部開發者提交過，必為外來植入物。 |
| **Q6：YARA 命中的字串是否僅為註解或安全掃描工具的簽名庫？** | 某些主機上可能安裝了資安掃描器（如 Nikto、Nessus、WAF 腳本），其本身的資料庫檔案可能包含常見 WebShell 語句。檢查該檔案所屬套件（`dpkg -S` 或 `rpm -qf`），確認是否為安全工具附帶之特徵庫檔案。 |

## 🛡️ 第五動：處置圍堵與系統加固 SOP

### 1. 發現 WebShell 現場緊急阻斷流程

若確認發現運作中的 WebShell，請嚴格依照順序執行處置：

```bash
# 步驟 1：解除 Web 伺服器針對該檔案的解析權限（微創阻斷，不影響業務核心）
chmod 000 /var/www/html/uploads/malicious.php
chattr +i /var/www/html/uploads/malicious.php 2>/dev/null

# 步驟 2：備份檔案樣本並提取雜湊值以供留證
mkdir -p /root/evidence/
cp -a /var/www/html/uploads/malicious.php /root/evidence/
sha256sum /root/evidence/malicious.php > /root/evidence/malicious.php.sha256

# 步驟 3：清查目前正在執行此腳本的進程並即時終結
# 查看哪個 PHP-FPM 或 Apache worker 正在開啟此檔案
lsof /var/www/html/uploads/malicious.php
# 強制終結關聯子行程
pkill -9 -f "php-fpm: pool www"

# 步驟 4：徹底從檔案系統中拔除該檔案
chattr -i /var/www/html/uploads/malicious.php 2>/dev/null
rm -f /var/www/html/uploads/malicious.php
```

### 2. 目錄級與架構級 WebShell 免疫加固規範

防範 WebShell 最有效的手法不是事後查殺，而是**在架構層面剝奪其執行權限**：

1. **Nginx 限制上傳目錄解析 PHP 腳本**：
   在 Nginx 配置檔的 `server` 區塊中加入以下嚴格拒絕規則：
   ```nginx
   # 嚴格禁止 uploads、images、assets 目錄執行任何動態腳本
   location ~* ^/(uploads|images|assets|data)/.*\.(php|php5|phtml|jsp|asp|aspx)$ {
       deny all;
       return 403;
   }
   ```
2. **作業系統層級掛載隔離**：
   若架構允許，將所有使用者上傳目錄（如 `/var/www/html/uploads`）掛載於獨立分割區，並在 `/etc/fstab` 中宣告 `noexec,nosuid,nodev` 選項：
   ```fstab
   /dev/sdb1  /var/www/html/uploads  ext4  defaults,noexec,nosuid,nodev  0  2
   ```
3. **PHP 核心函數停用（php.ini disable_functions）**：
   在生產環境的 `php.ini` 中，徹底關閉危險系統執行函數：
   ```ini
   disable_functions = exec,passthru,shell_exec,system,proc_open,popen,curl_exec,curl_multi_exec,parse_ini_file,show_source
   ```

### 實戰驗證步驟

#### 步驟 1：建立混淆 WebShell 測試樣本
在目標機器上模擬黑客建立兩個不同手法的 WebShell：
```bash
mkdir -p /var/www/html/uploads/2026/09/

# 樣本 A：動態變數混淆 WebShell (變形一字馬)
cat << 'EOF' > /var/www/html/uploads/2026/09/avatar_thumb.php

?>
EOF

# 樣本 B：Base64 壓縮加密木馬
cat << 'EOF' > /var/www/html/uploads/2026/09/cache_data.phtml
GIF89a
<?php
$payload = "c3lzdGVtKCRfUE9TVFsneiddKTs="; // system($_POST['z']);
eval(gzinflate(base64_decode($payload)));
?>
EOF
```

#### 步驟 2：執行初版 YARA 掃描驗證
建立測試規則檔 `/tmp/test_hunt.yar`：
```yara
rule Hunt_Upload_WebShell {
    strings:
        $php = "<?php" nocase
        $eval = "eval" nocase fullword
        $system = "system" nocase fullword
        $req = /\$_(REQUEST|POST|GET)/
    condition:
        $php in (0..50) and (
            ($eval and $req) or
            ($system and $req)
        )
}
```

執行掃描：
```bash
yara -s -r /tmp/test_hunt.yar /var/www/html/uploads/
```
*觀測結果*：樣本 B 遭到精準捕獲，但樣本 A 成功繞過！因為樣本 A 利用了字串拼接（`'s'.'y'...'m'`），記憶體中不存在連續的 `system` 字串。

#### 步驟 3：升級進階抗混淆 YARA 規則
修改 `/tmp/test_hunt.yar`，加入動態函數調用正則與跳躍字元匹配：
```yara
rule Hunt_Upload_WebShell_v2 {
    strings:
        $php = "<?php" nocase
        $req = /\$_(REQUEST|POST|GET)\[/

        $b64_eval = /eval\s*\(\s*(gzinflate|base64_decode)/ nocase

        filesize < 500KB and
        (
            ($php and $req and $dyn_invoke) or
            ($polyglot_gif at 0 and $b64_eval)
        )
}
```

## 📋 過關驗收檢查點 (Mastery Checklist)

- [ ] **Q1：在 YARA 規則字串宣告中，`nocase`、`wide` 與 `ascii` 同時宣告（`$s = "eval" nocase wide ascii`）時，YARA 底層會搜尋哪幾種變體？**
  - *驗收標準*：答出 YARA 會同時以「不區分大小寫」的方式搜尋單字節 ASCII 編碼（如 `eval`, `EVAL`, `Eval`）以及雙字節 UTF-16 LE Unicode 編碼（每個字元間隔 `0x00`），總計涵蓋所有大小寫與這兩種編碼的排列組合。
- [ ] **Q2：若攻擊者上傳了一個偽裝成正常圖片的 WebShell（Polyglot WebShell，開頭為 `GIF89a`），在 YARA 的 `condition` 中應如何撰寫條件以精準捕獲它？**
  - *驗收標準*：指出條件需包含 `$gif at 0`（宣告十六進位 `47 49 46 38 39 61` 必須位於檔案開頭偏移量 0 處），並且同時命中 PHP 代碼標籤與高危執行特徵（例如 `$php in (6..filesize)` 搭配 `$eval`）。
- [ ] **Q3：為什麼在生產環境大規模掃描數十萬個檔案時，YARA 規則的 `condition` 必須強烈建議加上 `filesize` 限制（例如 `filesize < 1MB`）？**
  - *驗收標準*：答出防範效能雪崩與資源耗盡（DoS）。WebShell 絕大多數小於幾百 KB，若不設限，YARA 引擎會將數十 GB 的備份檔、資料庫 dump 或影片檔整份讀入記憶體進行正則掃描，導致伺服器磁碟 I/O 飆死、記憶體爆裂。
- [ ] **Q4：在分析 PE 惡意檔案時，YARA 的 `pe.imphash()` 是依據什麼資訊計算而來的？為什麼它比檔案本身的 SHA256 雜湊更具抗變異性？**
  - *驗收標準*：答出 Import Hash（导入表哈希）是依據 PE 檔案導入的 DLL 名稱與 API 函數名稱排序後計算 MD5 而得。攻擊者即使更改程式碼、更換圖標或重新編譯改變了檔案 SHA256，只要其調用的 API 核心邏輯架構不變，`imphash` 就會完全一致，能有效跨家族批次獵捕。
- [ ] **Q5：當你寫了一條 YARA 規則部署至生產伺服器後，發現大量正常的開源架構（如 WordPress、Laravel）檔案引發了誤報，在不修改原始特徵字串的前提下，有哪些標準的「防誤報調優（FP Tuning）」手法？**
  - *驗收標準*：指出手法包含：(1) 增加否定條件（Negative Condition），排除合法廠商簽名或已知特定註解；(2) 提高命中閾值（從 `1 of them` 調高為 `3 of them`）；(3) 結合路徑排除（`not filepath contains "wp-includes"`）；(4) 嚴格限制變數必須與外部輸入源（`$_POST`）共同出現。
