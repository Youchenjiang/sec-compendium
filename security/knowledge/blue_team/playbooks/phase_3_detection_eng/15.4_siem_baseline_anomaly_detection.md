# 15.4 巨量資安日誌基準線與異常偏離偵測 (SIEM Baseline & Anomaly Detection)

## 🚨 案發現場破題 (Incident Scenario & Mental Workflow)

週日凌晨 03:45，企業核心金融資料庫所在的生產網段靜悄悄。這時，SIEM 監控大螢幕上突然彈出一筆「極低調」的日誌：一名資深資料庫管理員（DBA）的帳號 `db_admin_chen` 透過內部跳板機成功登入 Oracle 核心資料庫，並在一小時內陸續匯出了 1.2 GB 的加密財務報表與客戶個資。

若依照傳統「靜態閾值（Static Threshold）」規則：
- 「單一 IP 登入失敗 > 10 次」？——未觸發（黑客使用撞庫獲得的真實密碼，一次登入成功）。
- 「觸發高危漏洞攻擊簽章」？——未觸發（使用的是合法 SQL Developer 客戶端與原生查詢語法）。
- 「傳輸流量 > 10 GB」？——未觸發（黑客刻意將外發資料量壓制在 1.2 GB，精巧避開 5 GB 的靜態告警線）。

傳統規則在這種**「合法憑證 + 合法工具 + 偽裝業務行為」**的進階持續性滲透（APT）面前徹底致盲！

此時，拯救企業的是 SIEM 大數據分析平台運行的**「統計學動態基準線異常偵測（Statistical Baseline Anomaly Detection）」**模型：
SIEM 演算法透過歷史 60 天的日誌行為學習，為該帳號建立了四維動態基線：
1. **時間維度**：該帳號過去 60 天 100% 於週一至週五 08:30~18:30 登入，週日凌晨登入機率小於 0.001%（偏離值超過 3 個標準差 3-Sigma）。
2. **存取量維度**：該帳號日常查詢資料量常態分佈在 5 MB ~ 30 MB 之間，1.2 GB 偏離 IQR（四分位距）上限達 15 倍。
3. **來源設備指紋維度**：登入跳板機的內部來源主機 MAC 與硬體指紋為非註冊工作站。

SIEM 瞬間引爆 **P1 級重大內部威脅與資料外洩（Insider Threat / Exfiltration）**告警，自動聯防 PAM 堡壘機中斷連線並凍結該帳號，成功阻截了一起重大商業機密竊取案！

現代大數據資安分析師的心智思考模型：
1. **靜態閾值到動態統計的思維躍遷（From Static Threshold to Statistical Modeling）**：告別「死記硬背寫死大於 100 報警」，學習使用常態分佈（Gaussian Distribution）、移動平均（Moving Average）、標準差（Standard Deviation, $\sigma$）與四分位距（IQR）捕捉異常偏離。
2. **基線建立的時空窗口權衡（Baselining Time Windows）**：歷史基線該拉 7 天、30 天還是 90 天？如何過濾掉國定假日與維運變更日對基準線的「數據污染」？
3. **維度收斂與實體行為畫像（Entity Baselining: User / Host Profiling）**：將巨量日誌按 Entity（使用者、主機、網段、應用）分組，各自建立獨立的行為特徵輪廓（Profile）。
4. **離群值檢驗演算法（Outlier Detection Algorithms）**：掌握 3-Sigma 原則（Z-Score > 3）、箱型圖法（Tukey's Fences: $Q3 + 1.5 \times IQR$）與 Splunk MLTK 機器學習異常指令。
5. **警報疲勞抑制與動態門檻自適應（Adaptive Thresholding）**：業務隨季節增長時，靜態規則會瘋狂誤報；動態基線如何隨著業務自然的增長自動上浮門檻？

## 🧩 第一動：底層機制/協定解剖 (Mechanics & Physical Structs)

### 1. 異常偵測的四大統計學物理底層公式

在 SIEM 大數據分析中，藍軍工程師嚴禁拍腦袋定閾值，必須運用經典統計學公式對偏離程度進行數學證明：

#### (1) 平均值 (Mean, $\mu$) 與 標準差 (Standard Deviation, $\sigma$)
- **算術平均數**：
  $$\mu = \frac{1}{N} \sum_{i=1}^{N} X_i$$
- **總體標準差**：
  $$\sigma = \sqrt{\frac{1}{N} \sum_{i=1}^{N} (X_i - \mu)^2}$$

#### (2) Z 分數標準化 (Z-Score / 3-Sigma 原則)
$$Z = \frac{X - \mu}{\sigma}$$
- **統計學含義**：表示當前觀測值 $X$ 距離歷史平均值 $\mu$ 有幾個標準差的距離。
- **常態分佈判據**：
  - $|Z| \le 1$：佔總體數據的 **68.27%**（日常極度正常波動）。
  - $|Z| \le 2$：佔總體數據的 **95.45%**（輕度波動，常態放行）。
  - $|Z| > 3$：發生機率僅為 **0.27%**（小概率極端異常！藍軍標準 High 告警門檻）。
  - $|Z| > 4$：發生機率小於 **0.006%**（嚴重攻擊爆發！Critical 告警）。

#### (3) 四分位距與圖基離群值 (IQR & Tukey's Fences)
針對**非常態分佈（如流量突波、網路連線數等偏態分佈數據）**，標準差易受極端值污染，必須改用更穩健的四分位法：
- $Q1$：第 25 百分位數；$Q3$：第 75 百分位數。
- 四分位距：$IQR = Q3 - Q1$。
- **輕度異常上限 (Inner Fence)**：$\text{Upper\_Limit} = Q3 + 1.5 \times IQR$。
- **極度異常上限 (Outer Fence - 必報警)**：$\text{Extreme\_Limit} = Q3 + 3.0 \times IQR$。

```text
       最小非異常值              Q1           中位數 (Q2)       Q3             正常上限 (Q3+1.5*IQR)       極端異常 (>Q3+3*IQR)
          ├───[─────────────────┬─────────────────┬─────────────────]───┤                  ★ (惡意資料外洩!)
                                                  └─── IQR ───┘
```

## 💻 第三動：現場追兇——作戰指令與腳本庫

### 1. Splunk 巨量日誌動態基準線實戰查詢 (SPL 腳本庫)

#### (1) 基於 3-Sigma（標準差）的端點進程建立量異常偵測
```spl
# 偵測主機進程建立量突發暴增 (捕捉勒索病毒或批次執行橫向移動)
index=wineventlog EventCode=4688 earliest=-7d@d latest=now
| bin _time span=1h
| stats count as hourly_process_count by _time, ComputerName
# 第一步：計算每台主機過去 7 天的每小時進程平均值與標準差
| eventstats avg(hourly_process_count) as avg_count, stdev(hourly_process_count) as stdev_count by ComputerName
# 第二步：計算當前小時的 Z-Score
| eval z_score = round((hourly_process_count - avg_count) / stdev_count, 2)
# 第三步：過濾出偏離值超過 3 個標準差，且絕對計數大於 200 的極端異常
| where z_score > 3.0 AND hourly_process_count > 200
| eval upper_threshold = round(avg_count + (3 * stdev_count), 0)
| table _time, ComputerName, hourly_process_count, avg_count, upper_threshold, z_score
| sort - z_score
```

#### (2) 基於 IQR（四分位距）的帳號離峰出網流量異常偵測
```spl
# 偵測敏感帳號資料外洩：利用四分位距過濾偏態資料外發
index=firewall action=allowed earliest=-30d@d
| eval hour=strftime(_time, "%H")
# 鎖定離峰時段 (晚上 20:00 至隔日清晨 06:00)
| where hour >= 20 OR hour < 6
| bin _time span=1d
| stats sum(bytes_out) as daily_bytes by _time, src_user
# 第一步：計算 Q1 (25%), Q3 (75%) 與中位數
| eventstats p25(daily_bytes) as q1, p75(daily_bytes) as q3 by src_user
# 第二步：計算 IQR 與極端異常上限 (Tukey's Outer Fence: Q3 + 3*IQR)
| eval iqr = q3 - q1
| eval extreme_fence = round(q3 + (3 * iqr), 0)
# 第三步：抓獲昨夜突破正常上限的異常外洩實體
| where daily_bytes > extreme_fence AND daily_bytes > 104857600
| eval daily_mb = round(daily_bytes / 1024 / 1024, 2)
| eval limit_mb = round(extreme_fence / 1024 / 1024, 2)
| table _time, src_user, daily_mb, limit_mb
```

#### (3) 利用 Splunk 内建 `anomalies` 機器學習演算法快速搜尋
```spl
# 快速偵測全網登入失敗帳號的異常偏離
index=wineventlog EventCode=4625 earliest=-24h
| stats count by user, src_ip
| anomalies field=count threshold=0.01
| where unexpectedness > 0.8
| table user, src_ip, count, unexpectedness
```

### 2. Python 大數據離群值即時檢驗引擎 (Baseline Anomaly Engine)

```python
#!/usr/bin/env python3
# 藍隊專用：離線或串流日誌之 3-Sigma 與 IQR 混合異常分析腳本

import numpy as np
import sys

def detect_anomalies(data_points, labels=None):
    if len(data_points) < 10:
        print("[-] Data points too few to establish reliable statistical baseline (N < 10).")
        return

    data = np.array(data_points, dtype=float)
    
    # 1. 計算高斯分佈指標 (Gaussian Metrics)
    mean = np.mean(data)
    std = np.std(data)
    
    # 2. 計算四分位距指標 (IQR Metrics)
    q25, q75 = np.percentile(data, [25, 75])
    iqr = q75 - q25
    tukey_upper = q75 + (1.5 * iqr)
    tukey_extreme = q75 + (3.0 * iqr)
    
    print(f"=== Statistical Baseline Report ===")
    print(f"Sample Count (N)  : {len(data)}")
    print(f"Mean (μ)          : {mean:.2f}")
    print(f"StdDev (σ)        : {std:.2f}")
    print(f"Median (Q2)       : {np.median(data):.2f}")
    print(f"IQR               : {iqr:.2f} (Q1={q25:.2f}, Q3={q75:.2f})")
    print(f"Tukey Upper Fence : {tukey_upper:.2f}")
    print(f"Tukey Extreme Fnc : {tukey_extreme:.2f}")
    print("===================================\n")
    
    print("[*] Evaluating individual observations for anomalies:")
    for idx, val in enumerate(data):
        z_score = (val - mean) / std if std > 0 else 0
        tag = labels[idx] if labels else f"Point #{idx+1}"
        
        # 判定標準：Z > 3 且突破 Tukey Extreme Fence
        if z_score > 3.0 and val > tukey_extreme:
            print(f" [CRITICAL ANOMALY] {tag}: Value={val:.2f} (Z-Score: +{z_score:.2f}σ, > Extreme Fence)")
        elif z_score > 2.0 or val > tukey_upper:
            print(f" [SUSPICIOUS]       {tag}: Value={val:.2f} (Z-Score: +{z_score:.2f}σ, > Upper Fence)")

if __name__ == "__main__":
    # 模擬某重要主機連續 14 天的外部出網資料量 (單位: MB)
    historical_traffic = [
        12.5, 15.0, 11.8, 14.2, 13.0, 16.5, 14.1, 
        12.0, 13.5, 15.2, 11.0, 14.8, 13.9, 1250.0 # 最後一天爆發 1.25 GB 巨量外洩
    ]
    days = [f"Day {i+1}" for i in range(14)]
    detect_anomalies(historical_traffic, days)
```

| **Q7：該異常是否為業務大幅擴張或新產品上線導致的「新常態」？** | 業務背景調研：企業近期是否發布了重大促銷（如雙 11、週年慶）導致訪問量翻倍？若為業務增長，應對模型進行「重新基線化（Re-baselining）」。 |

### 1. 異常偏離處置與動態隔離 SOP

當基線模型捕獲到確鑿的多維度異常偏離時，依序執行阻斷流程：

```bash
# 步驟 1：針對異常偏離實體進行精準隔離 (以 Linux 主機為例)
# 透過 Ansible 或 EDR 下發指令，阻斷除資安取證端口外的所有外聯
iptables -I OUTPUT -p tcp --dport 22 -j ACCEPT
iptables -I OUTPUT -m state --state ESTABLISHED,RELATED -j ACCEPT
iptables -A OUTPUT -j DROP

# 步驟 2：提取該時間點的網路通訊與行程快照 (保留取證證據)
netstat -tunap > /tmp/anomaly_netstat.txt
ps auxf > /tmp/anomaly_ps.txt

# 步驟 3：在 SIEM 中將該實體標記為 "Compromised_Triage"，拉高其關聯威脅分值 (Risk Score +50)
```

### 2. 生產環境大數據基準線模型加固與維護規範

1. **實施滾動式時間窗口（Rolling Baseline Window）**：
   - 基準線不可一成不變，必須每週動態滾動計算過去 30 天數據，使演算法自動適應企業組織規模的平滑增長。
2. **剔除歷史髒數據（Data Sanitization）**：
   - 在每週重新訓練模型前，自動排除過去被標記為 `True Positive` 惡意攻擊事件的時間段，防止「攻擊常態化」污染基準線。
3. **雙重門檻過濾（Double-Gating Constraint）**：
   - 所有統計學偏離規則，必須強制加上**「絕對數值保護鎖（Absolute Threshold Gate）」**。
   - 例：`where z_score > 3.0 AND bytes_transferred > 50MB`，徹底杜絕因分母過小引發的除零錯誤與微幅擾動誤報。

### 實戰驗證步驟

#### 步驟 1：載入歷史日誌集並建立統計基準
執行 Python 基線分析腳本：
```python
import numpy as np

# 模擬某伺服器過去 30 天正常出網流量 (單位: MB, 均值 50MB, 標準差 5MB)
np.random.seed(42)
baseline_data = np.random.normal(loc=50, scale=5, size=30).tolist()

mean = np.mean(baseline_data)
std = np.std(baseline_data)
threshold_3sigma = mean + (3 * std)

print(f"[*] 歷史 30 天流量基準線: 均值={mean:.2f} MB, 標準差={std:.2f} MB")
print(f"[+] 3-Sigma 動態警報門檻值: {threshold_3sigma:.2f} MB")
```

#### 步驟 2：注入第 31 天測試流量（包含合法業務高峰與惡意資料外洩）
```python
test_traffic = [
    {"name": "正常日常流量", "value": 52.1},
    {"name": "業務月初小高峰", "value": 62.5}, # 稍微偏高但仍在合理範圍
    {"name": "黑客微量資料竊取", "value": 85.0}  # 惡意滲透外發！
]
```

#### 步驟 3：運行偏離度裁決演算法
```python
for item in test_traffic:
    val = item["value"]
    z = (val - mean) / std
    is_anomaly = val > threshold_3sigma
    status = "🚨 [CRITICAL ALERT] 觸發異常偏離！" if is_anomaly else "✅ [PASS] 正常業務波動"
    print(f"測試項目: {item['name']:<12} | 流量: {val:5.1f} MB | Z-Score: {z:+5.2f}σ | 判定結果: {status}")
```

#### 步驟 4：檢驗執行輸出結果
```text

[+] 3-Sigma 動態警報門檻值: 63.53 MB
測試項目: 正常日常流量      | 流量:  52.1 MB | Z-Score: +0.61σ | 判定結果: ✅ [PASS] 正常業務波動
```

## 📋 過關驗收檢查點 (Mastery Checklist)

- [ ] **Q1：在資安大數據分析中，傳統「靜態閾值告警」面臨的最大痛點是什麼？動態基準線（Baseline）如何解決該問題？**
  - *驗收標準*：答出靜態閾值若設太高會被黑客利用「低於閾值之慢速滲透」完全繞過（漏報）；若設太低則隨業務擴張引發大量警報疲勞（誤報）。動態基準線透過統計學方法隨歷史業務自動滾動學習均值與浮動區間，能在不依賴固定死值的前提下精準捕捉相對異常。
- [ ] **Q2：簡述 3-Sigma 原則（Z-Score）在常態分佈數據中的機率意涵。為什麼在資安領域通常將門檻設定為 $Z > 3$ 而非 $Z > 1$？**
  - *驗收標準*：答出在常態分佈中，$|Z| \le 1$ 涵蓋了 68.3% 的日常數據，若設為 1 會有高達 31.7% 的正常業務觸發警報（嚴重誤報）；而 $|Z| > 3$ 的發生機率僅為 0.27%，代表這是極低機率發生的極端異常，非常契合資安告警追求高精確度的要求。
- [ ] **Q3：面對明顯偏態（Skewed）、有極端突波的非高斯日誌（如網路傳輸位元組、登入失敗數），為什麼推薦使用四分位距（IQR）而非標準差（$\sigma$）？**
  - *驗收標準*：答出標準差的計算高度依賴平均值，極易受到少數極端突波（Outliers）的拉扯而嚴重失真（導致標準差過大從而漏檢攻擊）；而 IQR 採用中位數與第 25/75 百分位數，具備極強的抗干擾穩健性（Robustness）。
- [ ] **Q4：在設計 Splunk 基線查詢規則時，為什麼必須強制加入「絕對數值保護鎖（Absolute Gate）」？請舉一具體誤報案例。**
  - *驗收標準*：答出當歷史背景值極小（如某伺服器過去從無失敗登入，均值 0、標準差 0）時，只要今天出現 1 次微小的人工輸錯密碼，計算出來的 Z-Score 就會趨近無限大引發致命誤報。必須加上 `AND count > 10` 等絕對約束方可有效壓制統計噪聲。
- [ ] **Q5：什麼是歷史訓練資料集的「數據污染（Data Poisoning / Baseline Contamination）」？藍軍如何防範此現象？**
  - *驗收標準*：答出若歷史訓練數據中包含了先前未被發現的長期潛伏黑客通訊、蠕蟲爆發或大規模維運流量，演算法會誤將惡意攻擊納入「正常基準」，導致後續同類攻擊被漏報。防範措施為：在訓練基線前清洗並剔除歷史已確認的資安事件時間段，且引入同儕集群（Peer Group）多維交叉驗證。
