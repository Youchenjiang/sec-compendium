# 實戰手冊 27.3：紫隊 (Purple Teaming) 協同演練實務、防禦覆蓋熱圖與 ATT&CK 閉環

## 案發現場破題

在傳統的企業紅藍對抗演習中，常見一種割裂且低效的現象：紅隊（Red Team）在限定時間內竭盡所能撕裂防線，演習結束後丟下一份上百頁充滿艱深術語與漏洞清單的滲透測試報告；藍隊（Blue Team）則在毫無情境脈絡的情況下疲於奔命，不知哪些攻擊曾觸發日誌但未產生告警、哪些技術在端點根本未產生任何遙測。雙方陷入「紅隊炫技、藍隊背鍋」的零和博弈。

現代化資安成熟度講求「紫隊協同演練（Purple Teaming Practice）」——打破紅藍邊界，以透明協同、即時交流的方式同桌作戰。紅隊每執行一項特定 TTP（例如：T1055 處理程序注入、T1558.003 Kerberoasting），藍隊即時在 SIEM/EDR 感測台上觀察是否有對應的 Event ID、日誌延遲時間是多少秒、Sigma 規則是否精準命中。

雙方共同使用 **MITRE ATT&CK Navigator** 繪製防禦覆蓋熱圖（Detection Heatmap），量化真實防禦能力，並當場調校規則將防禦盲點（Red）轉化為具備即時阻斷能力的強固點（Green），實現從「對抗驗證 ➔ 遙測審視 ➔ 規則修補 ➔ 矩陣更新」的黃金閉環。


## 第一動：紫隊演練生命週期與協同作戰規範

### 1.1 紫隊演練四大標準階段（Exercise Lifecycle）
1. **準備階段（Preparation）**：
   - 確定演習範疇（Scope）：限定特定核心網段或 Active Directory 森林。
   - 建立演習劇本（Playbook Selection）：依據威脅情資（CTI）選定 10~20 項當前產業最常遭遇的 APT TTPs。
   - 工具鏈校時：確保紅隊攻擊發起機與藍隊 SIEM 伺服器時間完全 NTP 同步（誤差 < 1 秒）。
2. **執行與觀測階段（Execution & Observation）**：
   - 紅隊「慢速、透明」執行單一步驟。
   - 藍隊即時展示螢幕，核對該微秒端點日誌與網路 PCAP 是否捕獲。
3. **即時調校階段（Real-time Tuning）**：
   - 若發生漏報，立即修改偵測邏輯（如調整 Sysmon 配置檔或重寫 SPL）。
4. **回顧與度量階段（Reporting & Metrics）**：
   - 產出 ATT&CK Navigator JSON 圖層，計算本次演練的「防禦提升百分比（Delta %）」。

### 1.2 防禦成熟度四級量化計分模型
- **Score 0（盲區 Blind Spot）**：無任何感測器記錄該行為。
- **Score 30（日誌存在 Telemetry Only）**：日誌落盤但無告警規則，只能事後手動鑑識搜尋。
- **Score 70（規則告警 Alerted）**：SIEM/EDR 在 5 分鐘內觸發高危通知。
- **Score 100（即時阻斷 Blocked / Mitigated）**：防禦系統在行為發生當下主動終止進程或切斷連線。

## 第二動：ATT&CK Navigator 圖層架構與特徵語法

### 2.1 ATT&CK Navigator Layer JSON 規範
Navigator 圖層由標準 JSON 格式構成，核心屬性包含：
- `techniques` 陣列：記載 `techniqueID`、`tactic`、`score`（分數）、`color`（色碼）、`comment`（演練筆記）。
- `gradient`：顏色漸層定義（例如：0 分為紅色 `#ff6666`，100 分為綠色 `#00cc66`）。

### 2.2 典型技術標籤與註釋格式
每項技術標記中應詳實記錄：
- 測試時間戳。
- 觸發之具體命令。
- 對應之 SIEM 告警名稱與檢索語法。
- 負責調校之工程師與改善建議。

## 第三動：手動獵捕與鑑識分析（Navigator JSON 自動化生成）

### 3.1 Python 自動化產生紫隊演習 ATT&CK Navigator Layer 檔案
```python
import json
import datetime

def generate_purple_layer(exercise_results, output_file="purple_exercise_layer.json"):
    print(f"[*] 開始編譯紫隊演練 ATT&CK Navigator Layer 圖層...")

    layer_template = {
        "name": f"Purple Team Exercise - {datetime.date.today()}",
        "versions": {
            "attack": "14",
            "navigator": "4.9.1",
            "layer": "4.5"
        },
        "domain": "enterprise-attack",
        "description": "企業級紫隊實戰演習端到端防禦覆蓋閉環評估",
        "gradient": {
            "colors": ["#ff6666", "#ffcc00", "#33cc33"],
            "minValue": 0,
            "maxValue": 100
        },
        "techniques": []
    }

    score_colors = {
        0: "#ff6666",    # 紅色: 盲點未捕獲
        30: "#ff9933",   # 橙色: 僅有日誌無告警
        70: "#ffcc00",   # 黃色: 觸發告警
        100: "#33cc33"   # 綠色: 成功阻斷
    }

    for item in exercise_results:
        tech_entry = {
            "techniqueID": item["id"],
            "score": item["score"],
            "color": score_colors.get(item["score"], "#ffffff"),
            "comment": f"測試手法: {item['test_name']} | 狀態: {item['status']} | 筆記: {item['note']}",
            "enabled": True
        }
        layer_template["techniques"].append(tech_entry)

    with open(output_file, "w", encoding="utf-8") as f:
        json.dump(layer_template, f, indent=2, ensure_ascii=False)

    print(f"[+] 成功匯出 Navigator 圖層檔案: {output_file} (收錄 {len(exercise_results)} 項技術)")

if __name__ == '__main__':
    mock_results = [
        {"id": "T1003.001", "score": 100, "test_name": "LSASS Memory Dump", "status": "Blocked", "note": "Defender ASR 即時攔截"},
        {"id": "T1059.001", "score": 70, "test_name": "PowerShell EncodedCommand", "status": "Alerted", "note": "Sysmon EID 1 觸發 SPL 告警"},
        {"id": "T1055.001", "score": 30, "test_name": "Dynamic-link Library Injection", "status": "Telemetry Only", "note": "有 EID 8 但無偵測規則"},
        {"id": "T1070.004", "score": 0, "test_name": "File Deletion SDelete", "status": "Blind Spot", "note": "Sysmon 排除名單誤過濾"}
    ]
    generate_purple_layer(mock_results)
```

## 第四動：SIEM 關聯規則與端點威脅指標工程

### 4.1 Splunk 整合演練時序軸追蹤演練進度
在演習專用 Dashboard 中，將演習發起時間與端點告警建立對齊時序視窗：
```spl
index=soc_alerts sourcetype="siem:notable"
| eval exercise_window=if(_time >= strptime("2026-09-14 09:00:00", "%Y-%m-%d %H:%M:%S") AND _time <= strptime("2026-09-14 17:00:00", "%Y-%m-%d %H:%M:%S"), "IN_EXERCISE", "NORMAL")
| search exercise_window="IN_EXERCISE"
| stats count by rule_name, urgency, src_ip, dest_ip, signature_id
| eval verification="Purple Team Validated"
| table rule_name, signature_id, count, urgency, verification
```

### 4.2 Sigma 規則快速調校範例（以 T1055.001 DLL 注入為例）
演習中發現原規則因過濾條件過寬導致漏報，現場即時優化：
```yaml
title: Refined Process Injection into Legitimate Host Process
id: 4f1a2389-11c2-48a2-9102-8823194a0033
status: production
description: 演練現場調校：精準排除微軟合法簽名之 svchost 行為，鎖定非預期模組跨進程寫入
logsource:
  category: process_access
  product: windows
detection:
  selection:
    TargetImage|endswith: '\notepad.exe'
    GrantedAccess: '0x1F0FFF'
  filter_legit:
    SourceImage|startswith: 'C:\Windows\System32\'
  condition: selection and not filter_legit
level: critical
```

## 第五動：企業級防禦硬化與應急響應阻斷

### 5.1 建立紫隊常態化防禦改進追蹤看板（Jira / Kanban）
- 針對所有得分為 0（盲點）或 30（僅有日誌）的技術項目，直接指派 Ticket 至工程團隊：
  - **任務 A（端點補盲）**：更新 Sysmon XML 設定檔，取消特定過濾排除規則。
  - **任務 B（規則開發）**：由偵測工程師在 48 小時內編寫新版 Sigma 簽章。
  - **任務 C（二次驗收）**：安排自動化 Atomic 測試重新驗證，直到得分轉為 70 或 100 才能結案。

### 5.2 跨部門資安文化轉型
- 紫隊演練的根本目的不是評判輸贏，而是透過開放協作，消弭開發、運維、SOC 與滲透測試人員之間的資訊壁壘，將防禦覆蓋率指標轉化為全體技術團隊的共同 KPI。
