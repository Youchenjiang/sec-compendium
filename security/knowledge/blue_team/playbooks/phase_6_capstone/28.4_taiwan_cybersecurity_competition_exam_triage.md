# 實戰手冊 28.4：台灣資安法規遵從、關鍵基礎設施通報與資安競賽實體檢定 (金盾獎)

## 案發現場破題

在台灣的資安防禦實務中，藍隊人員不僅需要具備頂尖的技術分析與取證實力，更必須熟悉在地法規政策框架與重大事件通報機制。特別是依據台灣《資通安全管理法》（Cybersecurity Management Act）及其施行細則，面對針對國家關鍵基礎設施（CI, Critical Infrastructure）、公務機關或特定非公務機關之網路攻擊，資安應變人員必須在極為嚴苛的法定時限內（1 小時內通報、36 至 72 小時內完成損害控制與復原）完成事件級別判定與通報應變。

同時，台灣資安界最具指標性、歷史最悠久的國家級攻防競賽——「行政院國家資通安全科技中心 / 數位發展部金盾獎（Golden Shield Award）」與「T-CHALLENGE 資安實務競賽」，長年將客觀題（資安法規、密碼學、網路協定、風險評估）與實體術科題（逆向工程、封包鑑識、日誌分析、Web 滲透防禦）列為考核核心。

本實戰手冊作為全課綱藍隊百篇手冊的終極壓軸篇章，旨在打破「法規與技術脫鉤」的傳統弊病，將台灣《資通安全管理法》四大責任等級、四級事件通報標準，無縫融入金盾獎與企業級重大事件實體應變情境中，建立「技術鑑識 ➔ 法規通報 ➔ 損害圍堵 ➔ 根因分析（RCA） ➔ 體系稽核」的完整專業閉環。

## 第一動：台灣《資通安全管理法》四級事件判定標準速查表

在接獲重大告警時，資安長（CISO）與應變小組成員第一動必須依法判定級別，切忌遲報或匿報：

### 1.1 資通安全事件級別劃分矩陣（依《資通安全事件通報及應變辦法》）
| 事件級別 | 業務影響範疇 | 資料洩漏等級 | 法定通報時效 | 損害控制時效 |
| :--- | :--- | :--- | :--- | :--- |
| **第 1 級事件** | 非核心業務系統或設備遭中斷或影響 | 非屬核心機敏資料之一般資料洩漏 | 知悉後 **1 小時內** | **72 小時內** |
| **第 2 級事件** | 非核心業務系統無法運作，或核心業務遭短暫干擾 | 涉及核心業務機敏資料輕微洩漏 | 知悉後 **1 小時內** | **72 小時內** |
| **第 3 級事件** | 核心業務系統中斷，或關鍵基礎設施運作受損 | 涉及國家機密、密級以上或巨量個資外洩 | 知悉後 **1 小時內** | **36 小時內** |
| **第 4 級事件** | 國家關鍵基礎設施停擺、國安受威脅、社會秩序重大動盪 | 國家絕對機密外洩或跨機關重大骨幹癱瘓 | 知悉後 **1 小時內** | **36 小時內** |

## 第三動：金盾獎實體術科——封包鑑識與通訊協定逆向真題推演

金盾獎實體術科常給定數十 MB 至數百 MB 之 PCAP 封包，要求選手在極短時限內萃取出暗藏於應用層協定中的 Flag 或惡意指令：

### 3.1 提取 Modbus / SCADA 工控協定異常指令
在關鍵基礎設施演練題目中，攻擊者常竄改 PLC 暫存器數值：

```bash
# 1. 使用 tshark 篩選 Modbus 寫入暫存器之功能碼 (Function Code 0x06 或 0x10)
tshark -r /evidence/goldenshield_scada.pcap -Y "modbus.func_code == 16" -T fields -e frame.time -e ip.src -e modbus.reference_num -e modbus.data

# 2. 檢測特定異常寫入值（如強行關閉冷卻閥門之危險指令）
# 發現封包編號 1420 包含異常高壓寫入值 0xFFFF
```

### 3.2 提取 ICMP 隱蔽通道所藏之二進位 Flag
```python
# 腳本範例：自金盾獎 PCAP 萃取 ICMP Data 區段拼湊 Flag (solve_icmp_flag.py)
import pyshark

cap = pyshark.FileCapture('/evidence/goldenshield_forensic.pcap', display_filter='icmp.type == 8')

payload_bytes = bytearray()
for pkt in cap:
    try:
        # 提取 ICMP 負載最後 4 位元組
        raw_data = pkt.icmp.data.binary_value
        payload_bytes.extend(raw_data[-4:])
    except AttributeError:
        continue

# 搜尋 FLAG{} 格式
data_str = payload_bytes.decode('latin-1', errors='ignore')
start = data_str.find("FLAG{")
if start != -1:
    end = data_str.find("}", start)
    print(f"[+] 成功奪得金盾獎實體題 Flag: {data_str[start:end+1]}")
```

## 第四動：金盾獎實體術科——記憶體取證與 Linux 隱蔽後門查殺

### 4.1 檢測 Linux 動態庫預載入劫持 (LD_PRELOAD)
在金盾獎系統鑑識題中，主機常被植入用戶態 Rootkit，導致 `ls`, `ps`, `netstat` 皆無法看見惡意行程：

```bash
# 1. 繞過遭劫持之動態庫，直接以靜態二進位或安全模式檢視預載檔案
LD_PRELOAD="" /bin/cat /etc/ld.so.preload

# 輸出發現惡意共用庫：
# /lib/x86_64-linux-gnu/libhacker_hide.so

# 2. 永久清除劫持設定並恢復唯讀鎖定
LD_PRELOAD="" /bin/rm -f /etc/ld.so.preload
LD_PRELOAD="" /bin/chattr +i /etc/ld.so.preload
```

## 第五動：法定復原完成驗證與結案報告提報 (Post-Incident Review)

### 5.1 依規提報「資通安全事件調查處理及改善報告」
事件平息後，機關必須於一個月內依數位發展部標準範本提出檢討報告，核心章節包含：
1. **事件根因分析（Root Cause Analysis, RCA）**：如未落實邊界設備弱點更新（違反管理法第十條）。
2. **損害評估與影響清查**：確認外洩個資筆數（如符合《個人資料保護法》通報要件）。
3. **加固改善措施**：全面導入多因子身分認證（MFA）、啟用零信任架構（ZTA）端點健康度度量。
4. **懲處與獎懲建議**：依資通安全責任等級分級辦法辦理。

### 5.2 責任等級防護控制要求查核矩陣 (A / B / C 級機關)
依據《資通安全責任等級分級辦法》，不同責任等級之機關有嚴格的防護防線實施規範：

| 查核控制項目 | A 級機關規範要求 | B 級機關規範要求 | 藍隊合規落地查核方法 |
| :--- | :--- | :--- | :--- |
| **SOC 監控運作** | 需建置或委外 SOC 進行 7x24 全天候監控 | 需建置或委外 SOC 進行監控 | 驗證日誌進線即時性與告警 SLA 達成率 |
| **弱點掃描頻率** | 每半年至少執行一次弱點掃描 | 每年至少執行一次弱點掃描 | 檢驗 Nessus/OpenVAS 掃描報告與修補工單 |
| **滲透測試演練** | 每年至少辦理一次全網滲透測試 | 每兩年至少辦理一次滲透測試 | 審查滲透測試修補驗證報告 |
| **紅藍對抗演習** | 每兩年至少參與一次政府機關攻防演練 | 依主管機關指定參與 | 實施 Atomic Red Team / Caldera 自主驗證 |
