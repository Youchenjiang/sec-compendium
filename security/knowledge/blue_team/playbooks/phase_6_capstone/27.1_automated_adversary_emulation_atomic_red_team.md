# 實戰手冊 27.1：自動化對抗測試 (Atomic Red Team)、防禦遙測評估與日誌捕獲閉環

## 案發現場破題

傳統藍隊在部署 SIEM 關聯規則與 EDR 偵測簽章後，往往面臨一個致命的「薛丁格防禦狀態」：在未遭到真實駭客入侵前，沒有人能 100% 確定當特定攻擊技術發生時，端點的 Sysmon、Windows Security Event Log 或網路 IDS 是否能如期產生遙測資料，更無法保證 SIEM 的 SPL/KQL 偵測規則能否及時觸發高危告警。

這正是「防禦驗證工程（Breach & Attack Simulation, BAS）」與「紫隊原子化對抗測試（Atomic Red Team）」的核心價值。由 Red Canary 主導的開源框架 Atomic Red Team 將 MITRE ATT&CK 矩陣中的數百種 TTPs（戰術、技術與程序）解構為可重複、高精度、可安全執行的「原子測試案例（Atomic Tests）」。

藍隊防禦工程師透過手動或以 PowerShell `Invoke-AtomicTest` 觸發特定攻擊動作（例如：T1003.001 憑證轉儲、T1059.001 PowerShell 下載執行、T1070.004 檔案反鑑識抹除），並在微秒至秒級的時間窗口內檢驗日誌管線（Telemetry Pipeline）是否成功捕獲關鍵特徵、計算遙測覆蓋率（Telemetry Coverage Gap），最終達到「測一項、補一項、穩固一項」的防禦閉環。

```
紫隊原子化測試與遙測驗證閉環迴路 (The Atomic Verification Loop)：

[測試發起 (Atomic Execution)]
  測試工程師 / CI-CD 對抗管道 ──> 發起指定 Atomic 測試
  例：Invoke-AtomicTest T1003.001 -TestNumbers 1 (MiniDumpWriteDump)
            │
            ▼
[端點感測層 (Telemetry Generation)]
  - Windows Event ID 10 (ProcessAccess: Source -> lsass.exe)
  - Sysmon Event ID 10 (TargetImage: C:\Windows\system32\lsass.exe, GrantedAccess: 0x1FFFFF)
            │
            ├─ [遙測中斷/未產生] ──► 🚨 發現防禦盲點！修補 Sysmon XML 設定
            ▼
[日誌轉發與吸納 (Log Ingestion)]
  Universal Forwarder ──> Splunk Indexer (index=windows sourcetype=XmlWinEventLog:Microsoft-Windows-Sysmon/Operational)
            │
            ▼
[告警引擎觸發 (Detection Execution)]
  Sigma / SPL 關聯規則比對 ──> 觸發 True Positive 高危告警！
            │
            ▼
[防禦加固與收尾 (Cleanup & ATT&CK Update)]
  Invoke-AtomicTest T1003.001 -Cleanup ──> 恢復乾淨系統狀態，更新 ATT&CK 矩陣
```

## 第一動：Atomic Red Team 架構與測試安全規範

### 1.1 Atomic 測試四項基本結構（Test Spec）
每個 Atomic 測試均以 YAML 規範嚴格定義：
1. **Attack Commands**：實際執行的命令列語法（支援 Command Prompt, PowerShell, Bash, Python）。
2. **Prerequisites（前置相依性）**：測試所需的工具或二進位程式（如 Mimikatz、Procdump、Rubeus）。
3. **Get-Prereqs**：自動自官方受信任來源拉取測試工具的指令碼。
4. **Cleanup Commands**：**最關鍵的環節**！測試完成後必須完整清除暫存檔案、還原註冊表修改、停止測試服務，確保端點環境零殘留、無後遺症。

### 1.2 測試安全原則與防護護欄（Safety Guardrails）
- **嚴禁在未授權生產環境盲目執行全矩陣測試**：必須在特定測試主機或經過隔離的 Active Directory 驗證靶場中執行。
- **參數審查**：避免測試代碼夾帶未經確認的外部 C2 IP 或破壞性指令（如 `vssadmin delete shadows`）。
- **測試前預留快照**：虛擬機在執行高破壞性原子測試前，必須先建立快照以備不可逆損壞。

## 第二動：遙測遺失（Telemetry Gap）診斷與定位指標

### 2.1 遙測中斷三層瓶頸排查表
| 故障層級 | 現象指標 | 根因排查方向 |
| :--- | :--- | :--- |
| **端點生成層** | 執行攻擊後，本機 `Get-WinEvent` 查無任何相關事件 ID | 本機稽核原則（Audit Policy）未啟用；Sysmon 配置檔過濾排除（Exclude 過嚴） |
| **傳輸轉發層** | 本機有日誌，但 SIEM 搜尋完全無紀錄 | Splunk Universal Forwarder 服務停止；網路 9997 埠遭內部防火牆阻斷 |
| **SIEM 剖析層** | SIEM 收到 Raw Log，但無法提取欄位或延遲數小時 | 日誌時間戳偏差（Clock Skew）；Props.conf 欄位正則萃取失效 |

## 第三動：手動獵捕與鑑識分析（Invoke-AtomicTest 實踐）

### 3.1 佈建與初始化 Invoke-AtomicTest 模組
```powershell
# 步驟 1：安裝 PowerShell 執行引擎
IEX (New-Object Net.WebClient).DownloadString('https://raw.githubusercontent.com/redcanaryco/invoke-atomicredteam/master/install-atomicredteam.ps1')
Install-AtomicRedTeam -getAtomics

# 步驟 2：檢驗特定技術可用測試 (以 T1003.001 憑證轉儲為例)
Invoke-AtomicTest T1003.001 -ShowDetailsBrief

# 步驟 3：檢查並下載相依工具
Invoke-AtomicTest T1003.001 -GetPrereqs
```

### 3.2 執行受控測試並即時觀察本機事件捕獲
```powershell
# 步驟 1：執行第 1 項測試 (使用 comsvcs.dll 導出 LSASS 記憶體)
Invoke-AtomicTest T1003.001 -TestNumbers 1

# 步驟 2：立即使用 PowerShell 查詢本機 Sysmon Event ID 10 (Process Access)
Get-WinEvent -FilterHashtable @{
    LogName = 'Microsoft-Windows-Sysmon/Operational'
    Id = 10
} -MaxEvents 5 | Format-List TimeCreated, Message

# 步驟 3：確認測試產生之暫存檔案並執行安全清理
Invoke-AtomicTest T1003.001 -TestNumbers 1 -Cleanup
```

### 3.3 Python 自動化遙測驗證評估腳本
```python
import subprocess
import json
import time

def verify_atomic_telemetry(technique_id, test_number, expected_process):
    print(f"[*] 啟動紫隊自動化驗證: {technique_id} (Test #{test_number})")
    
    # 執行 Atomic Test
    cmd_run = f"powershell -Command \"Invoke-AtomicTest {technique_id} -TestNumbers {test_number}\""
    res = subprocess.run(cmd_run, shell=True, capture_output=True, text=True)
    print(f"[+] 測試執行輸出: {res.stdout.strip()[:100]}...")

    # 等待 3 秒使日誌完成落盤
    time.sleep(3)

    # 驗證本機 Sysmon Event ID 1 (Process Creation) 是否成功捕獲預期行程
    ps_query = f"""powershell -Command "Get-WinEvent -FilterHashtable @{{LogName='Microsoft-Windows-Sysmon/Operational'; Id=1}} -MaxEvents 10 | Select-Object -Property Id, TimeCreated, Message | ConvertTo-Json" """
    audit_res = subprocess.run(ps_query, shell=True, capture_output=True, text=True)

    captured = False
    if audit_res.stdout:
        try:
            events = json.loads(audit_res.stdout)
            if not isinstance(events, list):
                events = [events]
            for ev in events:
                if expected_process.lower() in ev.get("Message", "").lower():
                    captured = True
                    print(f"[PASS] 遙測驗證成功！捕獲到預期進程: {expected_process}")
                    break
        except json.JSONDecodeError:
            pass

    if not captured:
        print(f"[FAIL] 遙測中斷 (Telemetry Gap)！端點日誌未捕獲到進程: {expected_process}")

    # 清理測試環境
    cmd_clean = f"powershell -Command \"Invoke-AtomicTest {technique_id} -TestNumbers {test_number} -Cleanup\""
    subprocess.run(cmd_clean, shell=True, capture_output=True)
    print("[*] 測試環境清理完成。")

if __name__ == '__main__':
    verify_atomic_telemetry("T1059.001", 1, "powershell.exe")
```

## 第四動：SIEM 關聯規則與端點威脅指標工程

### 4.1 Splunk 檢驗 Atomic 測試之端到端觸發閉環
```spl
index=sysmon EventCode=1 Image="*\\powershell.exe"
| eval CommandLine=lower(CommandLine)
| search CommandLine="*downloadstring*" OR CommandLine="*invoke-atomictest*"
| stats count min(_time) as test_time by host, User, ParentImage, Image, CommandLine
| eval verification_status=if(count > 0, "VERIFIED", "UNVERIFIED")
| table test_time, host, User, CommandLine, verification_status
```

## 第五動：企業級防禦硬化與應急響應阻斷

### 5.1 遙測覆蓋率度量與 ATT&CK 矩陣可視化
- **ATT&CK Navigator 評分工程**：
  - 每完成一個技術點的 Atomic 驗證，在 Navigator 矩陣標記狀態：
    - `Green (Score=100)`：已驗證——遙測日誌存在且 SIEM 即時告警。
    - `Yellow (Score=50)`：部分覆蓋——端點有紀錄但 SIEM 未建立偵測規則。
    - `Red (Score=0)`：盲點（Coverage Gap）——端點無日誌捕獲。

### 5.2 自動化持續驗證（Continuous Security Validation, CSV）
- 將 Atomic Red Team 整合至日常自動化管線（例如夜間於隔離沙盒定時執行 5 項核心 TTPs），若隔日早晨 SIEM 告警儀表板未收到觸發，自動發送 Ticket 警示日誌收集異常。

## 靶場實戰：從觸發 T1003 到還原 LSASS 存取日誌

### 實驗目標
在 Windows 鑑識靶機上，利用 Atomic Red Team 安全執行 T1003.001 憑證轉儲模擬，並透過事件檢視器與 Splunk 驗證 Event ID 10 捕獲率達 100%：

```powershell
# 步驟 1：執行特定測試案例 (comsvcs.dll MiniDump)
Invoke-AtomicTest T1003.001 -TestNumbers 1

# 步驟 2：檢驗 MiniDump 檔案是否產生於 C:\Windows\Temp\ 或 Temp 目錄
Test-Path C:\Windows\Temp\lsass.dmp

# 步驟 3：執行清理指令碼強制刪除 Dump 檔案
Invoke-AtomicTest T1003.001 -TestNumbers 1 -Cleanup
Test-Path C:\Windows\Temp\lsass.dmp # 預期為 False
```
