# 實戰手冊 28.2：大規模企業級實網攻防資料集 (Splunk BOTS) 深度研判與實戰奪旗

## 案發現場破題

在真實企業安全營運中心（SOC）中，資安分析師面對的不是教科書上幾條乾淨的範例日誌，而是海量、多源且高度交織雜訊的巨量資料（Big Data Telemetry）。由 Splunk 官方推出的 **Boss of the SOC (BOTS)** 是全球藍隊社群公認最高水準的實網入侵演習資料集。

BOTS 資料集完整模擬了一家跨國企業（例如「Frothly 釀酒公司」或「Wayne Enterprises」）在遭受全方位的 APT 組織入侵期間，所產生的數千萬筆真實日誌。其資料來源涵蓋：
1. **網路周界日誌**：Palo Alto NGFW 流量與威脅日誌、Suricata IDS 告警、Cisco ASA 連線紀錄；
2. **端點遙測資料**：Windows Security Event Log、全網 Sysmon 事件（Process Creation、Network Connect、Image Loaded、DNS Query）、osquery、Powershell Operational Log；
3. **Web 與雲端日誌**：AWS CloudTrail、MS Office 365 稽核日誌、NGINX / Apache / IIS Access Log；
4. **網路封包串流**：Splunk Stream 模組深度解析之 HTTP、DNS、SMTP、SMB 封包元資料。

本實戰手冊將帶領學員全面攻克 BOTS 實戰資料集（以 BOTSv2 / BOTSv3 核心情境為藍本），掌握在海量日誌中「精準下篩選器、層層收斂、快速識別惡意指標」的高階 SPL 技巧與奪旗思維。

```
Splunk BOTS 大規模企業日誌關聯分析與收斂漏斗模型 (BOTS Triaging Funnel)：

[數千萬筆海量企業日誌 (index=botsv2 / botsv3)]
   │ (第一階：巨量收斂 - 過濾已知資產與時間範圍)
   ├─ earliest="08/24/2026:00:00:00" latest="08/25/2026:23:59:59"
   ▼
[周界告警與異常流量 (sourcetype=suricata / pan:threat)]
   │ (第二階：威脅錨定 - 鎖定觸發嚴重告警之內部受害主機 IP)
   ├─ 抓取 alert.severity=1 且關聯 dest_ip -> 192.168.2.20
   ▼
[受害主機端點行為 (sourcetype=XmlWinEventLog:Microsoft-Windows-Sysmon/Operational)]
   │ (第三階：行為還原 - 追蹤 Event ID 1 親子行程樹與 CLI 參數)
   ├─ CommandLine 檢索 LOLBAS (certutil, powershell -enc, mshta)
   ▼
[網路深度元資料 (sourcetype=stream:http / stream:dns)]
   │ (第四階：傳輸還原 - 萃取外傳封包 Header、URI、Payload 與 C2 域名)
   ▼
[精準奪旗與案件定性 (Capture The Flag & RCA)]
   └─ 產出破獲之 Flag 與攻擊者 IOC 總表
```

## 第一動：BOTS 環境架構、Index 佈局與常見 Sourcetype 快速對照

在 BOTS 演練前，必須熟知資料來源的分類，避免在錯誤的 Sourcetype 中大海撈針：

### 1.1 BOTS 核心日誌分類與索引表
| 日誌類型 | 典型 Sourcetype | 欄位命名特徵 (CIM / Splunk) | 關鍵鑑識定位 |
| :--- | :--- | :--- | :--- |
| **端點行程遙測** | `XmlWinEventLog:Microsoft-Windows-Sysmon/Operational` | `EventCode`, `Image`, `CommandLine`, `ParentImage` | 惡意程式啟動、LOLBAS 注入 |
| **端點安全日誌** | `WinEventLog:Security` | `EventCode=4624`, `TargetUserName`, `LogonType` | 暴力破解、憑證傳遞、橫向登入 |
| **網路串流 HTTP** | `stream:http` | `src_ip`, `dest_ip`, `uri`, `http_user_agent`, `status` | Web 攻擊載荷、C2 通訊內容 |
| **網路串流 DNS** | `stream:dns` | `query`, `query_type`, `record_type`, `reply_code` | DNS Tunneling、惡意 C2 查詢 |
| **網路周界防護** | `pan:traffic`, `pan:threat`, `suricata` | `action`, `signature`, `severity`, `app` | 外對內掃描阻斷、C2 簽章比對 |

## 第二動：初始突破口鎖定——Web 掃描與 RCE 漏洞利用定位

### 2.1 篩選外部 Web 異常存取流量
透過 `stream:http` 分析針對企業內部 Web 伺服器（例：`192.168.2.20`）之高頻探索：

```spl
index=botsv2 sourcetype=stream:http dest_ip=192.168.2.20
| stats count, values(uri) as sample_uris by src_ip, http_user_agent
| sort - count
```
**分析技巧**：
- 檢查非正常之 User-Agent（如 `sqlmap`, `nikto`, `curl`, `python-requests`）。
- 若發現大量 URI 返回 HTTP 404，而少數返回 HTTP 200/500，重點檢查返回 HTTP 200 之請求內容。

### 2.2 定位利用 Struts / REST API 漏洞之惡意載荷
```spl
index=botsv2 sourcetype=stream:http dest_ip=192.168.2.20 status=200
| search uri="*struts*" OR uri="*.action" OR "Content-Type: *multipart*"
| table _time, src_ip, uri, request_headers, payload
```
**奪旗關鍵**：從 `request_headers` 中發現包含 OGNL 表達式注入（`#_memberAccess`），其發起攻擊之外部 IP 即為初始攻擊者來源。

## 第三動：端點行為深挖——Sysmon 攻擊鏈還原

### 3.1 追蹤 Web 行程衍生之惡意子行程（Event ID 1）
當 Web 伺服器（如 Tomcat / IIS）遭 RCE 攻陷後，其母行程（如 `w3wp.exe` 或 `java.exe`）必然會衍生系統 Shell：

```spl
index=botsv2 sourcetype="XmlWinEventLog:Microsoft-Windows-Sysmon/Operational" EventCode=1
| eval ParentImage=lower(ParentImage)
| search ParentImage="*w3wp.exe" OR ParentImage="*tomcat*.exe" OR ParentImage="*httpd.exe"
| table _time, host, ParentImage, Image, CommandLine, User
```
**實戰發現**：
- `w3wp.exe` 於 `08:42:15` 衍生 `powershell.exe -NoP -NonI -W Hidden -Enc SQBFAFgA...`
- 立即使用 SPL 將 Base64 命令解碼進行語意分析。

### 3.2 解碼 PowerShell Base64 命令列
```spl
index=botsv2 sourcetype="XmlWinEventLog:Microsoft-Windows-Sysmon/Operational" EventCode=1 Image="*powershell.exe"
| rex field=CommandLine "-(enc|encodedcommand)\s+(?<b64_cmd>[A-Za-z0-9+/=]+)"
| where isnotnull(b64_cmd)
| eval clean_b64=b64_cmd
| table _time, host, CommandLine, clean_b64
```
將取出的 Base64 字串透過 CyberChef 或 Python 轉碼，確認為 Empire / Cobalt Strike 之 Stager 下載指令。

## 第四動：憑證存取與橫向移動軌跡關聯 (Lateral Movement Pivot)

### 4.1 檢測 Mimikatz / Procdump 對 LSASS 之記憶體存取（Event ID 10）
攻擊者取得本機管理員權限後，必會嘗試轉儲憑證：

```spl
index=botsv2 sourcetype="XmlWinEventLog:Microsoft-Windows-Sysmon/Operational" EventCode=10
| search TargetImage="*\lsass.exe"
| stats count by _time, host, SourceImage, GrantedAccess, CallTrace
| where NOT (SourceImage LIKE "%\csrss.exe" OR SourceImage LIKE "%\services.exe")
```
**鑑識結論**：發現 `C:\Temp\procdump.exe` 以 `GrantedAccess=0x1FFFFF` 讀取 `lsass.exe` 產生 `lsass.dmp`。

### 4.2 檢測橫向移動：WMI 與 SMB 遠端登入（Event ID 4624 LogonType 3）
```spl
index=botsv2 sourcetype="WinEventLog:Security" EventCode=4624 Logon_Type=3
| search Target_User_Name!="ANONYMOUS LOGON" AND Target_User_Name!="*$"
| stats count, values(Source_Network_Address) as src_hosts, values(Target_User_Name) as users by host
| sort - count
```
**軌跡還原**：攻擊者自 `192.168.2.20` 利用管理員帳號 `frothly_admin` 透過 SMB 遠端登入 `192.168.2.5`（財務伺服器）並上傳二進位後門。

## 第五動：C2 連線與資料外洩分析 (C2 Beaconing & Exfiltration)

### 5.1 統計可疑 DNS 查詢頻率與長度異常
```spl
index=botsv2 sourcetype="stream:dns"
| eval query_length=len(query)
| where query_length > 40
| stats count, avg(query_length) as avg_len by query, src_ip
| sort - count
```
**分析指標**：發現大量長度超過 50 字元、形如 `[hex].ns1.hacker-c2.net` 的高頻查詢，判定為 DNS Tunneling。

### 5.2 提取 HTTP 外洩敏感資料大小與標頭
```spl
index=botsv2 sourcetype="stream:http" dest_ip!=192.168.* AND dest_ip!=10.*
| stats sum(bytes_out) as total_exfil, values(uri) as uris by src_ip, dest_ip, http_method
| sort - total_exfil
```

### 5.3 實務外洩指標關聯與封包 Payload 提取
在鎖定異常傳輸後，進一步使用 `stream:http` 提取外傳之檔案特徵與傳輸方法：

```spl
index=botsv2 sourcetype="stream:http" dest_ip=198.51.100.88
| eval payload_len=len(payload)
| table _time, src_ip, dest_ip, http_method, uri, payload_len, http_content_type
```
**關鍵判斷指標**：
1. 觀察 HTTP POST 請求頻率是否具備規律性（Jitter < 10%），判斷是否為自動化腳本定期回傳。
2. 檢查封包中是否夾帶 `application/octet-stream` 或二進位檔案標頭（如 PK、7z 檔頭特徵）。
