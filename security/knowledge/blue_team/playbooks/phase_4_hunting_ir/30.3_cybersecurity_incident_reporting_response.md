# 實戰手冊 30.3：資通安全事件通報及應變辦法 (1小時通報/36小時復原) 與演練實務

## 案發現場破題

在台灣《資通安全管理法》體系中，《資通安全事件通報及應變辦法》是所有藍隊人員面對突發入侵時最關鍵的法定處置準則。法律明文規定：不論是公務機關或特定非公務機關（關鍵基礎設施、公營事業、政府捐助之財團法人），只要**「知悉」**資通安全事件發生，必須在**「1 小時內」**完成通報程序。

某國營水利機構在週六清晨遭到勒索軟體攻擊，外部監控服務供應商（MSSP）於 03:15 發出高危告警。然而該機構的輪值工程師直到 06:30 才通知資訊主管，並在上午 09:00 才於「國家資通安全通報應變網站（N-ISAC / N-CERT）」填報資安事件通報單。

這起處置導致該機構直接違法：
1. **通報延遲違法**：自知悉（03:15）至正式通報（09:00）耗時近 6 小時，遠超法定 1 小時上限！
2. **級別判定錯誤**：將影響民生供水控制系統之重大事件判定為「2 級事件」，導致主管機關未能及時啟動跨部會國家級聯防！
3. **法律追責與裁罰**：主管機關依管理法第二十條處以數十萬元罰鍰，並將延遲通報人員移送考績委員會懲處。

本實戰手冊將深入解構法定「1~4 級事件判定決策樹」、「知悉後 1 小時通報 SOP」、「36/72 小時復原控制」以及「1 個月內調查改善報告」之全流程標準規範，並提供自動化通報工具與金盾獎實戰闖關演練。


## 第一動：資通安全事件 1~4 級法定裁量基準與研判決策樹

### 1.1 事件等級裁量標準矩陣（依《資通安全事件通報及應變辦法》附表）
| 事件等級 | 核心業務中斷標準 | 機密性衝擊標準 | 完整性衝擊標準 | 法定損害控制時效 |
| :--- | :--- | :--- | :--- | :--- |
| **第 1 級** | 非核心業務系統或設備遭中斷，但未中斷一般日常營運 | 非機密性、非核心機敏資料遭洩漏 | 系統或網頁遭竄改，但未影響營運 | **72 小時內** |
| **第 2 級** | 非核心業務系統無法運作，或核心業務短暫受干擾但未中斷 | 核心業務機敏資料輕微洩漏（未達國家機密） | 核心系統資料遭輕微竄改但可迅速復原 | **72 小時內** |
| **第 3 級** | 關鍵基礎設施或核心業務系統中斷，但未達全國性癱瘓 | 涉及國家機密、密級以上資訊或巨量個資外洩 | 核心資料庫遭惡意竄改且影響業務運作 | **36 小時內** |
| **第 4 級** | 國家安全受威脅、關鍵基礎設施全面停擺、社會秩序動盪 | 國家絕對機密外洩或跨部會核心骨幹資料全洩 | 國家關鍵基礎設施核心控制系統永久毀損 | **36 小時內** |

### 1.2 現場事件等級 30 秒研判決策流程 (Decision Workflow)

```text
[ 接獲確證之資安事件 (True Positive Incident) ]
                     │
                     ▼
  [ Q1: 是否導致國家安全動盪或關鍵基礎設施全面停擺? ]
       ├── YES ──► 🚨 【定性：第 4 級事件】(36小時內完成復原)
       └── NO
             │
             ▼
  [ Q2: 是否造成關鍵基礎設施/核心業務中斷或國家機密外洩? ]
       ├── YES ──► 🚨 【定性：第 3 級事件】(36小時內完成復原)
       └── NO
             │
             ▼
  [ Q3: 核心業務是否遭短暫干擾或核心機敏資料輕微洩漏? ]
       ├── YES ──► ⚠️ 【定性：第 2 級事件】(72小時內完成復原)
       └── NO  ──► 🟡 【定性：第 1 級事件】(72小時內完成復原)
```

## 第二動：知悉後 1 小時通報通報單填報核心規範 (Notice Field Standards)

通報不是寫抒情文，必須提供可供 N-ISAC / N-CERT 與聯防體系快速阻斷的結構化情資：

### 2.1 通報單必填八大關鍵欄位清單
1. **通報者與聯絡窗口**：機關名稱、通報人員姓名、緊急聯絡電話與電子郵件。
2. **事件發生與知悉時間**：記錄準確至分鐘（UTC+8），此處為法規稽核之關鍵基準點。
3. **受害資產屬性**：主機名稱、IP 位址、資產重要性評等（是否為核心資通系統）。
4. **事件類別**：阻斷服務 (DoS)、未授權存取、惡意程式植入、網頁竄改、機敏資料外洩。
5. **攻擊來源指標 (IOCs)**：來源 IP、惡意網址 (URL)、C2 域名、惡意檔案 SHA-256 雜湊。
6. **初步影響評估**：受影響之服務、影響範圍百分比、初判事件等級 (1~4 級)。
7. **已採行之緊急應變措施**：拔除網路線、防火牆阻斷黑名單、重設管理者密碼。
8. **後續支援需求**：是否需要國家資安署或外部應變專家團隊進駐技術支援。

## 第三動：自動化事件通報輔助與時效倒數計時工具 (Incident Countdown CLI)

藍隊人員可建立自動化倒數腳本，確保在處置事件過程中絕對不逾越法定時效：

```python
# 腳本範例：法定應變通報與復原時效倒數器 (legal_incident_timer.py)
import datetime

class IncidentTimer:
    def __init__(self, discovered_time_str, incident_level):
        self.discovered_at = datetime.datetime.fromisoformat(discovered_time_str)
        self.level = int(incident_level)
        self.report_deadline = self.discovered_at + datetime.timedelta(hours=1)
        self.recovery_deadline = self.discovered_at + datetime.timedelta(hours=36 if self.level in [3, 4] else 72)

    def check_status(self, current_time=None):
        now = current_time or datetime.datetime.now(datetime.timezone.utc)
        report_remaining = (self.report_deadline - now).total_seconds() / 60
        recovery_remaining = (self.recovery_deadline - now).total_seconds() / 3600

        print(f"[*] 事件知悉時間: {self.discovered_at.isoformat()}")
        print(f"[*] 判定事件等級: 第 {self.level} 級事件")
        
        if report_remaining > 0:
            print(f"[!] 🚨 通報法定倒數: 剩餘 {report_remaining:.1f} 分鐘 (需於知悉後 1 小時內完成)")
        else:
            print(f"[FAIL] ❌ 通報已違法超期！超期 {-report_remaining:.1f} 分鐘")

        if recovery_remaining > 0:
            print(f"[!] ⏰ 復原法定倒數: 剩餘 {recovery_remaining:.2f} 小時 (限期 {36 if self.level in [3,4] else 72} 小時內完成)")
        else:
            print(f"[FAIL] ❌ 損害控制與復原已超期！")

timer = IncidentTimer("2026-09-15T02:00:00+00:00", incident_level=3)
timer.check_status(datetime.datetime.fromisoformat("2026-09-15T02:40:00+00:00"))
```

## 第四動：重大事件損害控制與跨機關支援程序 (Eradication & Support)

### 4.1 申請外部支援機制與啟動條件
當機關遭受 3 級或 4 級重大資安事件且自身技術量能不足以圍堵時：
1. **向主管機關提出技術支援申請**：於通報單勾選「需主管機關支援」，數位發展部資通安全署將派遣「國家資安緊急應變小組（E-SIRT）」進駐。
2. **配合鑑識證據保全**：外部團隊進駐前，本地工程師嚴禁重灌伺服器或覆蓋硬碟，必須保留 RAM Snapshot 與原始日誌。
3. **每日進度滾動通報**：在 36 小時損害控制期間，應變小組應每 4 至 8 小時更新通報系統備忘錄。

## 第五動：資通安全事件調查處理及改善報告編撰範本 (RCA Report Template)

事件平息並解除列管後，必須於法定期限 **一個月內** 提報正式結案報告：

### 5.1 調查改善報告核心架構表
| 章節結構 | 填寫重點與要求 | 藍隊檢附佐證 |
| :--- | :--- | :--- |
| **一、事件發生概要** | 人事時地物、受影響資產、事件起始與復原完成時間 | 系統告警截圖、通報單序號 |
| **二、技術根因分析** | 攻擊手法還原（Kill Chain）、CVE 漏洞編號、攻擊路徑 | ATT&CK 標定矩陣、PCAP/EVTX 日誌片段 |
| **三、損害評估** | 資料洩漏筆數、系統停機時長、直接與間接經濟損失 | 資料庫存取審計日誌、個資盤點表 |
| **四、緊急應變過程** | 隔離步驟、補償控制、防毒特徵更新與修補程式安裝 | 防火牆規則設定異動單、系統上線檢核單 |
| **五、長期改善對策** | 網路架構重構、零信任 (ZTA) 導入、密鑰輪換機制 | 預算規劃書、設備採購時程表 |

### 5.2 主管機關審查指標與退件風險防範
提報結案改善報告時，若存在以下情事，極易遭數位發展部或上級機關退件並要求限期重辦：

| 退件常見態樣 | 稽核認定缺失 | 改善合規對策 |
| :--- | :--- | :--- |
| **根因草率歸咎員工** | 僅載明「同仁點擊釣魚郵件」，未分析系統層面缺少郵件防護或隔離機制 | 深入分析 Mail Gateway、EDR 規則為何未在端點即時防堵 |
| **未提具體改善期程** | 改善措施填寫「加強資安教育訓練」，缺乏量化時程與驗收指標 | 明列下季度全體同仁社交工程演練合格率需達 95% 以上 |
| **鑑識跡證鏈不完整** | 未留存受害當下記憶體 Dump 或硬碟 SHA-256 映像雜湊 | 檢附符合 ISO 27037 規範之鑑識證據保管鏈 (CoC) 清冊 |
| **未執行漏洞修補驗證** | 宣稱已修補漏洞，但未檢附重測 (Retest) 之弱點掃描報表 | 檢附 Nessus 掃描零高危之驗收紀錄與組態變更工單 |
