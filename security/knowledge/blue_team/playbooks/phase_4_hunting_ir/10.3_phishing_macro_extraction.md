## 🧩 第一動：底層機制/協定解剖 (Mechanics & Physical Structs)

### 2.1 Office 文件實體儲存結構的物理本質
微軟 Office 文件主要分為兩大世代架構，其巨集存在形式截然不同：

```
1. 舊版 OLE2 複合文檔 (Compound File Binary Format - CFBF)
   - 附檔名：.doc, .xls, .ppt
   - 魔術字元 (Magic Bytes)：D0 CF 11 E0 A1 B1 1A E1 (又稱 "Docfile")
   - 物理組織：類似小型檔案系統，包含 FAT (File Allocation Table)、Directory Entries 與多個 Stream。
   - 巨集位置：存放於 `_VBA_PROJECT_CUR` 或 `Macros/VBA` 專屬二進位串流中。

2. 新版 Office Open XML (OOXML)
   - 附檔名：.docx (無巨集), .docm (啟用巨集), .xlsx, .xlsm
   - 魔術字元：50 4B 03 04 (標準 PKZip 壓縮封裝包)
   - 物理組織：內含 XML 設定檔架構。當包含巨集時，壓縮包內必定含有：
     `word/vbaProject.bin` 或 `xl/vbaProject.bin`
   - `vbaProject.bin` 本身即為一個封裝在 ZIP 內的 OLE2 CFBF 結構！
```

### 2.2 MS-OVBA 巨集壓縮演算法架構
VBA 源代碼在寫入 `vbaProject.bin` 時，並非直接以 ASCII/UTF-8 明文儲存，而是經由微軟專屬的 **MS-OVBA (VBA Compression Algorithm)** 進行封裝：
1. **Header (標頭)**：包含壓縮標記與模組資訊。
2. **Chunk (資料塊)**：每個 Chunk 大小為 4096 位元組，內含壓縮位元標記 (Flag Byte)。
3. **Token (詞法標記)**：字串與關鍵字經壓縮 Token 化。
> *這就是為什麼直接使用 Notepad 或普通的 `strings` 工具打開文檔時，往往只能看見亂碼或斷斷續續的片段。`oledump.py` 或 `pcodedmp` 的核心功能就是對 MS-OVBA 進行解壓縮與 P-Code 還原。*

### 2.3 巨集自動觸發事件矩陣 (Auto-Execution Triggers)
攻擊者無法直接在使用者開啟檔案時執行任意代碼，必須仰賴 Office 預設內建的生命週期事件回呼：

| 應用程式類別 | 自動觸發回呼函數名稱 (Auto-Execution Events) | 觸發時機點 |
| :--- | :--- | :--- |
| **Word (.doc/.docm)** | `AutoOpen()`, `Document_Open()` | 文件開啟並啟用巨集瞬間自動執行 |
| **Word (.doc/.docm)** | `AutoClose()`, `Document_Close()` | 使用者點擊關閉視窗或退出 Word 時觸發 |
| **Excel (.xls/.xlsm)**| `Auto_Open()`, `Workbook_Open()` | 工作簿開啟瞬間自動執行 |
| **Excel (.xls/.xlsm)**| `Workbook_Activate()`, `SheetCalculate()` | 切換工作表或儲存格重新計算時觸發 |
| **PowerPoint (.pptm)**| `Auto_Open()`, `SlideShowNextClick()` | 幻燈片播放或點擊滑鼠時觸發 |

### 3.1 oledump.py 實戰提取三部曲
`oledump.py`（由 Didier Stevens 開發）是全球 DFIR 與 SOC 研判 Office 惡意巨集的黃金標準工具。

```bash
# 步驟 1：列舉文件內的所有資料串流 (Streams)
python3 oledump.py maldoc.docm

# 輸出範例：
#   1:        4096 'word/fontTable.xml'
#   2:         812 'word/settings.xml'
#   3:        1204 'word/vbaProject.bin'
#   4: A       512 'VBA/_VBA_PROJECT'
#   5: M     14205 'VBA/NewMacros'   <-- 注意！標記為 'M' 代表此 Stream 含有巨集代碼！

# 步驟 2：提取指定巨集串流並進行解壓縮 (以串流編號 5 為例，-s 指定串流，-v 自動解壓縮 MS-OVBA)

# 步驟 3：快速清查串流中所有可讀 ASCII/Unicode 字串 (無需解壓代碼)
python3 oledump.py -s 5 -a maldoc.docm
```

### 3.2 巨集自動化分析與去混淆器 (`macro_triage.py`)
針對現代攻擊者常用的 Chr() 拼接與反轉字串混淆，編寫以下 Python 自動化分析腳本：

```python
#!/usr/bin/env python3
"""
macro_triage.py - Weaponized Office Macro Automated Analysis Tool
自動化反混淆常見 VBA 惡意模式 (Chr 數值還原、StrReverse、Shell 呼叫萃取)
"""
import sys
import re

def deobfuscate_chr(content):
    """將 Chr(xx) 數值拼接與字串串接還原為明文字串"""
    def chr_replace(match):
        try:
            num = int(match.group(1))
            if 32 <= num <= 126:
                c = chr(num)
                if c == '"':
                    return '""'
                return f'"{c}"'
            return f'"\\x{num:02x}"'
        except Exception:
            return match.group(0)

    pattern = re.compile(r'Chr[W\$]?\s*\(\s*(\d+)\s*\)', re.IGNORECASE)
    cleaned = pattern.sub(chr_replace, content)
    # 連續合併字串拼接: "a" & "b" -> "ab"
    prev = ""
    while prev != cleaned:
        prev = cleaned
        cleaned = re.sub(r'"\s*&\s*"', '', cleaned)
    return cleaned

def triage_macro(file_path):
    print(f"[*] 讀取解壓縮之巨集源碼: {file_path} ...")
    with open(file_path, 'r', encoding='utf-8', errors='ignore') as f:
        raw_code = f.read()

    print("=" * 80)
    print("1. 觸發事件檢測 (Execution Triggers):")
    triggers = ["AutoOpen", "Auto_Open", "Document_Open", "Workbook_Open", "Document_Close", "AutoClose"]
    found_triggers = [t for t in triggers if re.search(r'\b' + t + r'\b', raw_code, re.IGNORECASE)]
    if found_triggers:
        print(f"  🔴 [高危觸發器] 命中: {', '.join(found_triggers)}")
    else:
        print("  🟢 未發現標準自動觸發器 (可能依賴控制項回呼)")

    print("\n2. 高危系統呼叫與 API 檢測 (Suspicious APIs):")
    risky_apis = [
        ("Shell Execution", r'\b(Shell|CreateObject\("WScript\.Shell"\)|WScript\.Shell|ShellExecute)\b'),
        ("Process Spawning", r'\b(Win32_Process|CreateProcess|cmd\.exe|powershell\.exe)\b'),
        ("Network Download", r'\b(URLDownloadToFile|MSXML2\.XMLHTTP|WinHttp\.WinHttpRequest)\b'),
        ("File Operations", r'\b(Scripting\.FileSystemObject|WriteAllText|ADODB\.Stream|SaveToFile)\b')
    ]
    deob = deobfuscate_chr(raw_code)
    for category, pattern in risky_apis:
        matches = set(re.findall(pattern, raw_code, re.IGNORECASE) + re.findall(pattern, deob, re.IGNORECASE))
        if matches:
            print(f"  🔴 [{category}] 命中關鍵字: {matches}")
        else:
            print(f"  🔴 [{category}] 命中關鍵字: set()")

    print("\n3. 自動去混淆處理 (Deobfuscation Preview):")
    # 尋找 URL 特徵
    urls = re.findall(r'https?://[a-zA-Z0-9\.\-_/:\?=%&]+', deob)
    if urls:
        print("  👉 提取出之潛在 C2 / 下載網址 (Extracted URLs):")
        for u in sorted(set(urls)):
            print(f"     [+] {u}")

    # 尋找 PowerShell / CMD 命令列 (排除註解行)
    code_only = re.sub(r"^\s*'.*$", "", deob, flags=re.MULTILINE)
    commands = re.findall(r'(powershell[^\r\n"]+|cmd\.exe[^\r\n"]+)', code_only, re.IGNORECASE)
    if commands:
        print("  👉 提取出之下發命令列 (Extracted Shell Commands):")
        for cmd in sorted(set(commands)):
            print(f"     [!] {cmd.strip()}")

    print("=" * 80)

if __name__ == "__main__":
    if len(sys.argv) < 2:
        print(f"使用方式: python3 {sys.argv[0]} <extracted_macro.vba>")
        sys.exit(1)
    triage_macro(sys.argv[1])
```


### 5.2 長期架構加固 (Long-term Hardening)
1. **阻斷自互聯網下載文件的巨集執行 (Mark of the Web - MOTW)**：
   - 透過 GPO 啟用群組原則：
     `使用者設定 ➔ 系統管理範本 ➔ Microsoft Word 2016 ➔ Word 選項 ➔ 信任中心`

## 📋 過關驗收檢查點 (Mastery Checklist)

- [ ] **Q1：為什麼使用 `strings` 工具直接檢視 `.docm` 檔案，往往找不到巨集裡的關鍵網址，但用 `oledump.py -v` 卻能看見？**  
  *考核核心*：新版 `.docm` 本質上是一個 PKZip 壓縮檔，巨集二進位檔案 `vbaProject.bin` 封裝在其中；更重要的是，`vbaProject.bin` 內部的 VBA 源碼採用了微軟特有的 MS-OVBA 壓縮演算法。若不透過 ZIP 解壓縮並對 MS-OVBA 解碼（`oledump -v` 所執行的動作），原始碼字串將處於壓縮狀態而無法被普通的 ASCII 檢視工具讀取。

- [ ] **Q2：在 `oledump.py` 的輸出清單中，串流指示符號 `M` 與 `m` 分別代表什麼物理含義？**  
  *考核核心*：大寫字母 `M` 代表該串流內包含可解壓縮的完整 VBA 代碼（Macro Code）；小寫字母 `m` 代表該串流包含巨集模組屬性或標頭，但其源代碼長度為 0（通常僅包含屬性定義或編譯後的 P-code 殘留，無實質文本）。SOC 分析師應優先提取帶有 `M` 標記的串流。

- [ ] **Q3：微軟在現代 Windows 環境中推行的「MOTW (Mark of the Web)」機制，是如何阻斷武器化巨集攻擊鏈的？**  
  *考核核心*：當使用者從網際網路、郵件客戶端或瀏覽器下載檔案時，NTFS 檔案系統會自動在該檔案附加一個名為 `Zone.Identifier` 的交替資料串流 (Alternate Data Stream - ADS)，並註記 `ZoneId=3`（代表 Internet）。Office 2016/365 檢測到此標記後，會預設強制阻斷巨集執行，不再顯示黃色的「啟用內容」允許點擊，從根源粉碎透過社交工程誘導使用者啟動巨集的攻擊手段。

- [ ] **Q4：攻擊者為什麼要在巨集中利用 `UserForm`（使用者表單）的控制項屬性來隱藏惡意 Shellcode 或 PowerShell 腳本？**  
  *考核核心*：為了防禦靜態 YARA 與基於代碼文本的防毒簽章。傳統 AV 會掃描 VBA 模組中的危險函數與可疑字串。攻擊者將載荷（如 Base64 腳本）切割存放在表單控制項（如 Label.Caption, TextBox.Text）的二進位資源串流中，VBA 模組本身只保留數行合法的屬性讀取代碼，在運行時動態取出組裝，藉此達成靜態繞過。

- [ ] **Q5：若遇到一個惡意文件，其 VBA 源代碼已被完全清除（VBA Purging），但文件開啟時仍然能執行惡意行為，其底層原理是什麼？該如何鑑識？**  
  *考核核心*：此技術稱為 **VBA Purging (P-Code 執行)**。Office 在編譯巨集時會生成底層位元組碼 P-Code 與可讀源代碼。攻擊者可刻意將儲存源代碼的模組清空或填零，但保留編譯好的 P-Code。當受害者的 Office 版本與攻擊者編譯時的版本完全一致時，Office 會直接執行 P-Code 而忽略缺失的源代碼。鑑識員必須使用專門針對 P-Code 進行反彙編的工具（如 `pcodedmp.py`）方能還原其真實指令。
