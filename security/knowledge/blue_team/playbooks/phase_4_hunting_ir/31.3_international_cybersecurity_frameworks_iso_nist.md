# 實戰手冊 31.3：國際資安管理與網路安全框架 (ISO 27001:2022 / NIST CSF 2.0) 藍隊技術落實

## 案發現場破題

在現代企業與關鍵基礎設施的防禦體系中，藍隊人員的日常工作（部署 EDR、調校 SIEM 規則、分析惡意封包、清查特權帳號）並非無章法的技術拼湊，而是直接受控於國際兩大主流資安框架——**ISO/IEC 27001:2022** 與 **NIST Cybersecurity Framework (NIST CSF 2.0)**。

某跨國金融控股公司在準備申請 ISO 27001:2022 轉版驗證與主管機關監理查核時，外部主任稽核員（Lead Auditor）在實地訪查 SOC 監控中心時，要求藍隊主管出示：
1. **控制項 A.8.16（活動監控 Monitoring Activities）** 之落實佐證與偵測告警規則基準線；
2. **控制項 A.8.28（安全編碼 Secure Coding）** 與 CI/CD 軟體物料清單 (SBOM) 弱點審查紀錄；
3. **NIST CSF 2.0 新增核心功能「治理（Govern, GV）」** 下對供應鏈第三方風險（GV.SC）的持續監控技術軌跡。

由於該金控的藍隊長期處於「救火式維運」，防禦規則與國際框架完全脫節：既無法提出資產監控覆蓋率矩陣，亦無法交代 SIEM 規則對應至哪些具體控制目標，導致稽核開立多達 5 項「重大不符合事項（Major Non-Conformity）」，面臨撤銷 ISO 27001 證書的重大危機！

本實戰手冊旨在打破「管理框架歸顧問、技術實作歸工程師」的傳統壁壘，將 ISO 27001:2022 四大主題（93 項控制項）與 NIST CSF 2.0 六大核心功能（Govern, Identify, Protect, Detect, Respond, Recover），精準映射至藍隊日常的 Sysmon、Splunk、YARA、Suricata 與漏洞管理技術管線中，建立工業級的架構合規閉環。


## 第一動：ISO/IEC 27001:2022 附錄 A 四大主題架構與技術控制項速查

ISO 27001:2022 將舊版 114 項控制項精簡整併為四大主題共 93 項控制項，其中「技術控制項（Technological Controls）」是藍隊必須 100% 掌握的核心：

### 1.1 藍隊核心技術控制項 (Clause A.8) 與系統配置對照表
| 控制項編號與名稱 | 控制目標核心 | 藍隊技術落實作法 | 稽核抽驗標準佐證 |
| :--- | :--- | :--- | :--- |
| **A.8.7 防範惡意軟體 (Malware)** | 防止惡意二進位代碼執行 | 端點佈署 EDR/AV，啟用 AMSI 行為監控 | EDR 代理程式線上率 99% 報表 |
| **A.8.8 技術弱點管理 (Vulnerabilities)**| 及時評估並修補已知弱點 | 每月執行全網漏洞掃描，7 天修補高危 | 弱掃修補追蹤清單與變更工單 (RFC) |
| **A.8.9 組態管理 (Configuration)** | 建立系統安全基準組態 (CIS) | 透過 GPO / Ansible 強制套用安全基準 | CIS-CAT 基準稽核合規評分 ≥ 85% |
| **A.8.16 活動監控 (Monitoring)** | 記錄異常行為並及時告警 | 集中收集端點與網路日誌至 SIEM | 告警關聯規則庫與 SOC 值班處置紀錄 |
| **A.8.20 網路安全 (Network Security)** | 分割網路並防範未授權穿透 | 實施內部微隔離 (Microsegmentation) | 防火牆安全策略規則表與路由表 |
| **A.8.24 密碼學使用 (Cryptography)** | 機密資料傳輸與儲存加密 | 停用弱加密協定，全面啟用 TLS 1.3 | SSL Labs A+ 評級報告與金鑰清冊 |

## 第二動：NIST CSF 2.0 六大核心功能與實戰技術落地矩陣

NIST 於 2024 年正式發布 Cybersecurity Framework 2.0，正式將「治理（Govern）」獨立為第一核心：

### 2.1 NIST CSF 2.0 藍隊實作對應矩陣
```text
1. 治理 (Govern - GV)：
   - GV.OC: 確立組織資安目標與風險承受度
   - GV.SC: 供應鏈第三方風險管理 (審查供應商 SBOM 與 API 金鑰存取權)

2. 識別 (Identify - ID)：
   - ID.AM: 資產盤點與網路拓撲繪製 (使用 nmap / Asset Discovery 定期更新)
   - ID.RA: 風險評估與威脅建模 (結合 MITRE ATT&CK 建立攻擊面模型)

3. 保護 (Protect - PR)：
   - PR.AA: 身分驗證與存取控制 (啟用 FIDO2 / MFA，杜絕共用帳號)
   - PR.DS: 資料安全防護 (資料庫啟用 AES-256 透明加密與動態遮罩)

4. 偵測 (Detect - DE)：
   - DE.CM: 持續性安全監控 (SOC 7x24 即時分流，結合 Sigma/YARA 規則)
   - DE.AE: 異常事件分析 (識別網路連線與行程行為基準偏差)

5. 回應 (Respond - RS)：
   - RS.MA: 事件應變管理與 PICERL 圍堵 SOP 執行
   - RS.CO: 內部與外部通報 (知悉後 1 小時內通報主管機關)

6. 復原 (Recover - RC)：
   - RC.RP: 復原執行計畫 (依據 36 小時重大事件標準完成熱備援切換)
   - RC.IM: 事件後持續改善 (提交根因分析 RCA 與體系更新)
```

## 第三動：自動化合規性基準掃描與評分腳本 (Compliance Scorer CLI)

藍隊人員可撰寫自動化工具，量化評估主機或網段對國際框架的合規成熟度：

```python
# 腳本範例：ISO 27001 / NIST CSF 技術控制項成熟度評分器 (compliance_evaluator.py)
import json

class FrameworkEvaluator:
    def __init__(self, target_host):
        self.host = target_host
        self.controls = {
            "A.8.7_Malware_Defense": False,
            "A.8.8_Vulnerability_Scan": False,
            "A.8.16_Activity_Monitoring": False,
            "A.8.20_Network_Segmentation": False,
            "A.8.24_Cryptography_TLS13": False
        }

    def evaluate(self, telemetry_data):
        # 檢驗 EDR 狀態
        if telemetry_data.get("edr_installed") and telemetry_data.get("edr_running"):
            self.controls["A.8.7_Malware_Defense"] = True

        # 檢驗弱掃週期
        if telemetry_data.get("last_vuln_scan_days", 999) <= 30:
            self.controls["A.8.8_Vulnerability_Scan"] = True

        # 檢驗 Sysmon / SIEM 轉發
        if telemetry_data.get("sysmon_forwarding") and telemetry_data.get("siem_connected"):
            self.controls["A.8.16_Activity_Monitoring"] = True

        # 檢驗傳輸加密
        if telemetry_data.get("tls_version") in ["TLSv1.2", "TLSv1.3"] and not telemetry_data.get("weak_ciphers"):
            self.controls["A.8.24_Cryptography_TLS13"] = True

        score = (sum(self.controls.values()) / len(self.controls)) * 100
        return score, self.controls

test_telemetry = {
    "edr_installed": True,
    "edr_running": True,
    "last_vuln_scan_days": 15,
    "sysmon_forwarding": True,
    "siem_connected": True,
    "tls_version": "TLSv1.3",
    "weak_ciphers": False
}

evaluator = FrameworkEvaluator("srv-prod-db01.corp.internal")
score, details = evaluator.evaluate(test_telemetry)
print(f"[*] 主機: {evaluator.host}")
print(f"[+] ISO 27001:2022 控制項合規得分: {score:.1f}%")
print(f"[*] 控制項落實細節: {json.dumps(details, indent=2)}")
```

## 第四動：合規稽核追蹤工單與持續改進閉環 (PDCA Cycle in Blue Team)

ISO 27001 要求落實 PDCA 戴明環持續改善：
1. **Plan（規劃）**：依據威脅情資與風險評估，訂定偵測規則增訂計畫。
2. **Do（執行）**：將 Sigma 規則轉譯為 SPL 並上線至 SIEM 告警系統。
3. **Check（檢查）**：執行 Atomic Red Team 原子化測試，檢驗遙測捕獲率（覆蓋率 Audit）。
4. **Act（處置）**：針對測試遺失（Missed TTPs）調校 Sysmon XML 與關聯閥值。
