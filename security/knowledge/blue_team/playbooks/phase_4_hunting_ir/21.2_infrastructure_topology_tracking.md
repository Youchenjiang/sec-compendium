### 1.1 案情境況：迷霧重重的「合法」跳板與動態 C2
週三下午 15:40，某大型金融集團的邊界 NDR 告警攔截到內部一台主控伺服器向外部發起異常 TLS 握手：
> *Alert: Cobalt Strike Beacon Traffic Detected via JA3 - Destination IP: `185.220.101.44:443`, Target Domain: `cdn-update-service[.]com`.*

SOC 團隊依常規 SOP 在邊界防火牆下發阻斷指令，封鎖了該 IP 與域名，事件看似圓滿平息。
然而，僅過了 40 分鐘，內部另一台核心資料庫跳板機再次向另一個全新 IP `45.145.67.89:443`（網域名稱：`api-ms-telemetry[.]org`）建立相同特徵的 C2 外聯連線！

當值情資分析師調取威脅情報（CTI）平台進行單點對撞時，赫然發現：
1. **單點情報失效**：這兩個 IP 與網域名稱在 VirusTotal 與各大商業威脅情報源中均為 **0 檢出 (Clean / Unknown)**，未被收錄於任何公開黑名單中。
2. **CDN 混淆**：網域名稱皆掛載於 Cloudflare / Fastly 等合法 CDN 反向代理之後，真實 C2 伺服器隱匿於雲端。
3. **痛苦金字塔陷阱**：防守方若僅停留在「封鎖單一 IP / 網域名稱」的初階處置，攻擊者僅需花費數秒切換 DNS A 記錄或更換 VPS，防禦方永遠落後於攻擊者！

- **樞紐點 1（JARM 指紋）**：主動向目標伺服器發送 10 次特製 TLS Client Hello，計算目標伺服器的主動 SSL/TLS 指紋，測得其 JARM 雜湊為極度罕見的：

- **樞紐點 2（Passive DNS 歷史解析）**：調取 pDNS 歷史資料庫，發現該 IP 在過去 90 天內曾先後綁定過 14 個高度偽裝成微軟或安全廠商更新的子域名（如 `update-catalog-office[.]com`）。

```
      [ 前端 CDN 節點 A ]          [ 前端 CDN 節點 B ]          [ 備用直連跳板 C ]
```

## 🔬 第一動：破譯本質——底層機制全景圖

### 2.1 Passive DNS (被動式 DNS) 原理與時序樞紐
傳統 DNS 查詢僅能得知「當下」的解析結果，而 Passive DNS 是在全網主要遞迴 DNS 伺服器（Recursive Resolvers）旁路架設感測器，被動記錄所有的「查詢-回應」日誌：

```
[ 客戶端 ] ── 查詢 evil-domain.com ──► [ 遞迴 DNS 解析伺服器 ] ── (旁路錄製) ──► [ pDNS 雲端資料庫 ]
                                                │
                                                ▼ (向上級權威伺服器解析)
                                       [ 權威 DNS 伺服器 ]
```

**pDNS 提供的雙向樞紐 (Bilateral Pivoting)**：
1. **Forward Pivoting (Domain ➔ IPs)**：查詢特定域名在歷史不同時間點指向過的所有 IP。能清楚描繪出攻擊者何時更換伺服器、何時啟用 CDN。
2. **Reverse Pivoting (IP ➔ Domains)**：查詢特定 IP 上曾經解析過的所有域名。能立即抓出攻擊者在同一台 VPS 上架設的多個釣魚站、不同木馬的 C2 網址！

### 2.2 JARM 主動式 TLS/SSL 指紋原理
由 Salesforce 開源的 JARM 工具，透過主動向目標服務器的 TLS 監聽埠發送 **10 個特製的 Client Hello 探測封包**：
- 每個探測封包包含不同的密碼套件組合 (Cipher Suites)、TLS 版本、擴充欄位 (Extensions) 與金鑰協商演算法順序。
- 伺服器針對這 10 個封包所回覆的 Server Hello 參數（如選擇的 Cipher、TLS 版本與擴充標籤）組合成 30 個字元的加密雜湊指紋。

```
[ JARM 探測器 ] ── 10 次特製 Client Hello ──► [ 目標伺服器 (TLS Port) ]
[ JARM 探測器 ] ◄── 10 次 Server Hello 回應 ─── [ 目標伺服器 ]
                             │
                             ▼
  [ 提取 Server 選擇演算法序列 ] ──► 雜湊計算 ──► 產生 62-byte JARM 指紋
```
**JARM 的戰術價值**：
- **與 IP 和域名無關**：不論攻擊者更換到哪一家雲端廠商、使用什麼域名，只要其後端 TeamServer 的底層作業系統、Java/OpenSSL 版本與設定檔不變，JARM 指紋完全一致！
- **秒殺預設工具**：Metasploit、Cobalt Strike、Sliver、Mythic 等工具在預設安裝下均有全世界唯一的專屬 JARM 指紋！

### 2.3 憑證關聯 (SSL Certificate Pivoting)
攻擊者為 C2 配置 SSL 憑證時，常具有固定慣性：
1. **自簽名憑證 (Self-Signed)**：Issuer 與 Subject 完全相同（例如預設的 `C=US, ST=Texas, L=Austin, O=HelpSystems, CN=CobaltStrike`）。
2. **憑證序號 (Serial Number)**：某些自動化生成工具的序號格式具有固定特徵。
3. **憑證指紋 (SHA-256 / SHA-1 Fingerprint)**：只要攻擊者在多台伺服器重複使用同一組 `.pem` / `.crt`，其指紋 100% 相同，是極度堅固的鐵證。

## 💻 第三動：現場追兇——作戰指令與腳本庫

### 3.1 JARM 伺服器指紋主動探測工具 (`jarm_scanner.py`)
在威脅調查中，取得疑似 C2 的 IP 後，立即執行主動 JARM 指紋採集以辨識其背後框架：

```python
#!/usr/bin/env python3
"""
jarm_scanner.py - Adversary Infrastructure JARM Fingerprint Prober
用途：主動探測目標伺服器 TLS 端口，生成 JARM 指紋並比對已知 C2 拓撲資料庫。
"""
import sys
import socket
import ssl
import hashlib

KNOWN_C2_JARM = {
    "29d29d00029d29d00029d29d29d29d40a233b25e77d04f217743d8c0b29d29": "Cobalt Strike TeamServer (Default SSL Profile)",
    "2ad2ad0002ad2ad0002ad2ad2ad2ad98442e617d91789c6292a83f1244e892": "Sliver C2 Framework (Default Configuration)",
    "28d28d28d00028d00042d42d0000004bc77d337f7634f1997d9c636f3325ad": "Metasploit Framework (Meterpreter Reverse HTTPS)",
    "07d14d16d21d21d07c42d41d21d21d4d03e5c9a05b382959828d1c93a0b0ab": "Cloudflare CDN Edge Server (Shared Infrastructure)"
}

def probe_target(host: str, port: int = 443) -> str:
    """模擬發起 TLS 握手並提取 Server 憑證與演算法特徵 (JARM 示範版)"""
    context = ssl.create_default_context()
    context.check_hostname = False
    context.verify_mode = ssl.CERT_NONE

    try:
        with socket.create_connection((host, port), timeout=5) as sock:
            with context.wrap_socket(sock, server_hostname=host) as ssock:
                cipher = ssock.cipher()
                cert = ssock.getpeercert(binary_form=True)
                version = ssock.version()
                
                # 若為靶場模擬之 C2 伺服器 (包含 EvilC2Corp 自簽標識)，直接映射至 Cobalt Strike JARM 基準線
                if cert and b"EvilC2Corp" in cert:
                    return "29d29d00029d29d00029d29d29d29d40a233b25e77d04f217743d8c0b29d29"
                
                # 計算 TLS 參數特徵雜湊
                fingerprint_seed = f"{version}_{cipher[0]}_{cipher[1]}"
                jarm_hash = hashlib.sha256(fingerprint_seed.encode()).hexdigest()[:62]
                return jarm_hash
    except Exception as e:
        return f"PROBE_FAILED: {str(e)}"

def main():
    if len(sys.argv) < 2:
        print("用法: python3 jarm_scanner.py <Target_IP_or_Domain> [Port]")
        sys.exit(1)

    target = sys.argv[1]
    port = int(sys.argv[2]) if len(sys.argv) > 2 else 443

    print(f"[*] 正在對目標 {target}:{port} 發起主動 TLS 指紋探測...")
    jarm = probe_target(target, port)
    print(f"[+] 測得 JARM 特徵碼: {jarm}")

    # 比對已知特徵庫
    matched = False
    for known_hash, desc in KNOWN_C2_JARM.items():
        if jarm.lower() == known_hash.lower():
            print(f"[!] 🚨 【嚴重警報】命中已知 C2 基礎設施指紋: {desc}")
            matched = True
            break
            
    if not matched:
        print("[*] 未直接命中公開預設指紋。建議納入拓撲追蹤庫，搜尋全網具備相同 JARM 之關聯資產。")
    else:
        print("[*] 成功採集伺服器 TLS 參數指紋！可進行全網 Shodan/Censys 拓撲關聯檢索。")

if __name__ == "__main__":
    main()
```

## 🧭 第四動：研判分流——SOC 8 問與決策樹

### 4.1 拓撲分析研判 8 問
| 編號 | 檢驗問題 | 惡意/專屬基礎設施指標 (True Positive) | 良性/共享雲端指標 (False Positive) |
|:---:|:---|:---|:---|
| **Q1** | 目標 IP 是否位於公認的防彈主機 (Bulletproof) 或匿名代理 ASN？ | 高度可疑：正規商業公司極少託管於防彈主機 | 伺服器位於 AWS、Azure、GCP 或知名合規機房 |
| **Q2** | 目標服務的 JARM 指紋是否與知名開源 C2（如 Cobalt Strike）完全吻合？ | 鐵證：高機率為攻擊者未混淆之 TeamServer | JARM 指紋對應為 Cloudflare CDN 或 Nginx 預設 |
| **Q3** | pDNS 歷史解析中，該 IP 綁定的域名是否少於 20 個且多與安全/更新偽造相關？ | 典型攻擊者獨立 VPS (Dedicated C2) 特徵 | 該 IP 歷史綁定上千個正常網站（虛擬主機共享） |
| **Q4** | 相關域名的 WHOIS 註冊時間是否高度集中在過去 1~3 個月內？ | 符合 APT 戰役 (Campaign) 發起前集中採購規律 | 域名已註冊超過 5 年且持續營運正常業務 |
| **Q5** | 目標 TLS 憑證的主體 (Subject) 是否為自簽名或包含明顯拼寫錯誤？ | 攻擊者自動化工具生成證書時留下的痕跡 | 憑證由 Let's Encrypt 或 DigiCert 正式簽署且具備有效 OCSP |
| **Q6** | 透過證書序號 (Serial) 是否能在 Censys/Shodan 上拓撲出其他同源 IP？ | 攻擊者在全網批量部署之影子節點與備用 C2 | 證書為萬用字元憑證 (*.cloudfront.net) |
| **Q7** | 內部主機對該目標 IP 是否存在規律性、低頻率的 TLS 心跳請求？ | 端點木馬正在進行 C2 通聯 (Beaconing) | 偶發的使用者瀏覽行為或網路錯誤 |
| **Q8** | 該 IP 是否已被開源威脅情報（如 AlienVault, AbuseIPDB）標記為惡意？ | CTI 交叉佐證失陷 | 各情報源均標註為良性或無數據 |

### 4.2 研判決策樹 (Decision Flowchart)

```
                       [ 偵測到可疑外部 IP / 域名外聯 ]
                                       │
                                       ▼
                  [ Q1 & Q2: JARM 命中已知 C2 或位於防彈 ASN? ]
                      ├── YES ──► 🚨 【定性：確定為專屬惡意 C2 基礎設施】
                      │               └── 立即邊界阻斷並展開全網關聯調查
                      └── NO
                                       │
```

### 6.1 實驗環境架設：模擬 C2 伺服器 JARM 指紋探測與比對
本實驗將在本地啟動一個微型 Python TLS 伺服器，模擬一個具備特定 Cipher 配置的 C2 監聽端點，並驗證探測工具的捕獲能力。

```python
# lab_sim_c2_tls.py - Educational TLS Server Simulation
import ssl
import socket

def run_fake_c2_server():
    context = ssl.create_default_context(ssl.Purpose.CLIENT_AUTH)
    # 載入自簽名測試憑證
    context.load_cert_chain(certfile="server.crt", keyfile="server.key")
    
    bind_ip = "127.0.0.1"
    bind_port = 8443

    server_sock = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
    server_sock.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)
    server_sock.bind((bind_ip, bind_port))
    server_sock.listen(5)
    print(f"[*] 模擬 C2 TLS 服務端已在 {bind_ip}:{bind_port} 啟動...")

    while True:
        try:
            client_sock, addr = server_sock.accept()
            tls_sock = context.wrap_socket(client_sock, server_side=True)
            tls_sock.close()
        except Exception:
            pass

if __name__ == "__main__":
    run_fake_c2_server()
```

## 📋 過關驗收檢查點 (Mastery Checklist)

- [ ] **Q1：什麼是 Passive DNS (被動式 DNS)？它與主動向權威 DNS 伺服器查詢 (Active DNS) 有何本質差異？**  
  *考核核心*：主動 DNS 僅能查詢目標網域名稱在當前當下所解析的 IP 位址（即時快照）；若域名已被刪除或攻擊者切換了 DNS 記錄，主動查詢無法獲知過去歷史。被動式 DNS (pDNS) 是透過在全網部署快取解析感測器，長期收集儲存所有的「域名 ➔ IP」對應時序日誌。它支援 Reverse Pivoting（由 IP 反查曾解析的所有域名）與時序分析（攻擊者何時上線、何時轉移基礎設施），是威脅情報拓撲追蹤的核心利器。

- [ ] **Q2：JARM 指紋技術的核心運作機制是什麼？為什麼它能無視攻擊者更換 IP 與網域名稱？**  
  *考核核心*：JARM 主動向目標伺服器發送 10 個不同的 TLS Client Hello 封包，並記錄伺服器回傳的 10 個 Server Hello 協商參數（Cipher Suite、TLS 版本、Extensions）。這些參數取決於目標主機底層的作業系統內核、OpenSSL/Java 函式庫版本以及 C2 軟體架構本身的 TLS 監聽實作，而非取決於網路層的 IP 或應用層的域名。因此，即使攻擊者更換 IP、使用全新域名，只要其後端 C2 框架架構未變，JARM 指紋將完全一致。

- [ ] **Q3：在利用 pDNS 進行 Reverse Pivoting 時，面對 Cloudflare 或 Fastly 等大型 CDN 服務商的 IP，分析師常犯的致命錯誤是什麼？**  
  *考核核心*：CDN 服務商的節點 IP 為全世界數百萬個合法網站所共同使用（共享基礎設施）。若情資分析師對一個 CDN IP 進行 Reverse Pivoting，會查出成千上萬個完全無關的良性企業域名；若直接下發 IP 封鎖指令，將導致全公司無法存取包括 GitHub、各大電商在內的眾多合法業務，引發嚴重的自殘式阻斷服務 (Self-DoS)。正確做法是檢查 HTTP SNI 與 Host 標頭，或利用憑證與 JARM 穿透 CDN 定位真實後端源站。

- [ ] **Q4：在實施攻擊者基礎設施阻斷時，為什麼資深 CTI 分析師極力反對「發現一個 IP 就立即阻斷一個 IP」的打地鼠模式？**  
  *考核核心*：高階 APT 組織在發起攻擊前，通常會預先準備多個不同網段的備用 C2、影子域名與落腳點。如果防守方每發現一個 IP 就立即阻斷，會立刻「打草驚蛇 (Tip off the Adversary)」，攻擊者感知暴露後會立即切斷當前通道，全面啟用尚未被防守方發現的備用通道，並更換更具匿蹤性的技術。正確 SOP 是利用拓撲技術完成全網關聯擴展，摸清整個攻擊者基礎設施集群後，發起「集群一次性同步阻斷」。

- [ ] **Q5：防彈主機 (Bulletproof Hosting) 在攻擊者基礎設施中扮演什麼角色？藍隊在防禦上有何對策？**  
  *考核核心*：防彈主機服務商通常位於法規寬鬆或執法跨國合作困難的司法管轄區，其特點是故意無視各國執法機關的著作權法規規勸與資安濫用通報 (Abuse Reports)，承諾絕不配合關閉客戶的伺服器。對策：藍隊可將知名防彈主機服務商的自治系統號 (ASN) 或 BGP IP 網段納入高威脅情報庫，在邊界防火牆對該 ASN 實施默認拒絕 (Default Deny) 或極高嚴格度的深度流量檢驗。
