## 🚨 案發現場破題 (Incident Scenario & Mental Workflow)

### 1.1 案情境況：千辛萬苦抓到黑客，法庭上證據卻因瑕疵被判無效！
某跨國上市科技公司遭遇重大商業間諜竊密事件。資安團隊經過數週夜以繼日的排查，終於在某涉案離職員工留下的公司筆電中，成功還原出已被刪除的加密壓縮包與向境外網盤傳輸的歷史連線記錄。
公司委任律師提起刑事自訴與高額民事侵權賠償訴訟，警方與法官正式開庭審理。

然而，在法庭舉證與交互詰問攻防中，被告辯護律師針對該「鐵證」提出了致命質疑：
1. **未封裝無防寫**：資安工程師在第一時間採集筆電證據時，直接按下了電源鍵開機，並插上隨身碟複製檔案，未外接任何硬體防寫設備 (Hardware Write Blocker)，導致該系統硬碟在勘驗過程中有超過 1,200 筆檔案存取時間戳 (Access Time) 遭到作業系統靜默竄改！
2. **監管鏈記錄中斷 (Broken Chain of Custody)**：該硬碟在提取後，曾放置在 IT 部門無門禁管制的共用測試機房長達 5 天，期間有至少 4 位非鑑識專職工程師進出，且完全沒有任何「移交/借調簽署表單 (Custody Log)」。
3. **無雙雜湊即時固化**：在採集當下，工程師未即時計算 MD5 與 SHA-256 雙雜湊值並留存簽署封存袋，僅在兩週後提交分析報告時補附了一組雜湊。

法官採納了辯護律師的異議：**「因數位證據具備極易被竄改、覆蓋與偽造之物理特性，原告方未能證明採集過程之不可竄改性與全程監管鏈完整性，無法排除證據遭人為污染之合理懷疑，依法判定該數位證據欠缺證據能力 (Inadmissible in Court)！」**
公司因此敗訴，數千萬元研發機密損失徹底求償無門！

這起慘痛判例揭示了藍隊與 DFIR 工程師最容易忽視的血淋淋現實：**技術上查出真相只是前半場，在法律上守住證據能力 (Evidence Admissibility) 才是全場的勝利！**

## 🔬 第一動：破譯本質——底層機制全景圖

### 2.1 ISO/IEC 27037:2012 國際標準核心生命週期
ISO/IEC 27037 專門指導數位證據的處置規範，定義了四個不可逆轉的標準處理階段：

```
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│ 1. 識別         │     │ 2. 採集         │     │ 3. 獲取         │     │ 4. 保存         │
│ (Identification)│ ──► │ (Collection)    │ ──► │ (Acquisition)   │ ──► │ (Preservation)  │
│ 定位潛在證據載體│     │ 實體扣押/移置   │     │ 製作映像/Bit-by-│     │ 封裝於防竄改袋  │
│ 標記現場物理環境│     │ 貼上專屬證物標籤│     │ Bit 鏡像 (E01)  │     │ 恆溫恆濕金庫監管│
└─────────────────┘     └─────────────────┘     └─────────────────┘     └─────────────────┘
```

**數位證據的法定三大支柱（法定三性）**：
1. **合法性 (Legality)**：證據的取得必須符合法律授權（如搜索票、當事人書面同意書、公司資通訊安全使用政策授權）。非法竊聽或非法侵入電腦取得之檔案，觸犯「毒樹果實理論 (Fruit of the Poisonous Tree)」，法庭得全面排除。
2. **真實性 / 完整性 (Authenticity / Integrity)**：證明從案發現場扣押的原始位元組 (Bits)，與法庭呈堂呈交的二進位映像，其內容完全未受任何增刪、篡改或作業系統自動寫入。這由 **密碼學雙雜湊 (Dual-Hash, MD5 + SHA-256)** 予以擔保。
3. **關聯性 (Relevance)**：證據必須與待證犯罪事實（如誰在何時竊取了何檔案）具有直接或間接的因果推論關係。

### 2.2 監管鏈 (Chain of Custody, CoC) 的本質
**監管鏈是一份具有法律約束力的實體歷史檔案**。它必須鉅細靡遺地記錄：
> *「是誰（Who）、在什麼精確時間（When）、從哪裡（Where）、取得了什麼證物（What）、基於什麼目的（Why）、採取了什麼防護手段（How），以及此後每一次經手移交（Transfer）時的收受人簽名與狀態確認。」*

若監管鏈在任何一個時間點出現「無法解釋的空檔」或「未簽名經手人」，該數位證據即被認定為「監管鏈斷裂 (Broken Chain)」，在法庭上將遭受滅頂打擊！

## 💻 第三動：現場追兇——作戰指令與腳本庫

### 3.1 現場數位證據雙雜湊採集與固化工具 (`evidence_hasher.py`)
鑑識人員扣押外部磁碟或完成 Bit-by-Bit 鏡像後，必須立刻使用具備多執行緒的鑑識腳本計算雙雜湊，並生成不可篡改的查驗清單：

```python
#!/usr/bin/env python3
"""
evidence_hasher.py - Forensic Dual-Hash Generator (ISO/IEC 27037 Compliant)
用途：針對現場採集之映像檔或磁碟，即時計算 MD5 與 SHA-256 雙雜湊並產出合規存證報告。
"""
import sys
import hashlib
import os
import datetime

def calculate_dual_hash(file_path: str, block_size: int = 65536):
    md5 = hashlib.md5()
    sha256 = hashlib.sha256()
    total_bytes = 0

    print(f"[*] 開始讀取證物檔案: {file_path}")
    start_time = datetime.datetime.now()

    with open(file_path, 'rb') as f:
        while True:
            chunk = f.read(block_size)
            if not chunk:
                break
            md5.update(chunk)
            sha256.update(chunk)
            total_bytes += len(chunk)

    end_time = datetime.datetime.now()
    duration = (end_time - start_time).total_seconds()

    return {
        "file_name": os.path.basename(file_path),
        "file_size": total_bytes,
        "md5": md5.hexdigest(),
        "sha256": sha256.hexdigest(),
        "timestamp_utc": datetime.datetime.utcnow().isoformat() + "Z",
        "duration_sec": round(duration, 2)
    }

def main():
    if len(sys.argv) < 2:
        print("用法: python3 evidence_hasher.py <Evidence_Image_Path>")
        sys.exit(1)

    target_path = sys.argv[1]
    if not os.path.exists(target_path):
        print(f"[-] 錯誤：找不到證物檔案 {target_path}")
        sys.exit(1)

    result = calculate_dual_hash(target_path)
    
    report_content = f"""================================================================================
🏛️  ISO/IEC 27037 數位證據雜湊完整性固化存證報告
================================================================================
證物檔名 (File Name)        : {result['file_name']}
實體大小 (Size in Bytes)    : {result['file_size']} bytes
採集時間 (Timestamp UTC)    : {result['timestamp_utc']}
運算耗時 (Elapsed Time)     : {result['duration_sec']} 秒
--------------------------------------------------------------------------------
密碼學雜湊校驗值 (Cryptographic Hashes):
 - MD5     : {result['md5']}
 - SHA-256 : {result['sha256']}
--------------------------------------------------------------------------------
鑑識宣告 (Forensic Declaration):
本校驗值係於證物獲取後即刻透過二進位串流計算生成，保證未經任何增刪與篡改。
鑑識工程師簽名：____________________    複核主管簽名：____________________
================================================================================
"""
    print(report_content)
    
    # 同步輸出存證檔案
    report_filename = f"{result['file_name']}.hash_report.txt"
    with open(report_filename, "w", encoding="utf-8") as f:
        f.write(report_content)
    print(f"[+] 存證校驗報告已輸出至: {report_filename}")

if __name__ == "__main__":
    main()
```

## 🛡️ 第五動：處置圍堵與系統加固 SOP

### 5.1 現場證據封裝與入庫標準作業程序 (Evidence Packaging SOP)
1. **靜電與防磁保護**：所有硬碟與隨身碟必須第一時間裝入防靜電袋 (Anti-static Bag)。
2. **防竄改封籤 (Tamper-Evident Tape)**：
   - 封口處貼上一次性防偽封籤。
   - 鑑識工程師於封籤與袋身交界處親筆簽名並註明日期時間（若封籤被撕開，會留下不可逆的 VOID 碎紋）。
3. **入庫雙人驗證**：移入證物庫時，必須由「鑑識人員」與「證物管理員」雙人共同在場驗證外包裝完整性並簽署 CoC 表單。

## 🎯 靶場實戰檢驗 (Hands-on Lab Walkthrough)

### 6.1 實驗環境架設：模擬硬碟映像採集與雙雜湊固化
本實驗將在受控實驗室中，利用 Python 創建一個模擬的磁碟二進位檔案，模擬使用鑑識腳本進行雜湊固化，並驗證任何微小改動對雜湊的雪崩效應。

## 📋 過關驗收檢查點 (Mastery Checklist)

- [ ] **Q1：什麼是數位證據的「監管鏈 (Chain of Custody, CoC)」？為什麼監管鏈一旦出現時間或簽名斷裂，證據將面臨被法庭全面排除的風險？**  
  *考核核心*：監管鏈是記錄數位證據從犯罪現場被扣押、包裝、運送、分析到法庭呈堂的全程「不間斷書面移交歷史」。由於數位位元 (Bits) 容易在無人知曉的情況下遭到覆蓋、修改或植入偽證，法庭仰賴連續的監管鏈確認該證物在任何時間點均處於明確授權與受控狀態。一旦出現空檔或未授權經手人，防禦方將無法在法律上排除「他人趁機修改證物」的合理懷疑，導致證據能力徹底瓦解。

- [ ] **Q2：ISO/IEC 27037 標準所定義的數位證據處理四大核心原則是什麼？**  
  *考核核心*：
  1. **Auditability (可稽核性)**：所有採集、處理與分析程序皆有詳盡日誌，獨立第三方能完整審查。
  2. **Repeatability (可重複性)**：任何具備相同資格的鑑識人員在相同條件下重複操作，必須得到完全一致的結果。
  3. **Reproducibility (可再現性)**：使用不同的鑑識工具與方法，仍能導出相同的客觀結論。
  4. **Justifiability (合理正當性)**：鑑識人員採取的任何行動（如開機或拔線）皆有充分的專業理由與標準依據。

- [ ] **Q3：在數位鑑識中，為什麼必須同時計算「雙雜湊 (Dual-Hash: MD5 + SHA-256)」而非僅依賴 MD5？**  
  *考核核心*：MD5 在密碼學上已被證實存在理論上的碰撞漏洞 (Collision Attack)，技術高超的攻擊者有理論可能構造出具有相同 MD5 雜湊但內容不同的惡意檔案。在現代法庭攻防中，辯護律師常藉此攻擊 MD5 的可靠性。透過同時計算 MD5 與結構完全不同的 SHA-256（或 SHA-3），在數學上兩者同時發生碰撞的機率為零，能為法庭提供無懈可擊的完整性保證。

- [ ] **Q4：什麼是「硬體防寫設備 (Hardware Write Blocker)」？為什麼在現場取證時不能僅依靠作業系統的唯讀掛載 (Mount Read-Only)？**  
  *考核核心*：硬體防寫設備在物理介面（SATA/NVMe/USB）與鑑識電腦之間建立單向通信屏障，硬體控制器直接攔截並丟棄所有傳向被檢硬碟的 SCSI/ATA 寫入指令（Write Commands）。作業系統層級的軟體唯讀掛載存在極高的人為失誤風險（如操作者誤下指令、外掛驅動程式自動掛載時修改日誌或時間戳記），法庭高度質疑純軟體防寫，硬體防寫設備則是具備國際認證的標準法律鐵壁。

- [ ] **Q5：如果必須扣押一台正在開機運行中的伺服器，鑑識人員為什麼絕對不能直接在未拍照前按下關機鈕或拔除電源？**  
  *考核核心*：
  1. 違反現場環境保全原則：未拍照記錄螢幕顯示內容、當前登入使用者與網路線連線狀況，無法證明該主機在案發時的實際物理狀態。
  2. 違反數據揮發性次序 (RFC 3227)：直接關機或斷電會導致常駐於記憶體 (RAM) 中的未落盤惡意代碼、加密通訊金鑰、網路連線狀態與當前登入憑證瞬間被物理清除，永久銷毀決定性線索。
