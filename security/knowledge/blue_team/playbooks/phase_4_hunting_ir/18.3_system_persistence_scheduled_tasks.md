## 🚨 案發現場破題 (Incident Scenario & Mental Workflow)

### 1.1 案情境況：反覆復活的挖礦與 C2 後門
某金融科技公司的 SOC 在過去兩週內連續三次接獲告警：核心資料庫伺服器 `db-srv-01` 於每天凌晨 03:30 會異常向海外未知 IP 發起持續 10 分鐘的高負載網路通訊，CPU 使用率飆升至 100%。

先前當班的兩名 L1 維運人員每次均採取相同的處理方式：
1. 開啟工作管理員，找到佔用 CPU 的惡意進程 `C:\Users\Public\svchost_update.exe`。
2. 使用 `taskkill /f /im svchost_update.exe` 終止進程。
3. 手動刪除 `C:\Users\Public\` 下的二進位檔。
4. 在工單填寫「已清除惡意檔案，事件結案」。

然而，到了隔天凌晨 03:30，該進程猶如「殭屍復活」般再次重新生成並恢復外聯通訊！

這是一起典型未徹底清查 **系統持久化機制 (Persistence Mechanism)** 導致的處置失敗案例。攻擊者早在第一次入侵成功時，便在 Windows 底層埋設了隱蔽的 **排程任務 (Scheduled Task)** 與 **註冊表自啟動鍵值 (Registry RunKey)**。單純殺死進程或刪除單一二進位檔案，只要持久化排程未被拔除，系統重啟或時間條件觸發時，惡意代碼便會重新自網路下載或從隱藏磁區釋放！

```
[ 黑客成功取得初始存取 (Initial Compromise) ]
                     │
                     ▼
[ 埋設持久化種子 (Establish Persistence) ]
         ├── 1. 登錄檔鍵值: HKCU\Software\Microsoft\Windows\CurrentVersion\Run
         ├── 2. 排程任務: Task Scheduler (每日 03:30 觸發 schtasks /create)
         └── 3. WMI 事件訂閱: __EventFilter + CommandLineEventConsumer
                     │
                     ▼ (L1 僅殺進程，未清持久化)
[ ❌ 每日凌晨 03:30: 排程自動甦醒 ➔ 重新下載 Payload ➔ 感染擴散！]
```

## 🧩 第一動：底層機制/協定解剖 (Mechanics & Persistence Anatomy)

### 2.1 Windows 計劃任務 (Task Scheduler) 的物理存儲本質
Windows 排程任務並非單純儲存於單一設定檔中，而是具備雙重儲存結構：

1. **XML 任務定義檔 (XML Task Definition)**：
   - 存儲路徑：`C:\Windows\System32\Tasks\`（受 TrustedInstaller 保護之隱藏目錄）。
   - 結構：包含 `<Triggers>`（觸發時機，如開機、特定時間、使用者登入）、`<Actions>`（執行之程式與參數）、`<Principals>`（以 SYSTEM 還是特定使用者身分執行）。
2. **登錄檔註冊項 (Registry Task Tree)**：
   - 存儲路徑：`HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Schedule\TaskCache\`
   - 子鍵：
     - `\Tasks\{GUID}`：記載任務具體動作與觸發器二進位結構。
     - `\Tree\<任務名稱>`：記載任務在介面上的階層樹狀結構與安全描述元。
> **進階黑客免殺技術（Ghost Task 幽靈任務）**：攻擊者若具備 SYSTEM 權限，可直接刪除 `TaskCache\Tree\<任務名>` 下的 `SD` (Security Descriptor) 鍵值。此時該任務在 `taskschd.msc` 圖形介面與 `schtasks /query` 指令中**完全隱形（看不見）**，但底層 `Schedule` 服務依然會如期自動執行！

### 2.2 登錄檔經典與深層自啟動路徑 (Registry Auto-Start Locations)
除了眾所周知的 `Run` 鍵之外，攻擊者最常利用的深入持久化位置：

```
1. 經典使用者/系統自啟動鍵值：
   - HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Run
   - HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\RunOnce
   - HKCU\Software\Microsoft\Windows\CurrentVersion\Run
   - HKCU\Software\Microsoft\Windows\CurrentVersion\RunOnce

2. 登入介面劫持鍵值 (Winlogon Hijacking - T1547.004)：
   - HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon\Userinit
     (正常值: C:\Windows\system32\userinit.exe, 攻擊者常在後方以逗號追加惡意程式)
   - HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon\Shell
     (正常值: explorer.exe，若被篡改為惡意程式則登入即執行)

3. 映像檔劫持 (Image File Execution Options - IFEO / T1546.012)：
   - HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Image File Execution Options\<目標程式.exe>\Debugger
     (例如針對 sethc.exe 粘滯鍵設定 Debugger=cmd.exe，達成鎖定螢幕按 5 次 Shift 彈出 SYSTEM Shell)
```

| :--- | :--- | :--- | :--- |
| **Scheduled Tasks** | 任務執行的二進位檔位於 `%TEMP%`, `%APPDATA%`, `C:\Users\Public\` 或調用 `powershell -enc`。 | 指向 `C:\Program Files\`，且具備知名廠商 Authenticode 數位簽章（如 GoogleUpdate, AdobeARM）。 | 🔴 **極高 (Critical)** |

| **Winlogon 鍵值篡改** | `Userinit` 欄位包含逗號後綴（如 `userinit.exe, C:\Users\Public\backdoor.exe`），或 `Shell` 不為 `explorer.exe`。 | `Userinit` 嚴格等於 `C:\Windows\system32\userinit.exe,`；`Shell` 嚴格等於 `explorer.exe`。 | 🔴 **極高 (Critical)** |
| **IFEO 粘滯鍵後門** | `sethc.exe`, `utilman.exe`, `osk.exe` 鍵下存在 `Debugger` 鍵值，指向 `cmd.exe`。 | 正常系統預設無任何 Debugger 鍵值，僅供 Visual Studio 偵錯器合規設定。 | 🔴 **極高 (Critical)** |
| **Startup 捷徑目錄** | `Start-up` 目錄下存放偽裝成 Word/PDF 圖示之 `.lnk` 捷徑，其目標指向 `cmd.exe /c ...`。 | 聊天軟體（Teams/Line/WeChat）或雲端硬碟自啟動捷徑，目標指向原廠主程式。 | 🟡 **高 (High)** |
| **隱匿任務命名** | 任務名稱刻意模仿微軟系統任務（如 `\Microsoft\Windows\UpdateService`），但 Author 留空或為本機使用者。 | 完整命名空間為 `\Microsoft\Windows\...`，Author 官方標記為 Microsoft Corporation。 | 🟡 **高 (High)** |

## 💻 第三動：現場追兇——作戰指令與腳本庫

### 3.1 Sysmon 與 Splunk SPL 持久化獵捕語法庫

#### 1. Splunk 聚合獵捕：捕捉透過 `schtasks.exe` 建立之異常排程 (Event ID 1)
```spl
index=sysmon EventCode=1 (Image="*\\schtasks.exe" OR OriginalFileName="schtasks.exe")
| eval is_create = if(match(CommandLine, "(?i)/create"), 1, 0)
| where is_create=1
| rex field=CommandLine "(?i)/tn\s+\"?(?<task_name>[^\s\"]+)"
| rex field=CommandLine "(?i)/tr\s+\"?(?<task_run>[^\"]+)"
| stats count min(_time) as first_seen max(_time) as last_seen 
        values(task_name) as tasks values(task_run) as binaries values(CommandLine) as cmds
        by host, User, ParentImage
| table host, first_seen, last_seen, User, ParentImage, tasks, binaries, cmds
```

#### 2. Splunk 聚合獵捕：捕捉登錄檔 RunKey 異常寫入 (Sysmon Event ID 13)
```spl
index=sysmon EventCode=13 
TargetObject="*\\CurrentVersion\\Run*" OR TargetObject="*\\Winlogon*"
| where NOT match(Details, "(?i)^\"?C:\\\\Program Files")
| stats count by _time, host, User, Image, TargetObject, Details
| sort - _time
```

### 3.2 PowerShell 本機自動化持久化清查工具 (`hunt_persistence.ps1`)
在現場應急響應時，資安分析師可使用此腳本一鍵全面審計計劃任務、登錄檔自啟鍵值與 Winlogon 劫持：

```powershell
# hunt_persistence.ps1 - Automated Windows Persistence Hunting Tool
Write-Host "=================================================================" -ForegroundColor Cyan
Write-Host "[*] 正在審查全機系統持久化機制 (Scheduled Tasks, RunKeys, Winlogon)..." -ForegroundColor Cyan
Write-Host "=================================================================" -ForegroundColor Cyan

$suspiciousPatterns = "Users\\Public|AppData\\Local\\Temp|AppData\\Roaming|cmd\.exe|powershell\.exe|mshta|certutil"

# 1. 審查 Scheduled Tasks
Write-Host "`n[+] 1. 審查計劃任務 (Scheduled Tasks)..." -ForegroundColor Yellow
$tasks = Get-ScheduledTask -ErrorAction SilentlyContinue
$badTasks = @()

foreach ($t in $tasks) {
    $actions = ($t.Actions | ForEach-Object { "$($_.Execute) $($_.Arguments)" }) -join " "
    if ($actions -match $suspiciousPatterns) {
        $badTasks += [PSCustomObject]@{
            TaskName = $t.TaskName
            TaskPath = $t.TaskPath
            State    = $t.State
            Action   = $actions
        }
    }
}

if ($badTasks.Count -gt 0) {
    Write-Host "  🔴 發現 $($badTasks.Count) 筆高危排程任務！" -ForegroundColor Red
    $badTasks | Format-Table -AutoSize
} else {
    Write-Host "  ✅ 未發現直接指向臨時路徑的可疑排程。" -ForegroundColor Green
}

# 2. 審查登錄檔 Run / RunOnce 鍵值
Write-Host "`n[+] 2. 審查登錄檔 Run/RunOnce 鍵值..." -ForegroundColor Yellow
$regPaths = @(
    "HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Run",
    "HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\RunOnce",
    "HKCU:\Software\Microsoft\Windows\CurrentVersion\Run",
    "HKCU:\Software\Microsoft\Windows\CurrentVersion\RunOnce"
)
$badRegs = @()

foreach ($path in $regPaths) {
    if (Test-Path $path) {
        $key = Get-ItemProperty -Path $path
        $props = $key.PSObject.Properties | Where-Object { $_.Name -notmatch "^(PS|Host)" }
        foreach ($p in $props) {
            $val = $p.Value.ToString()
            if ($val -match $suspiciousPatterns -or $val -notmatch "^\"?C:\\(Windows|Program Files)") {
                $badRegs += [PSCustomObject]@{
                    Hive  = $path
                    Name  = $p.Name
                    Value = $val
                }
            }
        }
    }
}

if ($badRegs.Count -gt 0) {
    Write-Host "  🔴 發現 $($badRegs.Count) 筆異常自啟動鍵值！" -ForegroundColor Red
    $badRegs | Format-Table -AutoSize
} else {
    Write-Host "  ✅ 登錄檔 Run 鍵未發現明顯異常。" -ForegroundColor Green
}

# 3. 審查 Winlogon 劫持
Write-Host "`n[+] 3. 審查 Winlogon 劫持..." -ForegroundColor Yellow
$winlogon = Get-ItemProperty -Path "HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon" -ErrorAction SilentlyContinue
$userinit = $winlogon.Userinit
$shell = $winlogon.Shell

if ($userinit -and $userinit -ne "C:\Windows\system32\userinit.exe,") {
    Write-Host "  🔴 [CRITICAL] Winlogon Userinit 遭篡改: $userinit" -ForegroundColor Red
} else {
    Write-Host "  ✅ Winlogon Userinit 正常 ($userinit)" -ForegroundColor Green
}

if ($shell -and $shell -ne "explorer.exe") {
    Write-Host "  🔴 [CRITICAL] Winlogon Shell 遭篡改: $shell" -ForegroundColor Red
} else {
    Write-Host "  ✅ Winlogon Shell 正常 ($shell)" -ForegroundColor Green
}

Write-Host "`n=================================================================" -ForegroundColor Cyan
```

## ⚖️ 第四動：研判分水嶺——真實威脅 vs 業務誤報

### 4.1 SOC 研判對決 8 問 (SOC 8 Critical Questions)

| 編號 | 檢驗提問 (Verification Questions) | 是 (Yes) 判定導向 | 否 (No) 判定導向 |
| :---: | :--- | :--- | :--- |
| **Q1** | 該排程任務或 RunKey 執行的檔案路徑是否位於使用者可自由寫入的 `%TEMP%` 或 `Public` 目錄？ | 極高危：符合木馬落地持久化標準特徵 (T1053) | 位於受權限保護之 `C:\Program Files\` 目錄 |
| **Q2** | 執行的二進位檔案是否缺少微軟或合法商業軟體的有效 Authenticode 數位簽章？ | 高度可疑：未簽名或自簽憑證木馬 | 具備原廠合法受信任證書且未過期 |
| **Q3** | 任務執行的命令列是否包含了 Base64 編碼字串（`-enc`）或無副檔名腳本解析器？ | 意圖隱蔽代碼邏輯的防禦規避特徵 | 參數清晰，指向明確的業務執行檔 |
| **Q4** | 該排程任務的觸發條件是否設定為「在系統啟動時 (At startup)」或「以最高權限 (SYSTEM)」運行？ | 攻擊者企圖維持重啟後的特權控制 | 一般使用者登入時觸發，權限受限 |
| **Q5** | 建立該計劃任務的父進程是否為 Office 軟體、Web 伺服器進程（w3wp/tomcat）或遠端連線？ | 100% 確定為橫向移動或漏洞利用後建立之持久化 | 維運管理員在遠端桌面 (RDP) 手動配置 |
| **Q6** | `Winlogon\Userinit` 欄位值中，是否在逗號後方追加了非標準系統路徑的可執行檔？ | 典型 Winlogon 劫持後門，登入立即重啟惡意進程 | 僅標準之 `C:\Windows\system32\userinit.exe,` |
| **Q7** | 該排程任務是否在 CMDB 資產維運紀錄中有正式工單或發布記錄可供核對？ | 傾向業務合規排程（需核對變更時間） | 幽靈排程，攻擊者私自建立之惡意後門 |
| **Q8** | 檢查登錄檔 `IFEO`，在 `sethc.exe` 或 `utilman.exe` 下是否發現了 `Debugger` 鍵值？ | 確定為經典粘滯鍵後門 (Sticky Keys Backdoor) | 正常系統無 Debugger 鍵值存在 |

## 🛡️ 第五動：處置圍堵與系統加固 SOP

### 5.1 應急處置階段 (Immediate Triage & Containment)

#### 1. 微創拔除惡意排程與終止進程
針對已確定的惡意計劃任務與進程實施聯動清理：

```powershell
# 步驟 1：依據任務名稱強制註銷惡意計劃任務 (以 UpdateCheck 為例)
Unregister-ScheduledTask -TaskName "UpdateCheck" -Confirm:$false -ErrorAction SilentlyContinue

# 步驟 2：終止由該任務衍生之惡意進程 (以 PID 4312 為例)
Stop-Process -Id 4312 -Force -ErrorAction SilentlyContinue

# 步驟 3：刪除實體檔案系統中的 XML 任務定義檔 (防範幽靈任務殘留)
Remove-Item -Path "C:\Windows\System32\Tasks\UpdateCheck" -Force -ErrorAction SilentlyContinue

# 步驟 4：刪除落地於 Public 之二進位檔案
Remove-Item -Path "C:\Users\Public\svchost_update.exe" -Force -ErrorAction SilentlyContinue
```

#### 2. 清理與復原登錄檔鍵值
```powershell
# 步驟 1：刪除 Run 鍵值下的惡意自啟動項
Remove-ItemProperty -Path "HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Run" -Name "SystemUpdate" -ErrorAction SilentlyContinue
Remove-ItemProperty -Path "HKCU:\Software\Microsoft\Windows\CurrentVersion\Run" -Name "SystemUpdate" -ErrorAction SilentlyContinue

# 步驟 2：還原 Winlogon Userinit 為官方純淨預設值
Set-ItemProperty -Path "HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon" -Name "Userinit" -Value "C:\Windows\system32\userinit.exe,"

# 步驟 3：清理 IFEO 粘滯鍵後門 (若存在)
Remove-Item -Path "HKLM:\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Image File Execution Options\sethc.exe" -Recurse -ErrorAction SilentlyContinue
```

### 5.2 長期架構加固 (Long-term Hardening)
1. **啟用 Sysmon Event 12/13/14 登錄檔寫入嚴密監控**：在 Sysmon 配置中將 `CurrentVersion\Run`、`Winlogon` 與 `IFEO` 列為高優先級包含規則 (Include Rules)。
2. **透過 GPO 限制非特權使用者註冊計劃任務**：鎖定 `C:\Windows\System32\Tasks` 資料夾的 ACL 權限，禁止普通帳號調用 `schtasks` 建立自啟動排程。
3. **部署定期端點持久化基線巡檢 (Autoruns Automation)**：使用微軟 Sysinternals 的 `autorunsc.exe` 配合每日排程，自動比對全網主機自啟動項差異（Baseline Diffing），任何未在白名單內的新增自啟項均自動觸發 P2 警報。

## 🎯 靶場實戰檢驗 (Hands-on Lab Walkthrough)

### 6.1 實驗環境架設：模擬高隱蔽排程任務與 RunKey 持久化
本實驗將在測試環境中，以 PowerShell 建立一筆具備典型威脅特徵的惡意排程任務與登錄檔鍵值。

```powershell
# 步驟 1：在測試環境建立模擬惡意檔案
New-Item -Path "C:\Users\Public\simulated_agent.vbs" -ItemType File -Value "WScript.Echo ""Simulated Beacon Alive""" -Force

# 步驟 2：以 schtasks 建立隱蔽排程任務 (每 10 分鐘觸發一次)
schtasks.exe /create /tn "MicrosoftEdgeHealthUpdate" /tr "wscript.exe C:\Users\Public\simulated_agent.vbs" /sc minute /mo 10 /ru "SYSTEM" /f

# 步驟 3：寫入 HKCU Run 鍵值
Set-ItemProperty -Path "HKCU:\Software\Microsoft\Windows\CurrentVersion\Run" -Name "EdgeUpdateService" -Value "C:\Users\Public\simulated_agent.vbs"
```

## 📋 過關驗收檢查點 (Mastery Checklist)

- [ ] **Q1：為什麼處置惡意程式時，「只刪除磁碟檔案與終止進程」經常導致病毒在隔天自動復活？**  
  *考核核心*：現代惡意程式必定會在系統中留下至少一處持久化機制（如計劃任務、RunKey、WMI 事件訂閱、服務等）。若持久化指標未被徹底拔除，當定時排程觸發或電腦重新開機時，持久化機制會自動重新執行二階段下載邏輯，再度將被刪除的惡意檔案拉回磁碟並重啟進程，導致清除作業功虧一簣。

- [ ] **Q2：什麼是 Windows「幽靈任務 (Ghost Task)」？防守方如何在 `schtasks /query` 看不到的情況下定位它？**  
  *考核核心*：攻擊者以 SYSTEM 權限刪除了登錄檔 `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Schedule\TaskCache\Tree\<任務名>\SD`（安全描述元）鍵值。這會導致 Windows API 認為該任務無存取權限而拒絕在 GUI 與 CLI 清單中顯示，但底層服務依然會解析其 XML 並如期執行。防守方必須直接以管理員權限比對實體資料夾 `C:\Windows\System32\Tasks\` 內的 XML 檔案與 `schtasks /query` 的輸出差異，找出檔案存在但未列於清單的任務。

- [ ] **Q3：在 Winlogon 劫持中，`Userinit` 鍵值後面為什麼必須嚴格帶有一個「逗號」？攻擊者如何利用它？**  
  *考核核心*：微軟 Windows 設計中，`Userinit` 支援以「逗號分隔」的多個可執行檔連續執行。其標準純淨值為 `C:\Windows\system32\userinit.exe,`。攻擊者通常在逗號後方直接串接惡意程式路徑（如 `..., C:\Users\Public\bad.exe`）。系統在登入時會依照清單依序啟動 userinit.exe 與黑客的程式，既不影響使用者桌面載入，又能達成登入即啟動後門的目的。

- [ ] **Q4：在 Sysmon 遙測日誌中，哪兩個 Event ID 的組合最適合用來建立「未授權排程任務建立」的精確關聯規則？**  
  *考核核心*：**Sysmon Event ID 1 (Process Creation: `schtasks.exe /create`)** 與 **Sysmon Event ID 11 (FileCreate: 於 `C:\Windows\System32\Tasks\` 下建立 XML 檔案)**。兩者結合能同時捕獲命令行層級的參數輸入，以及檔案系統底層的任務定義檔寫入，即使攻擊者透過 COM 接口直接呼叫工作排程器 API（未啟動 schtasks.exe），Event ID 11 依然能牢牢鎖定任務的建立。

- [ ] **Q5：WMI 事件訂閱 (WMI Event Subscription) 是如何實現全無檔案 (Fileless) 持久化的？包含哪三個核心組件？**  
  *考核核心*：WMI 持久化包含三大組件：
  1. `__EventFilter`：定義觸發事件條件（如系統運行每滿 60 分鐘或特定事件日誌產生）。
  2. `__EventConsumer`（如 `CommandLineEventConsumer` 或 `ActiveScriptEventConsumer`）：定義滿足條件時執行的動作（如執行 PowerShell 指令或 VBScript）。
  3. `__FilterToConsumerBinding`：將 Filter 與 Consumer 進行綁定。
  這三者全部儲存於 WMI 儲存庫資料庫中（`OBJECTS.DATA`），無須任何實體檔案落地或註冊表 RunKey，重啟後依舊由 WMI 服務背景觸發，具備極高的隱蔽性。
