## 🚨 案發現場破題 (Incident Scenario & Mental Workflow)

### 1.1 案情境況：急躁拔電源，幾百萬贖金的解密金鑰瞬間灰飛煙滅！
清晨 06:20，某大型醫院核心醫療影像 PACS 伺服器傳出災情：螢幕跳出勒索軟體黑底白字視窗，所有 `.dcm` 斷層掃描檔案副檔名被強制篡改為 `.locked`！
院內值班的網管人員驚慌失措，第一反應是：「快！拔掉主機電源線！不能讓它繼續加密其他病歷！」
隨著「啪」的一聲拔除插頭，伺服器瞬間斷電熄滅。

兩小時後，外部專業 DFIR 鑑識團隊趕抵現場勘驗，聽聞拔插頭後無奈長嘆：
1. **揮發性記憶體徹底死滅**：該勒索病毒採用的機制是：在本地端動態生成隨機 AES-256 對稱金鑰加密檔案，加密完畢後才呼叫公鑰加密該金鑰並上傳。**在伺服器被拔掉電源的前一秒，解密全院病歷檔案的原始 AES 金鑰與未加密的記憶體映像，正好完整保存在揮發性記憶體 (RAM) 當中！**
2. **斷電導致無解死局**：拔除電源使記憶體電容電荷在數十毫秒內完全消散，原本只要透過 3 分鐘記憶體 Dump 就能提取出來的「全院免費解密金鑰」，被網管人員親手徹底物理抹除！醫院最終面臨數千萬元癱瘓損失與支付巨額贖金的悲劇。
3. **無檔案惡意載荷灰飛煙滅**：攻擊者留下的內存注入木馬 (Cobalt Strike Beacon)、正處於連線狀態的境外 C2 Socket、以及攻擊者當下登入的 Command History，全部隨斷電一同永久滅失！

這起慘痛事故狠狠證實了 RFC 3227 規範的核心價值：**在面對任何資安事件現場時，「嚴禁直接拔除電源 / 嚴禁隨意重開機」是所有資安人員不可動搖的最高鐵律！**

```

               │                                                         │
```

## 🔬 第一動：破譯本質——底層機制全景圖

### 2.1 RFC 3227 數據揮發次序 (Order of Volatility) 六大階梯
RFC 3227（網際網路安全事件採集與存檔指引）明訂，現場取證必須 **從最易揮發、保存期最短的數據開始採集，最後才採集最穩定的數據**：

```
最易揮發 (幾奈秒 ~ 幾分鐘)  ▲  1. 暫存器與 CPU 快取 (Registers, Cache)
                           │  2. 路由表、ARP 快取、進程表、核心記憶體 (Routing, ARP, Process, RAM)
                           │  3. 臨時檔案系統 / 交換分區 (Temporary file systems, Swap/Pagefile)
                           │  4. 實體硬碟資料 (Disk data, File systems)
                           │  5. 遠端日誌與網路監控記錄 (Remote logging, Network traffic)
最不易揮發 (幾個月 ~ 幾年)   ▼  6. 實體拓撲架構與媒體備份 (Physical topology, Backup tapes)
```

**階梯深度剖析**：
- **階梯 1 & 2 (RAM / Volatile Memory)**：斷電即失！包含：
  - 攻擊者注入的動態無檔案 Shellcode（如 Meterpreter、Cobalt Strike）。
  - 加密通訊的對稱密鑰（TLS Master Key、BitLocker Key、Ransomware AES Key）。
  - 正在維持的 TCP/UDP 網路 Socket、未存檔的登錄密碼雜湊。
- **階梯 3 (Pagefile / Swap)**：作業系統在物理記憶體不足時換頁至硬碟的暫存區，重開機後會被快速覆寫。
- **階梯 4 (Disk)**：非揮發性儲存媒介（HDD / SSD / NVMe），斷電後資料依然完整保留，因此其取證優先級 **遠低於記憶體**！

### 2.2 海森堡測不準原理在數位鑑識中的體現
在開機狀態下執行任何鑑識指令（如執行 `tasklist`、運行記憶體傾倒軟體），**必然會將鑑識工具自身的代碼載入 RAM、產生新的進程、並覆蓋微量記憶體分頁**。
- **原則**：無法做到 100% 零影響，但必須追求 **影響最小化 (Minimal Footprint)**。
- **規範**：
  1. 嚴禁在受害主機上下載或安裝大型分析軟體。
  2. 鑑識工具必須存放於外接唯讀隨身碟中執行。
  3. 採集輸出的記憶體 dump 檔嚴禁寫入受害主機本地硬碟（必須直接串流導向外部儲存媒介）。

## 💻 第三動：現場追兇——作戰指令與腳本庫

### 3.1 Linux 現場揮發性數據最小化採集腳本 (`live_triage_linux.sh`)
在採集完整 RAM 之前，第一時間將當前秒級揮發的網路與進程狀態抓取固化：

```bash
#!/usr/bin/env bash
# live_triage_linux.sh - RFC 3227 Order of Volatility Live Triage for Linux
# 執行原則：將輸出直接導向外接掛載目錄，避免覆蓋受害磁碟

DEST_DIR="/mnt/forensic_usb/triage_$(date +%Y%m%d_%H%M%S)"
mkdir -p "$DEST_DIR"

echo "[*] 1. 採集系統精確時間與時區..."
date -u > "$DEST_DIR/system_time_utc.txt"
uptime >> "$DEST_DIR/system_time_utc.txt"

echo "[*] 2. 採集即時網路連線與監聽 Socket (RFC 3227 優先級 2)..."
ss -tupna > "$DEST_DIR/netstat_sockets.txt" 2>/dev/null || netstat -anp > "$DEST_DIR/netstat_sockets.txt"
ip route show > "$DEST_DIR/routing_table.txt"
ip neigh show > "$DEST_DIR/arp_cache.txt"

echo "[*] 3. 採集運行中進程樹與命令行參數 (RFC 3227 優先級 2)..."
ps auxef > "$DEST_DIR/ps_process_tree.txt"

echo "[*] 4. 採集已載入之核心模組 (檢驗 Rootkit)..."
lsmod > "$DEST_DIR/kernel_modules.txt"

echo "[*] 5. 採集當前登入使用者與登入歷史..."
w > "$DEST_DIR/logged_in_users.txt"
last -n 20 > "$DEST_DIR/last_logins.txt"

echo "[+] 揮發性摘要採集完成，存檔於: $DEST_DIR"
```

### 3.2 Windows 記憶體完整轉儲現場指令 (Memory Dump SOP)
使用免安裝之鑑識工具（如 `winpmem.exe` 或 DumpIt）獲取完整 RAM：

```cmd
:: 假設外接鑑識隨身碟掛載為 E: 槽
:: 步驟 1：切換至外接隨身碟，嚴禁將 dump 寫入 C: 槽！
cd /d E:\ForensicsTools
:: 步驟 2：執行 winpmem 製作物理記憶體 RAW 鏡像

:: 步驟 3：立即計算該 RAM 鏡像之雙雜湊值
```

## 🧭 第四動：研判分流——SOC 8 問與決策樹

### 4.1 現場處置研判 8 問
| 編號 | 檢驗問題 | 推薦安全決策 (Sound Action) | 致命危險操作 (Deadly Mistake) |
|:---:|:---|:---|:---|
| **Q1** | 涉案主機當前處於開機還是關機狀態？ | **開機狀態**：保持通電，立刻採集揮發性 RAM。 | 直接按下關機鍵或拔插頭（銷毀所有 RAM 數據）。 |
| **Q2** | 涉案主機當前是否正在對內網進行高頻橫向擴散或資料外洩？ | **實施網路邏輯/物理隔離**：拔除實體網路線或阻斷交換機 Port。 | 直接拔掉電源插頭（連帶摧毀記憶體）。 |
| **Q3** | 攻擊類型是否為無檔案攻擊 (Fileless) 或勒索軟體加密中？ | **記憶體轉儲第一優先**：先抓 RAM 再進行進程處置。 | 先殺進程或先重啟主機（金鑰與載荷永久蒸發）。 |
| **Q4** | 現場硬碟是否開啟了 BitLocker / LUKS 全碟加密？ | **在當前開機解密狀態下導出金鑰或製作映像**。 | 關機後重啟（若無金鑰將面對無法解密的黑磚）。 |
| **Q5** | 外接鑑識隨身碟插入受害主機時，是否已關閉 AutoRun 自動執行？ | 確保鑑識機關閉自動運行，避免受害主機惡意代碼逆向感染。 | 插入隨身碟直接雙擊打開，造成交叉污染。 |
| **Q6** | 採集的記憶體映像檔案儲存路徑為何？ | 嚴格指向外接隨身碟或網路 NFS 共享存儲。 | 直接儲存在受害主機 C 槽桌面（覆寫被刪除檔案分區）。 |
| **Q7** | 現場螢幕是否有彈出視窗、記事本或命令列正在顯示關鍵字？ | 立即拿出手機或相機進行高解析度拍照存證。 | 直接動滑鼠關閉視窗或隨意鍵盤輸入。 |
| **Q8** | 實施記憶體獲取時，是否有同仁複核並記錄開始與結束時間？ | 詳實記載於現場處置日誌中，符合 ISO 27037 規範。 | 一人作業且無任何時間與動作紀錄。 |

### 6.1 實驗環境架設：模擬開機狀態揮發數據採集與分析
本實驗將在 Linux 實驗環境中啟動一個隱藏在後台的惡意反彈連線，模擬第一響應人員如何依照 RFC 3227 順序提取出該隱藏進程的記憶體與網路資訊。

```bash
# 步驟 1：建立演練目錄
mkdir -p /tmp/rfc3227_lab && cd /tmp/rfc3227_lab

```

### 6.2 執行揮發性數據提取

## 📋 過關驗收檢查點 (Mastery Checklist)

- [ ] **Q1：RFC 3227 所定義的「數據揮發次序 (Order of Volatility)」核心原則是什麼？請列出前四項層級。**  
  *考核核心*：核心原則是「由最易揮發（生命週期最短、最易消失）至最不易揮發的順序依序進行採集與保全」。前四項為：
  1. 暫存器與快取 (Registers and Cache)。
  2. 路由表、ARP 快取、進程表、核心記憶體 (Routing table, ARP cache, process table, kernel memory)。
  3. 臨時檔案系統 (Temporary file systems)。
  4. 實體硬碟資料 (Disk data)。

- [ ] **Q2：面對遭勒索軟體感染且正在加密中的伺服器，為什麼「直接拔掉電源插頭」通常是災難性的處置錯誤？**  
  *考核核心*：現代勒索軟體通常在記憶體中生成動態 AES/Salsa20 對稱金鑰進行高速加密，待全盤加密完成後才銷毀金鑰。在加密當下，該對稱金鑰與解密算法實例完整常駐於實體記憶體 (RAM) 中。一旦拔除電源插頭，記憶體電容電荷迅速消散，RAM 中的對稱解密金鑰將永久被物理抹除，原本有機會透過記憶體取證直接提取金鑰解密病歷或業務檔案的唯一生機被徹底斷絕。

- [ ] **Q3：在數位鑑識領域，什麼是「海森堡測不準原理 (Heisenberg's Uncertainty Principle)」的體現？鑑識人員應如何應對？**  
  *考核核心*：在開機狀態下對受害主機進行任何操作（如移動滑鼠、鍵入指令、執行採集腳本），必然會將新的代碼載入記憶體並創建進程，從而改變當前系統的記憶體分頁並微量覆寫原始數據。鑑識人員無法達成 100% 毫無改變，但必須追求「最小化足跡 (Minimal Footprint)」：工具必須存放於外接唯讀隨身碟中執行，且採集輸出嚴禁寫入受害本地磁碟，必須直接導向外部媒介。

- [ ] **Q4：如果受害主機正在向外網瘋狂外洩機密資料，正確的現場處置第一動作是什麼？「拔電源」與「拔網線」有何本質差別？**  
  *考核核心*：正確的第一動作是 **拔除實體網路線 (或在交換機端斷開連接埠 / 關閉無線網卡)**，達成網路層級的即時物理隔離。「拔網線」能立刻阻止資料繼續外洩與黑客遠端控制，同時保持主機主機板與記憶體持續通電，完整保留 RAM 中的所有揮發性證據；而「拔電源」則是毀滅性的物理關機，會將連線、木馬、金鑰與未存檔資料一併摧毀。

- [ ] **Q5：如果一台涉案的筆記型電腦已經處於「關機狀態」，第一響應人員到達現場後是否應該開機檢查裡面的檔案？為什麼？**  
  *考核核心*：**絕對嚴禁開機！** 一旦按下電源按鈕，作業系統引導載入器會啟動，成千上萬個系統服務、臨時檔案與登錄檔會被更新與覆寫，破壞原始檔案系統的時間戳記 (MACB) 並可能觸發攻擊者預埋的自毀邏輯。對於關機狀態的媒介，唯一正確的做法是：保持關機、拆卸硬碟、串接硬體防寫設備後製作 Bit-by-Bit 離線鑑識鏡像。
