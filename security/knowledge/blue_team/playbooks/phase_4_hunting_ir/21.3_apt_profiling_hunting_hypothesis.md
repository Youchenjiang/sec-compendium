## 🚨 案發現場破題 (Incident Scenario & Mental Workflow)

### 1.1 案情境況：靜默在告警門檻之下的隱匿陰影
某關鍵基礎設施與高科技製造業的 SOC 監控大屏上一片祥和：
> *SOC Daily Status: Total Ingested Events: 450,000,000 | Triggered High/Critical Alerts: 0 | EDR Coverage: 99.8%.*

所有傳統的 SIEM 關聯規則均安靜無聲，沒有任何外部已知惡意 IP 連線、沒有明文指令注入告警、也沒有已知木馬病毒雜湊 (Hash) 觸發。
然而，在每季例行性的高階威脅獵捕行動中，情資團隊收到了一份針對特定區域與半導體供應鏈的國家級威脅情報通報：
> *CTI Flash Report: APT 組織「伏羲竹 (BambooViper)」正針對亞太高科技產業發起代號「矽幕行動 (Operation SiliconCurtain)」的長期間諜行動。該組織極度擅長合法程式白利用 (LOLBAS)，通訊採用合法雲端存儲服務 (OneDrive/Google Drive API) 進行中繼，且登入全程利用竊取之有效憑證 (Valid Accounts - T1078)！*

這意味著：
1. **被動告警全面失效**：因為攻擊者使用的是合法帳號、合法雲端 API 與微軟內建二進位檔，現有的基於黑名單門檻 (IOC-based) 告警永遠不會響起！
2. **獵捕心態轉變**：防守方必須轉向 **「假設主機已被攻陷 (Assume Breach)」** 的核心哲學。
3. **主動出擊**：不能等待告警，必須依據威脅情資的 APT 畫像，主動設計 **可驗證的威脅獵捕假說 (Threat Hunting Hypothesis)**，主動在數億筆巨量日誌中翻找深埋的異常行為足跡！

                                       │

### 1.2 獵捕專家心智模型 (Mental Workflow)
高階威脅獵捕絕非盲目搜尋，而是由科學假設驅動的閉環流程（SANS Threat Hunting Loop）：
1. **第一動：破譯本質**——掌握 Diamond Model 鑽石模型、ATT&CK 戰術映射與假設驅動獵捕 (Hypothesis-Driven Hunting) 核心架構。
2. **第二動：解碼意圖**——建立 APT 組織動機、目標價值、工具箱與戰術特徵矩陣速查表。
3. **第三動：現場追兇**——編寫針對 APT 特殊 TTPs 的全網 Splunk SPL / Elastic KQL 獵捕檢索式與自動化分析工具。
4. **第四動：研判分流**——透過 SOC 必備 8 問與判定決策樹區分高階 IT 管理維運與真性 APT 潛伏。
5. **第五動：處置圍堵**——將獵捕成果沉澱為高保真常規偵測規則，並執行全鏈條根本性清除。

## 🔬 第一動：破譯本質——底層機制全景圖

### 2.1 鑽石模型 (Diamond Model of Intrusion Analysis)
在建構 APT 組織特徵畫像時，防守方利用鑽石模型將所有零散線索結構化：

```
                           [ 攻擊者 (Adversary) ]
                       APT 組織身分、國家背景、動機
                                 /     \
                                /       \
                               /         \
     [ 基礎設施 (Infrastructure) ] ─────── [ 攻擊能力/工具 (Capability) ]
      域名、VPS、CDN、專用 C2                自製惡意代碼、0-day、LOLBAS
                               \         /
                                \       /
                                 \     /
                            [ 受害者 (Victim) ]
                       目標行業、資產價值、受害用戶
```
- **社會政治軸 (Socio-political Axis)**：Adversary ➔ Victim（攻擊者為何選定我們？其戰略意圖是智慧財產權竊取還是勒索破壞？）。
- **技術軸 (Technology Axis)**：Infrastructure ➔ Capability（攻擊者如何利用特定的基礎設施投遞其武器化載荷？）。

### 2.2 獵捕假說的四大生成維度 (Hypothesis Generation Sources)
一個高質量的威脅獵捕假說必須具備 **可驗證性 (Verifiable)**、**具體性 (Specific)** 與 **行為導向 (Behavior-oriented)**：

```
                    ┌─────────────────────────────────────────┐
                    │ 1. 威脅情資驅動 (CTI-Driven)            │
                    │    依據外部 APT 戰情報告與已知 TTPs     │
                    └────────────────────┬────────────────────┘
                                         │
                    ┌────────────────────┼────────────────────┐
                    │ 2. 業務風險驅動 (Crown Jewels-Driven)  │
                    │    圍繞核心資產 (如 Active Directory)   │
                    └────────────────────┼────────────────────┘
                                         │
                    ┌────────────────────┼────────────────────┐
                    │ 3. 異常基準偏離驅動 (Anomaly-Driven)    │
                    │    利用統計學長尾 (Long-tail) 與極端值 │
                    └────────────────────┼────────────────────┘
                                         │
                    ┌────────────────────┴────────────────────┐
                    │ 4. 攻擊技術演練驅動 (Red Team-Driven)   │
                    │    由紫隊內部實戰攻防演練成果推演       │
                    └─────────────────────────────────────────┘
```

**良好假說 vs 劣質假說範例**：
- ❌ **劣質假說**：「我們的內網可能中了病毒。」（過於籠統，無法定義具體日誌檢索範圍與驗證標準）。
- ⭕ **良好假說**：「假設 APT 攻擊者已經攻陷了外圍 DMZ 伺服器，正在利用 WMI (`wmic process call create`) 在內網進行橫向移動，我們將在目標伺服器的 Sysmon Event 1 中觀察到 `WmiPrvSE.exe` 衍生異常 Shell 進程。」

## 💻 第三動：現場追兇——作戰指令與腳本庫

### 3.1 威脅獵捕假說驗證引擎 (`hypothesis_hunter.py`)
資深獵捕專家使用本工具，載入定義好的 YAML/JSON 假說模型，對端點遙測日誌進行行為鏈式對撞：

```python
#!/usr/bin/env python3
"""
hypothesis_hunter.py - Hypothesis-Driven APT Threat Hunting Automation Tool
用途：針對特定 APT 戰術假說，自動化分析日誌並輸出攻擊鏈匹配度評分。
"""
import sys
import json
import re

class ThreatHuntingEngine:
    def __init__(self, hypothesis_name: str):
        self.hypothesis_name = hypothesis_name
        self.findings = []

    def evaluate_wmi_lateral_movement(self, process_events: list):
        """
        假說：攻擊者正在利用 WMI 執行遠端代碼 (T1047)
        獵捕特徵：WmiPrvSE.exe 作為父進程，衍生 cmd.exe / powershell.exe / certutil.exe
        """
        print(f"[*] 正在執行獵捕假說驗證: 【{self.hypothesis_name}】")
        for event in process_events:
            parent = event.get("parent_image", "").lower()
            child = event.get("image", "").lower()
            cmdline = event.get("command_line", "")
            host = event.get("host", "Unknown")

            if "wmiprvse.exe" in parent:
                if any(sh in child for sh in ["cmd.exe", "powershell.exe", "powershell_ise.exe", "cscript.exe"]):
                    self.findings.append({
                        "host": host,
                        "technique": "T1047 - WMI Execution",
                        "parent": parent,
                        "child": child,
                        "cmdline": cmdline,
                        "confidence": "HIGH"
                    })

    def generate_report(self):
        print(f"\n[+] 獵捕分析完成！共命中 {len(self.findings)} 個高度可疑的行為序列：")
        for idx, f in enumerate(self.findings, 1):
            print(f"  [{idx}] 主機: {f['host']}")
            print(f"      戰術技術: {f['technique']} (信心等級: {f['confidence']})")
            print(f"      行為鏈條: {f['parent']} ➔ {f['child']}")
            print(f"      執行參數: {f['cmdline']}\n")

if __name__ == "__main__":
    # 模擬端點遙測日誌
    mock_telemetry = [
        {"host": "SRV-DC-01", "parent_image": "C:\\Windows\\System32\\services.exe", "image": "C:\\Windows\\System32\\svchost.exe", "command_line": "svchost.exe -k netsvcs"},
        {"host": "SRV-APP-02", "parent_image": "C:\\Windows\\System32\\wbem\\WmiPrvSE.exe", "image": "C:\\Windows\\System32\\cmd.exe", "command_line": "cmd.exe /c powershell -enc SQBFAFgA..."},
        {"host": "WS-FIN-08", "parent_image": "C:\\Windows\\explorer.exe", "image": "C:\\Program Files\\Chrome\\chrome.exe", "command_line": "chrome.exe"}
    ]

    engine = ThreatHuntingEngine("APT 組織內網 WMI 橫向移動與無落地執行獵捕")
    engine.evaluate_wmi_lateral_movement(mock_telemetry)
    engine.generate_report()
```

### 3.2 Splunk SPL 獵捕庫：專項假說驗證查詢

#### 假說 1：APT 組織利用長尾異常進程父子關係潛伏
在企業所有 Windows 主機中，統計父子進程配對的罕見程度（尋找全網出現次數少於 3 次的極端異常）：
```spl
index=sysmon EventCode=1
| stats count, values(CommandLine) as samples, min(_time) as first_seen, max(_time) as last_seen by ParentImage, Image
| where count < 3
| sort count ASC
| table ParentImage, Image, count, first_seen, last_seen, samples
```

#### 假說 2：攻擊者利用偽裝微軟更新排程進行憑證竊取 (T1053.005)
```spl
index=wineventlog EventCode=4698
| eval TaskContent=CommandLine
| regex TaskContent="(?i)(powershell|rundll32|regsvr32|mshta|wscript)"
| stats count by _time, Computer, TaskName, TaskContent, SubjectUserName
| table _time, Computer, SubjectUserName, TaskName, TaskContent
```

## 🧭 第四動：研判分流——SOC 8 問與決策樹

### 4.1 APT 獵捕研判 8 問
| 編號 | 檢驗問題 | APT 惡意特徵 (True Positive) | 良性管理行為 (False Positive) |
|:---:|:---|:---|:---|
| **Q1** | 發現的異常行為是否完全由微軟合法工具 (LOLBAS) 發起但參數經過 Base64 編碼？ | 典型 APT 規避代碼簽名之隱匿手法 | 企業內部正式自動化維運腳本（需對照變更工單） |
| **Q2** | 觸發行為的使用者帳號，其登入來源 IP 與地理位置是否出現「不可能的旅行 (Impossible Travel)」？ | 帳號憑證已遭外部攻擊者竊取並濫用 | 員工使用合法公司 VPN 切換節點 |
| **Q3** | 該操作行為是否發生於半夜、清晨或連續假期等非上班時段？ | APT 刻意規避白天資安人員當班監控 | 自動化備份排程或批次排程作業 |
| **Q4** | 獵捕到的外聯連線是否指向未分類、新註冊或高動態之合法雲端存儲服務？ | 攻擊者利用合法 SaaS 作為中繼與數據滲透通道 | 員工日常業務之檔案分享與備份 |
| **Q5** | 在受害主機上是否發現惡意程式利用 `Timestomp` 將檔案建立時間竄改為與系統核心檔案完全一致？ | 100% 惡意：極專業之反鑑識偽裝痕跡 | 正常軟體安裝程序遵循標準檔案時間戳記 |
| **Q6** | 端點的 Windows Security Event 日誌是否在關鍵時間點存在大段空白或遭手動清除 (Event 1102)？ | 攻擊者清理軌跡之鐵證 | 系統因磁碟空間不足正常滾動覆蓋 |
| **Q7** | 內部跳板機是否對域控制器 (Domain Controller) 進行了高頻的 LDAP 查詢或 `nltest /dclist`？ | 內網偵察 (Reconnaissance) 準備橫向移動 | 剛加入網域之伺服器正常探索 DC |

## 🛡️ 第五動：處置圍堵與系統加固 SOP

### 5.1 獵捕成果處置與沉澱閉環 (Hunting-to-Detection Lifecycle)

2. **強制實施 AppLocker / WDAC 白名單**：嚴格封鎖未受控的 PowerShell 解譯器與 LOLBAS 二進位檔直接執行腳本。

## 📋 過關驗收檢查點 (Mastery Checklist)

- [ ] **Q1：威脅獵捕 (Threat Hunting) 與傳統的 SOC 告警處理 (Alert Triage) 在本質上有何核心哲學差異？**  
  *考核核心*：傳統 SOC 告警處理是 **被動反應式 (Reactive)** 的，仰賴既有規則或已知 IOC 黑名單（IP、Hash）被觸發後才介入；若黑客使用未被收錄的未知工具或合法憑證，告警將永遠不會發生。威脅獵捕是 **主動探索式 (Proactive)** 的，基於「假定失陷 (Assume Breach)」原則，獵捕專家不依賴告警，而是結合威脅情資與進階 TTPs 主動提出具體假說，主動挖掘深埋在海量正常遙測日誌中的高級攻擊鏈。

- [ ] **Q2：入侵分析鑽石模型 (The Diamond Model) 的四個頂點分別是什麼？它對資安團隊有何具體助益？**  
  *考核核心*：四個頂點為：**Adversary (攻擊者)**、**Capability (武器與能力)**、**Infrastructure (基礎設施)**、**Victim (受害者)**。鑽石模型幫助資安分析師在面對複雜攻擊時，將零散混亂的事件線索結構化，明確刻畫出攻擊者是透過何種基礎設施運載何種惡意武器進攻受害者，並利用技術軸與社會政治軸建立攻擊者畫像，進而推導出全網拓撲與防禦策略。

- [ ] **Q3：在設計一個威脅獵捕假說時，為什麼必須聚焦於 ATT&CK 的 TTPs（行為層次）而非單純的 IOCs（指標層次）？**  
  *考核核心*：根據 David Bianco 的「痛苦之塔 (Pyramid of Pain)」，雜湊值與 IP 位於最底層，攻擊者更換成本極低，基於 IOC 的獵捕時效極短且易失效。而 TTPs 位於痛苦之塔頂端，代表攻擊者完成戰略目標的行為模式與思考習慣（例如習慣使用 WMI 橫向移動、習慣在特定登錄檔建排程）。基於 TTPs 設計的假說能跨越不同工具與惡意載荷，迫使攻擊者重新學習與重構整個攻擊鏈，達到最高的防禦效益。

- [ ] **Q4：在進行端點獵捕時，如何利用「長尾分析 (Long-Tail Analysis)」找出隱匿在成千上萬合法運維操作中的 APT 行為？**  
  *考核核心*：在大型企業中，合法的業務進程、管理腳本與日常軟體會產生數以百萬計的高度重複日誌（大頭）。APT 攻擊者為了匿蹤，其自製工具、異常父子進程配對或特定注入行為在全網發生的頻率通常極低（長尾）。獵捕人員透過統計分組（如 `ParentImage` + `Image`），將全網出現次數少於 2~3 次的極端罕見配對排序至最頂端進行人工審查，能極高效率地從雜訊中撈出真正的潛伏威脅。

- [ ] **Q5：一場成功的威脅獵捕行動在結束後，其標準的「回饋閉環 (Feedback Loop)」應該包含哪些具體產出？**  
  *考核核心*：不能僅止於「清除受害主機」。標準閉環包括：
  1. **調查報告與攻擊鏈還原**：產出完整的 ATT&CK 戰術映射報告。
  2. **偵測工程沉澱**：將此次獵捕到的有效行為特徵轉化為自動化的 Sigma / EDR / SIEM 告警規則，使未知風險變成已知的日常監控。
  3. **架構防禦補強**：填補資安盲區（例如補齊 Sysmon Event 8/10 監控，強化 GPO 白名單限制），全面提升企業防禦成熟度。
