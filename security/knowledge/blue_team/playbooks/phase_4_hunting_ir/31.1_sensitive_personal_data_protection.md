# 實戰手冊 31.1：台灣《個人資料保護法》特種個資識別、遮罩脫敏與資料外洩防禦

## 案發現場破題

在企業與醫療機構的安全營運中，藍隊人員不僅防範外部主機遭入侵，更肩負著防止「敏感個人資料（PII / Sensitive Data）」外洩的最高防線。依據台灣《個人資料保護法》（Personal Data Protection Act）第六條，個人資料分為「一般個人資料」與規範極為嚴苛的**「特種個人資料（Sensitive Personal Data）」**。

某大型健檢診所的 Web 應用程式在提供民眾下載健檢報告時，存在未授權直接物件參照（IDOR）漏洞。攻擊者透過竄改 URL 參數中的 `report_id`，在短短 2 小時內自動化爬取下載了超過 5,000 份包含客戶姓名、身分證字號、血液腫瘤標記、家族遺傳病史與詳細診斷病歷之完整 PDF 報告。

當此事件被揭發後，該診所面臨毀滅性法律衝擊：
1. **直接觸犯《個資法》第六條特種個資蒐集處理利用限制**：
   - 醫療、基因、性生活、健康檢查與病歷屬於特種個資，原則上**「完全不得蒐集、處理或利用」**，除非符合法律明文規定或經當事人單獨書面同意！
2. **觸犯第二十七條未落實安全維護措施**：
   - 系統架構未對特種個資實施分級儲存、資料庫欄位未加密、Web 傳輸未落實權限隔離。
3. **法律追責與鉅額民刑事求償**：
   - 依個資法第二十八條與第四十一條，受害人得請求損害賠償，且法人代表面臨二年以下有期徒刑與最高數千萬元之民事團體訴訟賠償責任！

本實戰手冊將深入解構台灣《個人資料保護法》六大特種個資之法定定義、資料庫與日誌中的動態遮罩脫敏技術（Data Masking）、自動化 DLP 規則檢索，以及遭外洩時的技術保全標準。

## 第一動：台灣《個資法》六大特種個資法定定義與鑑識排查清單

### 1.1 六大特種個資特徵與判定標準表
| 特種個資類型 | 法定涵蓋範疇 | 企業/醫療系統常見欄位名 | 藍隊違規外洩嚴重度 |
| :--- | :--- | :--- | :--- |
| **1. 病歷** | 醫師依醫師法製作之診療紀錄、會診單、出院病摘 | `medical_record`, `clinical_chart`, `diagnosis_note` | 🔴 最高 (直接違反醫療法與個資法第6條) |
| **2. 醫療** | 各項醫療處置、手術過程、處方用藥、物理治療紀錄 | `treatment_plan`, `prescription`, `surgery_log` | 🔴 最高 (涉及個人健康隱私) |
| **3. 基因** | 脫氧核糖核酸 (DNA) 定序分析、染色體檢驗報告 | `dna_seq`, `genetic_profile`, `chrom_analysis` | 🔴 最高 (具備高度遺傳識別與歧視風險) |
| **4. 性生活** | 性傾向、性功能障礙診斷、性傳染病篩檢紀錄 | `sexual_orientation`, `std_screening`, `hiv_test` | 🔴 最高 (高度敏感私密資訊) |
| **5. 健康檢查** | 健檢中心報告、體格檢查表、血液生化指標數值 | `checkup_report`, `lab_result`, `biomarker_data` | 🔴 最高 (民間企業與健檢院所最常外洩) |
| **6. 犯罪前科** | 警察刑事紀錄證明 (良民證)、前科素行、起訴裁判資料 | `criminal_record`, `police_clearance`, `conviction` | 🔴 最高 (不得任意於人資系統明文保存) |

## 第二動：身分證字號與特種個資動態遮罩與去識別化技術 (Masking SOP)

在資料流經日誌、測試環境或前台介面時，藍隊工程師必須確保敏感資訊受到遮罩：

### 2.1 台灣身分證字號動態遮罩正規表示式
台灣身分證字號格式為 1 碼英文字母 + 9 碼數字（第 2 碼為 1 或 2）：

```python
# 腳本範例：身分證字號驗證與動態遮罩工具 (taiwan_id_masker.py)
import re

def validate_and_mask_tw_id(tw_id: str) -> str:
    # 台灣身分證字號標準格式：[A-Z][12][0-9]{8}
    pattern = r"^[A-Z][12]\d{8}$"
    if not re.match(pattern, tw_id):
        return "INVALID_ID_FORMAT"
    
    # 標準遮罩規範：保留前 3 碼與後 3 碼，中間 4 碼遮罩為 ****
    masked = tw_id[:3] + "****" + tw_id[7:]
    return masked

def deidentify_medical_record(record_text: str) -> str:
    # 遮罩身分證
    id_pattern = r"\b[A-Z][12]\d{8}\b"
    record_text = re.sub(id_pattern, lambda m: m.group(0)[:3] + "****" + m.group(0)[7:], record_text)
    
    # 遮罩手機號碼 (09xxxxxxxx -> 09xx-***-xxx)
    phone_pattern = r"\b09\d{2}-?\d{3}-?\d{3}\b"
    record_text = re.sub(phone_pattern, "09**-***-***", record_text)
    
    return record_text

sample_log = "病患姓名: 王大明, 身分證: A123456789, 健檢紀錄: 血液常規檢查正常, 電話: 0912-345-678"
print("[*] 原始日誌: ", sample_log)
print("[+] 脫敏遮罩: ", deidentify_medical_record(sample_log))
```

## 第三動：自動化 DLP 檢測——資料庫與 Web 日誌特種個資獵捕

### 3.1 檢測資料庫導出 Dump 檔案中之未加密特種個資
藍隊人員可撰寫自動化腳本定期掃描伺服器目錄與備份檔：

```bash
# 1. 檢索是否包含台灣身分證字號明文儲存
grep -Ero "[A-Z][12][0-9]{8}" /backup/database_dumps/ | head -n 10

# 2. 檢索是否包含特種醫療關鍵字明文字串
grep -Eri "HIV|良民證|腫瘤標記|病歷號|DNA" /var/www/uploads/ | head -n 10
```

### 3.2 關聯式資料庫特種個資欄位自動化審查 (SQL Audit Script)
透過資訊綱要 (Information Schema) 審查資料庫所有欄位名稱，識別未經加密之特種個資：

```sql
-- 檢索包含病歷、健檢、診斷等敏感欄位之資料表
SELECT TABLE_SCHEMA, TABLE_NAME, COLUMN_NAME, DATA_TYPE 
FROM INFORMATION_SCHEMA.COLUMNS 
WHERE COLUMN_NAME REGEXP 'medical|clinic|dna|hiv|checkup|disease|record_id'
ORDER BY TABLE_SCHEMA, TABLE_NAME;
```

## 第四動：特種個資外洩事件現場應變與技術圍堵 (Containment SOP)

當監控發現特種個資大量外流時，立即執行四大處置：
1. **即刻切斷存取路徑**：下線有漏洞之 API 端點或封鎖外部異常 IP。
2. **資料庫審計追查（Forensic Audit）**：檢索 MySQL/PostgreSQL 查詢審計日誌，統計遭下載之資料筆數與時間窗口。
3. **保全數位鐵證**：保留 Web Access Log 與防火牆 PCAP，驗證外洩資料之真實性。
4. **啟動法規通報準備**：產出外洩當事人名冊，以備執行法定告知義務。

## 第五動：合規稽核表——個人資料保護安全維護措施實施矩陣

依《個人資料保護法施行細則》第十二條，機關必須落實適當安全維護措施：

### 5.1 十一項安全維護措施技術落實對照
| 個資法安全維護項目 | 藍隊技術落實作法 | 稽核驗收標準 |
| :--- | :--- | :--- |
| **一、配置管理人員與相當資源** | 指定個人資料保護專責人員或小組 | 具備正式派兼公文與執掌職掌表 |
| **二、界定個人資料之範圍** | 建立全組織個資盤點清冊 (Data Inventory) | 涵蓋所有特種個資儲存節點與庫表 |
| **三、個人資料之風險評估機制** | 執行個資隱私衝擊分析 (PIA) | 產出年度個資風險矩陣評估報告 |
| **四、個人資料之事故預防通報** | 建立個資外洩緊急應變與通報 SOP | 明定 72 小時通報與告知當事人標準 |
| **五、個人資料之內部管理程序** | 實施最小權限原則 (RBAC) | 嚴禁全體同仁共用高權限帳號 |
| **六、資料安全管理與傳輸加密** | 採用 TLS 1.3 傳輸與 AES-256 資料庫儲存 | 外部傳輸禁止明文 HTTP / FTP |
| **七、資料設備安全管理** | 機房實體進出管制與伺服器防竊防護 | 機房門禁刷卡紀錄保存至少 1 年 |
| **八、資料使用之查驗機制** | 啟用特種個資存取日誌 (Audit Log) | 存取與查詢日誌保存至少 6 個月 |
| **九、業務終止後之資料處理** | 磁碟消磁、實體粉碎或國防級資料抹除 | 出具第三方法定資料銷毀證明書 |
| **十、個人資料安全稽核機制** | 每年定期辦理內部個人資料保護查核 | 產出個人資料保護內部稽核報告 |
| **十一、使用紀錄軌跡之保存** | 日誌集中儲存於 WORM 唯讀日誌庫 | 避免日誌遭竄改或未授權覆寫 |

### 5.2 特種個資違反蒐集處理利用之法律責任與裁罰標準
依據台灣《個資法》最新修正規範，違反特種個資規定之罰則極為嚴苛：

| 違規型態 | 法律依據 | 行政裁罰標準 | 刑事與民事責任 |
| :--- | :--- | :--- | :--- |
| **非法蒐集利用特種個資** | 個資法第 41 條、第 47 條 | 處新臺幣 **5 萬元以上 50 萬元以下** 罰鍰 | 意圖營利者處 **5 年以下有期徒刑**，得併科 100 萬元罰金 |
