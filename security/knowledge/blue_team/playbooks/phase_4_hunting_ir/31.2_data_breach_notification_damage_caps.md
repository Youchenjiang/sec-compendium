# 實戰手冊 31.2：個資外洩法定通知時限、損害賠償上限與主管機關處分因應

## 案發現場破題

在企業遭遇勒索軟體攻擊或資料庫外洩時，事件處置絕不僅僅是還原系統或重設密碼。依據台灣《個人資料保護法》第十二條：「個人資料被竊取、洩漏、竄改或受其他侵侵害事故者，公務機關或非公務機關應於查明後，以適當方式通知當事人。」

某知名電商平台在遭受撞庫攻擊後，發現有超過 10 萬名會員之姓名、手機號碼、送貨地址與信用卡前六後四碼遭攻擊者導出並張貼於暗網販售。然而，該電商高層因擔憂股價受挫與商譽損失，選擇「私下低調修補，不向主管機關通報，亦未主動通知受害會員」。

數週後，多名消費者因接獲精準解除分期付款詐騙電話而蒙受鉅額財產損失，刑事局與數位發展部個資保護籌備處正式立案對該電商開展突擊行政調查：
1. **觸犯未依規定通知當事人義務**：
   - 依個資法第十二條與施行細則第二十二條，查明外洩後必須以簡訊、書面或電子郵件等適當方式主動告知當事人外洩事實及建議防護作為！
2. **面臨個資法行政裁罰最高上限**：
   - 依最新修訂個資法第四十八條第二項與第三項，非公務機關未落實安全維護義務致個資外洩，情節重大者處新臺幣 **15 萬元以上 1,500 萬元以下罰鍰**，並得按次連續處罰！
3. **面臨鉅額民事團體訴訟求償**：
   - 依個資法第二十八條，被害人雖不易證明實際損害額，得請求法院依侵害情節，以每人每一事件新臺幣 **500 元以上 20,000 元以下** 計算；對同一原因事實最高賠償總額上限為 **2 億元**！

本實戰手冊將詳細拆解個資外洩事件之「法定查明與通知時效判定」、「當事人法定通知書核心範本」、「主管機關裁罰防禦與補償抗辯」，以及在技術層面產出外洩名冊之自動化鑑識提取 SOP。

## 第一動：法定查明責任與外洩當事人名冊技術導出 (Forensic Extraction)

在通知當事人前，藍隊首要任務是透過資料庫審計日誌與網路封包，精確釐清「誰被外洩、洩漏了什麼欄位」：

### 1.1 資料庫外洩名單自動化取證與清冊產出腳本
```python
# 腳本範例：外洩當事人名冊提取與去識別化清查 (breach_roster_extractor.py)
import csv
import json

def extract_breached_users(audit_log_path, output_csv_path):
    breached_users = []
    
    with open(audit_log_path, "r", encoding="utf-8") as f:
        for line in f:
            if "SELECT" in line and "users" in line and "LIMIT" not in line:
                # 模擬解析提取遭攻擊者 dumps 導出之使用者資訊
                record = json.loads(line)
                user_id = record.get("user_id")
                email = record.get("email")
                phone = record.get("phone")
                breached_users.append({
                    "user_id": user_id,
                    "email": email,
                    "phone": phone,
                    "breach_timestamp": record.get("timestamp"),
                    "notification_status": "PENDING"
                })

    # 產出標準當事人通知清冊
    with open(output_csv_path, "w", newline="", encoding="utf-8") as out:
        writer = csv.DictWriter(out, fieldnames=["user_id", "email", "phone", "breach_timestamp", "notification_status"])
        writer.writeheader()
        writer.writerows(breached_users)

    print(f"[*] 外洩名冊提取完成，確證受害當事人總數: {len(breached_users)} 筆")

extract_breached_users("/evidence/audit_log.json", "/tmp/breached_notification_list.csv")
```

## 第二動：個資法第十二條當事人法定通知書編撰規範 (Notification Letter SOP)

依《個人資料保護法施行細則》第二十二條，通知當事人之內容必須明確，嚴禁模糊焦點：

### 2.1 法定通知書四大核心章節架構
1. **個人資料被侵害之事實及發生時間**：具體說明何時因何種技術事由遭未授權存取。
2. **已採取之因應處置作為**：說明已修正系統漏洞、重設 API 金鑰、通報檢警與數位發展部。
3. **建議當事人防範與因應措施**：
   - 立即變更該平台密碼及其他共用相同密碼之網路服務。
   - 警惕假冒客服、銀行或公務機關之不明來電（防範社交工程二次詐騙）。
4. **專責諮詢服務窗口與聯絡方式**：提供免費客服專線、專用通報信箱與專人答詢服務。

## 第三動：中央目的事業主管機關外洩通報時限與程序

除了通知當事人，機關還需向中央主管機關報備：

### 3.1 主管機關個資外洩通報時限對照表
| 產業類別 | 中央目的事業主管機關 | 法定通報時限 | 逾期罰則上限 |
| :--- | :--- | :--- | :--- |
| **無店面零售/電商** | 數位發展部 (MODA) | 知悉後 **72 小時內** | 最高處 1,500 萬元罰鍰 |
| **金融與虛擬資產** | 金融監督管理委員會 (FSC) | 重大事件 **30 分鐘內電話通報，2 小時內填單** | 依銀行法/個資法加重處分 |
| **醫療與社福機構** | 衛生福利部 (MOHW) | 知悉後 **24 ~ 72 小時內** | 最高處 200 萬元並得按次處罰 |
| **製造與關鍵基礎設施** | 經濟部、交通部、國家通訊傳播委員會等 | 依各業管辦法 **1 ~ 72 小時內** | 依法追究行政責任 |

## 第四動：損害賠償上限與民事求償風險推演 (Liability Calculation)

### 4.1 個資法損害賠償責任試算公式
依《個資法》第二十八條，當事人受侵害時的賠償試算模型：

```python
# 腳本範例：個資外洩民事賠償風險與上限試算 (liability_calculator.py)

def calculate_liability_risk(victim_count: int, per_person_claim: float = 1000.0):
    # 法定每人每事件賠償區間：500 元 ~ 20,000 元
    legal_min_per_person = 500.0
    legal_max_per_person = 20000.0
    statutory_cap = 200000000.0  # 兩億元上限 (非財產上損害)

    claim_unit = max(legal_min_per_person, min(legal_max_per_person, per_person_claim))
    raw_total = victim_count * claim_unit
    capped_total = min(raw_total, statutory_cap)

    print(f"[*] 受害當事人人數: {victim_count:,} 人")
    print(f"[*] 試算每人求償金額: NT$ {claim_unit:,.0f}")
    print(f"[*] 原始損害請求總額: NT$ {raw_total:,.0f}")
    print(f"[!] ⚖️ 法定賠償總額上限: NT$ {capped_total:,.0f} (上限 2 億元)")

calculate_liability_risk(victim_count=100000, per_person_claim=2000.0)
```

## 第五動：技術免責與抗辯要件——證明已採行「適當安全維護措施」

依個資法第二十八條第一項但書：「非公務機關能證明其無故意或過失者，不負賠償責任。」藍隊必須提供完整的安全維護技術證明以爭取免責：

### 5.1 法庭技術免責抗辯清單
1. **具備 ISO/IEC 27001 / CNS 27001 國際資安驗證**，且證書於事發時為有效狀態。
2. **已實施傳輸加密 (TLS 1.3) 與資料庫靜態加密 (AES-256)**。
3. **定期執行弱點掃描與滲透測試**，且高危漏洞皆已於時限內完成修補。
4. **建置完整的特種個資存取日誌**，證明外洩並非內部同仁盜賣，而是不可抗力之零日漏洞 (0-Day)。

### 5.2 行政調查應對與合規佐證封包 (Audit Defense Package)
當主管機關（如數位發展部或金管會）進駐開展外洩行政調查時，藍隊應於 24 小時內備妥以下佐證卷宗：

| 佐證類別 | 文件名稱與技術證明 | 稽核認定價值 |
| :--- | :--- | :--- |
| **制度面控制** | 年度個人資料保護維護計畫書與資安政策簽核版 | 證明組織具備成文合規政策 |
| **存取審計面** | 遭入侵伺服器前後 30 天特種個資查詢日誌備份 | 證明已掌握外洩精確邊界，未擴散至其他庫表 |
| **技術修補面** | 弱點修補變更工單 (RFC) 與修復後複測掃描報告 | 證明已即時採取阻斷與除錯處置 |
| **通報告知面** | 對受害當事人發送之簡訊 / 郵件傳輸成功紀錄清冊 | 證明已依法定程序履行第 12 條告知義務 |
