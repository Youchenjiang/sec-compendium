## 🚨 案發現場破題 (The Incident Scenario)

> **情境帶入**：  
> 週四上午 11:45，內部威脅獵捕（Threat Hunting）小組在 SIEM 儀表板上注意到一組極其詭異的現象：  
> 一台開發測試主機 `DEV-WIN11-03` 上的合法計算機程式 `calc.exe`，竟然主動對俄羅斯的公網 IP（`185.220.101.5`）的 TCP 443 通訊埠發起了持續的長連線！  
> 
> 分析師打開 Windows 內建的 Security 日誌，除了一筆稀鬆平常的 Event ID 4624 登入外，**完全找不到 `calc.exe` 是由誰在何時連外網的紀錄**。防毒軟體也沒有發出任何報警，因為 `calc.exe` 本身帶有合法的微軟數位簽章。  
> 
> 幸運的是，這台主機預先安裝了微軟官方出品的驅動級遙測神器——**Sysmon（System Monitor）**！  
> 調查員調出 `Microsoft-Windows-Sysmon/Operational` 日誌：  
> 1. **Event ID 8 (CreateRemoteThread)**：清晰記錄了 `powershell.exe`（PID: 3412）在幾分鐘前對 `calc.exe`（PID: 5820）注入了一段未命名的遠端執行緒！  
> 2. **Event ID 7 (ImageLoaded)**：記錄了注入完成後，`calc.exe` 竟然異常載入了網路通訊模組 `wininet.dll`！  
> 3. **Event ID 3 (NetworkConnect)**：直接將 `calc.exe` 與外部 C2 IP、完整通訊時間點進行了釘死！  
> 
> 這是典型的 **進程掏空與遠端代碼注入攻擊（Process Hollowing / Remote Thread Injection）**！  
> 在黑客普遍採用「白利用（Living off the Land）」與「無檔案（Fileless）記憶體注入」的今天，原生 Windows 日誌早已千瘡百孔。  
>
> **本手冊的使命**：帶你深入 Sysmon 的核心驅動層（`SysmonDrv.sys`），掌握 Event ID 1（進程建立）、Event ID 3（網路連線）、Event ID 7（模組載入）與 Event ID 8（遠端執行緒注入）的核心語法，並運用精準的 Sysmon XML 過濾設定檔與 Splunk 查詢，在記憶體被污染的第一秒抓出 Shellcode 注入的鐵證。


## 🧩 第一動：驅動級遙測解剖——Sysmon 為何是藍隊的「顯微鏡」？

原生 Windows 安全日誌是在用戶態（User Mode）由進程自行或由系統 API 通報記錄，極易被繞過或隱匿。  
而 **Sysmon** 透過安裝一個核心層驅動程式（`SysmonDrv.sys`，Minifilter 驅動），**直接在 Windows 核心（Kernel Mode）攔截所有的系統呼叫**，黑客就算在用戶態玩出花樣，也逃不過底層驅動的法眼。

### 1.1 Sysmon 4 大王牌 Event ID 定位

在威脅獵捕與鑑識中，Sysmon 提供了超過 25 種事件類型，其中最致命、含金量最高的是這 4 個：

```
[Microsoft-Windows-Sysmon/Operational]
  ├── Event ID 1 : 處理程序建立 (Process Creation)
  │      • 比 4688 更強！強制計算 SHA256/MD5/IMPHASH、記錄工作目錄 (CurrentDirectory) 與 Integrity Level。
  ├── Event ID 3 : 網路連線 (Network Connection)
  │      • 破案神兵！直接將「具體進程 PID / 執行路徑」與「外連 IP、Port、連線方向、發起者」強綁定！
  ├── Event ID 7 : 映像載入 (Image Loaded)
  │      • 捕捉 DLL 劫持與非典型功能呼叫！記錄進程動態加載了哪些 DLL，及其數位簽章與 Hash。
  └── Event ID 8 : 建立遠端執行緒 (CreateRemoteThread)
         • 【內存注入唯一死穴】！記錄進程 A（SourceProcess）在進程 B（TargetProcess）記憶體中創建執行緒的行為！
```

## 🧭 第二動：解碼意圖——Sysmon 異常特徵與攻擊手法速查表

在海量 Sysmon 遙測中，你該如何依據事件鏈一眼看穿黑客手法？

### 2.1 Sysmon 異常特徵與攻擊手法速查表

| Sysmon 特徵現象（看到什麼） | 底層成因與攻擊手法（是什麼攻擊） | 威脅影響與處置優先級（怎麼應對） |
| :--- | :--- | :--- |
| **Event ID 8：`SourceImage` 為未知進程，`TargetImage` 為 `lsass.exe`** | **Mimikatz 記憶體憑證竊取 (Credential Dumping)**：<br>攻擊者在 `lsass.exe` 中建立遠端執行緒或嘗試讀取其虛擬記憶體，企圖倒出全機明文密碼與 NTLM Hash。 | • **影響**：全網管理員憑證即將失陷！<br>• **處置優先級**：緊急（P1 重大事件，立即中斷發起源進程並隔離）。 |
| **Event ID 8：`TargetImage` 為合法的 `calc.exe`、`notepad.exe` 或 `svchost.exe`** | **進程掏空 / 遠端執行緒注入 (Process Injection)**：<br>黑客為了躲避防毒偵測，將惡意 Shellcode 注入到系統白名單進程中，藉其名義進行後續活動。 | • **影響**：防毒軟體視而不見，木馬成功隱形。<br>• **處置優先級**：高（終止 Target 與 Source 進程，提取內存分析）。 |
| **Event ID 3：不應具備外聯功能的進程（如 `calc.exe`, `wordpad.exe`, `notepad.exe`）發起連線** | **注入成功後的 C2 外聯連線 (Injected C2 Beaconing)**：<br>無辜宿主進程遭注入後，被當成傀儡向黑客外部 C2 伺服器建立長連線。 | • **影響**：內網已被建立隱蔽遠端控制通道。<br>• **處置優先級**：高（封鎖外部目的 IP，阻斷通訊）。 |
| **Event ID 7：`explorer.exe` 或一般軟體從臨時目錄載入了未簽署的 DLL** | **DLL 側加載 / 劫持 (DLL Sideloading / Hijacking)**：<br>合法二進位檔啟動時，因搜尋順序漏洞（DLL Search Order），在同一目錄下被誘導載入了黑客放置的惡意 DLL。 | • **影響**：白名單程式被綁架執行惡意載荷。<br>• **處置優先級**：中至高（排查該 DLL 的來源目錄與發起檔案）。 |
| **Event ID 1：`Image` 路徑不在標準目錄，且 `Hashes` 欄位匹配已知木馬** | **非標準路徑二進位執行 (Malware Execution)**：<br>可執行檔從 `C:\Users\*\AppData\` 或 `C:\PerfLogs\` 啟動，且 IMPHASH 與已知名單吻合。 | • **影響**：新落地的惡意二進位檔正在運行。<br>• **處置優先級**：高（計算 SHA256 進行全網情資查殺）。 |

## 💻 第三動：現場追兇——作戰指令與檢驗腳本

身為現場調查員，你必須掌握在終端機利用 Sysmon 日誌還原「注入與外聯鏈條」的技能。

### 3.1 PowerShell 現場快速獵殺代碼注入（Event ID 8）

#### 步驟 1：檢出最近 24 小時內所有的 CreateRemoteThread 注入記錄
```powershell
# 結構化提取 Sysmon Event ID 8，並過濾出可疑的注入來源與目標
Get-WinEvent -FilterHashtable @{
    LogName   = 'Microsoft-Windows-Sysmon/Operational'
    Id        = 8
    StartTime = (Get-Date).AddHours(-24)
} | ForEach-Object {
    $xml = [xml]$_.ToXml()
    $data = $xml.Event.EventData.Data
    [PSCustomObject]@{
        TimeCreated   = $_.TimeCreated
        SourceImage   = ($data | Where-Object { $_.Name -eq 'SourceImage' }).'#text'
        SourcePID     = ($data | Where-Object { $_.Name -eq 'SourceProcessId' }).'#text'
        TargetImage   = ($data | Where-Object { $_.Name -eq 'TargetImage' }).'#text'
        TargetPID     = ($data | Where-Object { $_.Name -eq 'TargetProcessId' }).'#text'
        StartAddress  = ($data | Where-Object { $_.Name -eq 'StartAddress' }).'#text'
    }
} | Format-Table -AutoSize
```

#### 步驟 2：揪出「無辜進程異常聯網」（Event ID 3 獵捕傀儡）
```powershell
# 尋找 notepad, calc, wordpad, spoolsv 等不應有聯網行為的進程連線
$SuspiciousImages = @('calc.exe', 'notepad.exe', 'wordpad.exe', 'spoolsv.exe', 'cmd.exe')

Get-WinEvent -FilterHashtable @{
    LogName   = 'Microsoft-Windows-Sysmon/Operational'
    Id        = 3
    StartTime = (Get-Date).AddHours(-24)
} | ForEach-Object {
    $xml = [xml]$_.ToXml()
    $data = $xml.Event.EventData.Data
    $img = ($data | Where-Object { $_.Name -eq 'Image' }).'#text'
    $leaf = Split-Path $img -Leaf
    
    if ($SuspiciousImages -contains $leaf) {
        [PSCustomObject]@{
            TimeCreated = $_.TimeCreated
            Image       = $img
            PID         = ($data | Where-Object { $_.Name -eq 'ProcessId' }).'#text'
            DestIP      = ($data | Where-Object { $_.Name -eq 'DestinationIp' }).'#text'
            DestPort    = ($data | Where-Object { $_.Name -eq 'DestinationPort' }).'#text'
            User        = ($data | Where-Object { $_.Name -eq 'User' }).'#text'
        }
    }
} | Format-Table -AutoSize
```

#### 步驟 3：自動化代碼注入與反彈外聯關聯獵捕腳本 (`sysmon_injection_hunter.ps1`)
```powershell
<#
.SYNOPSIS
    自動關聯 Sysmon Event 8 (注入) 與 Event 3 (網路外聯)
#>
param (
    [int]$Hours = 12
)

$Since = (Get-Date).AddHours(-$Hours)
Write-Host "[*] 正在從 Sysmon 驅動日誌分析進程注入與外聯鏈條..." -ForegroundColor Cyan

# 1. 抓取 Event ID 8
$Injections = @()
Get-WinEvent -FilterHashtable @{
    LogName   = 'Microsoft-Windows-Sysmon/Operational'
    Id        = 8
    StartTime = $Since
} -ErrorAction SilentlyContinue | ForEach-Object {
    $xml = [xml]$_.ToXml()
    $data = $xml.Event.EventData.Data
    $Injections += [PSCustomObject]@{
        TimeCreated = $_.TimeCreated
        SourceImage = ($data | Where-Object { $_.Name -eq 'SourceImage' }).'#text'
        SourcePID   = ($data | Where-Object { $_.Name -eq 'SourceProcessId' }).'#text'
        TargetImage = ($data | Where-Object { $_.Name -eq 'TargetImage' }).'#text'
        TargetPID   = ($data | Where-Object { $_.Name -eq 'TargetProcessId' }).'#text'
        StartFunc   = ($data | Where-Object { $_.Name -eq 'StartFunction' }).'#text'
    }
}

# 2. 抓取 Event ID 3
$Connections = @()
Get-WinEvent -FilterHashtable @{
    LogName   = 'Microsoft-Windows-Sysmon/Operational'
    Id        = 3
    StartTime = $Since
} -ErrorAction SilentlyContinue | ForEach-Object {
    $xml = [xml]$_.ToXml()
    $data = $xml.Event.EventData.Data
    $Connections += [PSCustomObject]@{
        TimeCreated = $_.TimeCreated
        PID         = ($data | Where-Object { $_.Name -eq 'ProcessId' }).'#text'
        Image       = ($data | Where-Object { $_.Name -eq 'Image' }).'#text'
        DestIP      = ($data | Where-Object { $_.Name -eq 'DestinationIp' }).'#text'
        DestPort    = ($data | Where-Object { $_.Name -eq 'DestinationPort' }).'#text'
    }
}

Write-Host "[+] 提取完成: 發現 $($Injections.Count) 筆注入事件，以及 $($Connections.Count) 筆網路外聯。" -ForegroundColor Green

# 3. 雙向交叉比對
foreach ($inj in $Injections) {
    $conn = $Connections | Where-Object { $_.PID -eq $inj.TargetPID -and $_.TimeCreated -ge $inj.TimeCreated }
    if ($conn) {
        Write-Host "[!] 🚨 發現致命代碼注入外聯鏈 (Injection -> C2 Connection)!" -ForegroundColor Red
        Write-Host "    注入時間: $($inj.TimeCreated)"
        Write-Host "    發起源: $($inj.SourceImage) (PID: $($inj.SourcePID))"
        Write-Host "    受害宿主: $($inj.TargetImage) (PID: $($inj.TargetPID))"
        $conn | ForEach-Object {
            Write-Host "    --> 外聯時間: $($_.TimeCreated) | 目標: $($_.DestIP):$($_.DestPort)" -ForegroundColor Yellow
        }
    }
}
```

### 3.2 Splunk SPL 全網威脅獵捕語法

#### 偵測情境：代碼注入後隨即建立網路連線（Event ID 8 聯防 Event ID 3）
> **邏輯**：當進程 A 對進程 B 發起遠端執行緒注入（EID 8），隨後 5 分鐘內進程 B 發起了對外的網路連線（EID 3），**100% 判定為 Process Injection C2 通信！**

```splunk
index=sysmon (EventCode=8 OR EventCode=3)
| eval injected_target_pid=if(EventCode==8, TargetProcessId, null())
| eval network_pid=if(EventCode==3, ProcessId, null())
| eval compromised_image=if(EventCode==8, TargetImage, Image)
| transaction host maxspan=5m
| search injected_target_pid=* AND network_pid=*
| eval Alert_Level="🚨 CRITICAL: Remote Thread Injection followed by C2 Connection!"
| table _time, host, SourceImage, compromised_image, DestinationIp, DestinationPort, Alert_Level
```

## ⚖️ 第四動：研判分水嶺——正常開發除錯 vs 惡意內存注入？

在日常環境中，除錯工具（如 Visual Studio `devenv.exe`、Process Hacker、某些軟體打包器）也會呼叫 `CreateRemoteThread`。你該如何區分？

### 4.1 SOC 8 大黃金研判問題對照表

| 核心提問（研判維度） | 本技術點實戰檢核標準 |
| :--- | :--- |
| **Q1. 觸發原因**（為何會發出此警報？） | Sysmon 記錄到未在白名單中的跨進程遠端執行緒注入（Event ID 8），或核心進程異常外聯（Event ID 3）。 |
| **Q2. 注入發起端**（SourceImage 是什麼程式？） | 是已知的開發除錯程式（`devenv.exe`），還是由腳本直譯器（`powershell.exe`, `wscript.exe`）發起？**腳本發起注入 99% 為惡意！** |
| **Q3. 遭注入宿主**（TargetImage 是什麼進程？） | 目標是自定義的測試程式，還是關鍵系統進程（`lsass.exe`, `svchost.exe`, `explorer.exe`）？ |
| **Q4. 執行緒起始位址**（StartAddress 指向何處？） | 起始位址是否落在已載入的合法 DLL 導出函數（如 `kernel32.dll!LoadLibraryA`），還是落在一塊未具名且屬性為 PAGE_EXECUTE_READWRITE 的動態記憶體堆疊？ |
| **Q5. 關聯前置指令**（發起端是怎麼啟動的？） | 往前回溯 Event ID 1：發起注入的進程是否有帶有 Base64 混淆或下載外部代碼的命令列參數？ |
| **Q6. 伴隨行為**（注入後是否有後續動作？） | 比對 Event ID 7 與 Event ID 3：宿主進程是否在被注入後立即加載了非預期的網路/加密模組，或連往未知名境外 IP？ |
| **Q7. 橫向波及**（其他主機是否有相同特徵？） | 全網 SIEM 檢查：發起源的 SHA256 或連往的目的 IP 是否在其他工作站同步出現？ |
| **Q8. 處置動作**（下一步是什麼？） | 1. 立即隔離受害主機；2. 終止 SourcePID 與 TargetPID；3. 提取宿主進程記憶體（VAD 傾印）還原 Shellcode。 |

## 🛡️ 第五動：處置圍堵與防護加固 SOP (Mitigation & Hardening)

確認存在惡意遠端代碼注入時，依循以下作業程序處置並加固：

### 1. 斬斷注入進程與宿主進程
不要只終止宿主進程，必須同時終止注入的母體：
```powershell
# 同時強制終止發起注入的進程與被注入的傀儡進程
Stop-Process -Id <SourcePID>, <TargetPID> -Force
```

### 2. 部署微軟官方推薦之 Sysmon 高質量配置檔（SwiftOnSecurity / Florian Roth）
未經配置的 Sysmon 會產生數十 GB 的雜訊。部署業界金標準過濾規則以抑制誤報：
```cmd
:: 下載並套用 SwiftOnSecurity 高質量 Sysmon 規則範本
sysmon.exe -accepteula -i sysmonconfig-export.xml

:: 日後動態更新規則設定
sysmon.exe -c updated_rules.xml
```

### 3. 啟用 LSA 核心保護（RunAsPPL）
徹底杜絕針對 `lsass.exe` 的 Event ID 8 注入：
- 在登錄檔中配置 `HKLM\SYSTEM\CurrentControlSet\Control\Lsa\RunAsPPL = 1`。
- 開啟後，`lsass.exe` 將以受保護的處理程序（PPL）運行，任何非微軟官方數位簽章的進程**完全無法對其注入代碼或讀取記憶體！**

## 🎯 靶場實戰檢驗 (Hands-on Lab Walkthrough)

請帶著剛才學到的 Sysmon 事件鏈分析技巧，進入真實靶場：

### 推薦靶場：[TryHackMe - Sysmon (Windows Threat Detection)](https://tryhackme.com/room/sysmon)
- **靶場背景**：一個已部署 Sysmon 驅動的 Windows 靶機，攻擊者在其中執行了 Mimikatz、無檔案注入與惡意後門。
- **作戰任務**：
  1. 連入靶機，在終端機執行一次簡單的注入測試或檢視歷史日誌。
  2. 開啟事件檢視器導航至 `Microsoft-Windows-Sysmon/Operational`，過濾 `Event ID 8`，找出遭到注入的受害進程名稱。
  3. 檢視該次注入事件的 `SourceImage` 與 `SourceProcessId`，追蹤到底是誰發起了這次攻擊。
  4. 切換至 `Event ID 3`，比對該受害進程是否在注入後向外發起了連線，並記錄其對外連線的 IP 與通訊埠。

## 📋 過關驗收檢查點 (Mastery Checklist)

以下為本專案的 5 大實戰驗收問題與標準專家解析：

- [x] **Q1：Windows 原生安全日誌（Security Log）中已經有 Event ID 4688 了，為什麼在進階威脅偵測中，我們依然強烈需要部署 Sysmon Event ID 1？Sysmon 在欄位上提供了哪兩項 4688 無法提供的致命鑑識線索？**
  > **標準答案**：
  > 1. **驅動層捕捉與不可竄改性**：Event 4688 是用戶態事件機制，而 Sysmon Event ID 1 是由核心驅動 `SysmonDrv.sys`（Kernel Mode）攔截底層進程創建，更難被用戶態 Hook 或攻擊者繞過。
  > 2. **兩大不可替代之致命鑑識欄位**：
  >    - **多重密碼學雜湊（Hashes 欄位）**：Sysmon 會自動計算並記錄該進程二進位檔的 `SHA256`、`MD5`、`IMPHASH`（Import Hash）。即使攻擊者將 `mimikatz.exe` 重新命名為 `svchost.exe`，SIEM 也能透過 SHA256 或 IMPHASH 立即匹配威脅情資，而原生 4688 預設完全不具備雜湊計算功能。
  >    - **完整工作目錄與誠信層級（CurrentDirectory / IntegrityLevel）**：記錄進程啟動時所在的當前磁碟工作目錄（如發現明明是系統程式卻在 `C:\Users\Public\` 執行），以及 Process Integrity Level（如 `High`、`System`、`Medium`），直接揭示該進程是否具備提權特徵。

- [x] **Q2：在偵測進程掏空（Process Hollowing）與代碼注入攻擊時，為什麼 Sysmon Event ID 8 (CreateRemoteThread) 被稱為黑客無可規避的「阿基里斯之腱」？**
  > **標準答案**：
  > 1. **攻擊本質要求**：進程掏空或跨進程注入的核心步驟，是攻擊者必須在已存在的目標合法進程（如 `calc.exe`、`svchost.exe`）的虛擬記憶體中寫入惡意 Shellcode，並強制目標進程建立一個新的執行緒來執行這段代碼。
  > 2. **底層系統調用攔截**：只要攻擊者呼叫了 Windows API `CreateRemoteThread` 或 `NtCreateThreadEx`，這項操作必須經過 Windows 核心的物件管理員。
  > 3. **無可規避之處**：`SysmonDrv.sys` 直接在核心層註冊了執行緒建立回呼函數（`PsSetCreateThreadNotifyRoutine`）。不管攻擊者在用戶態如何偽裝，Sysmon 都能 100% 捕捉到「是進程 A（SourceProcess）在進程 B（TargetProcess）內強行啟動了執行緒」，將惡意操作的發起源頭與受害宿主無所遁形地釘死在一起。

- [x] **Q3：如果一台電腦上的 `notepad.exe` 突然產生了 Sysmon Event ID 3 的網路連線記錄，且連往外部 TCP 443，在紅藍攻防中這 99% 代表發生了什麼事？**
  > **標準答案**：
  > 1. **正常基準線嚴重偏離**：`notepad.exe`（微軟記事本）是一個純本機文字編輯工具，在正常 Windows 設計與日常運維中，**絕對不包含任何網路通訊協定棧調用代碼，也絕不可能主動與網際網路建立 TCP 連線**。
  > 2. **紅藍攻防實戰判定**：
  >    - **進程注入 / 傀儡進程（Process Injection / Hollowing）**：攻擊者以掛起狀態啟動了合法的 `notepad.exe`，將其中的記憶體清空並注入了 Cobalt Strike Beacon 或 Meterpreter Shellcode，隨後讓其連線回攻擊者的外部 C2 伺服器。
  >    - **冒名頂替（Process Masquerading）**：攻擊者將自己的木馬二進位檔直接命名為 `notepad.exe` 並放在使用者臨時目錄中執行。
  > 3. 藍隊必須立即將此告警定級為失聯前夕的 P1 重大入侵事件。

- [x] **Q4：在 Event ID 8 的日誌欄位中，`StartFunction` 顯示為 `null` 或未知，在記憶體鑑識層面通常揭示了什麼物理現象？**
  > **標準答案**：
  > 1. **合法執行緒的常規行為**：正常程式建立執行緒時，其入口點（StartAddress）通常會對應到磁碟上某個合法 PE 檔案所導出的符號函數（例如 `kernel32.dll!BaseThreadInitThunk` 或 `ntdll.dll!RtlUserThreadStart`），此時 Sysmon 能夠解析並在 `StartFunction` 填入函數名稱。
  > 2. **顯示為 `null` 的物理成因**：
  >    - 當攻擊者利用 `VirtualAllocEx` 在目標進程記憶體中動態分配了一塊全新的虛擬記憶體頁，並直接將一段無檔案（Fileless）的惡意 Shellcode 寫入該區域。
  >    - 接著，攻擊者呼叫 `CreateRemoteThread`，將線程起始位址直接指向這塊動態分配的記憶體位址。
  >    - 由於這塊記憶體位址**沒有對應到任何磁碟上的合法 DLL 或二進位映像模組**，系統符號表找不到任何導出函數名，因此 `StartFunction` 必然為 `null`。
  > 3. 這在記憶體鑑識上是 Shellcode 注入的經典指紋特徵。

- [x] **Q5：黑客若企圖透過 `Mimikatz` 讀取 `lsass.exe` 的記憶體密碼，在微軟系統中開啟 LSA Protection (RunAsPPL) 後，為什麼能從根本上防禦這種跨進程讀取與注入行為？**
  > **標準答案**：
  > 1. **Protected Process Light (PPL) 機制**：自 Windows 8.1 / Server 2012 R2 起，微軟引入了受保護的進程技術。開啟 `RunAsPPL` 後，`lsass.exe` 被標記為 PPL 保護進程。
  > 2. **底層安全邊界防禦原理**：
  >    - Windows 核心在執行緒存取檢查（Access Check）時實施強制安全策略：非 PPL 進程（或簽名等級低於微軟核心簽名的進程）無法獲取 PPL 進程的高權限控制代碼（Process Handle）。
  >    - 當 Mimikatz 呼叫 `OpenProcess` 並請求 `PROCESS_VM_READ`（讀取記憶體）或 `PROCESS_ALL_ACCESS` 特權時，即使 Mimikatz 是以 `NT AUTHORITY\SYSTEM` 本機最高特權運行，**Windows 核心也會直接回傳 `STATUS_ACCESS_DENIED`（拒絕存取，0x5）**。
  > 3. 這使得攻擊者無法再透過用戶態 API 直接 Dump 出 `lsass.exe` 的記憶體憑證。
