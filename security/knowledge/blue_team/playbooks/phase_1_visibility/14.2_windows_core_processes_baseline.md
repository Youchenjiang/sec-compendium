## 🚨 案發現場破題 (The Incident Scenario)

> **情境帶入**：  
> 週一上午 10:15，總經理秘書的電腦出現卡頓。你透過遠端 EDR 主控台打開它的進程列表（Process List），螢幕上密密麻麻列出了數百個正在運行的程式。  
> 
> 你的目光掃過以下幾個進程：  
> - `System` (PID: 4)  
> - `smss.exe` (PID: 340)  
> - `csrss.exe` (PID: 512)  
> - `svchost.exe` (PID: 1280)  
> - `lsass.exe` (PID: 644)  
> - `svch0st.exe` (PID: 4892) —— 等等，中間那個字母是數字 `0` 嗎？  
> - 還有一個 `lsass.exe`，它的母進程（Parent Process）竟然顯示為 `explorer.exe`？而且工作路徑是在 `C:\Users\Admin\AppData\Local\`？  
> 
> 在 Windows 端點鑑識中，黑客最擅長的手法不是無中生有，而是**「大隱隱於市」的進程偽裝（Process Masquerading）**——將惡意木馬命名為系統核心進程名稱、偽造進程親緣關係，甚至將惡意代碼注入到合法的進程記憶體中。  
> 如果你連「正常情況下 Windows 系統進程長什麼樣子」都背不出來，面對幾百個進程，你就像是在盲人摸象。
>
> **本手冊的使命**：建立藍隊分析師的「火眼金睛」，將 Windows 開機時核心系統進程的誕生順序、父子親緣關係（Parent-Child Relationship）、預設路徑與合法實例數量刻進腦海，並掌握用 PowerShell 與 Sysinternals 極速揪出冒牌進程的實戰技能。

## 🧩 第一動：核心親緣樹解剖——Windows 核心進程是如何誕生的？

Windows 從按下電源開機到呈現桌面，其進程生成具有**不可逆、極其嚴格的親緣樹結構**。這套規則就像是自然界的 DNA，任何人工偽造的進程都會在此留下破綻。

### 1.1 Windows 神聖開機進程樹 (The Golden Boot Tree)

```
[System Idle Process] (PID 0)
    │
    ▼
[System] (PID 4, 核心態進程, 無實體路徑)
    │
    ▼
[smss.exe] (工作階段管理員 - Session Manager Subsystem)
    │
    ├── 孵化 Session 0 (系統專屬隔離會話，無圖形介面)
    │     ├── [csrss.exe] (客戶端/伺服器執行階段子系統 - Session 0 專屬實例)
    │     └── [wininit.exe] (Windows 初始化進程)
    │           ├── [services.exe] (服務控制管理員 - SCM)
    │           │     ├── [svchost.exe] (多個實例！承載 Windows 系統服務)
    │           │     └── [spoolsv.exe] (列印多工服務)
    │           ├── [lsass.exe] (本地安全性授權子系統 - 掌管所有憑證)
    │           └── [lsm.exe] (本地工作階段管理員，Windows 7 為獨立進程，Win 10+ 轉為 svchost 服務)
    │
    └── 孵化 Session 1 / 2... (使用者互動式圖形會話)
          ├── [csrss.exe] (Session 1 專屬實例)
          └── [winlogon.exe] (Windows 登入進程)
                └── [userinit.exe] (載入使用者設定檔後自我終止)
                      └── [explorer.exe] (桌面與工作列，所有使用者軟體的共同祖先！)
```

> 💡 **至關重要的鑑識鐵律**：
> - `smss.exe` 是所有進程的「助產士」。在它創建完 Session 0 與 Session 1 之後，**最初的 `smss.exe` 會自我終止！**
> - 因此，在系統穩定運行時，**`wininit.exe`、`winlogon.exe`、`csrss.exe` 的父進程（PPID）在進程表裡通常顯示為「不存在的 PID」或「Non-existent Process」**，這屬於正常現象！但如果它們的父進程是 `explorer.exe` 或 `cmd.exe`，那就是 100% 的木馬偽裝！

## 🧭 第二動：解碼意圖——7 大核心進程基準速查表

身為合格的藍隊分析師，以下 7 大進程的**合法實例數、絕對路徑、合法父進程與運行使用者**，必須達到「30 秒內倒背如流」的肌肉記憶：

### 2.1 Windows 7 大核心進程基準與偽裝速查表

| 進程名稱與合法路徑（看到什麼） | 合法基準（母進程 / 實例數 / 權限） | 惡意偽裝特徵與手法（怎麼判定攻擊） |
| :--- | :--- | :--- |
| **`System`**<br>`N/A` (無磁碟檔案) | • **PID**：固定為 `4`（早年 Win2000 為 8）。<br>• **母進程**：`System Idle Process (0)`。<br>• **實例數**：僅有 `1` 個。<br>• **帳號**：`NT AUTHORITY\SYSTEM`。 | • **攻擊特徵**：如果出現任何路徑指向 `C:\Windows\System.exe`，或 PID 不是 4，必為偽裝木馬。<br>• **處置**：立即隔離該端點。 |
| **`smss.exe`**<br>`C:\Windows\System32\` | • **母進程**：`System`。<br>• **實例數**：僅有 `1` 個主實例（子實例創建完會終止）。<br>• **帳號**：`NT AUTHORITY\SYSTEM`。 | • **攻擊特徵**：實例超過 1 個、路徑不在 System32、或由其他第三方進程生成。<br>• **處置**：高危木馬，抓取記憶體傾印並終止。 |
| **`csrss.exe`**<br>`C:\Windows\System32\` | • **母進程**：無（原始 smss 已終止）。<br>• **實例數**：通常為 `2` 個以上（Session 0 一個，每個登入 Session 各一個）。<br>• **帳號**：`NT AUTHORITY\SYSTEM`。 | • **攻擊特徵**：常被拼寫錯誤欺騙（如 `crsss.exe`、`cssrs.exe`）。若母進程顯示為非空或一般程式，必為偽裝。<br>• **處置**：比對完整命令列與執行檔雜湊。 |
| **`wininit.exe`**<br>`C:\Windows\System32\` | • **母進程**：無（原始 smss 已終止）。<br>• **實例數**：固定只有 `1` 個。<br>• **帳號**：`NT AUTHORITY\SYSTEM`。 | • **攻擊特徵**：實例數大於 1，或在工作管理員中能被使用者手動結束（核心進程受保護無法結束）。 |
| **`services.exe`**<br>`C:\Windows\System32\` | • **母進程**：固定為 `wininit.exe`。<br>• **實例數**：固定只有 `1` 個。<br>• **帳號**：`NT AUTHORITY\SYSTEM`。 | • **攻擊特徵**：母進程不是 `wininit.exe`，或在非 System32 目錄下執行。此進程負責管理全機服務，黑客極愛偽造。 |
| **`lsass.exe`**<br>`C:\Windows\System32\` | • **母進程**：固定為 `wininit.exe`。<br>• **實例數**：固定只有 `1` 個。<br>• **帳號**：`NT AUTHORITY\SYSTEM`。 | • **攻擊特徵**：**紅隊頭號目標！** 常見偽裝如 `lsas.exe`、`isass.exe`（大寫 I 冒充小寫 l）。若母進程為 `explorer.exe`，100% 為 Mimikatz 竊密器！ |
| **`svchost.exe`**<br>`C:\Windows\System32\` | • **母進程**：固定為 `services.exe`。<br>• **實例數**：**非常多個（幾十到上百個）**。<br>• **命令列**：**必須帶 `-k` 參數**（如 `-k netsvcs`）。 | • **攻擊特徵**：命令列**完全沒有 `-k` 參數**、母進程不是 `services.exe`、或拼寫為 `svch0st.exe` / `scvhost.exe`。 |
| **`explorer.exe`**<br>`C:\Windows\` | • **母進程**：無（由 `userinit.exe` 建立後終止）。<br>• **實例數**：每個互動式登入使用者 1 個。<br>• **帳號**：已登入的使用者身分。 | • **攻擊特徵**：路徑不在 `C:\Windows\`（例如跑去 System32）、運行於 SYSTEM 帳號。 |

## 💻 第三動：現場追兇——作戰指令與檢驗腳本

當你連入疑似中毒的 Windows 端點時，不要僅憑眼睛看工作管理員，使用以下腳本進行深度排查。

### 3.1 PowerShell 現場極速獵殺冒牌進程

#### 步驟 1：一鍵抓出所有「不在 System32 目錄下」的冒名系統進程
黑客最常見的手法就是將木馬命名為 `svchost.exe`，放在 `C:\Users\Public\` 或 `C:\Windows\Temp\`。一行腳本全網現形：

```powershell
# 檢驗所有名稱為核心系統程式，但路徑不在預設目錄的冒牌進程！
$CoreProcesses = @('smss', 'csrss', 'wininit', 'services', 'lsass', 'winlogon', 'svchost')

Get-Process | Where-Object { $CoreProcesses -contains $_.ProcessName } | ForEach-Object {
    $proc = $_
    $path = $proc.Path
    $expectedPath = "$env:windir\System32\$($proc.ProcessName).exe"
    
    # 判斷是否為非法路徑
    if ($path -and ($path -ne $expectedPath)) {
        [PSCustomObject]@{
            Alert        = "🚨 高危：發現非法路徑冒牌進程！"
            PID          = $proc.Id
            ProcessName  = $proc.ProcessName
            IllegalPath  = $path
            ExpectedPath = $expectedPath
            StartTime    = $proc.StartTime
        }
    }
} | Format-Table -AutoSize
```

#### 步驟 2：獵殺「孤兒或冒名」`svchost.exe`（母進程與命令列雙重校驗）
合法的 `svchost.exe` 必須同時滿足兩個條件：
1. 母進程必須是 `services.exe`。
2. 啟動命令列必須帶有 `-k` 參數。

```powershell
# 使用 WMI/CIM 深度比對 svchost.exe 的母進程與命令行參數
Get-CimInstance Win32_Process -Filter "Name = 'svchost.exe'" | ForEach-Object {
    $parent = Get-CimInstance Win32_Process -Filter "ProcessId = $($_.ParentProcessId)"
    $isLegitParent = ($parent.Name -eq 'services.exe')
    $hasKParam = ($_.CommandLine -match "-k\s+")
    
    if (-not $isLegitParent -or -not $hasKParam) {
        [PSCustomObject]@{
            Alert       = "🚨 異常 svchost 發現！"
            PID         = $_.ProcessId
            ParentPID   = $_.ParentProcessId
            ParentName  = $parent.Name
            CommandLine = $_.CommandLine
        }
    }
} | Format-Table -AutoSize
```

#### 步驟 3：揪出拼寫錯誤進程（Typosquatting Masquerading）
搜尋包含常見混淆字符（如 `0` 代替 `o`、額外添加 `s`）的進程：
```powershell
# 抓取典型高仿進程名稱
Get-Process | Where-Object { 
    $_.ProcessName -match "^(svch0st|scvhost|lsas|isass|csrs|wininit1|taskmg|conh0st)$" 
} | Select-Object Id, ProcessName, Path, StartTime
```

#### 步驟 4：自動化進程基準線快速檢驗腳本 (`check_process_baseline.ps1`)
```powershell
<#
.SYNOPSIS
    全面比對系統目前進程樹與微軟核心基準線
#>
Write-Host "[*] 正在進行 Windows 核心進程基準線合規檢查..." -ForegroundColor Cyan

$Baseline = @{
    'smss'     = @{ Path = "$env:windir\System32\smss.exe"; Parent = 'System'; MaxInstances = 1 }
    'wininit'  = @{ Path = "$env:windir\System32\wininit.exe"; Parent = ''; MaxInstances = 1 }
    'services' = @{ Path = "$env:windir\System32\services.exe"; Parent = 'wininit.exe'; MaxInstances = 1 }
    'lsass'    = @{ Path = "$env:windir\System32\lsass.exe"; Parent = 'wininit.exe'; MaxInstances = 1 }
}

$AllProcs = Get-CimInstance Win32_Process

foreach ($name in $Baseline.Keys) {
    $matched = $AllProcs | Where-Object { $_.Name -like "$name.exe" }
    $cfg = $Baseline[$name]
    $instCount = $matched.Count
    
    if ($instCount -gt $cfg.MaxInstances) {
        Write-Host "[!] 異常實例數: $name.exe 實例數為 $instCount (預期上限 $($cfg.MaxInstances))" -ForegroundColor Red
    }
    
    foreach ($p in $matched) {
        $parent = $AllProcs | Where-Object { $_.ProcessId -eq $p.ParentProcessId }
        $parentName = if ($parent) { $parent.Name } else { "Non-existent / Terminated" }
        
        # 驗證路徑
        if ($p.ExecutablePath -and ($p.ExecutablePath -ne $cfg.Path)) {
            Write-Host "[!] 🚨 偽裝路徑: PID $($p.ProcessId) $name.exe 位於 $($p.ExecutablePath)" -ForegroundColor Red
        }
        # 驗證父進程
        if ($cfg.Parent -and ($parentName -ne $cfg.Parent)) {
            Write-Host "[!] 🚨 異常父進程: PID $($p.ProcessId) $name.exe 由 $parentName (PID $($p.ParentProcessId)) 啟動" -ForegroundColor Red
        }
    }
}
Write-Host "[+] 核心基準線掃描完成。" -ForegroundColor Green
```

### 3.2 Sysinternals Process Explorer 專家鑑識

若本機裝有 Sysinternals Suite 工具包，打開 `procexp.exe`，執行以下三大神操作：

1. **Verify Signatures（驗證微軟數位簽章）**：
   - 點擊選單 `Options` ➔ 勾選 `Verify Image Signatures`。
   - 觀察進程的 `Verified Signer` 欄位：所有核心進程必須顯示為 **`Microsoft Windows Component Publisher`** 或 **`Microsoft Windows`**。
   - 若顯示為 `(Unable to verify)`、空白或第三方廠商名稱，**100% 為未簽章之惡意程式！**
2. **VirusTotal 整合快篩**：
   - 點擊 `Options` ➔ `VirusTotal.com` ➔ 勾選 `Check VirusTotal.com`。
   - Process Explorer 會自動計算全機進程的 SHA256 雜湊並回傳雲端比對，直接標出惡意檢出率（如 `58/72`）。

## ⚖️ 第四動：研判分水嶺——合法第三方外掛 vs 惡意進程？

在企業生產環境中，某些軟體（如防毒軟體、虛擬機驅動 VMware Tools）也會衍生出帶有微軟進程名稱的輔助程式。你該如何精準研判？

### 4.1 SOC 8 大黃金研判問題對照表

| 核心提問（研判維度） | 本技術點實戰檢核標準 |
| :--- | :--- |
| **Q1. 觸發原因**（為何會發出此警報？） | EDR 觸發「Unusual Parent Process（異常父進程）」或「Unsigned System Binary（未簽署系統程式）」告警。 |
| **Q2. 實體檔案**（執行檔實體存放在哪裡？） | 檢查進程絕對路徑：是在 `%SystemRoot%\System32\`，還是在 `\AppData\Local\`、`\Users\Public\`、`\Temp\` 等使用者目錄？ |
| **Q3. 母子親緣**（父進程是誰？） | 檢視父進程：`lsass.exe` 的父進程是 `wininit.exe` 還是 `cmd.exe` / `powershell.exe`？由命令提示字元生出的核心進程必為惡意！ |
| **Q4. 執行身分**（運行的帳號權限？） | 核心系統進程必須運行於 `NT AUTHORITY\SYSTEM`。若發現某個 `svchost.exe` 或 `csrss.exe` 是以一般登入使用者帳號（如 `CORP\john`）運行，**必為木馬！** |
| **Q5. 啟動參數**（命令列參數是否合規？） | `svchost.exe` 是否帶有 `-k` 參數並指向合法的服務群組？是否夾帶了未知的 URL 或 Base64 編碼字串？ |
| **Q6. 數位簽章**（二進位檔案是否經過微軟簽章？） | 檢查檔案數位憑證：簽署者是否為 Microsoft，且憑證狀態是否有效未撤銷？ |
| **Q7. 網路連線**（該進程是否有不正常的對外連線？） | `lsass.exe`、`csrss.exe` 正常情況下**絕不會主動與公網 IP 建立 TCP 連線**！一旦發現外聯，代表已遭代碼注入（Injection）。 |
| **Q8. 處置動作**（下一步是什麼？） | 1. 立即隔離主機網路；2. 提取該異常進程的記憶體 Dump 作鑑識；3. 斬斷進程（`Stop-Process -Force`）並排查自啟動項。 |

## 🛡️ 第五動：處置與防禦加固 SOP (Mitigation & Hardening)

確認發現進程偽裝或非法冒充系統二進位檔時，依循以下步驟進行緊急處置：

### 1. 第一步：內存記憶體傾印取證（Memory Dump）
在殺掉惡意進程前，先保留揮發性證據，避免黑客無檔案載荷丟失：
```powershell
# 使用內建 rundll32 或 procdump 導出該惡意進程的記憶體鏡像
procdump.exe -ma <PID> C:\Cases\malicious_proc.dmp
```

### 2. 第二步：強制終止進程樹（Terminate Process Tree）
黑客進程往往有子進程或守護進程，必須連根拔除：
```powershell
# 強制終止指定 PID 及其所有衍生的子進程 (/T 參數)
taskkill /PID <PID> /T /F
```

### 3. 第三步：防禦加固——禁止在使用者目錄執行未授權二進位檔
黑客冒充系統檔最喜歡放在可寫目錄。透過 AppLocker 或 WDAC 下發軟體限制原則：
- **路徑規則限制**：嚴禁任何 `.exe`、`.dll` 直接從 `C:\Users\*\AppData\Local\Temp\` 或 `C:\Windows\Temp\` 目錄中啟動。
- **啟用進程建立命令行審計（Event ID 4688）**：確保後續所有進程的母進程與命令列皆被 SIEM 完整收集。

## 📋 過關驗收檢查點 (Mastery Checklist)

以下為本專案的 5 大實戰驗收問題與標準專家解析：

- [x] **Q1：在 Windows 穩定運行狀態下，為什麼 `wininit.exe` 與 `csrss.exe` 在進程檢視器中經常顯示「沒有母進程（Parent Process 不存在）」？這在系統架構層面是如何發生的？**
  > **標準答案**：
  > 1. **開機架構原理**：Windows 啟動時，核心進程 `System (PID 4)` 首先孵化出工作階段管理員 `smss.exe`。
  > 2. **助產士角色與退場**：`smss.exe` 負責建立 Session 0（系統隔離工作階段）並在該工作階段內啟動 `csrss.exe` 與 `wininit.exe`。當 Session 0 與使用者工作階段初始化完成後，**最初負責創建這些進程的 `smss.exe` 實例會正常自我終止並退出記憶體**。
  > 3. **鑑識意涵**：由於創建它們的父進程 `smss.exe` 已經結束生命週期，該 PID 已經不存在於目前進程表中，因此工作管理員或 EDR 會顯示母進程為「Non-existent Process」或空白。這是 Windows 正常的系統啟動行為，分析師切勿將其誤判為異常。

- [x] **Q2：為什麼在 Windows 核心進程中，`System` 進程的 PID 永遠是 `4`？它在硬碟上有沒有對應的 `System.exe` 實體執行檔？**
  > **標準答案**：
  > 1. **核心態虛擬容器**：`System` 進程代表 Windows 作業系統核心（`ntoskrnl.exe`）所擁有的核心態工作階段（Kernel-mode Threads），它不是一個常規的用戶態（User Mode）應用程式。
  > 2. **硬碟實體檔案**：在硬碟磁碟機上**根本不存在名為 `System.exe` 的可執行檔案**。任何出現在磁碟（例如 `C:\Windows\System.exe` 或 `C:\Windows\System32\System.exe`）的實體檔案，100% 都是冒名頂替的惡意木馬病毒。
  > 3. **固定 PID 4**：自 Windows XP / Server 2003 起，微軟將核心進程結構的 PID 固定寫死為 `4`（PID 0 為 System Idle Process）。如果系統進程表中出現 PID 不是 4 的 `System`，必為偽造。

- [x] **Q3：合法的 `svchost.exe` 必須具備哪兩個不可妥協的特徵？如果一個 `svchost.exe` 的母進程是 `explorer.exe`，這通常意味著什麼資安事故？**
  > **標準答案**：
  > 1. **兩大不可妥協之核心特徵**：
  >    - **特徵 A（親緣樹）**：合法 `svchost.exe` 的母進程**必須且唯一是 `services.exe`**（Service Control Manager）。
  >    - **特徵 B（啟動命令列）**：合法 `svchost.exe` 的啟動命令列中**必須帶有 `-k` 參數**（例如 `svchost.exe -k netsvcs -p`），指向登錄檔中定義的服務群組。
  > 2. **母進程為 `explorer.exe` 的事故意義**：
  >    - `explorer.exe` 是 Windows 桌面圖形外殼與檔案管理員，其子進程代表「使用者在桌面或資料夾中以滑鼠雙擊啟動的程式」。
  >    - 若 `svchost.exe` 的母進程是 `explorer.exe`，代表**有人（或惡意腳本）手動在桌面或使用者目錄下點擊執行了一個名為 `svchost.exe` 的偽裝木馬檔案**，這是一起嚴重的冒名執行事件，絕非合法 Windows 服務！

- [x] **Q4：黑客若將惡意程式命名為 `lsass.exe` 並放在 `C:\Windows\System32\` 以外的目錄，如果攻擊者以一般使用者身分執行它，你在工作管理員的使用者名稱欄位（User Name）會抓到什麼致命破綻？**
  > **標準答案**：
  > 1. **合法的身分基準**：真正的 `lsass.exe`（Local Security Authority Subsystem Service）掌管全機憑證驗證與 Kerberos/NTLM 認證，**必須以最高系統權限帳號 `NT AUTHORITY\SYSTEM` 運行**。
  > 2. **致命破綻**：攻擊者若以一般受害者帳號登入系統，在沒有成功提權（Privilege Escalation）的情況下手動執行其偽裝的 `lsass.exe`，該進程的使用者名稱欄位會顯示為該登入使用者的名稱（例如 `CORP\john` 或 `DESKTOP-01\User`）。
  > 3. **研判原則**：只要在進程清單中看見任何核心系統程式（`lsass`、`services`、`smss`、`csrss`）運行在非 SYSTEM 帳號下，即可立即判定為惡意偽裝進程。

- [x] **Q5：什麼是「字元替換偽裝（Typosquatting Masquerading）」？請列舉出至少 3 個黑客在冒充 Windows 系統核心進程時最常用的微小拼寫變形。**
  > **標準答案**：
  > 1. **手法定義**：字元替換偽裝是指攻擊者利用人類視覺的盲點，挑選外觀極為相似的英文字母、數字（如數字 `0` 與英文字母 `O`、小寫字母 `l` 與大寫字母 `I`）或微調字母順序，製造出肉眼難以察覺的檔案名稱，企圖躲避管理員在工作管理員中的目視檢查。
  > 2. **3 個常見變形範例**：
  >    - **`svch0st.exe` / `scvhost.exe`**：利用數字 `0` 替換字母 `o`，或對調 `c` 與 `v` 的順序（冒充 `svchost.exe`）。
  >    - **`isass.exe` / `lsas.exe`**：利用大寫字母 `I` 冒充小寫字母 `l`（在某些字型下 `Isass` 與 `lsass` 完全相同），或刻意少寫一個字母 `s`。
  >    - **`crsss.exe` / `csrs.exe`**：微調字母順序或減少字母（冒充客戶端子系統 `csrss.exe`）。
