# 📘 實戰手冊 14.4：防毒與主機防護日誌鑑識 (Microsoft Defender Event ID 1116 / 1117 / 5001)

---

## 🚨 案發現場破題 (The Incident Scenario)

> **情境帶入**：  
> 週二凌晨 04:18，整棟辦公大樓空無一人。你的 SOC 郵箱突然收到連續 3 封來自 Microsoft Defender 的自動通報郵件：  
> - 04:18:02 — `[Defender Alert] Threat Detected: Trojan:Win32/CobaltStrike.gen!A on HR-PC-09`  
> - 04:18:05 — `[Defender Alert] Threat Remediated: Action Taken: Quarantine`  
> - 04:19:30 — `[Defender Alert] Real-time Protection Disabled on HR-PC-09`  
> 
> 值班初級分析師看了一眼說：「Defender 已經自動把它隔離（Quarantine）了，威脅已經解除了，可以把 Ticket 關閉去睡覺了吧？」  
> 
> 且慢！  
> 請仔細看時間線：為什麼木馬被隔離後僅過了 1 分多鐘，這台主機的 **即時防護（Real-time Protection）竟然被關閉了**？  
> 隔離真的意味著「徹底安全」了嗎？黑客在木馬被抓到的前幾秒鐘，有沒有在記憶體中留下其他無檔案（Fileless）後門？攻擊者是不是利用繞過技術手動竄改了登錄檔，強行將 Defender 癱瘓？  
> 
> 這是典型的 **防毒隔離殘留與防護盲化攻擊（Defense Evasion / Antivirus Tampering）**！  
> Microsoft Defender 不只是一個殺毒軟體，它的專屬作業日誌（Operational Log）是主機取證的無價金礦。
>
> **本手冊的使命**：帶你深入 Microsoft Defender 底層事件引擎，掌握 Event ID 1116（偵測到威脅）、1117（執行防護動作）與 5001（即時防護遭停用）的欄位結構，透視黑客常用的 Defender 白名單排除項（Exclusions）後門，並運用 PowerShell 與 Splunk 建立防毒告警溯源與防護盲化監控體系。

```
[調查心智脈絡流]
🚨 接到防毒偵測/防護停用告警 
  ↳ 🔍 第一動：底層引擎解剖（Defender Operational 日誌位置、1116 威脅元數據、1117 動作碼、5001 防護停用）
      ↳ 🧭 第二動：解碼意圖（Defender 異常與逃逸速查表：白名單排除項注入、隔離後死灰復燃、TAMPER 竄改）
          ↳ 💻 第三動：現場追兇（PowerShell 現場抓取 Defender 歷史事件、清查隱蔽 Exclusions、Splunk 監控）
              ↳ ⚖️ 第四動：研判分水嶺（正常誤殺 vs 惡意攻擊與後續二次感染、SOC 8 大黃金提問）
                  ↳ 🛡️ 第五動：加固收斂 SOP（開啟防篡改保護 Tamper Protection、清除惡意排除項、全盤離線深掃）
```

## 🧩 第一動：底層引擎解剖——Microsoft Defender 事件日誌的核心骨架

很多分析師只知道看 Application 或 System 日誌，而**完全不知道 Microsoft Defender 的所有詳細情報都獨立記錄在一個專屬的通道中**：  
`%SystemRoot%\System32\Winevt\Logs\Microsoft-Windows-Windows Defender%4Operational.evtx`

### 1.1 Defender 4 大核心 Event ID 定位

在 Defender 的 Operational 日誌中，藍隊鑑識人員只需鎖定以下 4 個關鍵代碼：

```
[Microsoft-Windows-Windows Defender/Operational]
  ├── Event ID 1116 : 發現惡意軟體或潛在垃圾程式 (Malware Detected)
  ├── Event ID 1117 : 防毒軟體對該威脅採取了具體處置動作 (Action Taken: Quarantine / Clean)
  ├── Event ID 1119 : 處置動作失敗！(Action Failed - 嚴重！代表木馬已抵抗防毒處置！)
  └── Event ID 5001 : 即時防護已遭關閉！(Real-time Protection Disabled - 遭盲化攻擊！)
```

---

### 1.2 Event ID 1116 與 1117 關鍵欄位解構

當 Defender 抓到木馬時，1116 與 1117 記錄了極度詳盡的取證情報：

```yaml
Event ID: 1116 (Threat Detected)
Description: Antivirus has detected malware or other potentially unwanted software.

Threat Information:
  Threat Name:    Trojan:Win32/CobaltStrike.gen!A  <-- 威脅命名與家族識別！
  Severity ID:    Severe                           <-- 嚴重程度 (Low / Medium / High / Severe)
  Category:       Trojan                           <-- 威脅類別 (Ransomware / Backdoor / Exploit)
  Path:           file:_C:\Users\Admin\Downloads\payload.exe <-- 惡意檔案完整路徑！
  Detection Origin: Internet                       <-- 來源管道 (本機磁碟 / 網路共用 / 網頁下載)
  Process Name:   C:\Windows\explorer.exe          <-- 發起建立該檔案的父進程！

Event ID: 1117 (Action Taken)
Description: Antivirus took action to protect your machine.

Action Information:
  Action:         Quarantine                       <-- 處置動作 (Quarantine 隔離 / Clean 清除 / Block 阻斷)
  Status Code:    0x00000000                       <-- 0x0 代表動作成功，非 0 代表處置失敗！
```

## 🧭 第二動：解碼意圖——防毒異常與逃逸手法速查表

黑客在被防毒偵測到之後，絕不會坐以待斃。你該如何依據後續日誌識破對抗手法？

### 2.1 Defender 異常特徵與攻擊手法速查表

| 日誌特徵現象（看到什麼） | 底層成因與攻擊手法（是什麼攻擊） | 威脅影響與處置優先級（怎麼應對） |
| :--- | :--- | :--- |
| **1116 偵測到威脅，緊接著出現 Event ID 1119 或 1117 狀態碼非 0** | **防護處置失敗（Remediation Failed）**：<br>木馬已被載入核心記憶體中鎖定、進程具備反終止保護，或具有權限阻擋 Defender 存取實體檔案。 | • **影響**：木馬持續活躍於主機中！<br>• **處置優先級**：緊急（P1 重大事件，立即拔除網路線進入安全模式）。 |
| **1117 顯示已隔離，但在 5 分鐘內同主機出現 Event ID 5001** | **防禦盲化與防篡改突破（Tamper Attack）**：<br>攻擊者第一階段 Payload 遭查殺，但其在記憶體中的 Shellcode 立即下發命令停用 Defender 即時防護。 | • **影響**：端點已失去防護，主機遭完全接管。<br>• **處置優先級**：緊急（立即隔離主機，提取記憶體進行深檢）。 |
| **登錄檔中新增了 `Exclusions\Paths` 或 `Exclusions\Extensions`** | **白名單排除項持久化（Defender Exclusion Abuse）**：<br>攻擊者透過 `Add-MpPreference -ExclusionPath "C:\"`，將全硬碟或特定資料夾加入白名單，使後續木馬完全免殺。 | • **影響**：攻擊者獲得免殺綠色通道。<br>• **處置優先級**：高（清查並移除所有非官方排除項）。 |
| **同一主機在 10 分鐘內連續爆發數十筆不同路徑的 1116 告警** | **勒索病毒前置加密或大規模丟失 Stager**：<br>勒索軟體正在全機批量釋放加密模組，或蠕蟲正在本機嘗試多種橫向滲透工具。 | • **影響**：全機即將遭勒索加密毀滅。<br>• **處置優先級**：緊急（切斷網路，啟動離線備份防護）。 |
| **1116 威脅類型顯示為 `HackTool:Win32/Mimikatz` 或 `CobaltStrike`** | **專業紅隊滲透工具入侵（Targeted Attack）**：<br>非普通流氓廣告軟體，代表有專業攻擊者正人工在內網進行特權提取或 C2 連線。 | • **影響**：內網面臨重大數據洩漏風險。<br>• **處置優先級**：高（以該主機為中心展開橫向移動溯源）。 |

## 💻 第三動：現場追兇——作戰指令與檢驗腳本

面對疑似被盲化或發生告警的端點，使用以下專用指令進行現場排查。

### 3.1 PowerShell 現場快速萃取 Defender 偵測記錄

不要盲目去翻事件檢視器，直接在終端機利用 Defender 專屬 PowerShell 模組快速取證：

#### 步驟 1：檢視目前 Defender 的運作狀態與即時防護開關
```powershell
# 檢視 Defender 核心保護是否被關閉
Get-MpComputerStatus | Select-Object -Property `
    AntivirusEnabled, `
    RealTimeProtectionEnabled, `
    IoavProtectionEnabled, `
    AntivirusSignatureLastUpdated, `
    AMServiceEnabled
```
> ⚠️ **致命指標**：若 `RealTimeProtectionEnabled` 為 `False`，代表主機**正處於完全無防護的裸奔狀態！**

#### 步驟 2：清查被黑客偷偷加入的「白名單排除項 (Exclusions)」
```powershell
# 檢查是否有目錄、副檔名或進程被黑客排除在防毒掃描之外
Get-MpPreference | Select-Object -Property `
    ExclusionPath, `
    ExclusionExtension, `
    ExclusionProcess
```
> 🚨 **指紋抓獲**：如果看到 `ExclusionPath` 包含 `C:\`、`C:\Users\`、`C:\Windows\Temp`，**100% 代表主機已被黑客動過手腳！**

#### 步驟 3：結構化讀取最近 24 小時內的 1116 威脅偵測日誌
```powershell
# 從 Operational 日誌直接抓取 1116 事件並輸出威脅名稱與檔案路徑
Get-WinEvent -FilterHashtable @{
    LogName   = 'Microsoft-Windows-Windows Defender/Operational'
    Id        = 1116
    StartTime = (Get-Date).AddHours(-24)
} | ForEach-Object {
    $xml = [xml]$_.ToXml()
    $data = $xml.Event.EventData.Data
    [PSCustomObject]@{
        TimeCreated = $_.TimeCreated
        ThreatName  = ($data | Where-Object { $_.Name -eq 'Threat Name' }).'#text'
        Severity    = ($data | Where-Object { $_.Name -eq 'Severity Name' }).'#text'
        Path        = ($data | Where-Object { $_.Name -eq 'Path' }).'#text'
        DetectionId = ($data | Where-Object { $_.Name -eq 'Detection ID' }).'#text'
    }
} | Format-Table -AutoSize
```

#### 步驟 4：自動化 Defender 鑑識排查腳本 (`defender_forensics_triage.ps1`)
```powershell
<#
.SYNOPSIS
    自動排查 Defender 狀態、威脅歷史與惡意排除項
#>
Write-Host "[*] 正在檢查 Microsoft Defender 運行健康度與防護狀態..." -ForegroundColor Cyan

$Status = Get-MpComputerStatus
$Pref = Get-MpPreference

# 1. 檢查核心開關
if (-not $Status.RealTimeProtectionEnabled) {
    Write-Host "[!] 🚨 警告: 即時防護 (Real-time Protection) 已遭關閉!" -ForegroundColor Red
} else {
    Write-Host "[+] 即時防護正常運作中。" -ForegroundColor Green
}

# 2. 檢查排除項
$BadPaths = @('C:\', 'C:\Users', 'C:\Windows\Temp', 'C:\Users\Public')
$FoundBadExclusions = $false
foreach ($p in $Pref.ExclusionPath) {
    if ($BadPaths -contains $p -or $p -eq 'C:\*') {
        Write-Host "[!] 🚨 發現高危防毒排除路徑: $p" -ForegroundColor Red
        $FoundBadExclusions = $true
    }
}
if (-not $FoundBadExclusions) {
    Write-Host "[+] 未發現典型高危排除路徑。" -ForegroundColor Green
}

# 3. 檢查最近的防護遭停用事件 (Event 5001)
$Events5001 = Get-WinEvent -FilterHashtable @{
    LogName   = 'Microsoft-Windows-Windows Defender/Operational'
    Id        = 5001
    StartTime = (Get-Date).AddDays(-3)
} -ErrorAction SilentlyContinue

if ($Events5001) {
    Write-Host "[!] 🚨 過去 3 天內曾發生防護遭關閉事件 (Event 5001):" -ForegroundColor Red
    $Events5001 | ForEach-Object {
        Write-Host "    時間: $($_.TimeCreated)"
    }
} else {
    Write-Host "[+] 過去 3 天內無 5001 防護停用事件。" -ForegroundColor Green
}
```

### 3.2 Splunk SPL 全網威脅獵捕語法

#### 偵測情境：防護盲化致命鏈（1116 威脅偵測後隨即出現 5001 防護停用）
> **邏輯**：同一台主機在發生威脅偵測後 15 分鐘內，記錄到了 Event ID 5001（即時防護遭停用），判定為 **黑客反撲並成功盲化防毒！**

```splunk
index=wineventlog (EventCode=1116 OR EventCode=5001)
| eval threat_detected=if(EventCode==1116, Threat_Name, null())
| eval protection_disabled=if(EventCode==5001, "YES", null())
| transaction host maxspan=15m
| search threat_detected=* AND protection_disabled="YES"
| eval Alert_Level="🚨 CRITICAL: Antivirus Tampering & Blind Spot Created!"
| table _time, host, threat_detected, protection_disabled, Alert_Level
```

## ⚖️ 第四動：研判分水嶺——正常誤殺 vs 惡意攻擊殘留？

在日常維運中，內部開發的測試工具、打包軟體也經常被 Defender 誤報（False Positive）。你該如何區分是誤殺，還是真正的 APT 攻擊？

### 4.1 SOC 8 大黃金研判問題對照表

| 核心提問（研判維度） | 本技術點實戰檢核標準 |
| :--- | :--- |
| **Q1. 觸發原因**（為何會發出此警報？） | Defender 觸發 Event ID 1116 偵測，或即時防護被關閉（Event ID 5001）。 |
| **Q2. 威脅命名**（被查殺的威脅特徵為何？） | 是知名黑客工具（`HackTool`, `CobaltStrike`, `Mimikatz`），還是通用啟發式（`Heur`, `PUA` 潛在垃圾軟體）？ |
| **Q3. 檔案路徑**（被攔截的檔案位於何處？） | 是位於工程師的開發專案目錄（易誤報），還是位於瀏覽器快取、Word 暫存目錄、`C:\Users\Public\`？ |
| **Q4. 處置結果**（防護動作是否真正成功？） | 比對 Event ID 1117：處置動作是否為 `Quarantine` 且狀態碼為 `0x00000000`？是否有出現 1119 處置失敗？ |
| **Q5. 盲化連鎖**（後續防護是否被關閉？） | 在查殺之後，該主機是否出現 5001（即時防護關閉）或新增了排除目錄（Exclusions）？ |
| **Q6. 關聯進程**（是誰把這個檔案寫進磁碟的？） | 檢視 1116 中的 `Process Name`：是由合法的下載器（`chrome.exe`），還是由不明的 PowerShell/CMD 或 Office 衍生建立？ |
| **Q7. 橫向連鎖**（全網是否有其他主機報警？） | 全網 SIEM 檢查：相同的威脅名稱或檔案 SHA256，是否在其他機器上同步被檢出？ |
| **Q8. 處置動作**（下一步是什麼？） | 1. 成功隔離且無後續異常：通知使用者並確認來源；2. 出現防護關閉或失敗：立即網路隔離主機並啟動全面深檢。 |

## 🛡️ 第五動：加固收斂 SOP (Mitigation & Hardening)

面對防毒遭盲化或頑固木馬殘留，執行以下標準作業程序：

### 1. 第一步：強制啟用「防篡改保護（Tamper Protection）」
防止惡意軟體透過 PowerShell 或登錄檔擅自關閉 Defender：
- **Intune / 雲端開啟**：在 Microsoft Defender for Endpoint 入口中將 **Tamper Protection** 設為強制啟用。
- 一旦開啟後，即使攻擊者獲取了本機 `NT AUTHORITY\SYSTEM` 特權，也無法透過登錄檔停用 Defender 或加入排除目錄！

### 2. 第二步：清理被惡意注入的排除目錄（Exclusions）
```powershell
# 移除所有未授權的排除路徑
Remove-MpPreference -ExclusionPath "C:\" -ErrorAction SilentlyContinue
Remove-MpPreference -ExclusionPath "C:\Users\Public" -ErrorAction SilentlyContinue
```

### 3. 第三步：重啟即時防護並執行離線深度掃描
```powershell
# 1. 強制重新開啟即時防護
Set-MpPreference -DisableRealtimeMonitoring $false

# 2. 觸發 Windows Defender 完整全盤掃描 (ScanType 2: Full Scan)
Start-MpScan -ScanType FullScan
```

- **靶場背景**：受害主機遭遇多重攻擊，防毒軟體雖然攔截了部分載荷，但攻擊者仍試圖破壞防線。
- **作戰任務**：

  4. 搜尋 Event ID 5001，回答：防護軟體是否在後續被攻擊者成功停用？記錄其被停用的精確時間點。

## 📋 過關驗收檢查點 (Mastery Checklist)

以下為本專案的 5 大實戰驗收問題與標準專家解析：

- [x] **Q1：在 Windows 端點鑑識中，為什麼單純查看 Application 或 System 日誌經常找不到 Defender 的詳細告警？Defender 的專屬日誌存放於哪一個專門的 EVTX 檔案路徑中？**
  > **標準答案**：
  > 1. **通道分離架構**：微軟自 Windows Vista / 7 起將系統日誌重構為 Applications and Services Logs（應用程式及服務日誌）。Defender 作為獨立的安全引擎，其詳細的遙測、引擎更新、即時偵測與處置動作均被寫入獨立的專屬通道，而非經典的 Application 或 System 紀錄。
  > 2. **專屬實體檔案路徑**：
  >    `C:\Windows\System32\Winevt\Logs\Microsoft-Windows-Windows Defender%4Operational.evtx`
  > 3. **鑑識價值**：該檔案詳細記錄了 1116（偵測）、1117（處置）、1119（失敗）、5001（防護關閉）、5007（組態變更）等關鍵事件，是主機取證與防毒繞過調查的第一現場。

- [x] **Q2：Event ID 1116 與 Event ID 1117 的本質區別是什麼？如果系統產生了 1116，但緊隨其後的不是 1117 而是 Event ID 1119，這在實戰攻防中代表了什麼嚴重危機？**
  > **標準答案**：
  > 1. **本質區別**：
  >    - **Event ID 1116**：代表**「威脅識別階段 (Threat Detection)」**，Defender 掃描引擎透過特徵碼或啟發式演算法發現了惡意程式，記錄惡意軟體名稱、檔案路徑與雜湊。
  >    - **Event ID 1117**：代表**「處置完成階段 (Action Taken)」**，Defender 成功對該檔案實施了隔離（Quarantine）、清除（Clean）或阻斷（Block）。
  > 2. **出現 Event ID 1119 的嚴重危機**：
  >    - Event ID 1119 代表 **「處置動作失敗 (Action Failed)」**。
  >    - 這意味著 Defender 雖然認出了該木馬，但在嘗試殺掉進程或隔離檔案時被阻擋（例如木馬已取得最高權限將檔案鎖死、木馬使用了核心驅動保護進程、或者存取被拒）。惡意代碼**目前依然在作業系統中活躍運行**，屬於 P1 級重大資安失陷事件，必須立即拔除網路線介入人工處置！

- [x] **Q3：黑客在攻陷主機後，最常用的「防毒持久化繞過手法」之一是利用 PowerShell 呼叫 `Add-MpPreference`。他通常會下達什麼參數來建立免殺綠色通道？你該如何快速排查？**
  > **標準答案**：
  > 1. **常用指令與參數**：
  >    攻擊者通常執行：
  >    `Add-MpPreference -ExclusionPath "C:\"`（將整個 C 槽加入掃描排除名單，使全機免殺），或者：
  >    `Add-MpPreference -ExclusionPath "C:\Users\Public"`、`Add-MpPreference -ExclusionExtension ".exe"`、`Add-MpPreference -ExclusionProcess "powershell.exe"`。
  > 2. **快速排查手法**：
  >    - PowerShell 指令：執行 `Get-MpPreference | Select-Object ExclusionPath, ExclusionExtension, ExclusionProcess`。
  >    - 登錄檔路徑：檢查 `HKLM\SOFTWARE\Microsoft\Windows Defender\Exclusions\Paths` 底下是否存在未授權鍵值。
  >    - 事件日誌：檢視 Defender Operational 日誌中的 **Event ID 5007（防護設定變更）**。

- [x] **Q4：為什麼在 SOC 告警研判中，看到「Threat Detected ➔ Threat Remediated (Quarantine)」後，絕對不能立即將 Case 關閉（Close Ticket）？你必須額外排查哪兩個關鍵後續行為？**
  > **標準答案**：
  > 1. **防毒隔離的局限性**：Quarantine 僅代表磁碟上的那顆惡意實體執行檔（Dropper / Stager）被移動到隔離區，**不代表攻擊者在記憶體中運行的 Shellcode 或反彈 Shell 已被消滅**。很多載荷在被隔離前數秒內就已經成功完成記憶體注入或註冊了開機自啟動排程。
  > 2. **必須排查的兩大關鍵行為**：
  >    - **行為 A（防護盲化排查）**：檢查隔離發生後 15 分鐘內，該主機是否緊接著觸發了 **Event ID 5001（即時防護被關閉）** 或新增了排除路徑。攻擊者經常利用殘留權限直接癱瘓防毒。
  >    - **行為 B（父進程與網路外聯排查）**：回溯 1116 的 `Process Name`（是誰把這個惡意檔案拉進來的），並檢查端點是否有異常子進程衍生（Event ID 4688 / Sysmon 1）或不明公網連線（Sysmon 3），確認是否已存在記憶體駐留後門。

- [x] **Q5：微軟引入的防篡改保護（Tamper Protection）在底層是如何防範黑客的？為什麼它能阻止以 `SYSTEM` 最高權限運行的木馬透過竄改登錄檔來停用即時防護？**
  > **標準答案**：
  > 1. **傳統攻擊面**：在未啟用 Tamper Protection 前，Windows Defender 的各項開關主要依賴登錄檔鍵值控制（例如 `DisableRealtimeMonitoring = 1`）。黑客只要提權至 `LocalSystem` 或本機管理員，就能直接修改登錄檔或呼叫 WMI/PowerShell 停用防護。
  > 2. **Tamper Protection 底層防禦原理**：
  >    - 啟用後，Defender 的安全決策權被收攏至核心隔離環境（Protected Process Light, PPL）與微軟雲端安全服務。
  >    - 任何來自本地端對關鍵登錄檔的寫入請求（即使發起者是 `NT AUTHORITY\SYSTEM`）都會被 Defender 核心驅動程式直接攔截並丟棄。
  >    - 本地任何嘗試關閉即時防護或新增排除項的命令（如 `Set-MpPreference`）會被忽略，系統強制維持最後由雲端或 Intune 簽署下發的安全原則狀態，徹底杜絕了本地惡意程式盲化防毒的可能。
