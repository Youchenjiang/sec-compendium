# 實戰手冊 19.2：程式碼混淆還原、動態字串解密與 FLOSS / x64dbg 實戰

## 案發現場破題

現代進階持續性威脅（APT）與商品化木馬（如 Cobalt Strike、Qakbot、AsyncRAT）在編譯階段普遍導入了代碼混淆（Code Obfuscation）與字串加密技術。攻擊者刻意將關鍵 C2 網址、API 函式名稱、註冊表鍵值與解密金鑰藏匿於動態建構的堆疊字串（Stack Strings）、XOR 迴圈或 RC4/AES 加密區塊中，徹底癱瘓傳統基於靜態字串（如 `strings` 指令）與靜態 YARA 簽章的自動化防禦。

當藍隊 SOC 與鑑識工程師面對此類高對抗樣本時，必須具備從靜態高級字串反混淆到動態除錯插樁提取明文的能力。利用 Mandiant FLOSS 工具自動化提取混淆字串，並結合 x64dbg 在關鍵 API 記憶體位址下中斷點，鑑識人員能在數分鐘內迫使惡意程式在記憶體中「吐出」真實的 C2 基礎設施、通信協議與特徵碼，完成高價值情報產出。

```
惡意字串混淆型態與還原戰術矩陣：

[靜態明文 (直接暴露)]
"powershell.exe -enc ..." ===> `strings` 直接提取 (低階威脅)

[堆疊字串 Stack Strings (字元逐一塞入堆疊)]
mov [ebp-10h], 'h'
mov [ebp-0Fh], 't'
mov [ebp-0Eh], 't'
mov [ebp-0Dh], 'p'  ===> FLOSS 靜態符號執行自動組裝還原

[動態解密函式 / XOR-RC4 加密]
.rdata: [Encrypted Bytes]
      │
      ▼
解密迴圈 (Decryption Routine) ──(xor 0x5A)──> 明文 C2 IP:Port
      │
      ▼
呼叫動態解析: GetProcAddress("InternetOpenA")
  * 戰術：FLOSS 辨識 Tight Loops 模擬執行 或 x64dbg 在解密出口下斷點提取 RAM
```

## 第一動：字串混淆技術架構與解密原理

### 1.1 常見字串混淆手法
1. **Stack Strings（堆疊字串）**：編譯器在執行階段透過一連串的 `mov byte ptr [rbp-xx], 'c'` 指令將字串逐位元寫入區域變數堆疊。在二進位靜態磁碟檔案中，字串並不以連續位元組形式存在，導致常規文字搜尋完全落空。
2. **單字節 / 多字節 XOR 掩碼**：最古老且高頻的手法。利用固定 Key（如 `0x5A`）或動態累加 Key 對字串逐位元異或，直到運行前夕才調用內部自訂小函式進行還原。
3. **AES / RC4 / ChaCha20 區塊加密**：將所有設定資訊（C2 IP、Victim UUID、Beacon 間隔）打包為加密結構體，儲存於 `.data` 或 `.rsrc` 區段，解密 Key 則通常硬編碼在二進位中或透過環境特徵（如主機 MAC、BIOS UUID）動態派生。
4. **API Hashing（API 雜湊動態解析）**：為了逃避 IAT（導入表）監控，惡意程式不儲存 API 字串（如 `VirtualAlloc`），而是儲存該字串的雜湊值（如 ROR13、MurmurHash、CRC32），運行時動態遍歷 `PEB->Ldr` 載入之 DLL 導出表並比對雜湊。

### 1.2 FLOSS (FireEye / Mandiant FLOSS) 還原機理
FLOSS（Flares Floss）超越普通 `strings` 工具，其內部採用了進階的啟發式演算法與模擬執行引擎（基于 Vivisect 二進位分析框架）：
- 自動識別所有「高頻出現小函式」且包含算術迴圈（Tight Loops）。
- 利用 CPU 模擬器對疑似解密函式進行指令模擬（Emulation）。
- 監控模擬過程中的暫存器與記憶體寫入，一旦在記憶體中捕獲到連續且符合 ASCII/UTF-16 規範之字串，即標記為解密字串輸出。

## 第二動：動態除錯斷點戰略與暫存器特徵

### 2.1 x64dbg 常用攔截斷點清單
在動態逆向時，攻擊者無論如何混淆，最終必須呼叫系統 API 來分配記憶體或發起連線。以下 API 是攔截明文字串的最佳觀測點：

| 監控 API | 攔截目的 | 關鍵參數與觀察暫存器 (x64 ABI) |
| :--- | :--- | :--- |
| `kernel32.VirtualAlloc` | 攔截注入代碼或大區塊解密緩衝區 | `RCX` (位址), `RDX` (大小), `R8` (配置型態), `R9` (保護屬性) |
| `kernel32.GetProcAddress` | 捕捉 API Hashing 動態還原出之 API 原名 | `RDX` (指向 API 名稱字串之記憶體指針) |
| `wininet.InternetConnectA` | 攔截明文 C2 域名、伺服器 IP 與 Port | `RDX` (lpszServerName 伺服器字串), `R8` (nServerPort) |
| `ws2_32.connect` | 攔截原始 Socket 連線目標 IP 與 Port | `RDX` (指向 `sockaddr_in` 結構體之指針) |

### 2.2 內存轉儲（Memory Dump）指標
- 追蹤返回位址（`Ctrl+F9` 執行到返回）：當進入解密常式後，在函式返回指令 `ret` 處下中斷點，觀察呼叫方接收到的回傳暫存器（如 `RAX`），在記憶體區塊中按滑鼠右鍵「在傾印中跟隨」，即可立即目視解密後的原始明文字串。

## 第三動：手動獵捕與鑑識分析（FLOSS & Python）

### 3.1 使用 FLOSS 提取進階混淆與堆疊字串
```bash
# 執行 FLOSS 全自動掃描 (包含靜態、Stack Strings 與解密字串)
floss --no-static-strings malware_sample.bin > floss_results.txt

# 指定僅提取 Stack Strings
floss --only stack malware_sample.bin

# 針對特定解密函式位址進行強制模擬
floss --functions 0x1400012a0 malware_sample.bin
```

### 3.2 Python 實現暴力破解單字節 XOR 混淆字串
當在二進位中發現疑似密文特徵區塊時，可使用 Python 暴力測試 256 個 Key 並比對關鍵特徵詞（如 `http`, `powershell`, `.dll`）：

```python
import sys

def brute_force_xor(file_path, min_len=4):
    with open(file_path, "rb") as f:
        raw_data = f.read()

    targets = [b"http://", b"https://", b"powershell", b"cmd.exe", b".dll", b"POST"]
    print(f"[*] 開始暴力搜尋 0x00 ~ 0xFF 單字節 XOR 密文字串...")

    for key in range(1, 256):
        decrypted = bytes([b ^ key for b in raw_data])
        for target in targets:
            if target in decrypted:
                offset = decrypted.find(target)
                # 截取周邊 64 位元組視窗
                snippet = decrypted[max(0, offset-10):offset+50]
                # 濾除不可見字元
                clean_str = "".join([chr(c) if 32 <= c <= 126 else "." for c in snippet])
                print(f"[+] 找到命中! Key: 0x{key:02X} | 偏移量: 0x{offset:08X}")
                print(f"    內容: {clean_str}")

if __name__ == '__main__':
    if len(sys.argv) > 1:
        brute_force_xor(sys.argv[1])
    else:
        print("用法: python xor_hunt.py <target_file>")
```

## 第四動：SIEM 關聯規則與端點動態阻斷工程

### 4.1 Splunk 獵捕記憶體動態載入未映射模組（Reflective DLL / Memory Allocation）
結合 Sysmon Event ID 10（ProcessAccess）與 Sysmon Event ID 7（ImageLoaded）：
```spl
index=sysmon EventCode=10
| eval TargetImage=lower(TargetImage), SourceImage=lower(SourceImage)
| search GrantedAccess="0x1F0FFF" OR GrantedAccess="0x147A"
| stats count min(_time) as first_seen max(_time) as last_seen by SourceImage, TargetImage, CallTrace
| search CallTrace="*UNKNOWN*"
| eval alert="Reflective Memory Injection or Shellcode Execution Detected"
| table first_seen, SourceImage, TargetImage, CallTrace, alert
```

## 第五動：企業級防禦硬化與應急響應阻斷

### 5.1 部署記憶體完整性與 AMSI（Antimalware Scan Interface）
- 啟用 Windows AMSI 防護機制。當 PowerShell、VBScript 或 .NET 程式於記憶體中將加密字串拼裝完成、即將送入解譯器執行前，AMSI 會在記憶體緩衝區進行內容快照掃描，令任何靜態混淆手法在執行當下直接原形畢露。

### 5.2 封裝防禦與 EDR API 監控策略
- 在端點 EDR 上設定針對 `InternetConnectA` 與 `DnsQuery_A` 之即時連線稽核，一旦非標準行程（如 Word、Excel 或 Runonce）呼叫解密後之 C2 域名，即刻觸發進程終止（Terminate Process）與網路隔離。

## 靶場實戰：利用 XOR 加密建構惡意樣本並以 FLOSS 成功逆推

### 實驗目標
在靶場中撰寫一個具備 XOR 加密 C2 字串之 C 程式，靜態 `strings` 無法識別，隨後利用 FLOSS 與 Python 腳本精準還原出真實 C2：

```bash
# 步驟 1：編寫加密字串樣本 source.c (使用 0x7B XOR 加密 "http://attacker-c2.evil.corp:8080")
cat << 'EOF' > obfuscated.c
#include <stdio.h>
#include <string.h>

// 密文: "http://attacker-c2.evil.corp:8080" XOR 0x7B
unsigned char enc_c2[] = {
    0x13, 0x01, 0x01, 0x0B, 0x41, 0x54, 0x54, 0x1A, 0x0F, 0x0F, 0x1A, 0x18, 0x1E, 0x09, 0x56, 0x18,
    0x49, 0x55, 0x1E, 0x0D, 0x12, 0x17, 0x55, 0x18, 0x14, 0x09, 0x0B, 0x41, 0x43, 0x4B, 0x43, 0x4B, 0x00
};

void decrypt_and_print() {
    char buf[64];
    int len = sizeof(enc_c2) - 1;
    for(int i = 0; i < len; i++) {
        buf[i] = enc_c2[i] ^ 0x7B;
    }
    buf[len] = '\0';
    printf("[*] Decrypted Target: %s\n", buf);
}

int main() {
    decrypt_and_print();
    return 0;
}
EOF

# 步驟 2：編譯產出二進位檔案
x86_64-w64-mingw32-gcc obfuscated.c -o obfuscated.exe

# 步驟 3：驗證傳統 strings 徹底失效 (查無 http://)
strings obfuscated.exe | grep "attacker-c2"

# 步驟 4：執行 Python 暴力搜尋還原明文 C2
python xor_hunt.py obfuscated.exe
```
