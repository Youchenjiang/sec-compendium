# 實戰手冊 26.2：Android 系統執行時日誌 (Logcat)、ADB 取證與沙盒 SQLite 資料庫鑑識

## 案發現場破題

在行動安全事件調查中，靜態反編譯（Static Analysis）僅能揭示應用程式的潛在功能，而無法證實其是否真實被觸發、以及何時竊取了哪些敏感資料。當受害員工的公務 Android 手機疑似遭到間諜軟體（Stalkerware）或金融木馬感染時，數位鑑識人員必須深入作業系統運行時環境。

Android 採用基於 Linux UID/GID 隔離的「應用程式沙盒機制」（Application Sandbox），每個 App 的私有資料庫與快取被嚴格鎖定於 `/data/data/<package_name>/` 目錄下。透過 ADB（Android Debug Bridge）除錯橋接器提取運行時日誌（Logcat）、拉取應用程式私有目錄、並對 SQLite 資料庫（`webview.db`, `messages.db`, `cache.db`）進行 SQL 取證與 Write-Ahead Logging (WAL) 隱藏紀錄還原，鑑識人員能夠精確拼湊出攻擊者通訊的時間線、外洩的敏感憑證與即時通訊對話紀錄。


## 第一動：Android 沙盒安全模型與儲存架構

### 1.1 應用程式沙盒（Application Sandbox）與權限隔離
- **UID 唯一性**：Android 在安裝每個 App 時，會分配一個獨立的 Linux UID（例如 `u0_a145`）。
- **目錄權限鎖定**：私有目錄 `/data/data/<package_name>` 的權限設定為 `drwx------`，擁有者為該 App 專屬 UID。正常情況下，其他 App 即使宣告了所有儲存權限，也無法跨越沙盒邊界讀取此目錄，除非：
  - 裝置被 Root 提權。
  - 應用程式配置了 `android:sharedUserId`。
  - 應用程式將敏感檔案錯誤存放在外部共享儲存區（`/sdcard/` 或 `/storage/emulated/0/`）。

### 1.2 SQLite 交易日誌模式：Rollback Journal vs WAL
- **Rollback Journal（`.db-journal`）**：在覆寫原始資料庫前，將舊數據拷貝至 journal 檔案，交易成功後刪除。
- **WAL（Write-Ahead Logging, `.db-wal`）**：現代 Android 預設模式。所有異動先寫入 WAL 檔案，原始 `.db` 保持不變，直到觸發 Checkpoint 機制才合併回寫。
  - **鑑識黃金重點**：攻擊者在應用程式中故意「刪除」的通聯記錄或快取，往往仍以殘留片段（Slack Space / Free List）留存於 `.db-wal` 之中！若直接複製 `.db` 而遺漏 `.db-wal`，將遺失關鍵鐵證。

## 第二動：執行時特徵定位與日誌軌跡指標

### 2.1 Android Logcat 環形緩衝區（Logcat Buffers）
Logcat 內部維護四個獨立的環形記憶體緩衝區（Ring Buffers）：
- `main`：主要應用程式層級日誌。
- `system`：核心系統服務與 Framework 事件（如 Package Manager, Activity Manager）。
- `radio`：通話、行動網路與 SIM 卡數據調用紀錄。
- `events`：二進位系統事件（如螢幕開關、App 切換前台）。

### 2.2 敏感外洩與木馬活動高危日誌特徵
- 搜尋未經混淆的明文 HTTP 請求或含有 `Bearer` 權杖之字串。
- 搜尋惡意 App 故意列印至日誌除錯的電話號碼、聯絡人清單或 GPS 座標（Tag: `System.out`, `AndroidRuntime`）。

## 第三動：手動獵捕與鑑識分析（ADB & SQLite3）

### 3.1 使用 ADB 採集全緩衝區 Logcat 運行時紀錄
```bash
# 步驟 1：檢視連接之行動設備
adb devices

# 步驟 2：傾印所有 Logcat 環形緩衝區日誌 (帶精準微秒時間戳與 PID/TID)
adb logcat -b all -v time -d > /tmp/forensic_logcat.txt

# 步驟 3：即時監控目標惡意 Package 的活動與 Intent 調用
adb logcat | grep -E "com.suspicious.app|ActivityManager"
```

### 3.2 提取目標 App 私有沙盒資料目錄
```bash
# 途徑 A：若手機具備 root 權限 (鑑識靶機標準作業)
adb shell "su -c 'tar -czvf /sdcard/app_dump.tar.gz /data/data/com.suspicious.app/'"
adb pull /sdcard/app_dump.tar.gz ./evidence/
tar -xzvf ./evidence/app_dump.tar.gz

# 途徑 B：若手機無 root 但 App 宣告 android:allowBackup="true" (備份漏洞提取)
adb backup -f backup.ab -noapk com.suspicious.app
# 使用 abe (android-backup-extractor) 解開備份 tar 檔
java -jar abe.jar unpack backup.ab backup.tar
tar -xvf backup.tar
```

### 3.3 SQLite 資料庫與 WAL 日誌深度查詢
```bash
# 步驟 1：檢查 databases 目錄中是否存在 .db-wal 檔案
ls -la ./evidence/data/data/com.suspicious.app/databases/

# 步驟 2：使用 sqlite3 進入互動式鑑識
sqlite3 ./evidence/data/data/com.suspicious.app/databases/chat_history.db

# 步驟 3：查詢所有資料表綱要與已發送外洩訊息
.tables
.schema messages
SELECT datetime(timestamp/1000, 'unixepoch', 'localtime'), sender, recipient, content FROM messages ORDER BY timestamp DESC;
```

### 3.4 Python 腳本自製 WAL 殘留字串與敏感資訊提取器
```python
import re
import sys

def parse_sqlite_wal(wal_file_path):
    print(f"[*] 鑑識 SQLite WAL 交易日誌: {wal_file_path}")
    with open(wal_file_path, "rb") as f:
        data = f.read()

    # 正則表達式獵捕常見外洩資料格式: 手機號碼, 身分證字號, 經緯度, Token
    patterns = {
        "Taiwan Phone": rb"09\d{8}",
        "URL / C2": rb"https?://[a-zA-Z0-9\.\-_/]+",
        "JWT / Bearer Token": rb"eyJ[a-zA-Z0-9_-]{20,}\.[a-zA-Z0-9_-]{20,}",
        "GPS Coordinates": rb"-?\d{1,3}\.\d{4,8},-?\d{1,3}\.\d{4,8}"
    }

    print("\n--- WAL 記憶體殘留資訊比對 ---")
    for desc, p in patterns.items():
        matches = set(re.findall(p, data))
        if matches:
            print(f"[+] 檢出 {desc} (共 {len(matches)} 筆):")
            for m in list(matches)[:5]: # 顯示前 5 筆
                print(f"    - {m.decode(errors='ignore')}")
        else:
            print(f"  - 未檢出 {desc}")

if __name__ == '__main__':
    if len(sys.argv) > 1:
        parse_sqlite_wal(sys.argv[1])
    else:
        print("用法: python parse_wal.py <target_database.db-wal>")
```

## 第五動：企業級防禦硬化與應急響應阻斷

### 5.1 Android 原生安全屬性加固（Manifest 基準）
針對企業內部自主研發之行動軟體，強制落實下列安全屬性：
1. **關閉備份通道**：
   在 `AndroidManifest.xml` 中強制宣告 `android:allowBackup="false"`，徹底杜絕攻擊者透過 ADB 備份功能旁路導出沙盒私有 SQLite 資料庫。
2. **啟用資料庫加密（SQLCipher）**：
   沙盒內儲存之 SQLite 資料庫全面導入 SQLCipher 實施 256-bit AES 全盤加密，金鑰動態儲存於硬體級安全金鑰庫（Android Keystore），即使物理提取資料庫檔案亦無法明文讀取。

### 5.2 禁止日誌列印（Proguard / R8 日誌剝離）
在生產環境發布版本中，透過 Proguard 規則強制剝離所有 `Log.d()`, `Log.v()`, `Log.i()` 代碼，防止敏感個人資料或 Token 洩漏至系統公共 Logcat 緩衝區中。

## 靶場實戰：從 ADB 提取受害 App 資料庫並還原外洩 Cookie

### 實驗目標
在模擬 Android 靶場環境中，利用 ADB 提取目標電商 App 的沙盒目錄，並解析 `Cookies.db` 還原攻擊者冒用之登入會話金鑰：

```bash
# 步驟 1：使用 ADB 將沙盒 SQLite 資料庫導出至本機
adb pull /data/data/com.shop.victim/databases/webviewCookiesChromium.db ./test_cookies.db

# 步驟 2：啟動 sqlite3 查詢 cookies 資料表
sqlite3 ./test_cookies.db "SELECT host_key, name, value, datetime(expires_utc/1000000-11644473600, 'unixepoch') FROM cookies;"

# 步驟 3：將提取之 Session ID 轉換為 Curl 指令驗證權杖有效性
curl -s -H "Cookie: session_id=7a8b9c0d1e2f" https://shop.victim.corp/api/user/profile
```
