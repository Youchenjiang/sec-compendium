# 實戰手冊 19.1：PE 結構逆推、區段屬性鑑識與資訊熵 (Shannon Entropy) 檢測

## 案發現場破題

在端點威脅獵捕與惡意軟體初篩中，可執行檔（PE, Portable Executable）是攻擊者在 Windows 系統植入木馬、載荷（Payload）與勒索軟體的最主要載體。面對每日數以萬計的未知檔案，SOC 研判人員與鑑識工程師不可能對每個樣本進行完整的反編譯與動態除錯。

第一時間透過靜態結構解析——檢驗 DOS 標頭（MZ）、NT 標頭（PE Signature）、Optional Header 進入點（AddressOfEntryPoint）、區段屬性（如 `.text` 異常可寫、異常區段名稱如 `.upx0`）以及計算各區段之夏農資訊熵（Shannon Entropy），防禦人員能在數秒內判定該檔案是否經過加殼（Packer）、代碼混淆（Obfuscation）或在資源段（`.rsrc`）隱藏加密載荷。本手冊詳細拆解 PE 規範、靜態特徵提取技術與自動化檢驗管道。

```
Windows PE 32/64 內部核心結構對應：

+-------------------------------------------------------+
| IMAGE_DOS_HEADER (MZ 標頭, 0x5A4D)                     |
| e_lfanew (指向 NT 標頭之檔案偏移量)                   |
+-------------------------------------------------------+
| DOS Stub ("This program cannot be run in DOS mode")   |
+-------------------------------------------------------+
| IMAGE_NT_HEADERS                                      |
|  - Signature ("PE\0\0", 0x00004550)                   |
|  - FileHeader (機器架構 Machine, 區段數 NumberOfSections)|
|  - OptionalHeader (AddressOfEntryPoint, ImageBase)    |
+-------------------------------------------------------+
| Section Table (區段頭列表)                            |
|  - .text  (可執行代碼段, 特徵: 包含 IMAGE_SCN_MEM_EXECUTE)|
|  - .data  (全域已初始化變數段)                          |
|  - .rsrc  (資源段: 圖示、對話盒、內嵌二進位)           |
+-------------------------------------------------------+
| Sections Data (各區段原始二進位二進制資料)            |
+-------------------------------------------------------+
```

## 第一動：PE 結構鑑識核心原理與夏農資訊熵

### 1.1 PE 標頭核心欄位與異常指標
- **DOS Header (`IMAGE_DOS_HEADER`)**：
  - `e_magic`：固定為 `0x5A4D`（ASCII: `MZ`）。若被竄改或損壞，Windows 載入器將拒絕執行。
  - `e_lfanew`：位於偏移 `0x3C`，記錄 PE 標頭（NT Headers）的起始位址。若此值指向檔案極尾端或非預期區域，可能為 Header Manipulation 隱匿技巧。
- **File Header (`IMAGE_FILE_HEADER`)**：
  - `NumberOfSections`：區段數量，一般正常編譯程式通常介於 3 至 8 個之間。若只有 1~2 個（如 UPX 只有 2 個區段）或超過 20 個，需高度警惕。
  - `TimeDateStamp`：編譯時間戳。若時間戳為 1970 年以前或未來時間，為典型偽造時間戳（Timestomping）反鑑識跡象。
- **Optional Header (`IMAGE_OPTIONAL_HEADER`)**：
  - `AddressOfEntryPoint (AoEP)`：程式載入記憶體後的初始執行位址（RVA）。正常編譯器的 AoEP 應指向 `.text` 或 `.code` 區段。若 AoEP 落在最後一個區段、`.rsrc` 甚至區段以外，通常為加殼殼頭（Stub）或 Packer 的解密跳轉點。
  - `Characteristics`：區段權限標記。若區段同時具備 `IMAGE_SCN_MEM_WRITE`（0x80000000）與 `IMAGE_SCN_MEM_EXECUTE`（0x20000000），即具備 W+X 屬性，違反 DEP 原則，極可能是自解密加殼程式（Self-decrypting Packer）。

### 1.2 夏農資訊熵（Shannon Entropy）物理意義
夏農資訊熵公式為：
$$H(X) = - \sum_{i=0}^{255} P(x_i) \log_2 P(x_i)$$
- 數值範圍介於 `0.0` 至 `8.0` 之間。
- **0.0 ~ 3.0**：高度重複內容（如整段 `0x00` 或全空白字元）。
- **4.0 ~ 6.0**：普通純文字、常規未經混淆的 x86/x64 機械碼與資料。
- **6.8 ~ 7.2**：代碼輕度混淆或使用常見壓縮演算法。
- **7.2 ~ 8.0**：極度隨機化，典型為高強度壓縮（Packer）、AES/RC4 加密載荷或 Shellcode。若 `.rsrc` 或特定自訂區段的 Entropy 逼近 8.0，通常意味該區段內嵌了加密的二階段木馬（Stager）。

## 第二動：靜態鑑識特徵與雜湊取證定位

### 2.1 關鍵識別特徵清單
1. **區段名稱異常**：非標準區段名稱（例如 `.upx0`, `.upx1`, `.aspack`, `.vmp0`, `.themida`）。
2. **Raw Size vs Virtual Size 懸殊**：
   - 正常情況：`SizeOfRawData` 與 `VirtualSize` 數值接近。
   - 加殼特徵：`SizeOfRawData == 0` 但 `VirtualSize` 極大（例如 100KB），表示檔案在磁碟時不佔空間，執行時才動態解壓縮在記憶體中配置並填入代碼。
3. **Import Table（導入表, IAT）極端匱乏**：正常程式導入數十到數百個 API；加殼程式通常僅導入 `LoadLibraryA` 與 `GetProcAddress` 兩個 API 用於運行時自解析。

### 2.2 多維雜湊特徵提取（Imphash & ssdeep）
- **Imphash (Import Hash)**：計算導入函數名稱與順序的 MD5 雜湊，同一個惡意家族即使主程式加混淆，若其呼叫 API 清單相同，Imphash 仍高度一致。
- **ssdeep (CTPH, Context Triggered Piecewise Hashing)**：模糊雜湊（Fuzzy Hashing），用以比對兩個二進位樣本的相似百分比。

## 第三動：手動獵捕與鑑識分析（pefile & Python）

### 3.1 使用 Python `pefile` 深度解析 PE 結構與計算資訊熵
```python
import sys
import math
import pefile

def calculate_entropy(data):
    if not data:
        return 0.0
    entropy = 0
    total_bytes = len(data)
    byte_counts = [0] * 256
    for b in data:
        byte_counts[b] += 1
    for count in byte_counts:
        if count > 0:
            p = float(count) / total_bytes
            entropy -= p * math.log(p, 2)
    return entropy

def analyze_pe(file_path):
    print(f"[*] 鑑識目標: {file_path}")
    pe = pefile.PE(file_path)
    
    # 提取基本屬性
    entry_point = pe.OPTIONAL_HEADER.AddressOfEntryPoint
    image_base = pe.OPTIONAL_HEADER.ImageBase
    num_sections = pe.FILE_HEADER.NumberOfSections
    compile_time = pe.FILE_HEADER.TimeDateStamp
    imphash = pe.get_imphash()
    
    print(f"[+] EntryPoint: 0x{entry_point:08X} (ImageBase: 0x{image_base:08X})")
    print(f"[+] Sections Count: {num_sections}, Compile Timestamp: {compile_time}")
    print(f"[+] Imphash: {imphash}")
    
    print("\n--- 區段屬性與資訊熵 (Section Entropy Audit) ---")
    is_packed = False
    for section in pe.sections:
        sec_name = section.Name.decode('utf-8', errors='ignore').strip('\x00')
        raw_size = section.SizeOfRawData
        virt_size = section.Misc_VirtualSize
        entropy = section.get_entropy()
        characteristics = section.Characteristics
        
        # 檢測 W+X 屬性
        is_write = bool(characteristics & 0x80000000)
        is_exec = bool(characteristics & 0x20000000)
        wx_flag = " [ALERT: W+X]" if (is_write and is_exec) else ""
        
        print(f"  - 區段 [{sec_name:8s}] RawSize: {raw_size:8d} | VirtSize: {virt_size:8d} | Entropy: {entropy:.2f}{wx_flag}")
        
        if entropy > 7.0 or (is_write and is_exec) or (raw_size == 0 and virt_size > 4096):
            is_packed = True

    if is_packed:
        print("\n[!] 結論: 該樣本高度疑似加殼 (Packed) 或經代碼加密混淆！")
    else:
        print("\n[+] 結論: 結構常態，未發現明顯加殼或高熵異常。")

if __name__ == '__main__':
    if len(sys.argv) > 1:
        analyze_pe(sys.argv[1])
    else:
        print("用法: python analyze_pe.py <target_pe_file>")
```

## 第四動：SIEM 關聯規則與端點威脅指標工程

### 4.1 Splunk 整合 Sysmon Event ID 7 關聯 Imphash 威脅獵捕
當端點載入驅動或未知二進位檔案時，利用 Sysmon Event ID 7（Image loaded）之 Imphash 與威脅情資比對：
```spl
index=sysmon EventCode=7
| eval imphash=lower(Imphash)
| search imphash IN ("a7b4f539e8020e28b12228830f305f88", "3b290119318854a8494b9aa1f86d6ee4")
| stats count min(_time) as first_seen max(_time) as last_seen by host, Image, ImageLoaded, imphash
| eval threat_level="CRITICAL"
| table first_seen, host, Image, ImageLoaded, imphash, count
```

### 4.2 YARA 規則：檢測可疑高熵與 W+X 區段 PE 檔案
```yara
rule Suspicious_Packed_HighEntropy_PE
{
    meta:
        description = "檢測包含高夏農資訊熵區段或 W+X 可寫可執行區段之 PE 檔案"
        author = "BlueTeam SOC"
        date = "2026-09-14"
        severity = "High"
    condition:
        // 驗證為合法 PE 檔案
        uint16(0) == 0x5A4D and uint32(uint32(0x3C)) == 0x00004550 and
        (
            // 規則 1: 包含極少導入函式且區段數過少
            pe.number_of_sections <= 2 or
            // 規則 2: 任何區段資訊熵大於 7.4
            for any section in pe.sections : (
                section.entropy > 7.4
            ) or
            // 規則 3: 任何區段同時具備可寫與可執行權限
            for any section in pe.sections : (
                (section.characteristics & 0x80000000) and (section.characteristics & 0x20000000)
            )
        )
}
```

## 第五動：企業級自動化審查硬化與處置阻斷

### 5.1 部署前 CI/CD 二進位安全閘門（Security Gate）
- 在編譯產線中整合自動化 PE 檢查腳本。若產出的 DLL/EXE 包含未預期區段、未啟用 DEP（Data Execution Prevention）或 ASLR（Address Space Layout Randomization），立即阻斷發布流程：
```bash
# 驗證 DLL/EXE 是否強制開啟 DllCharacteristics 中的 ASLR 與 NX 相容
pefile_dump --check-mitigations target_binary.exe
```

### 5.2 應用程式白名單與 AppLocker 防線加固
- 利用 Imphash 與數位簽名（Digital Signature）建立多重白名單基線。
- 設定 AppLocker / WDAC（Windows Defender Application Control）策略，禁止在一般使用者可寫目錄（如 `%AppData%`, `%Temp%`）執行未經簽名且具備 W+X 屬性之二進位程式。

## 靶場實戰：從原始未加殼到 UPX 加殼樣本之比對鑑識

### 實驗目標
在 Linux/Windows 靶場環境中，使用原生編譯程式產出乾淨樣本，並使用 UPX 加殼後進行雙向取證比對：

```bash
# 步驟 1：建立乾淨測試程式 (test_clean.exe)
cat << 'EOF' > test.c
#include <stdio.h>
int main() { printf("Cyber Range Defense Benchmark\n"); return 0; }
EOF
x86_64-w64-mingw32-gcc test.c -o test_clean.exe

# 步驟 2：使用 UPX 加殼產出惡意模擬樣本 (test_packed.exe)
upx -9 test_clean.exe -o test_packed.exe

# 步驟 3：使用 Python 腳本對比兩者資訊熵與區段
python -c "
import pefile
for f in ['test_clean.exe', 'test_packed.exe']:
    pe = pefile.PE(f)
    print(f'=== {f} ===')
    for s in pe.sections:
        print(f'{s.Name.decode().strip()}: Entropy={s.get_entropy():.2f}, RawSize={s.SizeOfRawData}, VirtSize={s.Misc_VirtualSize}')
"
```
