# 實戰手冊 19.3：文件型惡意巨集深度逆推、內嵌 OLE 物件與 Shellcode 萃取

## 案發現場破題

在進階持續性威脅（APT）與金融犯罪釣魚活動中，惡意微軟 Office 文件（如 `.docm`, `.xlsm`, `.doc`, `.xls`）長期位居初始入侵管道前三名。攻擊者利用使用者對「啟用巨集內容以檢視受保護文件」提示的鬆懈心態，將惡意 VBA 巨集（Visual Basic for Applications）嵌入複合檔案二進位格式（OLE, Compound File Binary Format）或 OpenXML 結構中。

高階攻擊者往往採用巨集混淆（VBA Stomping 抹除原始碼只留 P-Code）、內嵌 OLE 套件（Package 物件內夾帶 PE/VBS）、或透過 Excel 4.0 (XLM) 巨集在試算表儲存格呼叫 Win32 API 執行 Shellcode。身為藍隊鑑識與威脅分析專家，必須掌握離線安全解析技術，利用 `oledump.py`、`oletools`（olevba, oletimes）與 `pcodedmp` 在不開啟 Office 軟體的無害化環境中，精準剝除外殼、萃取出原始 Shellcode 與惡意載荷。

```
惡意 Office 文件解構與鑑識工具對照：

[OLE 複合結構 (Legacy .doc/.xls)]
Root Entry ───┬───> DocumentSummaryInformation
              ├───> WordDocument
              └───> Macros / VBA ──┬───> dir (模組目錄)
                                   ├───> ThisDocument (VBA Source + P-Code)
                                   └───> Module1 (惡意載荷)
  * 工具：`oledump.py -s <idx> -v` 提取解壓縮 VBA 原始碼

[VBA Stomping 攻擊模式 (反靜態掃描)]
  - 原始碼 (Source Code) 區段被全數以 0x00 覆蓋填滿！
  - 編譯後二進位 P-Code 保留在模組中。
  - 當被害端 Office 版本與攻擊者相符時，直接執行 P-Code 成功載入 Shellcode！
  * 戰術：`olevba` 靜態掃描為空，必須改用 `pcodedmp` 反編譯 P-Code 虛擬機指令。
```

## 第一動：OLE 結構、VBA 儲存模型與攻擊向量

### 1.1 OLE2 複合檔案（CFBF）內部存取機制
- **儲存結構（Storage & Streams）**：OLE 結構如同一個迷你虛擬檔案系統，分為「目錄儲存區（Storage）」與「資料流（Stream）」。
- **VBA 巨集資料流儲存**：VBA 專案儲存在 `_VBA_PROJECT_CUR` 或 `VBA` 儲存區內。各模組資料流包含了被微軟專有演算法（MS-OVBA）壓縮的原始碼文字，以及編譯產生的 P-Code 二進位字節碼。

### 1.2 三大惡意觸發與逃逸技術
1. **自動執行觸發器（Auto-Execution Hooks）**：
   - Word: `AutoOpen`, `AutoExec`, `Document_Open`, `Document_Close`。
   - Excel: `Auto_Open`, `Workbook_Open`, `Workbook_Activate`。
2. **VBA Stomping（P-Code 與原始碼脫鉤）**：攻擊者故意抹去或偽造壓縮文字流（CompressedSourceCode），但保留 `PerformanceCache` 中的編譯 P-Code。傳統防毒與靜態 YARA 若只掃描解壓後原始碼將徹底撲空。
3. **Excel 4.0 (XLM) 巨集**：無需啟用 VBA 模組，直接將指令藏匿於隱藏工作表（Hidden/VeryHidden Sheets）的儲存格公式中（如 `=CALL("kernel32","VirtualAlloc",...)`），呼叫 Win32 API 進行記憶體注入。

## 第二動：資料流索引鑑識與特徵指標

### 2.1 `oledump.py` 資料流標記特徵
執行 `oledump.py` 時，各 Stream 前方會標註特殊字元：
- `m`（小寫）：代表該 Stream 包含巨集程式碼，但為空白或無實質有效代碼。
- `M`（大寫）：**高危標記**！代表該 Stream 包含具備實質指令的 VBA 巨集代碼，必須立即提取。
- `O`（大寫）：代表內嵌 OLE 物件或二進位 Package，通常內夾惡意 EXE、DLL 或 CHM。

### 2.2 典型高危特徵關鍵字矩陣
| 惡意行為分類 | 關鍵特徵字串（VBA 函數 / API 宣告） |
| :--- | :--- |
| **自動觸發** | `AutoOpen`, `Document_Open`, `Auto_Open`, `Workbook_Open` |
| **行程拉起** | `Shell`, `WScript.Shell`, `Process.Create`, `Environ("COMSPEC")` |
| **記憶體載荷執行** | `Declare PtrSafe Function VirtualAlloc`, `RtlMoveMemory`, `CreateThread` |
| **字串拼接混淆** | `Chr()`, `ChrW()`, `StrReverse()`, `Replace()`, `XOR` 運算迴圈 |
| **檔案導出** | `CreateObject("Scripting.FileSystemObject")`, `ADODB.Stream` |

## 第三動：手動獵捕與鑑識分析（oledump & pcodedmp）

### 3.1 使用 oledump.py 提取 OLE 結構與 VBA 程式碼
```bash
# 步驟 1：檢視所有資料流清單，鎖定帶有大寫 'M' 之高危 Stream
oledump.py suspicious_doc.docm

# 步驟 2：提取指定 Stream（假設為第 8 個 Stream）的解壓縮 VBA 原始碼
oledump.py -s 8 -v suspicious_doc.docm > extracted_vba.txt

# 步驟 3：如果包含內嵌 OLE 物件 (Stream 標示為 O)，導出原始二進位二進制檔案
oledump.py -s 4 -d suspicious_doc.docm > embedded_payload.bin
```

### 3.2 使用 pcodedmp 破解 VBA Stomping 反鑑識攻擊
若 `olevba` 或 `oledump.py -v` 輸出為空，但巨集在被害主機依然能執行，則判定為 VBA Stomping：
```bash
# 反編譯 P-Code 虛擬機指令，還原隱藏的真實呼叫
pcodedmp -d suspicious_doc.docm

# 觀察反編譯輸出中的核心指令 (例如 LitStr 字串載入、Concat 拼接與 Call 呼叫)
```

### 3.3 Python 自動化辨析 Office 隱藏工作表與 XLM 巨集
```python
import sys
import openpyxl

def audit_excel_sheets(file_path):
    print(f"[*] 審查 Excel 活頁簿工作表狀態: {file_path}")
    try:
        wb = openpyxl.load_workbook(file_path, read_only=False, keep_vba=True)
        for sheet_name in wb.sheetnames:
            sheet = wb[sheet_name]
            # state: visible, hidden, veryHidden
            state = sheet.sheet_state
            if state in ["hidden", "veryHidden"]:
                print(f"[ALERT] 發現隱藏工作表: '{sheet_name}' (狀態: {state})")
                # 掃描前 20 欄是否有 CALL 或 EXEC 公式
                for row in sheet.iter_rows(max_row=50, max_col=10, values_only=True):
                    for cell in row:
                        if cell and isinstance(cell, str) and ("CALL" in cell.upper() or "EXEC" in cell.upper() or "HALT" in cell.upper()):
                            print(f"  [CRITICAL] 檢出惡意 XLM 公式: {cell}")
            else:
                print(f"  - 正常工作表: '{sheet_name}' (狀態: {state})")
    except Exception as e:
        print(f"[-] 檢查失敗 (可能為非標準 OpenXML 或 OLE 格式): {e}")

if __name__ == '__main__':
    if len(sys.argv) > 1:
        audit_excel_sheets(sys.argv[1])
    else:
        print("用法: python check_excel.py <target_file>")
```

## 第四動：SIEM 關聯規則與端點動態阻斷工程

### 4.1 Splunk 偵測 Office 進程拉起命令列直譯器（LOLBAS 獵捕）
```spl
index=sysmon EventCode=1
| eval ParentImage=lower(ParentImage), Image=lower(Image)
| search ParentImage IN ("*\\winword.exe", "*\\excel.exe", "*\\powerpnt.exe")
  AND Image IN ("*\\cmd.exe", "*\\powershell.exe", "*\\pwsh.exe", "*\\mshta.exe", "*\\certutil.exe", "*\\wscript.exe", "*\\cscript.exe")
| stats count min(_time) as first_seen max(_time) as last_seen by host, User, ParentImage, Image, CommandLine
| eval severity="CRITICAL"
| table first_seen, host, User, ParentImage, Image, CommandLine
```

### 4.2 YARA 規則：檢測內嵌 Shellcode API 宣告與 AutoOpen 之惡意文件
```yara
rule Malicious_Office_Macro_VBA_API_Execution
{
    meta:
        description = "檢測包含記憶體分配 API 與自動觸發事件之惡意 Office 巨集"
        author = "BlueTeam DFIR"
        date = "2026-09-14"
        severity = "Critical"
    strings:
        // 自動執行進入點
        $auto1 = "AutoOpen" nocase
        $auto2 = "Document_Open" nocase
        $auto3 = "Workbook_Open" nocase
        
        // 記憶體宣告與注入 API
        $api1 = "VirtualAlloc" ascii nocase wide
        $api2 = "RtlMoveMemory" ascii nocase wide
        $api3 = "CreateThread" ascii nocase wide
        $api4 = "PtrSafe" ascii nocase wide
    condition:
        // 匹配 OLE 或 ZIP/OpenXML 魔術字節
        (uint32(0) == 0xE011CFD0 or uint32(0) == 0x04034B50) and
        (any of ($auto*)) and
        (2 of ($api*))
}
```

## 第五動：企業級防禦硬化與應急響應阻斷

### 5.1 全面落實 GPO 封鎖 Internet 來源檔案之巨集執行
- **微軟預設封鎖 Mark-of-the-Web (MOTW)**：
  - 透過 GPO 啟用「封鎖來自網際網路檔案中的巨集執行」（Block macros from running in Office files from the Internet）。
  - 路徑：`User Configuration > Administrative Templates > Microsoft Word 2016 > Word Options > Security > Trust Center`。
  - 當檔案具備 `Zone.Identifier = 3`（Internet）時，Office 直接禁止使用者手動啟用巨集。

### 5.2 禁用 Excel 4.0 (XLM) 巨集
- 在 GPO 中明確禁止使用 Excel 4.0 巨集，僅允許具備受信任憑證簽名之 VBA 專案執行。

## 靶場實戰：從惡意樣本文檔中剝離 Shellcode 與還原 URL

### 實驗目標
在靶場中分析一份具備字串拼接與 API 呼叫的惡意 Word 文件 `sample_phish.docm`，提取隱藏在其中的 C2 下載位址與 Shellcode：

```bash
# 步驟 1：使用 oledump.py 盤點資料流
oledump.py sample_phish.docm

# 步驟 2：導出巨集並過濾拼接字元
oledump.py -s 7 -v sample_phish.docm | grep -i "Chr("

# 步驟 3：撰寫快速單行 Python 將 Chr() 陣列轉回 ASCII
python -c "
import re
payload = 'Chr(104) & Chr(116) & Chr(116) & Chr(112) & Chr(58) & Chr(47) & Chr(47) & Chr(101) & Chr(118) & Chr(105) & Chr(108)'
nums = [int(x) for x in re.findall(r'Chr\((\d+)\)', payload)]
print('還原明文: ' + ''.join([chr(n) for n in nums]))
"
```
