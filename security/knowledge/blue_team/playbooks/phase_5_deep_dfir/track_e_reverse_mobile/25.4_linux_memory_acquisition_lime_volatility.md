# 實戰手冊 25.4：Linux 實體記憶體採集 (LiME)、核心符號表 (ISF) 還原與 Volatility 3 深度鑑識

## 案發現場破題

在 Linux 伺服器遭受無檔案惡意程式（Fileless Malware）、內存注入後門（MemShell）或核心 Rootkit（LKM）攻擊時，攻擊者的一切執行痕跡僅留存於揮發性實體記憶體（Physical RAM）中。依據 RFC 3227 數據揮發次序，記憶體獲取是鑑識黃金流程的第一優先級。

然而，不同於 Windows 記憶體鑑識擁有微軟公開且完備的 PDB 符號伺服器，Linux 核心具有高度碎片化特性——不同的發行版（Ubuntu, Debian, RHEL, CentOS, Rocky）、不同的微核心版本（Kernel Release / Patch level）其內部核心結構體（如 `struct task_struct`, `struct cred`, `struct mm_struct`）成員偏移量完全不同。若沒有精準匹配的符號資訊表（ISF, Intermediate Symbol Format），Volatility 3 將徹底無法解析記憶體鏡像！身為數位鑑識專家，必須精通使用 LiME（Linux Memory Extractor）採集 RAW / Lime 鏡像，掌握利用 DWARF 除錯資訊或 Ubuntu Debug DDEB 產出 JSON 格式 ISF 符號表，並以 Volatility 3 還原無檔案隱蔽行程。

```
Linux 記憶體採集與 Volatility 3 ISF 符號鏈條還原全景：

[目標 Linux 受害伺服器]
  1. 編譯或載入 LiME 核心模組:
     insmod lime.ko "path=/tmp/mem_dump.lime format=lime"
          │ (實體 RAM 鏡像 Dump)
          ▼
     mem_dump.lime (二進位實體記憶體)

  2. 提取或建構符號資訊 (ISF - Intermediate Symbol Format):
     - 核心符號表: /boot/System.map-$(uname -r)
     - 核心除錯資訊: vmlinux (DWARF 除錯符號 - 來自 kernel-debuginfo / ddeb)
          │
          ▼ 透過 dwarf2json 工具轉譯
     linux-image-$(uname -r).json (ISF 符號表)

[鑑識分析工作站 (Volatility 3)]
  volatility3/symbols/linux/ 放置: linux-image-$(uname -r).json
       │
       ▼ (精準鎖定核心結構體偏移量)
  vol -f mem_dump.lime linux.pslist / linux.malfind / linux.check_modules
```

## 第一動：Linux 記憶體架構、LiME 採集與格式規範

### 1.1 LiME（Linux Memory Extractor）核心原理
- **繞過 `/dev/mem` 限制**：現代 Linux 核心普遍開啟 `CONFIG_STRICT_DEVMEM` 與 Kernel Lockdown，禁止用戶態行程透過 `/dev/mem` 讀取實體記憶體。LiME 作為載入核心模組（LKM），直接於 Ring 0 空間走訪實體頁框（Page Frames）並透過核心 API（如 `kmap_atomic`）進行映射採集。
- **支援鏡像格式**：
  1. `format=raw`：純二進位實體記憶體傾印，不帶任何檔案頭，鏡像大小與實體 RAM 完全 1:1。
  2. `format=lime`：包含 LiME 專屬結構頭，精準記錄實體記憶體各區塊（Memory Ranges）的起始位址與長度，自動跳過硬體 I/O 映射區（MMIO Holes），相容性與鑑識標準最高。
  3. `format=padded`：在 MMIO 洞穴填入 `0x00` 填充以維持全記憶體線性連續。

### 1.2 採集防污染原則（Anti-Forensic Contamination）
- **本地採集**：將 `lime.ko` 放置於外接唯讀防寫隨身碟，輸出目標指向外接式儲存設備或掛載之 NFS 共享路徑，嚴禁將數十 GB 的 Dump 檔直接寫入受害伺服器本機磁碟，避免覆蓋已刪除檔案之 Inode 與資料區塊。
- **網路傳輸模式**：LiME 內建網路傳輸功能（`format=lime path=tcp:4444`），鑑識人員可於遠端主機使用 `nc -l 4444 > mem.lime` 直接跨網路接收記憶體流，將主機污染降至最低。

## 第二動：Volatility 3 ISF 符號表建構體系

### 2.1 為什麼需要 ISF（Intermediate Symbol Format）？
Volatility 2 時代依賴打包有 `module.c` 與 `System.map` 的 ZIP Profile；Volatility 3 徹底重構為基於 JSON 格式的 ISF 檔案。ISF 記載了該特定版本核心的所有：
- 基本資料型態大小（Primitive Types）。
- 核心結構體定義與成員位元組偏移量（Struct Members Offset）。
- 全域符號位址（Global Variables & Function Addresses）。

### 2.2 建構 ISF 的兩種途徑
1. **途徑 A：自官方除錯倉庫下載帶有 DWARF 的 `vmlinux`**
   - Debian/Ubuntu: 安裝 `linux-image-$(uname -r)-dbgsym`。
   - RHEL/CentOS: 安裝 `kernel-debuginfo`。
2. **途徑 B：使用 dwarf2json 轉譯**
   官方開源工具 `dwarf2json` 讀取 `vmlinux` 與 `System.map`，自動產出可直接供 Volatility 3 使用的 `.json` 符號表。

## 第三動：手動採集與 ISF 建構實戰（LiME & dwarf2json）

### 3.1 編譯並使用 LiME 採集記憶體
```bash
# 步驟 1：在目標主機或相同核心版本環境編譯 LiME (需具備 kernel-headers)
git clone https://github.com/504ensicsLabs/LiME.git
cd LiME/src
make

# 步驟 2：載入 LiME 模組並透過本機輸出鏡像 (或外接硬碟 /mnt/usb/mem.lime)
sudo insmod lime-$(uname -r).ko "path=/mnt/usb/ubuntu2204_ram.lime format=lime"

# 步驟 3：卸載 LiME 模組
sudo rmmod lime

# 步驟 4：立即計算 SHA256 建立證據監管鏈 (Chain of Custody)
sha256sum /mnt/usb/ubuntu2204_ram.lime > /mnt/usb/ubuntu2204_ram.lime.sha256
```

### 3.2 建構 Volatility 3 專用 ISF 符號表
```bash
# 步驟 1：下載並編譯 dwarf2json 工具
git clone https://github.com/volatilityfoundation/dwarf2json.git
cd dwarf2json
go build

# 步驟 2：使用 dwarf2json 結合 vmlinux 與 System.map 產出 ISF
./dwarf2json linux --elf /usr/lib/debug/boot/vmlinux-$(uname -r) \
  --system-map /boot/System.map-$(uname -r) > linux-image-$(uname -r).json

# 步驟 3：將產出之 JSON 檔案部署至 Volatility 3 符號目錄
mkdir -p /opt/volatility3/volatility3/symbols/linux/
cp linux-image-$(uname -r).json /opt/volatility3/volatility3/symbols/linux/
```

### 3.3 執行 Volatility 3 深度鑑識分析指令集
```bash
# 檢視行程清單 (EPROCESS equivalent: task_struct)
vol -f ubuntu2204_ram.lime linux.pslist

# 獵捕無檔案注入代碼與可疑記憶體屬性 (PAGE_EXECUTE)
vol -f ubuntu2204_ram.lime linux.malfind

# 檢查核心模組隱藏與斷鏈 (DKOM 斷鏈)
vol -f ubuntu2204_ram.lime linux.check_modules

# 還原記憶體中已關閉之網路 Socket
vol -f ubuntu2204_ram.lime linux.sockstat

# 檢查系統呼叫表 (Syscall Table) 是否遭掛鉤
vol -f ubuntu2204_ram.lime linux.check_syscall
```

## 第四動：SIEM 關聯規則與端點鑑識告警工程

### 4.1 Splunk 整合 Volatility 鑑識產出之異常行程
將 `linux.malfind` 輸出轉為 CSV/JSON 吸納至 SIEM，比對執行映像路徑與記憶體保護屬性：
```spl
index=dfir_artifacts sourcetype="volatility:linux:malfind"
| eval Protection=upper(Protection)
| search Protection="*WRITE*" AND Protection="*EXECUTE*"
| stats count by host, PID, Process, StartVPN, Protection
| eval alert="Fileless Code Injection in Linux Process Memory"
| table host, PID, Process, StartVPN, Protection, alert
```

### 4.2 Sigma 規則：偵測透過 insmod 載入未知核心模組之行為
```yaml
title: Suspicious Kernel Module Insertion During Incident Response Window
id: c9281a4b-91f2-421b-8712-441295fa9012
status: experimental
description: 檢測未經變更審查之 insmod 操作，避免攻擊者或未授權工具破壞記憶體現場
logsource:
  category: process_creation
  product: linux

  selection:
    CommandLine|contains:
      - 'insmod '

      - '.ko'
  condition: selection
```

## 第五動：企業級防禦硬化與應急響應阻斷

### 5.1 離線核心符號快取庫（Enterprise ISF Repository）
- 在企業大型伺服器群中，為所有上線運行的 Golden Image（包含標準 Ubuntu/RHEL 核心更新）自動化建構並集中歸檔其 ISF JSON 符號表。
- 一旦突發資安事件，鑑識人員無需在受害現場花費數小時尋找 debuginfo 套件，可直接調用中心倉庫對應的符號表，實現 15 分鐘內即時分析。

### 5.2 記憶體採集安全防護 SOP
- 嚴格遵守 RFC 3227。在提取 RAM 鏡像前：
  - **嚴禁重啟主機（Reboot）**：重啟將直接導致記憶體中無檔案木馬、解密後之 C2 字串與連線 Socket 灰飛煙滅。
  - **嚴禁使用 `kill -9` 終止未知進程**：避免破壞進程記憶體映射（VMA 結構）與打開之檔案描述符。
  - **計算雙重雜湊**：鏡像產出後立即計算 MD5 與 SHA256，並將 Hash 值存入安全紀錄表，確保证據法律效力。

## 靶場實戰：從編譯 LiME 到 Volatility 3 走訪進程樹

### 實驗目標
在 Linux 靶場虛擬機中，使用 LiME 完成實體 RAM 鏡像 Dump，並在分析機上利用預編之 ISF 成功執行 `linux.pslist` 還原出目標行程：

```bash
# 步驟 1：在靶場主機執行背景測試進程 (模擬隱藏後門)
(exec -a "[kworker/u2:1-ev]" sleep 3600 &)

# 步驟 2：使用 LiME 快速導出實體記憶體
sudo insmod lime.ko "path=/tmp/target_ram.lime format=lime"
sudo rmmod lime

# 步驟 3：在鑑識端運行 Volatility 3 解析行程
vol -f /tmp/target_ram.lime linux.pslist | grep -E "PID|sleep|kworker"

# 步驟 4：執行 malfind 檢驗是否存在可寫可執行注入區段
vol -f /tmp/target_ram.lime linux.malfind

# 步驟 5：比對 bash 歷史紀錄提取記憶體命令
vol -f /tmp/target_ram.lime linux.bash
```
