# 03.1 交換機連接埠安全與 err-disable 違規狀態處置 (Switch Port-Security & Err-Disable Recovery)

## 案發現場破題

在企業內部辦公室或資料中心中，攻擊者最常見的實體介入或內網漫遊手段，便是在未經許可的情況下將惡意筆電、迷你路由器（如 WiFi Pineapple）或硬體分流器（Network Tap）直接插入牆面網路孔，或利用工具（如 `macof`）在數秒內發送數十萬個隨機 MAC 地址發動 **MAC 泛洪攻擊（MAC Flooding）**。這會迅速填滿交換機的 CAM 表（Content Addressable Memory Table），迫使交換機退化為「集線器（Hub）模式」，將所有內部未加密流量廣播至全網段。

```
[攻擊者惡意主機 / 隨機 MAC 泛洪]
       │
       ▼ (高速發送大量偽造來源 MAC 封包)
+-------------------------------------------------------------------------------+
| Cisco / 企業級 L2 交換機接入埠 (Access Port: Gi0/1)                            |
|                                                                               |
|  [ CAM 表位址空間 (MAC Table) ]                                                |
|    - 正常容量: 8,192 筆                                                       |
|    - 遭攻擊: 數秒內塞滿 100,000+ 筆隨機垃圾 MAC                               |
|                                                                               |
|  【Port-Security 防禦觸發】                                                   |
|    - 最大允許 MAC 數: 1 (Sticky MAC)                                          |
|    - 違規處理模式: Shutdown                                                   |
+-------------------------------------------------------------------------------+
       │
       ▼ (觸發 Violation: 連接埠被強制關閉進入 err-disable 狀態)
[Gi0/1 斷開連線 ➔ 阻斷廣播洩漏 ➔ SNMP Trap 通報 NOC/SOC 告警]
```

### 痛點場景
- **交換機 CAM 表溢位癱瘓**：交換機一旦 CAM 表耗盡，便無法學習正常 MAC 轉發，導致合法員工連線中斷或通訊內容被攻擊者全量側聽（Sniffing）。
- **私接未授權 AP 與 Hub**：員工私自將家用無線路由器插入辦公網路孔，導致外部訪客在未經 802.1X 認證下直通核心內網。
- **err-disable 處置混亂**：連接埠被交換機判定違規而閉鎖（err-disable）後，維運人員常盲目執行 `shutdown` ➔ `no shutdown` 強制重啟，而未先排查實體威脅，導致網路反覆震盪（Flapping）。

## 第一動：Port-Security 三大違規模式與底層運作 (Violation Modes Breakdown)

Cisco IOS 等企業級交換機針對 Port-Security 提供三種違規處理動作（Violation Actions）：

```
+-----------------------------------------------------------------------------------------------+
| Port-Security 三大違規處置模式對比                                                             |
|                                                                                               |
| 1. Protect (保護模式 - 靜默丟棄)                                                              |
|    - 行為：直接丟棄未知 MAC 的封包。                                                          |
|    - 缺點：不增加違規計數器 (Violation Counter)，不發送 SNMP Trap，網管與 SOC 完全無感。     |
|                                                                                               |
| 2. Restrict (限制模式 - 丟棄並告警)                                                           |
|    - 行為：丟棄未知 MAC 的封包。                                                              |
|    - 優點：違規計數器累加，即時發送 SNMP Trap 與 Syslog 告警，但埠維持開啟狀態。             |
|                                                                                               |
| 3. Shutdown (關閉模式 - 徹底阻絕【業界黃金標準】)                                              |
|    - 行為：立即將介面狀態置於 err-disable (Down) 狀態。                                       |
|    - 優點：徹底斷開實體連線，實體埠燈號變為橘色/關閉，必須手動排查或等待計時器復原。          |
+-----------------------------------------------------------------------------------------------+
```

### 模式特性決策矩陣

| 違規模式 | 封包轉發狀態 | 違規計數器 (Counter) | Syslog / SNMP Trap | 連接埠實體狀態 |
| :--- | :---: | :---: | :---: | :---: |
| **`protect`** | 丟棄未授權封包 | 不增加 | 否 | Up |
| **`restrict`** | 丟棄未授權封包 | 增加 | 是 | Up |
| **`shutdown`** | 徹底關閉介面 | 增加 | 是 | **Down (err-disable)** |

## 第二動：交換機配置與攻擊模擬實務 (Switch Configuration & Attack Emulation)

### 1. Cisco 交換機安全配置標準命令 (CLI)
在接入層交換機介面上啟用黏滯 MAC（Sticky MAC）與 Shutdown 模式：
```text
Switch# configure terminal
Switch(config)# interface GigabitEthernet0/1
Switch(config-if)# switchport mode access
Switch(config-if)# switchport access vlan 10
Switch(config-if)# switchport port-security
Switch(config-if)# switchport port-security maximum 1
Switch(config-if)# switchport port-security mac-address sticky
Switch(config-if)# switchport port-security violation shutdown
Switch(config-if)# end
```

### 2. MAC 泛洪攻擊模擬 (使用 macof 測試工具)
在紅隊或測試端點上發動泛洪攻擊以驗證防護效果：
```bash
# 使用 dsniff 工具包中的 macof 以每秒數千個隨機來源 MAC 進行泛洪
sudo macof -i eth0 -n 100
```
- 交換機在接收到第 2 個非認可 MAC 時，應在幾毫秒內將 `Gi0/1` 轉入 `err-disable`。

## 第三動：交換機遙測與日誌審計配置 (Telemetry Setup: Syslog & SNMP)

### 1. 配置交換機轉發 Syslog 至 SOC 日誌伺服器
```text
Switch(config)# logging host 10.99.1.50 transport udp port 514
Switch(config)# logging trap warnings
Switch(config)# logging source-interface Loopback0
```

### 2. 關鍵 Syslog 告警訊息解讀
- **`%PM-4-ERR_DISABLE: psecure-violation error detected on Gi0/1, putting Gi0/1 in err-disable state`**
  - 代表該連接埠偵測到 Port-Security 違規，已強制進入保護性關閉狀態。
- **`%PORT_SECURITY-2-PSECURE_VIOLATION: Security violation occurred, caused by MAC 0050.7966.6800 on port GigabitEthernet0/1`**
  - 精確記錄引發違規之非法硬體 MAC 地址。

## 第四動：SIEM 關聯規則與即時獵捕分析 (Splunk & Sigma Rules)

### 1. Splunk SPL：偵測交換機連接埠觸發 err-disable 事件
```spl
index=network_syslog sourcetype="cisco:ios" "%PM-4-ERR_DISABLE" "psecure-violation"
| rex field=_raw "detected on (?<Interface>\S+), putting \S+ in err-disable"
| rex field=_raw "caused by MAC (?<ViolatingMAC>[a-fA-F0-9\.]+)"
| stats count earliest(_time) as first_seen latest(_time) as last_seen by host, Interface, ViolatingMAC
| convert ctime(first_seen) ctime(last_seen)
| table first_seen, last_seen, host, Interface, ViolatingMAC, count
```

### 2. Splunk SPL：偵測短時間內跨多台交換機出現相同 MAC 違規 (Rogue Device Moving)
```spl
index=network_syslog sourcetype="cisco:ios" "psecure-violation"
| stats dc(host) as SwitchCount, values(host) as Switches by ViolatingMAC
| where SwitchCount >= 2
| table ViolatingMAC, SwitchCount, Switches
```

### 3. Sigma 偵測規則：Cisco Switch Port Security Violation Shutdown
```yaml
title: Cisco Switch Port Security Violation
id: 4a2b1090-33de-4122-8921-99881122aaff
status: production
description: 偵測網路接入層交換機觸發 Port-Security 違規並轉入 err-disable 狀態
logsource:
    category: network_os
    product: cisco
detection:
    selection:
        message|contains:
            - '%PM-4-ERR_DISABLE'
            - 'psecure-violation'
    condition: selection
level: high
```

## 第五動：err-disable 調試、自動復原與安全加固 (Diagnostics & Recovery)

```
[交換機介面進入 err-disable]
              │
              ├── 1. 排查實體端點：確認是否有未授權 Hub 或惡意網卡
              ├── 2. 登入 CLI：show interface status err-disable
              ▼
 ┌─────────────────────────────────────────────────────────────┐
 │ 復原方式選擇                                                │
 │                                                             │
 │ A. 手動重設 (排查完成後)：                                  │
 │    interface Gi0/1 ➔ shutdown ➔ no shutdown                 │
 │                                                             │
 │ B. 自動化逾時復原 (Auto-Recovery)：                         │
 │    errdisable recovery cause psecure-violation              │
 │    errdisable recovery interval 300 (等待 300 秒自動重試)    │
 └─────────────────────────────────────────────────────────────┘
```

### 1. 檢驗連接埠狀態與違規 MAC 記錄 (Cisco CLI)
```text
# 查詢全機處於 err-disable 的連接埠與成因
Switch# show interfaces status err-disable

# 查詢特定介面之詳細 Port-Security 運行統計
Switch# show port-security interface GigabitEthernet0/1
```
- 觀察 `Port Status: Secure-shutdown`
- 觀察 `Last Source Address: 0050.7966.6800`

### 2. 配置安全自動復原計時器 (Errdisable Recovery)
避免網路管理員手動重啟的繁重負擔，同時確保違規存在時持續閉鎖：
```text
Switch(config)# errdisable recovery cause psecure-violation
Switch(config)# errdisable recovery interval 300
```
- 若 300 秒後非法設備已被移除，連接埠將自動恢復正常；若非法設備仍插在上面，則會再次觸發違規並重置 300 秒閉鎖。

## 靶場實戰：私接路由器引發 err-disable 調查與復原

### 靶場環境情境
- **核心接入交換機**: `SW-FLOOR-03`
- **辦公網孔**: `Gi0/15` (原綁定財務部經理電腦 MAC: `0011.2233.4455`)
- **突發事件**: 該網孔網路突然中斷，實體燈號熄滅，經理通報無法連線內部 ERP。

### 實戰步驟一：調閱日誌研判
1. 查詢 Syslog 伺服器，發現 5 分鐘前記錄：
   `%PM-4-ERR_DISABLE: psecure-violation error detected on Gi0/15`
   `Security violation occurred, caused by MAC a42b.b0c1.99aa`
2. 比對 MAC OUI，發現 `a42b.b0` 屬於 TP-Link 路由器，確認有私接未經核准的 WiFi AP。

### 實戰步驟二：現場排查與阻斷
1. 實體走訪現場，發現員工為了給手機連 WiFi，將桌上型小型 AP 插入牆面網孔。
2. 拔除該私接路由器，重新接回原合法筆記型電腦。

### 實戰步驟三：介面復原與驗證
1. 登入交換機手動解除閉鎖：
   ```text
   SW-FLOOR-03# conf t
   SW-FLOOR-03(config)# interface Gi0/15
   SW-FLOOR-03(config-if)# shutdown
   SW-FLOOR-03(config-if)# no shutdown
   ```
2. 驗證介面狀態恢復為 `connected`，違規計數器歸零。

## 過關驗收：實戰能力檢核清單 (Mastery Checklist)

- [ ] **模式差異**：能精準區分 `protect`, `restrict`, `shutdown` 三種模式在封包處理、計數器累加與 SNMP 告警上的行為差異。
- [ ] **威脅防範**：能深入說明 MAC Flooding 攻擊對交換機 CAM 表的破壞力，以及 Port-Security 如何終結 Hub 降級風險。
- [ ] **命令熟練**：能在 Cisco 交換機上獨立配置 `maximum`, `sticky` 與 `violation shutdown` 等安全命令。
- [ ] **排錯與復原**：熟練掌握 `show interfaces status err-disable` 調試指令，並能配置 `errdisable recovery interval` 機制。
- [ ] **日誌關聯分析**：能撰寫 SIEM 規則即時捕捉 `%PM-4-ERR_DISABLE` 告警，並提取違規來源 MAC 實體地址。
