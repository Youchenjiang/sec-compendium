# 實戰手冊 08.2：Wi-Fi WPA3 SAE (Dragonfly) 密鑰交換防禦與 KRACK 重裝攻擊獵捕

## 案發現場破題

無線網路傳統 WPA2-PSK 協議天生存在握手離線碰撞風險與著名的 KRACK（Key Reinstallation Attack，金鑰重裝攻擊，CVE-2017-13077）漏洞。攻擊者透過中間人劫持或重送 EAPOL Message 3，誘使用戶端重置 Nonce 與重送計數器，進而將密鑰流歸零解密通訊封包。

為了徹底解決離線字典攻擊與 Forward Secrecy 問題，IEEE 802.11az / Wi-Fi Alliance 推出 WPA3-Personal，採用 SAE（Simultaneous Authentication of Equals，基於 Dragonfly 握手協議）對等實體身分驗證。然而在企業升級至 WPA3 的過渡期中，過渡模式（Transition Mode）的降級攻擊以及 Dragonfly 協議本身的側信道外洩（Dragonblood，CVE-2019-9494 等）成為紅隊入侵企業無線內網的新興跳板。身為 SOC 與無線安全防禦人員，必須深入掌握 SAE 交換邏輯、Dragonblood 漏洞緩解與 KRACK 告警特徵。

```
WPA2 vs WPA3 握手架構與防禦演進：

[WPA2-PSK 四向握手 (脆弱點)]
Station <====== EAPOL M1/M2/M3/M4 ======> AP (Authenticator)
  - 易受離線暴力破解攻擊 (PMK = PBKDF2(passphrase))
  - KRACK 攻擊：重放 M3 -> 迫使 Station 重裝 PTK -> Nonce 重置為 0

[WPA3-SAE Dragonfly 握手 (零知識證明 + 前向保密)]
Station <--- Commit (Scalar + Element) ---> AP
Station <--- Confirm (SEND-CONFIRM)   ---> AP
  - 基於 RFC 7664 / 橢圓曲線 ECC (Brainpool / NIST curves)
  - 密碼本身不直接參與衍生金鑰，防止離線字典暴力枚舉
  - 內建反重放防護與 PFS，每次連線產生獨立 Ephemeral Key
```

## 第一動：無線安全核心架構與威脅機理

### 1.1 KRACK（Key Reinstallation Attack）漏洞機理
在 802.11i 協議中，當 Client 接收到 AP 發送的 EAPOL Message 3 時，會安裝 PTK（Pairwise Transient Key）並重置封包重送計數器（RSC）與發送計數器（TSC）。
如果攻擊者在 Message 4 發出後，攔截並人為重放 Message 3：
- Client 會再次重新安裝完全相同的加密密鑰（PTK）。
- Client 的封包發送計數器 Nonce 被強制重置為初始值（0 或 1）。
- 導致加密密碼流（Keystream）重複使用，攻擊者利用異或（XOR）運算可直接還原明文內容或進行封包偽造注入。

### 1.2 WPA3-SAE (Dragonfly) 協議交互流程
SAE 握手建立於零知識證明協議基礎上，包含兩個階段：
1. **Commit 階段**：雙方利用預共享密碼衍生出基線點 PWE（Password Element），並各自生成隨機私鑰與純量（Scalar），向對方公開純量與橢圓曲線點元素。
2. **Confirm 階段**：雙方驗證對方的 Commit 元素並計算得出對稱的主密鑰 PMK（Pairwise Master Key），接著發送 Confirm 交換確認驗證碼。成功後再接續標準 4-Way Handshake 產生實際通訊用的 PTK。

### 1.3 Dragonblood 攻擊面分析
- **過渡模式降級攻擊（Transition Mode Downgrade）**：AP 同時啟用 WPA2/WPA3 過渡模式時，惡意 Rogue AP 發送 Beacon 偽造僅支援 WPA2，誘騙設備降級至 WPA2-PSK 實施字典枚舉。
- **側信道時序攻擊（Timing / Cache Side-Channel）**：SAE 在生成 PWE 過程中若使用「Hash-to-Curve」循環搜尋演算法，其計算耗時與迴圈次數取決於密碼字符，攻擊者測量回應微秒級延遲即可逐步還原密碼字符。

## 第二動：封包特徵與日誌軌跡定位

### 2.1 KRACK 封包特徵與 Wireshark 檢索式
- 異常的 EAPOL-Key 重送頻率：短期內收到多個相同 Key Replay Counter 或 Re-transmitted Message 3。
- 檢索式：
```wireshark
# 篩選重傳之 EAPOL Message 3
wlan.fc.type_subtype == 0x0028 && eapol.keydes.type == 2 && eapol.keydes.msgnr == 3

# 檢測重複使用 Key Replay Counter
wlan.analysis.retransmission && eapol
```

### 2.2 WPA3-SAE 封包特徵定位
- Authentication 幀的驗證演算法代號由 Open System (0) 或 Shared Key (1) 變更為 SAE (3)。
- 檢索式：
```wireshark
# 篩選 SAE 驗證幀 (Commit 與 Confirm)
wlan.fc.type_subtype == 0x000b && wlan.fixed.auth_alg == 3

# 檢視 SAE Authentication 序號 (1=Commit, 2=Confirm)
wlan.fixed.auth_seq == 1 || wlan.fixed.auth_seq == 2
```

## 第三動：手動獵捕與鑑識分析（tshark & Python）

### 3.1 使用 tshark 快速提取 SAE 與 EAPOL 異常
```bash
# 統計環境中是否仍有 WPA2 4-Way Handshake 甚至 KRACK 重傳
tshark -r wireless_capture.pcap -Y "wlan.fc.type_subtype == 0x000b && wlan.fixed.auth_alg == 3" \
  -T fields -e frame.time -e wlan.ta -e wlan.ra -e wlan.fixed.auth_seq

# 檢查是否有未加密或重複 Nonce 之重送數據封包
tshark -r wireless_capture.pcap -Y "wlan.fc.type == 2 && wlan.analysis.retransmission" \
  -T fields -e wlan.sa -e wlan.da -e wlan.seq
```

### 3.2 Python 腳本檢測 WPA3 側信道計時異常與 KRACK 徵兆
```python
import pyshark
import collections

def audit_wpa3_krack(pcap_file):
    cap = pyshark.FileCapture(pcap_file, display_filter="eapol || (wlan.fc.type_subtype == 0x000b)")
    eapol_m3_tracker = collections.defaultdict(list)
    sae_auth_count = collections.defaultdict(int)

    for pkt in cap:
        try:
            # 檢測 KRACK 症狀：相同 Client 短時間內收到異常 M3 重送
            if hasattr(pkt, 'eapol') and hasattr(pkt.eapol, 'keydes_msgnr'):
                if pkt.eapol.keydes_msgnr == '3':
                    client_mac = pkt.wlan.ra
                    eapol_m3_tracker[client_mac].append(float(pkt.sniff_timestamp))

            # 統計 SAE 驗證爆破或異常提交
            if hasattr(pkt.wlan, 'fixed') and hasattr(pkt.wlan.fixed, 'auth_alg'):
                if pkt.wlan.fixed.auth_alg == '3':
                    client_mac = pkt.wlan.ta
                    sae_auth_count[client_mac] += 1
        except AttributeError:
            continue

    print("=== KRACK 疑似攻擊檢測 ===")
    for client, timestamps in eapol_m3_tracker.items():
        if len(timestamps) > 3:
            print(f"[ALERT] Client {client} 收到 {len(timestamps)} 次 M3 重送，可能遭受 KRACK 金鑰重裝攻擊！")

    print("\n=== WPA3-SAE 握手統計 ===")
    for client, count in sae_auth_count.items():
        print(f"Station {client} 發送 SAE 交互幀共 {count} 次")

if __name__ == '__main__':
    audit_wpa3_krack("test_wpa3.pcap")
```

## 第五動：企業級防禦硬化與應急響應阻斷

### 5.1 全面啟用 802.11w 保護管理幀（Protected Management Frames, PMF）
- WPA3 強制要求必須啟用 PMF（Capable 或 Required）。PMF 對 Deauth / Disassoc 等控制管理幀進行 AES-CMAC 簽名，杜絕假冒 AP 發送斷網重連發動握手捕獲攻擊。
- Cisco Catalyst WLC CLI 加固範例：
```text
(Cisco Controller) > config wlan security pmf mandatory 1
(Cisco Controller) > config wlan security wpa wpa3 sae enable 1
(Cisco Controller) > config wlan security wpa wpa2 disable 1
```

### 5.2 關閉 Transition Mode（過渡模式）實施純 WPA3-Enterprise
- 淘汰過渡模式，避免紅隊發動 Beacon 降級欺騙。針對訪客網路或專屬終端改用 802.1X EAP-TLS 數位憑證認證，徹底終結 PSK 暴力破解風險。

### 5.3 防範 Dragonblood 側信道補丁驗證
- 確認所有 AP 韌體支援 Hash-to-Curve 演算法的常數時間實作（Constant-Time Processing），更新 hostapd 至 2.8 以上版本修復 CVE-2019-9494。

## 靶場實戰：分析 KRACK 封包與驗收 WPA3 加固

### 模擬情境
本實驗在離線靶場環境重現 WPA2 KRACK 攻擊封包並升級至 WPA3 SAE 進行配置檢驗：
1. 載入靶場提供的 `krack_attack_simulation.pcap`。
2. 驗證 Client 接收到 4 次重傳之 EAPOL M3 且後續發送之數據幀其 WEP/CCMP 序號異常歸零。
3. 在 Hostapd 模擬環境中配置純 WPA3-SAE 與 PMF 阻斷管理幀欺騙。

```bash
# 步驟 1：檢驗 Capture 檔案內之重送計數
tshark -r krack_attack_simulation.pcap -Y "eapol" -T fields \
  -e frame.number -e eapol.keydes.msgnr -e eapol.keydes.replay_counter

# 步驟 2：配置 Hostapd WPA3 純淨模式 (hostapd.conf)
cat << 'EOF' > /tmp/wpa3_secure_hostapd.conf
interface=wlan0
ssid=CORP_SECURE_WPA3
hw_mode=g
channel=7
wpa=2
wpa_key_mgmt=SAE
rsn_pairwise=CCMP
ieee80211w=2
sae_pwe=1
wpa_passphrase=HighlyComplexEnterpriseWPA3Key!
EOF
```
