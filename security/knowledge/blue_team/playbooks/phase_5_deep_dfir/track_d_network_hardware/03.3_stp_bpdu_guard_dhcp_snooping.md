# 03.3 生成樹協定安全 (STP BPDU Guard) 與 DHCP Snooping / DAI 聯防 (STP Protection & Layer 2 Defense)

## 案發現場破題

在企業內部區域網路中，廣播風暴（Broadcast Storm）與中間人攔截（MitM）往往源自於二層（Layer 2）協定的先天信任缺陷。攻擊者將自帶的非法交換機或運行了 Scapy / Yersinia 的攻擊筆電接入一般接入埠（Access Port），發送優先級更高的 **偽造 BPDU（Bridge Protocol Data Unit）**，即可強行爭奪為全網的 **根橋（Root Bridge）**，迫使全網交換機重新計算生成樹拓撲，將整個資料中心的流量全數重定向繞經黑客主機。與此同時，若缺乏 DHCP Snooping，攻擊者還能架設 **惡意 DHCP 伺服器（Rogue DHCP Server）**，隨機派發偽造的 Gateway 與 DNS，於數秒內癱瘓或全量側聽整個部門的網路通訊。

```
[攻擊者主機 (運行 Yersinia 發送 Priority 0 偽造 BPDU)]
       │
       ▼ (接入未配置防護的一般員工網孔 Gi0/5)
+-------------------------------------------------------------------------------+
| 接入層交換機 (Access Switch)                                                  |
|  - 接收到 Priority 0 的 BPDU ➔ 認為對方是全網最高特權交換機！                 |
|  - 觸發生成樹拓撲變更 (Topology Change Notification, TCN)                     |
+-------------------------------------------------------------------------------+
       │
       ▼ (根橋角色被黑客奪走，全網流量被牽引進行中間人監聽)
+-------------------------------------------------------------------------------+
| 【Layer 2 鋼鐵防線：BPDU Guard & Root Guard & DHCP Snooping】                |
|  1. BPDU Guard: 接入埠只要收到 BPDU 立即將介面置於 err-disable 閉鎖！        |
|  2. Root Guard: 嚴禁特定埠成為根埠 (Root Port)                                |
|  3. DHCP Snooping: 僅信任上聯 Trunk 埠派發 IP，阻斷未授權 DHCP Offer          |
|  4. DAI (Dynamic ARP Inspection): 比對 Snooping Binding 表，封殺 ARP 欺騙     |
+-------------------------------------------------------------------------------+
```

### 痛點場景
- **生成樹拓撲震盪（STP Flapping）**：未設防的交換機在收到惡意 BPDU 後頻繁重新收斂，導致全網轉發暫停 30 到 50 秒，企業關鍵服務瞬間雪崩。
- **惡意 DHCP 派發無從查起**：內網出現兩台 DHCP 伺服器搶答，員工電腦隨機拿到錯誤的網關 IP，傳統網路設備無日誌記錄是哪台主機在冒充伺服器。
- **ARP 欺騙橫向監聽**：只要攻擊者發送偽造的 ARP Reply，交換機便照單全收更新主機 ARP 表，使微隔離形同虛設。

## 第一動：二層防禦四劍客底層技術矩陣 (L2 Defense Triad & DAI Architecture)

```
+-----------------------------------------------------------------------------------------------+
| 二層安全聯防體系 (L2 Security Architecture)                                                   |
|                                                                                               |
| 1. STP BPDU Guard                                                                             |
|    - 部署位置：所有終端接入埠 (Edge / PortFast Ports)。                                       |
|    - 防禦機制：接入埠絕不該收到 BPDU！一旦收到立即關閉該埠 (err-disable)，斬斷非法交換機接入。 |
|                                                                                               |
| 2. STP Root Guard                                                                             |
|    - 部署位置：連接次級交換機的下聯 Trunk 埠。                                                |
|    - 防禦機制：若對端發送優於現有根橋的 BPDU，強制將該介面置於 root-inconsistent 狀態阻斷轉發。|
|                                                                                               |
| 3. DHCP Snooping (動態主機配置監聽)                                                          |
|    - 部署位置：全局啟用，將上聯伺服器埠設為 Trusted，其餘所有接入埠預設為 Untrusted。         |
|    - 防禦機制：Untrusted 埠若傳入 DHCP Offer / ACK 封包直接丟棄，並動態建立 IP-MAC-Port 繫結表|
|                                                                                               |
| 4. DAI (Dynamic ARP Inspection 動態 ARP 檢驗)                                                 |
|    - 部署位置：全網依賴 DHCP Snooping 繫結表。                                                |
|    - 防禦機制：硬體逐一比對每個 ARP 封包之 IP 與 MAC 是否存在於繫結表中，直接封殺 ARP 欺騙。  |
+-----------------------------------------------------------------------------------------------+
```

## 第二動：交換機全套二層加固配置命令實務 (Cisco IOS Hardening)

### 1. 接入埠啟用 PortFast 與 BPDU Guard
```text
Switch(config)# interface range GigabitEthernet0/1 - 24
Switch(config-if-range)# switchport mode access
Switch(config-if-range)# spanning-tree portfast
Switch(config-if-range)# spanning-tree bpduguard enable
```

### 2. 啟用 DHCP Snooping 與信任連接埠配置
```text
# 全域啟用 DHCP Snooping 並套用至特定 VLAN
Switch(config)# ip dhcp snooping
Switch(config)# ip dhcp snooping vlan 10,20,30

# 將通往合法 DHCP 伺服器的上聯 Trunk 埠設為信任埠 (Trusted)
Switch(config)# interface GigabitEthernet0/24
Switch(config-if)# ip dhcp snooping trust

# 限制非信任接入埠的 DHCP 請求速率 (防範 DHCP 飢餓耗盡攻擊)
Switch(config)# interface range GigabitEthernet0/1 - 23
Switch(config-if-range)# ip dhcp snooping limit rate 15
```

### 3. 啟用動態 ARP 檢驗 (Dynamic ARP Inspection, DAI)
```text
Switch(config)# ip arp inspection vlan 10,20,30
# 對信任的上聯埠免除 DAI 檢查
Switch(config)# interface GigabitEthernet0/24
Switch(config-if)# ip arp inspection trust
```

## 第三動：交換機遙測與二層違規日誌審計 (Telemetry Setup)

### 1. 啟用 DAI 與 DHCP Snooping 日誌緩衝與 Syslog 轉發
```text
Switch(config)# ip arp inspection log-buffer entries 1024
Switch(config)# ip arp inspection log-buffer logs 50 interval 10
```

### 2. 核心違規日誌解讀
- **`%SPANTREE-2-BLOCK_BPDUGUARD: Received BPDU on port Gi0/5 with BPDU Guard enabled. Disabling port.`**
  - 代表接入埠收到非法 BPDU，已自動閉鎖該連接埠防止拓撲搶奪。
- **`%DHCP_SNOOPING-5-DHCP_SNOOPING_UNTRUSTED_PORT: DHCP_SNOOPING drop message on untrusted port Gi0/8`**
  - 接入埠出現未授權的 DHCP 伺服器回應用答。
- **`%SW_DAI-4-DHCP_SNOOPING_DENY: 1 Invalid ARPs (Req) on Gi0/2, vlan 10. ([0011.2233.4455/10.10.10.50/0000.0000.0000/10.10.10.1])`**
  - 偵測到與 DHCP Snooping 繫結表不相符的偽造 ARP 欺騙封包。

## 第四動：SIEM 關聯規則與即時獵捕分析 (Splunk & Sigma Rules)

### 1. Splunk SPL：偵測內網未授權 DHCP 伺服器活動 (Rogue DHCP Alert)
```spl
index=network_syslog sourcetype="cisco:ios" "%DHCP_SNOOPING_UNTRUSTED_PORT"
| rex field=_raw "drop message on untrusted port (?<ViolatingPort>\S+), mac address (?<AttackerMAC>[a-fA-F0-9\.]+)"
| stats count earliest(_time) as first_seen latest(_time) as last_seen by host, ViolatingPort, AttackerMAC
| convert ctime(first_seen) ctime(last_seen)
| table first_seen, last_seen, host, ViolatingPort, AttackerMAC, count
```

### 2. Splunk SPL：偵測 DAI 攔截之大規模 ARP 欺騙攻擊 (ARP Poisoning Spikes)
```spl
index=network_syslog sourcetype="cisco:ios" "%SW_DAI-4-DHCP_SNOOPING_DENY"
| bin _time span=5m
| stats count as DroppedARPs by _time, host
| where DroppedARPs > 20
| table _time, host, DroppedARPs
```

### 3. Sigma 偵測規則：Cisco Switch BPDU Guard Violation Triggered
```yaml
title: Cisco Switch Port Blocked by BPDU Guard
id: 8b2c1145-9a02-4412-881a-4433221199aa
status: production
description: 偵測終端接入埠因接收到未授權 BPDU 觸發 BPDU Guard 閉鎖保護
logsource:
    category: network_os
    product: cisco
detection:
    selection:
        message|contains:
            - '%SPANTREE-2-BLOCK_BPDUGUARD'
    condition: selection
level: critical
```

## 第五動：二層實體排錯與攻擊隔離處置 (Containment & Hardening Verification)

```
[交換機記錄到 %SW_DAI 或 %DHCP_SNOOPING 告警]
              │
              ├── 1. 查詢 DHCP Snooping 繫結表 (show ip dhcp snooping binding)
              ├── 2. 定位違規來源 MAC 所在實體埠 (show mac address-table address <MAC>)
              ▼
 ┌─────────────────────────────────────────────────────────────┐
 │ 立即處置動作                                                │
 │  - 將涉案介面強制 shutdown                                  │
 │  - 通知資安鑑識人員前往實體網孔檢查是否插有未經許可之軟硬體設備│
 └─────────────────────────────────────────────────────────────┘
```

### 1. 檢視 DHCP Snooping 動態安全繫結表 (Binding Table)
```text
Switch# show ip dhcp snooping binding
MacAddress          IpAddress        Lease(sec)  Type           VLAN  Interface
------------------  ---------------  ----------  -------------  ----  --------------------
00:50:56:AB:CD:EF   10.10.10.15      86400       dhcp-snooping  10    GigabitEthernet0/1
```
- 所有通過合法 DHCP 分配的設備皆會被硬體記錄，無法造假。

### 2. 自動化清理靜態偽造 ARP 綁定
若發現存在靜態 IP 設備未透過 DHCP 獲派，可在交換機上配置靜態 ARP 存取控制清單（ARP Access-List）授權該設備，避免被 DAI 誤殺：
```text
Switch(config)# arp access-list STATIC-SERVERS
Switch(config-arp-nacl)# permit ip host 10.10.10.200 mac host 0050.56aa.bbcc
Switch(config)# ip arp inspection filter STATIC-SERVERS vlan 10
```

## 靶場實戰：非法交換機與 Rogue DHCP 雙重阻斷驗證

### 靶場環境情境
- **接入交換機**: `SW-CORE-01`
- **攻擊者節點**: 插入 `Gi0/4` (嘗試使用 Yersinia 爭奪根橋，並以 `dnsmasq` 架設流氓 DHCP)
- **防禦狀態**: `Gi0/4` 已啟用 `spanning-tree bpduguard enable` 與 DHCP Snooping。

### 實戰步驟一：根橋爭奪阻斷
1. 攻擊者啟動 Yersinia 發送 Priority 0 BPDU。
2. 5 毫秒內，交換機輸出：`%SPANTREE-2-BLOCK_BPDUGUARD: Received BPDU on port Gi0/4... putting Gi0/4 in err-disable state`。
3. 連接埠立即中斷，生成樹拓撲完全無震盪。

### 實戰步驟二：Rogue DHCP 攔截驗證
1. 經排查後將介面切換為僅啟用 DHCP Snooping 測試。
2. 攻擊者嘗試發送 DHCP Offer 封包，交換機直接丟棄並輸出：`%DHCP_SNOOPING-5-DHCP_SNOOPING_UNTRUSTED_PORT`。
3. 局域網其他主機完全未接收到偽造的網關與 DNS 資訊，防線固若金湯。

## 過關驗收：實戰能力檢核清單 (Mastery Checklist)

- [ ] **協定機制**：能透徹說明 BPDU Guard 與 Root Guard 在保護生成樹拓撲穩定性上的職責劃分與部署位置。
- [ ] **連鎖防禦邏輯**：能深入解釋為何 Dynamic ARP Inspection (DAI) 必須建立在 DHCP Snooping 繫結表的基礎上運行。
- [ ] **命令熟練**：能在 Cisco 交換機上正確配置 PortFast、BPDU Guard、DHCP Snooping Trust 與 DAI。
- [ ] **日誌解碼**：能由 Syslog 精準解讀 `%SPANTREE-2-BLOCK_BPDUGUARD`、`%DHCP_SNOOPING` 與 `%SW_DAI` 違規代碼。
- [ ] **例外處理**：掌握面對靜態 IP 伺服器時，編寫 `arp access-list` 避免被 DAI 誤殺的標準工程程序。
