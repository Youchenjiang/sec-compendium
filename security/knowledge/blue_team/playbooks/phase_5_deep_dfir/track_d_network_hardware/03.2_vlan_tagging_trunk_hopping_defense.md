# 03.2 IEEE 802.1Q VLAN 標籤結構與 Trunk 跳躍攻擊防護 (802.1Q Tagging & VLAN Hopping Defense)

## 案發現場破題

在企業區域網路中，虛擬區域網路（Virtual Local Area Network, VLAN）被廣泛用作邏輯隔離的基石。然而，許多網路工程師誤以為「劃分了 VLAN 就等於絕對隔離」。事實上，如果交換機的 Trunk 埠（中繼鏈路）或原生 VLAN（Native VLAN）配置疏漏，攻擊者僅憑一台普通工作站，即可發動 **VLAN 跳躍攻擊（VLAN Hopping）**——利用 **雙重標籤注入（Double Tagging）** 或 **動態中繼協定欺騙（DTP Spoofing）**，突破廣播域限制，將未授權的惡意封包跨網段走私進核心管理網段或隔離的財務伺服器。

```
[攻擊者主機 (位於 VLAN 10)]
       │
       ▼ (構造外層 VLAN 10 + 內層 VLAN 20 的雙重 802.1Q Tag 封包)
+-------------------------------------------------------------------------------+
| 接入交換機 (Switch 1)                                                         |
|  - 發現外層標籤 (VLAN 10) 與本機 Native VLAN 相同！                           |
|  - 依據 802.1Q 規範：剝除外層標籤 (Untag) 並沿 Trunk 鏈路轉發                 |
+-------------------------------------------------------------------------------+
       │
       ▼ (封包僅剩餘內層 VLAN 20 標籤，跨過 Trunk 抵達 Switch 2)
+-------------------------------------------------------------------------------+
| 對端交換機 (Switch 2)                                                         |
|  - 讀取封包標頭：發現 VLAN 20 標籤                                            |
|  - 直接將封包派送至 VLAN 20 實體埠 (完全繞過三層防火牆與路由器 ACL 審查！)     |
+-------------------------------------------------------------------------------+
       │
       ▼
[機敏 VLAN 20 伺服器接收到單向攻擊封包 (如 UDP 溢位 / 偽造 TCP RST)]
```

### 痛點場景
- **無感跨越 L2/L3 邊界**：傳統網路架構通常透過三層路由器或核心防火牆檢查跨 VLAN 流量。但雙重標籤跳躍完全發生在二層硬體轉發層，完全不經過網關，防火牆日誌一片死寂。
- **DTP 動態協商預設開啟**：許多 Cisco 交換機的預設交換機模式為 `dynamic auto` 或 `dynamic desirable`。攻擊者使用工具（如 `yersinia`）發送偽造的 DTP 封包，即可在幾秒內將一般接入埠「協商提升」為 Trunk 埠，監聽所有 VLAN 廣播流量。
- **預設 Native VLAN 1 泛濫**：全網交換機普遍維持出廠預設值 `VLAN 1` 作為 Native VLAN，給予雙重標籤跳躍攻擊現成的溫床。

## 第一動：IEEE 802.1Q 封包結構與跳躍攻擊原理 (802.1Q Frame & Attack Vectors)

標準乙太網路影格（Ethernet Frame）在插入 802.1Q 標籤後，會在來源 MAC 與 Type 欄位之間擴展 4 個位元組（4-Byte Tag）：

```
+-----------------------------------------------------------------------------------------------+
| IEEE 802.1Q 4-Byte VLAN Tag 欄位解析                                                          |
|                                                                                               |
|  [ TPID: 2 Bytes ] : 標籤協定識別碼，固定為 0x8100 (代表 802.1Q)                               |
|  [ TCI: 2 Bytes ]                                                                             |
|    ├─ PCP (3 bits) : 優先權代碼點 (Priority Code Point, 0-7, 用於 QoS)                        |
|    ├─ DEI (1 bit)  : 丟棄資格指示器 (Drop Eligible Indicator)                                  |
|    └─ VID (12 bits): VLAN 識別碼 (VLAN ID, 範圍 1 ~ 4094)                                     |
+-----------------------------------------------------------------------------------------------+
```

### VLAN 跳躍兩大核心攻擊戰術

| 攻擊戰術名稱 | 觸發前置條件 (Preconditions) | 攻擊運作機制與限制 (Mechanism & Limitations) |
| :--- | :--- | :--- |
| **DTP 欺騙 (Switch Spoofing)** | 連接埠配置為 `dynamic desirable` 或 `dynamic auto`。 | 偽造 DTP 封包誘騙交換機建立 Trunk 鏈路。成功後可**雙向**收發所有允許通行 VLAN 的流量。 |
| **雙重標籤 (Double Tagging)** | 攻擊者所在 VLAN 必須與 Trunk 鏈路的 **Native VLAN** 相同。 | 構造內外雙層 802.1Q 標籤。第一台交換機剝除外層後，第二台交換機按內層轉發。屬於**單向（Unidirectional）**攻擊。 |

## 第二動：攻擊模擬與封包構造實務 (Attack Emulation: Yersinia & Scapy)

### 1. DTP 協商欺騙模擬 (使用 Yersinia)
```bash
# 在 Linux 攻擊機上發起 DTP 主動協商，將連線埠提升為 Trunk
sudo yersinia dtp -interface eth0 -attack 0
```

### 2. Scapy 構造雙重 802.1Q 標籤跳躍封包 (Python)
```python
from scapy.all import *

# 構造雙重標籤封包：外層 VLAN 1 (Native VLAN)，內層 VLAN 20 (目標隔離區)
pkt = Ether(dst="00:11:22:33:44:55", src="00:aa:bb:cc:dd:ee") / \
      Dot1Q(vlan=1) / \
      Dot1Q(vlan=20) / \
      IP(src="10.10.10.5", dst="10.20.10.100") / \
      UDP(dport=53) / \
      DNS(rd=1, qd=DNSQR(qname="test.corp.local"))

sendp(pkt, iface="eth0", verbose=1)
print("[+] 雙重標籤 VLAN 跳躍封包發送完畢！")
```

## 第三動：網路遙測與異常流量抓取 (Telemetry Setup: SPAN & TShark)

### 1. Cisco 交換機配置 SPAN 連接埠鏡像監控
將 Trunk 鏈路的跨網段流量鏡像至 SOC 流量感測器：
```text
Switch(config)# monitor session 1 source interface GigabitEthernet0/24 both
Switch(config)# monitor session 1 destination interface GigabitEthernet0/10
```

### 2. TShark 捕捉雙重 802.1Q 標籤異常封包
在監控埠上運行過濾器，尋找封裝了兩個 0x8100 標籤的畸形影格：
```bash
# 抓取包含巢狀 802.1Q Tag 之封包
tshark -i eth1 -Y "vlan and vlan.etype == 0x8100" -T fields -e frame.number -e eth.src -e vlan.id
```

## 第四動：SIEM 關聯規則與即時獵捕分析 (Splunk & Suricata Rules)

### 1. Splunk SPL：偵測接入層交換機未預期的 Trunk 模式轉變 (DTP Trunking Event)
```spl
index=network_syslog sourcetype="cisco:ios" "%DTP-5-TRUNKPORTON"
| rex field=_raw "Interface (?<TrunkInterface>\S+) has become a trunk port"
| stats count earliest(_time) as first_time latest(_time) as last_time by host, TrunkInterface
| convert ctime(first_time) ctime(last_time)
| table first_time, last_time, host, TrunkInterface, count
```

### 2. Suricata 偵測規則：Nested 802.1Q Double Tagging Detected
```yaml
alert ip any any -> any any (
    msg:"SEC-NETWORK Potential 802.1Q Double VLAN Tagging Attack";
    flow:to_server;
    vlan.id:any;
    threshold: type limit, track by_src, count 1, seconds 60;
    classtype:bad-unknown;
    sid:2009121;
    rev:1;
)
```

### 3. Sigma 偵測規則：Cisco Switch Unexpected Dynamic Trunk Negotiation
```yaml
title: Unexpected DTP Trunk Port Up
id: 7c1a9021-44de-4122-8b9a-1122aa44bc11
status: production
description: 偵測非預期之接入埠轉變為 Trunk 狀態，符合 DTP 欺騙攻擊特徵
logsource:
    category: network_os
    product: cisco
detection:
    selection:
        message|contains:
            - '%DTP-5-TRUNKPORTON'
            - '%SPANTREE-2-RECV_PVID_ERR'
    condition: selection
level: high
```

## 第五動：VLAN 安全基線加固五大金科玉律 (Network Hardening Standards)

```
[接入埠 Access Ports]                                 [中繼埠 Trunk Ports]
  ├─ 1. 強制 switchport mode access                     ├─ 1. 強制關閉 DTP 協商 (switchport nonegotiate)
  ├─ 2. 徹底關閉 DTP (switchport nonegotiate)           ├─ 2. 修改 Native VLAN 為專屬黑洞 VLAN (例: 999)
  └─ 3. 停用未使用的空置連接埠 (shutdown)               └─ 3. 嚴格限制允許通行清單 (switchport trunk allowed vlan)
                                                                 │
                                                                 ▼
                                                  [全網啟用 802.1Q Tag Native]
```

### 1. 關閉所有接入埠的 DTP 動態協商
嚴禁交換機介面自主決定是否成為 Trunk：
```text
Switch(config-if)# switchport mode access
Switch(config-if)# switchport nonegotiate
```

### 2. 修改 Trunk 鏈路的 Native VLAN 為未使用的專用黑洞 VLAN
切勿將 Native VLAN 設為任何使用者所在的 VLAN（尤其是 VLAN 1）：
```text
Switch(config-if)# switchport trunk encapsulation dot1q
Switch(config-if)# switchport mode trunk
Switch(config-if)# switchport trunk native vlan 999
Switch(config-if)# switchport trunk allowed vlan 10,20,30
Switch(config-if)# switchport nonegotiate
```

### 3. 全域強制對 Native VLAN 進行標籤化 (Tag Native VLAN)
徹底消滅雙重標籤跳躍的前提——強制交換機對 Native VLAN 也打上 802.1Q 標籤，不執行 Untag：
```text
Switch(config)# vlan dot1q tag native
```

## 靶場實戰：雙重標籤跳躍封包攔截演練

### 靶場環境情境
- **測試拓撲**: `SW1` (Access: VLAN 10) ➔ 802.1Q Trunk ➔ `SW2` (Target: VLAN 20)
- **初始漏洞配置**: `SW1` 與 `SW2` 之間 Trunk 的 Native VLAN 仍為預設的 `VLAN 1`，且攻擊者剛好獲派 `VLAN 1` IP。

### 實戰步驟一：攻擊者注入跳躍封包
1. 攻擊者在 VLAN 1 工作站執行 Scapy 腳本，封裝外層 `VLAN 1` 與內層 `VLAN 20` 的 UDP 封包發往目標財務伺服器 `10.20.10.50`。
2. `SW1` 接收後剝除 `VLAN 1` 標籤，將帶有 `VLAN 20` 的封包轉交 `SW2`，`SW2` 直接派發至財務伺服器。

### 實戰步驟二：SOC 偵測與審計
1. 監控感測器觸發 Suricata 警報：`SEC-NETWORK Potential 802.1Q Double VLAN Tagging Attack`。
2. 交換機 Syslog 記錄到跨 Native VLAN 不一致告警：`%SPANTREE-2-RECV_PVID_ERR`。

### 實戰步驟三：防禦加固
1. 在 `SW1` 與 `SW2` 全域執行 `vlan dot1q tag native`。
2. 將兩端 Trunk 的 Native VLAN 統一變更為空置的 `VLAN 999`。
3. 再次發送雙重標籤封包，確認封包在 `SW1` 出口被強制標註雙層標籤，抵達 `SW2` 後因外層仍為 999 而無法匹配，直接被硬體拋棄！

## 過關驗收：實戰能力檢核清單 (Mastery Checklist)

- [ ] **802.1Q 結構**：能精準背誦 802.1Q 4 位元組標籤結構（TPID 0x8100, PCP 3 bits, DEI 1 bit, VID 12 bits）。
- [ ] **雙重標籤成因**：能清楚解釋為何雙重標籤攻擊「必須依賴外層標籤與 Trunk 的 Native VLAN 一致」才能成功觸發。
- [ ] **DTP 威脅防禦**：能熟練在交換機介面配置 `switchport nonegotiate` 與 `switchport mode access` 徹底封殺交換機欺騙。
- [ ] **加固黃金準則**：能在生產交換機落實「修改專屬 Native VLAN」、「限制 Allowed VLAN」與「`vlan dot1q tag native`」三大基線。
- [ ] **封包分析識別**：能使用 Wireshark / TShark 快速過濾出含有巢狀 802.1Q 標籤的未授權二層流量。
