# 07.1 SNMP 版本演進與 authPriv 安全等級加固 (SNMPv3 Architecture & authPriv Hardening)

## 案發現場破題

在企業網路與 IT 維運監控體系中，簡單網路管理協定（Simple Network Management Protocol, SNMP）是網管伺服器（NMS, 如 Zabbix, PRTG, SolarWinds）採集交換機、路由器、防火牆與主機 CPU、記憶體與流量資訊的核心標準。然而，許多網路環境至今仍沿用 1990 年代設計的 **SNMPv1 / SNMPv2c**。這些早期版本採用**完全明文的「社群字串（Community String）」**作為認證憑證，且多數設備出廠預設為極易猜測的 `public`（唯讀）與 `private`（讀寫）。攻擊者僅憑一次被動流量側聽或 UDP 161 埠掃描，即可取得交換機完全配置、甚至透過 SNMP SET 直接竄改靜態路由與 VLAN 劃分。

```
[攻擊者主機 (使用 snmpwalk 探測 UDP 161)]
       │
       ▼ (發送明文 Community String: "public")
+-------------------------------------------------------------------------------+
| 傳統未設防網路設備 (SNMPv1 / SNMPv2c)                                          |
|  - 明文傳輸：社群字串無任何加密或雜湊保護                                     |
|  - 資訊裸奔：吐出全網路由表、ARP 快取、介面流量、甚至管理員帳號清單           |
+-------------------------------------------------------------------------------+
       │
       ▼ 【SNMPv3 安全升級：authPriv 最高安全等級】
+-------------------------------------------------------------------------------+
| SNMPv3 實體設備 (USM 使用者安全模型 + VACM 檢視存取控制)                      |
|  - 身分驗證 (auth): SHA-256 HMAC 雜湊認證 (防竄改與重放攻擊)                   |
|  - 訊息加密 (priv): AES-128 / AES-256 對稱加密 (防竊聽)                        |
|  - 檢視授權 (View): 僅允許特定網管使用者讀取特定 MIB 樹分支                    |
+-------------------------------------------------------------------------------+
       │
       ▼ (非授權探測直接被硬體拋棄，觸發 usmStatsNotInTimeWindows 告警)
[安全防護全面落地，杜絕內網監聽與配置篡改]
```

### 痛點場景
- **明文社群字串滿天飛**：SNMPv1/v2c 在網路上以 UDP 封包明文傳遞 `public`/`private`，任何位於同一交換機廣播域或具備 SPAN 埠的攻擊者，開啟 Wireshark 即可一秒捕獲認證密鑰。
- **SNMP 寫入特權（Write Access）致命濫用**：若 `private` 寫入權限開放，攻擊者可透過 OID 樹直接觸發設備重啟、下載遠端 TFTP 惡意設定檔或變更開機映象檔。
- **SNMP 反射放大 DDoS 攻擊**：由於 SNMP 運行於無連線導向的 UDP 161 埠，攻擊者偽造受害者來源 IP 發送 `GetBulkRequest`，可用極小頻寬誘發數十倍的放大流量回擊受害者。

## 第一動：SNMPv1/v2c/v3 演進架構與安全等級矩陣 (SNMP Security Levels)

```
+-----------------------------------------------------------------------------------------------+
| SNMPv3 三大安全等級對比 (Security Levels)                                                     |
|                                                                                               |
| 1. noAuthNoPriv (無認證無加密)                                                                |
|    - 認證機制：僅匹配 Username (不驗證密碼)。                                                 |
|    - 傳輸狀態：明文傳輸，安全性等同於 SNMPv1/v2c，嚴禁於生產環境使用。                         |
|                                                                                               |
| 2. authNoPriv (有認證無加密)                                                                  |
|    - 認證機制：使用 MD5 或 SHA 雜湊進行 HMAC 挑戰回應認證。                                  |
|    - 傳輸狀態：封包酬載（Payload）依然為明文，防竄改但無法防側聽。                            |
|                                                                                               |
| 3. authPriv (有認證有加密【業界黃金標準】)                                                    |
|    - 認證機制：強制採用 SHA-256 / SHA-512 HMAC 身分驗證。                                     |
|    - 傳輸狀態：使用 AES-128 / AES-256 徹底加密整個 PDU 酬載，提供完整的機密性、完整性與時效性。 |
+-----------------------------------------------------------------------------------------------+
```

### SNMP 協定版本特性完整對照表

| 協定版本 | 認證方式 (Authentication) | 加密保護 (Encryption) | 存取控制顆粒度 | 抵禦中間人能力 |
| :--- | :--- | :--- | :--- | :--- |
| **SNMPv1** | 明文社群字串 (Community) | 無 (完全明文) | 粗糙 (全域 RO / RW) | 零 (極易被側聽與偽造) |
| **SNMPv2c**| 明文社群字串 (支援 GetBulk) | 無 (完全明文) | 粗糙 (全域 RO / RW) | 零 (仍為明文 UDP 傳輸) |
| **SNMPv3** | USM 模組 (HMAC-SHA 認證) | USM 模組 (AES-128/256) | 精細 (VACM 檢視顆粒度) | 高 (具備抗重放與抗竊聽防護) |

## 第二動：SNMP 滲透探測模擬與 Cisco 加固實務 (Toolchain Practice)

### 1. 使用 snmpwalk 探測遺留的 SNMPv2c 明文設備
```bash
# 對目標交換機以 public 弱社群字串枚舉系統 MIB 資訊
snmpwalk -v 2c -c public 10.10.10.1 1.3.6.1.2.1.1

# 枚舉內網所有活動 IP 與對應 MAC 映射 (ARP Cache MIB)
snmpwalk -v 2c -c public 10.10.10.1 1.3.6.1.2.1.4.22
```

### 2. Cisco IOS 部署 SNMPv3 authPriv 標準命令
在交換機上建立安全檢視（View）、群組（Group）與專屬網管使用者：
```text
# 1. 建立僅能存取特定 MIB 分支的限制檢視 (VACM View)
Switch(config)# snmp-server view NMS-VIEW iso included

# 2. 建立要求 authPriv 的安全性群組
Switch(config)# snmp-server group NMS-ADMINS v3 priv read NMS-VIEW

# 3. 建立網管使用者，指定 SHA 認證密碼與 AES 加密金鑰
Switch(config)# snmp-server user secops_admin NMS-ADMINS v3 auth sha StrongAuthPass2026! priv aes 128 StrongPrivKey2026!

# 4. 強制停用 SNMPv1 與 SNMPv2c 社群字串
Switch(config)# no snmp-server community public
Switch(config)# no snmp-server community private
```

## 第三動：網路遙測與 SNMP 異常流量捕獲 (Telemetry Setup: Wireshark)

### 1. Wireshark 解構 SNMPv2c 明文漏洞
- 過濾語法：`snmp`
- 展開封包檢視 `community: public`，明文密鑰一覽無遺。

### 2. Wireshark 檢驗 SNMPv3 加密封包
- 展開封包：`msgFlags: 03 (authFlag: 1, privFlag: 1)`。
- PDU 欄位顯示 `encryptedPDU`，所有 OID、數值與參數皆被 AES 密文覆蓋，無法還原。

## 第四動：SIEM 關聯規則與即時獵捕分析 (Splunk & Sigma Rules)

### 1. Splunk SPL：偵測外網或非授權 IP 嘗試暴力破解 SNMP 社群字串
```spl
index=network_syslog sourcetype="cisco:ios" "%SNMP-3-AUTHFAIL"
| rex field=_raw "authentication failure for community (?<Community>\S+) from (?<SrcIP>\S+)"
| stats count earliest(_time) as first_attempt latest(_time) as last_attempt 
        values(Community) as AttemptedCommunities by host, SrcIP
| where count >= 5
| convert ctime(first_attempt) ctime(last_attempt)
| table first_attempt, last_attempt, host, SrcIP, AttemptedCommunities, count
```

### 2. Splunk SPL：偵測 SNMPv3 時效性過期與重放攻擊 (Out of Time Window)
```spl
index=network_syslog sourcetype="cisco:ios" "usmStatsNotInTimeWindows"
| stats count by _time span=5m, host, SrcIP
| table _time, host, SrcIP, count
```

### 3. Sigma 偵測規則：SNMP Authentication Failure Spike
```yaml
title: SNMP Authentication Failure Spike
id: 5a1b9024-81cc-4eb1-99af-11223344bb55
status: production
description: 偵測網路設備接收到大量未授權 SNMP 認證失敗事件，符合枚舉或密碼爆破特徵
logsource:
    category: network_os
    product: cisco
detection:
    selection:
        message|contains:
            - '%SNMP-3-AUTHFAIL'
    condition: selection
level: high
```

## 第五動：SNMP 存取控制清單與全域加固 (ACL Hardening & Best Practices)

```
[NMS 網管中心 (10.99.1.100)] ──► [交換機 SNMP 介面]
                                      │
                                      ├── 1. 基礎架構 ACL 限制 (僅允許 10.99.1.100 存取 UDP 161)
                                      ├── 2. 強制 authPriv (SHA-256 + AES)
                                      ├── 3. 徹底拔除 SNMP Write 寫入權限
                                      ▼
                             [安全傳輸核心維運數據]
```

### 1. 綁定基礎架構存取控制清單 (Infrastructure ACL)
即使啟用了 SNMPv3，亦必須在網路層封殺未授權 IP 探測：
```text
Switch(config)# ip access-list standard SNMP-AUTHORIZED-HOSTS
Switch(config-std-nacl)# permit host 10.99.1.100
Switch(config-std-nacl)# deny any log
Switch(config)# snmp-server group NMS-ADMINS v3 priv access SNMP-AUTHORIZED-HOSTS
```

### 2. 拔除所有 MIB 寫入權限（唯讀原則）
除非特定自動化部署場景，否則一律不設定 `write` 檢視，將群組限制為純粹 `read`。

### 3. 停用不必要的 MIB 分支 (VACM 最小化)
限制外部僅能讀取 `system` 與 `interfaces` 分支，嚴禁讀取 `ipRouteTable` 或 `atTable`（ARP 表）：
```text
Switch(config)# snmp-server view RESTRICTED-VIEW system included
Switch(config)# snmp-server view RESTRICTED-VIEW interfaces included
```

## 靶場實戰：SNMPv1 弱密鑰外洩鑑識與 v3 升級驗證

### 靶場環境情境
- **受害核心交換機**: `SW-CAMPUS-CORE`
- **突發事件**: 網管主機遭攻陷，黑客透過 `snmpwalk` 試出預設 `public` 社群字串，成功導出全校各棟大樓的拓撲與 IP 分配圖。

### 實戰步驟一：鑑識分析
1. 檢視交換機目前 SNMP 設定：
   發現未配置 ACL，且存在 `snmp-server community public RO`。
2. 調閱流量封包，確認社群字串以明文傳遞。

### 實戰步驟二：全面阻斷與升級
1. 刪除所有 v1/v2c 社群字串：
   `no snmp-server community public`
2. 部署 SNMPv3，建立 `secops_admin` 帳號並配置 `auth sha` 與 `priv aes 128`。
3. 綁定 `SNMP-AUTHORIZED-HOSTS` ACL。

### 實戰步驟三：防禦驗證
1. 再次執行 `snmpwalk -v 2c -c public`，連線逾時（Timeout），完全無任何回應。
2. 以 SNMPv3 authPriv 憑證連線，通訊受 AES 加密保護，順利完成資產採集。
