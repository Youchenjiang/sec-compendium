> 3. **USBSTOR / MountedDevices**：完整還原外接隨身碟的廠商名稱、產品型號、全球唯一序號（iSerialNumber）與初次/最後掛載時間！

## 🧩 第一動：底層機制解剖——Windows 使用者登錄檔與活動快取

### 1.1 使用者登錄檔核心結構 (User Registry Hives)
在 Windows 中，使用者個人的設定與操作軌跡並非存放在系統全域登錄檔（如 `SYSTEM` 或 `SOFTWARE`），而是獨立存放在每個使用者的設定檔目錄中：
1. **`NTUSER.DAT`**：位於 `C:\Users\<Username>\NTUSER.DAT`。儲存使用者的個人設定、終端機命令歷程（RunMRU）、自動執行鍵（Run/RunOnce）、以及 **UserAssist** 執行記錄。
2. **`UsrClass.dat`**：位於 `C:\Users\<Username>\AppData\Local\Microsoft\Windows\UsrClass.dat`。儲存使用者模式的 COM 元件資訊、桌面視窗檢視偏好，以及關鍵的 **ShellBags** 資料夾檢視快取！

### 1.2 UserAssist 核心運作機制與 ROT13 混淆
- **登錄檔路徑**：`HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\UserAssist\{GUID}\Count`。
- **ROT13 演算法**：微軟為了避免這些內部快取值被一般文字搜尋工具意外讀取，特意對子機碼的值名稱實施了可逆的 **ROT13 (Rotate 13)** 字元位移替換（例如字母 `A` 變為 `N`，`U` 變為 `H`）：
  - 混淆值：`HRZR_EHACNGU:P:\Grzc\onpxqbber.rkr`
  - 解密後：`UEME_RUNPATH:C:\Temp\backdoor.exe`
- **資料結構欄位**：每個值包含 72 位元組的二進位結構體，其中包含：
  - **點擊執行次數 (Count)**：記錄使用者透過 GUI 點擊該捷徑或程式的次數（從數值中扣除基準偏移量 5）。
  - **聚焦時間 (Focus Time)**：記錄該程式視窗在螢幕前台獲得焦點的總時長。
  - **最後執行時間 (Last Execution Time)**：精確的 64 位元 FILETIME 時間戳。

```
┌───────────────────────────────────────────────────────────┐
│              UserAssist 二進位結構體 (72 Bytes)           │
├───────────────┬───────────────────────────────────────────┤
│ Offset 0x00   │ Session ID / Header                       │
├───────────────┼───────────────────────────────────────────┤
│ Offset 0x04   │ Execution Count (點擊執行次數，需扣除 Base) │
├───────────────┼───────────────────────────────────────────┤
│ Offset 0x08   │ Focus Count (聚焦次數)                     │
├───────────────┼───────────────────────────────────────────┤
│ Offset 0x0C   │ Total Focus Time (前台累積聚焦毫秒數)      │
├───────────────┼───────────────────────────────────────────┤
│ Offset 0x3C   │ Last Execution FILETIME (精確最後執行時間) │
└───────────────┴───────────────────────────────────────────┘
```

### 1.3 ShellBags 資料夾檢視快取機制
Windows 檔案總管為了記住使用者在每一個資料夾中的檢視喜好（例如：是以「大圖示」、「詳細資料」呈現，或是視窗的大小與位置），會在登錄檔中建立一套精密的階層式快取，稱為 **ShellBags**。
- **儲存路徑**：`UsrClass.dat\Local Settings\Software\Microsoft\Windows\Shell\Bags` 與 `BagMRU`。
- **鑑識價值**：
  - **「走過必留下痕跡」**：即使目標資料夾已被整顆刪除，或者該資料夾位於隨身碟（`E:\Confidential\Vaccine_Formula`），只要使用者在檔案總管中點開過該資料夾，其資料夾名稱、MFT 節點號、絕對路徑與點閱時間戳便會永久保存在 ShellBags 中！

### 3.2 自動化 UserAssist ROT13 解密與聚焦時間解析器 (`userassist_decoder.py`)

以下 Python 腳本直接解析導出的 `NTUSER.DAT` 登錄檔或純文字匯出檔，自動執行 ROT13 解密，並計算真實點擊次數與最後執行時間：

```python
#!/usr/bin/env python3
"""
userassist_decoder.py - Decodes Windows UserAssist ROT13 Artifacts
Extracts application execution counts, focus times, and last execution timestamps.
"""

import sys
import codecs
import struct
from datetime import datetime, timezone, timedelta

def filetime_to_dt(ft: int):
    if ft == 0:
        return "N/A (Never executed)"
    us = ft / 10
    return (datetime(1601, 1, 1, tzinfo=timezone.utc) + timedelta(microseconds=us)).strftime("%Y-%m-%d %H:%M:%S UTC")

def decode_rot13(s: str) -> str:
    return codecs.decode(s, "rot_13")

def parse_userassist_entry(raw_name: str, raw_bytes: bytes):
    decoded_name = decode_rot13(raw_name)
    if len(raw_bytes) < 68:
        return None
        
    # Windows 7/10/11 72-byte structure
    session_id, count, focus_count, focus_time_ms = struct.unpack_from("<IIII", raw_bytes, 0)
    last_run_ft = struct.unpack_from("<Q", raw_bytes, 60)[0]
    
    # Base adjustment: Windows adds 5 to the actual run count
    actual_count = max(0, count - 5) if count >= 5 else count
    last_run_str = filetime_to_dt(last_run_ft)
    
    return {
        "path": decoded_name,
        "run_count": actual_count,
        "focus_time_seconds": focus_time_ms / 1000.0,
        "last_run": last_run_str
    }

def print_demo():
    print("=" * 80)
    print("Demo: Decoding sample ROT13 UserAssist string:")
    sample = "HRZR_EHACNGU:P:\\Grzc\\Icppvar_Rksvygengbe.rkr"
    print(f"  Raw:     {sample}")
    print(f"  Decoded: {decode_rot13(sample)}")
    print("=" * 80)

if __name__ == "__main__":
    if len(sys.argv) < 2:
        print("Usage: python userassist_decoder.py --demo")
        print("       (Feed extracted registry values into parser)")
        print_demo()
        sys.exit(0)
    if sys.argv[1] == "--demo":
        print_demo()
```

### 4.2 SOC 告警研判 8 大黃金提問 (The 8 Golden Questions)
1. **Who (登入者帳號)**：進行操作時登入的本機或網域使用者帳號為何？
2. **What (存取標的)**：ShellBags 中記錄被瀏覽的資料夾是否屬於機密研發專案？
3. **Where (路徑所在磁區)**：該資料夾是位於本機 C 槽，還是曾掛載過的外接隨身碟（如 `E:\` 磁碟機）？
4. **When (互動時戳)**：UserAssist 記錄的最後執行點擊時間，與隨身碟拔除時間是否相差在數秒之內？
5. **Why (動機關聯)**：該使用者在離職前夕為何會密集點開超過 50 個未授權的歷史專案資料夾？
6. **How (操作方式)**：是透過檔案總管一層層滑鼠點閱（ShellBags 具有完整父子層階層記錄），還是下達批次命令？
7. **Impact (損害估計)**：外接隨身碟的硬體序號為何？是否曾插入過公司其他敏感伺服器？
8. **Confidence (研判信心度)**：ShellBags 與 USBSTOR 硬體記錄吻合，信心度為 100%。

## 🛡️ 第五動：處置圍堵與根除加固 SOP (Mitigation & Hardening)

### 1. 第一步：鎖定外接硬體序號並實施扣押
- **萃取唯一硬體序號**：從 `SYSTEM\CurrentControlSet\Enum\USBSTOR` 提取該隨身碟的 `iSerialNumber`。
- **實體證據鏈建立**：立即向法務部通報，對涉案員工的私人物品進行合規保全與扣押。

### 2. 第二步：全域回溯隨身碟插拔足跡
- **全網端點 SIEM 掃描**：以該 USB 序號為特徵，在全企業的端點日誌（Event ID 20001 / Event ID 7045）中搜尋過去 365 天內該隨身碟曾在哪些主機插拔過，徹底排查資料擴散範圍。

### 3. 第三步：架構加固——強制啟用 USB 儲存裝置管控
- **部署 GPO 停用隨身碟寫入權限**：
  - 在網域群組原則中配置：`電腦設定` ➔ `系統管理範本` ➔ `系統` ➔ `卸除式存放裝置存取權` ➔ `所有卸除式存放裝置類別: 拒絕所有存取 (或拒絕寫入存取)`。
  - 強制所有需要使用外接儲存的部門必須經過審核，並全面推行具備硬體 AES 加密之企業受控隨身碟。

## 📋 過關驗收檢查點 (Mastery Checklist)

- [x] **Q1：為什麼微軟要對 UserAssist 登錄機碼的數值名稱實施 ROT13 加密混淆？這是否屬於真正的密碼學加密？鑑識人員該如何解讀？**
  > **標準答案**：
  > 1. **非密碼學加密**：ROT13（位移 13 位的凱撒密碼）**完全不屬於**現代密碼學意義上的安全加密，它只是初階的「混淆（Obfuscation）」。
  > 2. **微軟的設計動機**：微軟在設計 Windows Explorer 快取時，僅是希望避免這些內部活動紀錄被普通的純文字檢索工具、或終端使用者在使用登錄檔編輯器（`regedit`）時無意中看到或搜尋到，屬於輕度遮蔽。
  > 3. **鑑識解讀方法**：ROT13 具有對稱自逆性（加密與解密演算法完全相同，再次位移 13 位即還原）。鑑識人員只需將混淆字串傳入簡單的字元對映函數，即可 100% 原汁原味還原出可執行檔的真實絕對路徑。

- [x] **Q2：在內部人調查中，如果涉案員工在拔除隨身碟前，將隨身碟中的特定目錄直接刪除了，為什麼 ShellBags 依然能夠精確證明他「曾經看過那個被刪除的目錄」？**
  > **標準答案**：
  > 1. **資料儲存位置的獨立性**：資料夾被刪除是在「外接隨身碟的檔案系統」上進行；而 ShellBags 則是記錄在「**本機使用者的 `UsrClass.dat` 登錄檔**」中。
  > 2. **GUI 檢視快取的生命週期**：當使用者的 Windows 檔案總管進入該目錄時，系統為了記住該資料夾的圖示排列與視窗坐標，會立即在本地 `UsrClass.dat` 中分配一筆 BagMRU 節點。
  > 3. **不可抹滅性**：Windows 檔案總管在目標目錄被刪除或外接碟拔除時，**根本不會去清理歷史 ShellBags 登錄機碼**！因此，該目錄的完整名稱、第一次檢視時間與路徑結構，會作為永恆的歷史快照永久保存在本機端點上。

- [x] **Q3：在 UserAssist 記錄中，「執行次數 (Run Count)」與「聚焦時間 (Focus Time)」在還原使用者惡意意圖時，具有何種強大的證明力？**
  > **標準答案**：
  > 1. **排除背景與誤觸**：常規的進程監控僅能證明二進位檔曾被加載；但 UserAssist 的紀錄直接代表使用者在 GUI 桌面環境中「以滑鼠主動雙擊點擊」該程式，直接排除了惡意軟體背景無感呼叫的可能。
  > 2. **證明主觀持續操作**：`Focus Time` 記錄了該程式視窗在螢幕最前台活躍顯示的總毫秒數。若涉案程式在前台聚焦長達 20 分鐘，足以在法庭上直接粉碎涉案人「我只是不小心點到一下、馬上就關掉了」的卸責辯詞，鐵證如山地證明其存在長時間的主觀操作意圖。

- [x] **Q4：在比對外接隨身碟鑑識時，如何從 Windows 登錄檔中提取出該隨身碟的「全球唯一硬體序號」？遇到未燒錄序號的隨身碟該如何辨別？**
  > **標準答案**：
  > 1. **唯一硬體序號查詢路徑**：檢視 `HKLM\SYSTEM\CurrentControlSet\Enum\USBSTOR` 鍵值。在裝置子目錄下，通常會呈現一組英數混合的字串，即為該隨身碟出廠時燒錄在硬體韌體中的全球唯一序號（iSerialNumber）。
  > 2. **未燒錄序號的辨識特徵**：部分廉價白牌隨身碟未依 USB-IF 規範寫入唯一序號。當 Windows 發現第二個字元為 `&`（例如 `7&19a5b7c&0`）時，代表該序號不是出廠硬體序號，而是 Windows 作業系統內部自行生成的「父層硬體識別雜湊碼」。

- [x] **Q5：如果一名高階主管辯稱：「那台隨身碟我借給很多同事用過，裡面的檔案不一定是我從這台電腦拷貝的。」鑑識人員如何從端點上提供閉環證據鏈證明是他在此主機上拷貝的？**
  > **標準答案**：
  > 1. **時間戳閉環互證**：
     - 比對 `USBSTOR` 記錄的**最後插入時間 (Last Arrival Time)** 與**拔除時間 (Last Removal Time)**。
     - 比對涉案主機 `UsrClass.dat` 中的 ShellBags 記錄，證實該隨身碟盤符（如 `E:\`）下的目錄**被瀏覽的時間點完全落在該插入區間內**。
  > 2. **身分帳號綁定**：ShellBags 與 UserAssist 是儲存在**該主管個人的使用者設定檔（SID 專屬的 `UsrClass.dat` 與 `NTUSER.DAT`）**中，其他登入該主機的帳號無法寫入他的專屬設定檔。
  > 3. **LNK 捷徑檔案佐證**：在該主管專屬的 `Recent` 目錄下提取 LNK 檔案，比對其中記錄的目標檔案大小、磁碟區序號與隨身碟硬體序號完全一致，形成無法辯駁的 100% 證據閉環！
