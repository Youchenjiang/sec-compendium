## 🧩 第一動：底層機制解剖——三大執行痕跡的物理架構

### 1.1 Prefetch (預取檔案, `.pf`) 機制
Windows 為了加速應用程式啟動，在每次執行二進位程式時，由 Cache Manager 監視其在前 10 秒內存取的磁碟分頁與載入的檔案，並將其壓縮寫入 `C:\Windows\Prefetch\` 目錄，副檔名為 `.pf`。

#### Prefetch 核心檔案格式：
- **命名規則**：`[程式名稱]-[雜湊值].pf`（例如 `CMD.EXE-AC752C28.pf`）。其雜湊值是由可執行檔的完整路徑計算而來（Windows 10/11 採用自訂的 Hash 演算法）。
- **壓縮演算法**：Windows 10/11 採用 **MAM (XPRESS LZX)** 專有壓縮格式（檔案開頭前 4 位元組為 `MAM\x04`）。
- **關鍵鑑識元資料**：
  1. **執行次數計數器 (Run Count)**：該程式自作業系統安裝以來累計被執行的次數。
  2. **最後執行時間戳 (Run Timestamps)**：Windows 10/11 會依序記錄最近 **8 次** 的執行時間戳！
  3. **相依模組清單 (Referenced Files / Loaded DLLs)**：包含該 EXE 執行時所讀取的所有檔案、動態庫 DLL 路徑。攻擊者即使刪除了木馬本体，其載入過的惡意 DLL 或存取過的文件仍會在 Prefetch 的相依清單中現形！

```
┌───────────────────────────────────────────────────────────┐
│               Windows Prefetch (.pf) 架構                 │
├───────────────────────────────────────────────────────────┤
│ Header (MAM 壓縮) │ Magic, Uncompressed Size             │
├───────────────────┼───────────────────────────────────────┤
│ File Information  │ Executable Name, Hash, Run Count      │
├───────────────────┼───────────────────────────────────────┤
│ Last Run Times    │ 8 組精確 FILETIME 時間戳 (最後 8 次執行)│
├───────────────────┼───────────────────────────────────────┤
│ Volume Info       │ 原始硬碟序號、磁碟區建立時間          │
├───────────────────┼───────────────────────────────────────┤
│ File References   │ 執行期間讀取的數十到數百個檔案與 DLL   │
└───────────────────┴───────────────────────────────────────┘
```

### 1.2 ShimCache (AppCompatCache) 運作機制
Application Compatibility Cache (ShimCache) 是微軟為了確認應用程式是否需要套用修補程式（Shim）而維護的機制：
- **儲存位置**：存放於核心記憶體中，僅在系統**正常關機或重新開機時**才會寫入登錄檔 `SYSTEM\CurrentControlSet\Control\Session Manager\AppCompatCache`。
- **鑑識關鍵物理特性**：
  - **檔案路徑與最後修改時間**：記錄被列舉之檔案的完整路徑、檔案大小、以及該檔案自身的 `$SI.Modified` 時間戳。
  - **「存在不等於執行」重要法則**：當使用者在檔案總管瀏覽某個資料夾，或透過命令列執行 `dir` 時，系統有時會自動掃描該目錄下的可執行檔並加入 ShimCache。因此，**ShimCache 只能證明該二進位檔曾經「存在於」該路徑，不能單獨作為 100% 執行過的鐵證**！

### 1.3 Amcache (`Amcache.hve`) 機制
Amcache 是一個獨立的登錄區配置單元（Registry Hive），路徑位於 `C:\Windows\appcompat\Programs\Amcache.hve`：
- **記錄內容**：它記錄了在系統上執行過的應用程式之豐富元資料，包括：
  1. **未經加鹽的 SHA-1 檔案雜湊值**（File Hash）。
  2. 檔案版本、廠商名稱、編譯時間戳。
  3. 應用程式初次被系統發現並執行的建立時間（First Run / Installation Time）。
- **鑑識價值**：即使攻擊者使用 `sdelete` 將惡意程式粉碎抹除，Amcache 中依然完整保留該檔案的 **SHA-1**。鑑識人員可直接將此 SHA-1 丟上 VirusTotal 識別木馬家族！

### 2.1 三大執行證據特性橫向對比表

| 鑑識維度 | Prefetch (`.pf`) | ShimCache (`AppCompatCache`) | Amcache (`Amcache.hve`) |
| :--- | :--- | :--- | :--- |
| **預設啟用範圍** | Windows Client 預設開啟；Server 版預設關閉 | 全版本 Windows 預設強制開啟 | Windows 8/10/11/Server 預設開啟 |

| **相依檔案還原** | ✅ 可列舉所有載入之 DLL/檔案 | ❌ 無法還原相依性 | ✅ 可還原關聯的驅動與未註冊 PE |

### 3.2 自動化執行鐵證交叉關聯工具 (`execution_triangulator.py`)

以下 Python 腳本讀取 PECmd 與 AmcacheParser 產生的 CSV 報表，自動比對惡意程式的執行時間、執行次數與 SHA-1 雜湊：

```python
#!/usr/bin/env python3
"""
execution_triangulator.py - Triangulates Windows Execution Evidence
Correlates PECmd (Prefetch) and AmcacheParser outputs to build high-fidelity execution timelines.
"""

import sys
import csv
from pathlib import Path
from collections import defaultdict

def parse_prefetch(csv_file: Path):
    print(f"[*] Parsing Prefetch: {csv_file.name}")
    exec_data = {}
    with open(csv_file, "r", encoding="utf-8-sig", errors="ignore") as f:
        reader = csv.DictReader(f)
        for row in reader:
            exe_name = row.get("ExecutableName", "").lower()
            run_count = row.get("RunCount", "0")
            last_run = row.get("LastRun", "")
            files_loaded = row.get("FilesLoaded", "")
            if exe_name:
                exec_data[exe_name] = {
                    "run_count": run_count,
                    "last_run": last_run,
                    "files_loaded": files_loaded.split(", ") if files_loaded else []
                }
    return exec_data

def parse_amcache(csv_file: Path):
    print(f"[*] Parsing Amcache: {csv_file.name}")
    hash_data = {}
    with open(csv_file, "r", encoding="utf-8-sig", errors="ignore") as f:
        reader = csv.DictReader(f)
        for row in reader:
            filename = row.get("Name", "").lower()
            sha1 = row.get("FileHashSha1", row.get("SHA1", ""))
            first_run = row.get("FileKeyCreationTime", "")
            path = row.get("FullPath", "")
            if filename and sha1:
                hash_data[filename] = {
                    "sha1": sha1,
                    "first_run": first_run,
                    "path": path
                }
    return hash_data

def triangulate(prefetch_csv: Path, amcache_csv: Path):
    prefetch = parse_prefetch(prefetch_csv)
    amcache = parse_amcache(amcache_csv)
    
    print("=" * 80)
    print(f"{'Executable':<20} | {'RunCount':<8} | {'Last Run (Prefetch)':<22} | {'SHA-1 (Amcache)':<40}")
    print("-" * 80)
    
    suspicious_keywords = ["mimikatz", "procdump", "cobalt", "powershell", "certutil", "vssadmin", "wevtutil"]
    for exe, pf in prefetch.items():
        # Check if suspicious
        is_suspect = any(kw in exe for kw in suspicious_keywords)
        sha1 = amcache.get(exe, {}).get("sha1", "N/A (Not found in Amcache)")
        
        if is_suspect or int(pf["run_count"]) <= 3:
            flag = "🚨 SUSPICIOUS" if is_suspect else "ℹ️ Low Frequency"
            print(f"{exe:<20} | {pf['run_count']:<8} | {pf['last_run']:<22} | {sha1:<40} [{flag}]")

if __name__ == "__main__":
    if len(sys.argv) < 3:
        print("Usage: python execution_triangulator.py <prefetch_parsed.csv> <amcache_parsed.csv>")
        sys.exit(1)
    triangulate(Path(sys.argv[1]), Path(sys.argv[2]))
```

## ⚖️ 第四動：研判分水嶺——ShimCache 存在 vs Prefetch 執行的研判陷阱

### 4.1 核心研判決策樹
```
[在取證證據中發現惡意程式路徑 (如 C:\Temp\mimikatz.exe)]
                            │
                            ▼
               [該路徑出現在何種證據中?]
               /                        \
       (僅出現在 ShimCache)        (出現在 Prefetch / Amcache)
              /                                  \
[比對是否有 RunCount 或執行日誌]            [Prefetch 是否存在該 .pf 檔案?]
      /                 \                        /             \
   (無)                 (有)                    (是)            (否)
    │                    │                       │               │
    ▼                    ▼                       ▼               ▼
[僅證明該檔案曾落地]   [確認曾執行]         [100% 確鑿執行過]   [可能透過免預取執行]
(不能作為已執行定罪)   (定性為入侵)         (提取最後8次時間戳) (檢查 Amcache 雜湊)
```

### 4.2 SOC 告警研判 8 大黃金提問 (The 8 Golden Questions)
1. **Who (執行者身分)**：執行該程式的帳號 SID 為何？是否為匿名服務或已遭劫持帳號？
2. **What (程式實體)**：該二進位檔的真正名稱與 Amcache SHA-1 雜湊為何？
3. **Where (原始落地路徑)**：程式當初是在哪一個目錄被觸發（如 `C:\Users\Public\`、`Temp` 還是 UNC 網路共用夾）？
4. **When (執行頻率與時間軸)**：Prefetch 記錄的 8 次執行時間點，與資料外洩發生的時機點是否高度吻合？
5. **Why (商業合理性)**：這台終端為何需要執行 `vssadmin.exe` 或 `procdump.exe`？
6. **How (載入相依模組)**：Prefetch 相依檔案清單中，是否包含可疑的自訂 DLL 或敏感認證快取檔案？
7. **Impact (執行次數評估)**：`RunCount` 是 1 次（攻擊者初次嘗試）還是上百次（已潛伏數月）？
8. **Confidence (研判信心度)**：同時具備 Prefetch 執行次數與 Amcache SHA-1 雜湊，信心度為 100%。

## 🛡️ 第五動：處置圍堵與根除加固 SOP (Mitigation & Hardening)

### 1. 第一步：提取 SHA-1 並全網阻斷
- **立即下發 EDR 黑名單**：透過 Amcache 萃取出的惡意程式 SHA-1，直接在微軟 Defender 或 CrowdStrike 控制台下發全球封鎖（Block Hash）。
- **全域回溯搜尋**：在 SIEM 中搜尋過去 180 天內所有接觸過該 Hash 的主機並即刻隔離。

### 2. 第二步：深入 Prefetch 提取 DLL 載入軌跡
- **檢查 DLL 劫持 (DLL Side-Loading)**：檢視可疑 Prefetch 檔案清單中的 DLL 路徑。若發現微軟合法程式（如 `OneDrive.exe`）載入了位於 `AppData\Local\Temp` 下的未簽名 DLL，即可證實為白加黑 DLL 劫持攻擊。

### 3. 第三步：架構加固——伺服器環境開啟 Prefetch
- **在 Windows Server 啟用 Prefetch**：預設情況下 Windows Server 出於效能考量關閉 Prefetch。在關鍵伺服器上，建議透過修改登錄檔開啟，以利日後取證：
  ```powershell
  # 開啟 Windows Server 應用程式預取 (EnablePrefetcher = 3: 包含開機與程式執行)
  Set-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Control\Session Manager\Memory Management\PrefetchParameters" -Name "EnablePrefetcher" -Value 3 -Type DWord
  ```

## 📋 過關驗收檢查點 (Mastery Checklist)

- [x] **Q1：在數位鑑識法庭質證時，辯方律師聲稱：「我的當事人只是不小心下載了該駭客工具，但從來沒有執行過它。」你身為鑑識專家，能僅憑 ShimCache 中存在該工具的紀錄，就斷定他「肯定執行過」嗎？為什麼？**
  > **標準答案**：
  > 1. **不能**！僅憑 ShimCache 的存在紀錄，**絕對不能**作為程式「肯定執行過」的法庭鐵證。
  > 2. **底層系統行為分析**：Windows 的 AppCompatCache 是為了相容性評估而設計。當使用者透過 Windows 檔案總管瀏覽資料夾、或者透過批次腳本列舉檔案目錄時，作業系統可能會自動掃描目錄中的二進位檔案屬性並將其登錄至 ShimCache 中，即使該程式從未被啟動過。
  > 3. **正確取證主張**：必須進一步提出 **Prefetch (`.pf`) 檔案（具有明確的 Run Count > 0 與執行時間戳）**、**UserAssist 登錄檔**、或 **Amcache 中的執行紀錄** 進行交叉互證，方能在法庭上確立「該程式確實曾被執行」的事實。

- [x] **Q2：為什麼 Windows 10/11 的 Prefetch 檔案會採用 MAM 壓縮？鑑識人員如果直接用常規 Hex 編輯器打開 `.pf` 檔案會看到什麼？該如何正確解壓？**
  > **標準答案**：
  > 1. **節省空間與 I/O 效率**：Windows 10/11 引入了專有的 MAM（Modified Lempel-Ziv / XPRESS LZX）即時壓縮演算法，以減少大量預取檔案對磁碟空間的佔用並提升開機讀取速度。
  > 2. **直接檢視的現象**：若直接用純文字或常規 Hex 編輯器打開，前 4 個位元組只會看到 `MAM\x04`（Magic Header），其後所有的字串與時間戳皆呈現為壓縮亂碼，無法直接讀取。
  > 3. **解壓縮方法**：必須使用專門支援 MAM 演算法的鑑識工具（例如 Eric Zimmerman 的 `PECmd`，或 Python 函式庫 `libscca` / `decompress-mam`），先在記憶體中還原出原始未壓縮的 Prefetch 二進位格式，才能正確解析出標頭與時間戳表。

- [x] **Q3：在惡意程式調查中，若目標可執行檔已經被攻擊者從磁碟上徹底粉碎刪除（連 MFT 記錄都被覆寫），為什麼 Amcache (`Amcache.hve`) 依然能提供破案的最強關鍵線索？**
  > **標準答案**：
  > 1. **獨立儲存機制**：`Amcache.hve` 是一個獨立的系統登錄區檔案，不受個別檔案所在目錄刪除操作的影響。
  > 2. **不可抹滅的 SHA-1 雜湊記錄**：Windows 在首次執行或安裝應用程式時，會主動計算並將該程式的完整 **SHA-1 雜湊值** 固化在 `Amcache.hve` 的二進位鍵值中。
  > 3. **破案價值**：即使磁碟上已無任何木馬本體二進位檔案可供逆向，鑑識人員只要從 Amcache 提取出該 SHA-1，即可直接向全球威脅情報資料庫（VirusTotal、Hybrid-Analysis）查詢該檔案的家族歸屬、C2 通訊協定與危害特徵，完成案件定性。

- [x] **Q4：在 Windows Server 作業系統中，預設情況下 Prefetch 通常處於停用狀態，身為企業資安架構師，你會建議在什麼情況下開啟？開啟後對系統會產生什麼具體影響？**
  > **標準答案**：
  > 1. **預設停用原因**：微軟在 Server 版作業系統預設停用 Prefetch，是因為伺服器通常持續運行固定服務（如 IIS、SQL Server），鮮少頻繁啟動互動式桌面軟體，且伺服器追求極致的磁碟 I/O 穩定性，避免快取寫入爭搶。
  > 2. **建議開啟場景**：在**高安全等級堡壘機（Jump Server）、終端伺服器（RDS / Citrix）、以及高價值關鍵工作站**，強烈建議將 `EnablePrefetcher` 設為 `3`。
  > 3. **具體影響評估**：開啟後會稍微增加 `C:\Windows\Prefetch` 的磁碟小檔案寫入量（對現代 SSD 或 NVMe 儲存影響微乎其微），但能夠換取高達最近 8 次執行時間戳與相依 DLL 的無價審計鐵證，顯著縮減未來 DFIR 事件調查的時間成本。

- [x] **Q5：攻擊者如何利用「白加黑 (DLL Side-Loading)」技術欺騙只看執行檔名稱的初階分析師？在 Prefetch 鑑識中如何精準識破？**
  > **標準答案**：
  > 1. **欺騙手法**：攻擊者利用具有微軟官方合法數位簽章的可執行檔（白檔案，如 `calc.exe`、`OneDrive.exe`），將其複製到任意暫存目錄，並在同目錄下放置一個同名或惡意特製的動態庫（黑檔案，例如 `version.dll`）。執行白檔案時，系統會優先載入當前目錄下的惡意 DLL。初階分析師只看執行檔名會誤以為是正常微軟程式在運行。
  > 2. **Prefetch 破局點**：Prefetch 內部不僅記錄主檔名，還完整收錄了 **`FilesLoaded`（相依檔案與動態庫清單）**！
  > 3. **鑑識判定方法**：檢查 Prefetch 記載的 DLL 載入路徑。若合法的系統程式載入的 DLL 不是來自 `C:\Windows\System32\`，而是來自使用者臨時資料夾（如 `C:\Users\...\AppData\Local\Temp\version.dll`），即可 100% 斷定為 DLL 劫持攻擊！
