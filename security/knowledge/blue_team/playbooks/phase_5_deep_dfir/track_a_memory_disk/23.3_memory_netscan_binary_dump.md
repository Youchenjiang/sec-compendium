## 🧩 第一動：底層機制解剖——核心網路物件與記憶體二進位導出原理

### 1.1 Windows 核心網路結構體 (Network Control Blocks)
在 Windows NT 架構中，所有網路傳輸由 `tcpip.sys` 核心驅動程式負責管理。每當應用程式建立 Socket 連線時，核心會在分頁池或非分頁池（Paged/Non-Paged Pool）中配置特定的結構體：
1. **`_TCP_ENDPOINT`**：代表一個活躍或處於狀態機轉換中的 TCP 連線端點。欄位包含本地 IP、本地埠號、遠端 IP、遠端埠號、TCP 狀態（`ESTABLISHED`、`LISTENING`、`TIME_WAIT`、`CLOSED`）以及擁有該連線的進程物件指針 `Owner` (`_EPROCESS`)。
2. **`_UDP_ENDPOINT`**：代表 UDP 監聽或通訊端點，記載本地綁定 IP 與通訊埠及擁有者進程。
3. **`_TCP_LISTENER`**：代表系統中等待外部連入的 TCP 服務端監聽端口。

```
[Windows 核心態網路物件與 EPROCESS 關聯圖]

   Non-Paged Pool (tcpip.sys)                     Executive Pool
┌─────────────────────────────────┐          ┌───────────────────────┐
│       _TCP_ENDPOINT             │          │       _EPROCESS       │
├─────────────────────────────────┤          ├───────────────────────┤
│ LocalAddress  : 192.168.1.50    │          │ UniqueProcessId: 3488 │
│ LocalPort     : 49821           │          │ ImageFileName  : svch │
│ RemoteAddress : 104.244.76.13   │          │ CreateTime     : ...  │
│ RemotePort    : 443 (HTTPS)     │          │                       │
│ State         : TIME_WAIT       │          │                       │
│ Owner (Pointer) ───────────────┼─────────►│ ActiveProcessLinks    │
└─────────────────────────────────┘          └───────────────────────┘
  (即使連線中斷，物件依然殘留於 Pool)
```

### 1.2 netstat vs netscan 底層物理機制差異
- **即時指令 `netstat -ano`（用戶態）**：透過呼叫 `IPHLPAPI.DLL`（IP Helper API）向 `tcpip.sys` 查詢當前處於活躍狀態的連線表。如果連線已被調用 `closesocket()` 且超過 `TIME_WAIT` 週期，系統會將其從內部活躍雜湊表中移除，用戶態將徹底看不見。
- **Volatility 3 `windows.netscan`（記憶體池特徵雕刻）**：
  - 完全不依賴作業系統的活躍雜湊表。
  - 直接在實體記憶體中搜尋特定的核心網路池標籤（Pool Tags），例如：
    - `TcpE`：代表 `_TCP_ENDPOINT`。
    - `UdpA`：代表 `_UDP_ENDPOINT`。
    - `TcpL`：代表 `_TCP_LISTENER`。
  - 即使連線已經在 30 分鐘前中斷，只要這塊核心記憶體沒有被作業系統覆寫（Overwritten），`netscan` 就能將其挖出，還原當時的五元組（源 IP、源埠、目的 IP、目的埠、協定）與 PID！

### 1.3 二進位導出 (Binary Dumping) 原理與限制
攻擊者植入的二進位程式在記憶體中通常有兩種存在形態：
1. **檔案備份映象 (File-Backed Images)**：
   - 經由標準載入器載入的 EXE 或 DLL，其 VAD 節點關聯到一個 `_FILE_OBJECT`。
   - Volatility 3 的 `windows.dumpfiles` 插件能走訪該進程的虛擬記憶體區段，將磁碟快取或記憶體映射中的檔案還原為原始的 PE 檔案。
2. **無檔案注入映像 (In-Memory Unbacked Payloads)**：
   - 若為反射式 DLL 或 Shellcode，在 VAD 樹中顯示為 `MEM_PRIVATE`，背後無任何 `_FILE_OBJECT`。
   - 此時必須使用 `windows.vaddump` 或 `windows.malfind --dump`，針對特定的記憶體虛擬位址區段（Virtual Address Range）進行實體字節傾印。

### 3.2 自動化 Netscan 差集與 IOC 關聯工具 (`netscan_ioc_analyzer.py`)

以下 Python 腳本解析 Volatility 3 `netscan` 輸出，過濾出私有 IP 與公網 IP，標記可疑外聯進程並產出威脅研判報表：

```python
#!/usr/bin/env python3
"""
netscan_ioc_analyzer.py - Volatility 3 Netscan Log Carving and IOC Extraction
Parses windows.netscan outputs, filters external C2 connections, and maps suspicious PIDs.
"""

import sys
import re
import ipaddress
from collections import defaultdict

def is_public_ip(ip_str: str) -> bool:
    try:
        ip = ipaddress.ip_address(ip_str)
        return not (ip.is_private or ip.is_loopback or ip.is_link_local or ip.is_unspecified)
    except ValueError:
        return False

def parse_netscan(file_path: str):
    print(f"[*] Reading netscan log: {file_path}")
    connections = []
    
    with open(file_path, "r", encoding="utf-8", errors="ignore") as f:
        for line in f:
            parts = line.strip().split()
            if len(parts) < 6:
                continue
            # Volatility 3 netscan table format: Offset, Proto, LocalAddr, LocalPort, ForeignAddr, ForeignPort, State, PID, Owner, Created
            # Look for IPv4 patterns
            match = re.search(r"(\d{1,3}(?:\.\d{1,3}){3}):(\d+)\s+(\d{1,3}(?:\.\d{1,3}){3}):(\d+)", line)
            if match:
                local_ip, local_port, foreign_ip, foreign_port = match.groups()
                # Find PID and Owner
                pid = "Unknown"
                owner = "Unknown"
                for p in parts:
                    if p.isdigit() and int(p) > 0 and int(p) < 65535:
                        pid = p
                for candidate in ["svchost.exe", "powershell.exe", "cmd.exe", "rundll32.exe", "explorer.exe"]:
                    if candidate in line.lower():
                        owner = candidate
                        break
                connections.append({
                    "local": f"{local_ip}:{local_port}",
                    "foreign": f"{foreign_ip}:{foreign_port}",
                    "foreign_ip": foreign_ip,
                    "foreign_port": foreign_port,
                    "pid": pid,
                    "owner": owner,
                    "raw": line.strip()
                })
                
    return connections

def generate_report(connections):
    public_conns = [c for c in connections if is_public_ip(c["foreign_ip"])]
    print(f"[+] Total connections parsed: {len(connections)}")
    print(f"[!] External public IP connections found: {len(public_conns)}")
    print("=" * 80)
    
    c2_candidates = defaultdict(list)
    for c in public_conns:
        c2_candidates[c["foreign_ip"]].append(c)
        
    for ip, conns in c2_candidates.items():
        print(f"\n🚨 Suspicious Foreign Destination: {ip}")
        for c in conns:
            print(f"    Local: {c['local']:<22} | PID: {c['pid']:<6} | Owner: {c['owner']:<15} | Port: {c['foreign_port']}")
            
    print("=" * 80)

if __name__ == "__main__":
    if len(sys.argv) < 2:
        print("Usage: python netscan_ioc_analyzer.py <netscan_output.txt>")
        sys.exit(1)
        
    conns = parse_netscan(sys.argv[1])
    generate_report(conns)
```

### 4.2 SOC 告警研判 8 大黃金提問 (The 8 Golden Questions)
1. **Who (主體進程)**：發起該連線的進程為何？為何文檔編輯器或列印後台需要發起外聯？
2. **What (外聯標的)**：連線的遠端 IP 屬於哪一個國家/自治系統（ASN）？是否名列 CTI 威脅情報黑名單？
3. **Where (通訊協議與埠號)**：連線使用的是非標準通訊埠（如 4444、8088、1337）還是混淆在 443/80？
4. **When (活動時機)**：連線建立的時間點是否在非工作時間（如凌晨 02:00-05:00）？
5. **Why (商業合理性)**：是否有正當的業務需求需要該端點與該境外 IP 通訊？
6. **How (連線頻率與型態)**：連線是單次短暫傳輸（可能是外洩數據），還是固定間隔的 Heartbeat 心跳連線？
7. **Impact (受害深度)**：該連線所屬的進程在系統中是否具備高特權（SYSTEM / Administrator）？
8. **Confidence (研判信心度)**：透過記憶體池結構體雕刻取得五元組與 PID 關聯，信心度達 100%。

## 🛡️ 第五動：處置圍堵與根除加固 SOP (Mitigation & Hardening)

### 1. 第一步：邊界防火牆阻斷與主機圍堵
- **下發全網阻斷黑名單**：將 `netscan` 萃取出的 C2 IP 與網段立即寫入邊界防火牆、NGFW 與 DNS 阻斷清單。
- **端點實體隔離**：在未重開機的前提下切斷受害端點的網路連線，避免攻擊者接收連線中斷信號後下達抹除或破壞指令。

### 2. 第二步：二進位還原與特徵提煉
- **導出映像**：使用 `windows.dumpfiles` 與 `windows.vaddump` 完整匯出該進程的所有代碼區段。
- **雜湊比對與逆向**：計算二進位檔案之 SHA256，送入內部 Sandbox 分析外聯協定、加密金鑰與下行指令結構。

### 3. 第三步：全域威脅獵捕 (Threat Hunting)
- **SIEM / EDR 回溯掃描**：以導出檔案的雜湊值與 C2 IP，在 SIEM 日誌中搜尋過去 90 天內是否有其他主機曾發起相同外聯或執行過該檔案。

### 4. 第四步：架構加固——強化邊界微隔離
- **限制伺服器主動外聯**：嚴格配置伺服器群的出口策略（Egress Filtering），伺服器預設禁止主動連向網際網路，必須透過具備身分驗證與 SSL 解密之正向代理（Forward Proxy）。

## 📋 過關驗收檢查點 (Mastery Checklist)

- [x] **Q1：為什麼在主機端執行 `netstat -ano` 看不到的歷史網路連線，透過 Volatility 3 的 `windows.netscan` 卻能被完整挖出來？其底層核心機制為何？**
  > **標準答案**：
  > 1. **用戶態 API 與核心活動表的侷限**：`netstat` 透過呼叫 Windows 網路 API 查詢核心當前的「活躍連線雜湊表」。當連線正常或異常關閉並結束 `TIME_WAIT` 狀態後，核心會將其從該活躍表中除名，因此用戶態命令完全無法列出。
  > 2. **核心記憶體池物件殘留 (Pool Carving)**：`tcpip.sys` 為連線所分配的 `_TCP_ENDPOINT` 結構體存在於核心記憶體池中。即使連線斷開，除非該記憶體分頁恰好被作業系統回收並寫入新資料，否則該結構體（包含 IP、Port、PID 與時間戳）仍會完整留存在實體 RAM 中。
  > 3. **特徵標記掃描**：`windows.netscan` 採用池標記掃描（Pool Tag Scanning）技術，逐頁搜尋 `TcpE` 等標籤，因此能夠繞過作業系統的活躍表，直接「雕刻」出歷史連線紀錄。

- [x] **Q2：在進行記憶體二進位導出時，`windows.dumpfiles` 與 `windows.vaddump` (或 `malfind --dump`) 有何適用場景與技術限制？**
  > **標準答案**：
  > 1. **`windows.dumpfiles` 的適用場景**：專門用於導出具備磁碟檔案背書（File-Backed）的模組。它走訪記憶體中與 `_FILE_OBJECT` 關聯的分頁快取（DataSectionObject / ImageSectionObject），能還原出磁碟上原始的 PE 檔案結構，非常適合提取被載入的實體木馬 EXE 或惡意 DLL。
  > 2. **`windows.vaddump` 的適用場景**：專門用於導出記憶體私有分頁（`MEM_PRIVATE`）。當攻擊者採用無檔案注入（如反射式 DLL、Shellcode）時，進程記憶體中根本沒有對應的 `_FILE_OBJECT`，`dumpfiles` 會直接跳過；此時必須使用 `vaddump` 按照虛擬位址區間將記憶體字節原始傾印出來。

- [x] **Q3：在 `windows.netscan` 輸出中，看到某個連線的 PID 對應的進程在 `windows.pslist` 中找不到，代表什麼含意？該如何交叉驗證？**
  > **標準答案**：
  > 1. **第一種可能（正常退出的短命進程）**：惡意程式發動連線並完成任務後主動呼叫 `ExitProcess` 退出，該進程已從進程鏈表中移除，但核心網路結構尚未被完全覆寫。
  > 2. **第二種可能（DKOM 斷鏈隱藏進程）**：該進程遭到核心 Rootkit 從 `ActiveProcessLinks` 中摘除，進程依然活躍但對鏈表隱形。
  > 3. **交叉驗證方法**：執行 `windows.psscan`。若 `psscan` 找到該 PID 且 `ExitTime` 為空，證實為活體 DKOM 隱藏進程；若 `psscan` 顯示該 PID 帶有過去的 `ExitTime`，則證實為短命進程殘留。

- [x] **Q4：如果攻擊者在傳輸資料時採用了 HTTPS (443 Port) 加密，且我們無法取得通訊封包，記憶體鑑識如何協助分析該連線傳輸了什麼？**
  > **標準答案**：
  > 1. **提取應用層明文緩衝區**：TLS 加密是在進程將資料交給 SChannel 或 OpenSSL 函式庫時才進行。在資料被加密之前（或解密之後），明文必然以緩衝區（Buffer / Heap）的形式存在於進程的使用者空間記憶體中。
  > 2. **導出進程堆疊與記憶體**：利用 `windows.memmap --dump` 導出該進程的所有私有堆疊（Heap）分頁，透過正則表達式、字串檢索或特定協定解析工具，還原外洩的明文檔案內容、SQL 查詢結果或 C2 互動式命令。
  > 3. **提取 TLS 會話金鑰**：在記憶體中定位 SSL Master Key（如 LSASS 或瀏覽器模組中的金鑰快取），將金鑰導出後可用於解密在網路端錄製的 PCAP 封包。

- [x] **Q5：在分析 `_TCP_ENDPOINT` 結構體時，如果發現某個連線的 `LocalAddress` 為 `0.0.0.0` 且 `State` 為 `LISTENING`，但所屬進程為 `rundll32.exe`，這是什麼戰術指標？**
  > **標準答案**：
  > 1. **戰術指標**：**反向綁定後門（Bind Shell / In-Memory Listener）**。
  > 2. **技術解析**：`rundll32.exe` 是 Windows 用於執行 DLL 函式的合法系統公用程式，正常情況下絕不會充當伺服器在 `0.0.0.0` 監聽所有網路介面。
  > 3. **攻擊意圖**：攻擊者透過注入或惡意參數呼叫，使 `rundll32.exe` 綁定本地連接埠等待攻擊者從外部直連連入，逃避常見的邊界出站流量檢測，屬於高危內網跳板後門。
