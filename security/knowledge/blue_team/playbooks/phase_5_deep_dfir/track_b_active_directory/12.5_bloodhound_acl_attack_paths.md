# 12.5 AD 物件權限濫用與 BloodHound 攻擊路徑阻斷 (BloodHound ACL Attack Paths & Remediation)

## 案發現場破題

在成熟的 Active Directory 企業網域環境中，攻擊者往往不需要依賴已知軟體弱點或遠端程式碼執行（RCE），僅憑網域物件（Domain Objects）與存取控制清單（Access Control Lists, ACLs / DACLs）設定疏漏，即可透過合法身分權限跳板串接出「無聲滲透路徑」，直搗 Domain Admins 核心。

```
[一般網域使用者 / 被攻陷端點]
        │ (MemberOf)
        ▼
[Domain Users / HelpDesk-Tier1]
        │
        ├── GenericAll / GenericWrite ──► [ServiceAccount-SQL]
        │                                        │
        │                                  WriteDacl / WriteOwner
        │                                        │
        │                                        ▼
        │                                 [IT-Operations-Group]
        │                                        │
        │                                 ForceChangePassword
        │                                        │
        │                                        ▼
        └──────── Shortest Path ────────► [Tier-0 Domain Admins]
```

### 痛點場景
- **攻擊面極度隱蔽**：權限濫用（如 `GenericAll`、`WriteDacl`、`WriteOwner`、`ForceChangePassword`）全程使用合法 LDAP / RPC 通訊協定，端點 EDR 與網路 IDS/IPS 極難僅依連線特徵產生告警。
- **權限配置漂移（Privilege Creep）**：企業長期運營下，為了臨時排錯、服務部署或外包支援，經常隨意將使用者加入高權限群組或委派特定 OU/物件管理權限，事後未回收，導致權限蜘蛛網無限蔓延。
- **防禦者視角盲區**：傳統稽核僅檢查「哪些帳號是 Domain Admins」，卻忽略「哪些帳號只要透過 2 到 3 步 ACL 躍遷即可成為 Domain Admins」，防禦層面完全處於被動。

## 第一動：攻防架構全景圖 (AD DACL Privilege Escalation Architecture)

Active Directory 中的每個物件（使用者、群組、電腦、GPO、OU）都擁有安全描述元（Security Descriptor），其中包含自主存取控制清單（DACL）。DACL 由多個存取控制項目（Access Control Entry, ACE）組成。

```
+-----------------------------------------------------------------------------------------------+
| Active Directory 物件安全描述元 (Security Descriptor)                                            |
|                                                                                               |
|  [ Owner SID ] : 指向該物件擁有者 (擁有寫入 DACL 之隱性特權)                                    |
|  [ Group SID ] : 網域主要群組                                                                 |
|  [ SACL ]      : 系統稽核清單 (稽核成功/失敗存取，觸發 Event ID 4662)                           |
|  [ DACL ]      : 自主存取控制清單 (定義誰擁有何種操作權限)                                      |
|       │                                                                                       |
|       ├─► ACE 1: Principal: "HelpDesk" | Type: Allow | Rights: GenericAll                     |
|       ├─► ACE 2: Principal: "DevOps"   | Type: Allow | Rights: WriteDacl                      |
|       ├─► ACE 3: Principal: "Contract" | Type: Allow | Rights: ExtendedRight (User-Force-Pwd) |
+-----------------------------------------------------------------------------------------------+
```

### 常見危險 ACE 權限與武器化手續

| 權限項目 (Active Directory Rights) | 攻擊武器化利用手法 (Weaponization) | 權限提權路徑與影響 (Impact) |
| :--- | :--- | :--- |
| **`GenericAll`** | 對目標物件擁有完全控制權。若目標為使用者，可直接重設密碼或變更 SPN；若為群組，可自由新增成員。 | 一鍵取得目標帳號或群組身分。 |
| **`GenericWrite`** | 允許修改目標物件之所有屬性（例如修改 `scriptPath`、`servicePrincipalName` 或特定敏感屬性）。 | 誘發 Kerberoasting 或設定登入劫持指令碼。 |
| **`WriteDacl`** | 允許修改目標物件的存取控制清單（DACL）。攻擊者可自我賦予 `GenericAll` 完全控制權。 | 兩階段提升為目標物件完全控制。 |
| **`WriteOwner`** | 允許變更目標物件的擁有人（Owner）。將擁有者設為自身後，利用 Owner 特權執行 `WriteDacl`。 | 三階段提升為目標物件完全控制。 |
| **`ForceChangePassword`** (`User-Force-Change-Password`) | 允許在不知曉舊密碼的情況下直接重設目標使用者密碼。 | 直接重設高權限帳號密碼並橫向接管。 |
| **`AddMember`** | 允許向目標安全群組（Security Group）中寫入新成員（如將自己加入 Administrators）。 | 直攻網域管理員特權。 |

## 第二動：紅隊攻擊路徑探測與圖論建模 (SharpHound & Neo4j Analysis)

紅隊在取得初步存取權限後，通常執行 SharpHound 收集全域物件屬性與 ACL 關聯，並利用 BloodHound (Neo4j 圖形資料庫) 快速運算最短攻擊路徑（Shortest Paths to Domain Admins）。

### 1. SharpHound 全域資料收集
```powershell
# 執行 SharpHound 收集網域內所有關聯、群組、會話與物件 ACLs
SharpHound.exe -c All,GPOLocalGroup --outputdirectory C:\ProgramData\loot --zipfilename domain_bloodhound.zip
```

### 2. Cypher 圖資料庫關鍵查詢語法
在 BloodHound / Neo4j 瀏覽器中，資安分析師可執行以下 Cypher 查詢主動探索高風險弱點：

```cypher
// 查詢所有能透過危險 ACE 直達 Domain Admins 的最短攻擊路徑
MATCH p=shortestPath((u:User)-[r:GenericAll|GenericWrite|WriteDacl|WriteOwner|ForceChangePassword|AddMember*1..5]->(g:Group {name: "DOMAIN ADMINS@CORP.LOCAL"}))
RETURN p

// 查詢非管理員帳號擁有 WriteDacl / WriteOwner 權限的受保護物件
MATCH (u:User)-[r:WriteDacl|WriteOwner]->(t)
WHERE NOT u.name ENDS WITH "ADMIN" AND t.name ENDS WITH "DC01.CORP.LOCAL"
RETURN u.name, type(r), t.name
```

## 第三動：Windows 稽核原則與日誌監控配置 (Detection Telemetry Setup)

預設情況下，Active Directory 不會記錄細緻的 DACL 存取行為。必須開啟「目錄服務存取（Directory Service Access）」進階稽核原則，並在關鍵物件上啟用 SACL。

### 1. 啟用進階稽核原則 (Advanced Audit Policy)
在 Default Domain Controllers Policy 中啟用：
- **Audit Directory Service Access**：Success & Failure
- **Audit Directory Service Changes**：Success

```powershell
# 檢驗網域控制站上的稽核原則配置狀態
auditpol /get /subcategory:"Directory Service Access"
auditpol /get /subcategory:"Directory Service Changes"
```

### 2. 關鍵稽核 Event IDs
- **Event ID 4662 (Security)**：`An operation was performed on an object`（在物件上執行了特定操作）。核心欄位包含：
  - `SubjectUserName`: 執行操作的帳號。
  - `ObjectServer`: DS (Directory Service)。
  - `ObjectType`: 物件類別 GUID（如 User: `bf967aba-0de6-11d0-a285-00aa003049e2`）。
  - `AccessMask`: 存取遮罩代碼（例如 `0x20` 為 WriteDacl, `0x40000` 為 WriteOwner）。
  - `Properties`: 存取操作的 GUID 清單（如 `00299570-246d-11d0-a7ec-00a0c9094af7` 代表 ForceChangePassword）。
- **Event ID 5136 (Security)**：`A directory service object was modified`（目錄服務物件屬性遭修改，包含新增、移除屬性值）。
- **Event ID 4728 / 4732 / 4756 (Security)**：成員被加入安全性群組（Global / Local / Universal Group）。

## 第四動：SIEM 關聯規則與即時獵捕分析 (Splunk / Sigma Rules)

### 1. Splunk SPL：偵測非授權帳號觸發 ForceChangePassword (Event ID 4662)
```spl
index=wineventlog sourcetype="WinEventLog:Security" EventCode=4662
    ObjectType="{bf967aba-0de6-11d0-a285-00aa003049e2}"
    Properties="*00299570-246d-11d0-a7ec-00a0c9094af7*"
| search NOT [
    | inputlookup authorized_it_helpdesk.csv 
    | rename username as SubjectUserName 
    | fields SubjectUserName
  ]
| eval TargetObject=ObjectName
| stats count earliest(_time) as first_time latest(_time) as last_time by SubjectUserName, TargetObject, Computer
| convert ctime(first_time) ctime(last_time)
```

### 2. Splunk SPL：監控高敏感群組成員異動 (Event ID 4728 / 4732)
```spl
index=wineventlog sourcetype="WinEventLog:Security" EventCode IN (4728, 4732, 4756)
    TargetUserName IN ("Domain Admins", "Enterprise Admins", "Schema Admins", "Administrators", "Account Operators")
| table _time, Computer, SubjectUserName, TargetUserName, MemberName, Action
```

### 3. Sigma 偵測規則：Active Directory Object DACL Tampering
```yaml
title: AD Object DACL or Owner Manipulation
id: b83c11e7-9a02-45e1-8841-3d2f9e42ac51
status: production
description: 偵測使用者嘗試修改 Active Directory 物件之 DACL (WriteDacl) 或擁有人 (WriteOwner)
logsource:
    product: windows
    service: security
detection:
    selection:
        EventID: 4662
        AccessMask|contains:
            - '0x20'      # WRITE_DAC
            - '0x40000'   # WRITE_OWNER
    filter_dc:
        SubjectUserName|endswith: '$'
    condition: selection and not filter_dc
falsepositives:
    - 網域管理員合法進行委派精靈 (Delegation Wizard) 配置變更
level: high
```

## 第五動：權限收斂、Tier 模型與動態阻斷 (Hardening & Remediation)

```
[Tier 0: 核心身分控制層 (DC, Domain Admins, PKI)]
        ▲
        │ 絕不允許向下管理或跨層存取 (Strict Boundary)
        │
[Tier 1: 企業伺服器與服務層 (Web, DB, File Server, Hyper-V)]
        ▲
        │ 嚴格劃分群組管理界線，禁止泛用 GenericAll
        │
[Tier 2: 使用者端點工作站 (Windows 11, Workstations, Laptops)]
```

### 1. 實施 Active Directory 階層化管理架構 (Enterprise Access Model / Tier Model)
- **Tier 0**：網域控制站、Domain Admins、PKI CA、Azure AD Connect 伺服器。
- **Tier 1**：應用程式伺服器、資料庫、網域成員伺服器。
- **Tier 2**：員工端點、終端裝置、印表機。
- **原則**：低層級帳號或系統嚴禁對高層級物件擁有任何寫入、管理或 ACL 存取權限。

### 2. PowerShell 清理異常 DACL 委派
若發現特定帳號被異常賦予高權限群組的 `GenericAll`，使用 `ActiveDirectory` 模組即時移除 ACE：

```powershell
Import-Module ActiveDirectory

$GroupDN = "CN=Domain Admins,CN=Users,DC=corp,DC=local"
$TargetUser = "CORP\contractor_temp"

# 取得目前群組 ACL
$Acl = Get-Acl "AD:$GroupDN"

# 尋找並移除該帳號的所有不當 Allow ACE
$RulesToRemove = $Acl.Access | Where-Object { $_.IdentityReference -eq $TargetUser }
foreach ($Rule in $RulesToRemove) {
    $Acl.RemoveAccessRule($Rule) | Out-Null
    Write-Host "[!] 已移除異常 ACE: $($Rule.ActiveDirectoryRights) 賦予給 $TargetUser" -ForegroundColor Yellow
}

# 寫回 Active Directory
Set-Acl -Path "AD:$GroupDN" -AclObject $Acl
Write-Host "[+] 成功清理 Domain Admins 異常存取控制權限！" -ForegroundColor Green
```

### 3. 開啟 AdminSDHolder 與 SDProp 自動修復機制
確保所有特權帳號（如 Domain Admins、Backup Operators）的繼承標記未被破壞，且由系統 `AdminSDHolder` 物件每 60 分鐘自動強制覆寫 DACL，杜絕任何未經授權的委派留存。

## 靶場實戰：BloodHound 攻擊路徑模擬與權限收斂驗證

### 靶場環境環境設定
- **Domain Controller**: `DC01.corp.local` (Windows Server 2022)
- **攻擊者節點**: `Workstation-05` (已淪陷一般使用者帳號 `jerry_intern`)
- **跳板帳號**: `svc_backup` (被配置對 `IT-Admins` 群組擁有 `WriteDacl`)
- **終極目標**: `Domain Admins` 群組

### 實戰步驟一：檢驗弱點與攻擊路徑建立
1. 攻擊者在 `Workstation-05` 上使用 BloodHound 發現路徑：
   `jerry_intern` -> (GenericAll) -> `svc_backup` -> (WriteDacl) -> `IT-Admins` -> (MemberOf) -> `Domain Admins`。
2. 攻擊者利用 PowerView 修改 `IT-Admins` 的 DACL，將 `jerry_intern` 賦予 `AddMember` 權限：
   ```powershell
   Add-DomainObjectAcl -TargetIdentity "IT-Admins" -PrincipalIdentity "jerry_intern" -Rights AddMember
   ```

### 實戰步驟二：SOC 監控觸發與事件獵捕
1. DC 觸發 Event ID 4662（AccessMask 包含 `0x20` WriteDacl，主體為 `svc_backup`）。
2. DC 觸發 Event ID 4728（`jerry_intern` 將自身加入 `IT-Admins`）。
3. SIEM 關聯規則警報觸發：「Non-Admin Principal modified Sensitive Group DACL」。

### 實戰步驟三：應變阻斷與鑑識復原
1. **立即凍結涉案帳號**：
   ```powershell
   Disable-ADAccount -Identity "jerry_intern"
   Disable-ADAccount -Identity "svc_backup"
   ```
2. **清除異常群組成員**：
   ```powershell
   Remove-ADGroupMember -Identity "IT-Admins" -Members "jerry_intern" -Confirm:$false
   ```
3. **執行權限審計與修復腳本**，重設 `IT-Admins` 之安全描述元為預設繼承模板。

## 過關驗收：實戰能力檢核清單 (Mastery Checklist)

- [ ] **圖論獵捕**：熟練撰寫 Neo4j Cypher 查詢語法，能自主搜尋最短攻擊路徑並繪製權限拓撲圖。

- [ ] **防禦實施**：能在 Active Directory 中規劃並落實 Tier 0/1/2 階層模型，移除跨層級危險 ACE 委派。
- [ ] **自動化修復**：能使用 PowerShell `Get-Acl` 與 `Set-Acl` 自動檢索並清除高敏感群組中不合規的存取控制項目。
