# 13.3 服務帳號權限濫用與 Azure AD PRT 權杖劫持防護 (Service Account & Primary Refresh Token Abuse)

## 案發現場破題

在混合雲端與 Active Directory 現代化架構下，身分邊界已高度延伸至端點作業系統的單一登入（SSO）機制與背景自動化服務帳號（Service Accounts）。攻擊者在獲得工作站本機權限後，最具破壞力的橫向移動手法之一便是：
1. **Pass-the-PRT（劫持主要重新整理權杖）**：從 Windows 端點提取或利用 LSASS / CloudAP 記憶體中的 Primary Refresh Token (PRT)，在不需輸入帳號密碼與通過 MFA 的情況下，無縫化身為受害使用者存取所有 Azure AD / Microsoft 365 雲端資源。
2. **服務主體與服務帳號濫用（Service Principal & Managed Identity Abuse）**：鎖定企業 CI/CD 流水線、內部自動化腳本或配置於伺服器上的 Managed Identities，竊取長效 Client Secret 或高權限認證憑證，發動 API 層級的全面接管。

```
[攻擊者控制之淪陷端點]
        │
        ├── 透過 Mimikatz / AADInternals 呼叫 TPM / CloudAP API
        ▼
[Windows 端點本機之 Primary Refresh Token (PRT)]
        │
        ├── 生成由本機 Session Key 簽署的 PRT Cookie (x-ms-RefreshTokenCredential)
        ▼
[Microsoft Entra ID 身分驗證端點]
        │
        └── 繞過條件式存取 MFA 限制，取得 Exchange / SharePoint / Azure Portal 存取權限
```

### 痛點場景
- **原生單一登入架構的隱性代價**：PRT 旨在提供順暢的使用者體驗，然而若端點缺乏硬體層級 TPM 保護與 VBS（虛擬化型安全性），攻擊者能直接透過本機系統權限（SYSTEM）濫用 CloudAP 服務簽發 PRT Cookie。
- **服務帳號缺乏生命週期管理**：許多企業內部應用程式與自動化服務使用永久有效的 Client Secret 或設定過寬的 API 權限（如 `Directory.ReadWrite.All`），一旦伺服器硬碟或程式碼外洩，攻擊者即可長期常駐。
- **檢測難度極高**：Pass-the-PRT 連線特徵來自受害者平時正常使用的作業系統與網路環境，日誌呈現完全合法的裝置狀態與使用者身分，傳統防護難以判斷為異常。

## 第一動：PRT 架構與服務主體鑑識原理 (PRT Architecture & Service Principals)

```
+-----------------------------------------------------------------------------------------------+
| Windows 端點 Primary Refresh Token (PRT) 安全架構                                              |
|                                                                                               |
|  [ 使用者登入 / 註冊裝置 ] ──► 由 Entra ID 簽發 PRT (受 TPM 綁定)                             |
|                                                                                               |
|  [ 本機儲存結構 ]                                                                             |
|    - PRT (JWT): 儲存於 LSASS 程序的 CloudAP 外掛中                                            |
|    - Session Key: 由 TPM (Trusted Platform Module) 加密保護                                  |
|                                                                                               |
|  [ SSO 請求發起 ]                                                                             |
|    - 瀏覽器 / 應用程式請求 Token ──► CloudAP 呼叫 TPM 簽署目前時間戳與隨機數 (Nonce)           |
|    - 輸出: x-ms-RefreshTokenCredential (PRT Cookie) 傳送至 login.microsoftonline.com         |
+-----------------------------------------------------------------------------------------------+
```

### 關鍵威脅利用手法

| 身分機制 | 攻擊手法名稱 (TTP) | 威脅利用原理與影響 (Mechanism & Impact) |
| :--- | :--- | :--- |
| **Entra ID PRT** | **Pass-the-PRT (T1539 / T1550)** | 攻擊者在目標端點以 SYSTEM 權限運行工具，透過本機 RPC 呼叫 CloudAP 介面，借用本機 TPM 簽署生成合法的 PRT Cookie。 |
| **Entra ID PRT** | **PRT Extraction (軟體加密金鑰)** | 在未配備 TPM 的舊型虛擬機或工作站上，PRT Session Key 以 DPAPI 軟體加密。攻擊者可直接匯出金鑰，將 PRT 複製至外部攻擊機重放。 |
| **服務主體** | **Service Principal Credential Addition** | 攻擊者在取得應用程式管理員特權後，向目標 App 注入新的 Client Secret 或 X.509 憑證，建立持續性隱密後門。 |
| **受控身分** | **Azure Managed Identity Theft** | 攻擊者攻陷雲端 VM 後，向本機 Instance Metadata Service (IMDS: `http://169.254.169.254`) 讀取 OAuth Access Token。 |

## 第二動：紅隊利用模擬與權杖竊取重現 (Attack Emulation: Pass-the-PRT & IMDS)

### 1. 本機端點生成 PRT Cookie (利用 AADInternals / Mimikatz)
在已淪陷的已加入 Azure AD 裝置上，以當前使用者或管理員身分呼叫 CloudAP 生成 PRT Cookie：
```powershell
# 使用 AADInternals 生成用於瀏覽器的 PRT Cookie
Import-Module AADInternals
$PrtCookie = New-AADIntUserPRTCookie -ClearCache
Write-Host "[+] 成功取得 PRT Cookie (x-ms-RefreshTokenCredential):" -ForegroundColor Green
$PrtCookie
```

### 2. 雲端伺服器 IMDS 提取受控身分 (Managed Identity) 權杖
若攻擊者在具有受控身分（Managed Identity）的 Azure Linux / Windows 虛擬機取得 Web Shell：
```bash
# 向內部非繞送 IP (IMDS) 請求 Azure Resource Manager 的存取權杖
curl -s -H "Metadata:true" "http://169.254.169.254/metadata/identity/oauth2/token?api-version=2018-02-01&resource=https://management.azure.com/" | jq .
```

## 第三動：日誌遙測設定與審計配置 (Telemetry Setup: CloudAP & ServicePrincipals)

### 1. 端點 Windows 事件日誌配置
監控端點針對 CloudAP 與 LSASS 的異常存取行為：
- **`Microsoft-Windows-AAD/Operational`**：
  - Event ID 1097 / 1098：CloudAP 處理 PRT 權杖請求之成功與錯誤資訊。
- **Sysmon Event ID 10 (ProcessAccess)**：
  - 監控非系統正常處理程序（如未知的 PowerShell, Cmd, 第三方執行檔）對 `lsass.exe` 進行具有 `0x1010` 或 `PROCESS_VM_READ` 的存取。

### 2. Entra ID 審計與登入日誌遙測
- **`ServicePrincipalSignInLogs`**：專門記錄應用程式金鑰或憑證登入事件，特別注意非預期的來源 IP。
- **`AuditLogs`** 關鍵事件：
  - `Add service principal credentials`（向應用程式新增憑證金鑰）。
  - `Update application – Certificates and secrets management`。

## 第四動：SIEM 關聯規則與威脅獵捕 (Splunk & Sigma Detection Rules)

### 1. Splunk SPL：偵測服務主體被異常新增憑證金鑰 (Credential Addition)
```spl
index=azure_ad sourcetype="azure:aad:audit" OperationName="Add service principal credentials"
| eval Initiator=InitiatedBy.user.userPrincipalName, AppDisplayName=TargetResources{}.displayName
| stats count earliest(_time) as first_time latest(_time) as last_time by Initiator, AppDisplayName, OperationName, correlationId
| convert ctime(first_time) ctime(last_time)
| table first_time, last_time, Initiator, AppDisplayName, OperationName
```

### 2. Splunk SPL：偵測服務主體來自異常來源 IP 的 API 呼叫 (Service Principal Anomaly)
```spl
index=azure_ad sourcetype="azure:aad:serviceprincipal" ResultType=0
| stats count earliest(_time) as first_seen latest(_time) as last_seen 
        values(IPAddress) as SrcIPs, values(Location) as Locations by ServicePrincipalName, AppId
| where mvcount(SrcIPs) > 3 OR NOT match(SrcIPs, "^(10\.|192\.168\.|172\.(1[6-9]|2[0-9]|3[0-1])\.)")
| convert ctime(first_seen) ctime(last_seen)
```

### 3. Sigma 偵測規則：Suspect LSASS Access for CloudAP PRT Secrets
```yaml
title: Potential CloudAP PRT Memory Dumping from LSASS
id: 5e91aa74-8890-410a-b18c-f09320d91244
status: production
description: 偵測非正常程序存取 LSASS 記憶體嘗試提取 PRT 資訊
logsource:
    category: process_access
    product: windows
detection:
    selection:
        TargetImage|endswith: '\lsass.exe'
        GrantedAccess|contains:
            - '0x1010'
            - '0x1F0FFF'
            - '0x1410'
    filter_legit:
        SourceImage|endswith:
            - '\csrss.exe'
            - '\MsMpEng.exe'
    condition: selection and not filter_legit
level: high
```

## 第五動：身分架構防禦加固與硬體綁定 (Hardening & Mitigation)

```
[端點防護升級]                                     [雲端存取限制]
  ├─ 啟用 TPM 2.0 與 Credential Guard       ──►      ├─ Token Protection for Sign-ins
  ├─ 啟用 Windows Defender Exploit Guard             ├─ 服務主體限制指定 IP 存取
  └─ 阻斷 IMDS 169.254.169.254 本機外聯              └─ 自動化輪替 Client Secrets (30天)
```

### 1. 啟用權杖保護 (Token Protection for Conditional Access)
啟用 Entra ID 的「Token Protection（Proof-of-Possession）」功能。此功能強制將 PRT 及其簽發的 Access Token 與端點的 TPM 2.0 硬體密碼金鑰深度綁定。即便攻擊者透過遠端連線或竊取到 PRT Cookie，在未具備相同實體 TPM 硬體私鑰的情況下，任何重放存取都將被身分驗證伺服器直接拒絕。

### 2. 封裝與阻斷雲端端點存取 IMDS
在公有雲（Azure/AWS）伺服器端點上，限制一般應用程式存取中繼資料伺服器：
```bash
# 透過本機 iptables 防火牆限制僅允許特定系統帳號存取 169.254.169.254
iptables -A OUTPUT -m owner ! --uid-owner 0 -d 169.254.169.254 -j DROP
```

### 3. 清理與輪替過期或異常服務主體金鑰 (PowerShell)
```powershell
Import-Module Microsoft.Graph.Applications

$AppId = "00000000-0000-0000-0000-000000000000"

# 取得應用程式現有所有憑證金鑰
$App = Get-MgApplication -ApplicationId $AppId
foreach ($Key in $App.PasswordCredentials) {
    if ($Key.EndDateTime -lt (Get-Date).AddDays(15)) {
        Write-Host "[!] 金鑰即將過期或存在風險，執行移除: $($Key.KeyId)" -ForegroundColor Yellow
        Remove-MgApplicationPassword -ApplicationId $AppId -KeyId $Key.KeyId
    }
}
Write-Host "[+] 服務主體認證金鑰清理與審計完成！" -ForegroundColor Green
```

## 靶場實戰：Pass-the-PRT 異常橫向移動應變

### 靶場環境情境
- **受害端點**: `WIN11-SALES-02`
- **受害帳號**: `alice_sales@corp.com`
- **警報觸發**: SOC 警報系統發現 `alice_sales` 在 5 分鐘內分別於台北辦公室與未知的雲端虛擬機 IP（荷蘭）發起對 SharePoint Online 機密報價單的連續下載。

### 實戰步驟一：鑑識分析與特徵比對
1. 調閱 `SignInLogs`，發現荷蘭 IP 的登入要求帶有完整的合規裝置宣告（Device Compliant = True），且無 MFA 挑戰紀錄。
2. 比對該登入之 User-Agent，發現為 Linux cURL 客戶端，與受害者的 Windows 11 Edge 明顯衝突，確認為 PRT 權杖遭竊取後重放。

### 實戰步驟二：即時阻斷處置
1. **撤銷該使用者所有已簽發之全域 Token**：
   ```powershell
   Revoke-MgUserSignInSession -UserId "alice_sales@corp.com"
   ```
2. **在端點實施隔離**，中斷 `WIN11-SALES-02` 的網路連線，防止本機惡意程式持續呼叫 CloudAP 重新生成 PRT Cookie。

### 實戰步驟三：全面加固
1. 在 Entra ID 條件式存取原則中，將「SharePoint Online」與「Exchange Online」納入 **Token Protection (Token Binding)** 強制套用範圍。
2. 在所有公司端點開啟 Windows Credential Guard，將 Kerberos/CloudAP 金鑰隔離於 Hyper-V 虛擬化空間內。
