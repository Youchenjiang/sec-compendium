# 02.2 內部網路微隔離與 VLAN 存取控制 (Internal Network Microsegmentation & Zero Trust Isolation)

## 案發現場破題

在傳統以邊界為核心（Perimeter-centric）的網路架構中，企業往往將重點放在南北向（North-South）防火牆上，內部網路（東西向 East-West）則呈現高度互通的扁平化（Flat Network）狀態。一旦外部攻擊者突破邊界（如 DMZ 區的 Web 伺服器遭 RCE 攻陷），即可在缺乏任何內部阻斷機制的內網中如入無人之境，透過 ARP 欺騙、橫向 SMB/RDP 掃描與憑證傳遞（Pass-the-Hash），於數十分鐘內擴散至核心資料庫與網域控制站。

```
[外部網際網路]
       │
       ▼ (通過南北向防火牆)
+-------------------------------------------------------------------------------+
| DMZ 區：Web 應用伺服器 (遭攻陷)                                               |
+-------------------------------------------------------------------------------+
       │
       ├── 傳統扁平內網：無微隔離 ──► 自由連線內部核心資料庫 (SQL / Oracle)
       ├── 傳統扁平內網：無微隔離 ──► 自由連線工控核心 (SCADA / PLC)
       │
       ▼ 【微隔離 Zero Trust 防禦落地】
+-------------------------------------------------------------------------------+
| 東西向微隔離控制點 (Host-based Firewalls / Distributed Firewall / SDN)        |
|  - 預設拒絕 (Default Deny)                                                   |
|  - 僅允許指定來源 IP:Port (TCP 3306 經雙向 TLS)                                |
|  - 阻斷未授權之 ICMP 探測、RPC、SMB 橫向擴散                                  |
+-------------------------------------------------------------------------------+
       │
       ▼ (被嚴密阻斷並觸發 SOC 高危告警)
[內部核心資料庫 / 網域控制站]
```

### 痛點場景
- **東西向橫向移動失控**：內網機器之間完全信任，攻擊者取得單一工作站權限後，能輕易對全網段進行 `nmap -sS -p 445,3389` 大規模掃描而不受任何網路層阻擋。
- **DMZ 與內部機敏區界線模糊**：Web 伺服器往往被過度開放存取底層資料庫或內部 API，缺乏依據應用程式身分的細粒度微隔離。
- **傳統硬體防火牆瓶頸**：若將所有內部虛擬機（VM）或容器的流量全數繞經實體防火牆進行過濾（Hairpinning / 髮夾彎流量），將引發嚴重的網路延遲與吞吐量崩潰。

## 第一動：微隔離技術架構與零信任模型 (Microsegmentation Architecture)

微隔離的核心精神在於**將安全周界推進到每個工作負載（Workload）、虛擬機、容器或端點層級**，徹底實施「持續驗證、永不信任（Never Trust, Always Verify）」的最小權限原則。

```
+-----------------------------------------------------------------------------------------------+
| 微隔離實施層級對比                                                                             |
|                                                                                               |
| 1. 網路層隔離 (Network-level: VLAN / ACL / VRF)                                                |
|    - 控制顆粒度：子網段 (Subnet / CIDR)                                                       |
|    - 優缺點：依賴實體或虛擬交換機，配置繁瑣，無法抵禦同子網內的橫向攻擊。                    |
|                                                                                               |
| 2. 主機核心層隔離 (Host-based: iptables / nftables / Windows Filtering Platform WFP)          |
|    - 控制顆粒度：個別主機 / 程序 / 使用者身分                                                 |
|    - 優缺點：不依賴底層網路拓撲，可精確控制行程與連接埠，但需具備端點統一派送引擎。          |
|                                                                                               |
| 3. 雲原生 / 服務網格隔離 (Cloud-Native: K8s NetworkPolicy / Cilium eBPF / Envoy Service Mesh) |
|    - 控制顆粒度：Pod 標籤 (Labels) / 身分服務主體 (SPIFFE ID) / L7 API 路徑                    |
|    - 優缺點：動態自適應彈性擴縮，支援 L7 協定解析，適用於微服務現代化架構。                  |
+-----------------------------------------------------------------------------------------------+
```

### 核心防禦矩陣：東西向存取控制基線

| 隔離維度 | 合法允許通行基準 (Allowlist) | 嚴格阻斷與監控特徵 (Strict Deny & Alert) |
| :--- | :--- | :--- |
| **DMZ ➔ 內部資料庫** | 僅允許 Web 伺服器叢集指定 IP 存取特定資料庫 Port（如 TCP 3306/5432），其餘全面阻絕。 | 任何來自 DMZ 伺服器對內部網路發起的 SSH (22)、RDP (3389)、SMB (445) 連線。 |
| **辦公區 ➔ 伺服器區** | 僅允許透過跳板機（Bastion Host / PAM）進行管理維護，使用者工作站不得直連生產端。 | 終端工作站直連生產環境伺服器管理連接埠。 |
| **辦公區 ➔ 辦公區** | 預設 **用戶端完全隔離（Client-to-Client Isolation）**，禁止一般端點彼此通訊。 | 同一辦公網段內出現未授權之橫向廣播、ARP 探測、IPC$ 存取。 |

## 第二動：主機防火牆與微隔離策略配置 (iptables, nftables & Windows Advanced Firewall)

### 1. Linux 生產伺服器最小權限微隔離 (iptables 腳本)
確保該主機僅能與指定的 Web 負載均衡器與資料庫通訊，全面關閉東西向自由探測：

```bash
#!/bin/bash
# 內部微隔離防火牆重設與基線套用
iptables -F
iptables -X
iptables -t nat -F

# 1. 預設策略：進出與轉發全面拒絕 (Default Deny)
iptables -P INPUT DROP
iptables -P FORWARD DROP
iptables -P OUTPUT DROP

# 2. 允許本機迴路 (Loopback)
iptables -A INPUT -i lo -j ACCEPT
iptables -A OUTPUT -o lo -j ACCEPT

# 3. 狀態連線追蹤：允許已建立之連線通過
iptables -A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
iptables -A OUTPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT

# 4. 東西向微隔離受控存取 (僅允許指定 DMZ 節點存取應用 API: 8080)
iptables -A INPUT -p tcp -s 10.10.10.50 --dport 8080 -m conntrack --ctstate NEW -j ACCEPT

# 5. 出向受控：僅允許連線至專屬資料庫 (10.20.10.100:5432)
iptables -A OUTPUT -p tcp -d 10.20.10.100 --dport 5432 -m conntrack --ctstate NEW -j ACCEPT

# 6. 記錄未授權之內部橫向掃描並阻斷
iptables -A INPUT -m limit --limit 5/min -j LOG --log-prefix "[MICROSEG_VIOLATION_IN]: " --log-level 4
iptables -A OUTPUT -m limit --limit 5/min -j LOG --log-prefix "[MICROSEG_VIOLATION_OUT]: " --log-level 4
```

### 2. Windows 進階防火牆：啟用端點客戶端隔離 (PowerShell)
在工作站網段強制阻斷端點間的 SMB (445) 與 RPC (135) 互連：
```powershell
# 建立群組原則或本機防火牆規則：禁止同網段工作站互連 445 與 135
New-NetFirewallRule -DisplayName "MicroSeg-Block-Inbound-SMB-From-LocalSubnet" `
    -Direction Inbound `
    -LocalPort 445,135 `
    -Protocol TCP `
    -RemoteAddress LocalSubnet `
    -Action Block `
    -Profile Domain,Private

Write-Host "[+] 成功啟用本機網段 SMB/RPC 橫向移動封鎖策略！" -ForegroundColor Green
```

## 第四動：SIEM 關聯規則與即時獵捕分析 (Splunk & Sigma Rules)

### 1. Splunk SPL：偵測內部跨網段或未授權微隔離違規 (Microsegmentation Violation)
```spl
index=firewall sourcetype="paloalto:traffic" action=blocked
    src_zone="DMZ" dest_zone IN ("Internal-DB", "PCI-Core", "Domain-Controllers")
| stats count earliest(_time) as first_time latest(_time) as last_time 
        values(dest_port) as TargetPorts by src_ip, dest_ip, app
| where count >= 5
| convert ctime(first_time) ctime(last_time)
| table first_time, last_time, src_ip, dest_ip, TargetPorts, app, count
```

### 2. Splunk SPL：偵測同一工作站子網內的高頻橫向探測 (Workstation Port Scan)
```spl
index=endpoint_firewall action=DROP
| bin _time span=5m
| stats dc(dest_ip) as ScannedHosts, count as TotalDrops by _time, src_ip
| where ScannedHosts > 10
| table _time, src_ip, ScannedHosts, TotalDrops
```

### 3. Sigma 偵測規則：Lateral Movement Attempt Blocked by Microsegmentation
```yaml
title: Unauthorized Lateral Movement Blocked by Microsegmentation
id: 3c7a1029-4d82-411a-82ef-990a82741121
status: production
description: 偵測受保護核心網段觸發之跨區未授權存取阻斷事件
logsource:
    category: firewall
    product: network
detection:
    selection:
        action: 'block'
        src_subnet: '10.10.10.0/24' # DMZ Subnet
        dest_subnet: '10.20.10.0/24' # Core DB Subnet
    filter_known_ports:
        dest_port:
            - 5432
    condition: selection and not filter_known_ports
level: high
```

## 第五動：零信任動態隔離與處置加固 (Zero Trust Hardening & Incident Containment)

```
[SOC 告警觸發] ──► [SOAR / 網路自動化腳本]
                          │
                          ├── 1. 查詢端點身分與 MAC / IP 對應
                          ├── 2. 觸發 SDN 控制器 (Cisco ACI / VMware NSX / OpenFlow)
                          ▼
                 [動態變更微隔離安全群組 ➔ 隔離隔離網段 (Quarantine ESG)]
```

### 1. 動態網路隔離處置 (Dynamic Host Isolation via iptables)
當特定主機被確認淪陷時，安全運維團隊應立即執行自動化隔離腳本，僅保留 SOC 調查管理通道，切斷其餘一切對外與對內連線：

```bash
#!/bin/bash
# 應急網路切斷腳本 (緊急隔離，保留鑑識通道)
SOC_JUMP_HOST="10.99.1.50"

iptables -F
iptables -P INPUT DROP
iptables -P OUTPUT DROP
iptables -P FORWARD DROP

# 僅允許 SOC 鑑識專用跳板機進行 SSH (Port 22) 存取
iptables -A INPUT -p tcp -s $SOC_JUMP_HOST --dport 22 -j ACCEPT
iptables -A OUTPUT -p tcp -d $SOC_JUMP_HOST --sport 22 -j ACCEPT

echo "[!] 主機已完全自內網微隔離！僅允許鑑識跳板機 $SOC_JUMP_HOST 通訊。"
```

### 2. 跨虛擬機與容器微隔離實踐 (Kubernetes NetworkPolicy)
在容器化環境中，限制前端 Pod 僅能存取特定後端：
```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: api-allow-db-only
  namespace: production
spec:
  podSelector:
    matchLabels:
      app: web-api
  policyTypes:
  - Egress
  egress:
  - to:
    - podSelector:
        matchLabels:
          app: postgres-db
    ports:
    - protocol: TCP
      port: 5432
```

## 靶場實戰：DMZ 滲透阻斷與微隔離防線驗證

### 靶場環境情境
- **Web-DMZ 主機**: `10.10.10.50` (安裝 Tomcat 服務，遭攻擊者利用漏洞植入 WebShell)
- **核心資料庫**: `10.20.10.100` (PostgreSQL，僅允許 `10.10.10.50:5432`)
- **網域控制站**: `10.20.10.10` (Windows Server DC01)

### 實戰步驟一：攻擊者嘗試發動內網橫向探測
1. 攻擊者在 WebShell 中執行 `fscan -h 10.20.10.0/24 -p 22,445,3389,1433,3306,5432`。
2. 探測封包撞擊主機微隔離防火牆規則，除 `10.20.10.100:5432` 外，其餘所有 TCP SYN 請求均被直接 DROP。

### 實戰步驟二：SOC 監控觸發與研判
1. SIEM 在 60 秒內收到 50 筆來自 `10.10.10.50` 的 `[MICROSEG_VIOLATION_OUT]` 核心日誌。
2. 分析師確認 Web 伺服器絕不可能向 DC01 發起 SMB/RPC 請求，研判為 True Positive 入侵後探測。

### 實戰步驟三：動態微隔離執行與防禦升級
1. 呼叫自動化腳本，將 `10.10.10.50` 的出向資料庫存取權限暫停，並移入鑑識隔離網段。
2. 進行 WebShell 清理與系統漏洞修補。

## 過關驗收：實戰能力檢核清單 (Mastery Checklist)

- [ ] **觀念認知**：能清晰說明南北向邊界防禦與東西向微隔離在遏阻內網橫向擴散上的本質差異。
- [ ] **策略規劃**：能針對 DMZ 區、辦公區與資料庫核心區制定 Default-Deny 的最小權限網路微隔離矩陣。
- [ ] **防火牆實作**：能熟練使用 Linux iptables / nftables 或 Windows 進階防火牆，封鎖同網段端點之間的未授權互連（如 445 / 135）。
- [ ] **日誌稽核分析**：能解讀防火牆 Dropped / Violation 日誌，並在 SIEM 中建立橫向探測高精確度告警。
- [ ] **容器隔離防禦**：能編寫 Kubernetes NetworkPolicy，精確限制 Pod 層級的東西向通訊流量。
