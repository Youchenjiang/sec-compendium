# 📐 藍隊原子實戰手冊 (Atomic Playbook) 撰寫黃金標準與模板

---

## 📌 宗旨與核心約束 (The Golden Mandate)
本規範為專案內所有技術點手冊（`playbooks/*/*.md`）的**唯一法定撰寫標準**。
任何手冊均不得偷工減料、不得僅列章節骨架、不得使用無法運行的偽代碼。每份手冊必須兼具**「引人入勝的案發現場偵探敘事流（Narrative）」**與**「字典級嚴謹速查表（Reference）」**。

---

## 🏗️ 實戰手冊標準 7 大區塊架構

每份手冊必須且僅能由以下 7 個標準區塊依序構成：

```
📘 實戰手冊 [技術編號]：[技術名稱]
├── 🚨 案發現場破題 (The Incident Scenario) & 調查心智脈絡流圖
├── 🧩 第一動：底層機制/協定解剖 (Mechanics & Data Structures)
├── 🧭 第二動：解碼意圖——異常特徵與攻擊手法速查表 (3 欄式速查表)
├── 💻 第三動：現場追兇——作戰指令與腳本庫 (Operational Cheatsheet)
├── ⚖️ 第四動：研判分水嶺——真實威脅 vs 業務誤報 (SOC 8 問 2 欄表 + 決策樹)
├── 🛡️ 第五動：處置圍堵與系統加固 SOP (Mitigation & Hardening)
├── 🎯 靶場實戰檢驗 (Hands-on Lab Walkthrough)
└── 📋 過關驗收檢查點 (Mastery Checklist - 5 道高難度實戰自測題)
```

---

## 📋 各區塊詳細規格與撰寫準則

### 1. 🚨 案發現場破題 (The Incident Scenario)
- **情境帶入**：拒絕空泛開場。必須設定具體的時間（如週二凌晨 03:14）、受害主機（如 `SRV-FINANCE-01`）與真實告警特徵。
- **痛點引出**：點出分析師面臨的核心矛盾（如：內容全加密如何抓木馬？為什麼正常服務沒掛但用戶連不進來？）。
- **心智脈絡圖**：必須繪製 ASCII 調查心智脈絡流（`[調查心智脈絡流] 🚨 接到警報 ➔ 🔍 第一動 ➔ 🧭 第二動 ➔ 💻 第三動 ➔ ⚖️ 第四動 ➔ 🛡️ 第五動`）。

---

### 2. 🧩 第一動：底層機制/協定解剖 (Mechanics)
- **拒絕抽象名詞**：必須把封包標頭、Windows 事件 XML 結構、Linux `/proc` 檔案系統或協定狀態機的**真實物理結構**畫出來。
- **維度拆解**：圈出日誌或封包中的核心關鍵欄位（誰發起、目標是誰、錯誤碼、連線參數），說明各欄位的底層含義。

---

### 3. 🧭 第二動：解碼意圖——異常特徵速查表（★ 嚴格 3 欄式規範）
表格欄位**禁止隨意增減**，必須嚴格遵守以下 3 欄邏輯：

| 封包與日誌特徵現象（看到什麼） | 底層成因與攻擊手法（是什麼攻擊） | 威脅影響與處置優先級（怎麼應對） |
| :--- | :--- | :--- |
| **肉眼直接看到的特徵** | **協定/系統層物理機制與攻擊命名** | **業務影響、攻擊後續與處理優先級** |

---

### 4. 💻 第三動：現場追兇——作戰指令庫 (Operational Cheatsheet)
- **全為生產級可執行指令**：
  - Windows：使用 `Get-WinEvent` 搭配 `FilterHashtable` 或 XML 查詢，禁止使用龜速的 `Get-EventLog` 或後端 `Where-Object`。
  - 網路：Wireshark 精準 Display Filter 語法、Tshark 命令列統計。
  - Linux：原生 `/proc` 查驗、`ss` 狀態聚合、套件校驗和（`dpkg -V` / `rpm -V`）。
  - SIEM：提供開箱即用的 Splunk SPL 語法（包含 `stats` 聚合、關聯查詢）。

---

### 5. ⚖️ 第四動：研判分水嶺（★ 嚴格 2 欄式 SOC 8 問 + 決策樹）
- **SOC 8 大黃金研判問題對照表**：必須將研判維度與問句合併為第 1 欄，嚴格遵守以下 2 欄式：

| 核心提問（研判維度） | 本技術點實戰檢核標準 |
| :--- | :--- |
| **Q1. 觸發原因**（為何會發出此警報？） | 具體時間窗口內的頻率、次數、統計偏離基準。 |
| **Q2. 來源實體**（誰/哪個 IP 觸發的？） | 內網、外網、VPN 段、資產歸屬排查。 |
| **Q3. 目標對象**（攻擊目標是誰？） | 受害主機/帳號特權層級與業務重要度。 |
| **Q4. 失敗/異常本質**（異常原因是什麼？） | 代碼、旗標、文字特徵之深度比對。 |
| **Q5. 途徑與手段**（透過何種管道連入？） | 通訊埠、連線協定、進程親緣樹。 |
| **Q6. 攻擊成果**（攻擊是否已得逞？） | 致命轉折點：失敗後是否出現成功、是否已取得 Shell/憑證。 |
| **Q7. 橫向波及**（是否有多台主機受害？） | 全網 SIEM 關聯該來源是否存在其他探測。 |
| **Q8. 處置動作**（下一步是什麼？） | 未遂處置 vs 失陷應變 SOP。 |

- **視覺化研判決策樹**：必須附上清晰的 ASCII 決策分支樹（正常業務/過期憑證 vs 惡意攻擊）。

---

### 6. 🛡️ 第五動：處置圍堵與系統加固 SOP (Mitigation & Hardening)
- 分為**「未遂阻斷」**與**「已失陷處置」**。
- 嚴格依循 PICERL 圍堵原則（斷網隔離、權杖撤銷、進程凍結 `kill -STOP`、GPO 基線下發）。

---

### 7. 🎯 靶場闖關 & 📋 五題驗收檢查點
- **精準靶場任務**：指向真實公開的靶場（CyberDefenders, TryHackMe, OverTheWire, SadServers, Wireshark Sample Captures），列出 3~4 項具體作戰目標。
- **過關驗收檢查點**：必須設計 **5 道高難度實戰檢驗題**（涵蓋底層原理、鑑識盲區、進階繞過與應變決策），作為通關自我考核。
