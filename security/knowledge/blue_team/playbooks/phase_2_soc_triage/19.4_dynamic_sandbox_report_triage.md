五分鐘後，沙箱生成了一份長達 40 頁的動態行為報告，內容包含：
1. **進程樹 (Process Tree)**：`EXCEL.EXE` 衍生出 `cmd.exe`，隨後呼叫 `powershell.exe -enc ...`，最後啟動 `regsvr32.exe`。

## 🧩 第一動：底層機制/協定解剖 (Mechanics & Sandbox Architecture)

### 2.1 動態沙箱工作原理與監控機制 (Hooking & Hypervisor Telemetry)
現代高階動態沙箱（如 CAPEv2）主要透過兩種核心技術截獲惡意程式行為：

1. **使用者態/核心態 API 掛鉤 (API Hooking via Inline Patching)**：
   沙箱在啟動目標樣本前，將監控 DLL（如 CAPE agent DLL）注入至每個進程空間中。透過替換 Windows 核心 API（如 `ntdll.dll` 中的 `NtCreateFile`, `NtAllocateVirtualMemory`, `NtProtectVirtualMemory`）的開頭 5 個位元組為 `JMP <MonitorHandler>`，實現即時攔截參數並記錄調用堆疊。

2. **虛擬機監視器與核心層捕獲 (Hypervisor / Kernel Driver Telemetry)**：
   為防範惡意程式自行修復 `ntdll.dll` 記憶體（Unhooking 技術），沙箱結合 QEMU/KVM、VirtualBox 或 Windows 核心驅動程式，透過 EPT (Extended Page Tables) 違例攔截記憶體寫入，或在核心層利用 `ObRegisterCallbacks` 與 `PsSetCreateProcessNotifyRoutineEx` 捕捉進程與執行緒創建。

### 2.2 核心進程注入簽章的物理剖析 (Process Injection Triage)
沙箱報告中最致命的警報往往是進程注入。鑑識員必須讀懂以下底層 API 呼叫鏈：

```
[ Attacker Process (e.g. regsvr32.exe) ]          [ Target Process (e.g. explorer.exe) ]
                  │                                                   │
                  ├──── 1. OpenProcess(PROCESS_ALL_ACCESS, PID) ─────►│ (取得目標進程句柄)
                  │                                                   │
                  ├──── 2. VirtualAllocEx(PAGE_EXECUTE_READWRITE) ───►│ (在目標進程開闢 RWX 記憶體)
                  │                                                   │
                  ├──── 3. WriteProcessMemory(Buffer, Shellcode) ────►│ (將惡意 Payload 寫入目標空間)
                  │                                                   │
                  └──── 4. CreateRemoteThread(TargetAddr, Parameter) ─►│ (在目標進程啟動獨立執行緒執行)
                                                                      ▼
                                                       [ 執行惡意代碼，連外 C2 ]
```

- **Process Hollowing (進程挖空)**：`CreateProcess(CREATE_SUSPENDED)` ➔ `NtUnmapViewOfSection` (卸載合法代碼) ➔ `VirtualAllocEx` ➔ `WriteProcessMemory` ➔ `SetThreadContext` ➔ `ResumeThread`。
- **QueueUserAPC (早鳥注入 Early Bird)**：在目標進程主執行緒尚未執行初始化前，利用 `QueueUserAPC` 將 Shellcode 加入非同步程序呼叫佇列，規避 EDR 的 API Hook。

### 2.3 反沙箱與規避技術物理特徵 (Evasion Tactics)
惡意程式通常會在前 30 秒執行環境偵測，若發現處於沙箱環境則靜默退出 (No-op)：
- **時間延遲規避 (Sleep Acceleration Detection)**：調用 `Sleep(600000)` (休眠 10 分鐘)。沙箱通常會「快轉」時間，惡意程式透過比對 `GetTickCount64()` 或 `NtDelayExecution` 前後的硬體時鐘 RTC / TSC 差值，若發現時間突變即判定為沙箱。
- **環境特徵探測**：
  - 記憶體小於 4GB、CPU 核心數小於 2。
  - 磁碟名稱包含 `VBOX`, `QEMU`, `VMWARE`。
  - 螢幕解析度為 800x600 或 1024x768。
  - 沒有滑鼠移動軌跡（利用 `GetCursorPos` 檢測）。

## 💻 第三動：現場追兇——作戰指令與腳本庫

### 3.1 CAPEv2 沙箱 JSON 報告自動化解析腳本 (`parse_cape_report.py`)
CAPEv2 沙箱生成的 `report.json` 往往超過 100MB。SOC 分析師可利用此 Python 腳本直接提煉進程樹、網路 C2 與高危行為簽章。

```python
#!/usr/bin/env python3
"""
parse_cape_report.py - CAPEv2 JSON Report Triage Tool
自動化萃取 CAPEv2 沙箱報告中的進程樹、高危簽章 (Signatures) 與網路 C2 連線。
"""
import json
import sys

def parse_cape_report(json_path):
    print(f"[*] 正在讀取沙箱報告: {json_path} ...")
    with open(json_path, 'r', encoding='utf-8', errors='ignore') as f:
        data = json.load(f)

    # 1. 基本資訊與評分
    info = data.get("info", {})
    score = data.get("malscore", 0.0)
    target = data.get("target", {}).get("file", {})
    print("=" * 80)
    print(f"檔案名稱: {target.get('name', 'N/A')}")
    print(f"SHA256  : {target.get('sha256', 'N/A')}")
    print(f"沙箱評分: {score} / 10.0 (CAPEv2 Threat Score)")
    print("=" * 80)

    # 2. 進程樹提煉 (Process Tree)
    print("\n[+] 關鍵進程樹軌跡 (Process Tree Execution Flow):")
    processes = data.get("behavior", {}).get("processes", [])
    for proc in processes:
        pid = proc.get("process_id")
        ppid = proc.get("parent_id")
        pname = proc.get("process_name")
        cmd = proc.get("command_line", "N/A")
        first_seen = proc.get("first_seen", "N/A")
        print(f"  └── [{first_seen}] PID: {pid:<6} (Parent: {ppid:<6}) -> {pname}")
        if cmd != "N/A" and cmd != pname:
            print(f"      命令列: {cmd}")

    # 3. 高危行為特徵簽章 (Signatures)
    print("\n[+] 觸發之惡意行為簽章 (Triggered Malicious Signatures):")
    signatures = data.get("signatures", [])
    for sig in signatures:
        severity = sig.get("severity", 1)
        name = sig.get("name", "")
        desc = sig.get("description", "")
        if severity >= 3:
            mark = "🔴 [HIGH/CRITICAL]"
        elif severity == 2:
            mark = "🟡 [MEDIUM]"
        else:
            mark = "🟢 [LOW]"
        print(f"  {mark} ({severity}) {name}: {desc}")

    # 4. 網路通訊與 C2 外聯 (Network Callbacks)
    print("\n[+] 網路通訊連線 (Network Connections & DNS):")
    network = data.get("network", {})
    dns_requests = network.get("dns", [])
    for dns in dns_requests:
        print(f"  [DNS] 查詢: {dns.get('request', '')} -> IP: {', '.join([ans.get('data','') for ans in dns.get('answers', [])])}")

    tcp_conns = network.get("tcp", [])
    for conn in tcp_conns:
        dst = conn.get("dst")
        dport = conn.get("dport")
        print(f"  [TCP 外聯] 目的地: {dst}:{dport}")

    http_requests = network.get("http", [])
    for http in http_requests:
        print(f"  [HTTP 請求] {http.get('method')} {http.get('uri')} (Host: {http.get('host')}) -> Status: {http.get('status')}")

    print("=" * 80)

if __name__ == "__main__":
    if len(sys.argv) < 2:
        print(f"使用方式: python3 {sys.argv[0]} <report.json>")
        sys.exit(1)
    parse_cape_report(sys.argv[1])
```

### 3.2 Any.run 動態互動沙箱實戰操作技巧
在 Any.run 這類互動式沙箱中，靜態腳本無法替代分析員的手動操作：

1. **破除惡意文件互動誘餌**：
   - 若 Word/Excel 提示「Enable Content / 啟用巨集」，必須在視窗彈出時手動點擊。
   - 若為偽裝成加密 ZIP 的釣魚信，在桌面開啟郵件時輸入信件正文給予的解密密碼（如 `1234` 或 `invoice`）。
2. **觀察滑鼠軌跡與視窗等待**：
   - 惡意程式常以 `GetCursorPos` 監測滑鼠是否移動。進入沙箱後應在桌面劇烈晃動滑鼠並點擊空白處，誘導樣本結束規避階段。
3. **查看右側 HTTP Requests 與 Connections 標籤**：
   - 尋找 `SURICATA` 告警標籤（如 `ET TROJAN Cobalt Strike Beacon Malleable Profile`）。
   - 點擊對應連線下載封包載荷 (Payload Drop) 獲取下一階段 Payload。

## 🛡️ 第五動：處置圍堵與系統加固 SOP

### 5.1 應急處置階段 (Immediate Triage & Containment)

#### 1. 萃取 C2 IOC 並實施邊界阻斷
沙箱報告分析完成後，首要任務是立刻阻斷攻擊鏈擴散：

```bash
# 步驟 1：萃取報告中的外聯 IP 與網域，推送到防火牆阻斷清單
iptables -I FORWARD 1 -d 194.26.29.112 -j DROP

# 步驟 2：在 DNS 伺服器 (如 BIND / Unbound) 將惡意網域解析導向 Sinkhole (127.0.0.1)
# 阻斷內網其他潛在受害者與 Stage-2 伺服器的通訊
```

#### 2. EDR 威脅獵捕 (Threat Hunting Across Enterprise)
將沙箱報告中的二進位 Hash (SHA256) 與進程命令列參數轉換為 EDR 獵捕查詢：

```spl
`comment("Splunk / EDR 查詢：全網獵捕是否有其他端點執行了相同的惡意命令列")`
index=edr sourcetype="sysmon:process_create"
(CommandLine="*regsvr32.exe*update.dll*" OR CommandLine="*powershell*-enc*")
| stats count min(_time) as first_seen max(_time) as last_seen by host, user, ParentImage, Image, CommandLine
```

#### 3. 清理受害端點持久化機制
若已在端點執行，依據沙箱報告中註冊的機碼與計劃任務進行精準修復：

## 📋 過關驗收檢查點 (Mastery Checklist)

- [ ] **Q1：在沙箱報告的進程樹中，若看到 `svchost.exe` 的父進程是 `cmd.exe`，代表什麼嚴重的資安異常？**  
  *考核核心*：Windows 正常架構中，所有合法的 `svchost.exe` 必須嚴格由 `services.exe`（服務控制管理器）衍生，且其命令列必定帶有 `-k <服務組名>` 參數。若 `svchost.exe` 的父進程為 `cmd.exe`、`powershell.exe` 或一般使用者進程，100% 為惡意程式偽裝系統進程名稱，或進行了進程空心化 (Process Hollowing) 注入。

- [ ] **Q2：沙箱報告顯示樣本呼叫了 `VirtualAllocEx` 申請記憶體，為什麼其保護屬性 `PAGE_EXECUTE_READWRITE (0x40)` 是一個極高危險性的指標？**  
  *考核核心*：根據現代作業系統的 W^X (Write XOR Execute / 資料執行防止 DEP) 安全原則，記憶體不應同時具備可寫 (Write) 與可執行 (Execute) 權限。正常編譯程式的代碼段為 RX，資料段為 RW。若進程跨空間申請 RWX 記憶體，99% 的機率是為了寫入 Shellcode 並隨後原地執行，是進程注入與無檔案攻擊的典型特徵。

- [ ] **Q3：惡意程式在沙箱中運行時「什麼都沒做」就直接退出了，通常可能的原因有哪些？分析員該如何應對？**  
  *考核核心*：主因是惡意程式偵測到了沙箱環境（觸發反虛擬化/反沙箱檢測，如 CPU 核心數、RAM 小於 4G、未檢測到滑鼠移動、Sleep 快轉偵測），或是需要特定命令列參數、解密密碼或外網特定資源回應。分析員應嘗試：在互動沙箱中模擬人為滑鼠移動、手動點擊誘餌、修補沙箱核心防止虛擬化特徵洩漏，或直接靜態反編譯逆向出其檢測邏輯。

- [ ] **Q4：為什麼沙箱報告中出現對 `raw.githubusercontent.com` 或 `discordapp.com` 的 HTTP 請求，不可直接將其判定為良性連線？**  
  *考核核心*：這屬於「Living off Trusted Sites (LOTS)」技術。現代攻擊者極常利用 GitHub、Discord Webhook、Telegram API、Pastebin、Google Drive 等高度信任的公開合法雲端平台作為第二階段載荷託管伺服器 (Stage-2 Staging) 或 C2 資料傳輸通道，企圖規避傳統基於網域信譽庫 (Domain Reputation) 的阻斷規則。分析員必須檢驗其請求的具體 URI、傳輸的檔案內容與隨後的端點行為。

- [ ] **Q5：在 CAPEv2 沙箱中，「API Hooking」與「Hypervisor Telemetry」各自有何優缺點？為何現代沙箱趨向兩者結合？**  
  *考核核心*：API Hooking 位於使用者態/核心態接口，能直觀獲取 API 名稱、參數字串與呼叫上下文，日誌語義豐富易讀；但極易被惡意程式的 Direct Syscalls (直接系統調用) 或 Unhooking (重新從磁碟讀取乾淨 ntdll 覆蓋記憶體) 繞過。Hypervisor Telemetry 運行在虛擬機外部（Ring -1），惡意程式完全無法感知或竄改，具備不可規避性；但其捕獲的是原始記憶體分頁違例與暫存器數值，缺乏高級語言的語義上下文。兩者結合方能在兼顧語義深度與抗規避能力之間取得平衡。
