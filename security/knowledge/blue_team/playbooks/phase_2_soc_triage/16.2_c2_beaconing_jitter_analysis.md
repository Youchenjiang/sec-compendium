## 🧩 第一動：底層機制/協定解剖 (Mechanics & Mathematical Modeling)

### 2.1 C2 心跳機制的數學本質：Sleep、Jitter 與時間方差
C2 框架（如 Cobalt Strike, Mythic, Sliver, Havoc）為了維持對受害者主機的持久控制，同時防止受害者主機開啟常駐 TCP 監聽端口（易被掃描發現），一律採用**反向非同步輪詢架構 (Asynchronous Reverse Polling)**。

#### 1. 核心參數定義
- **基準休眠時間 ($T_{base}$ 或 $Sleep$)**：Agent 預設的休眠週期（單位：秒）。
- **抖動百分比 ($J$ 或 $Jitter$)**：隨機浮動區間比例（範圍：$0.0 \le J \le 1.0$，通常設為 $10\% \sim 50\%$)。
- **實際休眠時間 ($T_{actual}$)**：
  $$T_{actual} = T_{base} \pm \text{Random}(0, T_{base} \times J)$$
  或者在部分框架中實作為：
  $$T_{actual} = T_{base} \times (1 - J) + \text{Random}(0, 2 \times T_{base} \times J)$$

例如：$T_{base} = 60\text{s}$, $Jitter = 20\%$ 時：
- 最短休眠時間：$60 \times (1 - 0.2) = 48\text{s}$
- 最長休眠時間：$60 \times (1 + 0.2) = 72\text{s}$
- 時間分佈：在 $[48, 72]$ 秒區間內呈現**均勻分佈 (Uniform Distribution)**。

#### 2. 統計量指標
在威脅獵捕與 RITA (Real Intelligence Threat Analytics) 演算法中，透過以下三組統計指標建立評分模型：

1. **時間差變異係數 (Coefficient of Variation, $CV$)**：
   $$CV = \frac{\sigma}{\mu} = \frac{\sqrt{\frac{1}{N-1} \sum_{i=1}^{N} (\Delta t_i - \bar{\Delta t})^2}}{\bar{\Delta t}}$$
   - 人類手動上網行為：$CV \gg 1.0$（隨機性極大，突發性高）
   - 帶抖動 C2 心跳 ($J=20\%$): $CV \approx \frac{J / \sqrt{3}}{1} = \frac{0.20}{1.732} \approx 0.115 \ll 0.3$
   - 剛性定時排程 ($J=0\%$): $CV \approx 0.001$

2. **資料傳輸大小方差 (Data Size Variance)**：
   正常使用者瀏覽網頁時，封包大小隨頁面內容劇烈波動；C2 在「無命令執行」狀態下發送心跳，每次請求的 HTTP Header 結構與加密長度近乎完全相同，位元組大小方差趨近於 0。

3. **連線頻率持續性 (Connection Persistence / Interval Density)**：
   C2 心跳通常 24 小時不間斷（不受人類作息上班 9 點、下班 18 點影響），在時間直方圖上呈現全天候平坦分佈。

### 2.2 RITA 演算法評分模型結構 (RITA Scoring Model)
RITA 透過將「時間間隔分數 ($S_{time}$)」與「資料大小分數 ($S_{size}$)」進行加權聚合：

```
       ┌────────────────────────────────────────────────────────┐
       │                RITA Beacon Score Engine                │
       └────────────────────────────────────────────────────────┘
                                   │
         ┌─────────────────────────┴─────────────────────────┐
         ▼                                                   ▼
┌───────────────────────────────┐   ┌───────────────────────────────┐
│     TS (Time Score) 模組      │   │     DS (Data Score) 模組      │
│ 1. Interval Skewness (偏度)   │   │ 1. Inbound Byte Consistency   │
│ 2. Interval Kurtosis (峰度)   │   │ 2. Outbound Byte Consistency  │
│ 3. Interval Mode Ratio (眾數) │   │ 3. Packet Count Uniformity    │
└───────────────────────────────┘   └───────────────────────────────┘
         │                                                   │
         └─────────────────────────┬─────────────────────────┘
                                   ▼
                 Final Beacon Score = (TS + DS) / 2
                 (Score > 0.85 ➔ 強烈判定為惡意 C2 Beacon)
```

### 3.1 Splunk SPL：跨連線時間差與變異係數 (CV) 獵捕心跳
在巨量日誌中，利用 `streamstats` 計算前後兩筆連線的精確時間差，並透過統計函數過濾出潛在 Beaconing。

```spl
index=firewall sourcetype="pan:traffic" action=allowed dest_ip!=10.0.0.0/8 dest_ip!=172.16.0.0/12 dest_ip!=192.168.0.0/16
| fields _time, src_ip, dest_ip, dest_port, bytes_out, bytes_in

`comment("步驟 1：依據 src_ip, dest_ip, dest_port 分組，並以時間排序計算相鄰時間差 delta_t")`
| sort 0 src_ip, dest_ip, dest_port, _time
| streamstats current=f window=1 last(_time) as prev_time by src_ip, dest_ip, dest_port
| eval delta_t = round(_time - prev_time, 2)
| where delta_t > 5 AND delta_t < 3600

`comment("步驟 2：聚合計算平均值、標準差、變異係數 CV 以及傳輸量標準差")`
| stats count as total_connections,
        avg(delta_t) as avg_interval,
        stdev(delta_t) as stdev_interval,
        avg(bytes_out) as avg_bytes_out,
        stdev(bytes_out) as stdev_bytes_out
        by src_ip, dest_ip, dest_port

`comment("步驟 3：變異係數計算與門檻過濾 (連線數 > 50 次，CV < 0.35 代表強週期性)")`
| eval cv_interval = round(stdev_interval / avg_interval, 3)
| where total_connections >= 50 AND cv_interval <= 0.35
| sort cv_interval asc
| table src_ip, dest_ip, dest_port, total_connections, avg_interval, stdev_interval, cv_interval, avg_bytes_out, stdev_bytes_out
```

### 3.2 Python 實戰鑑識工具：PCAP 封包心跳抖動分析器 (`beacon_hunter.py`)
若接獲 PCAP 檔案，可直接使用此腳本讀取封包時間戳，計算雙向 TCP/UDP 連線的抖動係數與位元組方差。

```python
#!/usr/bin/env python3
"""
beacon_hunter.py - C2 Beaconing & Jitter Detection Tool
針對 PCAP 檔案解析 TCP/UDP 會話的時間戳與載荷大小，辨識高置信度 C2 心跳。
"""
import sys
import math
from collections import defaultdict
from scapy.all import rdpcap, IP, TCP, UDP

def analyze_pcap(pcap_file, min_conns=15):
    print(f"[*] 讀取封包檔案: {pcap_file} ...")
    packets = rdpcap(pcap_file)
    
    # 聚合會話連線時間與大小: key = (src_ip, dst_ip, dport, proto)
    sessions = defaultdict(list)
    
    for pkt in packets:
        if IP in pkt:
            src = pkt[IP].src
            dst = pkt[IP].dst
            proto = "TCP" if TCP in pkt else ("UDP" if UDP in pkt else None)
            if not proto:
                continue
            dport = pkt[proto].dport
            
            # 過濾純 ACK 封包，只關注帶有載荷的資料封包或握手封包
            payload_len = len(pkt[proto].payload)
            sessions[(src, dst, dport, proto)].append((float(pkt.time), payload_len))

    print(f"[+] 總共分析了 {len(sessions)} 個雙向會話通道")
    print("=" * 95)
    print(f"{'Source IP':<16} {'Destination IP':<16} {'Port':<6} {'Count':<6} {'Avg Δt(s)':<10} {'StdDev':<8} {'CV':<6} {'Status':<10}")
    print("=" * 95)

    candidates = []

    for (src, dst, dport, proto), stream in sessions.items():
        if len(stream) < min_conns:
            continue
        
        # 提取時間序列
        timestamps = [item[0] for item in stream]
        payload_sizes = [item[1] for item in stream]
        
        # 計算時間差 delta_t
        intervals = [timestamps[i] - timestamps[i-1] for i in range(1, len(timestamps))]
        intervals = [t for t in intervals if t > 0.5] # 排除同一封包重傳或極短爆發
        
        if len(intervals) < min_conns - 1:
            continue
            
        n = len(intervals)
        avg_delta = sum(intervals) / n
        if avg_delta < 2.0: # 排除串流影片或連續下載
            continue
            
        variance = sum((x - avg_delta) ** 2 for x in intervals) / (n - 1)
        stdev = math.sqrt(variance)
        cv = stdev / avg_delta if avg_delta > 0 else 999.0
        
        # 計算載荷方差
        avg_size = sum(payload_sizes) / len(payload_sizes)
        size_var = sum((s - avg_size) ** 2 for s in payload_sizes) / len(payload_sizes)
        size_stdev = math.sqrt(size_var)

        # 研判標準：CV <= 0.35 且封包大小相對均勻
        if cv <= 0.35:
            jitter_pct = round(cv * 1.732 * 100, 1) # 由均勻分佈逆推預估 Jitter 百分比
            status = f"BEACON! (J~{jitter_pct}%)"
            candidates.append(((src, dst, dport, proto), len(stream), avg_delta, stdev, cv, status))
            print(f"{src:<16} {dst:<16} {dport:<6} {len(stream):<6} {avg_delta:<10.2f} {stdev:<8.2f} {cv:<6.3f} {status:<10}")

    print("=" * 95)
    print(f"[*] 掃描完成，發現 {len(candidates)} 個高可疑 C2 心跳通道！")

if __name__ == "__main__":
    if len(sys.argv) < 2:
        print(f"使用方式: python3 {sys.argv[0]} <traffic.pcap> [min_conns]")
        sys.exit(1)
    min_c = int(sys.argv[2]) if len(sys.argv) > 2 else 15
    analyze_pcap(sys.argv[1], min_c)
```

## ⚖️ 第四動：研判分水嶺——真實威脅 vs 業務誤報

### 4.1 SOC 研判對決 8 問 (SOC 8 Critical Questions)
在判定為 C2 心跳前，必須逐項回答以下 8 個關鍵提問：

| 編號 | 檢驗提問 (Verification Questions) | 是 (Yes) 判定導向 | 否 (No) 判定導向 |
| :---: | :--- | :--- | :--- |
| **Q1** | 目標 IP 是否屬於微軟、Google、AWS、Cloudflare 等已知公有雲 CDN 或企業簽約 SaaS？ | 傾向業務軟體長輪詢 (查閱 SNI/證書) | 需高度警惕，極可能是攻擊者租用 VPS |
| **Q2** | 雙向連線時間差變異係數 ($CV$) 是否低於 $0.35$ 且至少有 $50$ 次以上連續記錄？ | 符合數學心跳特徵，列為高危清單 | 隨機性高，偏向一般人類或間歇應用程式 |
| **Q3** | 該連線在非工作時間（深夜 00:00~06:00、週六日）頻率是否與白天完全一致？ | 典型無人值守機器人/惡意 Agent 特徵 | 使用者主機休眠或定時排程，可能為桌面程式 |
| **Q4** | 發起連線的本機進程是否具備合法、受信任且未過期的微軟/大廠 Authenticode 簽章？ | 進一步排查是否遭到記憶體注入/反射載入 | 無簽章或臨時路徑執行檔，立即啟動處置 |
| **Q5** | 發起連線的進程是否為系統核心進程（如 `svchost.exe`, `explorer.exe`）卻連外非標準端口？ | 高危：高機率為 Process Injection / Hollow | 正常：需視該進程原始網路功能定義研判 |
| **Q6** | 連線傳輸資料量（Upload/Download Bytes）是否高度收斂，幾乎無內容增減變化？ | 符合空轉心跳 (No-op Beacon Check-in) | 每次流量差異顯著，偏向實際業務資料交換 |
| **Q7** | EDR 是否在同一時間段記錄到進程記憶體中含有 RWX 權限且無磁碟映像 (Unbacked) 的記憶體區塊？ | 確定為 Cobalt Strike / In-memory Beacon | 需搭配其他 EDR 遙測進行綜合研判 |
| **Q8** | DNS 查詢紀錄中，連向該 IP 前是否解析了具備 DGA (動態網域名稱) 或全新註冊的網域？ | 高危：攻擊者彈性 C2 架構 | 正常：解析穩定老舊網域名稱 |

## 🛡️ 第五動：處置圍堵與系統加固 SOP

### 5.1 應急處置階段 (Immediate Triage & Containment)

#### 1. 邊界與主機級斷網圍堵
若確定為 C2 Beacon，第一動必須切斷 C2 通道，防止攻擊者下發進一步橫向移動命令：

```bash
# 步驟 1：防火牆微創封鎖外部 C2 IP
iptables -I FORWARD 1 -s 172.16.20.45 -d 185.220.101.5 -j DROP
iptables -I FORWARD 1 -d 185.220.101.5 -j DROP

# 步驟 2：EDR 發出主機隔離命令 (Network Isolation)
# 保留與 SOC/EDR 控制台之通訊，其餘所有入站與出站連線全數切斷
```

#### 2. 端點記憶體保全與取證 (Memory Forensics Before Kill)
**切忌直接使用 `taskkill /f` 終止進程！** 許多 C2 僅駐留於記憶體中（Fileless），直接殺進程將導致關鍵證據與攻擊者指令歷史永久遺失。

```powershell
# 步驟 1：使用 Sysinternals procdump 轉儲可疑進程記憶體 (以 PID 4312 為例)
procdump.exe -ma 4312 C:\Forensics\beacon_pid_4312.dmp

# 步驟 2：使用 Volatility 或 strings 快速擷取記憶體中的 C2 設定檔 (Watermark / C2 URL)
# Cobalt Strike 記憶體通常包含加密或混淆的配置結構
strings.exe -n 8 -e l C:\Forensics\beacon_pid_4312.dmp | Select-String -Pattern "http"
```

#### 3. 終止惡意進程與清理持久化
```powershell
# 步驟 3：確認轉儲完成後，終止惡意進程
Stop-Process -Id 4312 -Force

# 步驟 4：檢查並清除自啟動項、計劃任務 (Scheduled Tasks) 與服務
Get-ScheduledTask | Where-Object { $_.TaskPath -notlike "\Microsoft*" }
```

### 5.2 長期架構加固 (Long-term Hardening)
1. **阻斷內網直連公網非 HTTP/HTTPS 端口**：邊界防火牆一律禁止終端網段直接向外發起直連連線，所有 Web 流量必須強制經過顯式轉發代理 (Explicit Proxy) 或次世代防火牆深度封包檢測 (DPI)。
2. **部署 TLS 攔截與解密 (SSL/TLS Decryption)**：針對外發流量實施中間人 (MITM) 憑證檢視，使 C2 Malleable HTTP Profile 無所遁形。
3. **JA4 網路指紋與威脅情報聯防**：在 NGFW/IPS 上啟用 JA4/JA4S 異常用戶端指紋偵測，封殺 Python-requests、Go-http-client 等典型自動化外聯指紋。

## 🎯 靶場實戰檢驗 (Hands-on Lab Walkthrough)

### 6.1 實驗環境架設：模擬帶抖動的 C2 心跳流量
本實驗將在 Linux 實驗環境中，以 Python 模擬一個具備 `Sleep=10s`、`Jitter=30%` 的 C2 通訊 Agent，並由分析機抓包分析。

```bash
# 步驟 1：在被控機端執行 C2 模擬腳本 (c2_agent_sim.py)
cat << 'EOF' > /tmp/c2_agent_sim.py
import time
import random
import urllib.request

c2_url = "http://127.0.0.1:8080/heartbeat"
base_sleep = 10.0
jitter = 0.30 # 30% 抖動 (7s ~ 13s)

print("[*] 模擬 C2 帶抖動心跳啟動...")
for i in range(20):
    actual_sleep = base_sleep * (1.0 - jitter) + random.uniform(0, 2 * base_sleep * jitter)
    print(f"[{i+1}/20] 休眠 {actual_sleep:.2f} 秒後發起心跳...")
    time.sleep(actual_sleep)
    try:
        # 發送固定 128 Bytes 的請求載荷
        req = urllib.request.Request(c2_url, data=b"A"*128, headers={"User-Agent": "Mozilla/5.0"})
        urllib.request.urlopen(req, timeout=2)
    except Exception:
        pass
EOF

# 步驟 2：在背景啟動抓包監聽
sudo tcpdump -i lo port 8080 -w /tmp/c2_jitter_sim.pcap &
TCPDUMP_PID=$!

# 步驟 3：啟動微型監聽伺服器並運行 Agent
python3 -m http.server 8080 --bind 127.0.0.1 > /dev/null 2>&1 &
HTTP_PID=$!

python3 /tmp/c2_agent_sim.py

# 步驟 4：停止抓包與伺服器
kill $TCPDUMP_PID
kill $HTTP_PID
```

使用我們剛才編寫的 `beacon_hunter.py` 檢測抓獲的 `/tmp/c2_jitter_sim.pcap`：

## 📋 過關驗收檢查點 (Mastery Checklist)

- [ ] **Q1：攻擊者將 C2 Jitter 設定為 0% 與 50% 時，對 SOC 偵測會產生什麼具體影響？哪一種更難抓？**  
  *考核核心*：Jitter 0% 為完全固定週期（如每 60.00 秒一次），傳統 IDS 與 SIEM 簡單門檻即可抓出；Jitter 50% 時時間在 30s~90s 間大幅波動，傳統規則失效，必須依賴統計學方差與變異係數 ($CV$) 分析。Jitter 越大越難透過時間偵測，但過大的 Jitter 會導致命令交互延遲過高，因此攻擊者多折衷設定在 15%~30%。

- [ ] **Q2：為什麼只看連線時間差 ($Δt$) 還不夠，必須同時交叉比對資料傳輸量 (Bytes Variance)？**  
  *考核核心*：許多合法排程（如 NTP 校時、定時健康檢查）同樣具有低時間方差；但 C2 心跳在無操作時每次 Check-in 請求與回應位元組大小幾乎完全固定。雙維度交叉（時間方差小 + 位元組大小方差小）能大幅降低 90% 以上的業務排程誤報。

- [ ] **Q3：在 Splunk 中，為什麼不能直接用 `diff(_time)` 來計算時間差，而必須使用 `streamstats` 配合 `sort 0`？**  
  *考核核心*：Splunk 預設不保證檢索事件的絕對時間順序（尤其在分散式 Indexer 環境），直接計算會出錯。必須先透過 `sort 0 src_ip, dest_ip, _time` 進行不限筆數的精準正向排序，再透過 `streamstats window=1 current=f last(_time)` 抓取同組連線上一筆時間戳進行相減。

- [ ] **Q4：在 RITA 分析模型中，偏度 (Skewness) 和峰度 (Kurtosis) 分別衡量心跳流量的何種特徵？**  
  *考核核心*：偏度衡量連線時間間隔分佈的對稱性，峰度衡量分佈的尖銳程度（是否高度集中於特定時間點）。C2 Jitter 產生的均勻分佈其偏度趨近於 0，若分佈高度集中在中央眾數則具有特徵峰度，以此計算出的時間分數 (Time Score) 可量化週期強度。

- [ ] **Q5：發現疑似 C2 Beaconing 的內部主機時，為何資安人員第一步嚴禁直接重開機或殺死可疑進程？**  
  *考核核心*：現代進階 C2（如 Cobalt Strike Beacon）主要採用無檔案 (Fileless) 記憶體載入技術（Reflective DLL Injection / Process Hollowing），惡意代碼僅存在於記憶體中。一旦重開機或殺死進程，記憶體中未落盤的 Payload、C2 IP/Domain 配置、RSA 公鑰與命令執行歷史將被徹底抹除，造成無法復原的取證災難。正確做法是先進行記憶體轉儲 (Memory Dump) 後再隔離處置。
