## 🏁 階段一：雲端運算共同責任模型 (Shared Responsibility Model)（約 8 小時）

### 1.1 IaaS vs PaaS vs SaaS 安全責任劃分矩陣（金盾獎必考重點）

```
┌─────────────────────────────────────────────────────────────┐
│ 服務模式 │ 客戶責任 (Customer)     │ 雲端服務商責任 (CSP)       │
├─────────┼────────────────────────┼─────────────────────────┤
│ IaaS    │ 資料、身分(IAM)、應用、  │ 實體資料中心、硬體伺服器、│
│ (EC2/GCE│ 作業系統(OS)、網路防火牆│ 虛擬化底層 Hypervisor    │
├─────────┼────────────────────────┼─────────────────────────┤
│ PaaS    │ 資料、身分(IAM)、應用   │ 實體硬體、作業系統修補、 │
│ (RDS/App│ 程式本身與連線設定     │ 執行期環境 (Runtime)     │
├─────────┼────────────────────────┼─────────────────────────┤
│ SaaS    │ 資料分類、身分存取控制、│ 實體、主機、作業系統、   │
│ (M365)  │ 使用者帳號安全與多因子 │ 應用程式代碼、軟體修補   │
└─────────────────────────────────────────────────────────────┘
```

> 💡 **核心定律**：**「資料 (Data)」與「身分 (Identity/IAM)」無論在任何雲端架構下，客戶永遠必須承擔百分之百的保護責任！**

## 🪣 階段二：物件儲存桶安全與 IMDS 中繼資料劫持（約 8 小時）

### 2.1 雲端實體中繼資料服務 (IMDSv1 vs IMDSv2)

雲端虛擬機（如 AWS EC2）透過中繼資料位址 `http://169.254.169.254/` 獲取臨時 IAM 角色金鑰：
- **IMDSv1 (弱點)**：支援無認證直接 GET 請求。若主機存在 SSRF 漏洞，攻擊者可遠端竊取暫時性權杖。
- **IMDSv2 (加固)**：強制要求 `PUT` 請求預先獲取 `X-aws-ec2-metadata-token`，並設定 Token TTL，阻斷多數反射型 SSRF。

## 🐳 階段三：容器逃逸與 Kubernetes 叢集安全（約 10 小時）

### 3.1 經典容器逃逸手法

1. **Privileged 特權容器逃逸**：容器啟用 `--privileged`，擁有對主機 `/dev` 的存取權，可直接掛載主機根目錄硬碟。
2. **掛載 Docker Socket (`/var/run/docker.sock`)**：容器內部可直接呼叫主機 Docker 守護進程，建立逃逸至主機的特權容器。
