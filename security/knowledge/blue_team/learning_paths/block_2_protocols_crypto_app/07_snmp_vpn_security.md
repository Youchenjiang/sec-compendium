## 🏁 階段一：SNMP 版本演進與安全等級矩陣（約 8 小時）

### 1.1 SNMP 三大版本對比（金盾獎必考重點）

| 版本 | 認證方式 | 傳輸加密 | 核心缺陷 / 安全特性 |
| :--- | :--- | :---: | :--- |
| **SNMPv1** | 明文社群字串 (Community String) | ❌ 無 | 預設 `public` (唯讀)、`private` (讀寫)，封包完全明文，易被竊聽 |
| **SNMPv2c** | 明文社群字串 (Community String) | ❌ 無 | 增加 `GetBulkRequest` 與更豐富錯誤碼，但**安全性依舊為明文傳輸** |
| **SNMPv3** | USM 使用者安全模型 (User-based) | ✅ 支援 | 支援使用者身分認證 (MD5/SHA) 與酬載資料加密 (DES/AES) |

### 1.2 SNMPv3 USM 三種安全層級 (Security Levels)

1. `noAuthNoPriv`：無認證、無加密（僅比對使用者名稱）。
2. `authNoPriv`：**有認證、無加密**（以 HMAC-MD5 或 HMAC-SHA 驗證資料完整性與身分，但酬載可被監聽）。
3. `authPriv`：**有認證、有加密**（最高安全等級；HMAC 認證 + CBC-DES/AES 酬載加密）。

## 🔒 階段三：IPsec 核心架構：AH vs ESP（約 8 小時）

### 3.1 認證標頭 (AH) vs 封裝安全酬載 (ESP)

- **AH (Authentication Header，IP 協定 51)**：
  - 提供：資料來源認證、完整性檢驗、抗重放攻擊。
  - **不提供**：**資料加密（封包內容為明文！）**。
  - 限制：無法穿越 NAT（因為 NAT 修改 IP 標頭會破壞 AH 雜湊計算）。
- **ESP (Encapsulating Security Payload，IP 協定 50)**：
  - 提供：**資料加密 (Confidentiality)**、來源認證、完整性檢驗。
  - 現代 VPN 實務上 99% 皆採用 ESP。
