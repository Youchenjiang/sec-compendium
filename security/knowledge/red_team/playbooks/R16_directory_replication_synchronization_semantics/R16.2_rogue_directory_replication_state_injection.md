# R16.2 偽造目錄複寫狀態注入分析 (Rogue Directory Replication State Injection / DCShadow)

---

## 🎯 作戰任務破題 (Tactical Objective & Mental Workflow)

**偽造目錄複寫狀態注入 (DCShadow)** 是 Windows Active Directory (AD) 體系中最隱蔽的最高權限持久化與屬性竄改技術。其本質為：**「DCSync (R16.1) 是透過模擬 DC『拉取 (Pull)』憑證資料，而 DCShadow 則是透過將攻擊者工作站暫時註冊為一部臨時的虛擬網域控制站 (Rogue DC)，向合法 DC『推送 (Push)』惡意修改的目錄物件狀態；攻擊者藉此可修改常規 LDAP 介面嚴格禁止寫入的特權屬性（如 `sIDHistory`），且整個過程完全不產生常規的 LDAP 修改事件日誌 (Event ID 5136)，達成幽靈級的特權維持」**。

```
[攻擊者工作站 (具備 DA 權限)] ── 1. 在 CN=Configuration 快速註冊臨時 nTDSDSA 物件與 SPN
       │
       ├── 2. 本地記憶體架設 DRSUAPI RPC 服務端 (偽裝為合法的複寫源)
       ▼
[合法網域控制站 (DC01)]
       │ ◄── 3. 呼叫 DrsReplicaAdd / DrsReplicaSync，強制 DC01 向攻擊者拉取狀態！
       │
       ├── 4. DC01 將攻擊者注入的惡意屬性 (如為普通用戶加上 sIDHistory=EA-519) 寫入 NTDS.dit
       ▼
[攻擊者工作站] ── 5. 立即刪除註冊的臨時 DC 物件與 SPN (清理現場，歷時僅數秒)
       │
       ▼ [攻擊者帳號具備企業管理員 (Enterprise Admins) 特權，且無常規 LDAP 修改日誌！]
```

### 核心作戰決策與邊界
- **必要權限條件**：攻擊者必須具備對 Active Directory 的 **`Configuration` 容器** 或 **`CN=Sites`** 具備寫入權限（通常需要 Domain Admin 或 Enterprise Admin 權限；因此 DCShadow 主要用於**高隱蔽後門植入 (Stealth Persistence)** 與**防禦規避 (Defense Evasion)**）。
- **技術邊界**：
  - **與 DCSync (R16.1) 差異**：DCSync 是只讀的入站憑證提取；DCShadow 則是主動寫入出站的複寫狀態注入。
  - **與常規 LDAP 寫入差異**：常規 LDAP 修改受限於 Schema 限制（例如無法直接在 LDAP 中為用戶寫入 `sIDHistory`），且會產生 Event ID 5136；DCShadow 走複寫管線，突破限制且日誌脫鉤。

## 🔬 第一動：DCShadow 註冊與 MS-DRSR 推送機制全景解剖 (Mechanics & Ephemeral DC Registration)

### DCShadow 三階段物理執行流程

```
[階段 1：臨時 DC 身份註冊 (Registration)]
  - 在網域電腦物件上追加 Kerberos SPN：
    GC/FQDN/domain, E3514235-4B06-11D1-AB04-00C04FC2DCD2/GUID/domain (DRSUAPI 服務)
  - 在 CN=Servers,CN=Default-First-Site-Name,CN=Sites 建立 nTDSDSA 物件。

[階段 2：複寫觸發與狀態注入 (Push Replication)]
  - 本地啟動 RPC 伺服器，等待合法 DC 連線。
  - 發送 RPC 請求通知合法 DC (DC01) 發生架構變更，強制 DC01 呼叫 DRSGetNCChanges 向攻擊者拉取變更。
  - 攻擊者將包含偽造屬性的物件串流餵給 DC01，DC01 盲目合流寫入本地資料庫。

[階段 3：現場擦除與清理 (Deregistration)]
  - 立即刪除剛剛建立的 nTDSDSA 物件，並移除追加的 SPN，恢復普通工作站狀態。
```

### 核心注入向量速查表

| 模式與利用手法 | 注入屬性與目標 (Target Attributes) | 突防原理與作用標記 |
| :--- | :--- | :--- |
| **`sIDHistory` 後門植入** | `sIDHistory: S-1-5-21-...-519` (Enterprise Admins) | 將企業管理員 SID 賦予普通用戶，取得跨全林頂級權限且不被一般群組檢查察覺。 |
| **主群組 ID 篡改** | `primaryGroupID: 512` (Domain Admins) | 將帳號主群組修改為網域管理員，規避常規 `member` 屬性稽核。 |
| **密碼強制覆寫** | `unicodePwd: [NewPassword]` | 繞過密碼複雜度策略與修改密碼審計日誌。 |
| **特權標記指派** | `adminCount: 1` | 破壞 AdminSDHolder 保護機制。 |
| **帳號狀態解除** | `userAccountControl: 512` (NORMAL_ACCOUNT) | 強制啟用已被禁用的敏感帳號。 |

### Mimikatz 執行雙終端聯動指令
- **終端 1 (以 SYSTEM 權限註冊並啟動 RPC 服務端)**：
  ```cmd
  mimikatz # privilege::debug
  mimikatz # misc::dcshadow /stack
  ```
- **終端 2 (以 Domain Admin 權限發布屬性注入指令)**：
  ```cmd
  # 為普通帳號 operator 注入 Enterprise Admins (RID 519) 的 sIDHistory
  mimikatz # misc::dcshadow /object:operator /attribute:sIDHistory /value:S-1-5-21-12345678-12345678-12345678-519
  mimikatz # misc::dcshadow /push
  ```

## 🥷 第三動：防禦規避與日誌鑑識特徵 (Evasion & Telemetry)

- **常規日誌全面失明 (Bypassing Event 5136)**：
  - 傳統 SIEM 依賴 **Event ID 5136**（目錄服務物件被修改）監控敏感屬性異動；透過複寫管線注入的變更**完全不觸發 5136 日誌**！
- **鑑識與遙測特徵 (關鍵微痕跡)**：
  - **電腦 SPN 異常變更 (Event ID 4742)**：
    - 非 DC 工作站的電腦物件突發被註冊了 `GC/...` 或 `E3514235-4B06-11D1-AB04-00C04FC2DCD2/...` 等 DC 專屬 SPN。
  - **短暫存在的 nTDSDSA 物件**：
    - 在 `CN=Sites` 容器中短暫出現一個新建立並在數秒內被快速刪除的 `nTDSDSA` 物件。
  - **異常複寫事件 (Event ID 4929 / 4934)**：
    - 系統日誌中記錄到 DC 向非授權的來源 IP 發起目錄複寫同步。

## 🛡️ 第五動：安全加固與修復基線 (Hardening & Remediation Baseline)

### 1. 鎖定 Configuration 與 Sites 容器 ACL
```powershell
# 稽核並移除非 Domain/Enterprise Admins 在 Configuration 容器上的建立物件特權
Import-Module ActiveDirectory
$ConfigNC = (Get-ADRootDSE).configurationNamingContext
Get-Acl "AD:\CN=Sites,$ConfigNC" | Select-Object -ExpandProperty Access |
    Where-Object { $_.ActiveDirectoryRights -match "CreateChild|WriteProperty" -and $_.IdentityReference -notmatch "Domain Admins|Enterprise Admins|SYSTEM" }
```

### 2. SIEM 關聯規則：偵測非 DC 註冊 DRSUAPI SPN (Sigma Rule 範例)
```yaml
title: Detect DCShadow Rogue SPN Registration
status: production
logsource:
    product: windows
    service: security
detection:
    selection:
        EventID: 4742
        ServicePrincipalNames|contains:
            - 'E3514235-4B06-11D1-AB04-00C04FC2DCD2'
            - 'GC/'
    filter_legit_dcs:
        TargetUserName|endswith: '$' # 需比對是否為已知合法 DC 清單
    condition: selection and not filter_legit_dcs
level: critical
```

- **網域環境**：`corp.internal`
- **目標**：利用已獲取的 Domain Admin 憑證，將普通網域使用者 `backdoor_user` 植入隱密 `sIDHistory`，實現隱蔽持久化。

### 2. 三步驗證流程

1. **檢查注入前使用者的 SID 屬性**：


## 🎯 作戰驗收檢查點 (Mastery Checklist)

- [ ] **Q1. DCShadow 與 DCSync 在目錄複寫協議 (MS-DRSR) 的方向性上有何根本差異？**  
  *分析思路*：DCSync 是「入站拉取 (Inbound Pull)」，客戶端假冒 DC 要求目標 DC 回傳機密憑證；DCShadow 是「出站推送 (Outbound Push)」，客戶端假冒 DC 要求目標 DC 將客戶端構造的修改狀態同步寫入資料庫。

- [ ] **Q2. 為什麼 DCShadow 能夠完全繞過傳統 SIEM 的 Event ID 5136（目錄物件修改）日誌？**  
  *分析思路*：Event ID 5136 是專門記錄透過 LDAP 協定進行的物件新增與屬性修改；而 DCShadow 是走底層網域控制站之間的「目錄複寫服務 (Replication)」，AD 核心將其視為跨 DC 的合流同步，因此不會觸發 LDAP 層面的稽核事件。

- [ ] **Q3. 透過 DCShadow 注入 `sIDHistory` 屬性相比於直接修改群組成員 (Member) 有何戰術優勢？**  
  *分析思路*：修改群組成員（如將用戶加入 Domain Admins）會產生醒目的 Event ID 4728/4732，且容易被 BloodHound 等工具輕易枚舉；而 `sIDHistory` 隱藏在用戶物件內部，該用戶在介面上依然顯示為普通員工，但 Kerberos 驗證時產生的 PAC 卻包含企業管理員 SID，具備極強的防禦規避性。

- [ ] **Q4. 藍隊要成功監控並捕捉 DCShadow 攻擊，最核心的遙測事件是什麼？**  
  *分析思路*：監控電腦物件的 SPN 變更事件（Event ID 4742）；任何非官方網域控制站的普通主機突然被註冊了包含 DRSUAPI GUID (`E3514235...`) 或 `GC/` 的 SPN，即為 DCShadow 臨時註冊階段無可掩蓋的致命特徵。

- [ ] **Q5. 限制並防範 DCShadow 濫用的核心加固手段是什麼？**  
  *分析思路*：嚴格收斂 Active Directory 中 `Configuration` 命名空間與 `CN=Sites` 容器的存取權限，確保除了原生的 Enterprise Admins 外，杜絕任何帳號具備建立子物件與修改 SPN 的權限；部署 MDI (Defender for Identity) 進行即時複寫異常行為監控。
