## 🔬 第一動：Sudoers 語法樹、環境清理與 LD_PRELOAD 物理機制 (Mechanics & Linker Structs)

### 1. Sudo 授權語法結構剖析
在 `/etc/sudoers` 中，標準的授權指令格式如下：
```text
user_name host_name=(run_as_user:run_as_group) [TAGS] command_path
範例: dev ALL=(root) NOPASSWD: /usr/bin/vim, /usr/bin/tar
```

### 2. LD_PRELOAD 動態鏈結庫劫持原理
Linux 動態鏈結器 (`ld.so`) 在加載任何動態編譯程式前，會優先加載 `LD_PRELOAD` 環境變數所指定的動態共享物件 (`.so`)：
- 正常的 Sudo 會在執行前啟用 `env_reset` 清理所有使用者環境變數，防止未授權代碼被注入特權進程。
- 若管理員在配置中寫入 `Defaults env_keep += "LD_PRELOAD"`，動態鏈結器會在 Sudo 啟動後、二進位程式的主入口 `main()` 執行前，率先執行由 `LD_PRELOAD` 指定的惡意 `.so` 構造函數 (`_init()` 或 `__attribute__((constructor))`)，該函數在 root 權限下調用 `setuid(0); execve("/bin/sh")` 即可完成提權！

## 🛡️ 第五動：工程級防禦基線 (Hardening Baselines)

1. **嚴格限制 `NOPASSWD` 與指令參數**：
   - 杜絕使用通配型二進位指令；在 `/etc/sudoers` 中設定指令時，務必加上確切的參數白名單，防止參數注入逃逸。
2. **全面落實 `Defaults env_reset` 基準**：
   - 確保 `/etc/sudoers` 開頭包含 `Defaults env_reset`，嚴禁將 `LD_PRELOAD`, `LD_LIBRARY_PATH`, `PYTHONPATH` 加入 `env_keep`。

# sudo_preload_lab.sh

#include <stdio.h>
#include <sys/types.h>
#include <unistd.h>

## 🎯 作戰驗收檢查點 (Operational Checkpoints)

- [ ] **Q1：執行 `sudo -l` 時，回顯中的 `env_reset` 對系統安全有何關鍵意義？**
  - **戰術思維**：`env_reset` 會在切換至特權執行環境前，重置並清空普通使用者環境變數，防止攻擊者藉由注入 `LD_PRELOAD` 或 `PYTHONPATH` 劫持即將執行的特權二進位程式。
- [ ] **Q2：若 `/etc/sudoers` 允許免密碼執行 `/usr/bin/tar`，如何構造提權 Payload？**
  - **戰術思維**：利用 tar 的檢查點執行參數：`sudo tar -cf /dev/null /dev/null --checkpoint=1 --checkpoint-action=exec=/bin/sh`，tar 在壓縮過程中會調用 exec 執行外部 Shell。
- [ ] **Q3：在被授權執行 `sudo /usr/bin/less /var/log/syslog` 的情境下，如何逃逸至 root？**
  - **戰術思維**：`less` 支援內部命令執行，直接在 less 閱讀介面中輸入 `!/bin/sh` 並按下 Enter，即可在不關閉 less 的情況下直接開啟 root 交互式終端。
- [ ] **Q4：若 Sudo 配置為 `ALL=(root) /opt/scripts/*.sh`，存在何種提權風險？**
  - **戰術思維**：若目標目錄可寫，攻擊者可建立任意 `evil.sh` 執行；即使目錄不可寫，若目錄下某腳本內部調用了相對路徑指令（如 `cleanup` 而非 `/bin/cleanup`），可透過 PATH 劫持提權。
- [ ] **Q5：藍隊如何在主機端偵測 Sudo 衍生的異常提權行為？**
  - **戰術思維**：配置 Auditd 監控 `execve` 系統調用，比對父進程為 `sudo` 且衍生子進程為 `/bin/sh`, `/bin/bash` 的事件；結合 `/var/log/auth.log` 關聯異常執行命令。
