# R19.3 Windows 登錄檔 AlwaysInstallElevated MSI 提權 (AlwaysInstallElevated Abuse)

---

## 🎯 作戰任務破題 (Tactical Objective & Mental Workflow)

**Windows 登錄檔 AlwaysInstallElevated MSI 提權** 的物理本質為**利用 Windows Installer 服務的群組原則配置缺陷（當 `HKCU` 與 `HKLM` 兩個登錄檔鍵值皆被啟用時），允許任何低權限普通使用者在執行任何微軟安裝程式封裝檔 (`.msi`) 時，Windows Installer 服務進程 (`msiexec.exe`) 會自動脫離當前使用者的權限限制，以最高特權 `NT AUTHORITY\SYSTEM` 身份執行安裝邏輯**。在紅隊實戰中，若系統管理員為了方便員工自行安裝軟體而啟用了此策略，攻擊者即可構造包含反彈 Shell 或新增管理員指令的惡意 MSI 安裝檔，實現無阻礙垂直提權。

```
[取得 Windows 本機普通使用者權限] ── 查詢登錄檔 AlwaysInstallElevated 狀態
                                          │
                                          ▼ 驗證兩個必要註冊表鍵值是否同時為 1
┌─────────────────────────────────────────┴─────────────────────────────────────────┐
│ 1. 查詢 HKLM\SOFTWARE\Policies\Microsoft\Windows\Installer: AlwaysInstallElevated │
│ 2. 查詢 HKCU\SOFTWARE\Policies\Microsoft\Windows\Installer: AlwaysInstallElevated │
│ 3. 核心限制條件: 兩者皆必須為 dword:00000001，若僅啟用單一項則漏洞無法成立！      │
└─────────────────────────────────────────┬─────────────────────────────────────────┘
                                          ▼
[雙重登錄檔皆為啟用狀態] ─────────────────► 構造武器化惡意 MSI 封裝檔 (msfvenom / WiX)
                                          │
                                          ▼ 靜默模式執行安裝程式: msiexec /quiet /qn /i
[Windows Installer 啟動特權引擎] ─────────► msiexec.exe 以 NT AUTHORITY\SYSTEM 執行代碼
                                          │
                                          ▼
[獲取系統最高特權: NT AUTHORITY\SYSTEM] ──► 成功完成本機無損特權提升！
```

## 🔬 第一動：Windows Installer 服務架構與提升權限物理機制 (Mechanics & MSI Engine)

### 1. Windows Installer (MSI) 的雙進程模型
Windows Installer 在執行安裝時採用特殊的雙進程客戶端/伺服端架構：
- **客戶端進程**：以發起使用者的身分運行，負責 UI 介面呈現與使用者互動。
- **伺服端服務進程**：作為 Windows 服務 (`msiserver`) 運行，其二進位檔為 `C:\Windows\System32\msiexec.exe /V`，預設執行身分為 `NT AUTHORITY\SYSTEM`。

```
[普通使用者 (User)] ── msiexec.exe /i setup.msi ──► [客戶端 UI 進程 (User 權限)]
                                                              │
                                                              ▼ RPC 通訊發起安裝請求
[Installer 服務進程 (msiserver)] ◄────────────────────────────┘
        │
        ├── 檢查登錄檔 AlwaysInstallElevated 配置標記
        │   ├── 若 HKLM 與 HKCU 均為 1: 【開啟全域特權安裝模式！】
        │   └── 執行 MSI 內部定義的自定義動作 (CustomActions)
        ▼
[以 NT AUTHORITY\SYSTEM 身分執行自定義 Payload 代碼！]
```

### 2. 雙重註冊表開關的防禦約束
微軟在設計此功能時設置了嚴格的雙重檢查：
1. 本機機器策略：`HKLM\SOFTWARE\Policies\Microsoft\Windows\Installer\AlwaysInstallElevated`
2. 當前使用者策略：`HKCU\SOFTWARE\Policies\Microsoft\Windows\Installer\AlwaysInstallElevated`
只有當這兩個位置的 DWORD 值皆明確等於 `1` 時，Windows Installer 才會賦予無特權使用者提升安裝的權限。

```bash

```

```cmd

msiexec /quiet /qn /i add_admin.msi
```

## 🛡️ 第五動：工程級防禦基線 (Hardening Baselines)

1. **全面停用群組原則中的 AlwaysInstallElevated 配置**：
   - 在網域群組原則管理員 (GPMC) 中，將「電腦設定\系統管理範本\Windows 元件\Windows Installer\一律以提高的權限進行安裝」設為**已停用 (Disabled)**。
   - 同時將「使用者設定\系統管理範本\Windows 元件\Windows Installer\一律以提高的權限進行安裝」設為**已停用 (Disabled)**。
2. **清理殘留登錄檔鍵值**：
   - 刪除 `HKLM\SOFTWARE\Policies\Microsoft\Windows\Installer\AlwaysInstallElevated`。

## 🧪 實戰演練環境搭建 (Environment & Lab Setup)

### 1. 極簡 AlwaysInstallElevated 狀態檢測腳本 (PowerShell, 20 行)
```powershell
# check_msi_elevated.ps1
$hklm = (Get-ItemProperty -Path "HKLM:\SOFTWARE\Policies\Microsoft\Windows\Installer" -ErrorAction SilentlyContinue).AlwaysInstallElevated
$hkcu = (Get-ItemProperty -Path "HKCU:\SOFTWARE\Policies\Microsoft\Windows\Installer" -ErrorAction SilentlyContinue).AlwaysInstallElevated

Write-Host "[*] 正在檢查 Windows Installer 特權提升配置..."
Write-Host "    └── HKLM AlwaysInstallElevated: $hklm"
Write-Host "    └── HKCU AlwaysInstallElevated: $hkcu"

if ($hklm -eq 1 -and $hkcu -eq 1) {
    Write-Host "[+] 雙重註冊表皆已開啟！系統存在 AlwaysInstallElevated 提權弱點" -ForegroundColor Green
    Write-Host "[+] FLAG{ALWAYS_INSTALL_ELEVATED_PRIVESC_VALIDATED}"
} else {
    Write-Host "[-] 條件未滿足 (必須兩者皆為 1)" -ForegroundColor Yellow
}
```

### 2. 三步作戰驗證流程
```cmd
:: 步驟 1: 執行檢測腳本驗證登錄檔策略
powershell.exe -ExecutionPolicy Bypass -File check_msi_elevated.ps1

:: 步驟 2: 驗證物理特徵（確認兩項配置均為 1 且 FLAG 被成功回顯）
:: 驗證輸出：[*] HKLM ... HKCU ... FLAG{ALWAYS_INSTALL_ELEVATED_PRIVESC_VALIDATED}

:: 步驟 3: 驗證加固修復（刪除或將鍵值設為 0）
reg add HKLM\SOFTWARE\Policies\Microsoft\Windows\Installer /v AlwaysInstallElevated /t REG_DWORD /d 0 /f
```

## 🎯 作戰驗收檢查點 (Operational Checkpoints)

- [ ] **Q1：為何 AlwaysInstallElevated 漏洞必須在 HKLM 與 HKCU 同時啟用才成立？**
  - **戰術思維**：微軟出於防禦深度考量，要求機器層級（代表系統管理員授權）與使用者層級（代表當前使用者情境）必須同時開啟此原則，只要其中一項為 0 或未配置，Installer 服務就不會給予 SYSTEM 權限。
- [ ] **Q2：使用 msfvenom 產生提權 MSI 檔案時，`-f msi-nouac` 與 `-f msi` 有何差別？**
  - **戰術思維**：`msi-nouac` 會在封裝中移除請求 UAC 提升的屬性標記，直接利用 Installer 服務後台執行，避免在圖形介面上彈出需要管理員點擊確認的 UAC 提示窗。
- [ ] **Q3：在執行 `msiexec /quiet /qn /i app.msi` 時，`/quiet` 與 `/qn` 參數分別代表什麼？**
  - **戰術思維**：`/quiet` 代表靜默模式，不向使用者顯示任何對話框；`/qn` 代表無使用者介面 (No UI)，兩者結合可確保全過程在背景隱蔽執行。
- [ ] **Q4：若目標主機未安裝 Python 或編譯器，紅隊如何在本機產生合法的 MSI 載荷？**
  - **戰術思維**：可使用 WiX Toolset 的 `candle.exe` 與 `light.exe` 編譯原生的 XML 定義，或者使用純 PowerShell 腳本寫入一個結構合法的 MSI 二進位資料庫檔案。
- [ ] **Q5：藍隊如何在 SOC 中監控利用 MSI 進行的特權提升攻擊？**
  - **戰術思維**：透過 Sysmon 監控 `ParentImage` 為 `msiexec.exe` 且衍生執行身分為 `SYSTEM` 的可疑子進程（如 `cmd.exe`, `powershell.exe`, `net.exe`）。
