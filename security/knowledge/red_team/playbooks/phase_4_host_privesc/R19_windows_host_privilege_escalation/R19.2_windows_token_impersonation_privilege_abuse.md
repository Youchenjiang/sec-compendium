# R19.2 Windows 權杖模擬與 SeImpersonatePotato 濫用 (Token Impersonation & Potato)

---

## 🎯 作戰任務破題 (Tactical Objective & Mental Workflow)

**Windows 權杖模擬與 SeImpersonate 特權濫用** 的物理本質為**利用服務帳戶（如 `IIS APPPOOL\DefaultAppPool` 或 `NT AUTHORITY\NETWORK SERVICE`）所持有的 `SeImpersonatePrivilege` 或 `SeAssignPrimaryTokenPrivilege` 核心特權，透過本機 COM/RPC 介面誘騙本機高特權服務（如 BITS、DCOM、RPCSS）向攻擊者監聽的命名管道或 TCP 埠發起 NTLM 認證，藉此捕獲並模擬 `NT AUTHORITY\SYSTEM` 的主權杖 (Primary Token)**。在紅隊實戰中，這是 WebShell 打點成功後從服務帳號躍遷至最高控制權的最通用標準武器。


## 🔬 第一動：存取權杖、安全情境與 SeImpersonate 物理機制 (Mechanics & Access Tokens)

### 1. Windows Access Token 結構與模擬等級
每個 Windows 進程或執行緒在訪問安全物件時，由 LSA 賦予 Access Token：
- **Token 類型**：
  - **Primary Token (主權杖)**：代表進程本身的身分（由 `CreateProcessAsUser` 使用）。
  - **Impersonation Token (模擬權杖)**：執行緒在客戶端代表情境下使用的臨時身分。
- **模擬等級 (Impersonation Levels)**：
  1. `SecurityAnonymous`：無法獲取客戶端身分。
  2. `SecurityIdentification`：僅能獲取客戶端身分與 SID，不能模擬。
  3. `SecurityImpersonation`：可在本機系統上以客戶端身分訪問本機資源。
  4. `SecurityDelegation`：可跨網路代表客戶端訪問遠端資源（極高風險）。

### 2. SeImpersonatePrivilege 的致命利用鏈
當進程擁有 `SeImpersonatePrivilege` 時：
1. 攻擊者在本地建立具備特權的 Named Pipe（例如 `\\.\pipe\test\pipe\spoolss`）。
2. 誘騙本機以 SYSTEM 身分運行的服務向該管道發起認證連線。
3. 攻擊者調用 Win32 API `ImpersonateNamedPipeClient()`，將當前執行緒的模擬權杖切換為連線進來的 SYSTEM 帳戶。
4. 調用 `DuplicateTokenEx()` 將模擬權杖轉換為 Primary Token，隨後調用 `CreateProcessWithTokenW()` 衍生出具有 SYSTEM 權限的惡意進程！

## 🛡️ 第五動：工程級防禦基線 (Hardening Baselines)

1. **嚴格剝離服務帳號特權**：
   - 審計所有服務帳戶；若業務不需要模擬他人身分，在本機安全策略中將其從「驗證後模擬客戶端 (SeImpersonatePrivilege)」列表中移除。
2. **停用非必要之列印多工緩衝處理器 (Print Spooler)**：
   - 在不需要列印功能的伺服器（特別是 DC 與 Web 伺服器），將 `Spooler` 服務停止並設為停用 (`sc config Spooler start= disabled`)。

## 🎯 作戰驗收檢查點 (Operational Checkpoints)

- [ ] **Q1：為何 Web 伺服器（如 IIS `w3wp.exe`）預設被賦予了 `SeImpersonatePrivilege` 特權？**
  - **戰術思維**：因為 Web 伺服器在啟用 Windows 整合式身分驗證時，需要代表訪問的特定客戶端身分去存取後端檔案與資料庫，因此微軟預設為服務帳號賦予此模擬權杖特權。
- [ ] **Q2：JuicyPotato 為何在 Windows 10 1809 與 Windows Server 2019 後宣告失效？**
  - **戰術思維**：微軟在更新中修補了 DCOM 機制，禁止將 OXID 解析請求重定向至自定義本機通訊埠，阻斷了其在 135 埠的中間人反射鏈。
- [ ] **Q3：PrintSpoofer 是如何繞過微軟對 DCOM 的修補實現提權的？**
  - **戰術思維**：PrintSpoofer 改為利用 Windows Print Spooler 服務的 RPC 呼叫 (`RpcOpenPrinter`)，誘騙 Print Spooler 透過命名管道回連，巧妙繞過了 DCOM 的修補限制。
- [ ] **Q4：在 Windows 11 / Server 2022 最新環境下，哪款 Potato 武器具備通殺能力？**
  - **戰術思維**：GodPotato（神之土豆），它利用了 Windows 本機 DCOM 氧化機制 (Oxid Resolver) 的底層設計，即使 Print Spooler 服務被停用，仍可達成提權。
- [ ] **Q5：藍隊如何在 SOC 中有效獵捕來自 WebShell 的 Potato 提權行為？**
  - **戰術思維**：建立行為規則監控 `w3wp.exe`、`tomcat.exe` 等進程，若其直接衍生出 `cmd.exe` 或 `powershell.exe` 且執行身分為 `NT AUTHORITY\SYSTEM`，即判定為高危險提權告警。
