# R22.1 直接系統調用 Direct Syscalls 與 EDR 鉤子繞過 (Direct Syscalls & Unhooking)

---

## 🎯 作戰任務破題 (Tactical Objective & Mental Workflow)

**直接系統調用 Direct Syscalls 與 EDR 鉤子繞過** 的物理本質為**跳過被端點偵測與回應系統 (EDR) 在使用者態 (`ntdll.dll`) 中設置了行內鉤子 (Inline Hooks / JMP 指令) 的敏感 API（如 `NtAllocateVirtualMemory`, `NtWriteVirtualMemory`, `NtCreateThreadEx`），在組合語言層面直接透過 `syscall` 指令與系統調用號 (SSN) 進入 Windows 核心態完成特權調用**。在紅隊實戰中，現代主機防衛產品普遍透過 DLL 注入對所有 API 進行即時監控，紅隊透過 SysWhispers、Halo's Gate 或動態解析 SSN，可徹底粉碎使用者態 EDR 的所有監控視線。

```
[常規 API 調用 (被 EDR 阻斷)] ── OpenProcess / VirtualAllocEx
                                       │
                                       ▼ 跳轉至 ntdll.dll
┌──────────────────────────────────────┴──────────────────────────────────────┐
│ [ntdll!NtAllocateVirtualMemory] 被 EDR 置換為: jmp edr_sensor.dll           │
│ ➔ EDR 掃描記憶體指標、調用堆疊 (Call Stack) 與 Shellcode 特徵 ➔ 【直接攔截！】│
└─────────────────────────────────────────────────────────────────────────────┘

[直接系統調用 (Direct Syscalls 繞過)]
  1. 動態讀取 ntdll.dll 導出表，解析當前 Windows 版本的 SSN (System Service Number)
  2. 避開記憶體被 Hook 的前導位元組 (利用 Tartaros/Halo's Gate 鄰近搜尋)
  3. 在自己的代碼區段直接發起組合語言指令: mov r10, rcx; mov eax, SSN; syscall; ret
                                       │
                                       ▼ 跨過使用者態 Hook，直達 Windows Kernel
[Windows 核心 (ntoskrnl.exe)] ─────────► 執行特權操作，使用者態 EDR 遙測完全失明！
```

## 🔬 第一動：EDR Inline Hook、SSN 系統服務號與 Syscall 物理機制 (Mechanics & Syscall Engine)

### 1. EDR Inline Hook 物理結構
現代 EDR 在進程加載時，會修改 `ntdll.dll` 中高危敏感函數的前 5 個位元組：
- **未被 Hook 的乾淨 stub**：
  ```asm
  mov r10, rcx
  mov eax, 0x0018  ; SSN (系統服務調用號)
  test byte ptr [7FFE0308h], 1
  jne ...
  syscall
  ret
  ```
- **被 EDR Hook 的污染 stub**：
  ```asm
  jmp qword ptr [edr_inspection_engine]  ; 前 5 位元組被強制覆寫為跳轉
  nop
  ```

### 2. Halo's Gate (光環之門) 動態 SSN 解析原理
微軟在不同的 Windows 10/11 組建版本 (Build Number) 中，系統調用號 (SSN) 會頻繁動態變動：
- Halo's Gate 透過讀取 `ntdll` 內存；若目標函數已被 Hook（首位元組為 `0xE9` 即 JMP）。
- 它會向上或向下搜尋相鄰未被 Hook 的系統調用函數（其 stub 依然完整），根據 SSN 嚴格遞增的物理規律，推導出目標函數的真實 SSN！

### 1. Syscall 規避進階對抗策略表
| 規避面向 | 原始觸發特徵 | 變形隱蔽手法 | 原理解析 |

## 🎯 作戰驗收檢查點 (Operational Checkpoints)

- [ ] **Q1：傳統 EDR 為何需要對 `ntdll.dll` 實施 Inline Hooking？**
  - **戰術思維**：因為 Windows 應用層程序要訪問核心服務，最終都必須調用 `ntdll.dll` 導出的低階 API；EDR 藉由在此處插入跳轉指令，可在參數進入核心前進行惡意特徵審查。
- [ ] **Q2：Direct Syscalls 的核心原理是什麼？它如何擊敗傳統 EDR Hook？**
  - **戰術思維**：Direct Syscalls 直接在自己的代碼區段手寫組合語言 `syscall` 指令，完全繞過包含 Hook 的 `ntdll.dll`，使使用者態的 EDR 檢查模組完全無法被觸發。
- [ ] **Q3：什麼是 Halo's Gate (光環之門)？它解決了 Hell's Gate 的什麼痛點？**
  - **戰術思維**：Hell's Gate 若發現目標函數本身已被 Hook，便無法解析 SSN；Halo's Gate 透過向上/向下搜尋相鄰未被 Hook 的函數 stub，結合固定位元組間距動態推導出被 Hook 函數的正確 SSN。
- [ ] **Q4：為什麼現代高階 EDR 能偵測出 Direct Syscalls？紅隊如何應對？**
  - **戰術思維**：EDR 透過核心態 ETW-TI 檢查呼叫堆疊 (Call Stack) 的返回地址，若發現 syscall 不是從 `ntdll.dll` 內部發出的則告警；紅隊改用 Indirect Syscalls (間接調用)，跳轉到 `ntdll` 的 syscall 指令位置執行以維持合法堆疊。
- [ ] **Q5：企業藍隊應如何防範繞過使用者態 Hook 的進階攻擊手法？**
  - **戰術思維**：部署依賴核心回呼函數（如 `PsSetCreateProcessNotifyRoutineEx`）與硬體虛擬化保護 (HVCI) 的新一代 EDR，不再依賴脆弱的使用者態 Hook。
