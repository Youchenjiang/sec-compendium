# R22.5 父進程 ID (PPID) 欺騙與命令列參數偽裝 (PPID Spoofing & Argument Mocking)

---

## 🎯 作戰任務破題 (Tactical Objective & Mental Workflow)

**父進程 ID (PPID) 欺騙與命令列參數偽裝** 的物理本質為**利用 Windows 高級進程屬性清單 API (`InitializeProcThreadAttributeList` 與 `PROC_THREAD_ATTRIBUTE_PARENT_PROCESS`) 與進程環境區塊 (PEB - Process Environment Block) 動態重寫機制，在生成子進程時將其父進程欺騙指定為合法的系統長駐進程（如 `explorer.exe` 或 `winlogon.exe`），同時在建立進程時傳入無害良性的偽裝命令列參數，待進程以掛起狀態建立後、於記憶體中覆寫 PEB 的 `CommandLine` 緩衝區為真實的攻擊參數再恢復執行**。在紅隊實戰中，這是粉碎 EDR 基於「異常父子進程樹 (Process Tree)」與「可疑命令列引數 (CLI Arguments)」啟發式關聯告警的必備偽裝術。

```
[常規可疑攻擊鏈 (觸發 EDR 嚴重告警)]:
  powershell.exe (PID: 5040) ──► whoami.exe (父進程為 powershell，觸發偵測！)

[PPID 欺騙與參數偽裝作戰鏈]:
  1. 攻擊進程獲取 explorer.exe (PID: 1420) 之句柄
  2. 調用 CreateProcess(..., Attribute: PARENT_PROCESS=1420, Args: "notepad.exe benign.txt")
  3. 進程掛起: 記憶體覆寫 PEB 中的 CommandLine 為: "powershell -enc <MALICIOUS_PAYLOAD>"
  4. 恢復執行!
          │
          ▼ 藍隊 EDR 看到的進程樹:
  explorer.exe (PID: 1420 - 合法桌面環境) ──► notepad.exe / powershell.exe (父子關係完全合法！)
```

## 🔬 第一動：PROC_THREAD_ATTRIBUTE 屬性清單與 PEB 結構動態篡改物理機制 (Mechanics & Memory Spoofing)

### 1. PPID Spoofing (父進程欺騙) 底層原理
Windows Vista 引入了 `CreateProcessA/W` 的擴展版 **`CreateProcess` 搭配屬性清單 (`EXTENDED_STARTUPINFO_PRESENT`)**：
- 允許調用者透過 `UpdateProcThreadAttribute` 指定 `PROC_THREAD_ATTRIBUTE_PARENT_PROCESS` 屬性。
- 只要當前進程擁有對目標父進程（如 `explorer.exe`）的 `PROCESS_CREATE_PROCESS` 存取權限，核心就會將新進程的父進程指針指向該目標，在系統進程樹中直接「認祖歸宗」。

### 2. Argument Mocking / Spoofing (參數偽裝) 底層機制
- **第一階段**：以良性參數啟動進程（如 `cmd.exe /c echo "Safe"`），此時 EDR 用戶層 Hook 或 API 捕獲到的參數完全正常。
- **第二階段**：在進程尚未執行前，透過 `ReadProcessMemory` 定位目標進程的 PEB 結構，找到 `RTL_USER_PROCESS_PARAMETERS` 結構體。
- **第三階段**：利用 `WriteProcessMemory` 覆寫其 `CommandLine.Buffer`，注入真正的攻擊命令。核心調用完成後，進程啟動時讀取的是被篡改後的惡意命令列。

## ⚡ 第二動：戰術執行與工具鏈操作 (Attack Vectors & Exploitation)

### 1. 核心 PPID 欺騙 C++ 實作範例
```cpp
#include <windows.h>

void SpoofParentAndExecute(DWORD parentPid, LPCSTR targetCmd) {
    STARTUPINFOEXA si = { sizeof(si) };
    PROCESS_INFORMATION pi = { 0 };
    SIZE_T attributeSize = 0;

    HANDLE hParent = OpenProcess(PROCESS_CREATE_PROCESS, FALSE, parentPid);
    InitializeProcThreadAttributeList(NULL, 1, 0, &attributeSize);
    si.lpAttributeList = (LPPROC_THREAD_ATTRIBUTE_LIST)HeapAlloc(GetProcessHeap(), 0, attributeSize);
    InitializeProcThreadAttributeList(si.lpAttributeList, 1, 0, &attributeSize);

    // 關鍵: 設定父進程屬性為指定的 parentPid (如 explorer.exe)
    UpdateProcThreadAttribute(si.lpAttributeList, 0, PROC_THREAD_ATTRIBUTE_PARENT_PROCESS, &hParent, sizeof(HANDLE), NULL, NULL);

    CreateProcessA(NULL, (LPSTR)targetCmd, NULL, NULL, FALSE, EXTENDED_STARTUPINFO_PRESENT, NULL, NULL, (LPSTARTUPINFOA)&si, &pi);

    CloseHandle(pi.hProcess);
    CloseHandle(pi.hThread);
    CloseHandle(hParent);
}
```

## 🎯 作戰驗收檢查點 (Operational Checkpoints)

- [ ] **Q1：PPID 欺騙技術能夠粉碎藍隊 SIEM / SOC 分析師的何種直覺偵測模型？**
  - **戰術思維**：粉碎基於「異常父子進程樹」的關聯告警（如 Word/Excel 直接衍生 cmd.exe，或 PowerShell 衍生 whoami.exe）；使其看起來完全是從 explorer 正常點擊啟動。
- [ ] **Q2：使用 `PROC_THREAD_ATTRIBUTE_PARENT_PROCESS` 時，攻擊進程必須具備對偽造父進程的何種權限句柄？**
  - **戰術思維**：必須成功透過 `OpenProcess` 獲取包含 `PROCESS_CREATE_PROCESS` 存取遮罩的句柄。
- [ ] **Q3：什麼是命令列參數偽裝 (Argument Mocking)？其解決的 EDR 偵測問題是什麼？**
  - **戰術思維**：解決安全軟體在進程建立瞬間審查命令列中敏感關鍵字（如 `-enc`、`IEX`、`downloadstring`）的問題；初始建立時參數良性，建立後再在記憶體覆寫。
- [ ] **Q4：藍隊 EDR 為什麼可以從核心層識破用戶層的 PEB 命令列覆寫？**
  - **戰術思維**：因為 Windows 核心在建立進程時已經在核心物件 (`EPROCESS`) 中鎖定了原始命令列，核心追蹤與 ETW 日誌記錄的是最初的良性字串，兩者對比即可發現不一致。
- [ ] **Q5：若攻擊者選擇 `winlogon.exe` (SYSTEM) 作為欺騙父進程，但攻擊者自身僅為普通用戶，操作會成功嗎？**
  - **戰術思維**：不會成功。普通用戶無法跨權限打開 SYSTEM 權限進程的 `PROCESS_CREATE_PROCESS` 句柄，系統將直接回傳 `ERROR_ACCESS_DENIED`。
