## 🎯 作戰任務破題 (Tactical Objective & Mental Workflow)

**主機可達性驗證與存活探測 (Host Reachability Validation)** 的物理本質為**利用傳輸層與網路層控制協定之「狀態應答機制」，穿透邊界防火牆對 ICMP 之單純阻斷，精確判定目標 IP 是否具備活躍之網路堆疊 (Active Protocol Stack)**。現代邊界防火牆多預設丟棄 (DROP) ICMP Echo (Ping)；紅隊必須交叉調度 TCP SYN Ping、TCP ACK Ping (利用無狀態防火牆規則漏洞) 以及 UDP 應用探針，在不觸發大量告警的前提下迅速收斂出真實存在之主機清單。

```
[攻擊者控制台] ── 針對授權 IP 網段發送多樣化探測封包
                        │
                        ▼ 穿透邊界封包過濾防護
┌───────────────────────┴───────────────────────────────────────┐
│ 探針 A: ICMP Echo ─────► [邊界防火牆] ── 預設直接丟棄 (DROP / 無回應) │
│ 探針 B: TCP SYN (443) ─► [放行通過] ──► 目標主機回傳 SYN/ACK 或 RST  │
│ 探針 C: TCP ACK (80) ──► [無狀態過濾] ─► 騙過防火牆，目標主機回傳 RST  │
└───────────────────────┬───────────────────────────────────────┘
                        ▼
[捕獲協定底層應答 (RST / ACK)] ─► 物理證明目標作業系統網路堆疊處於存活狀態！
                        │
                        ▼ 排除無效離線 IP
[產出活躍主機白名單] ──────────► 精確界定作戰半徑，避免對空網段進行無效掃描！
```

## 🔬 第一動：網路探針通訊協定物理特徵矩陣 (Mechanics & Protocol Probes)

### 1. 存活探測協定應答物理機制對照表

| 探測技術 | 探測封包特徵 (Probe) | 活躍主機預期應答 | 防火牆穿透物理原理 |
| :--- | :--- | :--- | :--- |
| **ICMP Echo Ping** | ICMP Type 8 (Echo Request) | ICMP Type 0 (Echo Reply) | 最基礎探測，極易被外網邊界防火牆無差別阻斷 |
| **TCP SYN Ping** | TCP 旗標 `SYN` (Port 80/443) | `SYN/ACK` (埠開放) 或 `RST` (埠關閉) | 模擬合法握手首部，通常獲外部防火牆放行 |
| **TCP ACK Ping** | TCP 旗標 `ACK` (Port 80) | **強制回傳 `RST`** (未預期的 ACK 封包) | **穿透無狀態防火牆** (防火牆誤判為已建立之連線回應) |
| **UDP Ping** | UDP 封包至高位埠 (Port 40125) | ICMP Type 3 Code 3 (Port Unreachable) | 適用於探測封閉所有 TCP 埠之 Linux/Unix 主機 |

# 1. 結合 TCP SYN (443) 與 TCP ACK (80) 之高效穿透探測 (Nmap -sn)

# 4. 超高速平行 ICMP 掃描 (Fping)
fping -a -g 203.0.113.0/24 -r 1 -t 100 2>/dev/null

## 🛡️ 第五動：工程級防禦基線 (Hardening Baselines)

1. **全面部署具備狀態檢驗之防火牆 (Stateful Packet Inspection, SPI)**：
   - 嚴格校驗 TCP 連線狀態表；對未包含於連線狀態表之單獨 `ACK` 封包直接於邊界靜默丟棄 (DROP)，杜絕穿透探測。
2. **邊界靜默丟棄 ICMP (Border ICMP Silent Drop)**：
   - 外網對象一律禁止回傳 `ICMP Echo Reply` 或 `Destination Unreachable`，避免將主機存活信號外洩。
3. **部署網路蜜罐與暗網空間 (Darknet / Network Canaries)**：
   - 在未使用的私有 IP 網段配置蜜罐監聽，一旦有任何探測封包抵達未指派的 IP，100% 定性為內部掃描行為。

    s.connect((target_host, target_port))

## 🎯 作戰驗收檢查點 (Operational Checkpoints)

- [ ] **Q1：當目標主機回傳 `TCP RST` 封包時，為何可作為主機「100% 存活」的決定性證據？**
  - **戰術思維**：`RST` (連線重置) 封包是由**目標作業系統之 TCP/IP 核心堆疊主動產生**的（代表「此埠位未監聽服務」）。只有在主機硬體上電、作業系統運作且網路線接通的情況下才能發出 RST，因此主機必定存活。
- [ ] **Q2：無狀態防火牆 (Stateless Firewall) 為何無法阻擋 TCP ACK Ping 探測？**
  - **戰術思維**：無狀態防火牆只檢查單一封包的旗標；為了允許內網主機訪問外部 Web，通常會配置「允許包含 ACK 旗標的連線回傳」。攻擊者發送偽造的單獨 ACK 封包會被無條件放行，觸發目標主機回傳 RST。
- [ ] **Q3：在 IPv6 環境中，傳統廣播 Ping 徹底失效的原因為何，紅隊如何破局？**
  - **戰術思維**：IPv6 取消了廣播 (Broadcast) 機制；紅隊破局手法為改用 **多播位址 (Multicast Address)** 如 `ff02::1` (所有節點多播)，或從 DNS 歷史記錄、日誌與 IPv6 EUI-64 格式推導位址。
- [ ] **Q4：使用 Nmap `-Pn` 參數在何種情況下是強制必選的作戰配置？**
  - **戰術思維**：當目標邊界防火牆完全阻斷了所有探針 (ICMP/TCP Ping)，若不加上 `-Pn`，Nmap 會誤判目標主機已離線並直接放棄後續所有掃描；加上 `-Pn` 則跳過存活檢查，強制對目標發起完整掃描。
- [ ] **Q5：為何在內網橫向移動時，ARP Ping 比任何 IP 層探測都更加隱蔽高效？**
  - **戰術思維**：ARP 是二層 (Layer 2) 協定，**本機 Windows/Linux 防火牆完全無法攔截 ARP 查詢**；且 ARP 請求由網路交換機硬體直達，毫秒級完成整網存活判定。
