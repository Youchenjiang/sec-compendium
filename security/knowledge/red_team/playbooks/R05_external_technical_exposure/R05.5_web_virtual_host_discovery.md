# R05.5 Web 虛擬主機與主機標頭路由探測 (Web Virtual Host Discovery)

---

## 🎯 作戰任務破題 (Tactical Objective & Mental Workflow)

**Web 虛擬主機探測 (Virtual Host Discovery / VHost Fuzzing)** 的物理本質為**利用 HTTP/1.1 與 HTTP/2 中「以名稱為基礎的虛擬主機路由機制 (Name-Based Virtual Hosting)」，在目標 IP 保持不變的情況下動態替換 `Host` 標頭，藉以發掘未註冊公開 DNS 記錄、但實際監聽於該實體伺服器之內部開發、測試或管理站點 (Shadow VHosts)**。現代 Web 架構常在單一公網 IP 上藉由反向代理分發數十個內部網域；紅隊透過高精度回應濾波 (Filtering)，能在公網直接命中本應屬於內網之受保護核心系統。

```
[攻擊者控制台] ── 鎖定單一已確認之公網 IP: 203.0.113.10
                        │
                        ▼ 字典動態注入 Host 標頭: Host: FUZZ.corp.internal
┌───────────────────────┴───────────────────────────────────────┐
│ 請求 A: Host: www.corp.internal ─────► 回傳長度: 4210 bytes (預設首頁)│
│ 請求 B: Host: test.corp.internal ────► 回傳長度: 4210 bytes (無此站台)│
│ 請求 C: Host: staging-admin.corp ────► 回傳長度: 1530 bytes (命中內部站！)│
└───────────────────────┬───────────────────────────────────────┘
                        ▼
[邊界反向代理 (Nginx/Envoy)] ───► 匹配到隱藏之 server_name 區塊，路由至內部系統！
                        │
                        ▼ 穿透 DNS 邊界
[成功探獲影子虛擬主機] ─────────► 直接於外網存取未經授權之內部後台或測試環境！
```

## 🔬 第一動：Name-Based 虛擬主機路由與比對演算法物理架構 (Mechanics & VHost Routing)

### 1. Nginx `server_name` 核心路由判定演算法

| 匹配優先級 | 比對規則型態 | 匹配邏輯說明 | 攻擊探測要點 |
| :--- | :--- | :--- | :--- |
| **優先級 1** | **精確名稱 (Exact Name)** | 完全符合傳入之 `Host` 標頭字串 | 構造精確內部子網域 (`admin.corp.internal`) |
| **優先級 2** | **最長星號開頭萬用字元** | 如 `*.corp.internal` | 探測多級子網域名稱結構 |
| **優先級 3** | **最長星號結尾萬用字元** | 如 `mail.*` | 探測不同頂級域名之映射 |
| **預設降級** | **default_server** | 若所有規則均未命中，路由至預設站台 | 作為基線 (Baseline) 予以精確過濾排除 |

## ⚡ 第二動：戰術執行與工具鏈操作 (Attack Vectors & Automation)

### 1. 核心虛擬主機模糊測試指令速查表 (ffuf / Gobuster)

```bash
# 1. 獲取預設首頁之回應大小 (建立濾波基線)
curl -s -I "https://203.0.113.10" -H "Host: nonexistent.corp.internal" -k | grep -i "Content-Length"

# 2. 透過 ffuf 發起高速 Host 模糊測試 (以 -fs 濾除預設回應長度)
ffuf -u "https://203.0.113.10" -H "Host: FUZZ.corp.internal" \
    -w /usr/share/seclists/Discovery/DNS/subdomains-top1million-5000.txt \
    -fs 4210 -mc 200,301,302,401,403 -t 50 -o vhost_results.json

# 3. 使用 Gobuster vhost 模式執行探測
gobuster vhost -u https://203.0.113.10 -w subdomains.txt --append-domain -k

# 4. 針對 TLS SNI (Server Name Indication) 實施雙軌路由測試
ffuf -u "https://FUZZ.corp.internal" -w subdomains.txt --sni "FUZZ.corp.internal" -fs 4210
```

## 🥷 第三動：防禦規避與日誌特徵操控 (Evasion & Baseline Filtering)

### 1. 虛擬主機探測特徵消減策略表

| 規避面向 | 原始觸發特徵 | 變形隱蔽手法 | 原理解析 |
| :--- | :--- | :--- | :--- |
| **假陽性干擾 (False Positives)**| 伺服器對所有未命中請求均回傳 200 OK | **多維度動態過濾 (`-fw`, `-fl`)** | 改以單詞數 (Words) 或行數 (Lines) 消除雜訊 |
| **Host 標頭異常偵測** | 請求使用純 IP 存取但 Host 帶域名 | 構造內部常用端口綴詞 (`Host: dev:8080`) | 繞過僅過濾標準 80/443 之靜態檢驗規則 |
| **WAF 網域名稱阻斷** | WAF 攔截非公開網域名稱 | 利用 `X-Forwarded-Host` 標頭實施走私路由 | 誘使後端反向代理讀取備用標頭進行分發 |

## 🛡️ 第五動：工程級防禦基線 (Hardening Baselines)

1. **嚴格配置預設虛擬主機並靜默拋棄連線 (Explicit Default Server)**：
   - Nginx：配置預設伺服器塊，對任何未顯式匹配的主機名直接回傳 444 中斷連線：
     ```nginx
     # 安全: 阻斷未授權之 VHost 探測
     server {
         listen 80 default_server;
         listen 443 ssl default_server;
         server_name _;
         return 444; # 立即關閉 TCP 連線，不吐出任何字元
     }
     ```
2. **內外網實體環境嚴格隔離**：
   - 嚴禁將內部開發 (`dev`)、測試 (`staging`) 或管理介面與外部公開業務綁定在同一台反向代理與同一個公網 IP 上。
3. **強制 Host 標頭白名單校驗**：
   - 於應用層中介層強制校驗 `Host` 標頭是否屬於授權之生產網域名稱，不符者立即回傳 400 Bad Request。

## 🧪 實戰演練環境搭建 (Environment & Lab Setup)

### 1. 極簡多虛擬主機路由模擬靶機 (Python Flask, 20 行)
```python
# vhost_app.py
from flask import Flask, request, jsonify

app = Flask(__name__)

@app.route("/")
def router():
    host = request.headers.get("Host", "").split(":")[0]
    # 模擬以名稱為基礎之虛擬主機分發邏輯
    if host == "admin-internal.corp":
        return jsonify({
            "status": "success",
            "vhost": "admin-internal.corp",
            "flag": "FLAG{VHOST_DISCOVERY_INTERNAL_ROUTING_PWNED}"
        })
    # 預設公網公開站台回應 (長度固定，便於攻擊者透過 -fs 濾除)
    return "<html><body><h1>Welcome to Corporate Public Portal</h1></body></html>"

if __name__ == "__main__":
    app.run(port=8888)
```

### 2. 三步作戰驗證流程
```bash
# 步驟 1: 啟動靶機
python3 vhost_app.py

# 步驟 2: 模擬發送偽造 Host 標頭存取隱藏站點
curl -H "Host: admin-internal.corp" http://127.0.0.1:8888/
# 驗證輸出：{"flag":"FLAG{VHOST_DISCOVERY_INTERNAL_ROUTING_PWNED}","status":"success","vhost":"admin-internal.corp"}

# 步驟 3: 驗證未命中之預設站台特徵
curl -H "Host: random.corp" http://127.0.0.1:8888/
# 驗證輸出：回傳公網首頁 HTML (長度不同)，證實可透過長度過濾精確收割內部站
```

## 🎯 作戰驗收檢查點 (Operational Checkpoints)

- [ ] **Q1：虛擬主機探測 (VHost Fuzzing) 與子網域列舉 (Subdomain Recon) 有何關鍵物理差異？**
  - **戰術思維**：子網域列舉是查詢 **DNS 伺服器**；而虛擬主機探測是直接向 **Web 伺服器** 發送 HTTP 請求並替換 `Host` 標頭。即使某子網域完全未在公網 DNS 解析，只要目標 Web 伺服器有配置該路由，VHost Fuzzing 依然能將其完全挖出。
- [ ] **Q2：在 HTTPS 環境中，TLS 握手時的 SNI (Server Name Indication) 會對 VHost 探測造成何種影響？**
  - **戰術思維**：現代前端反向代理（如 Cloudflare 或嚴格配置的 Nginx）會在 TLS 握手階段即檢查 SNI；若 SNI 不符合，連線可能在 TCP 握手後立即被重置。因此工具必須支援同步變更 TLS SNI 欄位。
- [ ] **Q3：在執行 ffuf 模糊測試時，`-fs`、`-fw`、`-fl` 三者的選擇順序為何？**
  - **戰術思維**：首選 `-fs` (過濾固定 Bytes 大小)；若預設錯誤頁面包含動態時間戳導致長度微幅變動，改用 `-fw` (過濾單詞數) 或 `-fl` (過濾行數) 即可完美消除動態干擾。
- [ ] **Q4：何謂「Host 標頭走私/混淆 (Host Header Confusion)」，其如何繞過邊界過濾？**
  - **戰術思維**：利用傳入多個 Host 標頭、絕對 URI (Absolute URI `GET http://internal/`)，或在 Host 標頭中加入空白/Tab 字元，引發前端代理與後端伺服器在語意解析上的不一致。
- [ ] **Q5：為何在雲端託管環境 (如 AWS ALB, CloudFront) 中，VHost Fuzzing 通常無法探測到其他租戶？**
  - **戰術思維**：因為公有雲負載平衡器嚴格依賴註冊在該帳號下的目標群組 (Target Groups) 與憑證關聯；未綁定至該負載平衡器的網域名稱會在邊界直接被拋出 403/404，無法跨租戶漫遊。
