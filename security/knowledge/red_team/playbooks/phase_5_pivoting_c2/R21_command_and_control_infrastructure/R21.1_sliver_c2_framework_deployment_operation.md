## 🎯 作戰任務破題 (Tactical Objective & Mental Workflow)

## 🔬 第一動：Sliver 通訊架構、雙向憑證 mTLS 與載荷物理編譯機制 (Mechanics & Implant Engine)

### 1. 雙向相互認證 (mTLS) 通訊機制
Sliver 預設推薦使用 mTLS 作為 C2 通訊協議：
- 不僅伺服端擁有證書，**每個生成的 Implant 載荷內部都硬編碼了獨立的客戶端 X.509 憑證**。
- 連線時雙方互相校驗證書有效性。任何中間人（如 SOC 的 TLS 解密代理）因無法提供有效的客戶端證書，連線將在握手階段直接中斷，阻斷藍隊的封包內容還原！

### 2. 動態編譯與混淆引擎
Sliver 每次生成 Implant 時，是在伺服端後台現場調用 Go 編譯器：
- 隨機生成變數名、函數名與常數。
- 可整合 Garble 工具鏈對 Go 抽象語法樹進行深度混淆，抹除套件名稱、檔案路徑與執行緒追蹤資訊。

## 🎯 作戰驗收檢查點 (Operational Checkpoints)

- [ ] **Q1：Sliver C2 的 mTLS 傳輸模式與常規 HTTPS 傳輸相比，防禦規避優勢何在？**
  - **戰術思維**：mTLS 要求雙向憑證認證，若藍隊在中間架設 TLS 解密網關 (SSL Inspection Proxy)，因無法提供合法的客戶端證書，握手會直接失敗，有效保護 C2 指令不被還原。
- [ ] **Q2：Sliver 中的「Beacon」模式與「Session」模式有何本質區別？**
  - **戰術思維**：Session 模式維持即時長連線，操作響應快但容易觸發長連線告警；Beacon 模式以特定間隔定時異步輪詢（Sleep + Jitter），隱蔽性極高。
- [ ] **Q3：在生成 Sliver 載荷時，Jitter (抖動率) 的主要作用是什麼？**
  - **戰術思維**：在基礎休眠時間上增加隨機百分比的延遲波動，打破固定的心跳時間週期，讓 SIEM 無法利用時間間隔方差分析偵測出異常 C2 通訊。
- [ ] **Q4：Sliver 如何支援在記憶體中直接執行 C# 工具（如 Rubeus、Seatbelt）？**
  - **戰術思維**：Sliver 內建了 `execute-assembly` 功能，可在目標進程記憶體中動態加載 CLR (通用語言運行庫)，免二進位落地直接執行 .NET 武器。
- [ ] **Q5：藍隊應如何從主機記憶體維度獵捕休眠中的 C2 Implant？**
  - **戰術思維**：利用 Moneta 或 PE-sieve 等記憶體取證工具，掃描進程記憶體中具有可執行屬性但無對應磁碟模組映射（Unbacked Executable Memory）的私有頁面。
