## 🔬 第一動：Demon Agent 核心架構、間接系統調用與堆疊欺騙物理機制 (Mechanics & EDR Bypass)

### 1. Indirect Syscalls (間接系統調用) 的底層本質
傳統直接系統調用 (Direct Syscalls) 會在二進位中留下硬編碼的 `syscall` 指令，容易被 EDR 標記為靜態特徵。
- **Demon 的間接調用策略**：動態讀取 `ntdll.dll` 獲取真實的系統調用號 (SSN - System Service Number) 後，將執行流跳轉回 `ntdll.dll` 本體內的合法 `syscall; ret` 機器碼區間執行。
- **核心優勢**：向 Windows 核心發起調用時，堆疊回溯 (Stack Walking) 與 RIP 指針完全指向合法微軟系統 DLL 內部，徹底化解 EDR 用戶層 Hook 監控。

### 2. 動態呼叫堆疊欺騙 (Stack Spoofing)
- 在執行敏感 API 前，Demon 動態構建一個看似由合法系統 API（如 `BaseThreadInitThunk -> RtlUserThreadStart`）發起的偽造呼叫堆疊訊框。
- 當 EDR 核心回溯檢查呼叫來源時，無法追溯至非受管或動態分配之惡意記憶體頁。

## 🎯 作戰驗收檢查點 (Operational Checkpoints)

- [ ] **Q1：Havoc 的「間接系統調用 (Indirect Syscalls)」與傳統「直接系統調用 (Direct Syscalls)」在規避 EDR 上有何核心差異？**
  - **戰術思維**：直接調用在自身二進位中發起 `syscall`，呼叫堆疊來源是非法記憶體；間接調用則跳轉至 `ntdll.dll` 內部執行 `syscall`，維持合法的調用堆疊回溯。
- [ ] **Q2：Demon Agent 採用的 Ekko 休眠混淆技術是如何在休眠期躲過記憶體掃描器的？**
  - **戰術思維**：利用 Windows Timer Queue 與 ROP 鏈，在進入休眠前異步將自身的記憶體權限降為不可讀寫，並透過 XOR/RC4 加密記憶體，喚醒前再解密還原。
- [ ] **Q3：什麼是呼叫堆疊欺騙 (Call Stack Spoofing)？其解決的 EDR 偵測維度為何？**
  - **戰術思維**：偽造執行敏感 API 時的呼叫來源鏈路，使 EDR 在回溯線程呼叫棧時，看起來是由合法微軟系統 DLL 正常發起，消除動態內存注入痕跡。
- [ ] **Q4：在藍隊偵測角度，微軟的 ETW-TI (Threat Intelligence) 機制為何能有效遏制 Indirect Syscalls？**
  - **戰術思維**：因為 ETW-TI 位於 Windows 核心層 (Ring 0)，無論在用戶層如何跳轉繞過 Hook，核心在執行真正系統調用時都能捕獲真實的調用上下文與呼叫進程屬性。
- [ ] **Q5：在高度對抗環境中，紅隊操作員下達命令時應優先採用 Fork-and-Run 還是 Inline 模式？**
  - **戰術思維**：優先採用 Inline 模式（如 `inline-execute`），在自身進程內部動態載入執行，避免產生可疑的子進程生成 (Process Creation) 與跨進程注入特徵。
