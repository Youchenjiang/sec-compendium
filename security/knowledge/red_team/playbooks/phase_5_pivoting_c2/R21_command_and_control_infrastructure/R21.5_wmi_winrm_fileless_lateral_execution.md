# R21.5 WMI 與 WinRM 無檔案橫向移動與遠端執行 (WMI & WinRM Lateral Movement)

---

## 🎯 作戰任務破題 (Tactical Objective & Mental Workflow)

**WMI 與 WinRM 無檔案橫向移動與遠端執行** 的物理本質為**利用 Windows 企業環境內建的系統管理基礎設施（Windows Management Instrumentation 基於 DCOM/RPC 135 埠與 Windows Remote Management 基於 WS-Management HTTP/HTTPS 5985/5986 埠），在取得網域高權限或本地管理員身分後，直接調用作業系統原生的受信任管理服務進程（如 `WmiPrvSE.exe` 或 `wsmprovhost.exe`）在遠端目標主機記憶體中衍生執行後滲透代碼或命令，完全無需向目標主機磁碟上傳二進位惡意載荷，亦無需如 PsExec 般註冊具名 Windows 系統服務**。在紅隊實戰中，這是最具匿蹤性且最不易觸發端點啟發式攔截的橫向移動黃金途徑。

```
[紅隊控制端 (具備域管理或本地管理員憑證)]
      │
      ├── 途徑 A: WMI 橫向 (TCP 135 + 動態高位 RPC 端口)
      │    調用 Win32_Process::Create -> 遠端衍生進程: WmiPrvSE.exe -> powershell.exe
      │
      └── 途徑 B: WinRM 橫向 (TCP 5985/5986 WS-Management SOAP)
           建立遠端 PSSession / Evil-WinRM -> 遠端衍生進程: wsmprovhost.exe -> cmd.exe
      │
      ▼
[遠端內網目標主機 (執行無檔案記憶體代碼，磁碟無二進位殘留！)]
```

## 🔬 第一動：DCOM/RPC 協議鏈與 WS-Management 通訊底層機制 (Mechanics & Remote Invocation)

### 1. WMI 橫向移動的底層協議交互
- **DCOM/RPC 握手**：客戶端首先連接遠端主機的 **TCP 135 (RPC Endpoint Mapper)**，查詢 `IWbemLevel1Login` 介面的高位動態監聽埠（預設在 49152~65535 區間）。
- **進程衍生機制**：透過 `ROOT\CIMV2` 命名空間呼叫 `Win32_Process.Create` 方法。
- **架構特性**：執行的指令由系統受信任服務 **`WmiPrvSE.exe` (WMI Provider Host)** 作為父進程直接衍生啟動，天然具備合法系統調用特徵。

### 2. WinRM 與 PowerShell Remoting 運作架構
- **WS-Management 標準**：WinRM 基於 SOAP-XML 協定，透過 HTTP (預設 5985) 或 HTTPS (預設 5986) 傳輸加密管理負載。
- **WinRS 宿主機制**：遠端伺服器接收到請求後，在本地啟動專屬代理宿主進程 **`wsmprovhost.exe`**，支援直接執行 PowerShell 腳本塊或常規 Shell 指令，支援完全無檔案 (Fileless) 記憶體注入。

## 🎯 作戰驗收檢查點 (Operational Checkpoints)

- [ ] **Q1：相較於 PsExec，使用 WMI 或 WinRM 進行橫向移動為何具備更高的隱蔽性？**
  - **戰術思維**：PsExec 需要向目標磁碟上傳 `psexesvc.exe` 並註冊 Windows 服務；而 WMI 與 WinRM 全程利用已常駐的系統服務（`WmiPrvSE.exe` 或 `wsmprovhost.exe`），不落地二進位檔也不新建服務。
- [ ] **Q2：使用 Impacket 的 `wmiexec.py` 時，預設是如何將遠端命令的輸出結果取回本地的？**
  - **戰術思維**：`wmiexec.py` 將命令輸出重定向至 `ADMIN$` 共享中的臨時檔案，讀取該檔案後立即刪除；這會在磁碟上留下短暫的寫入與刪除痕跡。
- [ ] **Q3：在 WinRM 連接中，即使使用未加密的 HTTP 5985 端口，傳輸的密碼與指令是否為明文？**
  - **戰術思維**：不是明文。WinRM 協定層預設使用 Kerberos 或 NTLM 提供的 SPNEGO 會話密鑰對 HTTP 負載進行整段加密（Message Encryption），非 SSL 亦具加密防護。
- [ ] **Q4：藍隊 SIEM 監控 WMI 惡意橫向移動時，最典型且高可信度的進程樹特徵是什麼？**
  - **戰術思維**：以 `WmiPrvSE.exe` 為父進程，直接衍生創建出 `cmd.exe`、`powershell.exe`、`mshta.exe` 或 `cscript.exe` 等解譯器。
- [ ] **Q5：若目標啟用了 UAC，非 RID 500 的本機管理員帳號能否透過 WMI/WinRM 成功橫向執行命令？**
  - **戰術思維**：對於 WMI，會受到 `LocalAccountTokenFilterPolicy` 限制無法執行；而 WinRM 在預設配置下允許本地管理員群組成員直接登入執行。
