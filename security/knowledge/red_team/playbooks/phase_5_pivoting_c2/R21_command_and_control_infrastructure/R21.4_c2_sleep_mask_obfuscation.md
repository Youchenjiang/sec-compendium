# R21.4 C2 記憶體休眠混淆與呼叫堆疊欺騙 (C2 Sleep Mask & Call Stack Spoofing)

---

## 🎯 作戰任務破題 (Tactical Objective & Mental Workflow)

**C2 記憶體休眠混淆與呼叫堆疊欺騙** 的物理本質為**利用作業系統核心計時器與返回導向編程 (ROP - Return-Oriented Programming) 機制，在 C2 Agent 進入長時間等待指令的休眠期（Sleep Window）時，將自身常駐之可執行記憶體頁屬性（PAGE_EXECUTE_READWRITE / RX）動態降級為不可執行或完全不可存取（PAGE_READWRITE 或 PAGE_NOACCESS），並對整塊記憶體區塊進行 XOR/RC4/ChaCha20 密碼學加密，同時以合成偽造的合法系統呼叫堆疊幀（Synthetic Call Stack Spoofing）覆蓋線程真實調用鏈**。在紅隊實戰中，這是完全擊穿以 `Moneta`、`Hunt-Sleeping-Beacons` 與 EDR 週期性記憶體掃描器為代表之記憶體取證體系的終極防禦規避工藝。

```
[常態執行時 (Active Execution)]
  進程記憶體: 包含明文 C2 配置、Payload 機器碼 (PAGE_EXECUTE_READWRITE)
  呼叫堆疊: 正常運作
          │
          ▼ 觸發 Sleep Mask (調用 Ekko / Foliage 異步計時器)
[休眠期 (Dormant Sleep Window - 數分鐘至數小時)]
  1. 記憶體內容: 全區段經 RC4 / XOR 密鑰動態加密 (呈現隨機高熵值雜訊)
  2. 頁面權限: VirtualProtect -> 降級為 PAGE_NOACCESS (記憶體掃描器讀取即崩潰)
  3. 線程堆疊: 偽造為 RtlUserThreadStart -> BaseThreadInitThunk (合法微軟系統呼叫鏈)
          │
          ▼ 計時器回調自動喚醒 (Wake-up Event)
[喚醒執行 (Resume Execution)]: 記憶體恢復 RX 權限並解密，處理下發指令！
```

## 🔬 第一動：休眠混淆 (Ekko/Foliage) 與呼叫堆疊欺騙底層運作機制 (Mechanics & ROP Execution)

### 1. Ekko 異步計時器 ROP 執行鏈
傳統 `Sleep()` 函數無法由進程自己加密自己當前正在運行的代碼（若自己加密自己，CPU 立即在下一條指令引發存取違規）。
- **Ekko 的破局原理**：利用 Windows 內建的非同步計時器佇列 API (`CreateTimerQueueTimer`)。
- **ROP 串聯排程**：
  1. 建立 4 個串聯的 Timer 事件，指定由系統工作者線程 (ThreadPool Worker) 異步回調。
  2. 第一步：調用 `NtContinue` / `VirtualProtect` 將 Agent 記憶體改為 `PAGE_READWRITE`。
  3. 第二步：調用 `SystemFunction032` (RC4 加密函數) 對記憶體進行全量加密。
  4. 第三步：調用 `WaitForSingleObject` 進行長達 $N$ 秒的靜默休眠。
  5. 第四步：休眠結束後，反向調用解密並恢復 `PAGE_EXECUTE_READ`。

### 2. Synthetic Stack Spoofing (合成堆疊欺騙)
- 當線程處於等待狀態時，EDR 會遍歷線程的堆疊幀 (Stack Frames)。
- 堆疊欺騙技術藉由修改線程上下文中的 `RSP` 與返回位址，將棧幀重寫為合法 DLL（如 `kernel32.dll` 或 `ntdll.dll`）的典型等待鏈路，使記憶體鑑識工具判定為合法背景空閒線程。

## 🎯 作戰驗收檢查點 (Operational Checkpoints)

- [ ] **Q1：為什麼 C2 Agent 進入休眠時不能直接在自己線程內部調用 `VirtualProtect` 將自己加密？**
  - **戰術思維**：若在當前線程將自身正在運行的代碼段改為不可讀寫或進行加密，CPU 下一條指令取指 (Instruction Fetch) 將直接引發崩潰存取違規 (Access Violation)。
- [ ] **Q2：Ekko 技術利用哪一個 Windows 系統組件實現了「自己加密自己」的非同步執行？**
  - **戰術思維**：利用 Windows 內建的執行緒集區計時器佇列 (Timer Queue)，委託系統線程在延遲回調中操作目標線程的記憶體頁屬性與加密。
- [ ] **Q3：在對抗記憶體取證工具時，將記憶體保護屬性改為 `PAGE_NOACCESS` 有何特殊防護效果？**
  - **戰術思維**：許多記憶體掃描器在讀取目標進程記憶體時若未特別處理異常，嘗試讀取 `PAGE_NOACCESS` 記憶體頁會觸發違規異常甚至導致掃描器自身異常中斷。
- [ ] **Q4：什麼是呼叫堆疊欺騙 (Call Stack Spoofing)？其核心防禦對象是誰？**
  - **戰術思維**：核心防禦對象是透過 Stack Walking 檢查線程調用鏈來源的 EDR；欺騙技術將棧幀重寫為合法系統 DLL，掩飾真實私有代碼位置。
- [ ] **Q5：藍隊應如何從核心層或行爲特徵中識破經過 Sleep Mask 偽裝的 C2 進程？**
  - **戰術思維**：監控進程記憶體屬性的高頻動態翻轉 (VirtualProtect API 監控)、排查指向私有記憶體的異常計時器回調、以及檢查線程上下文中的偽造棧指針。
