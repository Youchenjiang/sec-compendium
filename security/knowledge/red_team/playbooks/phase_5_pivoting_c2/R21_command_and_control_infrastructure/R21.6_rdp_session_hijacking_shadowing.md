# R21.6 RDP 會話劫持與 Shadow 隱蔽無感監控 (RDP Session Hijacking & Shadowing)

---

## 🎯 作戰任務破題 (Tactical Objective & Mental Workflow)

**RDP 會話劫持與 Shadow 隱蔽無感監控** 的物理本質為**利用 Windows 遠端桌面服務 (Remote Desktop Services, TermService) 的原生會話管理機制與命令列工具（`tscon.exe` 與 `mstsc.exe /shadow`），在具備本機最高權限 (NT AUTHORITY\SYSTEM) 的情況下，無需獲取或破解目標高權限使用者的明文密碼或 NTLM Hash，直接將自己當前的終端連線無縫切換並「借殼」劫持至已登入或處於中斷 (Disconnected) 狀態的網域管理員活動會話中；或透過啟用系統 Shadow 陰影模式，實現對當前操作員螢幕畫面的靜默即時共享監控**。在紅隊實戰中，這是獲取已登入高管/網管之特權操作上下文與內部敏感系統權限的致命戰術。

```
[目標 Windows 伺服器 (TermService 運行中)]
  ├── 會話 1 (ID: 1): DOMAIN\DomainAdmin (狀態: Disconnected / Active)
  └── 會話 2 (ID: 2): 攻擊者普通 RDP 會話 (狀態: Active)
          │
          ▼ 攻擊者提權至 SYSTEM (PsExec / 服務創建)
[以 SYSTEM 權限執行 tscon.exe 進行會話劫持]
  命令: tscon.exe 1 /dest:2
          │
          ▼ 系統核心認證被繞過 (TermService 信任 SYSTEM 請求，不驗證密碼)
[攻擊者會話 2 瞬間切換為 DOMAIN\DomainAdmin 桌面！完整接管所有管理憑證與操作畫面！]
```

## 🔬 第一動：TermService 會話架構、tscon 核心切換與 Shadow 模式底層機制 (Mechanics & Session Architecture)

### 1. Windows RDP 會話與安全認證機制
- **會話列表 (Session Enumeration)**：Windows 透過 `qwinsta` 或 `query session` 查詢當前系統所有桌面會話（包含會話名、使用者名、會話 ID 與連線狀態）。
- **密碼認證繞過原理**：在 Windows 設計架構中，管理員使用 `tscon.exe <ID>` 切換會話時必須輸入目標密碼；但如果調用者身分是 **`NT AUTHORITY\SYSTEM`**，系統核心服務認為該請求源於本機最高信任實體，會無條件信任並跳過任何密碼驗證邏輯，直接完成視訊串流與輸入焦點的重新綁定。

### 2. RDP Shadow (陰影會話) 靜默監控
- Windows 內建的 Shadow 協定允許遠程或本地管理員連入其他使用者的活動桌面：
- **控制原則**：透過修改註冊表鍵值 `HKLM\SOFTWARE\Policies\Microsoft\Windows NT\Terminal Services` 下的 `Shadow` 數值：
  - `Shadow = 2`：允許完全控制，無需使用者同意 (Full Control without user permission)。
  - `Shadow = 4`：僅檢視畫面，無需使用者同意 (View session without user permission)。

### 2. 以 SYSTEM 權限執行 tscon 會話劫持
```cmd
:: 假設目標網域管理員會話 ID 為 3，當前自己連線會話 ID 為 2
:: 方法 A: 透過創建臨時 Windows 服務直接以 SYSTEM 執行
sc create HijackSession binpath= "cmd.exe /k tscon 3 /dest:rdp-tcp#2"
net start HijackSession
sc delete HijackSession

:: 方法 B: 使用 PsExec 提升至 SYSTEM 後直接執行
psexec.exe -s -i tscon 3 /dest:rdp-tcp#2
```

### 3. 配置註冊表開啟無感 Shadow 靜默即時監控
```powershell
# 1. 啟用 Shadow 政策 (允許無提示直接監視畫面)
Set-ItemProperty -Path 'HKLM:\SOFTWARE\Policies\Microsoft\Windows NT\Terminal Services' -Name 'Shadow' -Value 4 -Type DWord

# 2. 本地管理員直接無提示附著到目標會話 ID 3 進行監看
mstsc.exe /shadow:3 /noConsentPrompt /v:localhost
```

## 🥷 第三動：防禦規避與日誌特徵操控 (Evasion & Anti-Forensics)

### 1. RDP 會話劫持防禦規避策略表
| 規避面向 | 原始觸發特徵 | 變形隱蔽手法 | 原理解析 |
| :--- | :--- | :--- | :--- |
| **目標使用者被踢出** | 劫持處於 Active 的使用者會導致其畫面黑屏 | 優先挑選狀態為 `Disconnected` 的閒置會話 | 中斷會話無人在線操作，劫持過程無感且無衝突 |

| **Shadow 彈窗警示** | 預設連入時目標桌面跳出「是否允許遠程監看」 | 預先注入註冊表 `Shadow = 4` (noConsentPrompt) | 繞過使用者交互授權對話框，達成無感知螢幕串流 |

## 🛡️ 第五動：工程級防禦基線 (Hardening Baselines)

1. **強制實施 RDP 會話逾時自動登出 (Logoff Timeout)**：
   - 透過網域群組原則 (GPO) 設定：當使用者中斷連線超過 15 分鐘時，強制系統自動終止 (End) 該會話，嚴禁會話無限期處於 Disconnected 狀態。
2. **鎖定 RDP Shadow 權限原則**：
   - 設定群組原則 `電腦設定 -> 系統管理範本 -> Windows 元件 -> 遠端桌面服務 -> 遠端桌面工作階段主機 -> 連線`：設定「為遠端桌面服務使用者工作階段的遠端控制設定規則」為「不允許遠端控制」。

## 🎯 作戰驗收檢查點 (Operational Checkpoints)

- [ ] **Q1：普通本地管理員帳號執行 `tscon <ID>` 為何會被系統要求輸入密碼，而提升至 SYSTEM 後卻能直接繞過？**
  - **戰術思維**：Windows 設計認為本地管理員依然是用戶身分，必須驗證身分；而 `SYSTEM` 是作業系統核心服務信任實體，終端服務預設無條件允許其重新分配控制權。
- [ ] **Q2：在實戰中，紅隊為何通常優先選擇狀態為 `Disconnected` 的會話而非 `Active` 會話進行劫持？**
  - **戰術思維**：若劫持正在操作中 (`Active`) 的管理員會話，該管理員螢幕會瞬間黑屏或被踢出，立即觸發人為警覺；劫持中斷會話則無人知曉。
- [ ] **Q3：什麼是 RDP Shadow 模式？它與直接 tscon 劫持有何核心差異？**
  - **戰術思維**：`tscon` 會把原會話奪取並重定向至當前視窗；而 `Shadow` 模式是「即時畫面鏡像」，原使用者仍可正常操作，攻擊者在背景靜默同步觀看螢幕。
- [ ] **Q4：藍隊應監控哪兩個核心的 Windows Security 事件識別非正常的會話重新連線？**
  - **戰術思維**：Event ID 4778 (會話已重新連線至視窗站) 與 Event ID 4779 (會話已中斷連線)。
- [ ] **Q5：企業應如何透過 GPO 從根本上消滅處於 Disconnected 狀態的高權限會話被劫持的風險？**
  - **戰術思維**：設定 RDP 工作階段逾時限制，強制使用者中斷連線超過設定時間（如 10 分鐘）後，作業系統自動登出並關閉該會話進程。
