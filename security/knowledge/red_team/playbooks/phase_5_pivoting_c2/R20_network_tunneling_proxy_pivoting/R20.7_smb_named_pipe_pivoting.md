# R20.7 SMB 命名管道隧道穿越完全隔離子網域 (SMB Named Pipe Pivoting)

---

## 🎯 作戰任務破題 (Tactical Objective & Mental Workflow)

**SMB 命名管道隧道穿越完全隔離子網域** 的物理本質為**利用 Windows 網路作業系統原生的伺服器訊息區塊協定 (SMB/IPC$) 與命名管道 (Named Pipe) 機制，在被完全切斷外網連線（無網際網路存取、禁止任何出站連線）的高安全隔離內網主機上，透過向可連網的前端已攻陷跳板機反向監聽或主動連接具名管道（如 `\\pipe\msagent_xx`），將 C2 控制流量或代理請求封裝於標準 Windows 445 SMB 協定中實現串聯中繼**。在紅隊實戰中，這是突破多層網路防護（如銀行核心帳務系統、隔離生產網）的終極內聯橫向架構。

```
[外網 C2 伺服器 (HTTPS)]
      ▲
      │ 1. 標準 HTTPS/TCP C2 通道 (長輪詢 / WebSocket)
      ▼
[邊界跳板主機 (Compromised Parent Agent)]
      ▲
      │ 2. 內部 SMB 命名管道隧道: \\.\pipe\status_sync (封裝 C2 指令串流)
      │    (僅使用 Windows 合法 445 埠，無需直連外網)
      ▼
[完全隔離主機 (Isolated Child Agent - 無公網路由)]
```

## 🔬 第一動：SMB 命名管道、IPC$ 認證與進程間通訊機制 (Mechanics & Named Pipe Architecture)

### 1. Windows 命名管道 (Named Pipe) 的底層本質
- **進程間通訊 (IPC)**：命名管道為 Windows 提供單向或雙向的先進先出 (FIFO) 串流通訊機制。
- **跨網路傳輸**：當管道名稱格式為 `\\<hostname>\pipe\<pipename>` 時，Windows 將利用 SMB 協定（TCP 445 埠）透過 `IPC$` 共享將管道通訊透明封裝進 SMB 檔案讀寫請求 (`ReadFile` / `WriteFile`)。
- **認證機制**：存取遠端命名管道必須建立通過 Windows 域或本地 NTLM/Kerberos 認證的 SMB 會話，天然遵循目標企業的合法域信任鏈路。

### 2. 父子節點串聯架構 (Peer-to-Peer C2 Pivoting)
- **子節點 (Child)**：無網際網路存取權限的主機，呼叫 `CreateNamedPipeA` 創建管道監聽。
- **父節點 (Parent)**：具備對外連線的跳板機，呼叫 `CreateFileA` 連接子節點管道，並將 C2 伺服器下發的命令透傳進管道，再將子節點回傳的數據包打回外網 C2。

## 🎯 作戰驗收檢查點 (Operational Checkpoints)

- [ ] **Q1：在多層完全隔離的內網中，為什麼 SMB 命名管道常被紅隊視為首選通訊通道？**
  - **戰術思維**：隔離主機完全無網際網路存取權限，甚至無法解析外部 DNS；但內網通常信任並放行 Windows 445 埠進行檔案共享與管理，因此可藉此建立串聯跳板。
- [ ] **Q2：命名管道遠端連線建立的底層協定本質是什麼？**
  - **戰術思維**：底層是透過 SMB 協定訪問目標機器的 `IPC$` 共享，將對管道檔案的讀寫轉換為進程間的即時數據流。
- [ ] **Q3：在利用 SMB 管道橫向連接時，跳板主機必須具備何種身分憑證？**
  - **戰術思維**：必須具備隔離目標機器的合法存取憑證（域帳戶或相同本地管理員密碼），以完成 SMB 會話設置 (Session Setup) 認證。
- [ ] **Q4：藍隊應透過監控 Sysmon 的哪一個事件 ID 來捕獲惡意命名管道的建立？**
  - **戰術思維**：Sysmon Event ID 17 (Pipe Created) 與 Event ID 18 (Pipe Connected)。
- [ ] **Q5：若目標系統開啟了 UAC Remote Restrictions，普通本地管理員帳號能否直接透過 SMB 建立命名管道連線？**
  - **戰術思維**：不能。普通本地管理員會受到 `LocalAccountTokenFilterPolicy` 限制，除非是內建的 RID 500 Administrator 帳號或是域管理員帳號。
