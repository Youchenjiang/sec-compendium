# R20.3 SSH 動態轉發與 Proxychains 多級跳板 (SSH Dynamic Port Forwarding)

---

## 🎯 作戰任務破題 (Tactical Objective & Mental Workflow)

**SSH 動態轉發與 Proxychains 多級跳板** 的物理本質為**利用 OpenSSH 客戶端內建的 SOCKS4/5 代理伺服器功能（`-D` 參數），透過加密的 SSH 傳輸通道動態解析與封裝 TCP 請求，並結合本機 Hook 庫（Proxychains）攔截應用程式的 `connect()` 網路系統調用，強行將流量注入 SSH 隧道**。在紅隊實戰中，若已獲取內網 Linux 伺服器的 SSH 憑證（或私鑰），攻擊者無需上傳任何第三方黑客工具（LOLBAS），直接調用系統自帶的 `ssh` 二進位即可開闢隱蔽隧道，甚至串接多跳實現深層內網滲透。

```
[攻擊者本機] ── 1. 執行原生命令建立本地 SOCKS5 代理: ssh -D 1080 -N -f user@pivot1
      │
      ▼ 2. 本機 127.0.0.1:1080 端口開始監聽
[Proxychains 鉤子動態劫持] (攔截本機 nmap, impacket, curl 的 socket 呼叫)
      │
      ▼ 3. 流量進入加密 SSH 隧道 (Bypass 外部流量檢測)
[內網第一跳板機 (Pivot 1)] ──► 直連內部隔離資料庫 (192.168.10.50:3306)
      │
      ▼ 4. 多級跳板串接 (Nested Tunnel): 在 Pivot 1 上再建立通往 Pivot 2 的隧道
[第二層隔離私網 (10.0.0.0/24)] ──► 達成多重信任邊界穿透！
```

## 🔬 第一動：SSH 動態轉發底層架構、Direct-TCP 與 Proxychains 劫持機制 (Mechanics & SOCKS)

### 1. SSH `-D` 動態轉發 (Dynamic Forwarding) 機制
當使用 `ssh -D [bind_address:]port` 時：
- SSH 客戶端在本地開闢一個應用層 SOCKS5 服務。
- 當本地工具發送連線請求（例如連接 `192.168.10.5:445`）至 SOCKS5 時，SSH 客戶端將請求封裝為 SSH 協定的 `SSH_MSG_CHANNEL_OPEN` 訊息（類型為 `direct-tcpip`）。
- 遠端 SSH 伺服端在內網直接發起對 `192.168.10.5:445` 的真實 TCP 連線，並將資料雙向加密轉發。

### 2. Proxychains 函式庫劫持原理
Proxychains 透過 Linux `LD_PRELOAD` 機制，在應用程式啟動時掛鉤 (Hook) 標準 C 函式庫 (`libc.so`) 中的網路調用：
- 劫持 `connect()` 系統調用，將原本發往內網目標的連線請求重定向至本地的 SOCKS 代理埠。
- 劫持 `gethostbyname()`，實現 DNS 遠端代理端解析，杜絕本地 DNS 洩漏。

## ⚡ 第二動：戰術執行與工具鏈操作 (Attack Vectors & Exploitation)

### 1. 建立單級 SSH 動態 SOCKS5 代理
```bash
# 建立後台運行、不執行遠端命令的 SOCKS5 隧道
ssh -D 1080 -q -C -N -f user@192.168.1.100 -i ~/.ssh/id_rsa

# 參數解析:
# -D 1080 : 本地綁定 1080 端口提供 SOCKS5 服務
# -q      : 靜默模式
# -C      : 啟用資料壓縮
# -N      : 不執行遠端 Shell 指令 (純隧道)
# -f      : 在背景執行 (Fork to background)
```

### 2. 配置 Proxychains 與實戰內網穿透
```bash
# 編輯 /etc/proxychains4.conf
# 確保最後一行包含:
# socks5  127.0.0.1 1080

# 透過代理執行內網 SMB 認證枚舉
proxychains4 impacket-wmiexec Administrator@192.168.10.5
```

### 3. 多級跳板鏈式串接 (Multi-Hop Chaining)
```bash
# 在第一跳板已建立的情況下，透過 Proxychains 建立通往第二跳板的第二層 SOCKS5 代理 (綁定 1081)
proxychains4 ssh -D 1081 -q -C -N -f user2@10.0.0.50

# 更新 proxychains4.conf:
# dynamic_chain
# socks5 127.0.0.1 1080
# socks5 127.0.0.1 1081
```

## 🥷 第三動：防禦規避與日誌特徵操控 (Evasion & Anti-Forensics)

### 1. SSH 隧道防禦規避策略表
| 規避面向 | 原始觸發特徵 | 變形隱蔽手法 | 原理解析 |
| :--- | :--- | :--- | :--- |
| **目標端點日誌** | 伺服端 `/var/log/auth.log` 記錄登入會話 | 攜帶 `-N` 參數不分配 PTY 虛擬終端 | 不衍生互動式 Shell，僅維持純網路資料管道 |
| **本地工具流量** | 應用程式發起本地 DNS 解析導致洩漏 | 在 `proxychains4.conf` 啟用 `proxy_dns` | 強制所有網域名稱解析在遠端跳板機執行，避免本地痕跡 |
| **持久連線管理** | 長時間連線超時被防火牆斷開 | 設置 `ServerAliveInterval 30` 心跳 | 定期發送保活封包維持 TCP 狀態機連線活性 |

                     ▼

### 關鍵 Linux Auditd 規則 (監控 sshd 建立的 TCP 轉發連線)
```audit
-a always,exit -F arch=b64 -S connect -F exe=/usr/sbin/sshd -k ssh_forwarding
```

## 🛡️ 第五動：工程級防禦基線 (Hardening Baselines)

1. **全面停用非必要之 SSH TCP 轉發**：
   - 編輯 `/etc/ssh/sshd_config`，明確配置：
     ```text
     AllowTcpForwarding no
     AllowAgentForwarding no
     GatewayPorts no
     ```
2. **限制 SSH 存取來源 IP 與金鑰硬化**：
   - 使用 iptables/firewalld 限制 22 埠僅允許管理堡壘機連線；強制使用強金鑰認證並停用密碼驗證。

## 🎯 作戰驗收檢查點 (Operational Checkpoints)

- [ ] **Q1：`ssh -D` 動態轉發與 `ssh -L` 本地埠轉發的核心差異為何？**
  - **戰術思維**：`ssh -L` 只能固定一對一轉發特定的目標主機與通訊埠；而 `ssh -D` 是在本地開啟動態 SOCKS5 代理伺服器，允許連向遠端內網的任意 IP 與任意通訊埠。
- [ ] **Q2：使用 Proxychains 執行滲透測試時，為何設定檔中的 `proxy_dns` 至關重要？**
  - **戰術思維**：若未啟用 `proxy_dns`，所有網域名稱解析將由攻擊者本地 DNS 伺服器發起，不僅無法解析目標內部網域主機名稱，還會造成嚴重的情資外洩。
- [ ] **Q3：在被授權普通使用者 SSH 登入後，管理員如何從伺服器端禁止其建立代理隧道？**
  - **戰術思維**：在 `/etc/ssh/sshd_config` 中將 `AllowTcpForwarding` 設置為 `no`，重啟 sshd 即可從協定層面徹底拒絕客戶端發起的轉發請求。
- [ ] **Q4：在限制嚴格的跳板機上，若無法修改 `/etc/proxychains.conf`，紅隊如何指定自定義配置？**
  - **戰術思維**：Proxychains 支援優先讀取當前工作目錄下的 `./proxychains.conf`，或透過環境變數傳入自定義路徑。
- [ ] **Q5：藍隊如何在主機日誌中區分正常的 SSH 互動式登入與惡意的 SSH 穿透隧道？**
  - **戰術思維**：檢視 `/var/log/auth.log`，隧道建立通常伴隨無 PTY 分配日誌，且監控 `sshd` 進程是否有大量向其他內部主機發起的不尋常短連線。
