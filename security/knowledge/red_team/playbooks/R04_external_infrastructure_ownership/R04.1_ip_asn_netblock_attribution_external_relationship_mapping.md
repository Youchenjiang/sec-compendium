# R04.1 網際網路 IP、ASN 與網段歸屬關係對齊 (IP, ASN & Netblock Attribution)

---

## 🎯 作戰任務破題 (Tactical Objective & Mental Workflow)

**網際網路 IP、ASN 與網段歸屬對齊 (IP & Netblock Attribution)** 的物理本質為**透過全球五大區域網際網路註冊管理機構 (RIR) 的 RDAP/WHOIS 資料庫與邊界閘道協定 (BGP) 路由廣播表，精確劃定目標企業所「真正法定擁有」之自治系統編號 (ASN) 與 IPv4/IPv6 網段前綴 (CIDR)**。紅隊在實戰初期必須穿透多雲架構、第三方代管與電信業者共用 IP 池之干擾，排除非目標資產（避免打擊越界違法），並挖掘隱藏於專屬自營網段中的核心資料中心與未列管基礎設施。

```
[確定目標企業實體名稱: Corp Inc] ── 查詢五大 RIR 註冊庫 (ARIN / RIPE / APNIC)
                                            │
                                            ▼ 檢索組織句柄 (Org-ID: CORP-1234)
┌───────────────────────────────────────────┴───────────────────────────────────────────┐
│ 1. 自治系統對齊: 鎖定目標宣告之專屬 ASN (如 AS13370)                                    │
│ 2. BGP 前綴廣播: 提取該 ASN 在全網廣播之 IP 網段 (如 203.0.113.0/24, 198.51.100.0/22) │
│ 3. 排除代管噪聲: 區分專屬分配 (Direct Allocation) 與 ISP 租用共用池 (Provider Assigned)│
└───────────────────────────────────────────┬───────────────────────────────────────────┘

[獲得確定性法定 IP 攻擊面邊界] ─────────────► 【精準在冊 (In-Scope)】全網段共 1,280 個實體 IP！
                                            │
                                            ▼ 杜絕攻擊越界 (Out-of-Scope)
[授權作戰範圍確認] ────────────────────────► 進入主機探活與埠位掃描，奠定作戰合法性基石！
```

## 🛡️ 第五動：工程級防禦基線 (Hardening Baselines)

1. **部署 RPKI 與路由起點授權 (ROA, Route Origin Authorization)**：
   - 在所屬 RIR 為企業宣告的所有 IP 前綴建立加密 ROA 記錄，杜絕 BGP 劫持 (BGP Hijacking) 與非授權廣播。
2. **定期清理孤立網段與公網 IP 資源池**：
   - 審查企業所持有的所有 IPv4/IPv6 網段；將未實際承載業務之 IP 網段從 BGP 廣播中撤除，徹底收縮公網暴露面。
3. **維護嚴格準確的 RIR WHOIS/RDAP POC 資訊**：
   - 將法定 POC 資訊收斂至安全維運專用團隊信箱 (如 `security-poc@corp.com`)，避免暴露特定網路工程師姓名與手機。

## 🧪 實戰演練環境搭建 (Environment & Lab Setup)

### 1. 極簡 ASN 前綴解析與歸屬判定腳本 (Python, 20 行)
```python
# asn_attribution.py
import ipaddress

# 模擬企業法定在冊之 ASN 廣播網段清單
target_corporate_subnets = [
    ipaddress.ip_network("203.0.113.0/24"),
    ipaddress.ip_network("198.51.100.0/22")
]

def check_ip_scope(test_ip_str):
    test_ip = ipaddress.ip_address(test_ip_str)
    for net in target_corporate_subnets:
        if test_ip in net:
            return f"[+] 🎯 IP [{test_ip}] 命中企業法定資產網段 [{net}] ── 【合法在冊 IN-SCOPE】"
    return f"[-] ⚠️ IP [{test_ip}] 未在企業 ASN 廣播範圍內 ── 【越界危險 OUT-OF-SCOPE】"

print(check_ip_scope("203.0.113.45"))
print(check_ip_scope("8.8.8.8"))
print("[!] FLAG{IP_ASN_ATTRIBUTION_SCOPE_VERIFIED}")
```

## 🎯 作戰驗收檢查點 (Operational Checkpoints)

- [ ] **Q1：在實戰滲透中，誤將非目標企業的 IP 網段納入掃描範圍會引發何種嚴重後果？**
  - **戰術思維**：違反法律與交戰協議 (Rules of Engagement, ROE)。對未經授權的第三方資產進行掃描或利用屬於違法入侵行為，可能導致整個演習被叫停並面臨法律訴訟。
- [ ] **Q2：何謂「Direct Allocation」與「Provider Assigned (PA)」之關鍵差異？**
  - **戰術思維**：`Direct Allocation` 是 RIR 直接核發給企業的獨立專屬 IP，歸屬明確；而 `Provider Assigned` 是電信業者分派的 IP，可能由多個客戶動態共用，需謹慎核實真實所有權。
- [ ] **Q3：為何即使某 IP 具備反向解析 (PTR) 指向目標域名，仍不能 100% 證明該 IP 屬於目標企業？**
  - **戰術思維**：因為目標可能將子域名 CNAME 指向第三方 SaaS 或託管供應商（如 Heroku, AWS）；若供應商回收了該主機但目標未刪除 DNS 記錄，可能引發**子域名劫持**或誤判資產邊界。
- [ ] **Q4：BGP Looking Glass 在紅隊情報確認中扮演何種角色？**
  - **戰術思維**：Looking Glass 允許紅隊從世界各地的 Tier-1 骨幹路由器視角查看當前即時的 BGP 路由表，用以確認某個 ASN 是否「正在實時運作宣告」，排除已廢棄的歷史靜態網段。
- [ ] **Q5：若目標企業在全球有多個子公司與併購實體，紅隊如何全面捕獲所有 ASN？**
  - **戰術思維**：透過查詢跨國併購新聞、SEC 財務申報文件 (10-K 表格) 提取所有法律實體名稱，並在五大 RIR 中交叉比對所有關聯之 Org-ID 與維護者帳號 (Maintainer Handle)。
