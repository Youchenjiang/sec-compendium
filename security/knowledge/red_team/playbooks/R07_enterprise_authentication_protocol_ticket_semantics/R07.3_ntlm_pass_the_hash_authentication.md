# R07.3 NTLM 雜湊傳遞認證與身分橫向移動 (Pass-the-Hash)

---

## 🎯 作戰任務破題 (Tactical Objective & Mental Workflow)

**NTLM 雜湊傳遞 (Pass-the-Hash, PtH)** 的物理本質為**利用 NTLM 挑戰-回應 (Challenge-Response) 協定在密碼學設計上將「NTLM 雜湊 (Hash)」直接視作運算私鑰的固有缺陷**。在 NTLM 驗證握手過程中，客戶端永遠不需要提供明文密碼，而是使用密碼的 NTLM 雜湊對伺服器發出的隨機挑戰碼 (Server Challenge) 計算 HMAC 回應。因此，只要紅隊自記憶體 (LSASS) 或本機 SAM 資料庫中提取到使用者的 NTLM 雜湊，即可在**完全不知道明文密碼的前提下**直接注入憑證並發起橫向移動。

```
[攻擊者自本機 LSASS 萃取 NTLM 雜湊] ── (NTLM Hash: e52cac67419a9a224a3b108f3fa6cb6d)
                                                │
                                                ▼ 啟動 PtH 工具 (如 wmiexec / psexec)
[目標主機 (Port 445 / 135 / 5985)] ◄────────── 1. 發送 Type 1: NEGOTIATE_MESSAGE
                                                │
                                                ▼ 2. 回傳 Type 2: CHALLENGE_MESSAGE (隨機 8-byte 挑戰碼)
[攻擊者控制台] ─────────────────────────────────► 3. 使用目標 NTLM 雜湊計算 NTLMv2 Response
                                                │
                                                ▼ 4. 發送 Type 3: AUTHENTICATE_MESSAGE
[目標主機完成驗證 (或向 DC 驗證)] ─────────────► 【驗證成功】建立 Logon Type 3 (網路登入) 會話！
                                                │
                                                ▼
[橫向移動命令執行] ────────────────────────────► 獲取目標主機管理員權限，達成內網滾雪球突破！
```

## 🔬 第一動：NTLM 挑戰回應機制與密鑰物理特性 (Mechanics & NTLM Physics)

### 1. NTLMv2 驗證運算鏈路與密鑰角色

| 運算步驟 | 密碼學公式 / 資料流 | 攻擊利用物理條件 |
| :--- | :--- | :--- |
| **金鑰衍生** | `NTLM_Hash = MD4(UTF-16-LE(Password))` | 明文密碼唯一的用途僅為生成 NTLM 雜湊 |
| **回應金鑰 (Response Key)**| `NTLMv2_Hash = HMAC-MD5(NTLM_Hash, UPPER(User) + Domain)` | 只要持有 NTLM 雜湊即可精確算出回應金鑰 |
| **最終證明 (NTLMv2 Resp)** | `HMAC-MD5(ResponseKey, ServerChallenge + ClientBlob)` | 握手過程中**從未出現明文密碼**，雜湊即為等價密鑰！ |

## 🛡️ 第五動：工程級防禦基線 (Hardening Baselines)

1. **部署微軟 LAPS (Local Administrator Password Solution)**：
   - 確保全網所有工作站與伺服器的本機 Administrator 密碼皆為隨機、唯一且自動輪替，徹底粉碎「一台攻陷、全網橫移」的骨牌效應。
2. **網路限制與禁用 NTLM (Disable NTLM Globally)**：
   - 啟用群組原則：`網路安全性: 限制 NTLM: 傳向遠端伺服器的傳出 NTLM 流量 -> 全部拒絕`，全面強制採用 Kerberos 驗證。
3. **啟用受限管理模式 (Restricted Admin Mode)**：
   - 管理員使用 RDP 進行維護時強制加上 `/restrictedadmin` 參數，防止本機 NTLM 憑證洩漏至目標主機記憶體。

## 🎯 作戰驗收檢查點 (Operational Checkpoints)

- [ ] **Q1：Pass-the-Hash 攻擊是否能在純 Windows 網域環境中用於連線網域控制站 (DC)？**
  - **戰術思維**：**可以**。雖然 DC 預設優先使用 Kerberos，但若用戶端透過 IP 地址（如 `\\10.0.0.1\c$`）直接存取 DC，由於 Kerberos 無法對純 IP 建立 SPN，連線會**自動降級 (Fallback) 為 NTLM 驗證**，進而使 PtH 成功生效。
- [ ] **Q2：何謂 `LocalAccountTokenFilterPolicy`，其如何制約本機管理員帳號的 PtH 橫向移動？**
  - **戰術思維**：自 Vista 起，UAC 遠端存取原則預設會過濾除內建 `RID 500` (Administrator) 以外之所有其他本機管理員帳號的特權 Token。因此非 RID 500 的本機管理員發起 PtH 僅能取得低權限，除非目標註冊表顯式設定了 `LocalAccountTokenFilterPolicy=1`。
- [ ] **Q3：將密碼雜湊換算成 Kerberos 票證的攻擊稱作什麼？**
  - **戰術思維**：稱作 **Overpass-the-Hash (Pass-the-Key)**。利用 NTLM 雜湊 (作為 RC4 金鑰) 或 AES 金鑰向 KDC 發送 AS-REQ 換取合法的 Kerberos TGT，隨後轉為使用純 Kerberos 票證進行身分漫遊。
- [ ] **Q4：在藍隊鑑識日誌中，Logon Type 3 與 Logon Type 2 / 10 有何本質差異？**
  - **戰術思維**：Logon Type 3 為**網路登入 (Network Logon)**，由 SMB、WMI 或 RPC 發起，登入後使用者憑證通常不會在目標機器的 LSASS 中持久快取；而 Type 2 (互動式本機) 與 Type 10 (遠端桌面) 則會在目標機記憶體中寫入憑證材料。
- [ ] **Q5：若目標已啟用「保護的使用者 (Protected Users)」安全群組，對 PtH 有何直接影響？**
  - **戰術思維**：該群組成員的帳號完全**禁止使用 NTLM 進行任何認證**；即使紅隊持有其 NTLM 雜湊，在發起 Type 3 握手時亦會被目標系統直接拒絕。
