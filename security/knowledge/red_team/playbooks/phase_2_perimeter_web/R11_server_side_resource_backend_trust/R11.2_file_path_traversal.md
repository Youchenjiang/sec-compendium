# R11.2 路徑遍歷與檔案讀取機制解析 (Path Traversal & Filesystem Security)

---

## 🎯 作戰任務破題 (Tactical Objective & Mental Workflow)

**路徑遍歷 (Path Traversal)** 發生於應用程式接收檔案參數並拼裝至檔案系統路徑時。其本質為：**「作業系統虛擬檔案系統 (VFS) 支援 `../` 目錄跳躍語法；若應用程式未在呼叫底層系統調用 (`open`/`CreateFile`) 前實施嚴格的路徑規範化 (Canonicalization) 與目錄邊界檢查，攻擊者可突破預設目錄限制，任意讀取或覆寫伺服器機密檔案」**。

```
[攻擊者] ── 1. GET /download?file=../../../../etc/passwd ──► [Web 應用程式]
                                                                   │
                                                                   ▼ 未執行 realpath() 邊界校驗
                                                          [VFS 目錄階層解析]
                                                                   │
                                                                   ├── /var/www/uploads/../../..
                                                                   ▼ 遞迴回退至根目錄 /
                                                          [/etc/passwd 節點 (Inode)]
                                                                   │
[攻擊者控制台] ◄── 2. 回傳敏感檔案內容 (帳號密碼/金鑰洩漏) ────────┘
```

### 核心作戰決策與邊界
- **常見場景**：檔案下載、圖片讀取、報表產出、靜態資源路由。
- **作戰決策心流**：
  1. **確認 OS 特性**：Linux (`/`, 區分大小寫) vs. Windows (`\`, `/`, UNC `\\`, 8.3 縮寫 `PROGRA~1`)。
  2. **過濾機制繞過**：單次替換 ➔ 雙寫 `....//`；URL 過濾 ➔ 雙重編碼 `%252e%252e%252f`。
  3. **反向代理組態缺陷**：探測 Nginx `alias` 缺少結尾斜線的 Off-by-Slash 漏洞。
- **技術邊界**：
  - **與 LFI (R11.3) 差異**：路徑遍歷是純檔案內容讀取；LFI 則會被腳本直譯器（如 PHP）執行其中的代碼。

## 🔬 第一動：底層機制與 VFS 解析 (Mechanics & Canonicalization)

### 規範化前後對比速查表

| 階段 | 路徑字串範例 | 系統行為 |
| :--- | :--- | :--- |
| **輸入字串** | `/var/www/uploads/../../../../etc/passwd` | 表面前綴符合 `/var/www/uploads` |
| **規範化解析** | `realpath()` 解析後的真實物理路徑：`/etc/passwd` | 實際指向目標系統核心設定檔 |
| **安全檢查** | 檢查 `resolved_path.startswith(BASE_DIR)` | 發現 `/etc/passwd` 脫離 `/var/www/uploads`，立即阻斷 |

## ⚡ 第二動：弱點驗證與字典級攻擊向量 (Attack Vectors)

### 核心注入向量速查表

| 模式 | 典型 Payload | 作用與突防原理 |
| :--- | :--- | :--- |
| **標準相對路徑** | `../../../../etc/passwd` 或 `..\..\..\windows\win.ini` | 逐層跳出基礎目錄直達根目錄 |
| **絕對路徑直接覆蓋** | `/etc/passwd` 或 `C:\boot.ini` | 部分函式庫若輸入為絕對路徑，直接忽略前置 Base Dir |
| **雙寫嵌套繞過** | `....//....//etc/passwd` | 應用層正則僅替換單次 `../` 為空，外層重新閉合為 `../` |
| **雙重 URL 編碼** | `%252e%252e%252f` | 前端 WAF 解碼一次為 `%2e%2e%2f` 放行，後端二次解碼為 `../` |
| **16-bit Unicode 編碼** | `%u002e%u002e%u002f` 或 `%c0%ae%c0%ae/` | 突破舊型 IIS 或 Java 解析器的非法 UTF-8 解碼漏洞 |
| **NULL Byte 截斷** | `../../../../etc/passwd%00.jpg` | 在高版本已被修復；特定舊版 PHP/C 函式庫以 `\0` 提前截斷副檔名 |

## 🥷 第三動：防禦規避與日誌鑑識特徵 (Evasion & Telemetry)

- **Nginx Off-by-Slash 缺陷利用**：
  ```nginx
  location /files {
      alias /var/www/static/; # 缺陷：files 後方缺少斜線
  }
  ```
  攻擊者發送 `GET /files../secret/app.py`，Nginx 拼接成 `/var/www/static/../secret/app.py`，達成跨目錄存取。
- **鑑識特徵**：
  - **日誌特徵**：Web 存取日誌中出現連續的 `..%2f`、`..%5c` 或密集出現 `/etc/passwd` 等敏感路徑。
  - **系統呼叫監控 (Auditd / Sysmon)**：Web 進程發起對非業務目錄（如 `/etc/` 或 `C:\Windows\`）的大量 `open` 調用。

## ⚔️ 第四動：紅藍攻防對抗矩陣 (Red vs. Blue Confrontation Matrix)

| 攻擊模式 (Offense) | 藍隊遙測指標 (Blue Telemetry) | 防禦基線反制 (Mitigation Baseline) | 繞過與殘餘考量 (Residual Seam) |
| :--- | :--- | :--- | :--- |
| **相對路徑跳躍** | 存取日誌中包含 `../` 或 `..\` | 調用 `realpath()` 並檢驗路徑開頭是否在白名單內 | 利用軟連結 (Symlink) 繞過規範化檢查 |
| **雙寫 / 編碼繞過** | 檢測到 `%252e` 或非標 UTF-8 字元 | 拒絕所有非英數字元檔名，強制使用隨機 ID 存取 | 尋找未套用正則校驗的檔案上傳端點 |
| **Off-by-Slash** | 請求路徑命中缺少末端斜線之 location | Nginx 配置中嚴格保持 `location /dir/` 與 `alias` 斜線一致 | 依賴第三方模組路徑重寫漏洞 |
| **Windows 8.3 檔名** | 存取包含 `~1` 之短檔名特徵 | 在作業系統層全域停用 8.3 短檔名支援 | 轉向利用 Windows Alternate Data Streams (ADS) |

## 🛡️ 第五動：安全加固與修復基線 (Hardening & Remediation Baseline)

### 1. Python 生產級路徑規範化校驗
```python
import os

BASE_DIR = os.path.abspath("/var/www/uploads")

def get_safe_file_path(user_filename: str) -> str:
    # 1. 取得解析真實 Inode 後的唯一絕對路徑
    target = os.path.abspath(os.path.join(BASE_DIR, user_filename))
    
    # 2. 嚴格比對前綴，確保檔案物理位置必須在 BASE_DIR 之內
    if not target.startswith(BASE_DIR + os.sep):
        raise PermissionError("Access Denied: Path Traversal Detected")
        
    return target
```

### 2. 軟體工程最佳實踐：ID 映射法 (Indirection)
徹底避免讓客戶端直接指定檔案名稱；將檔案存儲於資料庫中，為每個檔案生成 UUID，用戶端僅能以 `GET /file?id=3fa85f64-5717...` 進行調用。

## 🧪 實戰演練環境導引 (Hands-on Range Lab Walkthrough)

### 1. 靶場核心代碼 (`traversal_lab.py`，極簡 20 行)
```python
from http.server import ThreadingHTTPServer, BaseHTTPRequestHandler
from urllib.parse import parse_qs, urlsplit
import os

BASE_DIR = "/tmp/sandbox"
os.makedirs(BASE_DIR, exist_ok=True)
with open(os.path.join(BASE_DIR, "safe.txt"), "w") as f: f.write("Safe content\n")

class TraversalHandler(BaseHTTPRequestHandler):
    def do_GET(self):
        filename = parse_qs(urlsplit(self.path).query).get('file', [''])[0]
        # 缺陷：直接拼接使用者輸入
        full_path = os.path.join(BASE_DIR, filename)
        
        if "safe=1" in self.path:
            # 加固邏輯
            real = os.path.realpath(full_path)
            if not real.startswith(os.path.realpath(BASE_DIR) + os.sep):
                self.send_response(403); self.end_headers(); self.wfile.write(b"Forbidden"); return
                
        try:
            with open(full_path, "rb") as f:
                self.send_response(200); self.end_headers(); self.wfile.write(f.read())
        except Exception as e:
            self.send_response(404); self.end_headers(); self.wfile.write(str(e).encode())

ThreadingHTTPServer(("127.0.0.1", 8112), TraversalHandler).serve_forever()
```

### 2. 三步驗證流程

1. **讀取正常檔案**：
   ```bash
   curl -s "http://127.0.0.1:8112/?file=safe.txt"
   # 回顯: Safe content
   ```
2. **路徑遍歷讀取系統 hosts**：
   ```bash
   curl -s "http://127.0.0.1:8112/?file=../../../../etc/hosts"
   # 成功越權回顯系統 hosts 內容！
   ```
3. **驗證加固端點**：
   ```bash
   curl -s "http://127.0.0.1:8112/?safe=1&file=../../../../etc/hosts"
   # 回顯 Forbidden，成功阻斷！
   ```

## 🎯 作戰驗收檢查點 (Mastery Checklist)

- [ ] **Q1. 為什麼單純字串替換（如將 `../` 替換為空）無法防禦路徑遍歷？**  
  *分析思路*：若非遞迴替換，攻擊者使用雙寫嵌套 `....//`，中間的 `../` 被移除後，外圍字符重新拼裝為 `../`，直接突破過濾。

- [ ] **Q2. 什麼是路徑規範化 (Canonicalization)？**  
  *分析思路*：將相對路徑、符號連結、目錄跳躍符號（如 `.` 與 `..`）轉換為作業系統檔案系統中唯一的絕對物理路徑的過程。

- [ ] **Q3. Nginx 的 Off-by-Slash 漏洞成因是什麼？**  
  *分析思路*：在 Nginx 配置中，`location /files` 後方缺少斜線，但 `alias /data/` 帶有斜線；存取 `/files../` 時 Nginx 產生字串拼接錯誤，使請求逃逸至 `/data/` 的上一層目錄。

- [ ] **Q4. 雙重 URL 編碼（`%252e%252e%252f`）為何能突破某些 Web 防護層？**  
  *分析思路*：第一層 WAF 解碼一次得到 `%2e%2e%2f`，判定不包含 `../` 而放行；後端應用伺服器在讀取參數時進行二次解碼，還原出 `../`，造成防線擊穿。

- [ ] **Q5. 徹底根治路徑遍歷的最佳架構方案是什麼？**  
  *分析思路*：使用 `realpath()` 校驗最終檔案絕對路徑是否嚴格以受信任根目錄為前綴；最佳解為全盤採用 UUID 資料庫映射，用戶端完全不接觸實體檔名。
