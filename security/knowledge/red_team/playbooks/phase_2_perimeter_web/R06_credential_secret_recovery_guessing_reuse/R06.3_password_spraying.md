# R06.3 橫向密碼噴灑與低頻率帳號鎖定規避 (Password Spraying)

---

## 🎯 作戰任務破題 (Tactical Objective & Mental Workflow)

**橫向密碼噴灑 (Password Spraying)** 的物理本質為**利用「廣度優先比對 (Horizontal Traversal)」逆向破解「垂直帳號鎖定原則 (Vertical Account Lockout)」**。常規暴力破解是在單一帳號上嘗試數千組密碼，瞬間觸發鎖定；而密碼噴灑則是**「挑選一組極高機率之通用密碼（如季節+年份 `Autumn2026!`），對全企業數千個有效帳號各嘗試一次」**。每個帳號的失敗計數器 (`badPwdCount`) 僅增加 1，完全不觸發防禦門檻。完成一輪後等待鎖定時窗歸零，再發動第二輪，達成全網帳號零被鎖、SOC 監控靜默的合法登入突破。

```
[收集全網有效使用者清單 (數千個帳號)] ── 挑選單一高命中密碼 (如: Welcome2026!)
                                                │
                                                ▼ 啟動分散式密碼噴灑 (CredMaster / FireProx)
┌───────────────────────────────────────────────┴───────────────────────────────────────────────┐
│ [輪次 1] 透過動態雲端代理 (AWS API Gateway)，對 User_001 至 User_999 各嘗試 1 次                 │
│         - 每個帳號失敗次數: 1 次 (安全門檻: 5 次 ➔ 0 帳號被鎖！)                             │
│         - 每個請求 IP 來源: 每次切換不同出口 IP (避開 IP 頻率封鎖！)                         │
└───────────────────────────────────────────────┬───────────────────────────────────────────────┘
                                                ▼
[強制冷卻時窗 (Cool-down)] ────────────────────► 等待 60 分鐘，待伺服器將 badPwdCount 清除歸零
                                                │
                                                ▼ 命中 2~5 組弱密碼使用者！
[突破外網周界認證 (M365 / VPN / OWA)] ─────────► 成功獲取初始身分權杖，達成完全無痕入侵！
```

## 🔬 第一動：噴灑陣列矩陣與計數器衰減物理架構 (Mechanics & Lockout Reset)

### 1. 噴灑作戰維度與傳統暴破對比

| 比較維度 | 傳統定向暴破 (Brute-Force) | 橫向密碼噴灑 (Password Spraying) |
| :--- | :--- | :--- |
| **目標矩陣** | $1 \text{ User} \times M \text{ Passwords}$ (縱向深度) | $N \text{ Users} \times 1 \text{ Password}$ (橫向廣度) |
| **單一帳號失敗率**| 極高 (秒級突破 5 次) | **極低 (每小時僅 1 次，永遠小於閾值)** |
| **帳號鎖定風險** | **100% 觸發鎖定** (引起業務中斷與 SOC 介入) | **0% 鎖定風險** (安全無害隱蔽潛行) |
| **候選密碼來源** | 巨型字典 (rockyou.txt) | 季節變形 (`Summer2026!`)、公司簡稱 (`Corp123!`) |

## 🛡️ 第五動：工程級防禦基線 (Hardening Baselines)

1. **全面推行具備號碼比對的 MFA (MFA with Number Matching)**：
   - 杜絕單純可盲點「允許」之 Push Notification，強制輸入螢幕上顯示的兩位數號碼，阻斷疲勞轟炸與噴灑登入。
2. **部署 Microsoft Entra 密碼保護 (Password Protection)**：
   - 啟用全域動態禁用密碼清單，禁止設定包含企業名稱、季節 (`Spring` / `Summer`)、年份之常見噴灑密碼。
3. **雲端智慧型鎖定機制 (Smart Lockout)**：
   - 配置智慧型鎖定原則，自動依據連線信譽只鎖定惡意來源的猜測通道，同時確保企業內部真實使用者不受 DoS 影響。

for user, actual_pass in user_db.items():
    # 模擬隨機抖動延遲，規避速率監控

## 🎯 作戰驗收檢查點 (Operational Checkpoints)

- [ ] **Q1：在選擇噴灑密碼時，紅隊最優先選擇的「黃金密碼模式」是什麼？**
  - **戰術思維**：**「當前季節/月份 + 當前年份 + 特殊符號」**（如 `Spring2026!` 或 `Summer2026@`）。這是絕大多數強制要求 90 天定期更換密碼之企業員工最常採用的「合規應付型弱密碼」。
- [ ] **Q2：密碼噴灑時，若目標鎖定原則為「5 次錯誤鎖定 30 分鐘」，安全的作業間隔為何？**
  - **戰術思維**：最保守安全的作戰節奏是**每輪噴灑僅嘗試 1 組密碼，輪次之間嚴格休眠 35~40 分鐘**，確保所有帳號的失敗計數器在下一輪開始前已安全歸零。
- [ ] **Q3：為何使用 AWS API Gateway (FireProx) 能徹底化解現代 WAF 的 IP 頻率封鎖？**
  - **戰術思維**：API Gateway 是無伺服器架構，每次轉發 HTTP 請求時都會自 AWS 龐大的全域 IP 池中動態分配一個全新的出口 IP，伺服器看到的每個請求來源 IP 皆完全不同，使基於來源 IP 的計數器徹底失效。
- [ ] **Q4：在混合雲環境中，針對地端 AD 噴灑與針對 Entra ID (Azure AD) 噴灑有何風險差異？**
  - **戰術思維**：地端 AD 若配置了鎖定原則，若未妥善控制間隔可能引發全公司大規模鎖定 (DoS)；而 Entra ID 具備 Smart Lockout，只會鎖定攻擊者的異常連線，不會鎖死本機使用者，但會觸發更高層級的雲端風險事件 (Risky Sign-ins)。
- [ ] **Q5：為何密碼噴灑前，先透過 OSINT 獲取精確的員工名單 (Username Enumeration) 是成敗關鍵？**
  - **戰術思維**：若帳號清單中充斥著不存在的無效帳號，登入端點回傳的錯誤特徵可能異常，且容易觸發防禦方針對「不存在使用者枚舉」之告警；高品質的真實帳號名單能將雜訊降至最低。
