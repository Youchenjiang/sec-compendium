# R06.4 外洩憑證撞庫與已知憑證跨域重用 (Credential Stuffing)

---

## 🎯 作戰任務破題 (Tactical Objective & Mental Workflow)

**外洩憑證撞庫與跨域重用 (Credential Stuffing & Credential Reuse)** 的物理本質為**利用人類在不同平台「重複使用相同密碼組合」的心理慣性，將歷史外洩資料庫 (Breach Databases) 武器化為直接突破企業周界的精準彈藥**。紅隊自公開情報源或外洩合輯 (Combo Lists) 提取含有目標企業網域名稱 (`@corp.com`) 或高管個人郵箱之帳密配對，透過自動化測試通道將其批次注入目標組織的外部驗證介面（如 VPN、SSO、Webmail、SaaS 應用），在零漏洞依賴的情況下直接獲得有效身分工作階段。

```
[歷史外洩資料庫 (DeHashed / Breach VIP)] ── 檢索目標網域: *@corp.internal
                                                │
                                                ▼ 獲取正規化帳密組合清單 (Combo List: user:pass)
[自動化撞庫引擎 (OpenBullet / Puppeteer)] ────── 1. 動態偽造 TLS 指紋 (JA3/JA4) 與瀏覽器特徵
                                                │
                                                ▼ 2. 掛載住宅代理池 (Residential Proxies) 併發重放
[企業外網身分入口 (VPN / Okta / Azure AD)] ◄─── 3. 提交已外洩之合法憑證組合
                                                │
                                                ▼ 4. 比對成功！回傳 Session Token 或 MFA 提示
[憑證重用突破] ────────────────────────────────► 突破外網周界，獲取企業內部網路合法通行證！
```

## 🛡️ 第五動：工程級防禦基線 (Hardening Baselines)

1. **部署外洩憑證即時比對服務 (Breached Password Protection)**：
   - 整合 **Have I Been Pwned (HIBP)** 或 Azure AD 密碼防護；當使用者變更密碼或登入時，自動比對全網最新外洩資料庫，命中者強制要求更換。
2. **全面落實抗釣魚/抗重用之 FIDO2 多因素驗證**：
   - 強制全域啟用硬體金鑰 (YubiKey) 或 WebAuthn Passkeys，使靜態密碼即使外洩亦無法完成第二道身分授權。
3. **部署進階反機器人防禦 (Advanced Bot Management)**：
   - 引入客戶端行為特徵分析（滑鼠軌跡、打字停頓）與非同步挑戰 (Proof-of-Work)，在網路邊界將自動化撞庫腳本全數過濾。

# 模擬自外部 DeHashed 撈出之外洩名單
leak_combo = [("hr@corp.internal", "123456"), ("ceo@corp.internal", "admin"), ("sales@corp.internal", "welcome")]

print("[*] 啟動自動化外洩憑證跨域重用驗證作戰...")

## 🎯 作戰驗收檢查點 (Operational Checkpoints)

- [ ] **Q1：Credential Stuffing (撞庫) 與 Password Spraying (噴灑) 的本質差異為何？**
  - **戰術思維**：密碼噴灑是使用「單一或少量猜測性通用密碼」遍歷所有帳號；而撞庫是直接使用「歷史真實外洩的大規模帳密配對」進行一對一重放比對，其密碼是真實使用過的，命中率遠高於噴灑。
- [ ] **Q2：為何企業即便推行了超嚴格的內部密碼原則，依然無法抵禦撞庫威脅？**
  - **戰術思維**：因為員工常在「外部非受控之個人服務」（如購物網站、社群論壇、線上工具）使用公司郵箱註冊並設定相同或相似密碼；當該外部網站遭入侵外洩時，企業內網便直接面臨跨域重用風險。
- [ ] **Q3：在對抗現代 WAF 時，JA3 與 JA4 指紋對撞庫工具有何致命影響？**
  - **戰術思維**：JA3/JA4 會根據客戶端發送的 TLS ClientHello 封包（Cipher Suites、Extensions 順序）計算雜湊值。若使用未經偽裝的 Python `requests`，WAF 能在不檢查 HTTP 內容的情況下直接依據 TLS 特徵判定為腳本並阻斷。
- [ ] **Q4：為何住宅代理 (Residential Proxies) 是執行大規模撞庫的必備武器？**
  - **戰術思維**：因為住宅 IP 來自真實家用寬頻與行動基地台，其 IP 聲譽評分極高且地理位置分散，現代防禦系統若對住宅 IP 實施無差別封鎖會引發嚴重的真實客戶誤殺。
- [ ] **Q5：若目標企業啟用了條件式存取 (Conditional Access)，撞庫成功後如何進一步突破？**
  - **戰術思維**：分析條件式存取規則（如要求受信任裝置或合規網段）；若外曝服務包含不受條件約束之舊版認證協定（如 POP3/IMAP 或 ActiveSync），可轉由該通道繞過 MFA 存取資料。
