### 1. 快速雜湊 vs 慢速硬雜湊對抗特徵

| 演算法類型 | 典型演算法代表 | 密碼學加鹽 / 迭代 | GPU 破解算力吞吐 (RTX 4090) | 防禦抗性等級 |
| :--- | :--- | :--- | :--- | :--- |
| **快速無鹽雜湊** | NTLM, MD5, SHA1 | 無鹽 (NTLM) 或單次 Hash | **> 100 GH/s** (百億次/秒) | 極低 (秒級被字典破譯) |
| **迭代型對稱雜湊** | WPA2, Kerberos TGS (RC4) | 具備特定環境 Context | **> 10 GH/s** (數十億次/秒) | 低 (弱密碼快速淪陷) |
| **CPU 密集慢雜湊** | SHA512-crypt (`$6$`), PBKDF2| 具備動態 Rounds (如 5000 次) | **~ 1 MH/s** (百萬次/秒) | 中等 (抗暴力窮舉) |
| **記憶體硬雜湊** | Argon2id, bcrypt, scrypt | 具備記憶體硬度 (Memory-Hard) | **< 100 kH/s** (千次/秒) | 極高 (物理阻斷 ASIC/GPU) |

## 🧪 實戰演練環境搭建 (Environment & Lab Setup)

### 1. 極簡 NTLM 雜湊產生與字典比對模擬器 (Python, 20 行)
```python
# hash_cracker.py
import hashlib

target_ntlm = "e52cac67419a9a224a3b108f3fa6cb6d"  # 密碼明文為: password
wordlist = ["admin", "123456", "welcome", "password", "Password123!"]

def ntlm_hash(password):
    return hashlib.new('md4', password.encode('utf-16le')).hexdigest()

print(f"[*] 開始離線字典碰撞目標 NTLM: {target_ntlm}")
for word in wordlist:
    h = ntlm_hash(word)
    if h == target_ntlm:
        print(f"[+] 碰撞成功！明文密碼還原為: [{word}] (耗時: 0.001s)")
        break
else:
    print("[-] 字典耗盡，未找到匹配項")
```

## 🎯 作戰驗收檢查點 (Operational Checkpoints)

- [ ] **Q1：為何 NTLM 雜湊在現代 GPU 前幾乎毫無抗性？**
  - **戰術思維**：NTLM 僅為單次 MD4 雜湊運算，**完全沒有任何加鹽 (Salt)**，也沒有任何運算迭代；現代頂級 GPU 架構每秒可執行數百億次 MD4 運算，任何 8 碼以內的常規密碼皆可在數分鐘內被彩虹表或窮舉攻破。
- [ ] **Q2：Hashcat 中的 `-O` (Optimized Kernels) 參數有何利弊？**
  - **戰術思維**：優點為透過記憶體暫存器優化大幅提升 30%~100% 的運算速度；限制在於該參數會限制密碼長度（通常限制在 32 字元以內），無法用於超長密語破解。
- [ ] **Q3：在實戰破解中，何謂「Prince 演算法」？**
  - **戰術思維**：Prince (PRobability INfinite Chained Elements) 演算法專門將字典中的詞彙依機率鏈式拼接（如 `word + 123 + !`），相較於傳統正則變形，能更智慧且高效地生成符合人類習慣的組合密碼。
- [ ] **Q4：若獲取的 Linux `/etc/shadow` 檔案雜湊以 `$y$` 開頭，代表何種挑戰？**
  - **戰術思維**：`$y$` 代表採用了 **yescrypt** 演算法，屬於高強度的現代記憶體硬雜湊架構，具有極強的抗 GPU/FPGA 專用加速晶片能力，破解速度極其緩慢。
- [ ] **Q5：為何藍隊部署密碼複雜度原則（要求大寫+小寫+數字）反而常常降低安全性？**
  - **戰術思維**：因為迫使人類採用可預測的套路模式（例如首字強制大寫、結尾強制加上 `1!` 或當前年份），紅隊只需在 Hashcat 中套用對應的簡單 Rule 即可精確秒殺，遠不如推行純長度字元串 (Passphrase) 有效。
