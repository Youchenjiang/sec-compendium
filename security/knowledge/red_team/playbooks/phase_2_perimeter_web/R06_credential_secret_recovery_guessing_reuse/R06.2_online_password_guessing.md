# R06.2 線上服務密碼定向猜測與通道探測 (Online Password Guessing)

---

## 🎯 作戰任務破題 (Tactical Objective & Mental Workflow)

**線上服務密碼定向猜測 (Online Password Guessing)** 的物理本質為**針對目標外曝網路驗證端點（如 SSH、RDP、VPN、Web 登入介面），以受控之低頻速率對特定高價值單一帳號發起字典比對**。與離線破解不同，線上猜測受制於網路往返延遲 (RTT)、伺服器防禦閾值與「帳號鎖定原則 (Account Lockout Threshold)」。紅隊必須透過開源情報 (OSINT) 構建極小化、高命中率之定向候選字典，並在嚴格的速率步調 (Pacing) 控制下實施精準刺客式猜測，避免觸發帳號鎖定中斷作戰鏈。

```
[鎖定目標高特權帳號: admin@corp] ── 基於 OSINT 產生 3~5 組高命中候選密碼
                                            │
                                            ▼ 評估目標防禦原則: 鎖定閾值 = 5 次，時窗 = 15 分鐘
┌───────────────────────────────────────────┴───────────────────────────────────────────┐
│ 1. 步調調度: 每次發送 1 次猜測 ➔ 強制休眠 5 分鐘 (Jitter 隨機抖動)                  │
│ 2. 通道選擇: 優先選擇不支援 MFA 或缺乏 Captcha 之舊版協定端點 (如 Exchange ActiveSync)│
│ 3. 節點輪替: 透過代理池 (Proxychains / Residential IPs) 輪換來源 IP 避開 IP 封鎖     │
└───────────────────────────────────────────┬───────────────────────────────────────────┘
                                            ▼
[目標認證端點 (VPN / OWA / SSH)] ──────────► 成功回傳 200 OK / Login Success (耗時 < 15 分鐘)
                                            │
                                            ▼ 零告警、未觸發帳號鎖定！
[初始外網存取突破] ────────────────────────► 獲取合法互動式憑證，成功建立內網立足點！
```

## 🔬 第一動：線上驗證協定機制與鎖定計數器物理架構 (Mechanics & Lockout Physics)

### 1. 主流認證協定與鎖定特徵矩陣

| 服務協定 | 預設監聽埠 | 驗證協定握手特徵 | 鎖定回傳特徵 |
| :--- | :--- | :--- | :--- |
| **SSH** | TCP 22 | 非對稱金鑰協商後明文傳輸密碼 | `Permission denied (publickey,password)` |
| **RDP** | TCP 3389 | CredSSP / NLA (網路等級驗證) | `STATUS_ACCOUNT_LOCKED_OUT (0xC0000234)` |
| **HTTP Basic** | TCP 80/443 | Base64 編碼於 `Authorization` 標頭 | HTTP 401 Unauthorized / 429 Too Many Requests |
| **ActiveSync** | TCP 443 | 常用於行動裝置同步郵件，常漏設 MFA | HTTP 200 (成功) 或 HTTP 403 (鎖定) |

## ⚡ 第二動：戰術執行與工具鏈操作 (Attack Vectors & Automation)

### 1. 核心線上定向猜測指令速查表 (Hydra / Medusa / Crowbar)

```bash
# 1. 針對 Web 表單登入介面進行低頻定向猜測 (THC-Hydra)
hydra -l admin -P targeted_passwords.txt 10.0.0.10 http-post-form \
    "/login:user=^USER^&pass=^PASS^:F=invalid password" -t 1 -W 60

# 2. 針對 Windows RDP 端點發起 NLA 猜測 (Crowbar)
crowbar -b rdp -s 10.0.0.10/32 -u Administrator -C targeted_passwords.txt

# 3. 針對 SSH 服務實施嚴格間隔猜測 (避免觸發 fail2ban)
medusa -h 10.0.0.10 -u root -P passwords.txt -M ssh -t 1 -r 15

# 4. 透過 SOCKS5 代理輪替發送猜測封包
proxychains hydra -l admin -P small_wordlist.txt 10.0.0.10 ssh -t 1
```

## 🥷 第三動：防禦規避與日誌特徵操控 (Evasion & Pacing Strategy)

### 1. 線上猜測防禦規避策略表

| 規避面向 | 原始觸發特徵 | 變形隱蔽手法 | 原理解析 |
| :--- | :--- | :--- | :--- |
| **帳號鎖定告警** | 連續 5 次錯誤導致帳號被鎖 (Event 4740) | **閾值內停步**：猜測 2 次後自動暫停等候計數器重置 | 確保 `badPwdCount` 永遠不突破鎖定門檻 |
| **單一 IP 頻率封鎖** | 短時間同 IP 密集請求觸發 Fail2ban 封鎖 | **住宅代理池輪替 (Residential IP Rotation)** | 每個猜測請求來自完全不同之自治系統 (ASN) |
| **驗證碼 (CAPTCHA)**| 登入失敗 3 次後強制要求圖形驗證碼 | 轉向無 Captcha 保護之 API 端點 (如 `/api/v1/auth`) | 利用架構邊界不一致性繞過人機防護 |

## 🛡️ 第五動：工程級防禦基線 (Hardening Baselines)

1. **強制啟用多因素身分驗證 (MFA Everywhere)**：
   - 所有外網可存取之服務（VPN, RDP, OWA, SSH）強制要求 FIDO2 或 TOTP MFA，使單純密碼猜測徹底失去作戰價值。
2. **部署自適應速率限制 (Adaptive Rate Limiting)**：
   - 針對 IP 與帳號雙維度實施指數退避延遲 (Exponential Backoff)，第 3 次失敗後每次強制等待 30 秒。
3. **安全帳號鎖定原則配置**：
   - 設定「5 次密碼錯誤後鎖定 15 分鐘」，並啟用「登入失敗計數器重設時間」為 15 分鐘，有效收窄暴破空間。

## 🧪 實戰演練環境搭建 (Environment & Lab Setup)

### 1. 極簡線上登入與鎖定計數器模擬靶機 (Python Flask, 20 行)
```python
# login_service.py
from flask import Flask, request, jsonify
import time

app = Flask(__name__)
# 模擬帳號資料庫 (密碼, 失敗次數, 鎖定截止時間)
users = {"admin": {"pass": "Spring2026!", "fails": 0, "locked_until": 0}}

@app.route("/login", methods=["POST"])
def login():
    u = request.json.get("user")
    p = request.json.get("pass")
    acc = users.get(u)
    if not acc: return jsonify({"error": "invalid"}), 401
    
    if time.time() < acc["locked_until"]:
        return jsonify({"error": "ACCOUNT_LOCKED", "flag": "FLAG{TRIGGERED_LOCKOUT}"}), 403
    
    if p == acc["pass"]:
        acc["fails"] = 0
        return jsonify({"status": "SUCCESS", "msg": "FLAG{ONLINE_GUESSING_PWNED}"})
    
    acc["fails"] += 1
    if acc["fails"] >= 3:
        acc["locked_until"] = time.time() + 60  # 鎖定 60 秒
        return jsonify({"error": "ACCOUNT_LOCKED"}), 403
    return jsonify({"error": "invalid credentials"}), 401

if __name__ == "__main__":
    app.run(port=8888)
```

### 2. 三步作戰驗證流程
```bash
# 步驟 1: 啟動模擬靶機
python3 login_service.py

# 步驟 2: 發送正確猜測密碼
curl -X POST http://127.0.0.1:8888/login -H "Content-Type: application/json" -d '{"user":"admin","pass":"Spring2026!"}'
# 驗證輸出：{"msg":"FLAG{ONLINE_GUESSING_PWNED}","status":"SUCCESS"}

# 步驟 3: 驗證鎖定防禦（故意連續傳入 3 次錯誤密碼）
# 驗證輸出：返回 403 ACCOUNT_LOCKED，證實計數器生效並阻絕後續猜測
```

## 🎯 作戰驗收檢查點 (Operational Checkpoints)

- [ ] **Q1：線上密碼猜測 (Guessing) 與密碼噴灑 (Spraying) 的根本戰術分水嶺為何？**
  - **戰術思維**：定向猜測是**「一個帳號、多組密碼」**，極易觸發目標帳號的鎖定閾值；密碼噴灑則是**「全網帳號、一組密碼」**，每個帳號僅嘗試一次，徹底規避帳號鎖定。
- [ ] **Q2：為何攻擊外曝的 Exchange ActiveSync 端點比常規 Web 介面更容易得手？**
  - **戰術思維**：ActiveSync 是為手機郵件設計的協定，許多企業為了讓員工手機同步郵件，在該協定上**未配置 CAPTCHA 驗證碼，甚至繞過了條件式存取 MFA 原則**。
- [ ] **Q3：在 Windows 網域環境中，`badPwdCount` 屬性何時會被重置為 0？**
  - **戰術思維**：當使用者**成功輸入正確密碼登入時**，或在連續失敗後**超過了群組原則配置的「重設帳戶鎖定計數器的時間 (Reset Lockout Counter After)」**，計數器會自動歸零。
- [ ] **Q4：若目標環境啟用了「智慧型鎖定 (Smart Lockout)」，對猜測者有何影響？**
  - **戰術思維**：智慧型鎖定能區分合法使用者與攻擊者的 IP 位置；來自外部攻擊者 IP 的連續失敗嘗試會被阻斷，但位於內網的真實使用者依然能夠正常登入，降低了 DoS 業務干擾。
- [ ] **Q5：在 SSH 猜測中，為何許多伺服器在 3 次嘗試失敗後會主動斷開 TCP Socket 連線？**
  - **戰術思維**：這是 OpenSSH 的 `MaxAuthTries` 預設保護機制（通常為 6 次，每連線嘗試 3 次）。攻擊者必須重新建立 TCP 連線，大幅增加了網路握手延遲與被防火牆識別的風險。
