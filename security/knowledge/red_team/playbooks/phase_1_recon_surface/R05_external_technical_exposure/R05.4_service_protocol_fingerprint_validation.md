# R05.4 服務協定與版本指紋精確識別 (Service & Protocol Fingerprint Validation)

---

## 🎯 作戰任務破題 (Tactical Objective & Mental Workflow)

**服務協定與版本指紋精確識別 (Service Fingerprinting)** 的物理本質為**向開放的傳輸層通訊埠主動發送應用層協定探針 (Application-Layer Probes)，依據目標端點回傳之 Banner、錯誤代碼樣態、TLS 參數協商與協定特殊實作細節，精確反查目標運行的真實軟體名稱與版本編號**。現代企業常將管理介面或內部服務偽裝於非標準埠位（如將 SSH 置於 443，或將 HTTP 置於 8443）；紅隊必須透過深度指紋驗證穿透埠位混淆，精準鎖定潛在存在已知漏洞 (N-Day) 的軟體版本。

```
[攻擊者針對開放埠位發送協定探針] ── (針對 TCP 8443 發送 HTTP / TLS / SSH 多重探針)
                                        │
                                        ▼ 捕獲應用層協定交握資料流
┌───────────────────────────────────────┴───────────────────────────────────────┐
│ 探針 1: TLS ClientHello ────────────► 獲取 X.509 憑證主體、JARM 指紋、ALPN 協商列表 │
│ 探針 2: HTTP GET / ─────────────────► 捕獲 Server 標頭、X-Powered-By、HTML Title  │
│ 探針 3: 異常畸形請求 ───────────────► 觸發預設錯誤頁面，萃取底層中間件版本標記    │
└───────────────────────────────────────┬───────────────────────────────────────┘
                                        ▼
[特徵庫比對 (Regex Match)] ─────────────► 【精確定性】識別為: Apache Tomcat 9.0.58 on Java 11
                                        │

[漏洞關聯庫對齊] ───────────────────────► 成功對齊特定 CVE，為後續精準武裝攻擊提供目標！
```

## 🔬 第一動：協定握手語意與版本特徵庫物理架構 (Mechanics & Probe Matching)

### 1. Nmap Service Probes 指紋比對引擎物理架構

| 探針指令類型 | 物理發送資料流 | 匹配規則 (Match Directive) | 萃取之核心屬性 |
| :--- | :--- | :--- | :--- |
| **NULL 探針** | 僅建立連線，不發送任何資料等待主動 Banner | `m|^SSH-([\d.]+)-OpenSSH_([\w.]+)|` | SSH 實體版本、OS 平台 |
| **Genericlines** | 發送 `\r\n\r\n` 觸發協定回顯 | `m|^220.*FTP|` | FTP 伺服器型態與歡迎標語 |
| **GetRequest** | 發送 `GET / HTTP/1.0\r\n\r\n` | `m|^Server: (Apache|nginx)/([\d.]+)|` | Web 伺服器中間件軟體版本 |
| **TLS ClientHello** | 包含特定 Cipher Suites 之握手請求 | 擷取 SANs、Issuer 與 JARM 雜湊 | 後端反向代理與真實證書主體 |

## ⚡ 第二動：戰術執行與工具鏈操作 (Attack Vectors & Automation)

### 1. 核心深度指紋識別指令速查表 (Nmap / Httpx / WhatWeb)

```bash
# 1. Nmap 深度服務版本探測 (啟用最高強度與腳本辨識)
nmap -sV --version-intensity 9 -sC -p 80,443,8080,8443 203.0.113.10 -oN services.txt

# 2. ProjectDiscovery httpx 高速 Web 指紋、狀態碼與標題收割
httpx -l live_hosts.txt -ports 80,443,8000,8080,8443,9000 \
    -status-code -title -web-server -tech-detect -o web_fingerprints.txt

# 3. 針對目標網站實施進階技術堆疊辨識 (WhatWeb)
whatweb -a 3 https://target.corp.internal --log-json whatweb_out.json

# 4. 針對未知高位埠發送指定協定握手探測 (利用 Netcat 手動拉取 Banner)
nc -nv -w 2 203.0.113.10 9999
```

## 🥷 第三動：防禦規避與日誌特徵操控 (Evasion & Probe Shaping)

### 1. 指紋探測特徵消減策略表

| 規避面向 | 原始觸發特徵 | 變形隱蔽手法 | 原理解析 |
| :--- | :--- | :--- | :--- |
| **全量探針風暴** | Nmap 預設發送數十個不同協定之探針 | **輕量探測 (`--version-light`)** | 僅發送最常見探針，降低畸形封包引發之 IDS 告警 |
| **User-Agent 特徵** | 標頭包含 `Nmap Scripting Engine` | 自訂偽裝為最新 Chrome/Safari 之 User-Agent | 避開 WAF 針對掃描器標頭之靜態阻斷 |
| **TLS 異常握手** | 不標準的 TLS 握手引發 JARM 監控 | 透過原生標準 Curl / OpenSSL 發送標準握手 | 使協商特徵完全貼合合法企業瀏覽器流量 |

## 🛡️ 第五動：工程級防禦基線 (Hardening Baselines)

1. **全面停用並剝離服務版本標籤 (Banner Stripping)**：
   - Nginx：配置 `server_tokens off;`。
   - Apache：配置 `ServerTokens Prod` 與 `ServerSignature Off`。
   - SSH：修改設定隱藏 OS 發行版綴詞。
2. **部署統一反向代理與標頭覆寫**：
   - 透過邊界 API 閘道或 CDN 強制覆寫 `Server` 標頭為通用標籤 (如 `Server: Protected-Gateway`)，抹除後端真實架構。
3. **客製化全域錯誤頁面 (Custom Error Pages)**：
   - 封閉 404/500 等預設錯誤回顯，杜絕因拋出例外堆疊 (Stack Trace) 洩漏 Tomcat、Django 或 Spring 底層版本。

## 🧪 實戰演練環境搭建 (Environment & Lab Setup)

### 1. 極簡 Banner 抓取與版本萃取模擬腳本 (Python, 20 行)
```python
# banner_grabber.py
import socket, re

target_ip = "127.0.0.1"
target_port = 8888

# 建立 TCP 連線發送 HTTP 探針
s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
s.settimeout(2.0)
s.connect((target_ip, target_port))
s.send(b"HEAD / HTTP/1.0\r\n\r\n")

response = s.recv(1024).decode(errors="ignore")
s.close()

# 解析 Server 標頭
match = re.search(r"Server:\s*(.+)", response, re.IGNORECASE)
if match:
    server_banner = match.group(1).strip()
    print(f"[+] 🎯 成功抓取服務版本指紋: [{server_banner}]")
    print(f"[!] FLAG{{SERVICE_FINGERPRINT_EXTRACTED_SUCCESS}}")
else:
    print("[-] 標頭中未發現 Server 指紋 (已加固或非 HTTP 服務)")
```

## 🎯 作戰驗收檢查點 (Operational Checkpoints)

- [ ] **Q1：當目標將 SSH 服務監聽在非標準的 TCP 443 埠時，Nmap 如何精確識別？**
  - **戰術思維**：Nmap 的 `-sV` 會先發送常規 HTTP 探針；當收到非預期回應時，會依照探針相容性與權重降級發送 NULL 探針。一旦連線建立，OpenSSH 伺服器會主動向用戶端吐出 `SSH-2.0-OpenSSH_...` 的歡迎字串，Nmap 即可藉由正則精確辨識。
- [ ] **Q2：何謂 JARM 雜湊指紋，其為何能跨越 IP 與網域名稱精準鎖定特定目標系統？**
  - **戰術思維**：JARM 探測的是「目標伺服器底層 TLS 堆疊的具體實作與密鑰套件偏好」。由於作業系統、OpenSSL 版本與應用程式底層設定不同，生成的 62 碼 JARM 雜湊具有極高唯一性，即使網站更換 IP 或域名，其 JARM 特徵依然不變。
- [ ] **Q3：在 Web 指紋識別中，favicon.ico 雜湊有何不可忽視之作戰價值？**
  - **戰術思維**：許多框架（如 Spring Boot、Apache Tomcat、GitLab）擁有預設的網站圖示；計算該圖示之 MurmurHash3 數值並在 Shodan/FOFA 中檢索，能瞬間找出全網所有採用該框架之隱藏端點。
- [ ] **Q4：若目標伺服器部署了「Banner 偽造防護 (Deceptive Banners)」，紅隊如何驗證其真偽？**
  - **戰術思維**：發送特定協定的「語法邊界探針」或「錯誤輸入測試」；觀察其回傳的狀態碼與例外格式（例如 Apache 與 Nginx 在處理超長 Header 或無效請求行時的預設行為差異），從底層行為特徵破除表面字串偽裝。
- [ ] **Q5：為何在進行服務版本識別時，必須嚴格控制 `--version-intensity`？**
  - **戰術思維**：強度設為 9 會發送全部 probe，其中包含大量畸形二進位封包，容易使脆弱的老舊工控 (ICS/SCADA) 設備當機或觸發強烈的 IDS/IPS 告警；常規作戰通常推薦使用強度 5~7 兼顧隱蔽性與精確度。
