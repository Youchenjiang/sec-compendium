# R05.3 傳輸層通訊埠狀態列舉與邊界過濾分析 (Port-State Enumeration)

---

## 🎯 作戰任務破題 (Tactical Objective & Mental Workflow)

**傳輸層通訊埠狀態列舉 (Port-State Enumeration)** 的物理本質為**透過主動注入不同 TCP/UDP 旗標組合之探測封包，依據目標端點與中間網路設備的回應特徵，精確推導出目標主機的通訊埠狀態（Open、Closed、Filtered）**。紅隊在確認主機存活後，必須調度 SYN 隱蔽掃描、FIN/Xmas 異常探測或高速非同步掃描器 (Masscan)，在最短時間內穿透邊界過濾器、辨識出全數 65,535 個潛在監聽端點，同時避開「所有通訊埠全開」的蜜罐混淆陷阱。

```
[攻擊者發送 TCP SYN 探測封包] ──► 注入目標 TCP/UDP 傳輸層埠位
                                        │
                                        ▼ 捕獲回傳之底層封包特徵
┌───────────────────────────────────────┴───────────────────────────────────────┐
│ 回應 A: 收到 TCP [SYN, ACK] ────────► 狀態判讀: 【OPEN】 (監聽中，立即回傳 RST 中斷)│
│ 回應 B: 收到 TCP [RST] ─────────────► 狀態判讀: 【CLOSED】 (無服務監聽，主機在線) │
│ 回應 C: 收到 ICMP Type 3 或完全逾時 ─► 狀態判讀: 【FILTERED】 (封包遭防火牆攔截丟棄)│
└───────────────────────────────────────┬───────────────────────────────────────┘
                                        ▼
[傳輸層攻擊面全開拓撲] ─────────────────► 繪製真實開放之服務埠位，進入服務協定指紋識別！
```

## 🔬 第一動：TCP/UDP 握手狀態與 6 大通訊埠狀態物理判定 (Mechanics & Port States)

### 1. Nmap 6 大核心埠位狀態物理判定矩陣

| 通訊埠判定狀態 | 探測封包形態 | 目標主機 / 防火牆回應封包 | 物理架構語意 |
| :--- | :--- | :--- | :--- |
| **Open (開放)** | TCP SYN 探針 | 收到 `SYN, ACK` 封包 | 應用程式正在監聽該埠位並準備接受連線 |
| **Closed (關閉)** | TCP SYN 探針 | 收到 `RST` 封包 | 作業系統核心活躍，但無任何行程綁定此埠 |
| **Filtered (過濾)** | TCP SYN 探針 | **完全無回應 (Timeout)** 或 ICMP Type 3 | 封包於抵達目標前遭防火牆/ACL 靜默丟棄 |
| **Unfiltered (未過濾)**| TCP ACK 探針 | 收到 `RST` 封包 | 埠位可達但不知是否開放 (用於探測防火牆規則) |
| **Open\|Filtered** | UDP 探針 / Xmas | **完全無回應 (Timeout)** | 無法判定是服務開放未回覆，還是被防火牆丟棄 |
| **Closed\|Filtered**| IP 協定探針 | 收到 ICMP Type 3 Code 2 | 協定不可達或遭過濾 |

## 🛡️ 第五動：工程級防禦基線 (Hardening Baselines)

1. **落實預設全部拒絕原則 (Default-Deny Ingress Baseline)**：
   - 邊界防火牆預設關閉所有 1-65535 埠位；僅顯式開放具備業務必要之外部埠位 (如 80/443)，其餘一律 DROP。
2. **部署敲門協定或零信任網路存取 (Port Knocking / ZTNA)**：
   - 將管理通訊埠 (SSH/RDP) 預設完全隱形；管理員必須先發送特定加密敲門序列或通過 ZTNA 驗證，防火牆才動態開放對應 IP 之連線。
3. **部署 Portspoof 主動混淆防禦**：
   - 對未授權的埠位掃描回傳虛假的 SYN-ACK 並模擬動態服務 Banner，徹底癱瘓自動化掃描器之識別邏輯。

## 🧪 實戰演練環境搭建 (Environment & Lab Setup)

### 1. 極簡 TCP 通訊埠掃描器核心邏輯 (Python, 20 行)
```python
# mini_port_scanner.py
import socket, sys

target_host = "127.0.0.1"
target_ports = [21, 22, 80, 443, 3389, 8888]

print(f"[*] 開始列舉目標 [{target_host}] 傳輸層通訊埠狀態:")
for port in target_ports:
    s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
    s.settimeout(0.5)
    result = s.connect_ex((target_host, port))
    if result == 0:
        print(f"[+] 🎯 埠位 [{port}/TCP] 狀態: 【OPEN】 (監聽中！)")
    elif result in [111, 10061]:  # Connection refused
        print(f"[-] 埠位 [{port}/TCP] 狀態: 【CLOSED】 (無服務監聽)")
    else:
        print(f"[?] 埠位 [{port}/TCP] 狀態: 【FILTERED】 (封包遭丟棄或逾時)")
    s.close()
```

## 🎯 作戰驗收檢查點 (Operational Checkpoints)

- [ ] **Q1：TCP SYN 掃描 (Stealth Scan) 為何相比 TCP Connect 掃描更具隱蔽性？**
  - **戰術思維**：SYN 掃描在收到目標回傳的 `SYN/ACK` 後，會**主動回傳 `RST` 封包終止連線**，從未完成三次握手。在許多作業系統中，只有完成握手的連線才會被傳遞給應用層，因此不會在 Web 伺服器等日誌中留下連線記錄。
- [ ] **Q2：若掃描器回報目標主機的所有 65,535 個通訊埠全部處於「Open」狀態，紅隊如何處置？**
  - **戰術思維**：這通常意味著命中了**主動防禦設備或蜜罐 (如 Portspoof)**。紅隊應立即停止全面掃描，改為僅針對特定核心協議（HTTP/HTTPS/DNS）發送標準應用層 Payload 進行真偽驗證。
- [ ] **Q3：在全域網際網路掃描中，Masscan 為何能達到每秒百萬封包的極致吞吐？**
  - **戰術思維**：Masscan 繞過了作業系統核心網路堆疊，採用原生封包驅動 (PF_RING / raw sockets) 直接在網卡上進行**非同步無狀態發包**，且使用自研之微型 TCP 狀態機解析應答。
- [ ] **Q4：UDP 埠位掃描為何速度極度緩慢且容易出現「Open|Filtered」模糊狀態？**
  - **戰術思維**：因為 UDP 是無連線協定，多數開放服務在收到空封包時不主動回傳資料；且作業系統核心對回傳 `ICMP Port Unreachable` (代表關閉) 設有嚴格的速率限制（如每秒僅 1 個），導致掃描器必須長時間等待逾時。
- [ ] **Q5：何謂「Idle Scan (空閒掃描 / 殭屍掃描)」，其對紅隊隱蔽性有何終極意義？**
  - **戰術思維**：利用網路上的一台閒置主機 (Zombie) 作為跳板，藉由觀察其 IP ID 序列增量來推測目標主機的埠位狀態。整個掃描過程中，**攻擊者的真實 IP 永遠不向目標主機發送任何封包**，實現完全匿名。
