# R05.6 Web 目錄路徑與敏感端點發現 (Web Content & Path Discovery)

---

## 🎯 作戰任務破題 (Tactical Objective & Mental Workflow)

**Web 目錄路徑與敏感端點發現 (Directory & Path Fuzzing)** 的物理本質為**利用字典窮舉與自動化爬蟲，探尋 Web 應用程式未在公開頁面建立超連結 (Unlinked)、但實際存在於伺服器檔案系統或路由表中的敏感端點與資源**。包括被遺忘之原始碼備份檔 (`.zip`, `.bak`)、版本控制元資料 (`.git`)、環境變數組態 (`.env`)、API 文件 (Swagger) 與未經身分認證之管理後台。紅隊透過高效遞迴掃描與狀態碼微調，往往能在邊界直接獲取足以接管全系統的核心憑證。

```
[鎖定目標 Web 應用程式] ── 啟動目錄模糊測試 (ffuf / Feroxbuster)
                                │
                                ▼ 字典注入 URI 路徑: https://target.corp.internal/FUZZ
┌───────────────────────────────┴───────────────────────────────────────────────┐
│ 探針 1: /.git/HEAD ─────────────────► 回傳 200 OK: ref: refs/heads/main (原始碼洩漏！)│
│ 探針 2: /.env ──────────────────────► 回傳 200 OK: DB_PASSWORD=Secret! (資料庫密鑰！)│
│ 探針 3: /v3/api-docs ───────────────► 回傳 200 OK: 取得全套 RESTful API 規格文件      │
│ 探針 4: /admin/ ────────────────────► 回傳 403 Forbidden (確認管理後台物理存在)      │
└───────────────────────────────┬───────────────────────────────────────────────┘
                                ▼
[敏感路徑與資產定位] ───────────► 獲取核心環境變數與原始碼，直接轉入後端 RCE 利用鏈！
```

## 🔬 第一動：URI 解析管線與敏感檔案命名物理機制 (Mechanics & Path Schemas)

### 1. 核心高危險暴露檔案類型與特徵矩陣

| 資源類別 | 典型曝險路徑 / 檔案名稱 | 物理洩漏本質 | 作戰威脅評級 |
| :--- | :--- | :--- | :--- |
| **版本控制元資料** | `/.git/HEAD`, `/.git/index` | 完整 Git 物件庫，可完全還原全站原始碼與 Commit 歷史 | **極度致命 (Critical)** |
| **環境設定檔** | `/.env`, `/config.json`, `/web.config` | 明文資料庫連線密碼、API 金鑰、JWT 簽名密鑰 | **極度致命 (Critical)** |
| **代碼備份封裝** | `/www.zip`, `/backup.tar.gz`, `/.bak` | 開發人員在 Web 根目錄臨時打包之完整壓縮檔 | **高危 (High)** |
| **API 介面定義** | `/swagger-ui.html`, `/openapi.json` | 暴露全部後端隱藏路由、參數規範與內部微服務名稱 | **高危 (High)** |
| **Spring Actuator** | `/actuator/env`, `/actuator/heapdump` | 包含 JVM 記憶體轉儲，可直接倒出記憶體中明文帳密 | **極度致命 (Critical)** |

## ⚡ 第二動：戰術執行與工具鏈操作 (Attack Vectors & Automation)

### 1. 核心目錄模糊測試指令速查表 (ffuf / Feroxbuster / Dirsearch)

```bash
# 1. 現代 Rust 高速遞迴掃描器 (Feroxbuster: 深度遞迴 + 自動濾波)
feroxbuster -u https://target.corp.internal -w /usr/share/seclists/Discovery/Web-Content/raft-medium-directories.txt \
    -x php,asp,aspx,jsp,html,js,json,bak,zip -t 30 -d 2 --no-state

# 2. ffuf 高精度副檔名模糊測試 (排除常見自訂 404 回應長度)
ffuf -u "https://target.corp.internal/FUZZ" \
    -w /usr/share/seclists/Discovery/Web-Content/raft-large-files.txt \
    -e .zip,.bak,.tar.gz,.env,.git -mc 200,301,302,403 -fc 404 -t 40

# 3. 專門針對 Git 洩漏實施無損原始碼還原 (GitDumper)
python3 gitdumper.py https://target.corp.internal/.git/ ./dumped_source/

# 4. 針對 API 與微服務端點進行定向爆破
ffuf -u "https://target.corp.internal/api/FUZZ" \
    -w /usr/share/seclists/Discovery/Web-Content/api-endpoints.txt -mc 200,401,403
```

## 🥷 第三動：防禦規避與日誌特徵操控 (Evasion & Rate Control)

### 1. 目錄探測防禦規避策略表

| 規避面向 | 原始觸發特徵 | 變形隱蔽手法 | 原理解析 |
| :--- | :--- | :--- | :--- |
| **404 狀態碼突增** | 短時間產生數千次 404 觸發 WAF 阻斷 | **動態錯誤率控制 (`--max-time` / `-p 0.2`)** | 降低探測速率，使 404 頻率被正常流量稀釋 |
| **副檔名黑名單過濾** | WAF 攔截帶有 `.git` 或 `.env` 之請求 | 透過 URL 雙重編碼或斜線變更 (`/%2e%67%69%74/`) | 繞過基於字串正規之初級過濾器 |
| **蜘蛛爬蟲陷阱** | 命中網站刻意留置之無窮遞迴目錄 (Trap) | 設定最大遞迴深度 (`-d 2`) 並限制單網域 URL 總數 | 防止掃描器陷入資源耗盡死迴圈 |

## 🛡️ 第五動：工程級防禦基線 (Hardening Baselines)

1. **強制封鎖隱藏檔案與敏感目錄存取**：
   - Nginx：配置全域規則直接拒絕所有點開頭之目錄與檔案：
     ```nginx
     # 安全: 全域封閉隱藏目錄與備份檔
     location ~ /\.(?!well-known) {
         deny all;
         return 404;
     }
     location ~* \.(bak|config|sql|tar\.gz|zip)$ {
         deny all;
     }
     ```
2. **CI/CD 自動化排程清理**：
   - 確保打包部署腳本中**絕對排除** `.git`, `.vscode`, `.env.local` 等敏感檔案，杜絕開發產物進入生產環境。
3. **全面停用目錄清單瀏覽 (Disable Directory Listing)**：
   - 關閉 Web 伺服器之 `autoindex` (Nginx) 或 `Options -Indexes` (Apache)，防止目錄結構被直接遍歷。

## 🎯 作戰驗收檢查點 (Operational Checkpoints)

- [ ] **Q1：當目標將敏感管理介面置於 `/admin/` 且目錄設定了 403 Forbidden，這是否代表死路？**
  - **戰術思維**：**絕對不是**。403 物理證實了該目錄「真實存在」。紅隊應以 `/admin/` 為基準發起第二級遞迴探測（如 `/admin/login.php`, `/admin/dashboard`, `/admin/api/`）；許多子頁面往往未繼承父目錄之存取控制。
- [ ] **Q2：何謂結尾斜線陷阱 (Trailing Slash Trap)，其在目錄探測中有何微妙影響？**
  - **戰術思維**：對於某些後端架構，訪問 `/admin` 會回傳 404 或轉址 301，而訪問 `/admin/` (帶斜線) 才會正確由目錄索引處理。若字典中缺少結尾斜線，可能直接漏掉整個核心系統。
- [ ] **Q3：在 Spring Boot 架構中，`/actuator/heapdump` 外洩對紅隊有何終極戰術價值？**
  - **戰術思維**：`heapdump` 是整個 Java 虛擬機器的記憶體映像檔；紅隊下載後可透過 MAT (Memory Analyzer Tool) 或 Jhat 直接抽取出快取在記憶體中的資料庫明文密碼、外部微服務 Token 與加解密金鑰。
- [ ] **Q4：在模糊測試中，若遇到伺服器實施頻率限制 (HTTP 429 Too Many Requests)，工具鏈應如何調整？**
  - **戰術思維**：在 ffuf 或 Feroxbuster 中調降併發執行緒 (`-t 2`)，啟用延遲參數 (`-p 0.5`)，或掛載支援多出口 IP 之代理池，確保請求頻率低於伺服器 Leaky Bucket 演算法之閾值。
- [ ] **Q5：為何透過爬蟲 (Crawler) 提取前端靜態 JavaScript 檔案常能發現最隱蔽的 API 路徑？**
  - **戰術思維**：現代前端單頁應用 (SPA) 所有的動態 API 調用端點皆以硬編碼字串形式存在於打包後的 `.js` (如 `app.bundle.js`) 之中，爬取並正規解析 JS 檔案能 100% 挖掘出字典中不存在的私有業務路徑。
