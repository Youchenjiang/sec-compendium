# R03.1 網域名稱註冊資訊與 RDAP/WHOIS 實體情報關聯 (WHOIS & RDAP Intelligence)

---

## 🎯 作戰任務破題 (Tactical Objective & Mental Workflow)

**網域名稱註冊情報檢索 (WHOIS / RDAP Intelligence)** 的物理本質為**透過網際網路名稱與數位位址分配機構 (ICANN) 轄下之頂級域名註冊局 (TLD Registries) 與受理註冊商 (Registrars)，檢索目標組織的法定註冊人、聯絡信箱、名稱伺服器 (NS) 與維護者標籤**。紅隊利用「反向 WHOIS (Reverse WHOIS)」技術，以單一已知的註冊人信箱或組織名稱為樞紐，批次關聯挖掘出企業名下所持有的**所有隱藏一級根網域 (Root Domains)**，徹底瓦解影子資產與孤立附屬業務邊界。

```
[已知目標品牌單一根域名: target.com] ── 查詢 RDAP / WHOIS 註冊伺服器
                                                │
                                                ▼ 萃取註冊人實體特徵
┌───────────────────────────────────────────────┴───────────────────────────────────────────────┐
│ 1. 組織名稱標籤: Registrant Organization = "Target Enterprise Corp"                           │
│ 2. 歷史註冊信箱: Registrant Contact = "dns-admin@target.com" (未受隱私保護之舊記錄)           │
│ 3. 專屬名稱伺服器: Nameservers = ns1.target-dns.com, ns2.target-dns.com                      │
└───────────────────────────────────────────────┬───────────────────────────────────────────────┘
                                                ▼
[發動反向 WHOIS 關聯搜尋 (Whoxy / ViewDNS)] ──► 以組織名稱與專屬 NS 為條件全網比對
                                                │
                                                ▼ 收割 15 個全新一級關聯網域！
[繪製企業全景網域邊界] ────────────────────────► 包含 target-pay.com, target-logistics.net...
```

## 🔬 第一動：WHOIS 協定 vs RDAP 結構物理機制 (Mechanics & RDAP Hierarchy)

### 1. 傳統 WHOIS 與現代 RDAP 協定特性對照表

| 比較維度 | 傳統 WHOIS (RFC 3912) | 現代 RDAP (RFC 7480-7484) |
| :--- | :--- | :--- |
| **傳輸層協定** | TCP Port 43 (純文字 Socket) | **HTTPS (RESTful JSON API)** |
| **資料格式** | 非結構化明文字串 (各註冊商格式迥異) | **標準化 JSON 物件 (jCard 規格)** |
| **國際化支援** | 僅支援 ASCII，多位元編碼易亂碼 | 完全原生支援 UTF-8 與國際化域名 (IDN) |
| **GDPR 隱私遮蔽** | 多數欄位被強制替換為 `REDACTED FOR PRIVACY` | 支援基於身分驗證的分級存取控制 (Bootstrapping) |

## ⚡ 第二動：戰術執行與工具鏈操作 (Attack Vectors & Automation)

### 1. 核心網域情報與反向關聯指令速查表 (CLI / RDAP / Amass)

```bash
# 1. 透過現代 RDAP 查詢結構化網域資訊 (自動追蹤權威 ICANN 註冊局)
rdap target.com --json | jq -r '.entities[] | select(.roles[] | contains("registrant")) | .vcardArray[1]'

# 2. 透過 OWASP Amass intel 實施反向 WHOIS 全網關聯搜尋
amass intel -whois -d target.com -o related_domains.txt

# 3. 透過 Whoxy API 根據組織名稱批量反查所有歷史關聯網域
curl -s "http://api.whoxy.com/?key=<API_KEY>&reverse=whois&company=Target+Enterprise+Corp" | jq -r '.search_result[].domain_name'

# 4. 檢索歷史 WHOIS 資料庫以繞過現代 GDPR 隱私保護 (ViewDNS / SecurityTrails)
curl -s "https://api.securitytrails.com/v1/history/target.com/whois" \
    -H "apikey: <API_KEY>" | jq -r '.records[0].contact'
```

| 規避面向 | 原始觸發特徵 | 變形隱蔽手法 | 原理解析 |

## 🛡️ 第五動：工程級防禦基線 (Hardening Baselines)

1. **全面啟用 WHOIS 隱私保護 (Privacy Protection Baseline)**：
   - 所有公開註冊之域名強制啟用註冊商隱私遮蔽，禁止在公網暴露真實工程師個人信箱、電話與地址。
2. **啟用註冊局鎖定機制 (Registry Lock / Transfer Lock)**：
   - 配置 `clientTransferProhibited` 與 `serverTransferProhibited` 狀態旗標，防止網域名稱遭惡意劫持轉移。
3. **統一收斂名稱伺服器 (NS Consolidation)**：
   - 杜絕使用自建且包含企業特徵名稱的 NS (如 `ns1.corp.com`)，改採公共雲端託管 DNS (如 AWS Route53、Cloudflare)，切斷反向 NS 關聯利用鏈。

## 🎯 作戰驗收檢查點 (Operational Checkpoints)

- [ ] **Q1：何謂反向 WHOIS (Reverse WHOIS)，其在紅隊繪製攻擊面拓撲中有何關鍵價值？**
  - **戰術思維**：常規 WHOIS 是「由域名查註冊人」；反向 WHOIS 是「**由註冊人信箱/電話/組織名稱查名下擁有的所有網域名稱**」。它能將紅隊的作戰視野從「單一已知網站」瞬間擴展到「目標企業在全球註冊的數百個關聯與子公司網站」。
- [ ] **Q2：歐盟 GDPR 實施後，現代 WHOIS 普遍被隱私遮蔽，紅隊如何破局？**
  - **戰術思維**：檢索歷史快照資料庫（如 SecurityTrails、Whoxy 或 DomainTools 存檔）。因為許多網域在 2018 年以前就已註冊，其當時的純明文註冊資料早已被各國情資庫抓取留存，歷史記錄不受現代遮蔽影響。
- [ ] **Q3：在檢視網域名稱狀態 (Domain Status) 時，`clientHold` 代表何種狀態？**
  - **戰術思維**：`clientHold` 代表該網域已被註冊商**強制暫停解析 (Suspended)**，通常源於欠費、濫用投訴或執法調查；紅隊應將其標記為無效節點並排除出當前攻擊面。
- [ ] **Q4：為何專屬的 Nameserver (如 `ns1.company.com`) 會成為反向關聯的致命弱點？**
  - **戰術思維**：即使企業在所有網域上都開啟了 WHOIS 隱私遮蔽，但為了統一管理解析，通常會將所有網域的 NS 指向自家專屬的 DNS 伺服器；紅隊只要搜尋「使用該 NS 的所有網域」，隱私保護即刻形同虛設。
- [ ] **Q5：RDAP 相較於傳統 Port 43 WHOIS 在防火牆穿透與自動化上有何革命性優勢？**
  - **戰術思維**：傳統 WHOIS 使用 TCP 43，常被受限內網或雲端防火牆阻斷；RDAP 是標準的 **HTTPS (Port 443) RESTful API**，天然穿透所有防火牆，且回傳標準 JSON，完全不需針對不同註冊商撰寫繁瑣的正則表達式解析器。
