# R03.3 被動與歷史 DNS 解析情資反查 (Passive & Historical DNS Intelligence)

## 🎯 作戰任務破題 (Tactical Objective & Mental Workflow)

**被動與歷史 DNS 情資分析 (Passive DNS, pDNS)** 的物理本質為**利用全球遞迴解析伺服器 (Recursive Resolvers) 與感測器網路所長期截獲並聚合之歷史解析快照，在「零網路發包、零目標互動」的前提下，重構目標企業隨時間推移的數位基礎設施演變歷史**。紅隊藉此可精準發掘已被現代 DNS 刪除但伺服器仍實體運作之「影子端點」、在引入 CDN 之前曾綁定之「真實源站舊 IP」，以及指向過期第三方雲端服務之「懸空 CNAME (Dangling DNS)」。

```
[目標主域名: target.corp.internal] ── 查詢全球被動 DNS 資料庫 (SecurityTrails / Farsight)
                                            │
                                            ▼ 檢索歷史時間序列 (First-Seen ~ Last-Seen)
┌───────────────────────────────────────────┴───────────────────────────────────────────┐
│ 發現 1: dev.target.corp ─────► 2021 年曾解析至 203.0.113.88 (現已刪除 DNS，但主機仍連網！)│
│ 發現 2: www.target.corp ─────► 2023 年遷移至 Cloudflare 前，真實 IP 為 198.51.100.10     │
│ 發現 3: blog.target.corp ────► CNAME 指向 target.github.io (第三方平台已刪除，可被劫持！)│
└───────────────────────────────────────────┬───────────────────────────────────────────┘
                                            ▼
[時間軸跨度情資收斂] ───────────────────────► 掌握未列管之遺留伺服器、原始真實 IP 與劫持標的！
                                            │
                                            ▼ 完全零發包、目標 SOC 零感知
[精準實施邊界突破] ────────────────────────► 針對未經安全加固之遺留端點實施降維打擊！
```

## 🔬 第一動：pDNS 感測器架構與時間序列解析物理機制 (Mechanics & Sensor Networks)

### 1. 被動 DNS 運作架構與數據欄位規格

| 核心欄位 | 物理意義 | 作戰判讀價值 |
| :--- | :--- | :--- |
| **RRSet (資源集合)** | `(Domain, Type, RData)` 三元組 | 記錄特定網域名稱曾對應之具體 IP 或別名 |
| **First-Seen** | 感測器全球首次捕獲該解析之時間戳 | 判定該資產或服務上線之確切歷史起點 |
| **Last-Seen** | 感測器全球最近一次捕獲該解析之時間戳 | **判定資產是否仍在運作** (若距今僅數小時，高機率存活) |
| **Count** | 歷史上捕獲此解析請求之總次數 | 評估該端點之存取頻率與業務重要性權重 |

## ⚡ 第二動：戰術執行與工具鏈操作 (Attack Vectors & Automation)

### 1. 核心被動 DNS 檢索指令速查表 (CLI & SecurityTrails / VirusTotal)

```bash
# 1. 透過 SecurityTrails API 萃取目標網域的所有歷史 A 記錄 (含首次與最後看見時間)
curl -s -N "https://api.securitytrails.com/v1/history/corp.internal/dns/a" \
    -H "apikey: <API_KEY>" | jq -r '.records[] | "\(.values[].ip) | \(.first_seen) ~ \(.last_seen)"'

# 2. 檢索目標網域歷史存在過之全部子網域名稱 (Subdomain History)
curl -s -N "https://api.securitytrails.com/v1/domain/corp.internal/subdomains" \
    -H "apikey: <API_KEY>" | jq -r '.subdomains[]' > historical_subdomains.txt

# 3. 透過 VirusTotal pDNS API 反查特定 IP 歷史綁定過的所有網域名稱
curl -s -X GET "https://www.virustotal.com/api/v3/ip_addresses/203.0.113.10/resolutions" \
    -H "x-apikey: <VT_API_KEY>" | jq -r '.data[].attributes.host_name'

# 4. 利用 OWASP Amass 整合被動 DNS 引擎實施純被動拓撲收集
amass enum -passive -d corp.internal -o passive_hosts.txt
```

## 🛡️ 第五動：工程級防禦基線 (Hardening Baselines)

1. **落實 DNS 生命週期終止自動化 (DNS Lifecycle Management)**：
   - 服務下線流程中，將「刪除關聯之 DNS 記錄」列為強制簽核步驟；嚴禁保留指向已釋放 IP 的孤立記錄。
2. **防範子網域劫持之懸空指標巡檢 (Dangling CNAME Auditing)**：
   - 每週自動化掃描所有 CNAME 記錄，若其指向之第三方平台 (AWS S3, Azure Blob, GitHub Pages) 回傳 404 或未宣告，強制立即註銷該 CNAME。
3. **更換 CDN 時強制輪替源站 IP (Origin IP Re-IPing)**：
   - 在為網站啟用 Cloudflare 或 Akamai 前，必須同步將後端源站的公網 IP 進行更換，徹底使歷史 pDNS 記錄中的舊 IP 失效。

## 🎯 作戰驗收檢查點 (Operational Checkpoints)

- [ ] **Q1：被動 DNS (Passive DNS) 的數據來源物理本質是什麼？**
  - **戰術思維**：pDNS 不是透過爬蟲主動掃描生成的，而是在全球各地大型 ISP 與遞迴 DNS 伺服器出口處部署「旁路封包監聽感測器 (Sniffers)」，被動記錄所有真實使用者在「快取未命中 (Cache Miss)」時向上游權威 DNS 查詢的回應封包並匯總入庫。
- [ ] **Q2：何謂「子網域劫持 (Subdomain Takeover)」，其物理觸發條件為何？**
  - **戰術思維**：目標將子網域 CNAME 指向第三方託管服務（如 `target.s3.amazonaws.com`）；隨後目標刪除了該 S3 儲存桶，但**忘記刪除 DNS 中的 CNAME 記錄**。攻擊者只需在 AWS 重新註冊該同名儲存桶，即可完全控制該官方子網域之內容。
- [ ] **Q3：在被動 DNS 記錄中，若某個已廢棄子網域的 Last-Seen 顯示為數小時前，代表何事？**
  - **戰術思維**：代表在全球範圍內，直到數小時前依然有真實用戶或排程系統在查詢並解析該網域名稱，物理證明該端點背後的基礎設施極可能仍在開機運作，具備極高的作戰攻擊價值。
- [ ] **Q4：被動 DNS 能否幫助紅隊挖掘目標的影子 API 端點 (Shadow APIs)？**
  - **戰術思維**：**可以**。歷史記錄常包含 `api-v1-deprecated.corp.com`、`mobile-staging.corp.com` 等早期版本路由；這些端點往往缺乏現代 WAF 保護與最新身分驗證基線，成為防線最薄弱的突破口。
- [ ] **Q5：為何目標組織更換了權威名稱伺服器 (NS) 後，舊的 pDNS 記錄依然會被保留？**
  - **戰術思維**：被動 DNS 是「 append-only (僅追加) 的不可變時序資料庫」；歷史上只要曾被記錄過一次，即便目標更換註冊商、變更 NS 或徹底刪除網域，歷史條目永遠留存供情資分析與鑑識回溯。
