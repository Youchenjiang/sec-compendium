# R02.1 開放網路搜尋引擎偵察與進階 Dorking 語法 (Search-Engine Reconnaissance)

---

## 🎯 作戰任務破題 (Tactical Objective & Mental Workflow)

**開放網路搜尋引擎偵察 (Google Dorking / Search Engine Intelligence)** 的物理本質為**利用全球商業搜尋引擎（Google、Bing、DuckDuckGo、Baidu）長期爬取並建立之「倒排索引 (Inverted Index)」資料庫，藉由特定邏輯運算元 (Search Operators)，精確過濾出目標組織無意洩漏於網際網路上的機密文件、敏感管理介面、組態備份檔與軟體錯誤堆疊**。紅隊在此階段完全不與目標伺服器進行任何直接網路交互，純粹從搜尋引擎快取中提取內部員工帳號、印表機路徑與軟體架構情資。

```
[攻擊者控制台] ── 構造 Google 高級 Dorking 語法: site:corp.internal filetype:xlsx "password"
                        │
                        ▼ 發送請求至 Google / Bing 倒排索引資料庫
┌───────────────────────┴───────────────────────────────────────┐
│ 【物理邊界: 零目標接觸】 查詢流量僅抵達 Google 伺服器，目標 SOC 完全零感知 │
│ 語法 1: site:corp.internal filetype:pdf ─────► 萃取員工通訊錄與組織章程  │
│ 語法 2: site:corp.internal inurl:login ──────► 定位未列管之影子後台與 SSO│
│ 語法 3: site:corp.internal ext:sql OR ext:env ► 直接命中洩漏之資料庫備份 │
└───────────────────────┬───────────────────────────────────────┘
                        ▼
[提取機密檔案並執行元資料分析 (FOCA / ExifTool)] ──► 萃取出內部網域帳號、作業系統版本、印表機路徑
                        │
                        ▼ 零告警獲取企業內部架構
[奠定後續精準打擊情報基礎] ──────────────────────► 為定向社交工程與密碼噴灑提供高價值彈藥！
```

## 🔬 第一動：網路爬蟲索引機制與進階運算元物理架構 (Mechanics & Search Operators)

### 1. 核心搜尋引擎運算元矩陣與語意規範

| 運算元 | 語法結構 | 物理過濾機制 | 紅隊情報挖掘應用 |
| :--- | :--- | :--- | :--- |
| **`site:`** | `site:corp.internal` | 限制檢索結果僅包含指定網域及其子網域 | 鎖定特定企業範圍，排除無關外網雜訊 |
| **`filetype:` / `ext:`**| `filetype:pdf,xlsx,docx,sql`| 依據 HTTP MIME-Type 與副檔名過濾 | 挖掘外洩之財務報表、合約、資料庫 Dump |
| **`inurl:`** | `inurl:admin`, `inurl:api/v1` | 匹配 URL 路徑字串中包含的特定關鍵字 | 搜尋隱密管理入口、Swagger 文件、登入介面 |
| **`intitle:`** | `intitle:"index of /"` | 匹配 HTML `<title>` 標籤中的文字 | **直接定位開放目錄瀏覽 (Directory Listing)** |
| **`cache:`** | `cache:target.com/page` | 讀取 Google 伺服器先前保存之歷史快照 | 檢閱目標已刪除或已下線之敏感頁面內容 |

## ⚡ 第二動：戰術執行與工具鏈操作 (Attack Vectors & Automation)

### 1. 核心 Google Dorking 語法與自動化工具指令

```bash
# 1. 檢索開放目錄瀏覽與敏感組態檔案 (GHDB 經典語法)
site:corp.internal intitle:"index of /" "parent directory"
site:corp.internal ext:xml OR ext:conf OR ext:cnf OR ext:reg "password"

# 2. 檢索公網暴露之管理與監控後台
site:corp.internal inurl:login OR inurl:admin OR inurl:dashboard intitle:"Login"

# 3. 使用 Metagoofil 自動化批量下載目標公開文檔並提取元資料
metagoofil -d corp.internal -t pdf,doc,xls,xlsx -l 50 -n 20 -o ./corp_docs/ -f results.html

# 4. 透過 ExifTool 批量提取下載檔案中隱藏之內部使用者名稱與軟體路徑
exiftool -csv -Author -Creator -Producer -Software ./corp_docs/*.pdf > doc_metadata.csv
```

## 🥷 第三動：防禦規避與日誌特徵操控 (Evasion & Anti-CAPTCHA)

### 1. 搜尋情報探測防禦規避策略表

| 規避面向 | 原始觸發特徵 | 變形隱蔽手法 | 原理解析 |
| :--- | :--- | :--- | :--- |
| **Google 人機驗證 (CAPTCHA)**| 快速發送複雜 Dork 觸發 Google 機器人攔截 | 使用 **SerpAPI / Serper API** 或住宅代理輪替 | 透過合法 API 介面發起查詢，徹底免除 CAPTCHA |
| **目標伺服器日誌留存** | 點擊搜尋結果直連目標伺服器 | **僅檢視搜尋引擎快照 (Google Cache / Wayback)**| 閱讀快取內容，連線流量完全不抵達目標站台 |
| **單一搜尋引擎盲區** | 特定私有內容未被 Google 收錄 | 交叉調度 **DuckDuckGo, Bing, Baidu, Yandex** | 聚合多個獨立爬蟲索引庫，最大化情資覆蓋率 |

## 🛡️ 第五動：工程級防禦基線 (Hardening Baselines)

1. **嚴格配置防爬蟲標頭 (X-Robots-Tag Baseline)**：
   - 內部系統、管理介面與後台**強制在 HTTP 回應中附加 `X-Robots-Tag: noindex, nofollow, noarchive`**，徹底阻斷快取存檔。
2. **辦公文檔中繼資料自動清洗 (Metadata Stripping Pipeline)**：
   - 在企業外發檔案系統或官網 CMS 上傳入口配置自動化腳本，強制抹除 PDF、Word、Excel 中的 Author、Company、軟體版本與印表機路徑。
3. **建立 Google Hacking 定期主動自檢機制**：
   - 內部安全團隊定期使用自研腳本對自身主域名執行常見 GHDB 關鍵字檢索，第一時間發現並清理誤公開之測試檔案。

## 🎯 作戰驗收檢查點 (Operational Checkpoints)

- [ ] **Q1：`robots.txt` 檔案在紅隊作戰中為何常被戲稱為「藏寶圖」？**
  - **戰術思維**：因為開發人員為了防止敏感目錄被搜尋引擎收錄，常在 `robots.txt` 的 `Disallow:` 欄位中寫入如 `/admin/`、`/secret_backup/`、`/api_internal/`；攻擊者只需主動閱讀此檔案，即可瞬間掌握全站最核心的機密路徑。
- [ ] **Q2：從公開文檔的「Author」欄位中，紅隊能推導出何種決定性作戰情資？**
  - **戰術思維**：能夠精確掌握企業內部 Active Directory 的**帳號命名規則**（例如：`johndoe` 代表「名字首字母+姓氏」，或 `john.d`）。掌握此命名規律後，結合 LinkedIn 人員名單即可批次拼裝出全公司員工的精確登入帳號。
- [ ] **Q3：何謂「Google 快照 (Google Cache)」，當目標網站已緊急下架漏洞頁面時有何利用價值？**
  - **戰術思維**：Google 在爬取網頁時會在伺服器備份當前畫面的 HTML 快照。即便管理員已發現外洩並下架頁面，只要使用 `cache:URL` 語法，攻擊者依然能從 Google 伺服器調出已刪除的頁面與密文。
- [ ] **Q4：在執行大量 Google Dork 搜尋時，如何解決頻繁跳出的「reCAPTCHA」阻斷？**
  - **戰術思維**：捨棄無頭瀏覽器模擬，改用商業搜尋引擎 API（如 SerpAPI、DataForSEO 或 Zenserp），這些平台內建全球代理池與反爬蟲繞過機制，能穩定提供純 JSON 格式的搜尋結果。
- [ ] **Q5：為何將檔案格式限定為 `ext:sql` 或 `ext:env` 常能直接突破目標核心邊界？**
  - **戰術思維**：許多網頁工程師在進行資料庫遷移或臨時備份時，習慣將檔案命名為 `dump.sql` 或 `database.backup` 並暫存在 Web 根目錄下；一旦被爬蟲抓取入庫，攻擊者下載即可獲得全量使用者明文密碼與鹽值。
