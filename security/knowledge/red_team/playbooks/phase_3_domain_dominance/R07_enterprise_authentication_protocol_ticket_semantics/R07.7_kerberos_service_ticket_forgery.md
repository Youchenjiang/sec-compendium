# R07.7 Kerberos 服務票證離線偽造與白銀票證 (Silver Ticket)

---

## 🎯 作戰任務破題 (Tactical Objective & Mental Workflow)

**白銀票證 (Silver Ticket / 服務票證偽造)** 的物理本質為**利用目標服務帳號自身的密碼雜湊或電腦帳號 (Computer Account) 金鑰，完全在離線端偽造針對該特定服務主體 (SPN) 的 Kerberos 服務票證 (TGS)**。相較於黃金票證需攻陷全網核心 `krbtgt`，白銀票證僅需持有目標單一伺服器的密碼雜湊即可鑄造；且在存取目標服務時，**連線完全不經過網域控制站 (DC)，DC 伺服器日誌中 100% 零痕跡 (Zero Footprint)**，實現極度隱蔽的目標主機接管。

```
[攻擊者攻陷目標主機或自 SAM/LSASS 提取電腦帳號 Hash] ── (獲取 TARGET$ 機器帳號 NTLM Hash)
                                                                │
                                                                ▼ 轉移至外部離線環境
[攻擊者離線控制台] ───────────────────────────────────────────── 1. 呼叫 ticketer.py -spn cifs/target.corp
                                                                │
                                                                ▼ 2. 使用目標機器帳號金鑰離線偽造並簽署 PAC
[生成針對性之白銀票證 (Silver Ticket)] ────────────────────────► (身分: Administrator, 服務: CIFS)
                                                                │
                                                                ▼ 【完全不連線 DC KDC (Port 88)】
[直連目標應用伺服器 (Port 445)] ◄────────────────────────────── 3. 直接發送 AP-REQ 握手
                                                                │
                                                                ▼ 4. 目標主機以本機金鑰解密成功，授權存取
[單機最高管理特權掌控] ────────────────────────────────────────► 獲取目標伺服器本地 SYSTEM / Admin 特權！
```

## 🔬 第一動：白銀票證加密結構與 PAC 驗證機制 (Mechanics & Service Keys)

### 1. 黃金票證 vs 白銀票證核心架構差異

| 比較維度 | 黃金票證 (Golden Ticket) | 白銀票證 (Silver Ticket) |
| :--- | :--- | :--- |
| **簽署與加密金鑰** | 網域核心 `krbtgt` 帳號密鑰 | **目標服務自身之密碼雜湊 / 電腦帳號金鑰** |
| **票證型態** | 認證票證 (TGT) | **服務票證 (TGS)** |
| **存取範圍** | 全網域所有主機與服務 | **僅限被偽造之該單一目標服務 (Specific SPN)** |
| **KDC 通訊需求** | 需向 KDC 索取 TGS 票證 (產生通訊) | **完全不與 KDC 通訊 (DC 零日誌、零感知)** |
| **防禦能見度** | DC 出現未配對之 4769 異常 | **DC 端完全無跡可尋** (僅留存於目標端點 4624) |

| 規避面向 | 原始觸發特徵 | 變形隱蔽手法 | 原理解析 |
| :--- | :--- | :--- | :--- |
| **KDC 遙測監控** | 集中式 SIEM 監控 Port 88 票證流量 | 完全繞過 KDC，直連目標服務端點 | **DC 端審計日誌完全不觸發任何事件** |

## 🛡️ 第五動：工程級防禦基線 (Hardening Baselines)

1. **強制啟用 Kerberos PAC 簽署驗證 (KB5020805 / CVE-2022-37967)**：
   - 部署微軟最新 Kerberos 安全修補，強制要求所有服務票證必須包含由 KDC 認證金鑰簽名之 PAC，並在 Netlogon 通道強制啟用稽核與拒絕模式。
2. **電腦帳號密碼自動輪替原則**：
   - 確保網域主機電腦帳號密碼依原則每 30 天自動更新，壓縮機器帳號雜湊洩漏後的作戰時窗。
3. **端點網路微隔離 (Micro-Segmentation)**：
   - 嚴格限制主機間的橫向通訊（如阻斷工作站互訪 Port 445/135/5985），阻斷白銀票證在伺服器間之傳播鏈路。

## 🎯 作戰驗收檢查點 (Operational Checkpoints)

- [ ] **Q1：白銀票證在實戰紅隊作戰中，為何被稱為「靜默刺客」？**
  - **戰術思維**：因為白銀票證是 TGS 服務票證，客戶端與目標伺服器直接建立通訊，**完全不需要向網域控制站 (DC) 的 Port 88 發起任何請求**；網域控制站上的 Event 4768 與 4769 完全保持靜止，藍隊若只在 DC 上監控 Kerberos 流量將被完全致盲。
- [ ] **Q2：若目標伺服器配置了特定的 SPN（如 `HOST/Server01`），持有其金鑰能存取哪些子服務？**
  - **戰術思維**：`HOST` SPN 在 Windows 體系中享有廣泛的覆蓋範圍，持有了 `HOST` 服務票證通常等同於自動獲得了 `cifs` (檔案共享)、`rpcss` (遠端程序調用) 與 WMI 的存取權限。
- [ ] **Q3：白銀票證與黃金票證在影響範圍上有何最根本邊界？**
  - **戰術思維**：黃金票證是全網通行的「萬能身分證」(TGT)，可用來申請全網任意主機的存取權；白銀票證是針對特定單一服務的「專用門票」(TGS)，只能用來登入被偽造的那台特定伺服器。
- [ ] **Q4：微軟修補 CVE-2022-37967 如何重創了未受防護的白銀票證？**
  - **戰術思維**：該安全更新在 Kerberos PAC 中強制引入了包含伺服器簽名與 KDC 簽名的驗證屬性；在嚴格強制模式下，若目標伺服器發現收到的票證中 PAC 簽名異常或無法透過 Netlogon 獲得 KDC 認證，將強制終止連線。
- [ ] **Q5：若紅隊取得了一台網域控制站本身的機器帳號 (DC01$) 雜湊，偽造白銀票證有何毀滅性威脅？**
  - **戰術思維**：若目標是 DC 本身且 SPN 選擇 `ldap/DC01.corp`，攻擊者可藉此白銀票證直接調用目錄複製服務 RPC (DRSUAPI) 發動 **DCSync (R16.1)**，進而倒出全網域所有帳號之密碼雜湊！
