# R07.4 Kerberos 認證票證重放與票證傳遞 (Pass-the-Ticket)

---

## 🎯 作戰任務破題 (Tactical Objective & Mental Workflow)

**Kerberos 票證重放與票證傳遞 (Pass-the-Ticket, PtT)** 的物理本質為**直接提取並注入已通過 KDC 密碼學簽署的合法 Kerberos 認證票證 (Ticket Granting Ticket, TGT)**。在 Windows 網域體系中，使用者登入後其 TGT 票證與對應的 Session Key 會常駐於本機安全機構 (LSASS) 記憶體中。攻擊者若具備本機管理員權限，可直接將記憶體中的 `.kirbi` 或 Linux 環境下的 `ccache` 檔案導出，並將其重放 (Replay) 注入至攻擊者自身的登入會話中，**無需知曉使用者密碼、NTLM 雜湊或發起任何 AS-REQ**，即可持該票證直接向全網申請任意服務存取權。

```
[攻擊者攻陷網域成員主機] ── 具備本機特權，自 LSASS 記憶體導出高特權使用者之 TGT
                                    │
                                    ▼ 獲得 TGT 憑證實體 (ticket.kirbi / krb5cc_*)
[攻擊者工作階段] ────────────────── 1. 執行 Rubeus ptt / Mimikatz kerberos::ptt 注入記憶體
                                    │
                                    ▼ 2. 當前 Logon Session 立即具備該 TGT 權益
[向 KDC 發送 TGS-REQ] ─────────────► 3. 攜帶該 TGT 申請目標伺服器 (如 DC) 之服務票證
                                    │
                                    ▼ 4. KDC 驗證 TGT 簽章合法，順利簽發 TGS
[無密碼橫向移動] ──────────────────► 直連網域控制站 (DC)，完全接管目標特權資源！
```

## 🛡️ 第五動：工程級防禦基線 (Hardening Baselines)

1. **啟用 Credential Guard (虛擬化安全隔離)**：
   - 啟用 Windows **虛擬式安全性 (VBS)** 與 **Credential Guard**，將 LSA 密鑰材料隔離於安全虛擬環境 (LSAIso.exe) 中，使任何本機管理員即使擁有 Ring-0 權限亦無法直接讀取記憶體票證。
2. **啟用 LSA 保護機制 (RunAsPPL)**：
   - 設定註冊表啟用受保護行程 (Protected Process Light, PPL)，阻斷非簽章二進位程式碼對 LSASS 記憶體的注入與讀取。
3. **縮減 Kerberos 票證最長存留時間 (Ticket Lifetime)**：
   - 將網域原則中的 TGT 有效期限自預設的 10 小時縮短為 4 小時以內，大幅收窄重放攻擊的作戰利用時窗。

### 1. 極簡 Linux ccache 票證解析與有效性檢查腳本 (Python, 20 行)
```python
# check_ccache.py
import os, sys

ccache_path = os.environ.get("KRB5CCNAME", "/tmp/krb5cc_1000")

if not os.path.exists(ccache_path):
    print(f"[-] 票證快取檔案不存在: {ccache_path}")
    sys.exit(1)

with open(ccache_path, "rb") as f:
    header = f.read(4)
    # ccache 檔案標頭特徵檢查 (預設版本通常為 0x0504)
    if header.startswith(b"\x05\x04"):
        print(f"[+] 成功識別合法 Kerberos ccache v4 票證檔案: {ccache_path}")
        print("[!] 攻擊者可藉由此票證直接以 pass-the-ticket 發起完全橫向移動！")
    else:
        print("[-] 未知或損毀之票證格式")
```

## 🎯 作戰驗收檢查點 (Operational Checkpoints)

- [ ] **Q1：Pass-the-Hash (PtH) 與 Pass-the-Ticket (PtT) 在網路協定層面有何本質區別？**
  - **戰術思維**：PtH 依賴 **NTLM 協定**，流量集中於 TCP 445/135；而 PtT 依賴 **Kerberos 協定**，先向 KDC (Port 88) 交互申請 TGS 票證，再持 TGS 存取應用端點，天生具備跨跳點與完整網域委派能力。
- [ ] **Q2：為何在已啟用「Restricted Admin Mode」的 RDP 連線下，受害者主機無法導出 TGT？**
  - **戰術思維**：Restricted Admin 模式設計的核心目的即是「禁止客戶端的明文憑證與 TGT 傳送並快取至遠端目標主機的 LSASS」，因此攻擊者在攻陷的目標主機上完全找不到管理員的留存票證。
- [ ] **Q3：在 Windows 終端中，`klist` 指令所顯示的快取票證存於何處？**
  - **戰術思維**：存於 `lsass.exe` 核心記憶體中專屬於該 Logon Session 的 LSA 票證快取表中，`klist` 僅透過微軟官方提供的 LSA RPC 介面查詢並渲染輸出。
- [ ] **Q4：若網域管理員變更了其帳號密碼，已被竊取導出的 TGT 票證是否依然有效？**
  - **戰術思維**：**依然有效**，直到該 TGT 的自身過期時間 (預設 10 小時) 結束為止。因為 KDC 驗證 TGT 時僅使用 `krbtgt` 的金鑰進行驗證，完全不比對使用者本人的密碼雜湊。
- [ ] **Q5：使用 `Rubeus createnetonly` 建立臨時登入會話為何能提升作戰安全性？**
  - **戰術思維**：避免覆寫當前 Beacon 或攻擊機自身的原有網域憑證，所有票證注入與網路請求僅侷限於該獨立新開的 CMD/PowerShell 子行程中，便於隨時銷毀且不留痕跡。
