## 🎯 作戰任務破題 (Tactical Objective & Mental Workflow)

**目錄服務關聯圖譜採集與正規化 (BloodHound Graph Collection)** 的物理本質在於**將 Active Directory 龐大且分散的 LDAP 物件屬性、存取控制清單 (ACL) 與網路會話 (NetSession)，抽象轉換為圖論 (Graph Theory) 架構下的節點 (Nodes) 與邊 (Edges)**。紅隊透過標準 LDAP 查詢與 RPC 通訊，在不觸發告警的前提下全面繪製網域所有權限依賴鏈，為後續最短特權躍遷路徑分析奠定資料基礎。

```
[紅隊已獲取之普通網域帳號] ── 啟動 SharpHound / bloodhound.py
                                │
                                ▼ 透過 LDAP (389/636) 與 RPC/SMB (445) 併發採集
┌───────────────────────────────┴───────────────────────────────┐
│ 1. LDAP 查詢 ──► 提取 User, Computer, Group, GPO, OU 物件與 ACL 屬性 │
│ 2. SAMR 呼叫 ──► 查詢本地群組成員 (Administrators, Remote Desktop) │
│ 3. NetSession ─► 枚舉主機活躍登入會話 (尋找 Domain Admin 登入痕跡) │
└───────────────────────────────┬───────────────────────────────┘
                                ▼
[採集資料正規化] ───────────────► 壓縮轉換為 BloodHound JSON 規格 (v4/v5 Schema)
                                │
                                ▼ 匯入 Neo4j 圖形資料庫
[作戰可視化全景] ───────────────► 展現通往「Domain Admins」的最短攻擊躍遷路徑！
```

## 🔬 第一動：目錄採集協定與圖譜邊緣定義 (Mechanics & Graph Edges)

### 1. 採集協定與核心權限邊 (Graph Edges) 定義

| 圖譜邊緣 (Edge) | 物理協定/機制 | 原始安全屬性 | 作戰意義 |
| :--- | :--- | :--- | :--- |
| **MemberOf** | LDAP (389/636) | 物件之 `member` / `memberOf` 屬性 | 建立群組嵌套關係與權限繼承樹 |
| **AdminTo** | RPC (SAMR/NetWksta) | 目標主機本地 Administrators 成員 | 標記具備完全本機特權之受控主機 |
| **HasSession** | SMB (NetSessionEnum)| 網域控制站或目標主機之活躍連線 | 鎖定憑證竊取 (LSASS Dump) 目標節點 |
| **GenericAll** | LDAP Active Directory DACL | 物件安全描述元 (nTSecurityDescriptor) | 具備對該物件之完全控制權 (如重設密碼) |
| **WriteDacl** | LDAP Active Directory DACL | 物件存取控制清單寫入權 | 可向目標物件主動授予任意特權邊 |

## 🥷 第三動：防禦規避與日誌特徵操控 (Evasion & Telemetry)

### 1. 採集特徵消減與動態避險表

| 規避面向 | 原始採集特徵 | 變形混淆與規避手法 | 原理解析 |
| :--- | :--- | :--- | :--- |
| **NetSession 噪音** | 短時間向全網數百台工作站發起 SMB 連線 | 啟用 `--Stealth` 或使用 `--CollectionMethods DCOnly` | 僅向 DC 查詢，完全不對端點發起連線 |
| **LDAP 查詢頻率** | 大量未分頁查詢觸發 CPU 負載與 MDI 告警 | 設定 LDAP 分頁大小 (`--LdapPageSize 500`) 並加入隨機延遲 | 平滑化 LDAP 查詢特徵 |
| **加密通道傳輸** | 明文 LDAP 389 封包被 NTA / Zeek 深度解析 | 強制啟用 LDAPS (TCP 636) 或 Kerberos 封裝 | 將查詢內容隱匿於 TLS/Kerberos 加密流中 |

## 🛡️ 第五動：工程級防禦基線 (Hardening Baselines)

1. **限制 SAMR 遠端呼叫權限 (Restrict Remote SAMR)**：
   - 設定群組原則：`網路存取: 限制允許對 SAM 進行遠端呼叫的用戶端`，將存取權限僅限於本機 Administrators，杜絕普通網域帳號枚舉本地群組。
2. **強制 LDAP 簽章與通道繫結 (LDAP Signing & Channel Binding)**：
   - 啟用網域控制站 LDAP 伺服器簽署需求，阻斷中間人竄改與未加密查詢。
3. **部署蜜罐帳號 (Honeytokens) 與誘餌**：
   - 建立高吸引力但無實際用途的網域管理員帳號與 SPN；一旦其在 LDAP 查詢中被標記為目標或遭遇枚舉，觸發最頂級 SOC 告警。

## 🧪 實戰演練環境搭建 (Environment & Lab Setup)

### 1. 極簡 LDAP 圖譜枚舉模擬腳本 (Python, 20 行)
```python
# ldap_recon.py
from ldap3 import Server, Connection, ALL, SUBTREE
import json

# 連接目標網域控制站
server = Server("127.0.0.1", get_info=ALL)
conn = Connection(server, user="corp\\lowpriv", password="Password123!", auto_bind=True)

# 查詢所有網域管理員群組成員
search_filter = "(&(objectClass=user)(memberOf=CN=Domain Admins,CN=Users,DC=corp,DC=internal))"
conn.search(search_base="DC=corp,DC=internal", search_filter=search_filter, search_scope=SUBTREE, attributes=["sAMAccountName", "userPrincipalName"])

graph_nodes = []
for entry in conn.entries:
    graph_nodes.append({"user": entry.sAMAccountName.value, "admin_edge": True})

print(json.dumps({"domain": "corp.internal", "admins": graph_nodes}, indent=2))
```

## 🎯 作戰驗收檢查點 (Operational Checkpoints)

- [ ] **Q1：SharpHound 中的 `--CollectionMethods DCOnly` 為何被視為隱蔽滲透的關鍵選項？**
  - **戰術思維**：`DCOnly` 僅向網域控制站發送標準的 LDAP 查詢，**完全不與任何內網工作站或成員伺服器發起 SMB (Port 445) 網路連線**。這能彻底規避基於端點 RPC 連線頻率的 EDR/NDR 異常警報。
- [ ] **Q2：在未加入網域 (Non-Domain Joined) 的攻擊機上，如何解析 Active Directory 網域名稱？**
  - **戰術思維**：透過 `--nameserver` 指定 DC 的 IP 地址作為 DNS 伺服器，使攻擊工具能夠正確解析諸如 `_ldap._tcp.dc._msdcs.DOMAIN` 之 SRV 記錄並發起 Kerberos 票證申請。
- [ ] **Q3：BloodHound v5 與早期 v3/v4 版本在架構與匯入資料格式上有何根本革新？**
  - **戰術思維**：BloodHound CE (v5) 採用全新開源架構，由以往依賴本機 Neo4j 桌面版轉向 Docker 容器化 REST API 與 PostgreSQL + Neo4j 混合架構，並支援更廣泛的 Azure / Entra ID 混合雲身分邊界圖譜。
- [ ] **Q4：若目標網域部署了「NetCEase」，對圖譜採集會造成何種物理影響？**
  - **戰術思維**：NetCEase 透過限制 `NetSessionEnum` 的存取權限，阻斷普通網域使用者遠端枚舉伺服器上的活躍會話，導致採集工具無法取得 `HasSession` 邊，迫使紅隊改採其他提權路徑。
- [ ] **Q5：為何在大型企業內網中執行完整採集可能導致網域控制站 CPU 飆升？**
  - **戰術思維**：若使用了包含未建立索引屬性之複雜 LDAP 過濾器，且未設定適當的 `LdapPageSize`，DC 必須在記憶體中掃描整個 NTDS.dit 資料庫，產生極大記憶體與計算負載，觸發藍隊效能監控。
