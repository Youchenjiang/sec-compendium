# 跟課教材走查 (teaching walkthrough)

一份好的 hands-on 實作教材要同時做到兩件事：

- **自然**：讀起來像一位有經驗的老師帶學生理解一次完整過程，不像被文字牽著走流程。
- **有據**：任何指令、路徑、模組名、數值，學生都看得出它從哪來，不是憑空冒出來。

這兩件事都會出錯，但方向相反：有據不足會變「通靈」，自然不足會變「腳本旁白」。下面分開講，收尾的自檢清單也分兩欄。

錨定範例（寫新的照它的骨架）：
`tracks/courses/ncu_network_security/sessions/02_recon-to-shell-meta2/handout.md`

---

## 一、檔案分工（先確認寫對檔）

| 檔 | 角色 | 放什麼 |
|---|---|---|
| `handout.md` | 學生跟課教材（教） | 概念、完整走查、示範——**給好給滿** |
| `assignment.md` | 學生作業題目（做／交） | 要做的事、交付物、評分；「自己挑別條／自己查」這類**限制只放這裡** |
| `answer-key.md` | 教師用 | 完整答案、評分、多種打法與排錯、堂次定位 |

- 標題**只放內容**；角色由副標或開頭第一段自然帶出（開頭已講清楚就不必另加副標）；堂次（第幾堂）交給資料夾名，不進標題。
- 教材要大方，把完整可行的路徑教到底；收回手（「自己查」「挑別條」）是作業的事。
- **作業說明沿用課程既有格式**（繳交格式、參考講義連結、截圖並說明每步驟、額外加分），但**加分要符合本堂定位**——別照抄別堂的要求（例：這堂停在「拿到 shell」，加分就不要求提權或後滲透）。
- **作業難度**：必做放在好上手的靶機（人人能完成、顧到主旨），進階或不同性質的靶機當選做加分；**必做要禁用課堂示範的那一條**，逼學生自己偵察、自己查，而不是照抄示範。

---

## 二、有據：零通靈（這部分從嚴）

學生讀到的每個東西都要有出處：

| 冒出來的東西 | 出處要從哪來 |
|---|---|
| 版本號 | `-sV` 的輸出 |
| 漏洞機制 | 把腳本**關鍵幾行貼出來**讓學生自己讀懂，不要只寫結論 |
| exploit 路徑／檔名 | `searchsploit` 結果的 **Path** 欄 |
| 模組路徑 | `search <服務>` 的 **Name** 欄 |
| 要設的參數（RHOSTS…） | `show options` / `info` |
| 寫死的值（埠、帳號如 6200、`:)`） | 指出它在腳本哪一行、或協定裡哪來的 |

示範一條完整例子（選一個服務從掃描走到拿 shell），讓上面每一項都在例子裡真的出現、真的被導出。

---

## 三、自然：像老師講，不像腳本牽（這部分要克制）

這是最容易做過頭的地方——**本教材初版就是因為一直補銜接、補前指，寫成了旁白腳本**。守住以下幾點：

- **用邏輯串，不用銜接句牽。** 開頭用一兩句話交代整條流程的弧線就夠；之後讓每步內容自然接上，**不要每步都寫**「這就是下一步」「接下來我們要…」。前一步的結果自然指向後一步時，不必再提醒一次。
- **框架放頭尾，中間不放（書擋寫法）。** 開頭放一行概念鏈當整體地圖（例：偵察 → 查漏洞利用 → 取得 shell → 確認權限），結尾放一行具體口訣當收束（例：掃 → 讀 → 挑 → 查 → 打 → 進去看）。兩者是同一流程的不同顆粒度，頭尾呼應、各出現一次；中間各步靠邏輯自然接，不逐步預告。
- **觀念講一次。** 同一個重點（例如「版本是重要線索」）第一次說清楚，後面直接用，別反覆叮嚀。
- **深度可以不同。** 簡單操作直接講完；複雜概念才多花篇幅。不要六步都套同一個「為什麼→指令→輸出→你學到了什麼→預告下一步」的五拍模板。
- **語氣一致。** 親切可以，但要穩定；別讓專業術語、朋友聊天、操作手冊三種口吻交替出現。避免口語／黑話：打穿、一坨、人話、很猛、搞頭、打髒、魔術數字。
- **別替學生把話說死。** 「填得出表就代表讀懂了」「後面全看版本」這類為了有力而過度簡化的斷言不要寫——版本是線索不是證明，整理資訊是理解的起點不是終點。
- **刪廢話。** 對學生沒有實際作用的保證與背景（「放心操作」「弄壞了還原快照」「每人一台、已分配好」這類）一律砍掉，只留會影響他「怎麼做、交什麼」的資訊。

---

## 四、表格 vs 散文

- **散文**：敘事推進的步驟——那是脈絡，別壓成表。
- **表格**：平行／對照的資訊——多種打法比較、值↔意義、把掃描結果讀成的那張表。
- 判準：「一項接一項往前走」用散文；「幾個東西並排比」用表格。

---

## 五、用詞

- 術語**第一次出現就加括號註解**：shell（能下指令的介面）、banner（服務自我介紹字串）、root（最高權限）、CVE（漏洞全球編號）、exploit（現成攻擊程式）、RHOSTS（目標 IP）等。縮寫先給全名（msf → metasploit）。
- 課程本來就要教學生唸的指令／協定／工具名（`nmap`、`-sV`、`ftp`、`ssh`）**不用翻**。
- 未解釋的 jargon（提權、後滲透…）這堂用不到就別出現，要講就用白話。

## 六、改完的自檢清單

**有據**
- [ ] 有沒有任何值／路徑／名詞是沒出處就出現的？
- [ ] 機制是讓學生從程式碼／輸出讀出來的，還是我直接斷言的？

**自然**
- [ ] 有沒有多餘的銜接句、反覆的提醒？拿掉會不會更順？
- [ ] 語氣一致嗎？有沒有口語／黑話？
- [ ] 有沒有把技術講死的斷言？
- [ ] 簡單步驟是不是被硬撐成同一個模板？

**共同**
- [ ] 術語都在第一次出現時加註了？
- [ ] 標題只有內容、角色在副標、堂次沒進標題？
- [ ] 平行資訊該進表格的進了嗎？只該在作業的限制有沒有溜進教材？
- [ ] 有沒有對學生沒作用的廢話／保證句可以砍？
- [ ] 作業：格式沿用課程慣例？必做禁用示範那條？加分符合本堂定位（不越過本堂終點）？
